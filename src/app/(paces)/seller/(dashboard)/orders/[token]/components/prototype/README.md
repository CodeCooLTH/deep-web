# 🧪 PROTOTYPE — modal คืนของ ให้ desktop/mobile เป็น flow เดียวกัน

**throwaway · branch `proto/return-modal-unified` · ห้าม merge เข้า main**

## คำถามที่ prototype นี้ตอบ

> "re-design ux + ui สำหรับ modal การคืนของ โดยให้ทั้ง desktop / mobile เป็น flow เดียวกัน"

## ทำไมของเดิมยังไม่ใช่ flow เดียวกัน (วัดจากโค้ด ไม่ใช่ความรู้สึก)

`ReturnPanel.tsx` เขียนเปลือกชีตไว้ว่า

```
fixed inset-0 flex items-end justify-center … sm:items-center sm:p-4
card … h-full max-h-full rounded-b-none sm:h-auto sm:max-w-lg sm:rounded-lg
```

= **มือถือเป็นชีตยึดขอบล่างสูงเต็มจอ · เดสก์ท็อปเป็นกล่องลอยกลางจอสูงเท่าเนื้อหา**
เนื้อหาข้างในชุดเดียวกันก็จริง แต่ **รูปร่างที่ครอบมันคนละอย่าง** ⇒
- ที่ว่างต่างกันมาก → ขั้นที่ 1 (ตัวเลือก) พอดีจอบนเดสก์ท็อป แต่ต้องเลื่อนบนมือถือ
- ปุ่มหลักลอยท้ายเนื้อหา → บนมือถือมันเลื่อนหายไปใต้จอ บนเดสก์ท็อปเห็นตลอด
- ขั้นที่ 2 บนเดสก์ท็อป กล่องยุบสูงลงกะทันหันเพราะ `h-auto` → จอกระตุก

การพูดว่า "เนื้อหาเหมือนกัน" จึงไม่ได้แปลว่า flow เหมือนกัน — **ที่ต่างคือกล่อง ไม่ใช่ของข้างใน**

## แผน

3 variants บน route จริง `/seller/orders/[token]` สลับด้วย `?variant=A|B|C`
(sub-shape A — ชนกับ header/ข้อมูล/ความหนาแน่นจริง ไม่ใช่หน้าเปล่าที่ทุกแบบดูดีหมด)

ทั้ง 3 ใช้โมเดล **3 ตัวเลือก** ตามที่หัวหน้าสั่งล่าสุด (ส่งด้วย iShip / ร้านส่งเอง / ลูกค้าส่งเอง)
+ ขนส่งเป็น dropdown จากรายชื่อในระบบ — เพื่อให้เทียบกันได้ที่ *โครง* ไม่ใช่ที่ *เนื้อหา*

| | ยุทธศาสตร์ "หนึ่ง flow" | รูปร่าง |
|---|---|---|
| **A** | **ตัดขั้นตอนทิ้ง** — ไม่มี wizard เหลือคอลัมน์เลื่อนอย่างเดียว ซึ่งเป็นสิ่งเดียวที่ทุกขนาดจอทำเหมือนกันได้แน่นอน | ชีตยึดล่างทั้งสองขนาด · ปุ่มหลักตรึงท้ายกล่องเสมอ |
| **B** | **ตัดความต่างของกล่องทิ้ง** — เต็มจอทั้งคู่ เดสก์ท็อปได้คอลัมน์กลางกว้าง 560px บนพื้นเดียวกัน | เต็มจอ + หัวตรึง + แถบปุ่มตรึงล่าง (ท่าเดียวกับ route `(fullscreen)` ที่โปรเจกต์มีอยู่แล้ว) |
| **C** | **ตัดฟอร์มทิ้ง** — เป็น "ใบคืน" ที่เติมค่าที่พบบ่อยไว้ให้แล้ว แตะบรรทัดไหนก็กางแก้เฉพาะบรรทัดนั้น | การ์ดสรุป 3 บรรทัด · กางทีละบรรทัดในที่เดิม |

## 🛑 ข้อจำกัดของ prototype

- `onSubmit` เป็น stub **ไม่ยิง API** — ตอบคำถาม "ควรหน้าตายังไง" ไม่ใช่ "backend ทำงานไหม"
- ไม่มีเทส ไม่มี error handling ไม่มี a11y ครบ
- ชนะแล้วต้อง **เขียนใหม่ให้ถูกมาตรฐาน** แล้วลบทั้งโฟลเดอร์นี้ + บล็อก proto ใน `ReturnPanel.tsx`
