# Conventions — สรุปเต็มทุกฉบับ

> ฉบับเต็มที่ย้ายออกจาก `CLAUDE.md` เมื่อ 2026-10-04 เพื่อลด context — `CLAUDE.md` เก็บแค่สรุปบรรทัดเดียวแล้วลิงก์มาที่นี่. ตัวจริงของแต่ละข้ออยู่ใน `docs/conventions/<ชื่อ>.md`; ไฟล์นี้คือบทสรุปยาว

- `docs/conventions/rsc-mui-navigation.md` — RSC + MUI + next/link pattern
- `docs/conventions/date-format.md` — 🛑 วันที่/เวลาทั้งระบบใช้ `formatDate`/`formatDateTime` จาก `src/lib/format-date.ts` เท่านั้น (วัน-เดือน-ปี พ.ศ. `07-06-2569 10:06:13`, tz ไทย — **เรียงเป็นสตริงไม่ได้** ตารางต้อง sort จากค่าดิบ) — ห้าม `toLocaleDateString`/`Intl.DateTimeFormat` เอง
- `docs/conventions/no-emoji-use-icons.md` — 🛑 ห้าม emoji ใน UI ทุกจุด (ทุก surface/subdomain/theme) ใช้ icon จริงเท่านั้น (`@iconify/react`/wrapper); จุดที่ควรมี icon แต่ mockup/spec ไม่ได้ระบุตัว → **ต้องถาม user ก่อน implement เสมอ** (ห้ามเดาเอง)
- `docs/conventions/impeccable-design.md` — 🛑 งาน UI **ทุกชิ้น** ยึด **Impeccable design system** เป็นหลัก (`.impeccable/design.json` + `DESIGN.md`): north star "The Trusted Counter", One Voice (ม่วง ≤10%), Verified-Means-Green (#28C76F), Ink Plum ไม่ใช่ดำสนิท, tokens เงา/motion, anti-slop. **อ่าน design.json ก่อนทำ UI เสมอ** — ควบคู่ theme-copy (Hard Rule 1/8)
- `docs/conventions/enum-value-removal.md` — 🛑 ลบค่าออกจาก enum/union ที่ผู้ใช้เห็น ต้อง grep **ทั้ง repo** (`src/ e2e/ scripts/ prisma/ docs/`) ไม่ใช่แค่ `src/` เพราะ e2e/scripts **seed row จริง** และคอลัมน์ `String` ใน Prisma ไม่มี type ให้ TS จับ. grep จับ **object key ไม่ได้** → ต้องขยาย type union ให้ `tsc` บังคับ key ครบเป็นด่านสอง. ตรรกะ binary (`v === 'X' ? A : B`) ไม่พังเสียงดังเมื่อค่าที่ 3 มา — เขียนเป็น allow-list + fail-closed. ตั้งชื่อไทยของค่าใหม่ต้อง grep กันชนกับ label ที่มีอยู่ก่อน
- `docs/conventions/root-served-assets-and-proxy.md` — 🛑 ไฟล์ที่เสิร์ฟจาก **root** (ของใน `public/` + route ที่ Next สร้างเอง เช่น `manifest.ts`→`/manifest.webmanifest`) ต้องมีนามสกุลอยู่ใน allow-list ของ `src/proxy.ts` **ในคอมมิตเดียวกัน** ไม่งั้นโดน rewrite เป็น `/seller/...` = **404 เฉพาะบน subdomain** (main domain ปกติ จึงหลุด review ทุกครั้ง). พลาดมาแล้ว 2 ครั้ง — `.m4a` เสียงแจ้งเตือนไม่ดัง (2026-07-24) และ `.webmanifest` ทำ PWA "เพิ่มลงหน้าจอโฮม" บน seller/admin ใช้ไม่ได้มาตลอด (2026-08-05) **ทั้งคู่ user เป็นคนเจอ**; คอมเมนต์เล่าบั๊กครั้งก่อนอยู่เหนือ regex บรรทัดเดียวกันแต่กันซ้ำไม่ได้ เพราะคนเพิ่มไฟล์ไม่ได้เปิด `proxy.ts`
- `docs/conventions/webhook-subscription-two-layers.md` — 🛑 การ subscribe webhook ของ Meta มี **2 ชั้น** (ระดับแอปใน App Dashboard + ระดับเพจผ่าน `subscribed_apps`) **ขาดชั้นไหนก็เงียบเหมือนกัน** และ "ไม่มี event เข้ามา" หน้าตาเหมือน "ไม่มีอะไรเกิดขึ้น" ทุกประการ (ไม่มี error/log, tsc+build เขียว, โค้ดฝั่งรับถูกทุกบรรทัด — มันแค่ไม่เคยถูกเรียก). ชั้นระดับแอป **ไม่มีในรีโปเลย** ต้องอ่านจากฝั่ง Meta ด้วย DevTools MCP — ตรวจแต่โค้ดเราจะเจอแค่ครึ่งเดียวเสมอ. เคสจริงที่พบพร้อมกัน 2026-08-08 และ **ขาดคนละชั้นกัน**: `message_deliveries` (ขาดระดับแอป → สถานะ "ได้รับแล้ว" ไม่เคยทำงานเลยตั้งแต่ 08-05) · `message_edits` (ขาดระดับเพจ → `ingestMessageEdit` ไม่เคยถูกเรียกตั้งแต่ 08-03) · `messaging_handovers` (ขาดทั้งคู่ → เธรดที่ Meta AI ถือสิทธิ์คุมไม่เข้ากล่องจนกว่าคนจะ take over). 🛑 **แอปแชทไม่ใช่แอปเดียวกับแอป login** (`FACEBOOK_ID`=Deep Thailand ส่วน webhook=Deep Chat & LIVE) เช็คผิดแอปแล้วเห็น `fields: []` จะสรุปผิดทั้งกระดาน · `vercel env pull` redact `CHANNEL_TOKEN_KEY` เป็น `[SENSITIVE]` → **re-sync ต้องยิงจากในแอปที่ prod เท่านั้น** สคริปต์จากเครื่อง dev ได้ `CHANNEL_TOKEN_KEY_INVALID` ทุกเพจ · ตัวเลขรวมหลอกได้ ต้องเทียบ **รายเธรด** กับ Business Suite
- `docs/conventions/insert-then-catch-logs-every-error.md` — 🛑 **Postgres เขียน ERROR ลง log ทุก constraint violation ไม่สนว่าแอปดักด้วย try/catch แล้ว** → แพตเทิร์น "insert ไปก่อน แล้วดักตอนชน" (idempotency ผ่าน `@unique`) ผลิต ERROR หนึ่งบรรทัด **ต่อการทำงานที่สำเร็จหนึ่งครั้ง** — จำนวนบรรทัดใน log = ปริมาณงานที่สำเร็จ ไม่ใช่ที่ล้ม. เห็น error ไหลใน log ฐานข้อมูล **ให้ถามก่อนว่าโค้ดดักไว้หรือเปล่า** แล้วย้ายไปประเมินที่ *ต้นทุน* แทน *ความถูกต้อง* (เคสจริง 2026-08-10: `ChatMessage_externalMessageId_key` ไหลทุก 10–30 วิ = echo ของข้อความที่ร้านส่งเอง ชนแน่นอน 100% ทุกใบตามลำดับ ส่งก่อน→ได้ mid→เขียน DB ที่จงใจออกแบบไว้). ต้นทุนที่จ่ายจริงทุกใบ: write + ทรานแซกชัน + **INSERT ที่ล้มเขียน tuple/index entry ลงไปก่อน rollback → dead tuple ให้ autovacuum ตามเก็บ**. เพิ่ม pre-check ได้แต่ **ห้ามถอดตัวดักเดิม** (race ระหว่าง SELECT กับ INSERT ยังเกิดได้ ความถูกต้องต้องอยู่ที่ `@unique` เสมอ) · **จุดวางสำคัญกว่าตัว pre-check** — ต้องอยู่หลังทุก branch ที่ใช้ id เดิมโดยตั้งใจ (`is_deleted` ของ unsend ส่ง mid ที่มีอยู่แล้วมาเป็นปกติ วางก่อน = ข้อความที่ลูกค้ากดลบค้างในเธรดตลอดไปโดยไม่มีอะไรฟ้อง) · **อย่าไล่แก้ทุกที่ที่มีแพตเทิร์นเดียวกัน** ดูอัตราการชนจริงก่อน (LINE เขียนเหมือนกันเป๊ะแต่ `capabilities.echo=false` ชนเฉพาะ redelivery = ไม่คุ้ม)
- `docs/conventions/one-value-many-entry-points.md` — 🛑 ค่าที่ผู้ใช้กรอก (เช่น **เลขพัสดุ**) มีได้หลายทางเข้าและมักเก็บ **คนละตาราง** — ก่อนอ่าน/แสดง ให้ไล่ทางเข้าจากหน้าจอ (นับแท็บ/ปุ่ม submit ในโมดัล) ไม่ใช่จาก schema ที่กำลังแก้อยู่
- `docs/conventions/user-supplied-image-assets.md` — 🛑 รูปที่ user ส่งมาต้อง **เปิดดูก่อนใช้**: สัดส่วน (ไม่จัตุรัส + `object-cover` = ครอปเนื้อหาทิ้ง) · พื้นหลัง (ขาวบนการ์ดขาว = ขอบหาย ต้องมี `ring`) · ขนาดไฟล์; ห้ามไปหาโลโก้แบรนด์จากอินเทอร์เน็ตเอง; `ls` ทั้งโฟลเดอร์ก่อน filter (คนเลี่ยงอักขระพิเศษในชื่อไฟล์ `J&T` → `jandt-express.png`)
- `docs/conventions/contrast-fix-keeps-hue.md` — 🛑 แก้คอนทราสต์ปรับได้แค่ **ความเข้ม** ของสีเดิม **ห้ามสลับเฉด** (เหตุการณ์ 2026-08-03: `text-{tone}` → `-ink` 55 จุด ทำให้ดาวปักหมุดกลายเป็นน้ำตาล ปุ่ม danger กลายเป็นเลือดหมู ต้องย้อนทั้งหมด). `-ink` **ไม่ใช่ token ของธีม** (grep `theme/paces` = 0) — ก่อนใช้ token สีให้ grep `theme/` ก่อนเสมอ. ไอคอนที่ "สี = ตัวตน" (ดาว/โลโก้ช่องทาง) ไม่อยู่ใต้กฎคอนทราสต์ข้อความ. HR8 "Impeccable ชนะเรื่องสี" = ลำดับชั้น/น้ำเสียง/ความหมาย **ไม่ใช่ใบอนุญาตเปลี่ยนเฉดสีแบรนด์**
- `docs/conventions/aria-name-requires-supporting-role.md` — 🛑 **`aria-label` มีผลเฉพาะกับ element ที่ role รองรับ "ชื่อจากผู้เขียน"** — `<p>`(role=paragraph)/`<div>`/`<span>` เปล่า **ไม่รองรับ** screen reader ที่ทำตามสเปกจะทิ้ง label ทิ้ง. แพตเทิร์น "ใส่ label ที่พ่อ แล้ว `aria-hidden` ลูกทุกตัวกันอ่านซ้ำ" จึงทำให้ **ทั้งบล็อกไม่ถูกอ่านสักคำ** ไม่ใช่แค่อ่านไม่ครบ (เคสจริง 2026-08-08: บรรทัดกำไรรายออเดอร์เงียบสนิท ทั้งที่ `MiniShipmentTimeline.tsx` โฟลเดอร์เดียวกันใช้ `role="img"` ถูกอยู่แล้ว). `title=` ไม่ใช่ตัวแทน (มือถือไม่มี hover) ต้องมีคู่กันเสมอ. ญาติกัน: `role="dialog"` ต้องมี `aria-modal="true"` ไม่งั้นผู้ใช้อ่านหลุดออกไปหลังฉาก — **ยกเว้น popover ที่เกาะปุ่มและหน้าหลังยังกดได้จริง ตรงนั้นไม่ใส่คือถูกแล้ว** (โฟลเดอร์ `orders/` พลาดพร้อมกัน 8 ใบ). **ไม่มี gate ไหนของโปรเจกต์จับคลาสนี้ได้** (`tsc`/build/detector/`theme-guard` ผ่านหมดเพราะ markup ถูกทุกตัวอักษร) — และ **สคริปต์สแกน regex เชื่อผลดิบไม่ได้ ต้องเปิดไฟล์ยืนยันทุกจุด** (รอบนั้น false positive 4 จาก 6)
- `docs/conventions/partial-data-must-be-labeled-or-filled.md` — 🛑 **ตัวเลขบางส่วนที่หน้าตาเหมือนตัวเลขที่ครบแล้ว อันตรายกว่าไม่มีตัวเลข** ผู้ใช้ไม่มีทางรู้ว่ามันยังไม่จบ ได้แต่สรุปว่าระบบคำนวณผิดแล้วเลิกเชื่อทั้งหน้า (เกิดจริง 2026-08-10: ค่าส่งวันที่ 9 ขึ้น ฿328.88 จาก 31 ออเดอร์ เพราะมีราคาจริงแค่ 7 ใบ — เลขถูกทุกบาทตามข้อมูลที่มี). มีทางเลือก 2 ทางเท่านั้น: **บอก** (ป้ายต้องครอบ **ทั้ง 3 สถานะ** ครบ/**มาบางส่วน**/ยังไม่มี — ตัวกลางคือตัวที่มักลืมและเกิดบ่อยที่สุด · `0` ห้ามใช้แทน "ยังไม่รู้") หรือ **เติมให้เต็ม** (ค่าจริง → ค่าประมาณ → ไม่มี ห้ามบวกกัน) · **เลือกทางเติมแล้วถึงจะไม่ต้องมีป้ายได้** · อย่าผูกการเก็บค่าหนึ่งไว้กับเงื่อนไขของอีกค่าหนึ่ง (`cod_fee` รู้ตั้งแต่สร้างพัสดุ แต่ถูกทิ้งเพราะโค้ดรอ `carrierPrice`)

- `docs/conventions/oauth-signup-unique-collisions.md` — 🛑 **ค่าที่ตั้งจาก id ของผู้ให้บริการ (`username` = `${prefix}${providerAccountId}`, `email`) คงที่ตลอดกาล และ soft delete ไม่ปล่อยคอลัมน์ `@unique` คืนจนกว่าจะถึงรอบ purge** ⇒ ชนได้ **แม้ไม่มีใครล็อกอินอยู่** (เชื่อม OAuth → ถอด → ออกจากระบบ → ล็อกอิน id เดิม ⇒ ไม่เจอ `AuthAccount` จึงสร้าง user ใหม่ → ชน). ตัวดักเดิมเหมาว่า **P2002 = race เสมอ** พอหา `AuthAccount` ที่ชนไม่เจอก็ `throw` → NextAuth ตายกลางทาง → **หน้าล็อกอินค้าง มีวงกลมหมุนแต่ไม่พาไปไหน ไม่มี error ให้ใครเห็น** (เกิดจริง prod 2026-08-15) · ต้องอ่าน `err.meta.target` แล้วแยกตามคอลัมน์: `AuthAccount`→คืน user ที่อีก request สร้าง · `username`→ตั้งชื่อใหม่ · `email`→ไม่เก็บอีเมล (เป็นของแถวอื่น เราไปยึดไม่ได้) · **อื่น ๆ→`throw` ห้ามกลืน** · 🛑 **ไล่ constraint ให้ครบก่อนแก้ ไม่ใช่ปะทีละอาการ** — รอบแรกแก้แค่ `username` แล้วประกาศว่าจบ user ทดสอบแล้วยังค้างเพราะชนต่อที่ `email` ซึ่งอยู่ในสคีมาเดียวกัน (ดูสคีมา 5 วิก็เห็นครบทั้ง 3 ตัว) · 🛑 **ด่านต้องผูกกับสคีมาจริง** (regex ดึงคอลัมน์ `@unique` จาก `schema.prisma` มาเทียบ ⇒ เพิ่ม unique ใหม่แล้วแดงทันที) **และต้องเช็ค "ทำอะไรกับสิ่งที่เจอ" ไม่ใช่แค่ "ตรวจเจอ"** (ร่างแรกเช็คแค่ `target.includes("email")` — mutation พิสูจน์ว่าลบบรรทัดที่แก้ปัญหาทิ้งแล้วเทสยังเขียว)
