## 2. บทเรียนที่แพงที่สุด

### 2.1 คอมเมนต์ที่ประกาศกฎไว้ถูกต้อง แต่โค้ดใต้มันทำตรงข้าม

`ParcelTimeline.tsx` เขียนบนหัวไฟล์ว่า *"ลำดับ/ความหมายของ 4 จุดยกมาจาก MiniShipmentTimeline
ฝั่งร้าน **1:1** … ห้ามสร้างตรรกะแบ่งขั้นของตัวเองที่นี่"* แล้วบรรทัดถัดมาก็สร้างตรรกะของตัวเอง
ด้วยรายชื่อ key คนละชุด (`PARCEL_CREATED`/`LABEL_PRINTED`/`DELIVERED` = ค่าของ `OrderStageKey`)
ขณะที่ `deriveShippingStage()` คืน `ShippingStageKey` — **ตัดกันแค่ `SHIPPING` ค่าเดียว**

ผลบนหน้าจอผู้ซื้อ:
- พัสดุที่ส่งถึงแล้ว → `idx === -1` → ไฮไลต์ "สร้างพัสดุ"
- จุด "จัดส่งสำเร็จ" **ไม่มีทางติดสว่างได้เลย**
- แถบเตือน "พัสดุมีปัญหา" เทียบ `'PROBLEM'` กับ `'PARCEL_PROBLEM'` ⇒ **ไม่เคยขึ้นสักครั้งตั้งแต่วันแรก**

คนที่พัสดุติดปัญหาคือคนที่ไม่ได้รับการเตือน บนจอที่มีไว้พิสูจน์ว่าร้านซื่อสัตย์

**ทำไมไม่มีอะไรฟ้อง:** prop ประกาศเป็น `stage: string` ⇒ `tsc` มองไม่เห็น ส่วนฝั่งร้านพิมพ์เป็น
`Record<ShippingStageKey, number | null>` มาตลอด. หัวไฟล์ยังเขียนอีกว่า "ถูกใช้ทั้ง
GuestOrderView และ OrderDetailMobile" ซึ่งก็ไม่จริง (ใช้ที่เดียว)

**กติกาที่ได้:** คอมเมนต์ที่บอกว่า "ยกมา 1:1" ไม่ใช่หลักฐานว่ายกมาจริง — ถ้าสองจอต้องตรงกัน
ให้ **import ตารางเดียวกัน** ไม่ใช่เขียนคำสัญญาไว้ในคอมเมนต์ และ **prop ที่รับ enum
ต้องพิมพ์เป็น union ไม่ใช่ `string`** ไม่งั้นค่าที่ไม่มีในรายการจะตกไปจุดแรกอย่างเงียบ ๆ
ซึ่งเป็นค่าที่ "ดูสมเหตุสมผล" บนหน้าจอพอดี → ตอนนี้เป็น `SHIPMENT_STAGE_DOT_INDEX` ใน
`order-stage.ts` ที่ทั้งสองจออ่านร่วมกัน + เทส parity

### 2.2 ป้ายปุ่มโกหกในกรณีที่อันตรายที่สุด และมันคือรูปร่างของสแกมที่ product นี้มีไว้กัน

ออเดอร์ `PENDING` ที่โอนเข้าบัญชี ปุ่มหลักเขียนว่า **"ยืนยันการชำระเงิน"** แต่มันยิง
`POST /confirm` ⇒ ออเดอร์เป็น `CONFIRMED` ถาวร ป้อนเข้า Trust Score และ **ซ่อนปุ่มแจ้งปัญหาทิ้ง**

เดินตามเคสจริง: ร้านส่งลิงก์ก่อนส่งของ → ผู้ซื้อเห็นปุ่มม่วงเต็มความกว้างเขียนว่า
"ยืนยันการชำระเงิน" → กดเพราะเข้าใจว่ากำลังยืนยัน *การโอนของตัวเอง* → ทางออกเดียวหายไปในหนึ่งแตะ
**ไม่มี dialog ถามเลย** ขณะที่ "ยกเลิกคำสั่งซื้อ" ที่อยู่ห่างลงไป 5 บรรทัดมี dialog มาตลอด

ทั้ง 4 กรณี (SHIPPED / ไม่ต้องจัดส่ง / COD / โอน) เรียก endpoint เดียวกันและได้ผลเหมือนกันทุกประการ
— การแตกป้ายตามวิธีจ่ายเงินจึงไม่ได้ให้ข้อมูลอะไร มันแค่เปิดช่องให้ป้ายหนึ่งพูดผิด

**กติกาที่ได้:** ป้ายปุ่มต้องบอก *สิ่งที่จะเกิดขึ้น* ไม่ใช่ *บริบทรอบตัว* — และเมื่อการกระทำ
ย้อนไม่ได้ ให้ดูว่าปุ่มข้าง ๆ ที่อันตรายน้อยกว่ามี guard ไหม ถ้ามีแล้วตัวนี้ไม่มี นั่นคือสัญญาณ

### 2.3 เขียน convention เรื่องหนึ่งเมื่อวาน แล้ววันถัดมาละเมิดมันเอง

`docs/conventions/upload-body-size-limit.md` (เขียน 2026-08-10) บอกว่าห้ามส่งไฟล์ผ่าน body
ของ API route เพราะ Vercel ตันที่ 4.5MB — วันถัดมาคอมมิต D4 **ขึ้นเลขบนจอจาก "≤ 5MB" เป็น
"≤ 10MB"** ขณะที่เส้นทางยังเป็น multipart อยู่ ⇒ เลขที่แสดงห่างจากความจริงกว่าเดิมเท่าตัว

สุดท้ายมีเลข 3 ชุดที่ไม่ตรงกันสักชุด: จอ 10MB · client ตัด 5MB · แพลตฟอร์มตัด 4.5MB

**กติกาที่ได้:** เลขที่แสดงต้องอ่านจากตัวเดียวกับที่บังคับจริง (`uploadMaxSize('DOCUMENT')`)
ไม่ใช่พิมพ์ไว้ — ถ้าพิมพ์ไว้ มันจะถูกแก้แยกจากของจริงเสมอ **การรู้กฎไม่ได้แปลว่าจะไม่ละเมิด
ถ้ากฎไม่ได้ถูกบังคับด้วยโครงสร้าง**

### 2.4 ฟิลด์เดียวแบกสองความหมายที่ชนกันพอดี

`ProfileBanner` ตีความ `completionRate === null` ว่า "ร้านใหม่" (แสดงแบนเนอร์เทาแทนไล่สี)
ส่วน `getOrderSummaryForSignIn()` **hardcode `completionRate = null` เสมอโดยตั้งใจ**
เพราะ FR-OSM-11 สั่งไม่ให้โชว์ % บนจอนั้น

⇒ ถ้าเอาค่าจาก query ส่งเข้า `ProfileBanner` ตรง ๆ **ทุกร้านจะกลายเป็น "ร้านใหม่" หมด**
แม้ร้านที่ขายมาเป็นปี — และมันจะดู "ทำงาน" เพราะแบนเนอร์เทาเป็นสถานะที่มีจริง

จับได้เพราะ ux gate อ่านโค้ดของ `ProfileBanner` ก่อนออกสเปก ไม่ได้เดาจากชื่อฟิลด์

**กติกาที่ได้:** ก่อน reuse ฟิลด์เป็นสัญญาณ ให้ถามว่า *ใครเป็นคนเขียนค่านี้ และเขาเขียนด้วย
เจตนาอะไร* — `null` ที่แปลว่า "ไม่มีข้อมูล" กับ `null` ที่แปลว่า "จงใจไม่แสดง" หน้าตาเหมือนกัน

### 2.5 gate ที่ match คำเปล่า ๆ จะแดงถาวรเพราะไฟล์ที่ทำถูกกฎมักอ้างชื่อกฎไว้บนหัว

เกิด **3 ครั้งในรอบเดียว**:
- เทส "ห้ามมี badge ตอบแล้ว" ไปเจอ toast `'บันทึกคำตอบแล้ว'` (มีสตริง `ตอบแล้ว` อยู่ข้างใน)
- เทส "prop ต้องไม่เป็น `stage: string`" ไปเจอคอมเมนต์ที่อธิบายบั๊กเดิมด้วยตัวอักษรเดียวกัน
- theme-guard HR7 แดงเพราะคอมเมนต์ที่อธิบาย `text-[13px]` ที่ถูกลบไปแล้ว

CLAUDE.md บันทึกบทเรียนนี้ไว้แล้วตั้งแต่ HR9 (2026-08-02→03) — **การมีบทเรียนเป็นเอกสาร
กันการเกิดซ้ำไม่ได้** สิ่งที่กันได้คือ helper: ทุกเทสที่สแกนซอร์สในรอบนี้ตัดคอมเมนต์ก่อนตรวจ

### 2.6 critique จับได้ในสิ่งที่ gate อัตโนมัติทุกตัวผ่านหมด

รอบผู้ซื้อ **16/40** — ต่ำสุดเท่าที่เคยรัน. ทุกข้อผ่าน `tsc` + `build` + detector + theme-guard
+ grep gate เพราะแต่ละจุดเป็นโค้ดที่ถูกต้องตามชนิดทุกตัวอักษร **สิ่งที่ผิดคือความหมาย**

## 5. สิ่งที่ควรทำต่างออกไปรอบหน้า

1. **prop ที่รับค่าจาก enum ต้องพิมพ์เป็น union เสมอ** — `string` คือการปิดตาให้ `tsc`
   ในจุดที่มันช่วยได้ดีที่สุด
2. **สองจอที่ต้องแสดงของเดียวกัน ให้ import ตารางเดียวกันตั้งแต่บรรทัดแรก** ไม่ใช่ก็อปแล้ว
   เขียนคอมเมนต์ว่า "ยกมา 1:1"
3. **ตัวเลขที่แสดงบนจอต้องอ่านจากตัวที่บังคับจริง** — ค่าคงที่ที่พิมพ์ซ้ำจะถูกแก้แยกกันเสมอ
4. **รัน critique ก่อนประกาศว่าเสร็จ ไม่ใช่หลัง** — รอบนี้ทั้ง 2 รอบเจอ P0 ที่ ship ไปแล้ว
5. เทสที่สแกนซอร์ส **ตัดคอมเมนต์ก่อนตรวจเสมอ** (ทำเป็น helper ไปแล้ว)
