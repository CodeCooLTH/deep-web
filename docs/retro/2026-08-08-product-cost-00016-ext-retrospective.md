## 1. Problems

### P-1 🛑 นิยาม "กำไร" ที่ชนกันเองในไฟล์เดียวกับที่ import มาใช้ (P0 ของ critique)

การ์ดกำไรรายออเดอร์คำนวณ `totalAmount − Σ(cost×qty)` แล้วเรียกตัวเองว่า **"กำไรจากใบนี้"** โดยที่ `totalAmount` **รวม VAT** และ **ไม่หักค่าใช้จ่ายเลย**

ขณะที่ `NET_PROFIT_FORMULA` ประกาศว่า `กำไรสุทธิ = ยอดขายที่ยืนยันแล้ว − ต้นทุนสินค้า − ค่าใช้จ่าย` — และมันอยู่ใน `src/lib/format-money.ts` ซึ่งเป็น **ไฟล์เดียวกับที่การ์ดนี้ `import { formatBaht }` มาใช้**

หลักฐาน: `src/lib/format-money.ts:50` vs `OrderProfitCard.tsx` ก่อน `a247cf0a`

**ไม่มีชั้นไหนจับได้เลย** — tsc ผ่าน, build ผ่าน, detector 0 finding, grep ไม่มีอะไรให้ grep เพราะทั้งสองฝั่ง "ถูก" ในตัวเอง จับได้จาก `/impeccable critique` (dual-agent) เท่านั้น

### P-2 🛑 เอกสาร 2 ไฟล์เสียหายทั้งไฟล์บน `main` มา 6 วัน โดยไม่มีใครรู้

| # | ปัญหา | ทำไม |
|---|---|---|
| P-1 | นิยามชนกัน | เขียน SRS โดย**นิยามสูตรขึ้นใหม่** แทนที่จะ grep หาว่าโดเมนนี้มีนิยามอยู่แล้วหรือยัง — และไฟล์ที่มีนิยามเดิมคือไฟล์ที่ตัวเอง import มาใช้ในบรรทัดถัดไป ระยะห่างทางสายตา = 0 แต่ไม่ได้มอง |
| P-1 | ไม่มีชั้นไหนจับ | ทุก gate ของโปรเจกต์ตรวจ **รูปแบบ** (type, class, import, สตริงที่ห้าม) ไม่มีอันไหนตรวจ **ความหมาย** — "คำนี้แปลว่าอะไรในระบบนี้" ไม่ใช่สิ่งที่ regex ตอบได้ |

| P-3 | สเปกขัดโค้ด | เขียนสเปกจาก "สิ่งที่ควรเป็น" โดยไม่เปิดไฟล์ที่สเปกนั้นสั่งให้แก้ — ทั้ง 3 จุดเห็นได้ทันทีถ้าเปิดไฟล์ก่อนเขียน |
| P-4 | คอนทราสต์ตกโดยไม่มีใครเห็น | คอนทราสต์เป็น **ผลลัพธ์ของคู่สี ไม่ใช่คุณสมบัติของ class** — `text-warning` ถูกต้องตามกฎธีมทุกประการ มันตกเฉพาะเมื่อไปอยู่บน `bg-warning/10` ซึ่งไม่มี grep ไหนเห็นความสัมพันธ์นั้น |

| P-6 | rebase สะอาดแต่ผิด | git ตรวจ **บรรทัดที่ชนกัน** ไม่ได้ตรวจ **แพตเทิร์นที่ควรเหมือนกัน** — โค้ดที่เขียนคู่ขนานจากต้นแบบเดียวกันจะ diverge เงียบ ๆ เมื่ออีกฝั่งแก้ต้นแบบ |
| P-7 | agent ล้ม | ปล่อยให้ agent ตัวเดียวรับงานที่ต้องอ่าน 70+ ไฟล์ ทำให้ context โตจนคุยกับ API ไม่รอด |

## 3. Conventions to adopt

### C-1 🛑 ก่อนนิยามสูตร/ค่าคงที่ของโดเมน ให้ grep หานิยามเดิมในไฟล์ที่กำลังจะ import

**กฎ:** เมื่อจะเขียน "X = A − B" ที่เป็นศัพท์ธุรกิจ (กำไร ยอดขาย ต้นทุน ส่วนลด ค่าธรรมเนียม) **ห้ามนิยามขึ้นใหม่ก่อนทำ 2 อย่าง:**
1. `rg -n "FORMULA|_TOTAL|คำนั้นเป็นภาษาไทย" src/lib/ src/services/` — หาว่ามีนิยามอยู่แล้วไหม
2. เปิดไฟล์ที่กำลังจะ `import` อ่านให้จบ — นิยามที่ชนกันมักอยู่ในไฟล์เดียวกับ helper ที่เรากำลังหยิบ

**ถ้ามีนิยามเดิมและของใหม่ต่างจริง:** ต้อง (ก) ตั้งชื่อที่ต่างกันชัด (`GROSS_` vs `NET_`) (ข) วางไว้ **ติดกันในไฟล์เดียวกัน** (ค) เขียนคอมเมนต์บอกว่าต่างกันตรงไหนและทำไมผลรวมของสองอันจะไม่เท่ากัน

→ `docs/conventions/domain-term-single-definition.md`

### C-2 🛑 แก้ไฟล์ `.md` ด้วยสคริปต์ ต้องนับ heading ทันทีหลังเขียน

```bash
awk '/^#/{c++} END{print c+0}' <file>   # ได้ 0 ทั้งที่ไฟล์ยาว = เสียหาย
```
**ก่อนเขียนต่อท้ายเอกสารเก่าก็ต้องนับก่อนเช่นกัน** — ไม่มีชั้นไหนในระบบตรวจ `.md` เลย

กู้: หา prefix ที่ยาวที่สุดที่ทุกบรรทัดมีร่วมกัน ตัดทิ้ง แล้ว **พิสูจน์ว่าเนื้อหาไม่หายด้วย `git diff <commit-ก่อนพัง>^`**

### C-3 🛑 rebase ที่ผ่านสะอาด **ไม่ใช่** หลักฐานว่าปลอดภัย — ถ้ามีไฟล์ทับกัน ต้องอ่าน diff ของอีกฝั่งในไฟล์นั้น

```bash
comm -12 <(git diff --name-only origin/main...HEAD | sort) \
         <(git diff --name-only HEAD...origin/main | sort)   # ไฟล์ที่ทั้งสองฝั่งแตะ
git log --oneline HEAD..origin/main -- <ไฟล์นั้น>            # เขาแก้อะไร
git diff HEAD...origin/main -- <ไฟล์นั้น>                    # แก้ยังไง
```

เหตุผล: git ตรวจบรรทัดที่ชนกัน ไม่ได้ตรวจ **แพตเทิร์นที่ควรเหมือนกัน** — โค้ดที่เราเขียนคู่ขนานโดยก็อปต้นแบบจากไฟล์นั้น จะกลายเป็นเวอร์ชันก่อนแก้ทันทีที่อีกฝั่งแก้ต้นแบบ **โดยไม่มี conflict**

→ `docs/conventions/rebase-clean-is-not-safe.md`

### C-4 คอนทราสต์ต้องคำนวณจากคู่สีจริง ไม่ใช่ตรวจว่า class ถูกกฎ

`text-warning` ถูกต้องตามกฎธีมทุกประการ แต่ตกเกณฑ์ที่ 1.58:1 เมื่ออยู่บน `bg-warning/10` — **ไม่มี grep ไหนเห็นความสัมพันธ์ระหว่าง 2 class นี้**

**กฎ:** ข้อความ/ไอคอนบนพื้น tint (`/10` `/15`) ต้องใช้ `-ink` เสมอ ไม่ใช่ semantic ดิบ · เมื่อสงสัย ให้คำนวณ (blend tint บนพื้นการ์ดก่อน แล้วหา ratio) **ทั้งโหมดสว่างและมืด**

เพิ่มลง `docs/conventions/contrast-fix-keeps-hue.md` (มีอยู่แล้ว — ขยาย ไม่สร้างใหม่)

### C-5 token ที่ใช้เป็นทั้งสีพื้นและสีข้อความ แก้คอนทราสต์ด้วยการ redefine ไม่ได้

`--color-primary` ถูกใช้เป็น `bg-primary` ใน **209 ไฟล์** — redefine ให้อ่อนลงเพื่อแก้ `text-primary` บนพื้นเข้ม จะทำให้ปุ่มหลักทั้งแอปกลายเป็นพื้นอ่อนตัวอักษรขาว = แย่กว่าเดิม

**กฎ:** ก่อนแก้ค่า token ให้ `rg -c "bg-<token>|text-<token>|border-<token>" src/` — ถ้าถูกใช้เกิน 1 บทบาท **ห้ามแก้ค่า** ต้องแยก token หรือแก้ที่ระดับ class

## 4. What went right (ทำซ้ำ)

1. **สำรวจก่อนสร้าง** — ถ้าเริ่ม implement ตามคำสั่งตรง ๆ จะได้ฟีเจอร์ซ้ำทั้งก้อนกับของที่อยู่บน prod แล้ว การใช้ 5 นาทีแรก grep หาว่า "มันมีอยู่แล้วไหม" คุ้มที่สุดในทั้ง phase
2. **`/impeccable critique` แบบ dual-agent จับ P0 ที่ทุก gate อัตโนมัติมองไม่เห็น** — และ agent B ที่ถูกสั่งให้ **คำนวณเลขเอง** (ไม่ใช่ "ดูว่าดูดีไหม") ให้ผลที่ตรวจสอบได้ ตัวเลขที่มันคำนวณ cross-check กับที่ทีมเคยวัดจากจอจริงตรงกัน ±0.07
3. **mutation test เทสที่เพิ่งเขียน** — ลบบรรทัด guard ออกแล้วรัน: แดง 1 ข้อ (อีก 5 เขียว = ไม่ได้แดงมั่ว) คืนโค้ดแล้วเขียวครบ **เทสที่ผ่านแต่จับ regression ไม่ได้ไม่มีค่า**
4. **git blame ก่อนอ้างว่าเป็นหนี้เก่า** — ยืนยันทุกบรรทัดว่าไม่มีจุดไหนมาจากงานรอบนี้ แทนที่จะบอกลอย ๆ ว่า "น่าจะของเดิม"
5. **เทียบเทสแดงกับ baseline ด้วย worktree จริง** — สร้าง worktree ที่ `origin/main` รัน suite เดียวกัน ได้ 30 ไฟล์/98 เทสแดงเท่ากันเป๊ะ และ `comm` ชุดชื่อไฟล์ตรงกันทั้งหมด → พิสูจน์ได้ว่าไม่ใช่ของเรา
6. **verify หลัง rebase เสมอ และเช็ค fast-forward ซ้ำก่อน push** — จับได้ 3 อย่างคนละชนิดในรอบเดียว: Prisma client เก่า (build ล้ม), มีคน push แทรกตอน build, และ P-6
7. **ปฏิเสธข้อเสนอของ agent เมื่อ blast radius ไม่คุ้ม** — agent เสนอ redefine `--color-primary` ผมเช็คก่อนว่ามันถูกใช้กี่ที่แล้วปฏิเสธพร้อมเหตุผล แทนที่จะทำตาม
8. **ยืนยันชื่อ icon ด้วยการ grep ว่ามีใช้จริง** ก่อนใส่ทุกตัว (`calculator` 4 ไฟล์, `minus` 5, `chevron-right` 21) — spec เองเตือนว่า `calculator-off` ยังไม่เคยถูกใช้ จึงไม่ใช้
