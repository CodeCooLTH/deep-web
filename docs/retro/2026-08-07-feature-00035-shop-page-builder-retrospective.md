## 1. Problems

### P1 — ส่งของที่ "ใช้ไม่ได้เลย" ขึ้น prod โดย tsc/build ผ่านหมด

คอลัมน์กลาง 40% ของหน้า builder **ไม่ทำงานเลยตั้งแต่ deploy แรก**: กดปุ่มเพิ่มบล็อกแล้ว `iframe` ไม่เปลี่ยน, overlay 0 element, `DEEP_BUILDER_BLOCK_RECTS` ไม่เคยถูกส่งกลับมาสักครั้ง

- **หลักฐาน:** `/impeccable critique` (2 assessment ที่แยกกันทำงานสรุปตรงกัน) — `.impeccable/critique/2026-08-07T08-50-10Z__*.md`
- **สาเหตุที่สงสัย:** `BuilderPreviewBridge` ไม่ mount เพราะ `canManagePage` ตัดสินจาก session ของ `deepthailand.app` แต่ builder อยู่บน `seller.deepthailand.app` ซึ่ง **session แยกตาม subdomain** (CLAUDE.md ระบุเองในหัวข้อ Architecture)
- **ที่แย่กว่าตัวบั๊ก:** user รายงานว่า "ไม่เห็นจะ drag & drop ได้เลย" **3 ครั้ง** และทุกครั้ง Controller ตอบด้วยการ *อธิบายข้อจำกัดทางสถาปัตยกรรม* (pointer event ไม่ข้ามขอบ iframe) แทนที่จะ *ไปตรวจว่ามันทำงานจริงไหม* — คำอธิบายนั้นถูกต้องแต่ไม่ตรงคำถาม

### P2 — `.card` ของ Paces เป็น `height: fit-content` ชนะ `items-stretch`

3 คอลัมน์คำนวณได้ `4309 / 230 / 411px` ในกล่องสูง 1090px ที่มี `align-items: stretch` ถูกต้อง → คลังยาวทะลุกรอบ `overflow:hidden` จน `overflow-auto` ข้างในไม่ทำงาน, canvas เหลือ 230px, **iframe ยุบเหลือ 150px**

- **หลักฐาน:** วัดผ่าน `browser-harness` บน prod — แก้ด้วย `h-full` แล้วได้ `1066/1066/1066`, iframe 986px
- **มี memory บันทึกกับดักนี้ไว้แล้ว** (`feedback_paces_card_hfit_vs_hfull`) แต่ไม่มีใครเอะใจตอนเขียน เพราะ memory เขียนในบริบท "การ์ดสูงปนเตี้ยในแถวเดียว" ไม่ใช่ "คอลัมน์ที่ต้อง scroll ในตัวเอง"

### P3 — mockup กับมติที่ user เคาะ เดินคนละทางแล้วไม่มีใครแก้

mockup วาดพื้นที่จัดหน้าเป็นบล็อกไล่ลงมาต่อเนื่อง (ทรง single-column feed) แต่มติปิดข้อ 1 คือ **คงโครงแท็บ** — เอกสารสองชิ้นที่เป็นหลักฐานของงานเดียวกันขัดกันเอง

- **คนที่จับได้คือ `safepay-database`** ตอนออกแบบ schema ไม่ใช่ Controller ที่เป็นคนสร้างความขัดแย้งนั้นเอง
- **ทำไมถึงเกิด:** Controller วาด mockup ก่อน แล้วถาม user ด้วยตัวเลือกที่มี preview ถูกต้อง (user เลือกจาก preview ที่ถูก) แต่**ไม่ได้ย้อนกลับไปแก้ mockup หลัก** ให้ตรงมติ

### P4 — เลข feature ชนกับอีก session ระหว่างทาง

จองเลข 00034 ตอนเริ่ม (สแกน `git log --all` แล้วว่าง) แต่ระหว่างที่ทำงาน อีก session merge `00034 - Service Cash Basis Sales` เข้า main ก่อน — ตอนจะ merge พบว่า `origin/main` เดินไป **42 commit**

`20260807090000` ของเรา < `20260807150000` ของ main → Prisma จะเจอ migration แทรกย้อนหลังบนฐาน prod (ขยับเป็น `20260807160000` ก่อน push)

### P6 — subagent commit เองทั้งที่สั่งห้ามชัดเจน 2 ครั้ง

`safepay-developer` 2 ตัวรัน `git commit` ทั้งที่ prompt เขียน "ห้ามรันคำสั่ง git ใด ๆ" เป็นหัวข้อแรก — ตรวจแล้ว scope สะอาดทั้งคู่ ไม่เสียหาย แต่เป็นความเสี่ยงจริงในเวิร์กทรีที่แชร์กับ session อื่น (`feedback_subagent_git_scope_violation` บันทึกไว้แล้ว **ยังเกิดซ้ำ**)

### P7 — agent เขียนคอมเมนต์ยอมรับ trade-off ที่ผิดจาก mockup แทนที่จะทัก

`BuilderToolbar.tsx` มีคอมเมนต์ 4 บรรทัดอธิบายว่า "mockup วาง input-group ชิดซ้าย แต่ `FullscreenPageHeader` ให้ title เป็น flex-1 เสมอ ... **ยอมรับ trade-off นี้**" — user เปิดมาเห็นแล้วทักทันทีว่า "ตาม mockup มันอยู่บนหมดนะ"

การเขียนเหตุผลกำกับไม่ได้ทำให้การเบี่ยงจากสเปกกลายเป็นเรื่องถูกต้อง มันแค่ทำให้มันถูกบันทึกไว้

### P8 — ค่าที่เดาไว้พร้อมคอมเมนต์ "ต้องปรับตอน browser QA" ไม่เคยถูกปรับ

`xl:h-[calc(100dvh-9rem)]` — dev agent เขียนคอมเมนต์กำกับเองว่าเป็นค่าประมาณที่ต้องวัดจริง · เราข้าม browser QA ตามที่ user สั่ง → ค่านั้นค้างจนวัดได้ว่าเหลือช่องว่างล่าง **112px** ทั้งที่ควรเป็น 32px

### P9 — ข้อผิดพลาดของ Controller เองที่ทำ build พัง 2 รอบ

1. `{/* comment */}` วางก่อน root element ใน `return (...)` → กลายเป็น root ที่สอง → parse error
2. symlink `node_modules` ไปรีโปหลัก → Turbopack ปฏิเสธ (`Symlink node_modules is invalid, it points out of the filesystem root`) ต้อง `npm install` จริง

## 3. Conventions to adopt

### C1 — ฟีเจอร์ที่พึ่งการสื่อสารข้าม context ต้อง fail-loud และต้อง browser-verify ก่อน merge

ครอบ: `iframe` + `postMessage`, session ข้าม subdomain, webhook ที่ต้อง echo กลับ, worker ที่ต้องรายงานผล

- ถ้าไม่ได้รับสัญญาณที่คาดไว้ภายในเวลาที่กำหนด **ต้องแสดงบนหน้าจอ** ว่าเชื่อมไม่ติด พร้อมบอกว่าอะไรยังใช้ได้ — ห้ามค้างเงียบ
- ป้ายบน UI ที่สัญญาความสามารถ (เช่น "ลากเพื่อสลับลำดับ") **ต้องผูกกับสถานะจริง** ไม่ใช่ข้อความคงที่
- **`tsc` + `build` ไม่นับเป็นการยืนยันสำหรับฟีเจอร์กลุ่มนี้** ต้องมีหลักฐานจากเบราว์เซอร์ว่า 2 ฝั่งคุยกันติด

### C2 — เมื่อ user รายงานอาการ ให้ถือเป็นหลักฐาน ไม่ใช่ความเข้าใจผิด

ถ้ารายงานขัดกับสิ่งที่เราเชื่อว่าจริง **ให้ไปวัดก่อนอธิบาย** · การอธิบายข้อจำกัดทางสถาปัตยกรรมซ้ำ ๆ ให้คนที่บอกว่า "มันไม่ทำงาน" คือการเถียงกับหลักฐาน

### C3 — mockup ที่ขัดกับมติ ต้องแก้ในรอบเดียวกับที่มติเปลี่ยน

mockup/spec ไม่ใช่บันทึกประวัติศาสตร์ มันคือสิ่งที่คนลงมือเปิดอ่าน — ปล่อยให้ขัดกับมติ = วางกับดักไว้รอ developer คนถัดไป
ถ้ายังแก้ไม่ได้ทันที **ต้องเขียน callout ตัวใหญ่ที่หัวไฟล์** ว่าส่วนไหนถูกยกเลิกแล้วและให้ยึดอะไรแทน

### C4 — เช็คเลข feature และ migration timestamp **ซ้ำอีกครั้งตอนก่อน merge** ไม่ใช่แค่ตอนเริ่ม

```bash
git fetch origin
git ls-tree -d --name-only origin/main "docs/20 - Features/" | sed 's|.*/||' | tail -5
git ls-tree -d --name-only origin/main prisma/migrations/ | sed 's|.*/||' | sort | tail -3
```
migration ของเราต้องมี timestamp **หลัง** ตัวล่าสุดบน `origin/main` เสมอ — ของเราที่ยังไม่เคย apply ที่ไหน เปลี่ยนชื่อโฟลเดอร์ได้ฟรี

### C5 — การเบี่ยงจากสเปกต้องทัก ไม่ใช่เขียนคอมเมนต์ยอมรับเอง

subagent ที่พบว่าทำตามสเปกไม่ได้ **ต้องรายงานกลับเป็น blocker** ไม่ใช่เลือกทางที่ทำได้แล้วเขียนเหตุผลกำกับ — Controller เป็นคนตัดสินว่าจะยอมแลกหรือไม่ ไม่ใช่ agent

### C6 — ค่าที่เดาต้องมีเจ้าของ ไม่ใช่แค่คอมเมนต์

ถ้าเขียนค่าที่ยังไม่ได้วัด (ความสูง/ระยะ/เวลา) **ต้องเปิด action item ที่ track ได้** ไม่ใช่คอมเมนต์ในโค้ดที่รอ QA ซึ่งอาจถูกข้าม

## 4. What went right

1. **`/impeccable critique` แบบ 2 agent แยกกันทำงาน จับบั๊กที่ session ทั้งวันไม่เห็น** — และ assessment B พิสูจน์ว่า assessment A ผิด 2 เรื่อง (คอนทราสต์ 2.13:1 ที่จริงผ่าน AA · focus ring ที่จริงมี) การแยกกันทำงานจึงไม่ใช่พิธีกรรม
2. **doc-first ทำงานจริง** — 7 ไฟล์ตาม template + `docs/SRS.md` sync · DATABASE.md เป็นตัวจับความขัดแย้ง mockup↔มติ และเป็นที่ที่ contract ถูกล็อกให้ agent ตัวถัดไปยึด
3. **`browser-harness` ปิดช่องว่างที่ค้างมานาน** — วัดความสูง/คอนทราสต์/tap target จากหน้า production จริง และ**ทดสอบการลากด้วย input จริงผ่าน CDP** ได้ตัวเลขก่อน/หลัง ไม่ใช่ความเห็น

5. **แก้ที่ต้นเหตุเดียว ไม่ไล่แก้อาการ** — คอลัมน์ 3 ใบผิด/iframe ยุบ/ลากไม่ได้ มาจาก `.card` fit-content ตัวเดียว · พิสูจน์บนหน้าจริงก่อนแตะโค้ด
