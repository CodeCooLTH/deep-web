## 1. ปัญหา: แพตช์รอบเช้าปิดเงื่อนไขเดียวจากสองเงื่อนไข

**อาการ (user report + ภาพหน้าจอ 14:13 น.):** ร้าน BT Premium (`vertical=SERVICE_QUEUE`) กดบันทึก
"การเข้ารับบริการ" แล้วขึ้น `บันทึกไม่ได้ — ที่อยู่จัดส่งยังไม่ครบ` ทั้งที่ลูกค้าขับรถมาที่ร้าน
ทั้งที่แพตช์ `936ab241` เมื่อ 11:48 น. ของวันเดียวกันแก้เรื่องนี้ไปแล้ว

**หลักฐาน (query ฐาน prod ก่อนตั้งสมมติฐาน):**

| สินค้าของ BT Premium | fulfillmentMode | createdAt |
|---|---|---|
| I AM Prisim | **SHIPPED** | 2026-08-07 |
| ติดตั้งไฟหน้า | NO_SHIPPING | 2026-07-31 |

**Root cause:** เกณฑ์ "ออเดอร์นี้ต้องจัดส่งไหม" เป็น OR ของ 2 ข้อ

```
fulfillmentMode = SHIPPED  ⟸  (รายการพิมพ์เอง ∧ type=PHYSICAL)  ∨  (มีสินค้าที่ Product.fulfillmentMode=SHIPPED)
```

แพตช์รอบเช้าเติม `&& shipsGoods` ให้ **operand ซ้ายอย่างเดียว** — repro ที่ user รายงาน
(พิมพ์รายการเอง) จึงหายจริง แต่พอร้านเลือกสินค้าจากแคตตาล็อกในใบถัดไป operand ขวายิงแทน
ผลลัพธ์รวมเหมือนเดิมทุกประการ

**ทำไมร้านบริการมีสินค้าติดธง SHIPPED ได้ตั้งแต่แรก** — 2 ทาง ทั้งคู่ไม่มีใครเห็น:
1. **Quick-Create ใน `createOrder`/`updateOrder` เขียนคอลัมน์ตรง ๆ** ด้วย
   `data.type === "PHYSICAL" ? "SHIPPED" : "NO_SHIPPING"` ไม่ผ่าน `resolveFulfillmentMode`
   ซึ่งเป็น SSOT ที่ประกาศไว้ตั้งแต่ feature 00030 (BR-BKU-13) ว่า "ร้าน SERVICE_QUEUE →
   NO_SHIPPING เสมอ ไม่ว่า caller ส่งอะไรมา" — **ตัวล็อกล็อกได้เฉพาะคนที่เดินผ่านประตู**
   ร้านพิมพ์รายการเอง 1 ครั้ง = ได้สินค้าติดธงค้างในแคตตาล็อกถาวร
2. ร้านที่สร้างสินค้าไว้ตอนยังเป็น `ONLINE_SALES` แล้วเปลี่ยน vertical ทีหลัง (BT เปลี่ยนที่ DB
   2026-08-05) — ธงบนสินค้าเก่าไม่ถูกย้อนแก้

**และยังพบว่า `updateOrder` ไม่เคยมีด่านนี้เลยแม้แต่ชั้นแรก** — ร้านบริการที่กด "แก้ไข" ใบที่
สร้างสำเร็จไปแล้วจะโดนบังคับที่อยู่ทุกครั้ง (บั๊กคนละใบที่ไม่มีใครรายงานเพราะยังไม่มีใครไปถึง)

**สิ่งที่ทำ:** กั้นด้วย `shopShipsGoods` ทั้ง 4 จุด (createOrder 2 ชั้น · updateOrder 2 ชั้น ·
Quick-Create ทั้ง 2 ที่ · ฟอร์มฝั่งจอ) + migration ล้างธงที่ค้าง (prod 1 แถว)

## 2. ปัญหา: `truncate` ที่ใส่ถูกแล้วไม่ทำงาน เพราะ flex ตัดสิน wrap ก่อนหด

**อาการ:** ชื่อลูกค้า + ชิปชื่อเพจยาว → ปุ่ม "ข้อมูลลูกค้า" ตกไปบรรทัดสองของหัวเธรด หัวสูงผิดรูป

**Root cause:** `.card-header` ของ Paces เป็น `flex flex-wrap` และ flexbox **ตัดสินว่าจะ wrap ไหม
จากขนาด hypothetical (เนื้อหาเต็มก่อนหด)** ไม่ใช่ขนาดหลัง shrink. โครงสร้างมี `min-w-0` ครบสาย
อยู่แล้ว และชิปมี `truncate` ในตัว — แต่ทั้งหมดนั้นทำงาน *หลัง* browser ตัดสินใจ wrap ไปแล้ว
เพิ่ม `truncate` ให้ `<h5>` เฉย ๆ จึงไม่มีผลเลย ต้อง `flex-nowrap` ก่อน กลไกที่มีอยู่ถึงจะได้ทำงาน

**บทเรียนที่กว้างกว่านั้น:** "โค้ดมี `min-w-0` + `truncate` ครบแล้ว" ไม่ใช่หลักฐานว่าของจะหด —
ต้องดูว่า **container ยอมให้หดหรือเปล่า** ก่อน

## 3. ปัญหา: แถบเครื่องมือแชทล้นขอบจอ — ย่อคำอย่างเดียวแก้ไม่ได้

**อาการ:** ที่ ~390px ปุ่มสร้างออเดอร์ท้ายแถบถูกตัดหายครึ่งคำ

**Root cause + วิธีตัดสิน:** คำนวณงบพื้นที่ที่ 320px (จอแคบสุดที่ต้องรองรับ) — container หลัง
`px-4` = 288px, ปุ่มไอคอน 6 ตัว (`btn btn-icon` = 37px) + gap 4px×5 = 242px **เหลือ 46px** ให้ปุ่ม
ที่มีกติกาบังคับว่าต้องมีข้อความเสมอ (ไอคอนเปล่าเคยทำให้ user หาปุ่มไม่เจอ 2026-08-01) →
ตัวเลขบอกเองว่าการย่อคำแก้ไม่ได้ ต้องลดจำนวนไอคอนที่โชว์ตรง ๆ

**สิ่งที่ทำ:** <768px ยุบเครื่องมือรอง 4 ตัวเข้าเมนู "เพิ่มเติม" (`⋯`) · ≥768px ปุ่มสร้างออเดอร์
หายไปเองอยู่แล้ว (`md:hidden`) แถวจึงว่างพอให้ทุกปุ่มอยู่ครบ — เดสก์ท็อปไม่เสียการกด 1 ครั้ง

**กับดักที่เกือบพลาดตอนแยกตาม breakpoint:** แผงอิโมจิ/สติกเกอร์เป็น `absolute` ที่ยึด parent
(ไม่ใช่ portal) ถ้าซ่อน "กล่องยึด" ที่ breakpoint ไหน แผงจะหายตามไปด้วยที่ breakpoint นั้น →
ต้องซ่อน **ปุ่ม** ไม่ใช่ซ่อนกล่อง และให้แผงอยู่ที่เดียว ไม่ทำ 2 ชุด

## 4. สิ่งที่ทำถูก (anchor ที่ควรทำซ้ำ)

1. **query ฐาน prod ก่อนตั้งสมมติฐาน** — เจอชื่อสินค้าและวันที่สร้างที่ยืนยันสาเหตุภายในไม่กี่นาที
   แทนที่จะเดาว่า "แพตช์เมื่อเช้าไม่ได้ deploy" (ซึ่งเป็นคำอธิบายที่น่าเชื่อและผิด)
2. **ตรวจว่าคอมมิตอยู่ใน `origin/main` จริงไหมก่อนสรุปว่า "แก้ไปแล้ว"** — `git merge-base --is-ancestor`
   ตัดสมมติฐาน "ยังไม่ขึ้น prod" ทิ้งได้ทันที
3. **ไล่ทางเข้าให้ครบทั้งคลาสหลังเจอ 1 จุด** — เจอที่ `createOrder` แล้วไปเปิด `updateOrder` ด้วย
   จึงเจอบั๊กที่ยังไม่มีใครรายงาน
4. **ux gate ทักคำที่ user สั่ง** ("บริการ" ซ้ำกับหัวข้อ "วันเข้าใช้บริการ" ที่อยู่เหนือมันพอดี)
   → Controller ยึดคำที่ user ชี้หน้าจอสั่ง แล้ว**บันทึกข้อทักไว้ในคอมมิต** ไม่ใช่เงียบไปข้างใดข้างหนึ่ง

## 5. Conventions to adopt

1. **กฎที่เป็น OR ต้องกั้นที่ผลลัพธ์ ไม่ใช่ที่ operand เดียว** — ถ้าปิด operand หนึ่งแล้ว repro หาย
   นั่นแปลว่า repro หาย ไม่ได้แปลว่ากฎถูก ต้องไล่ทุก operand + ทุกทางเข้าที่คำนวณค่าเดียวกัน
   → `docs/conventions/stored-flag-vs-owner-truth.md`
2. **ธงที่เก็บในแถวข้อมูล ≠ ความจริงปัจจุบันของเจ้าของแถว** — `Product.fulfillmentMode` คือภาพนิ่ง
   ณ เวลาที่เขียน; อำนาจตัดสินอยู่ที่ `Shop.vertical` วันนี้ ไม่ใช่ธงที่เขียนไว้เมื่อวาน
   → ไฟล์เดียวกัน
3. **ประกาศ SSOT ของคอลัมน์ไหน ต้อง grep "ชื่อคอลัมน์" ไม่ใช่ grep "ชื่อฟังก์ชัน"** — ตัวที่หลบ
   SSOT คือตัวที่ไม่ได้เรียกมัน จึงไม่โผล่ในผลค้นหาที่ทุกคนใช้ตรวจ
   → ไฟล์เดียวกัน
4. **`min-w-0`/`truncate` ครบไม่ได้แปลว่าของจะหด — ดู container ก่อน** (flex-wrap ตัดสินจากขนาด
   ก่อนหด) → `docs/conventions/flex-header-truncation.md`
5. **แถวเครื่องมือที่มีปุ่มบังคับมีข้อความ ต้องคำนวณงบพื้นที่ที่จอแคบสุด ก่อนเสนอทางแก้** —
   ย่อคำเป็นทางแก้ที่พิสูจน์ได้ว่าพอหรือไม่พอด้วยเลขคณิต ไม่ใช่ด้วยความรู้สึก → ไฟล์เดียวกัน
6. **popover ที่เป็น `absolute` ยึด parent: ซ่อน "ปุ่ม" ได้ ห้ามซ่อน "กล่องยึด"** → ไฟล์เดียวกัน
