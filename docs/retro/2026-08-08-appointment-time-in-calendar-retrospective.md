## บทเรียนที่ควรเป็นกฎ

### 1. คอมเมนต์ที่ประกาศสมมติฐาน คือหนี้ที่รอวันถูกทวง

`AppointmentDateSheet` เขียนไว้ว่า *"ใช้ viewport breakpoint ได้ตรง ๆ ที่นี่ เพราะชีตนี้เป็น `fixed inset-0` เต็มวิวพอร์ตเสมอ ความกว้างจอ = ความกว้างจริงของมัน"* — เป็นเหตุผลที่ **ถูกต้อง ณ วันที่เขียน** และกลายเป็นเท็จเมื่อมีคนเปิดชีตจากบริบทที่มี `transform` ครอบ

น่าสังเกตว่า `AppointmentBlock.tsx` ในฟีเจอร์เดียวกันเขียนเตือนเรื่องนี้ไว้แล้วเป๊ะ ๆ (*"ห้ามผูก viewport breakpoint"*) **แต่คำเตือนอยู่คนละไฟล์กับที่ละเมิด** คอมเมนต์เตือนคนอ่าน ไม่ได้บังคับโค้ด

> **กติกา:** ใน `(paces)` component ที่เป็น overlay/sheet ให้ใช้ `@container` เป็นค่าตั้งต้น ไม่ใช่ viewport breakpoint — เว้นแต่พิสูจน์ได้ว่ามันไม่มีทางถูก mount ในบริบทที่แคบกว่าจอ ซึ่งพิสูจน์ยากกว่าการใช้ container query ไปเลย

### 2. `tsc` เขียว + build ผ่าน ไม่ได้แปลว่าโค้ดใหม่ถูกเรียก

งาน D เพิ่ม 4 field ครบทุกชั้น — Prisma select, type ของ `CustomerPanelOrder`, return type ของ service, สาขา render ใหม่ใน `OrderCardView` — **แต่ลืมส่ง prop ที่ call site เดียว** (`CustomerPanel.tsx`) ผลคือโค้ดใหม่ทั้งก้อนไม่มีวันทำงานบนเดสก์ท็อป ≥1280px และเพราะทุก prop เป็น `optional` จึงไม่มีอะไรฟ้องเลย

ซ้ำร้ายรอบเดียวกันยัง**ถอดปุ่ม "สร้างพัสดุ" ออกจากจอนั้น** → สุทธิแล้วเดสก์ท็อปแย่ลง ไม่ใช่ดีขึ้น

จับได้ด้วย `/impeccable critique` เท่านั้น (คลาสเดียวกับ `feedback_cross_context_fails_silently`)

> **กติกา:** เพิ่ม field ที่ไหลข้ามหลายชั้น ให้ไล่ **จากปลายทางย้อนกลับ** — เปิด call site ทุกตัวของ component ที่รับ field ใหม่ก่อนถือว่าเสร็จ · field ที่เป็นตัวเปิดสาขา render ควรประกาศเป็น required (รับ `null` ได้) เพื่อบังคับให้ทุก caller ตัดสินใจ แทนที่จะตกหล่นเงียบ

### 3. ย้ายของเข้ามาในจอเดียวกัน ต้องกางงบความสูงก่อน

งาน C ย้ายช่องเวลาเข้าไปอยู่ในชีตเพื่อให้เห็นคิวของวันนั้นขณะเลือกเวลา — แต่ส่วนที่ย้ายเข้าไปเป็น `shrink-0` สูง ~198px ในคอลัมน์ที่เหลือ ~219px **รายการคิว (สิ่งที่ทั้งงานนี้ทำมาเพื่อมัน) จึงถูกบีบเหลือ 0px** บนมือถือและในหน้าต่างแชท

ผลคือกลับไปเดาเวลาเหมือนก่อนแก้ โดยที่จอ "ดูครบ" ทุกอย่าง — `min-h-40` ที่ตั้งใจการันตีพื้นที่ ปกป้อง**คอลัมน์** ไม่ได้ปกป้อง**รายการ**

> **กติกา:** จอที่มี ≥3 ส่วนแย่งความสูงกันในกล่องความสูงคงที่ ให้กางเลขที่ความกว้าง/ความสูงจริงก่อนเสมอ (390×844 และกล่อง 384px ของหน้าต่างร่างออเดอร์) · ถ้าไม่พอ ให้ **เลื่อน** ดีกว่า **บีบ** — ของที่ถูกบีบจนหายไม่มีอะไรฟ้อง

### 4. แก้ป้ายอย่างเดียวไม่พอ ถ้าตัวกรองใช้เกณฑ์เดียวกัน

อาการ D อ่านเหมือน "คำผิด" แต่ตัวเลือกใบก็ใช้แกนเดียวกัน ถ้าแก้แค่ป้าย ร้านจะได้คำที่ถูกบนรายการที่ยังผิด (ออเดอร์บริการค้างตลอดกาล)

> **กติกา:** เมื่อเจอป้ายที่พูดผิดโดเมน ให้ตามไปดูด้วยว่า **ตัวกรอง/ตัวนับ** ใช้เกณฑ์เดียวกันหรือเปล่า — ป้ายกับตัวกรองที่มาจากฟังก์ชันเดียวกันคือของดี จนกระทั่งฟังก์ชันนั้นผิดโดเมน แล้วมันจะผิดพร้อมกันทั้งคู่

### 5. อย่าออกแบบป้ายที่อ้างสิ่งที่ระบบไม่มีทางรู้

user ขอ timeline "มัดจำ → เข้ารับบริการ → สำเร็จ" แต่ schema **ไม่มีคอลัมน์บอกว่ามัดจำถูกจ่ายแล้วหรือยัง** (ตั้งใจ — BR-RSV-49/50 ไม่กั้นคิวด้วยมัดจำ) ถ้าทำเป็นขั้นที่ติ๊กถูกได้ จะเป็นป้ายโกหก **คลาสเดียวกับ "รอเลขพัสดุ" ที่รอบนี้กำลังแก้อยู่พอดี**

ทางออก: แสดง "มัดจำที่ตกลงไว้ ฿X" ล้วน ไม่มีสีเขียว ไม่มีไอคอนถูก + บันทึกเป็น Known Gap ว่าทรงเต็มต้องเพิ่มอะไร

> **กติกา:** ก่อนออกแบบ progress/timeline ให้ถามทีละขั้นว่า "ระบบรู้ได้จากคอลัมน์ไหนว่าขั้นนี้ผ่านแล้ว" — ขั้นที่ตอบไม่ได้ ห้ามวาด

### 6. gate จับสิ่งที่ tsc/build/grep ไม่เห็น — และรอบนี้พิสูจน์อีกครั้ง

ทั้ง 2 ข้อ P0 (ข้อ 2 และ 3 ข้างบน) ผ่าน `tsc` เขียว เทสเขียว detector 0 finding grep gate ผ่านหมด **จับได้ด้วย `/impeccable critique` อย่างเดียว** และ `audit` ตามมาจับได้อีกว่า **เลือกวันในปฏิทินด้วยคีย์บอร์ดไม่ได้เลย** (ตก WCAG ระดับ A ที่งานหลักของจอ) ซึ่งเป็นของที่มีอยู่ก่อนหน้านี้แล้วและไม่มีใครเห็น

รอบนี้เคยเกือบปิดงานโดยรัน critique อย่างเดียว — ซึ่งไม่ครบตาม HR8 (ต้องมี clarify ด้วย, และ audit เมื่อแตะ a11y)

## สิ่งที่ทำได้ดี

- **สำรวจก่อนสร้าง** — อาการ B ฟังเหมือนฟีเจอร์ที่ขาด แต่เป็นค่าตั้งค่าที่หาไม่เจอ ถ้าเริ่ม implement ตามคำสั่งตรง ๆ จะได้ฟีเจอร์ซ้ำทั้งก้อน (บทเรียนเดียวกับ `feedback_feature_may_exist_behind_gate` ที่เพิ่งเจอเมื่อ 08-08 เช้า)
- **ไม่สร้างแกนที่สาม** — แกนสถานะนัดมีอยู่แล้วตั้งแต่ 00036 (`appointment-stage.ts`) และหัวไฟล์เขียนเจตนาไว้ว่า "แต่ละร้านมีแกนเสริมได้แกนเดียว" รอบนี้แค่ทำให้ประโยคนั้นเป็นจริงในห้องแชท
- **เทสที่พิสูจน์แล้วว่าจับ regression ได้จริง** — ปิด guard แล้วแดง 2 ข้อตรงจุด ไม่ใช่เทสเขียวเปล่า ๆ
- **เวิร์กทรีที่แชร์กับอีก session** — commit เฉพาะไฟล์ของตัวเอง และ rebase ใน worktree ชั่วคราวแยก ไม่ stash ไม่แตะงานค้างของเขาเลย
