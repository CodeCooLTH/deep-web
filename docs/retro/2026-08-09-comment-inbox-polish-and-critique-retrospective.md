## 1. Problems — คลาสที่ควรจำ

### P1 — endpoint ที่ล้มเพราะ "ตัวตนของคนที่ถูกถาม" ไม่ใช่ "รูปคำขอ"

`getContactProfile` ฝั่ง Messenger **ไม่เคยลอง User Profile API เลย** เพราะคอมเมนต์ที่เขียนไว้ตั้งแต่
00018 สรุปว่า *"ยิง `GET /{psid}` ตรง ๆ ไม่ได้ ทุกชุด field"* — ข้อสรุปนั้นมาจากการทดสอบกับ **ลูกค้า
อย่างเดียว** วัดใหม่ด้วย token เดียวกัน เพจเดียวกัน: ลูกค้าสุ่ม 30 คน → 400 ครบ 30 · **เจ้าของแอป →
200 พร้อม `profile_pic` ทั้ง 3 เพจ**

error ของ Graph ไม่ช่วยเลย: `code=100 subcode=33` เขียนว่า *"does not exist, cannot be loaded due to
missing permissions, or does not support this operation"* — เหมา 3 สาเหตุที่ต่างกันสิ้นเชิงไว้ในประโยค
เดียว อ่านแล้วเดาไม่ออกว่าตัวแปรคือ subject

**บทเรียน:** ก่อนสรุปว่า endpoint ของ Meta "ใช้ไม่ได้" ต้องทดสอบด้วย subject อย่างน้อย 2 ชนิด
(มี role บนแอป / ไม่มี) — คอมเมนต์ที่เขียนจากการทดสอบชนิดเดียวกลายเป็นข้อเท็จจริงปลอมที่ปิดทาง
คนถัดไปได้เป็นเดือน → `docs/conventions/graph-access-depends-on-subject.md`

### P2 — "โปรเจกต์อื่นทำได้" ไม่ใช่หลักฐานว่าสิทธิ์ต่างกัน

user ชี้ว่า GoChat V3 (`27578841345134305`) แสดงรูปโปรไฟล์ได้ ตรวจแล้วแอปนั้น
`Business Asset User Profile Access` = `REJECTED / access_level: none` **เหมือนกันเป๊ะ** และขอ scope
น้อยกว่าเราด้วยซ้ำ ที่เห็นรูปเพราะคนในจอคือนักพัฒนาที่ทดสอบด้วยบัญชีตัวเอง

เทียบผลลัพธ์บนหน้าจอโดยไม่ดูว่า subject เป็นใคร จะสรุปผิดทั้งกระดาน

### P3 — ผมตอบ user ผิด 2 รอบก่อนจะไปวัด

รอบแรกสรุปว่า "ยื่นรีวิวไม่ได้" ทั้งที่ user แค่จะ **เปิด Standard Access เพื่อทดสอบ** (คนละปุ่มกับ
Submit) รอบสองสรุปว่ารูปดึงไม่ได้เลย ทั้งที่ดึงได้กับ role holder

ทั้งสองรอบเกิดจากการตอบจากเอกสาร/สถานะที่อ่านมา แทนที่จะยิงของจริงก่อน — memory
`feedback_verify_dont_assume` มีอยู่แล้วและยังพลาดซ้ำ

### P4 — ปิดบั๊กหนึ่งแล้วเปิดกับดักอีกอันที่ถูกกลบไว้

หน้าคอมเมนต์ยิงรายการซ้ำตอน mount ทั้งที่ RSC ส่งมาแล้ว — พอปิด double-fetch นั้น กับดักที่ซ่อนอยู่
เปิดทันที: `rawFetchedRef` init ด้วย `initialCounts.all` (**ยอดทั้งร้าน** ไม่ใช่จำนวนที่ fetch มา)
ซึ่งผิดมาตลอดแต่ถูกเขียนทับด้วย fetch ซ้ำนั้นพอดี ถ้าปิดอย่างเดียวโดยไม่แก้อีกอย่าง ปุ่ม
"โหลดโพสต์เก่ากว่านี้" จะข้ามโพสต์เป็นสิบทันที

**บทเรียน:** บั๊กสองตัวที่กลบกันอยู่ ต้องแก้พร้อมกันเสมอ — การแก้ตัวที่เห็นชัดก่อนคือการปล่อยตัวที่
ซ่อนอยู่ออกมาโดยไม่มีใครรู้

### P5 — SSOT ที่มีผู้บริโภคศูนย์ราย

ผมสร้าง `deriveLogStatus()` พร้อมหัวไฟล์ประกาศว่า "ตัวกรองกับป้ายสถานะต้องใช้เกณฑ์ชุดเดียวกัน" แล้ว
ต่อแค่ฝั่งตัวกรอง — critique รอบถัดมาจับได้ว่า **ไม่มี production code เรียกเลยสักที่** (มีแต่เทส
ของตัวเอง) ถอดออกในวันเดียวกัน

สิ่งที่ซ้ำ *จริง* คือ **คำ** ("ส่งแล้ว/ข้าม/ไม่สำเร็จ" ถูกพิมพ์แยกกันสองที่) ซึ่งเป็น HR16 ตรงตัว —
ย้ายเป็น `LOG_STATUS_META` แล้วให้ทั้ง badge และตัวกรองอ่านตัวเดียว

**บทเรียน:** สิ่งที่กัน drift ได้จริงคือ **การมีผู้เรียกอย่างน้อยสองราย** ไม่ใช่การมีไฟล์ · SSOT ที่
ไม่มีใครเรียกจะเน่าเงียบและเทสมันจะเขียวตลอดไม่ว่าโค้ดจริงทำอะไร

### P6 — คำเตือน 3 อันในไฟล์เดียว ไม่ได้กันอันที่ 4

`CommentsClient.tsx` มีคอมเมนต์ประกาศว่าคลาส "ซ้ายบอก 8 แต่ panel บอก 7" คือบาปมหันต์ **อยู่ 3 ที่**
แล้วบั๊กคลาสเดียวกันยังกลับมาได้: server นับคอมเมนต์ลูกค้าทุกชั้น แต่ client ตัด top-level ของเพจทิ้ง
ทำให้ **ลูกหายไปพร้อมพ่อ** → แถวซ้าย "ยังไม่ตอบ 1" / เธรดว่าง / คำถามลูกค้าตอบไม่ได้เลย

และเครื่องมือนี้สร้างเคสนี้เอง (กดส่งตอนยังไม่เลือกจะตอบใคร = คอมเมนต์ระดับบนของเพจ)

**บทเรียน:** กฎที่ต้องตรงกันสองฝั่งต้องเป็น **ฟังก์ชันบริสุทธิ์ + เทส** ไม่ใช่คอมเมนต์เตือน —
สกัดไป `src/lib/comment-tree-visibility.ts` แล้ว

### P7 — ทางตันบนมือถือที่เกิดจาก "ทำงานสำเร็จ"

`selectedId` ไม่เคยถูกล้างเมื่อโพสต์หลุดจากรายการ และปุ่มย้อนกลับอยู่ **ข้างในกิ่ง `selectedPost`
truthy** → ตอบคอมเมนต์ค้างอันสุดท้ายในแท็บ "ยังไม่ตอบ" → realtime ดึงรายการใหม่ที่ไม่มีโพสต์นั้น →
บนจอ <1024px คอลัมน์ซ้าย `hidden` ไปแล้ว กิ่งที่ render คือกิ่งที่ไม่มีปุ่ม = **ออกไม่ได้เลย**

ทริกเกอร์ไม่ใช่ race หายาก มันคือปลายทางของลูปงานหลักทั้งหน้า

**บทเรียน:** ทางออก (ปุ่มปิด/ย้อนกลับ) ต้องอยู่ **นอก** ternary เสมอ ไม่ผูกกับความสำเร็จของการหา
ข้อมูล · และ "คิวงาน" ไม่ควรกลืนหลักฐานว่างานเสร็จ — ผู้ขายที่เพิ่งตอบเสร็จควรได้อยู่ในเธรดนั้นต่อ

### P8 — ถอนหญ้า 3 รอบเพราะไม่ถอนราก

### P9 — `npx tsc --noEmit | head -N; echo $?` คืน exit ของ `head`

ผมใช้ท่านี้หลายครั้งวันนี้และรายงานว่า "tsc = 0" ทั้งที่ค่านั้นไม่ได้พิสูจน์อะไรเลย
