# Retro — 00080 ขั้นตอนจัดส่งแบบส่งเอง (รอจัดส่ง → จัดส่งแล้ว → ส่งสำเร็จ) · 2026-10-18

ทำในวันเดียวจากคำถามของ user "กรอกเลขพัสดุแมนนวลแล้วสถานะไปอยู่ไหน" → PRD/BRD → โค้ด → E2E → deploy (user สั่ง "deploy เลย")

## สิ่งที่ได้
- ส่งเองแยก 3 ขั้น: บันทึกเลข = "รอจัดส่ง" (คำนวณ ไม่เพิ่มค่า `Order.status`) → "จัดส่งแล้ว" (เลิกทำได้ 5 วิ) → "ส่งสำเร็จ" (Swal · นับเท่าลูกค้ายืนยัน) · ทั้งหน้าออเดอร์และแผงพัสดุแชท
- ตั้งค่าจังหวะแจ้งเลขพัสดุ ON_SAVE | ON_DISPATCH · หน้าลูกค้าซ่อนเลขที่ server · ไทล์/ตัวกรอง/ป้าย/ไทม์ไลน์ "รอจัดส่ง" คำเดียวทุกที่
- migration 4 ตัว (additive) · vitest ทั้ง repo 10.8k ผ่าน (3 แดงเดิมของ main) · Playwright 10/10 กับ dev server จริง · reviewer 2 รอบ + security 1 รอบ + impeccable critique/clarify

## สิ่งที่พลาด / เรียนรู้
1. **นิยาม "มี iShip" มี 2 ตัวในโค้ด** — `LATEST_FORWARD_SHIPMENT` (ไม่ CANCELLED = นับใบ FAILED/dry-run) กับ `ACTIVE_FORWARD_SHIPMENT`/`hasLiveIshipShipment` (CREATED && !dryRun) · developer หยิบตัวแรก ⇒ ร้าน "ส่งเองแทน" หลังเปิด iShip ไม่ผ่านกดปุ่มไม่ได้ ทั้งที่หน้าจอโชว์ปุ่ม (หน้าจอใช้ตัวที่สอง)
   - ต่อไป: งานที่ถามว่า "ใบนี้เป็นของ iShip ไหม" ต้องระบุชื่อนิยามใน prompt ของ developer ตั้งแต่แรก
2. **เปลี่ยนความหมายของสถานะเดิม = ช่องใหม่โผล่ที่จุดที่ไม่ได้แตะ** — "PENDING ⇒ ยังไม่มีเลข" เป็นข้อสันนิษฐานเงียบใน `createShipment` (เปิดพัสดุ iShip ซ้อนได้) · `confirmOrder` (เขียนทับไม่มีเงื่อนไข ชนกับส่งสำเร็จ) · ไทม์ไลน์หน้าลูกค้า (`getOrderTimeline` ขึ้น "รอชำระเงิน") — สองอย่างแรก reviewer จับ · อย่างที่สาม user ทักก่อน deploy
   - ต่อไป: SDS ของงานที่เปลี่ยนความหมายสถานะต้องไล่ "ทุกผู้อ่านสถานะนี้" รวม stepper/ไทม์ไลน์ฝั่งผู้ซื้อ ไม่ใช่แค่ผู้อ่าน stage
3. **Design-Spec สั่งฟังก์ชันวันที่ผิดตัว** (`formatDateTime` แทน `formatDateTimeTH` ที่การ์ดใช้อยู่) ⇒ วันที่ในหน้าเดียวกันสองรูปแบบ — จับได้จากการเปิดภาพ E2E ไม่ใช่จากเทส
   - ต่อไป: spec ที่ระบุ helper ต้องอ่านโค้ดเดิมของบรรทัดนั้นก่อน (sibling-surface-parity)
4. **`next build` ทิ้ง `.next` แล้ว `next dev` ขึ้น Build Error ฟอนต์ทุกหน้า** — E2E แดง 7/7 ครั้งแรกทั้งที่โค้ดไม่ผิด · ลบ `.next` แล้วหาย
5. **Critique จับเรื่อง product ที่เทสจับไม่ได้** — ข้อความ Swal "นับเหมือนลูกค้ายืนยันเอง" สอนพฤติกรรมที่ขัด Positioning · user เลือกคง logic แต่เปลี่ยนคำ
6. **ดีขึ้นจากรอบก่อน**: branch จาก origin/main ตั้งแต่แรก · build/theme-guard/tests ในเครื่องก่อน push · เทสใหม่แยกไฟล์ (แต่ยังต้องแก้ไฟล์ `[blocker]` เดิม 13 ไฟล์ให้รับ key ใหม่ ⇒ ต้องติดป้าย `แตะด่าน`)
