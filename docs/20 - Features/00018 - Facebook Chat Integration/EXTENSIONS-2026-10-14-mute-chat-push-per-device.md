# ปุ่มปิดเสียงในหน้าแชท ปิดเสียงแจ้งเตือนเด้งของเครื่องนั้นด้วย

## BRD — ปัญหาและเป้าหมายทางธุรกิจ

**ปัญหา (ร้านแจ้ง 2026-10-13 พร้อมภาพหน้าจอ):** ร้านกดปุ่มลำโพงบนหน้าแชทเป็น "ปิด" แล้ว แต่แจ้งเตือนแชทใหม่ที่เด้งบนหน้าจอล็อกยังมีเสียง

**ต้นเหตุ:** เสียงมี 2 ทาง และปุ่มคุมได้ทางเดียว

| | เสียงในหน้าแชท | เสียงแจ้งเตือนเด้ง (push) |
|---|---|---|
| ดังเมื่อ | เปิดหน้าแชทค้างไว้ | ปิดแอป / ล็อกจอ |
| ใครเล่น | หน้าเว็บ (`src/lib/chat-sound.ts`) | iOS/Android หลังเซิร์ฟเวอร์ส่ง push มา |
| ปุ่มลำโพงคุม | ✅ (เก็บใน localStorage ของเครื่อง) | ❌ เซิร์ฟเวอร์ไม่รู้ว่ากดปิด |

ป้ายบนปุ่มเขียนว่า **"ปิดเสียงแจ้งเตือนข้อความใหม่"** (`th.ts` `inbox.soundOff`) ร้านจึงเข้าใจตามป้ายว่าแจ้งเตือนจะเงียบด้วย ⇒ ระบบทำไม่ตรงกับที่ปุ่มบอก

**เป้าหมาย:** กดปุ่มเดียว เงียบทั้งสองทาง **เฉพาะเครื่องที่กด** โดยร้านยังเห็นแจ้งเตือนเด้งเหมือนเดิม (ไม่พลาดแชทลูกค้า)

**มติ user (2026-10-14):** เลือกทาง ข. (ไม่ใช่ตัวเลือก "ไม่มีเสียง" ในหน้าบัญชี) · **ยังไม่ทำปุ่มปิดเสียงรายห้องแชท**

## PRD — สิ่งที่ผู้ใช้จะเห็น

| สถานการณ์ | ผลลัพธ์ |
|---|---|
| กดปิดเสียงในแอป Deep Seller บนมือถือ | เสียงในหน้าแชทเงียบ + แจ้งเตือนแชทใหม่ที่เด้งบน **มือถือเครื่องนี้** เงียบ (ยังเด้งขึ้นจอ ยังมีตัวเลขบนไอคอน) |
| กดปิดเสียงบนคอม/เบราว์เซอร์ | เหมือนเดิม: เงียบเฉพาะเสียงในหน้าแชทของคอมเครื่องนั้น (คอมไม่มีแจ้งเตือนเด้ง) |
| มือถืออีกเครื่องของบัญชีเดียวกัน / พนักงานคนอื่นในร้าน | ไม่กระทบ ยังมีเสียงตามปกติ |
| กดเปิดเสียงกลับ | กลับมาดังทั้งสองทาง |
| ร้านที่ไม่เคยกดปุ่ม | ไม่มีอะไรเปลี่ยน |
| ร้านที่ **กดปิดไว้ก่อนแล้ว** (ก่อนฟีเจอร์นี้ขึ้น) | ครั้งแรกที่เปิดหน้าแชทในแอปหลังฟีเจอร์ขึ้น แจ้งเตือนเด้งของเครื่องนั้นจะเงียบตามปุ่ม (ตรงกับที่ปุ่มบอกมาตลอด) |
| ตัวเลือกเสียงในหน้าบัญชี (เสียงแชท Deep / เสียงของเครื่อง) | ยังใช้ได้เหมือนเดิม กับเครื่องที่ไม่ได้ปิดเสียง |
| แจ้งเตือนอื่น (คำสั่งซื้อ, ส่งข้อความไม่สำเร็จ, ระบบ ฯลฯ) | **ไม่กระทบ** ยังมีเสียงตามปกติ — ปุ่มนี้คุมเฉพาะ "ข้อความใหม่" ตามป้าย |
| ปุ่มปิดเสียงรายห้องแชท | ไม่เปลี่ยน (ยังเงียบเฉพาะในหน้าแชท) — นอกขอบเขตรอบนี้ |

**ถ้อยคำ:** ป้ายปุ่มเดิม "ปิดเสียงแจ้งเตือนข้อความใหม่" / "เปิดเสียง…" ตรงกับพฤติกรรมใหม่แล้ว **ไม่เปลี่ยนคำ** · ไม่เพิ่มข้อความอธิบาย

**เมื่อไหร่ได้ผล:**
- **iPhone:** หลังเว็บ deploy ทันที ไม่ต้องอัปเดตแอป (iOS เงียบเมื่อ push ไม่มีค่า `sound`)
- **Android:** ต้องใช้แอปรุ่นใหม่ที่มีช่องแจ้งเตือนแบบเงียบ — แอปรุ่นเก่าบน Android กดปิดแล้วแจ้งเตือนยังมีเสียงเหมือนเดิม (ไม่พัง ไม่หาย) · ตอนนี้ Android ยังอยู่ closed testing จึงแทบไม่มีผู้ใช้กระทบ

## การออกแบบ (SDS ย่อ)

### 1) ข้อมูล — `PushToken.chatSoundMuted`
- `Boolean @default(false)` · migration additive ไม่ต้อง backfill
- **ผูกกับเครื่อง (token) ไม่ใช่บัญชี** — ตรงกับปุ่มเดิมที่เก็บใน localStorage ต่อเครื่อง
- ทำไมไม่ใช้ `User`: ผู้ใช้คนเดียวมีหลายเครื่อง ปิดบนเครื่องหนึ่งต้องไม่ทำให้อีกเครื่องเงียบ (ข้อเสียที่ทำให้ไม่เลือกเก็บระดับบัญชี)
- ออกจากระบบ ⇒ token ถูกลบอยู่แล้ว (`revokeDevicePushToken`) ⇒ ค่าหายตาม
- สลับบัญชีบนเครื่องเดิม ⇒ token ย้ายเจ้าของ (upsert เดิม) ค่าติดเครื่องไป ซึ่งตรงกับ localStorage ที่ก็ติดเครื่องเหมือนกัน

### 2) API — `PATCH /api/seller/push-token`
- body `{ token, chatSoundMuted: boolean }` · auth คุกกี้ session เหมือน POST/DELETE เดิม
- อยู่ใต้ `/api/seller/*` ⇒ ได้ CSRF Origin-check ของ `proxy.ts` (เหตุผลเดียวกับ POST)
- `updateMany({ where: { token, userId } })` — แก้ได้เฉพาะ token ของตัวเอง · ไม่พบแถว = 200 เงียบ (token อาจยังไม่ถูกลงทะเบียน)
- ไม่สร้างแถวใหม่ (การลงทะเบียน token ยังเป็นหน้าที่ของ POST เดิมเท่านั้น)

### 3) เว็บ — ส่งค่าปุ่มให้เซิร์ฟเวอร์ (`native-bridge.ts` + `ChatHeader`)
- `syncDeviceChatMute(muted)` ใน `native-bridge.ts` — ไม่อยู่ในแอป (ไม่มี `__DEEP_PUSH_TOKEN__`) ⇒ ไม่ทำอะไร
- เรียกเมื่อ: (ก) กดปุ่มลำโพง (ข) `ChatHeader` mount (ค) เมื่อแอปฝาก token ทีหลัง (event `deep:push-permission` ที่สคริปต์เดียวกันยิงอยู่แล้ว)
- **ค่าใน localStorage ของเครื่องคือตัวจริง** เซิร์ฟเวอร์เป็นสำเนา ⇒ (ข)+(ค) แก้ทุกกรณีที่ค่าไม่ตรง: กดตอนเน็ตหลุด, กดไว้ก่อนฟีเจอร์ขึ้น, token ถูกสร้างใหม่
- Android: ส่ง `true` เฉพาะเมื่อแอปประกาศความสามารถ `silent-chat-channel` (`hasNativeFeature`) — แอป Android รุ่นเก่าไม่มีช่องเงียบ ถ้าส่งไปช่องที่ไม่มีอยู่ แจ้งเตือนอาจไม่ขึ้นเลย ⇒ ยอมให้ยังมีเสียงดีกว่าหาย · iOS ส่งได้ทุกรุ่น
- ล้มเหลวเงียบ (เหมือน `revokeDevicePushToken`) — ปุ่มต้องเปลี่ยนสถานะทันทีเสมอ ไม่รอเน็ต

### 4) การส่ง — เฉพาะ `pushNewChatMessage`
- `pushToUsersWithStatus` รับ option ใหม่ `respectChatMute: true` (ค่าเริ่ม false ⇒ ผู้เรียกอื่นทุกตัวเหมือนเดิม)
- เมื่อเปิด: ดึง `chatSoundMuted` มาด้วย · token ที่ปิดเสียง ⇒ payload ไม่มี `sound` (iOS เงียบ) + `channelId: 'chat_silent'` (Android)
- token ที่ไม่ปิด ⇒ ใช้เสียงตามที่บัญชีเลือกเหมือนเดิม (`groupUsersByChatPushSound`)
- ยังยิงเป็น request เดียวต่อกลุ่มเสียงเหมือนเดิม (Expo รับ message ต่อ token อยู่แล้ว) — ไม่เพิ่มจำนวน request

### 5) แอปผู้ขาย (deep-seller-app) — ต้อง build ใหม่ (Android)
- `ensureAndroidChannels()` เพิ่มช่อง `chat_silent` ชื่อ "แชทใหม่ (ไม่มีเสียง)" importance HIGH ไม่มีเสียง ไม่สั่น
- เพิ่ม `silent-chat-channel` ใน `__DEEP_NATIVE_FEATURES__`
- iOS ไม่จำเป็นต้อง build แต่จะได้ไปพร้อมรอบถัดไป · `setNotificationHandler` ไม่ต้องแก้ (ไม่มี `sound` ใน payload = ไม่มีเสียงแม้แอปเปิดอยู่)
- ชื่อ `chat_silent` ต้องตรงกันทั้งสอง repo (เหมือนกติกาของ `chat`)

## สิ่งที่ไม่ทำรอบนี้
- ปิดเสียงรายห้องแชทให้มีผลกับแจ้งเตือนเด้ง (user สั่งยังไม่ทำ)
- ปิด "การแจ้งเตือน" ทั้งหมด (ไม่ใช่แค่เสียง) — มีอยู่แล้วที่ตั้งค่าแจ้งเตือนรายร้าน
- ตั้งเวลาเงียบ / โหมดกลางคืน
- แจ้งเตือนประเภทอื่นนอกจากแชทใหม่

## ความเสี่ยง
| ความเสี่ยง | ป้องกัน |
|---|---|
| ร้านกดปิดแล้วลืม พลาดแชท | แจ้งเตือนยังเด้งขึ้นจอและมีตัวเลขบนไอคอน — เงียบแค่เสียง · ไอคอนลำโพงขีดฆ่ายังเห็นบนหัวหน้าแชท |
| Android รุ่นเก่าได้ช่องที่ไม่มีอยู่ ⇒ แจ้งเตือนหาย | เว็บไม่ส่งค่าปิดเสียงให้ Android ที่ไม่ประกาศ `silent-chat-channel` |
| ค่าเครื่องกับเซิร์ฟเวอร์ไม่ตรง | ส่งค่าซ้ำทุกครั้งที่เปิดหน้าแชท/ได้ token (localStorage เป็นตัวจริง) |
| คนอื่นแก้ค่าของ token ที่ไม่ใช่ของตัวเอง | `where: { token, userId }` + CSRF ของ `/api/seller/*` |
| กระทบแจ้งเตือนอื่น | option ค่าเริ่ม false · เทส `[blocker]` ยืนยันว่าเฉพาะ `pushNewChatMessage` ส่ง `respectChatMute` |

## เทส (`[blocker]`)
1. `expo-push`: token ปิดเสียง ⇒ ไม่มี `sound` + `channelId: 'chat_silent'` · token ไม่ปิด ⇒ เสียงตามเดิม · ไม่มี option ⇒ เหมือนเดิมทุกตัว
2. `app-push`: `respectChatMute` ดึง `chatSoundMuted` และส่งต่อครบ · ผู้เรียกอื่นไม่ได้รับผล
3. `seller-push`: `pushNewChatMessage` เท่านั้นที่ส่ง `respectChatMute: true` (ตรวจ `pushChatSendFailed` ด้วยว่ายังมีเสียง)
4. API `PATCH`: แก้ได้เฉพาะ token ของตัวเอง · body ผิด 400 · ไม่ล็อกอิน 401 · ไม่สร้างแถวใหม่
5. `native-bridge`: ไม่อยู่ในแอป ⇒ ไม่ยิง · Android ไม่มี feature ⇒ ไม่ส่ง `true` · iOS ส่ง
6. DB จริง (tests/ + Postgres): migration + upsert ของ POST เดิมไม่ล้างค่า `chatSoundMuted`
7. แอป: มีช่อง `chat_silent` และ feature `silent-chat-channel` · ชื่อตรงกับเว็บ
- mutation: ลบ `respectChatMute`, กลับเงื่อนไข Android, ลบ `userId` ใน where ⇒ ต้องแดง

## ลำดับปล่อย
1. เว็บ (migration + API + การส่ง + ปุ่ม) ⇒ iPhone ได้ผลทันที
