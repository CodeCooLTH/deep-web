# ส่วนขยาย 2026-08-11 (รอบสอง) — แถบ "ที่มาของแชท" บรรทัดเดียว (`ThreadContextBar`)

> คำสั่ง user (ตรงตัว): *"เวลาที่มี reply ads, reply comment ตอนนี้ panel ด้านบน มันซ้อนกันเยอะ จนใช้ยาก"* (พร้อมภาพหน้าจอ prod จากมือถือ)
>
> Design Spec: `docs/superpowers/specs/2026-08-11-chat-context-bar-and-appointment-summary-design.md` §2
> ม็อกอัพ: `docs/superpowers/specs/2026-08-11-chat-context-bar-and-appointment-summary-mockup.html`

## 1. ปัญหา (วัดจากโค้ด ไม่ได้ประมาณ)

ใต้หัวเธรดใน `ChatThread.tsx` มีแถบได้ถึง **5 ชั้นซ้อนกัน** แต่ละชั้นเป็นบล็อกของตัวเอง:

| ลำดับ | ชั้น | ที่มา | สูง (390px) |
|---|---|---|---|
| 1 | `กำลังตอบในนามร้าน X` | 00037 (2026-08-08) | ~28px |
| 2 | แบนเนอร์โฆษณา | 00018 E5 | ~57px |
| 3 | ที่มาคอมเมนต์ | 2026-08-10 | ~57px |
| 4 | `ThreadStatusBar` | ยุบแล้ว 2026-08-02 | ~52px |
| 5 | `OrderProgressBar` | ยุบแล้ว 2026-08-05 | ~56px |

เคสในภาพโดนชั้น 2+3+5 = **~170px** + หัวเธรด 61px ≈ **29% ของจอ** ก่อนเห็นข้อความแรก

🛑 **ข้อสังเกตที่ตัดสินทางแก้:** ชั้น 4 และ 5 **เคยผ่านรอบยุบมาแล้ว** ด้วยเหตุผลเดียวกันเป๊ะ — `ThreadStatusBar.tsx:5` อ้าง user report 2026-08-02 ไว้ตรงตัวว่า *"การขึ้น alert box เยอะ ๆ ไม่ work มันรกหน้าจอมาก"* ชั้น 2 และ 3 คือสองอันที่ **ตกหล่นจากรอบนั้น** เพราะถูกเพิ่มคนละเวลา ทางแก้จึงไม่ใช่การประดิษฐ์แพตเทิร์นใหม่ แต่คือเอาแพตเทิร์นที่ตัดสินไปแล้วมาใช้กับสองอันที่ตกหล่น

## 3. Requirement

### FR-CTX-01 — แถบเดียวแทน 3 บล็อก

ทั้งสามบล็อกถูกรวมเป็น component เดียว `ThreadContextBar` ที่แสดง **บรรทัดเดียวสูง ~32px** เป็นค่าตั้งต้น

- **AC-CTX-01** ไม่มีรายการเลย → ไม่ render อะไรเลย (ไม่ใช่แถบว่าง)
- **AC-CTX-02** มี ≥1 รายการ → แสดงบรรทัดยุบเสมอ แม้มีรายการเดียว (กติกาเดียวกับ `ThreadStatusBar` ตั้งแต่ 2026-08-02 รอบสอง)
- **AC-CTX-03** มี >1 รายการ → แสดง badge `+N` ที่บอกจำนวนที่ถูกซ่อน — ห้ามซ่อนโดยไม่บอกจำนวน
- **AC-CTX-04** กดกาง → แสดง `detail` ของทุกรายการเรียงกัน + ปุ่ม "ย่อที่มาของแชท"
- **AC-CTX-05** `detail` ของแต่ละรายการต้องเหมือนของเดิม **ทุกพิกเซล** — งานนี้เปลี่ยนที่เก็บ ไม่ได้ออกแบบเนื้อหาใหม่

### FR-CTX-02 — ลำดับความสำคัญ (INVARIANT)

ลำดับใน `items` = ลำดับความสำคัญ **ตัวแรกคือตัวที่โชว์ตอนยุบ** — caller เป็นคนเรียง

- **AC-CTX-06** 🛑 **ถ้ามีแถบ "กำลังตอบในนามร้าน X" มันต้องเป็น `items[0]` เสมอ**

  เหตุผล: คอมเมนต์ที่ `ChatThread.tsx:2075` เขียนไว้เองว่านี่คือข้อมูลที่ต้องรู้ **ก่อนพิมพ์** ส่วนอีกสองอันเป็นข้อมูล "เฝ้าดู" ระหว่างคุย — ถ้าไปอยู่หลัง `+N` ผู้ขายหลายร้านจะ **ตอบลูกค้าในนามร้านผิด** ซึ่งถอนคืนไม่ได้ (ข้อความออกไปแล้ว) ต่างจากการไม่เห็นว่าแชทมาจากโฆษณาชิ้นไหน ซึ่งกดกางดูได้ตลอด
- **AC-CTX-07** ลำดับที่เหลือ: คอมเมนต์ → โฆษณา (คอมเมนต์ถือคำถามจริงของลูกค้า ซึ่งเป็นเหตุผลที่การ์ดนั้นถูกสร้างขึ้นแต่แรก — user report 2026-08-09 *"เปิดห้องมาแล้วไม่รู้ว่าตอบเรื่องอะไร"*; โฆษณาเป็นข้อมูลครั้งเดียวจบและปิดได้)

### FR-CTX-03 — โทนสี

- **AC-CTX-08** 🛑 พื้น **โปร่ง** ตัวอักษร `text-default-700/800` เท่านั้น — **ห้าม `bg-{semantic}/15` ใด ๆ**

  เหตุผล: `ThreadStatusBar` ที่อยู่ถัดลงมาใช้ `bg-danger/15` / `bg-warning/15` / `bg-info/15` ถ้าแถบบริบทมีพื้นสีด้วย ผู้ขายจะแยกไม่ออกว่าอันไหนคือ *"มีอะไรผิดปกติ"* กับ *"แชทนี้มาจากไหน"* และเมื่อโผล่พร้อมกันสองแถบสีติดกันจะอ่านเป็นบล็อกเดียว
- **AC-CTX-09** พื้น `bg-primary/5` เดิมของแถบชื่อร้าน **ถูกทิ้ง** — ตอนนี้มันเป็น 1 ใน 3 รายการของแถบเดียวกัน ถ้ายังมีพื้นสีเฉพาะตัว แถบจะเปลี่ยนสีไปมาตามว่ารายการแรกคืออะไร

### FR-CTX-04 — รูปทรง

- **AC-CTX-10** เป็น **แถวเต็มความกว้างติดหัวแชท มี `border-b`** ไม่ใช่การ์ดลอยที่มี padding รอบ

  เหตุผล: `ChatThread.tsx:2099` บันทึก user report 2026-07-26 ว่าการ์ดลอยทำให้เกิดช่องว่างคั่นระหว่างหัวแชทกับแบนเนอร์ จึงถูกเปลี่ยนเป็นแถวเต็มความกว้างมาแล้วครั้งหนึ่ง (`ThreadStatusBar` เป็นการ์ดลอยได้เพราะมันเป็น *คำเตือน* ที่ควรดูเหมือนของแปลกปลอมที่แทรกเข้ามา — แถบบริบทเป็นส่วนต่อของหัวเธรด)

### FR-CTX-05 — ปุ่มปิดแบนเนอร์โฆษณา

- **AC-CTX-11** ปุ่ม `✕` อยู่ใน `detail` ตอนกาง**เท่านั้น** ไม่มีในบรรทัดยุบ

  เหตุผล 2 ข้อ: (1) ที่ 390px บรรทัดยุบมีของคงที่ `px-4`(32) + thumb(20) + gap(8) + `+N`(24) + `⌄`(24) = 108px เหลือ ~282px ให้ข้อความ — เติม `✕` เข้าไปเหลือ ~250px (2) สองปุ่มนี้ **ผลลัพธ์ต่างกันคนละโลก** (ปิดถาวรต่อเธรด vs กางดู) วางห่างกัน 8px = แตะพลาดแน่นอน
- **AC-CTX-12** localStorage key เดิมของการปิดโฆษณา (`ChatThread.tsx:1189`) **ต้องไม่เปลี่ยน** — สถานะที่ผู้ขายเคยปิดไว้ต้องยังจำได้หลัง deploy
- **AC-CTX-13** ปิดโฆษณาแล้วรายการหายจาก `items` → เหลือรายการเดียวบรรทัดยุบเปลี่ยนเนื้อหาเอง · ไม่เหลือเลยแถบหายทั้งแถบ

### FR-CTX-06 — พฤติกรรมการยุบ/กาง

- **AC-CTX-14** ยุบเป็นค่าตั้งต้นเสมอ **ไม่จำสถานะกาง** (เหมือน `ThreadStatusBar`/`OrderProgressBar`) — ถ้าจำ ผู้ขายที่เผลอกางค้างจะกลับไปเจอปัญหาเดิมทุกห้องโดยไม่รู้สาเหตุ
- **AC-CTX-15** ทำงานเหมือนกันทุก breakpoint — **ไม่มี `xl:` ที่กางเองบนจอใหญ่** (จอ ≥1280 มี `CustomerPanel` แต่ panel นั้นตอบ "ลูกค้าเป็นใคร" ไม่ได้ตอบ "แชทนี้มาจากไหน")
- **AC-CTX-16** ปุ่มกาง/ย่อต้องมี `aria-expanded` และ `aria-label` ที่แยกกรณีมี/ไม่มี `+N` (WCAG 4.1.2 — บทเรียนจาก `OrderProgressBar`)
