# 00018 ส่วนขยาย 2026-09-09 — ตัวเลือกการเรียงลำดับกล่องแชท (Inbox Sort Mode)

> เอกสารนี้เขียน **ก่อนเขียนโค้ด** ตาม Hard Rule 11 · เจ้าของมติ: user (เคาะ 2026-09-09)

## 1. ที่มา

2026-09-08 ร้านรายงานว่า "แชทนี้ไม่เข้า" — สืบแล้วพบว่าข้อความเข้าครบ แต่เธรดจมอยู่ลำดับ ~547
เพราะ `Conversation.lastMessageAt` ไม่ขยับตอนร้านตอบจากแอป Messenger (echo) แก้ไปแล้วที่ `5155c6a0`
+ backfill 6,303 แถว

ระหว่างนั้น user ระบุว่าเคยคุยกันไว้ว่า **"การเรียงกล่องแชทควรตั้งค่าได้"** — ไล่เอกสาร 00018
ทั้งชุดแล้วไม่พบมติที่บันทึกไว้ (อาจอยู่ในเซสชันที่ไม่ได้บันทึก) จึงถือว่าเป็นความต้องการใหม่
และบันทึกไว้ที่นี่ให้ครบตั้งแต่รอบนี้

**ปัญหาที่แท้จริง:** กล่องแชทมีคีย์เรียงเดียว (`lastMessageAt`) ที่ปนคำถาม 2 ข้อเข้าด้วยกัน
- *"ห้องไหนเพิ่งมีความเคลื่อนไหว"* — ตอบด้วย `lastMessageAt`
- *"ลูกค้าคนไหนพิมพ์เข้ามาล่าสุด"* — ตอบด้วย `lastInboundAt`

🛑 **ห้ามอธิบายโหมดที่สองว่า "คนที่รอนานที่สุดขึ้นก่อน"** — โค้ดเรียง `lastInboundAt` **desc** (ลูกค้าที่พิมพ์ล่าสุดอยู่บนสุด) ซึ่งเป็นทิศ**ตรงข้าม**กับ "รอนานสุดขึ้นก่อน" พอดี · คำอธิบายรุ่นแรกที่ยกมาจาก Design Spec เขียนผิดข้อนี้และหลุดลงทั้ง `th.ts` และ `en.ts` — จับได้ด้วย `/impeccable clarify` เท่านั้น (`tsc`/build/เทส/detector ผ่านหมด เพราะสตริงถูกทุกตัวอักษร สิ่งที่ผิดคือ *ข้อเท็จจริงที่มันอ้าง*) คลาสเดียวกับ `docs/conventions/value-fate-decided-at-write-site.md`. ถ้าวันไหนอยากได้ "คนรอนานสุดขึ้นก่อน" จริง ๆ นั่นคือ **โหมดที่สาม** (`asc`) ไม่ใช่การแก้คำอธิบาย

คีย์เดียวตอบได้ทีละคำถาม จึงต้องให้ผู้ใช้เลือก

**ข้ออ้างของ ux ที่ตรวจกับโค้ดแล้วไม่จริง (บันทึกไว้กันคนหลงตาม):**
- *"reuse `ListBusyOverlay` ที่มีอยู่"* — `InboxList` **ไม่เคยใช้** ตัวนั้นเลย (มีเฉพาะที่ `/orders`) และ `loading` ที่มีอยู่ (บรรทัด 370) ถูกใช้กันการยิงซ้ำของ infinite scroll เท่านั้น **ไม่ได้ render อะไรบนจอ** ⇒ ดู KG-SORT-01
- *"ปุ่มตัวกรองใช้ `bg-primary/15 text-primary`"* — ของจริงคือ `border-primary text-primary` (`InboxFilterPanel.tsx:205`) ปุ่มใหม่จึงลอกสูตรนั้นมาตรง ๆ เพื่อให้สองปุ่มข้างกันเป็นของชนิดเดียวกัน

## 4c. ข้อจำกัดที่รู้ตัว

**KG-SORT-01 — สลับโหมดแล้วไม่มีสัญญาณว่ากำลังโหลด** รายการค้างแสดงลำดับเก่าจนผลชุดใหม่มาถึงแล้วสลับทันที **นี่เป็นพฤติกรรมเดิมของตัวกรองทุกตัวในกล่องแชท** (แท็บช่องทาง · แผงตัวกรอง · ค้นหา ล้วนไม่มีตัวบอกสถานะโหลด) ไม่ใช่ของใหม่ที่รอบนี้สร้าง — แต่โหมดเรียงทำให้เห็นชัดกว่าเพราะมันสลับ **ทั้งรายการ** ไม่ใช่กรองบางแถวออก. ทางแก้ที่ถูกคือยกแผงโหลด (`ListBusyOverlay`/`useListBusy` ที่ `/orders` ใช้อยู่) มาครอบ **ทุกตัวกรองของกล่องแชท** ไม่ใช่ครอบเฉพาะตัวเรียง (ครอบเฉพาะตัวเดียวจะกลายเป็นสองมาตรฐานในแถบเดียวกัน) — เป็นงานคนละชิ้น ยังไม่ทำในรอบนี้

**OQ-SORT-01 (ยังไม่ตัดสิน) — ค่าตั้งต้นของร้านที่สมัครใหม่**
`LAST_MESSAGE` ถูกเลือกด้วยเหตุผลว่า "ร้านเดิมไม่ควรตื่นมาเจอลำดับเปลี่ยน" ซึ่งใช้ได้กับ**ผู้ใช้ที่มีอยู่แล้ว**เท่านั้น — แต่ค่านี้จะใช้กับร้านที่สมัครใหม่ไปตลอดกาลด้วย ⇒ ร้านใหม่ทุกร้านต้องบังเอิญเจอปุ่มนี้เองถึงจะได้โหมดที่แก้ปัญหาที่ฟีเจอร์นี้ถูกสร้างมาแก้ · ทางเลือก: แยก default ตามวันสมัคร (grandfather) แลกกับกติกาที่อธิบายยากขึ้น **รอ user เคาะ**

## 5. นอกขอบเขต

- ไม่ทำโหมด "เรียงตามเวลาที่รอนานสุด" หรือ SLA/คิวงาน
- ไม่แตะการเรียงของแท็บความคิดเห็น (`/inbox/comments`)
- ไม่แตะกล่องข้อความฝั่งผู้ซื้อ
- ไม่ทำตัวเลือกเรียงจากเก่า→ใหม่ (ทั้ง 2 โหมดเป็นใหม่→เก่าเสมอ)
