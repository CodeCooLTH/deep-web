# ข้อความภายในของ Meta = META_NOTICE

## ปัญหา
Meta Business Suite ใส่บันทึกภายในลงเธรดในนามเพจ ลูกค้าไม่เห็น ร้านไม่ได้พิมพ์ แต่ Graph/webhook ส่งมาเหมือนร้านพิมพ์เอง
ระบบเก็บเป็น `senderRole='SHOP'` `type='TEXT'` → หน้าจอแสดงกลางห้องได้ (จับจากตัวอักษรด้วย `parseMetaSystemNotice`) แต่ระบบหลังบ้านนับเป็น **"ร้านตอบ"**:
- รายการแชท: ผู้ส่งล่าสุด = ร้าน ⇒ ห้องที่ลูกค้ามาจากโฆษณาไม่ขึ้นเป็นยังไม่ได้ตอบ
- AI ร่างคำตอบข้ามห้อง (ข้อความล่าสุดไม่ใช่ลูกค้า) · AI/ความจำเห็น "แอดมิน: Lead stage set to Converted"
- เวลาตอบกลับ · เส้นแบ่งข้อความที่ป้อนบอท

## กฎ (BR-FBC-META-01..04)
1. **ตัดสินตอนรับเข้า** ด้วย `isMetaInternalNote(body)` (`src/lib/meta-system-notice.ts`) เฉพาะแถวฝั่งเพจ (`SHOP`) ที่เป็นตัวอักษรล้วน — ป้าย `[…]` (การ์ด/ไฟล์ที่ส่งถึงลูกค้าจริง) ไม่นับ · ข้อความฝั่งลูกค้าที่ตรงคำเดียวกัน (เช่น "sent a payment") ไม่แตะ
2. เก็บเป็น `ChatMessage.type = 'META_NOTICE'` (`META_NOTICE_TYPE`) — ไม่ลบ ไม่ทิ้ง
3. **ไม่แตะสรุปเธรด**: `lastMessagePreview` · `lastSenderRole` · `lastMessageAt` · `shopLastReadAt` (webhook ข้าม update ทั้งก้อน · backfill ไม่นับเป็นใบล่าสุด)
4. **ไม่ใช่บทสนทนา**: ตัดออกคู่กับ `AUTO_ORDER_RESULT` ทุกจุด — AI ร่างคำตอบ (อัตโนมัติ + กดเอง) · ความจำแชท · เวลาตอบกลับ · เส้นแบ่งบอท · watchdog ออเดอร์อัตโนมัติ · client `latestRealMsg`
5. หน้าจอ: `ThreadMessageList` แสดงกลางห้องเสมอเมื่อ type = META_NOTICE (parser ไม่รู้จักคำแล้ว = ใช้ body ตรง ๆ)

## นอกขอบเขตรอบนี้
- รายงานผลงานแอดมิน (00059) ยังนับเป็น "ตอบจาก Business Suite" — มีเทส parity TS/SQL บังคับ แก้เป็นงานแยก
- แถวเก่าบน prod (~11,600) — แปลงเป็น META_NOTICE + ซ่อมสรุปเธรด เป็นขั้นข้อมูลแยก รอ user เลือกขอบเขตการซ่อมห้อง (ทุกห้อง / 30 วัน / ไม่ซ่อม)
