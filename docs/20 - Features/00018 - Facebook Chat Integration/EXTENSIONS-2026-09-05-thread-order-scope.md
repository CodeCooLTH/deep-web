# 00018 ส่วนขยาย 2026-09-05 — ออเดอร์หายจากห้องแชทเมื่อเบอร์ลูกค้าถูกแก้

## 1. ที่มา (user report, prod)

> "ลูกค้ามีการเปลี่ยนเบอร์โทรศัพท์จากหน้าแชท เนื่องจาก chat ให้ข้อมูลเบอร์โทรผิด
> แต่ปรากฏว่าพอเปลี่ยนเบอร์ ข้อมูล orders ของแชทนั้นหายไป"

## 2. กลไก — แผงถามผิดคำถาม

แผงออเดอร์ในห้องแชทดึงข้อมูลด้วย `ExternalContact.customerId` ล้วน ๆ ทั้ง 2 ทางเข้า
(SSR 20 ใบแรกที่ `inbox/[conversationId]/page.tsx` · ใบที่ 21+ ที่
`GET /api/chat/conversations/[id]/orders`) ⇒ มันถามว่า **"ออเดอร์ของลูกค้าคนนี้มีอะไรบ้าง"**
ทั้งที่ผู้ใช้ถามว่า **"ออเดอร์ของห้องนี้มีอะไรบ้าง"** — สองคำถามนี้ให้คำตอบตรงกันเฉพาะตอนที่
ไม่มีใครคีย์เบอร์ผิด ซึ่งเป็นข้อสมมติที่ระบบไม่เคยรับประกันให้เลย

`Customer.phone` เป็น `@unique` ทั้งระบบ ⇒ เบอร์ใหม่ = `Customer` คนละแถวเสมอ และเธรดผูก
ลูกค้าได้ทีละคน (`ExternalContact.customerId`) ⇒ การคีย์เบอร์ใหม่คือการ **สลับ** ลูกค้าของเธรด
ไม่ใช่การ **เพิ่ม** ⇒ ออเดอร์ทุกใบที่ผูกกับคนก่อนหน้าหลุดจากแผงทันทีที่กดบันทึก

🛑 **ทางที่ทำให้หายมี 2 ทาง ไม่ใช่ทางเดียว** และทั้งคู่เงียบสนิท (แถวยังอยู่ครบใน `/orders`):

| # | ทาง | ผล |
|---|-----|-----|
| 1 | คีย์เบอร์ใหม่ (แก้ใบเดิม **หรือสร้างใบใหม่ในห้องนั้น**) → `relinkThreadCustomer` ย้ายเธรดไปลูกค้าคนใหม่ | ใบเก่าที่ผูกคนเดิม **หายจากแผง** |
| 2 | แก้เบอร์จาก `/orders/[token]/edit` (หน้าเต็มจอ) ซึ่ง **ไม่เคยส่ง `conversationId` มาเลย** | `findThreadContact` คืน null → ไม่ relink เลย → ออเดอร์ย้ายไปคนใหม่ แต่เธรดค้างคนเก่า ⇒ **ใบที่เพิ่งแก้เองก็หาย** |

**หลักฐานบน prod (2026-09-05):** ห้อง `ecdd6369…` มีออเดอร์ที่เปิดจากห้องนั้น 2 ใบ
(`0614383569` 17 ส.ค. · `0614383566` 30 ส.ค. — ต่างกัน 1 หลัก) แผงเห็นแค่ใบเดียว และใบที่หาย
**ไม่มี event `ORDER_EDITED` เลยสักครั้ง** ⇒ มันหายเพราะ *ใบอื่น* ไปย้ายเธรดทิ้งมัน (ทางที่ 1)

## 3. FR-CHAT-090 — "ออเดอร์ของห้องนี้" มีนิยามเดียว

SSOT: **`resolveThreadOrderFilter()` ใน `src/lib/chat-thread-orders.ts`** (pure, ไม่ import prisma)

```
ออเดอร์ของห้องนี้ = Order.customerId = ลูกค้าที่เธรดผูกอยู่  OR  Order.conversationId = ห้องนี้
```

- `Order.conversationId` เขียนครั้งเดียวตอน `createOrder` จากเธรดที่ผ่าน `WHERE shopId` มาแล้ว
  และ **ไม่มีหน้าจอไหนแก้ได้ทีหลัง** จึงไม่ขยับตามเบอร์ที่ใครคีย์ (มีตั้งแต่ 2026-07-31 —
  ใบก่อนหน้านั้นเป็น `NULL` และยังกู้กลับเข้าห้องด้วยเกณฑ์นี้ไม่ได้)
- 🛑 คืน `null` เมื่อไม่มีทั้งลูกค้าและห้อง และ **`null` ต้องแปลว่า "ไม่ต้องยิงคิวรี"** ห้ามแปลว่า
  "ไม่ต้องกรอง" — ผู้เรียกที่เผลอ spread ค่าว่างเข้า `where` จะได้ออเดอร์ **ทั้งร้าน** โผล่ใน
  ห้องเดียว = ข้อมูลลูกค้าคนอื่นรั่ว ไม่ใช่แค่ผลลัพธ์ผิด
- ผู้เรียก 2 จุดต้องใช้ตัวเดียวกันเสมอ (SSR + lazy-load) ไม่งั้นรายการกระโดดตอนเลื่อนถึงใบที่ 21

`getOrdersByCustomer()` เปลี่ยนชื่อเป็น **`getThreadPanelOrders()`** และรับ `ThreadOrderFilter`
แทน `customerId` — ชื่อเดิมสื่อว่า "ของลูกค้า" ซึ่งไม่ตรงกับสิ่งที่มันทำแล้ว (คลาสเดียวกับ
`phoneMasked` ที่ถือค่าเต็ม)

## 4. FR-CHAT-091 — เธรดต้องย้ายตามเบอร์ ไม่ว่าหน้าจอไหนกดบันทึก

`updateOrder` หาเธรดจาก **`existing.conversationId ?? data.conversationId`** — อ่านจากแถว
ออเดอร์ก่อน แล้วค่อยถอยไปใช้ค่าที่ผู้เรียกส่งมา (ออเดอร์ที่ไม่ได้เกิดจากแชทเป็น `NULL` เช่นใบที่
คีย์จาก `/orders/new` แล้วเปิดแก้ในโมดัลของแชท) ⇒ ปิดทางที่ 2 ให้ **ทุกทางเข้า** ทั้งที่มีวันนี้
และที่จะเพิ่มวันหน้า โดยไม่ต้องไล่แก้ทีละหน้าจอ

## 5. UI (ผ่าน `safepay-ux` — mode Operate)

| จุด | มติ |
|---|---|
| ป้ายบนการ์ดที่มาจาก `conversationId` แต่คนละ `Customer` | **ไม่มี** — ไม่มี action ให้ผู้ขายทำต่อ (ไม่มีปุ่ม "รวมลูกค้า") และระบบพิสูจน์ไม่ได้ทั้งสองทางว่าเป็นคนเดียวกันไหม ⇒ ป้ายที่ฟันธงไม่ได้แต่โชว์ทุกใบ = เสียงรบกวน |
| ตัวเลขบนแท็บ/บล็อกสรุป | **คงนับตามลูกค้าเหมือนเดิม ไม่แตะ** (`customerStats`) |
| รายการ ≠ ตัวเลขบนแท็บ | แคปชันคงที่เหนือรายการ (แสดงเมื่อมีรายการ ≥1): `รวมทุก{noun}ที่เปิดจากห้องนี้ อาจมากกว่ายอดในแท็บ "ข้อมูลลูกค้า"` — คีย์ `inbox.customerPanel.listScopeNote` (th/en) |
| เธรดที่ยังไม่ผูกลูกค้า | บล็อกสรุป **ซ่อนทั้งก้อนตามเดิม** (ไม่ใช่ขีด `—` — ไม่ใช่ "ค่ายังไม่มา" แต่ "ไม่มี entity ให้ aggregate") |
| 🛑 empty-state ของแท็บ | เดิมผูกกับ `data.customer` ⇒ เธรดที่ยังไม่ผูกลูกค้าจะถูกซ่อนรายการ **ซ้ำอีกชั้น** (บั๊กตัวเดียวกับที่กำลังแก้) — เปลี่ยนไปผูกกับ `data.orders.length` แล้วใช้ `data.customer` เลือกแค่ *ข้อความตอนว่าง* |

## 8. สิ่งที่ยังไม่ทำในรอบนี้

- **ออเดอร์ก่อน 2026-07-31 ไม่มี `conversationId`** ⇒ ถ้าเคยหลุดจากห้องไปแล้วยังกู้ไม่ได้ด้วย
  เกณฑ์นี้ (ต้องผูกลูกค้าคืนด้วยมือ) — 282/824 ใบบน prod ที่คอลัมน์นี้เป็น `NULL`
- ยังไม่มี UI ให้ "รวมลูกค้า 2 แถวที่เป็นคนเดียวกัน" — เบอร์ที่คีย์ผิดยังทิ้ง `Customer` เศษไว้
  ในระบบ (เห็นได้ที่ `/customers`) `canRenameCustomerPhone` ช่วยได้เฉพาะตอนแถวเดิมยังไม่มี
  ออเดอร์/เธรดอื่นผูกอยู่
- **เบอร์ในแท็บ "ข้อมูลลูกค้า" (`ExternalContact.phones`) ไม่ผูกกับ `Customer` เลย** — แก้ตรงนั้น
  ไม่มีผลกับออเดอร์/การผูกลูกค้าใด ๆ ทั้งสิ้น (ผู้ขายที่เข้าใจว่าแก้ตรงนั้นแล้วระบบจะตามให้ จะเงียบ)
