# PRD: เมนูเรียกรถ (Courier Pickup List)

## Executive Summary
วันนี้ร้านเรียกรถเข้ารับได้จากหน้า **ตั้งค่า** เท่านั้น (โมดัลในแถว Flash / iShip) และเห็นได้แค่ **คำขอล่าสุด 1 รายการ** ไม่มีที่ดูย้อนหลังว่าเรียกไปกี่ครั้ง ใครเรียก รถรับงานหรือยัง หรือยกเลิกแล้ว
ฟีเจอร์นี้เพิ่มเมนู **"เรียกรถ"** ใต้ "คำสั่งซื้อ" ในกลุ่ม MANAGE เปิดหน้า `/pickups` ที่มี
1. ปุ่ม **เรียกรถ** (ใช้ขั้นตอนเดิมของแต่ละขนส่ง ไม่สร้างใหม่)
2. **รายการคำขอทั้งหมด** ของร้าน เรียงใหม่สุดก่อน พร้อม **สถานะ** และปุ่ม **ยกเลิก** สำหรับคำขอที่ยังยกเลิกได้

ไม่มี migration — ข้อมูลทั้งหมดอยู่ในตาราง `ShipmentPickup` แล้ว (ใช้ร่วม iShip + Flash)

## 1. เป้าหมาย
| เป้าหมาย | วัดผล |
|---|---|
| ร้านรู้สถานะรถเข้ารับโดยไม่ต้องโทรถามขนส่ง | คำขอทุกใบเห็นสถานะปัจจุบันบนหน้าเดียว |
| เรียก/ยกเลิกรถได้จากที่เดียวกับงานจัดส่ง | ไม่ต้องเข้าหน้าตั้งค่า |
| ตรวจย้อนหลังได้ (ใครเรียก กี่ชิ้น เมื่อไหร่) | ทุกแถวมีผู้เรียก + เวลา |

## 2. ผู้ใช้
เจ้าของร้านและพนักงานที่มีสิทธิ์งานจัดส่ง (capability เดียวกับ API เรียกรถเดิม `S1`) ของร้านขายออนไลน์ที่เชื่อม Flash หรือ iShip อย่างน้อยหนึ่งเจ้า

## 3. User Stories
- **US-1** ในฐานะร้าน ฉันกดเมนู "เรียกรถ" แล้วเห็นคำขอทั้งหมดของร้านพร้อมสถานะ
- **US-2** ฉันกด "เรียกรถ" บนหน้านี้แล้วเลือกขนส่ง (ถ้าเชื่อมไว้มากกว่าหนึ่ง) ใส่จำนวนชิ้น/หมายเหตุ แล้วส่งคำขอได้ทันที รายการอัปเดตเอง
- **US-3** ฉันยกเลิกคำขอที่ยังไม่มีรถมารับได้จากแถวนั้น
- **US-4** ฉันเห็นชื่อ/เบอร์พนักงานและช่วงเวลาเข้ารับเมื่อขนส่งส่งมา และกดโทรได้บนมือถือ
- **US-5** คำขอที่ล้มเหลวแสดงเหตุผล (ข้อความของเรา ไม่ใช่ข้อความดิบจากขนส่ง)

## 4. ขอบเขตฟีเจอร์ (FR)
| # | ความต้องการ |
|---|---|
| FR-1 | เมนู "เรียกรถ" (icon `truck`) อยู่ถัดจาก "คำสั่งซื้อ" ในกลุ่ม MANAGE · เห็นเฉพาะร้านที่ใช้งานได้ตาม BR-1 |
| FR-2 | หน้า `/pickups`: รายการเรียงตาม `createdAt` ใหม่สุดก่อน · แบ่งหน้า 20 รายการ |
| FR-3 | แต่ละแถว: วันเวลาเรียก · ขนส่ง (Flash / iShip+ชื่อเจ้า) · เลขคำขอ · จำนวนชิ้น · พนักงาน+เบอร์ · ช่วงเวลาเข้ารับ · สถานะ · ผู้เรียก · ปุ่มยกเลิก |
| FR-4 | ตัวกรองสถานะแบบชิป: ทั้งหมด / กำลังดำเนินการ (รอรับงาน+รับงานแล้ว) / เสร็จสิ้น / ยกเลิก / ไม่สำเร็จ |
| FR-5 | ปุ่ม "เรียกรถ" เปิดขั้นตอนเรียกรถของขนส่งที่เลือก (โมดัลเดิม) · สำเร็จแล้วรายการรีเฟรช |
| FR-6 | ยกเลิกผ่าน service เดิมของแต่ละขนส่ง (`cancelFlashPickup` / `cancelPickup`) พร้อมกล่องยืนยัน |
| FR-7 | ร้านที่ยังไม่เชื่อมขนส่งใดเลย: หน้าว่างพร้อมปุ่มไปตั้งค่าการจัดส่ง |
| FR-8 | มือถือ: แสดงเป็นการ์ดต่อคำขอ · desktop: ตาราง |

## 5. นอกขอบเขต
- เรียกรถแบบผูกกับพัสดุ/ออเดอร์รายใบ (ระบบขนส่งไม่รองรับ)
- แจ้งเตือนเมื่อสถานะเปลี่ยน (push/LINE)
- แก้ไขคำขอที่ส่งไปแล้ว
- ลบประวัติคำขอ
- เอาปุ่มเรียกรถในหน้าตั้งค่าออก (คงไว้ทั้งสองที่ในรอบนี้)

## 6. Acceptance Criteria
| AC | เกณฑ์ |
|---|---|
| AC-1 | ร้านเห็นเฉพาะคำขอของร้านตัวเอง (กรองด้วย `shopId` ที่ server จาก session) |
| AC-2 | สถานะแสดงตามตาราง BR-3 ทุกค่า · ค่าที่ไม่รู้จักแสดง "ไม่ทราบสถานะ" ไม่ล่ม |
| AC-3 | ปุ่มยกเลิกมีเฉพาะสถานะ REQUESTED / ACCEPTED และไม่ใช่ dry-run ที่หมดอายุ · กดแล้วสถานะเป็น "ยกเลิก" |
| AC-4 | พนักงานที่ไม่มีสิทธิ์ `S1` เข้า `/pickups` ไม่ได้และไม่เห็นเมนู |
| AC-5 | เรียกรถสำเร็จจากหน้านี้ → แถวใหม่อยู่บนสุดโดยไม่ต้องรีโหลด |

## 7. ความเสี่ยง
| ความเสี่ยง | การรับมือ |
|---|---|
| สถานะค้าง "รอรับงาน" ถ้าขนส่งไม่ยิง webhook | แสดงเวลาที่อัปเดตล่าสุด · ไม่เดาสถานะเอง |
| iShip และ Flash ใช้ field ต่างกัน | แสดงผ่านตัวแปลงกลางตัวเดียว (BR-3) |
