# PRD: ซื้อ Business Package ผ่าน In-App Purchase (iOS)

---

## Executive Summary

Apple ตีกลับแอป `deep-seller-app` ด้วย Guideline 3.1.1 / 3.1.3(c) เป็นรอบที่สอง โดยระบุว่า
**บริการที่เราขายให้ "องค์กร" นั้นบุคคลธรรมดาก็ซื้อได้** จึงไม่เข้าข้อยกเว้น enterprise services
และต้องขายผ่าน In-App Purchase

ฟีเจอร์นี้เปิดทาง **ซื้อ Business Package ในแอป iOS ผ่าน IAP** (StoreKit 2) โดยไม่แตะโมเดล
กระเป๋าเงินที่ใช้อยู่บนเว็บ ผลคือแอปผ่านเกณฑ์ Apple และผู้ขายบน iOS กลับมาซื้อแพ็กเกจได้อีกครั้ง
หลังจากถูกปิดทางไปตั้งแต่ 2026-08-04

**ขอบเขตรอบนี้จำกัดที่ Business Package เท่านั้น** — Deep Stock ไม่ขายในแอปและต้องซ่อนฟีเจอร์
ในแอปด้วย (เหตุผลที่ §6 ความเสี่ยง R-2)

---

## 1. Business Goals & KPIs

### 1.1 เป้าหมายทางธุรกิจ

| เป้าหมาย | รายละเอียด |
|---|---|
| **ผ่านรีวิว App Store** | ปิดข้อ 3.1.1 / 3.1.3(c) ซึ่งเป็นข้อเดียวที่เหลือค้าง — อีก 2 ข้อ (2.1(a), 3.1.1 การสมัครบัญชี) แก้แล้วตั้งแต่ 2026-08-25 |
| **เปิดรายได้ที่ปิดอยู่กลับมา** | ตั้งแต่ 2026-08-04 ผู้ขายที่ใช้แอป iOS ซื้อแพ็กเกจไม่ได้เลย (`shouldHidePayments`) — รายได้ช่องทางนี้เป็นศูนย์ |
| **ไม่กระทบผู้ใช้เดิม** | คนที่จ่ายผ่านกระเป๋าเงินอยู่แล้วต้องไม่รู้สึกว่ามีอะไรเปลี่ยน |

### 1.2 KPIs

| KPI | วิธีวัด | เป้าหมาย |
|---|---|---|
| ผลรีวิว Apple | สถานะ submission | ผ่านข้อ 3.1.1 |
| การเก็บเงินซ้ำ | `WalletTransaction` ที่ `reason='BUSINESS_PACKAGE_SUBSCRIPTION'` ของเจ้าของที่ `source='APPLE_IAP'` | **0 แถว ตลอดกาล** |
| สิทธิ์ค้างหลังยกเลิก | subscription `ACTIVE` ที่ Apple แจ้ง `EXPIRED` แล้วเกิน 24 ชม. | 0 |

## 2. ปัญหาที่แก้

### 2.1 สิ่งที่ Apple บอกมาตรง ๆ (2026-08-23)

> we still found the same enterprise services are also available to be sold to single users
> or consumers in the Basic plan without using In-App Purchase … To resolve this issue, it
> would be appropriate to **revise the app to only provide your services directly to
> organizations and groups** … **or revise the app to give App Store customers the option to
> purchase these services with In-App Purchases**

เราถาม 3 ข้อ Apple ตอบให้เลือก 2 ทาง — user เคาะ **ทาง IAP** (2026-09-01)

### 2.2 ทำไมไม่เลือกทาง "ขายเฉพาะนิติบุคคล"

ผู้ขายไทยส่วนใหญ่เป็นบุคคลธรรมดา การจำกัดต้องบังคับ **ทั้งเว็บด้วย** ไม่ใช่แค่ซ่อนในแอป
(ไม่งั้นก็ยังเป็น "ขายให้บุคคล" อยู่ดี) ⇒ ตัดรายได้กลุ่มใหญ่ที่สุดออกทุกแพลตฟอร์ม
เพื่อแลกกับการไม่ต้องเขียน IAP — ไม่คุ้ม

## 3. ผู้ใช้และสถานการณ์

| ใคร | สถานการณ์ | ผลที่ต้องได้ |
|---|---|---|
| ผู้ขายใหม่บน iOS | อยากเปิดร้านที่ 2 | เห็นแพ็กเกจ กดซื้อผ่าน Apple ได้จบในแอป |
| ผู้ขายเดิมที่จ่ายผ่านกระเป๋าเงิน | เปิดแอป iOS | ใช้ได้เหมือนเดิมทุกประการ ไม่มีปุ่มชวนซื้อซ้ำ ไม่มีอะไรสะดุด |
| ผู้ขายที่ซื้อผ่าน IAP แล้วเปิดเว็บ | ทำงานบนคอม | สิทธิ์ติดตามไปด้วย (สิทธิ์อยู่ที่ server ไม่ได้อยู่ที่เครื่อง) |
| ผู้ขายที่ยกเลิกกับ Apple | กดยกเลิกใน Settings ของ iPhone | สิทธิ์หมดตอนสิ้นรอบ ไม่ใช่หมดทันที และร้านถูกล็อกตามกติกาเดิม |
| ผู้ขายที่ขอเงินคืนจาก Apple | Apple อนุมัติ refund | สิทธิ์ถูกถอนทันทีที่ได้รับแจ้ง |

## 4. ขอบเขต

### 4.1 อยู่ในขอบเขต

- ซื้อ **Business Package** (Growth / Pro / Business) ผ่าน IAP บน iOS
- ต่ออายุอัตโนมัติโดย Apple + รับแจ้งผ่าน App Store Server Notifications v2
- คืนสิทธิ์ (`restore purchases`) สำหรับคนที่ลงแอปใหม่/เปลี่ยนเครื่อง
- แยกแหล่งที่มาของ subscription เพื่อกัน cron เก็บเงินซ้ำ
- ซ่อนฟีเจอร์ Deep Stock ในแอป iOS (บังคับโดย 3.1.3(b) — ดู R-2)

### 4.2 นอกขอบเขต

| ของ | เหตุผล |
|---|---|
| Deep Stock ผ่าน IAP | สิทธิ์เป็น "ต่อร้าน" แต่ Apple ขาย auto-renewable ได้ใบเดียวต่อ Apple ID — ต้องเปลี่ยนโมเดลราคาทั้งระบบ (user เคาะให้ตัดออก) |
| Android / Google Play Billing | ยังไม่ปล่อยแอป Android — แต่ `PAYMENT_RESTRICTED_SHELLS` เตือนไว้แล้วว่าต้องเพิ่มก่อนปล่อย |
| ย้ายผู้ใช้เดิมไป IAP | ดู §5 มติ D-3 |
| เลิกใช้กระเป๋าเงิน | SMS / AI / pin slot ยังใช้อยู่ กระเป๋าเงินไม่หายไปไหน |

## 5. มติที่เคาะแล้ว

| # | มติ | เหตุผล |
|---|---|---|
| **D-1** | ขายผ่าน IAP เฉพาะ **Business Package** | Deep Stock แมปกับ Apple ID ไม่ลงตัว (1 Apple ID ซื้อ auto-renewable ตัวเดิมซ้ำไม่ได้ แต่สิทธิ์เป็นต่อร้าน) |
| **D-2** | ใช้ **StoreKit 2 + ตรวจ JWS เอง** ไม่ใช้ตัวกลาง | ไม่มีบุคคลที่สามถือข้อมูลการจ่ายเงินของลูกค้า · ไม่มีค่าใช้จ่ายรายเดือน · entitlement ของเราซับซ้อน (ผูกร้าน/โควตา/ล็อกร้าน) จะต้องเขียนเองอยู่ดี |
| **D-3** | **ไม่ย้าย** ผู้ใช้เดิมที่จ่ายผ่านกระเป๋าเงิน | Apple ห้าม "ขาย" ในแอป ไม่ได้ห้าม "ให้สิทธิ์ที่ซื้อมาก่อนทำงานต่อ" · การบังคับย้าย = บริการสะดุด + เสี่ยงเก็บซ้ำ + ผู้ใช้จ่ายแพงขึ้น โดยไม่ได้อะไรกลับมา |
| **D-4** | ราคาในแอปเป็นคนละชุดกับเว็บ | ราคาบน App Store ต้องเลือกจาก price tier ที่ Apple กำหนด และมีต้นทุนช่องทางที่ต่างจากเว็บ ⇒ ตั้งเป็นชุดแยก ไม่ผูกสูตรกับราคาเว็บ |
| **D-5** | สิทธิ์ทุกใบเป็นของ **server** ไม่ใช่ของเครื่อง | ผู้ขายสลับเว็บ/แอปตลอดเวลา ถ้าสิทธิ์อยู่ที่เครื่องจะไม่ตรงกันทันที |

## 6. ความเสี่ยงที่รับรู้แล้ว

| # | ความเสี่ยง | ผลกระทบ | การรับมือ |
|---|---|---|---|
| **R-1** | cron เก็บเงินซ้ำกับคนที่จ่ายผ่าน Apple | ผู้ขายถูกหักเงิน 2 ทาง หรือถูกล็อกร้านทั้งที่จ่ายแล้ว — **ร้ายแรงที่สุดของฟีเจอร์นี้** | คอลัมน์ `source` + cron กรอง `source='WALLET'` **ต้องอยู่คอมมิตเดียวกับที่เปิด IAP** + เทส `[blocker]` พิสูจน์ด้วย mutation |
| **R-2** | ~~ผู้ขายที่จ่าย Deep Stock อยู่แล้วและใช้ iOS จะเห็นฟีเจอร์สต็อกหายไป~~ | **ไม่มีตัวตนจริง** | นับจาก prod 2026-09-01 แล้ว: `InventoryEntitlement` **ว่างเปล่า ไม่เคยมีใครสมัคร Deep Stock เลยสักราย** ⇒ ซ่อนได้โดยไม่กระทบใคร (ดู BRD §3.1) |
| **R-3** | ผู้ใช้จ่ายเงินกับ Apple สำเร็จ แต่ server เราล่มตอนบันทึก | จ่ายแล้วไม่ได้ของ | ห้าม `finishTransaction` จนกว่า server ยืนยัน — ธุรกรรมที่ยังไม่ finish จะถูก StoreKit ส่งกลับมาใหม่ทุกครั้งที่เปิดแอป |
| **R-4** | มีคนยิง JWS ปลอมเข้า endpoint | ได้สิทธิ์ฟรี | ตรวจลายเซ็นด้วย root cert ของ Apple + ตรวจ `bundleId` + กันใช้ธุรกรรมซ้ำด้วย unique |
| **R-5** | Apple แจ้ง refund/ยกเลิก แต่เราไม่ได้รับ webhook | ให้บริการฟรีตลอดไป | นอกจาก webhook ต้องมี cron เดินตรวจใบที่ `source='APPLE_IAP'` กับ App Store Server API เป็นตาข่ายชั้นสอง |
| **R-6** | คนซื้อ IAP ด้วย Apple ID เดียว แล้วล็อกอินหลายบัญชี Deep | สิทธิ์เดียวใช้หลายบัญชี | ผูก `originalTransactionId` เป็น unique — ถ้าเจอผูกกับ `ownerId` อื่นแล้วให้ปฏิเสธและอธิบาย |

## 7. เกณฑ์ความสำเร็จ (Acceptance)

| # | เกณฑ์ |
|---|---|
| AC-IAP-01 | ผู้ขายบน iOS เห็นแพ็กเกจพร้อมราคาจาก App Store (ไม่ใช่ราคาที่เรา hardcode) และกดซื้อจบในแอป |
| AC-IAP-02 | ซื้อสำเร็จ → สิทธิ์เปิดทันทีทั้งในแอปและบนเว็บ |
| AC-IAP-03 | subscription ที่มาจาก IAP **ต้องไม่ถูก cron หักกระเป๋าเงินเลยแม้แต่ครั้งเดียว** |
| AC-IAP-04 | Apple ต่ออายุ → `nextRenewalAt` ขยับตามที่ Apple แจ้ง ไม่ใช่ที่เราคำนวณเอง |
| AC-IAP-05 | ผู้ใช้ยกเลิกกับ Apple → สิทธิ์อยู่จนสิ้นรอบ แล้วล็อกร้านตามกติกาเดิมของ 00008 |
| AC-IAP-06 | Apple คืนเงิน → ถอนสิทธิ์ภายในรอบ webhook |
| AC-IAP-07 | ลงแอปใหม่/เปลี่ยนเครื่อง → กด "กู้คืนการซื้อ" แล้วสิทธิ์กลับมา |
| AC-IAP-08 | ผู้ใช้เดิมที่จ่ายผ่านกระเป๋าเงิน เปิดแอปแล้ว **ไม่เห็นปุ่มซื้อ** และของเดิมทำงานปกติ |
| AC-IAP-09 | บนเว็บทุกอย่างเหมือนเดิมทุกประการ — ไม่มีอะไรของ IAP โผล่ |
| AC-IAP-10 | ฟีเจอร์ Deep Stock ไม่ปรากฏในแอป iOS ทั้งปุ่มซื้อและตัวฟีเจอร์ |

|---|---|
