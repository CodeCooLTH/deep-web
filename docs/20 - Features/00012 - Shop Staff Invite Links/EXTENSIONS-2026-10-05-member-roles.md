## PRD — ทำไม

ร้าน BUSINESS มีเจ้าของได้คนเดียวมาตลอด (คนสร้างร้าน) ร้านที่มีหุ้นส่วน 2 คนต้องให้อีกคนเป็น "ผู้ดูแล"
ซึ่งเข้าหน้า `/admins` ไม่ได้ เชิญคนเพิ่มไม่ได้ และถ้าผู้สร้างร้านเลิกทำ ร้านไปต่อไม่ได้เพราะแพ็กเกจผูกกับตัวเขา

## BRD — กฎ

| # | กฎ | เหตุผล |
|---|---|---|
| BR-MR-01 | เจ้าของ (ทุกคนที่ `ShopMember.role='OWNER'`) เปลี่ยนบทบาทสมาชิกคนอื่นเป็น เจ้าของ/ผู้ดูแล ได้ | มติ 3: เจ้าของร่วมมีสิทธิ์เท่าผู้สร้างร้านในหน้า `/admins` (เหมือน gochat) |
| BR-MR-02 | **เจ้าของหลัก** = `Shop.userId` = คนที่แพ็กเกจของเขากำหนดโควตาร้าน — เปลี่ยนบทบาท/ลบไม่ได้ (`PRIMARY_OWNER_LOCKED`) | ร้านจึงมีเจ้าของ ≥1 คนเสมอ (เกณฑ์เดียวกับ gochat) และแพ็กเกจไม่หลุดจากร้าน |
| BR-MR-03 | **โอนเจ้าของหลัก** ได้ — ทำได้เฉพาะเจ้าของหลักคนปัจจุบัน (`NOT_PRIMARY_OWNER`) ให้สมาชิกที่อยู่ในร้านแล้ว | มติ 1 · จำกัดที่เจ้าของหลักเพราะเป็นเรื่องเงินของเขา — ถ้าเจ้าของร่วมโอนได้ = ยึดร้านไปจากคนจ่ายเงินได้ |
| BR-MR-04 | ผู้รับโอนต้องมีแพ็กเกจ ACTIVE (`RECIPIENT_NO_PACKAGE`) · จำนวนร้านธุรกิจของเขายังไม่เต็ม (`RECIPIENT_BUSINESS_QUOTA`) · จำนวนสมาชิกร้านนี้ไม่เกินโควตาของแพ็กเกจเขา (`RECIPIENT_ADMIN_QUOTA`) · ร้านต้องไม่ถูกล็อก (`SHOP_LOCKED`) | ไม่ปฏิเสธ = ร้านจะโดนล็อกทันทีหลังโอน (fail-closed ที่ประตู ดีกว่าล็อกทีหลัง) |
| BR-MR-05 | หลังโอน เจ้าของหลักเดิมยังเป็น **เจ้าของร่วม** (ผู้รับลดสิทธิ์/ลบออกเองได้ภายหลัง) | ย้อนกลับได้ ไม่มีใครหลุดจากร้านโดยไม่ตั้งใจ |
| BR-MR-06 | โควตา "แอดมิน" ของแพ็กเกจนับ **สมาชิกทุกคนยกเว้นเจ้าของหลัก** (เดิมนับ `role='ADMIN'`) — SSOT `staffCountWhere()` | มติ 2: ถ้าไม่นับเจ้าของร่วม จะเลี่ยงโควตาได้ด้วยการเชิญแล้วเลื่อนเป็นเจ้าของ · ข้อมูลเดิมผลเท่ากันเป๊ะ (ก่อนรอบนี้ OWNER มีแค่เจ้าของหลัก) |
| BR-MR-07 | ลบสมาชิก: เจ้าของทุกคนลบได้ทั้งผู้ดูแลและเจ้าของร่วม ยกเว้นเจ้าของหลัก และ**ห้ามลบตัวเอง** (`CANNOT_REMOVE_SELF`) | ลบตัวเอง = ล็อกตัวเองออกจากร้านกลางคัน (เหตุผลเดียวกับ gochat) |
| BR-MR-08 | "ร้านที่ฉันเป็นเจ้าของ" ในเรื่องเงิน (นับโควตาร้าน/หน้า `/business` `/subscriptions`/การ์ดแพ็กเกจ) = `Shop.userId === ฉัน` **ไม่ใช่** `role==='OWNER'` | เจ้าของร่วมไม่ได้จ่ายแพ็กเกจของร้านนั้น — นับผิด = โควตาร้านของเขาเต็มด้วยร้านของคนอื่น |

### ผลข้างเคียงที่ต้องรู้ (ไม่ใช่บั๊ก)
- ระดับยืนยัน L1 ของร้านอิงเบอร์ของ `Shop.userId` (SRS FR-2.7) ⇒ โอนแล้ว L1/Trust Score ของร้านเปลี่ยนตามผู้รับ — คำนวณใหม่ทันทีหลังโอน
- เจ้าของร่วมแก้บัญชีรับเงิน (payout) ได้ — `shop.service` เช็ค `role==='OWNER'` มาแต่เดิม ตรงกับมติ 3 (สิทธิ์เท่ากัน)

## API

| Method | Path | Body | สิทธิ์ |
|---|---|---|---|
| PATCH | `/api/business/shops/[shopId]/members/[memberId]` | `{ role: 'OWNER' \| 'ADMIN' }` | เจ้าของทุกคน |
| DELETE | `/api/business/shops/[shopId]/members/[memberId]` | — | เจ้าของทุกคน (เดิม: เจ้าของหลักเท่านั้น) |
| POST | `/api/business/shops/[shopId]/transfer` | `{ memberId }` | เจ้าของหลักเท่านั้น |

error → HTTP: `NOT_OWNER`/`NOT_PRIMARY_OWNER` 403 · `NOT_A_MEMBER` 404 · อื่น ๆ 409
