## ปัญหาจริงคืออะไร

คอมเมนต์ **ไม่ใช่ข้อความในเธรดและไม่มีทางเป็นได้** — Meta ไม่ย้ายคอมเมนต์เข้ากล่องข้อความ
ผู้ขายจึงเปิดห้องมาแล้ว **ไม่รู้ว่ากำลังตอบเรื่องอะไร** ต้องเด้งออกไปเปิด Facebook เอง
คำว่า "ไม่เจอข้อความ" ของหัวหน้าจึงถูกต้องตามที่เห็นทุกประการ แค่คนละสาเหตุกับที่ทีมเดาไว้ตอนแรก

## ทางแก้

แสดง **คอมเมนต์ต้นเหตุเป็นรายการแรกของเธรด** — ข้อมูลมีครบในฐานอยู่แล้ว
(`CommentReplyLog.conversationId ↔ commentId → PageComment`) **ไม่ต้องยิง Graph ใหม่
ไม่ต้อง migration ไม่ต้อง OTA แอป** และ query เดิมที่หน้าเธรดใช้อยู่แล้วก็แค่ `select` เพิ่ม

```
┌────────────────────────────────────────┐
│ ลูกค้าคอมเมนต์ใต้โพสต์ · 09 ส.ค. 10:25  │
│ เยี่ยม                                  │
│ ดูคอมเมนต์บน Facebook →                │
└────────────────────────────────────────┘
                วันนี้
                        [ สนใจรุ่นไหนคะ ]
```

### การตัดสินใจที่บันทึกไว้

- **วางเป็นรายการแรกในลิสต์ ไม่ใช่แถบปักหมุดเหนือลิสต์** — คอมเมนต์เกิดก่อนข้อความทุกใบจริง ๆ
  จึงเป็นเหตุการณ์แรกตามลำดับเวลา และเมื่อคุยกันยาวขึ้นมันจะเลื่อนหายไปเองเหมือนข้อความเก่า
  แทนที่จะกินหัวจอถาวร (บทเรียนเดียวกับแถบเตือนที่ user สั่งให้เอาออกวันเดียวกัน: ข้อมูลที่ค้าง
  อยู่หัวเธรดทุกครั้งที่เปิด กลายเป็น noise เมื่อไม่เกี่ยวกับสิ่งที่กำลังทำ)
- 🛑 **เงื่อนไข `!oldestCursor`** — ยังมีข้อความเก่ากว่านี้ให้โหลด = ตอนนี้ยังไม่ใช่หัวเธรดจริง
  ถ้าโชว์ไว้ คอมเมนต์จะไปแทรกกลางบทสนทนา ซึ่งผิดลำดับเวลา
- **ไม่ลบบรรทัดระบบของ Meta ทิ้ง** — มันเป็นแถวข้อความจริงในฐาน การซ่อนต้องไปยุ่งกับลิสต์/
  pagination โดยแลกมาแค่ความสวย ตอนนี้มันถูก render เป็นบรรทัดกลางจอสีเทา (meta-system-notice)
  ซึ่งอ่านเป็นเชิงอรรถอยู่แล้วเมื่อมีการ์ดภาษาไทยอยู่เหนือมัน
- **ลิงก์:** `FacebookPost.permalink` + `?comment_id={ท่อนหลังของ externalCommentId}` —
  ไม่มี permalink → ไม่ขึ้นลิงก์เลย ดีกว่าเดา URL แล้วพาไปหน้า error; ถ้าท่อน comment_id เพี้ยน
  Facebook ยังเปิดโพสต์ให้อยู่ดี (เสียแค่การเลื่อนไปที่คอมเมนต์)
- **คอมเมนต์ที่เป็นรูปล้วน** (`message` ว่าง + มี `attachmentUrl`) ขึ้นคำว่า "ส่งรูปมาในคอมเมนต์"
  ไม่ปล่อยการ์ดว่างซึ่งอ่านเหมือนระบบโหลดไม่ขึ้น

## E2 — คอมเมนต์ที่ทักแชทแล้วต้องหลุดจากคิว "ยังไม่ตอบ" + แท็บเหลือ 2 ตัว

ดูกฎเต็มที่ `SRS.md` §BR-CR-S1 (แก้ 2026-08-09) — สรุป: ไม่มีคำตอบสาธารณะแต่ทักแชทสำเร็จแล้ว
→ บอททัก = บอทตอบแล้ว · คนกดทัก = คนตอบแล้ว **ไม่เพิ่มค่าที่ 4 ในเอนัม**

แท็บด้านบนเหลือ **2 ตัว: ทั้งหมด / ยังไม่ตอบ** (user สั่ง) — ถอด "บอทตอบ"/"คนตอบ" ออกเพราะเป็น
การแบ่งที่ตอบว่า *ใครเป็นคนตอบ* ไม่ใช่ *เหลืออะไรต้องทำ* · **ถอดแค่แท็บ ไม่ได้ถอดความหมาย**
ป้ายบนแถวโพสต์และตัวกรอง `?state=` ฝั่ง server ยังรองรับครบทั้ง 3 สถานะ

ป้ายเขียว "ตอบแล้ว" ใต้บับเบิลในเธรดยังผูกกับคำตอบ**สาธารณะ**เท่านั้น (prop `publiclyAnswered`)
— ถ้าให้อ่านเกณฑ์เดียวกับคิว คอมเมนต์ที่ทักแชทอย่างเดียวจะขึ้นเขียวทั้งที่ไม่มีคำตอบให้คนอื่นเห็น
บนโพสต์ = ผิด Verified-Means-Green

## E4 — แถบที่มาของเธรดจากคอมเมนต์ (ห้องแชท)

การ์ดคอมเมนต์ต้นเหตุถูกยุบจาก 5 บรรทัดในสตรีมข้อความ → **แถวเดียวติดหัวแชท ที่เดียวกับแบนเนอร์
โฆษณา** (user: "merge เป็นด้านบนที่เดียว" · "มันกินพื้นที่เวลาอยู่บน mobile")

- บรรทัดบน = ข้อความโพสต์ (ตอบ "เค้า Post จากไหน") · บรรทัดล่าง = ข้อความคอมเมนต์ + ลิงก์ "ดูคอมเมนต์"
