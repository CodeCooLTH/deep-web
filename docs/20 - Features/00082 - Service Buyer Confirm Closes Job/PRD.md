# PRD: ลูกค้ายืนยันรับบริการ = ปิดงาน + ชำระครบ (ร้านบริการเท่านั้น)

## 1. ปัญหา

ร้านบริการ flow 4 ขั้น (00073): ร้านสร้างงาน → ลูกค้ายืนยันนัด → **ร้านปิดงาน** → **ลูกค้ายืนยันรับบริการ**

ผังของ 00073 มี "ทางลัด" ให้ลูกค้ากดยืนยันรับบริการได้เลยโดยข้ามขั้น 2–3 แต่ในระบบจริง ขั้น 3 ยังค้าง:

- ใบค้างเป็น **"ลูกค้ายืนยันแล้ว · รอร้านปิดงาน"** จนกว่าร้านจะกดปิดงานเอง
- ยอดไม่เข้าการเงินร้าน (การ์ดกำไร: "ยังไม่นับเป็นยอดขาย")
- ลูกค้า **ไม่ได้ใบเสร็จ** เพราะใบเสร็จต้องการ ปิดงานแล้ว + ชำระครบ (`canBuyerViewReceipt`)

เจอจริงบน prod 2026-10-21: ใบ DP256910831F0D9E (ร้าน BT Premium - สุขสวัสดิ์) ลูกค้าเห็นเส้นสถานะเขียวครบ แต่ร้านยังเห็นปุ่ม "ปิดงาน" และลูกค้าไม่มีใบเสร็จ

## 2. สิ่งที่จะทำ (มติ user 2026-10-21)

ลูกค้ากด **"ยืนยันรับบริการ"** (ชื่อปุ่มเดิม ไม่เปลี่ยน) บนงานที่ร้าน **ยังไม่ปิดงาน** ⇒ ระบบทำให้ในคลิกเดียว:

1. **ปิดงาน** ผล = ให้บริการแล้ว · วันปิดงาน = เวลาที่ลูกค้ากด · มีนัด ⇒ สถานะนัด = ให้บริการแล้ว
2. **บันทึกว่าชำระครบ** ยอดที่ยังค้างถูกลงเป็นรายการรับเงิน 1 รายการ (ร้านยกเลิกรายการนี้ได้ถ้าลูกค้ากดโดยยังไม่จ่าย)
3. **ใบเสร็จขึ้นให้ลูกค้าทันที** ไม่ต้องรีเฟรช

ร้าน **ปิดงานไปแล้วแบบค้างชำระ** แล้วลูกค้ามากดยืนยัน ⇒ บันทึกชำระครบให้ด้วย (ไม่ปิดซ้ำ วันปิดงานคงเดิม) — D-5

ใบเก่าที่ค้าง "ลูกค้ายืนยันแล้ว · รอร้านปิดงาน" อยู่แล้ว ⇒ **ปิดย้อนหลัง** นับวันตามวันที่ลูกค้ายืนยัน และ **บันทึกชำระครบด้วย** · ใบเก่าที่ร้านปิดแบบค้างและลูกค้ายืนยันแล้ว ⇒ บันทึกชำระครบด้วย

## 3. ขอบเขต

| อยู่ในขอบเขต | นอกขอบเขต (ไม่แตะ) |
|---|---|
| ร้าน `SERVICE_QUEUE` เท่านั้น (`usesServiceFinanceRules`) | ร้านขายของ · ที่พัก · การจอง (BOOKING) |
| ทางยืนยันทั้งเว็บ `/o/[token]` และแอป `/api/app/orders/[id]/confirm` (ใช้ `confirmOrder` ตัวเดียว) | ชื่อปุ่ม/หน้าตาฝั่งลูกค้า (นอกจากปุ่มใบเสร็จขึ้นทันที) |
| ปิดย้อนหลังใบเก่า (migration ข้อมูล) | ปุ่มร้านทุกปุ่ม (ปิดงาน · เริ่มงาน · เปิดงานอีกครั้ง · บันทึกรับเงิน) — ทำงานเหมือนเดิม |
| | รีวิว (รีวิวต่อได้เหมือนเดิม) · ไม่มาตามนัด (ยืนยันไม่ได้อยู่แล้ว) · รายงานกลุ่ม LINE · สิทธิ์ |

## 4. ผู้ใช้และผลที่เห็น

| ใคร | ก่อน | หลัง |
|---|---|---|
| ลูกค้า | กดยืนยันแล้วไม่มีใบเสร็จ (ถ้าร้านยังไม่ปิด) | กดยืนยันแล้วเห็นปุ่มใบเสร็จทันที |
| เจ้าของร้าน | ต้องกดปิดงานซ้ำทุกใบที่ลูกค้ายืนยันไปก่อน | ใบเป็น "ปิดงานแล้ว · ชำระครบ" เอง · ยอดเข้าการเงินวันนั้น |
| หน้าแรก/รายงานร้าน | ใบพวกนี้อยู่ "รอปิดงาน" / "ยังไม่ปิดงาน" (เหลือง) | ย้ายไป "ปิดงานแล้ว" (เขียว) ตามวันที่ลูกค้ายืนยัน |

## 5. ข้อยกเว้นกติกาเดิม (บันทึกไว้ให้เห็น)

- **กติกาหัวหน้า 2026-08-15 (00050):** "มีสลิป ≠ ได้รับเงิน — ระบบห้ามบันทึกรับเงินเองจากการกระทำของลูกค้า" ⇒ 00082 เป็นข้อยกเว้นที่ **user ตัดสินแล้ว 2026-10-21** (แบบ ก.): การกด "ยืนยันรับบริการ" ของลูกค้าร้านบริการ = ลูกค้ารับรองว่าชำระแล้ว · ทุกแถวยังมี `receivedByUserId` (= ลูกค้าที่กด) และแก้ด้วยการยกเลิกรายการ (void) ตามกติกาเดิม
- **ปิดงานก่อนเวลานัด:** ร้านปิดก่อนถึงเวลานัดไม่ได้ (BR-RSV-34) แต่ลูกค้ายืนยันเองว่าได้รับบริการแล้ว ⇒ ระบบปิดให้ได้ทุกเวลา

## 6. ตัวชี้วัด

- ใบร้านบริการสถานะ "ลูกค้ายืนยันแล้ว · รอร้านปิดงาน" = 0 หลัง deploy (ใบใหม่ไม่เกิด + ใบเก่าถูกปิดย้อนหลัง)
- ลูกค้าที่ยืนยันแล้วเปิดใบเสร็จได้ 100%

## 7. ความเสี่ยง

| ความเสี่ยง | การรับมือ |
|---|---|
| ลูกค้ากดยืนยันทั้งที่ยังไม่จ่าย ⇒ บัญชีร้านบอกว่าได้เงินแล้ว | ร้านยกเลิกรายการรับเงินนั้นได้ (มีอยู่แล้ว) ⇒ ใบกลับเป็นค้างชำระ · หมายเหตุบนรายการบอกว่าลูกค้าเป็นคนยืนยัน |
| ยอดย้อนหลังของเดือนก่อนเปลี่ยนเมื่อปิดย้อนหลัง | ตั้งใจ (มติ user: นับวันตามวันที่ลูกค้ายืนยัน = ตรงความจริง) |
| migration ข้อมูลรันบน prod ตอน merge | สคริปต์ idempotent · ทดสอบกับฐาน local ก่อน · แจ้ง 3 ข้อตาม HR15 |

## 8. คำถาม (ตอบครบแล้ว)

- **Q-1** ร้าน **ปิดงานไปแล้วแบบค้างชำระ** แล้วลูกค้ามากดยืนยันทีหลัง ⇒ บันทึกชำระครบให้ด้วยไหม (ทั้งใบใหม่และใบเก่า)
  - **ตอบ: ใช่** (user 2026-10-23) — "ลูกค้ายืนยัน = ชำระแล้ว" กติกาเดียวทุกกรณี ลูกค้าได้ใบเสร็จเหมือนกัน · วันปิดงานเดิมไม่ถูกแตะ
