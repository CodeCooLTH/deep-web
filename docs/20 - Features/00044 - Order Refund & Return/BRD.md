# BRD — 00044 คืนเงิน/คืนสินค้าหลังส่งถึงมือลูกค้า

> สถานะ: **ร่าง รอ user review** (คู่กับ `PRD.md` — HR11 ห้าม implement ก่อนทั้งคู่ผ่าน)
> วันที่: 2026-08-11

---

## 1. กฎธุรกิจ (BR)

| id | กฎ | เหตุผล / ที่มา |
|---|---|---|
| BR-RF-01 | mark คืนเงินได้เฉพาะออเดอร์ที่ **ของถึงมือลูกค้าแล้ว** — เกณฑ์ = `status='CONFIRMED'` **หรือ** พัสดุมี `carrierStatus ∈ DELIVERED_CARRIER_STATUSES` | ถ้าของยังไม่ถึง เส้นทางที่ถูกคือ "ยกเลิก" หรือปล่อยให้พัสดุตีกลับ ไม่ใช่คืนเงิน |
| BR-RF-02 | ห้าม mark ใบที่ `status='CANCELLED'` | ยกเลิกแล้วยอดถูกตัดไปแล้ว หักซ้ำ = ยอดขายติดลบ |
| BR-RF-03 | `0 < refundAmount ≤ totalAmount` ของใบนั้น | คืนเกินยอดที่รับมาไม่ใช่การคืน — เป็นการจ่ายเงินออก ซึ่งเป็น "ค่าใช้จ่าย" คนละบัญชี |
| BR-RF-04 | **บังคับระบุว่าของกลับเข้าสต็อกไหม** ไม่มีค่าตั้งต้น | D-2 — เดาแทนร้านแล้วสต็อก/ต้นทุนเพี้ยนโดยไม่มีใครรู้ |
| BR-RF-05 | ของกลับเข้าสต็อก → คืน `stockQty` ตามจำนวนในใบ **และ** ต้นทุน (COGS) ของใบนั้นถูกหักออกจากต้นทุนช่วงนั้น | ของกลับมาขายใหม่ได้ = ต้นทุนยังไม่ถูกใช้ไป |
| BR-RF-06 | ของไม่กลับ/เสียหาย → **ไม่แตะสต็อก และต้นทุนยังคงเป็นต้นทุน** | นี่คือขาดทุนจริง (จ่ายต้นทุน + คืนเงิน) ต้องเห็นในกำไร ไม่ใช่ซ่อน |
| BR-RF-07 | **ยอดขายสุทธิของใบ = `totalAmount − refundAmount`** และต้องมาจากฟังก์ชันเดียวทั้งระบบ | HR16 — ดู PRD §6 |
| BR-RF-08 | คืนเต็มจำนวน (`refundAmount = totalAmount`) **ไม่** ทำให้ใบนั้นหายจากรายงาน | ใบยังมีอยู่จริง เกิดต้นทุน/ค่าส่งจริง แค่ยอดขายสุทธิเป็น 0 — ซ่อนใบทิ้งคือการลบหลักฐาน |
| BR-RF-09 | **ไม่กระทบ** Trust Score · อัตราความสำเร็จ · จำนวนดีลสำเร็จบนโปรไฟล์ร้าน | BR-OSM-05: สิ่งที่ร้านกรอกเองต้องไม่มีอำนาจเหนือคะแนนที่ผู้ซื้อใช้ตัดสินใจ |
| BR-RF-10 | **ไม่นับเข้าป้ายเตือนพฤติกรรมลูกค้า** | D-3 — ของเสียหายเป็นความผิดของของ ไม่ใช่ของลูกค้า |
| BR-RF-11 | ถอน mark ได้ ตัวเลขทุกจอกลับเป็นเดิม · การถอนต้องคืนสต็อกที่เคยคืนกลับไปด้วย (ถ้าเคยคืน) | ป้องกันสต็อกบวมจากการกดผิดแล้วถอน |
| BR-RF-12 | ทุกการ mark/ถอน เขียน `OrderEvent` เสมอ | ประวัติคือหลักฐาน — ร้านต้องตอบลูกค้าได้ว่าคืนเมื่อไร เท่าไร ใครกด |
| BR-RF-13 | `OrderEvent.occurredAt` = **เวลาที่กดจริง** ห้ามย้อนตามวันที่ที่ร้านกรอก | บทเรียน 00033 — ประวัติคือหลักฐาน วันที่เชิงบัญชีเก็บใน `meta` |
| BR-RF-14 | สิทธิ์ mark = OWNER + `ShopMember(role='ADMIN')` | ตรงกับสิทธิ์ที่ใช้กับการยกเลิกออเดอร์อยู่แล้ว (ยืนยันตอน SDS) |

## 2. คำที่ใช้ (UX copy — ล็อกไว้กันชนกับของเดิม)

| แนวคิด | คำที่ใช้ | ห้ามใช้ | เหตุผล |
|---|---|---|---|
| ใบที่ร้านคืนเงินให้ | **"คืนเงินแล้ว"** | "ตีกลับ", "คืนของ" | "พัสดุตีกลับ" เป็นคำที่ระบบใช้กับของที่ไม่ถึงมืออยู่แล้ว (มีเทส `[blocker]` ล็อกไว้) ใช้คำเดียวกันจะทำให้สองสถานการณ์ที่ต่างกันสิ้นเชิงอ่านเหมือนกัน |
| ยอดที่คืน | **"ยอดที่คืน"** | "ส่วนลด" | ส่วนลดเกิดตอนขาย คืนเงินเกิดหลังขาย คนละบรรทัดในบัญชี (บทเรียน iShip `discount_price`) |
| ของกลับเข้าสต็อก | **"ได้ของกลับคืนมา"** | "รับคืน" | สั้นแต่กำกวมกับ "รับคืนเงิน" |
| ยอดขายหลังหักคืน | **"ยอดขายสุทธิ"** | — | ต้องนิยามคู่กับ `NET_PROFIT_FORMULA`/`GROSS_PROFIT_FORMULA` ที่มีอยู่แล้วใน `format-money.ts` และวางไว้ไฟล์เดียวกัน (HR16) |

## 3. ผลกระทบทางบัญชี (ตัวอย่างเลขจริง)

ออเดอร์ 890 บาท · ต้นทุนสินค้า 400 · ค่าส่ง 50

| กรณี | ยอดขายสุทธิ | ต้นทุน | กำไรขั้นต้น | สต็อก |
|---|---|---|---|---|
| ปกติ (ไม่คืน) | 890 | 400 | 490 | −1 |
| คืนเต็ม · **ได้ของกลับ** | 0 | 0 | 0 (เสียค่าส่ง 50 ที่ระดับค่าใช้จ่าย) | คืน +1 |
| คืนเต็ม · **ของเสียหาย** | 0 | 400 | **−400** | ไม่คืน |
| คืนบางส่วน 200 · ของไม่กลับ | 690 | 400 | 290 | ไม่คืน |

🛑 แถวที่ 3 คือเหตุผลทั้งหมดที่ต้องมี D-2: ถ้าระบบเดาว่า "คืนเงิน = ของกลับ" เสมอ ร้านจะไม่มีวัน
เห็นขาดทุน −400 ใบนี้เลย และจะเข้าใจว่าการคืนเงินไม่มีต้นทุน

## 4. ผลกระทบต่อฟีเจอร์ที่มีอยู่ (ต้องตรวจตอน SDS)

| ฟีเจอร์ | กระทบไหม | หมายเหตุ |
|---|---|---|
| ยอดขาย `/sales`, dashboard, P&L | **ใช่** | PRD §6 |
| กำไรรายใบ (`order-profit.ts`) | **ใช่** | ต้องหักทั้งยอดและต้นทุนตาม D-2 |
| ยอดซื้อรวมต่อลูกค้า (`/customers`, แผงลูกค้าในแชท) | **ใช่** | ไม่หัก = "ลูกค้ารายนี้ซื้อ 50,000" ทั้งที่คืนไป 20,000 |
| Inventory add-on (สต็อก) | **ใช่** (เฉพาะเมื่อของกลับ) | ต้องใช้เส้นทางบันทึกความเคลื่อนไหวสต็อกที่มีอยู่ ไม่เขียน `stockQty` ตรง ๆ |
| Trust Score / อัตราความสำเร็จ / โปรไฟล์ร้าน | **ไม่** | BR-RF-09 |
| ป้ายพฤติกรรมลูกค้า (งาน 2026-08-11) | **ไม่** | BR-RF-10 |
| การ์ดออเดอร์ในแชท / ไทม์ไลน์ | **ใช่** (แค่แสดงป้าย) | ป้าย "คืนเงินแล้ว" |
| iShip / พัสดุ | **ไม่** | คนละแกน ของส่งไปแล้วจริง |

## 5. ความเสี่ยง

| ความเสี่ยง | ผลถ้าเกิด | การป้องกัน |
|---|---|---|
| แก้ยอดขายไม่ครบทุกจุด | สองจอบนหน้าเดียวกันให้เลขคนละตัว ร้านเลิกเชื่อรายงาน | ฟังก์ชันเดียว (`netRevenueOf`) + เทสสแกนว่าไม่มีใคร SUM `totalAmount` ดิบในเส้นทางยอดขาย |
| ร้านใช้ mark คืนเงินแทนการยกเลิก | สถิติเพี้ยนทั้งชุด | BR-RF-01 กันที่ server (ต้องส่งถึงแล้วเท่านั้น) + copy อธิบายความต่าง |
| กดผิดแล้วสต็อกบวม | ของในระบบไม่ตรงของจริง | BR-RF-11 (ถอนแล้วคืนสต็อกกลับ) + บันทึกความเคลื่อนไหวทุกครั้ง |
| คืนเงินซ้ำสองครั้งบนใบเดียว | ยอดขายติดลบ | 1 ใบ = 1 การคืน (แก้ยอดได้ แต่ไม่ mark ซ้อน) — ยืนยันตอน SDS |

## 6. Definition of Done (ระดับธุรกิจ)

- ร้าน mark คืนเงินเต็ม/บางส่วนได้บนใบที่ส่งถึงแล้ว และถอนได้
- ตัวเลขทุกจอในตาราง §4 ที่ทำเครื่องหมาย "ใช่" หักยอดตรงกันหมด — **ตรวจด้วยการเปิดจริงทีละจอ
  ไม่ใช่เชื่อว่าแก้ที่ SSOT แล้วครบ** (บทเรียน 2026-08-08: การ์ดกำไรมีนิยามของตัวเองทั้งที่ import
  จากไฟล์เดียวกับ SSOT)
- Trust Score/อัตราความสำเร็จของร้านทดสอบ **ไม่ขยับ** ก่อน-หลัง mark
- มี `OrderEvent` ครบทั้งการ mark และการถอน
- เทส `[blocker]`: ยอดสุทธิ · เพดานยอดคืน · ของกลับ/ไม่กลับต่อกำไร · ถอนแล้วกลับเป็นเดิม ·
  ห้ามกระทบ Trust Score/ป้ายพฤติกรรม
