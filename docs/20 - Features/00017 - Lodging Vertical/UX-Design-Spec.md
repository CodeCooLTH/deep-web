### การตัดสินใจที่สำคัญ

**ทำไมใช้การ์ดเลือกได้ ไม่ใช่ radio เปล่า ๆ:** ความเสี่ยงอันดับต้นของฟีเจอร์นี้คือผู้ใช้สับสนระหว่าง *ประเภทกิจการ* กับ *ประเภทผู้ประกอบการ* (PRD §6.1) การ์ดที่มีคำอธิบายในตัวทำให้แยกออกทันทีโดยไม่ต้องอ่านป้ายอย่างเดียว ส่วนช่องผู้ประกอบการคง radio เรียบไว้ — **ความต่างของรูปแบบเองก็เป็นสัญญาณว่าคนละเรื่อง**

**ทำไมมีข้อความช่วยใต้ช่องผู้ประกอบการ:** เดิมไม่มี ทำให้ไม่มีอะไรบอกว่าช่องนี้ต่างจากช่องบนยังไง

### Paces class

| องค์ประกอบ | class |
|-----------|-------|
| การ์ดตัวเลือก | `card cursor-pointer border-2 border-transparent` → ถูกเลือก: `border-primary bg-primary/5` |
| ชื่อตัวเลือก | `text-default-800 font-medium` |
| คำอธิบาย | `text-default-500 text-sm` |
| คำเตือน | `text-default-500 text-sm` + icon `tabler:info-circle` |
| label | `form-label` · required: `text-danger ms-0.5` |

🛑 ห้าม arbitrary value — ใช้ `border-primary`/`bg-primary/5` token ไม่ใช่ hex

### ข้อความ (Impeccable — บอกสิ่งที่ได้ ไม่ขายของ)

- ประเภทกิจการ: `สินค้าและบริการ` / `บ้านพักตากอากาศ`
- คำอธิบาย: มาจาก `SHOP_VERTICAL_HINTS` ใน `lib/lodging.ts` (SSOT ไม่เขียนซ้ำในหน้า)
- คำเตือน: `เลือกแล้วเปลี่ยนภายหลังไม่ได้ หากต้องการประเภทอื่นให้สร้างธุรกิจใหม่`
- ช่วยเหลือใต้ผู้ประกอบการ: `ใช้สำหรับการยืนยันตัวตนระดับ 3`

### ส่วนมัดจำ — จุดที่ออกแบบยากที่สุด

**ปัญหา:** เจ้าของต้องเข้าใจทันทีว่ากำลังตั้งแบบไหน และผลลัพธ์จริงคือเท่าไร

**ทางออก: กล่องตัวอย่างคำนวณสด** ใต้ช่องกรอก อัปเดตตามค่าที่พิมพ์ โดยสมมติการจอง 3 คืนจากราคาที่กรอกไว้ในฟอร์มเดียวกัน

- โหมด `PERCENT` → แสดงยอดหลัง **ปัดขึ้นเป็นบาทเต็ม** ให้ตรงกับที่ระบบคิดจริง (BR-LODG-35)
- 🛑 การคำนวณตัวอย่างนี้เป็น **การแสดงผลเท่านั้น** ยอดจริงตอนสร้างการจองมาจาก server เสมอ (TFR-002) — client คำนวณซ้ำได้เฉพาะเพื่อ preview
- ใส่ 0 → กล่องเปลี่ยนเป็น `ไม่เก็บมัดจำ ผู้จองไม่ต้องโอนก่อน`

**ทำไมใช้ `form-select` ไม่ใช่ปุ่มสลับ:** เป็น field ที่ bind react-hook-form → Hard Rule 6 บังคับ native select (mobile ได้ OS picker + ไม่พังตอน re-render)

|-------|-------|----------|
| พื้นฐาน | 7 | Wi-Fi, แอร์, เครื่องทำน้ำอุ่น, สมาร์ททีวี, เครื่องซักผ้า, พัดลมเพดาน, โต๊ะทำงาน |

### รูปภาพ
- `FileUploader` เดิม, จำกัด **10 รูป** (`MAX_ROOM_IMAGES`)
- **ลากจัดลำดับได้** (ตัดสินโดย user 2026-07-22) — ลำดับใน array คือลำดับแสดงผล **ตัวแรก = รูปหลัก**
  - mobile ที่ลากยาก → มีปุ่ม `ตั้งเป็นรูปหลัก` บนรูปที่ไม่ใช่ตัวแรกด้วย (ไม่พึ่ง drag อย่างเดียว)
  - ไม่มี field แยกสำหรับรูปหลัก — ลำดับ array เป็น SSOT เดียว (ตรงกับ schema `images` Json)
- รูปหลักแสดงป้าย `★` (typographic dingbat สีเดียว = carve-out ที่อนุญาต ไม่ใช่ emoji)
- ปุ่มลบ `tabler:x` มุมรูป — ลบรูปใช้ Sweet Alerts confirm
- เกิน 10 → `pacesToast.warning('เพิ่มรูปได้สูงสุด 10 รูปต่อห้อง')`

### ข้อความ error (ยึด [[API]] §5.2 ห้ามเขียนใหม่)
- ราคา ≤ 0 → `ราคาต่อคืนต้องมากกว่า 0`
- มัดจำ % > 100 → `เปอร์เซ็นต์มัดจำต้องไม่เกิน 100`
- บันทึกสำเร็จ → `pacesToast.success('บันทึกห้องพักแล้ว')` (ไม่ไฮป์ ไม่ใส่ "เรียบร้อย!" ซ้ำซ้อน)

## 7. Impeccable compliance

| กฎ | ใช้ยังไงในงานนี้ |
|----|------------------|
| **The Trusted Counter** | ข้อความบอกทางออกเสมอ (empty state ชวนเพิ่มห้อง, error บอกวิธีแก้), กล่องตัวอย่างมัดจำลดความไม่แน่ใจของเจ้าของ |
| **One Voice (accent ≤10%)** | น้ำเงิน `bg-primary` ใช้เฉพาะปุ่มหลัก, การ์ดที่ถูกเลือก และ chip ที่เลือกแล้ว — ไม่ใช้เป็นพื้นตกแต่ง |
| **Verified-Means-Green** | เขียวใช้กับ badge "เปิดรับจอง" (ยืนยันแล้วว่าใช้งานได้) เท่านั้น; "ปิดรับจอง" ใช้สีกลาง **ไม่ใช่แดง** เพราะไม่ใช่ความผิดพลาด |
| **Sentence case** | ทุก label/ปุ่มเป็นไทย ไม่มี ALL CAPS |
| **Ink-tinted shadow** | ใช้เงาของ Paces `.card` เดิม ไม่เพิ่มเงาเอง ไม่ใช้ดำสนิท |
| **Anti-slop** | ไม่มี gradient ตกแต่ง, ไม่มี hero-metric, ไม่มี eyebrow ตัวพิมพ์ใหญ่จิ๋ว, ไม่ซ้อนการ์ดในการ์ด (การ์ดตัวเลือกใน §1 อยู่ใน card-body ไม่ใช่ card ซ้อน card) |
| **น้ำเสียง** | ไม่มี "ไม่สามารถ...ได้" / "คุณไม่มีสิทธิ์"; ไม่มี "เยี่ยมมาก!" |
| **ไม่มี emoji** | icon จริงทุกจุด — verified กับ iconify API แล้วทุกตัว; `★` รูปหลักเป็น typographic dingbat สีเดียว = carve-out ที่อนุญาต |

### จุดที่ theme กับ Impeccable อาจขัดกัน
Paces เดิมใช้ badge สีแดงกับสถานะ inactive ในบางหน้า — **ที่นี่เลือกไม่ตาม** เพราะ "ปิดรับจอง" เป็นการตัดสินใจปกติของเจ้าของ ไม่ใช่ข้อผิดพลาด การใช้สีแดงจะสื่อผิดและขัด Trusted Counter → ใช้สีกลางแทน
