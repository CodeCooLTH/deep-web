| — | `GET` ไม่มี session → 401 | ผ่าน |

**สองบั๊กที่เทสชุดนี้จับได้ตอนเขียน** (ไม่ใช่แค่ยืนยันของที่ถูกอยู่แล้ว)
1. เพดาน 6 คลิปไม่ได้ถูกบังคับที่ route — `replaceShopVideos` ตัดด้วย `slice` จึงไม่เกินลง DB แต่ response ตอบ `count` เท่าที่ร้านส่งมา ร้านที่ส่ง 7 ได้ `ok:true count:7` ทั้งที่เก็บ 6 = รายงานเท็จ แก้เป็นปฏิเสธ 400 `TOO_MANY`
2. `owned.failed` ถูกเช็คก่อนเทียบความเป็นเจ้าของ → ช่องทางใดล้มก็บล็อกการบันทึกทั้งหมด ทั้งที่คลิปที่ขอยืนยันได้ครบจากช่องที่ยังดี ร้านที่เชื่อม FB+IG จึงแก้คลิป FB ไม่ได้ตอน IG ล่ม แก้เป็นเทียบก่อน แล้วค่อยแยก 503/403 เมื่อไม่ครบ

## 3. E2E (Playwright) — `e2e/shop-video-showcase.spec.ts` (6 เคส ผ่านทั้งหมด)

รัน: `node_modules/.bin/dotenv -e ../main-3/.env.local -- npx playwright test e2e/shop-video-showcase.spec.ts`

| รหัส | เส้นทาง | ผล |
|---|---|---|
| A1 (E2E-4) | ผู้ชมที่ไม่ล็อกอินเปิดหน้าร้าน → "ปักหมุด" เป็นแท็บแรกและเปิดอยู่ + คลิปครบ + ยอดที่เป็น null ไม่กลายเป็น 0 | ผ่าน |
| A2 (E2E-6) | ร้านที่ไม่มีคลิป → ไม่มีแท็บ "ปักหมุด" เลย | ผ่าน |
| B (E2E-5) | ก่อนกดเล่น ไม่มี request ไปโดเมนแพลตฟอร์มแม้แต่รายการเดียว (NFR-V1) | ผ่าน |
| C | กดแล้วจึงฝัง iframe · src อยู่ในโดเมนที่ตั้งใจ · มี `sandbox` (NFR-V2/V3) | ผ่าน |
| D | ร้านที่ยังไม่เชื่อมช่องทาง → หน้าตั้งค่าบอกสถานะ ไม่ใช่หน้าเปล่า | ผ่าน |
| E | ยิง `PUT` จริงด้วย cookie ของร้าน ด้วยคลิปที่ไม่ใช่ของร้าน → ถูกปฏิเสธ + DB ว่างเปล่า | ผ่าน |

**ยังนอกขอบเขต** (ต้องมีบัญชี FB/IG ที่เชื่อมจริงถึงจะมีคลิปให้เลือก → ทำใน smoke test บน prod)
E2E-1 เลือกคลิปจากแท็บช่องทางแล้วบันทึก · E2E-2 เพดาน 6 คลิปบน UI · E2E-3 ถอดคลิปกลางออกแล้วลำดับเรียงต่อ

**กับดักที่เจอตอนเขียน spec:** `/b/[slug]` รับเฉพาะร้าน `kind = BUSINESS` แต่ `requireActiveShop` ฝั่งร้านหาร้าน BUSINESS ไม่เจอถ้า session ไม่มี `activeShopId` (ร้าน BUSINESS ผูกกับ user ผ่าน ShopMember ไม่ใช่ `userId` ตรง) → เคสหน้าสาธารณะต้อง BUSINESS เคสฝั่งร้านต้องคง PERSONAL ไม่งั้น API ตอบ 404 แทนที่จะถึงด่านที่กำลังทดสอบ
