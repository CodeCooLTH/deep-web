# PRD: Shop Video Showcase

---

## หมายเหตุสำคัญเรื่องลำดับการทำงาน

เอกสารชุดนี้เขียน**หลัง**ลงโค้ดและ deploy ไปแล้ว ซึ่งขัดกับ Hard Rule 11 ที่กำหนดว่าต้องมี PRD+BRD ผ่านการทบทวนก่อนเริ่ม implement

สาเหตุตามจริง: ฟีเจอร์นี้เกิดจากบทสนทนาที่เปลี่ยนขอบเขตหลายรอบภายในวันเดียว (จากแปะลิงก์ → เป็นเลือกจากบัญชีที่ยืนยันแล้ว → เพิ่ม Facebook → เพิ่มยอดวิว) การเขียนเอกสารตามทันแต่ละรอบจึงไม่เกิดขึ้น ถือเป็นหนี้ที่รับรู้ ไม่ใช่แนวปฏิบัติที่ถูกต้อง

## 1. ปัญหาและเป้าหมาย

ผู้ซื้อที่กำลังตัดสินใจโอนเงินให้ร้านที่ไม่เคยซื้อมาก่อน ต้องการหลักฐานว่าร้านมีตัวตนและมีของจริง ตัวเลขสถิติบนหน้าร้านตอบได้ระดับหนึ่ง แต่ไม่เท่ากับการได้เห็นสินค้าเคลื่อนไหวจากคลิปที่ร้านถ่ายเอง

ร้านส่วนใหญ่ลงคลิปสั้นบน Facebook และ Instagram อยู่แล้ว เป้าหมายคือดึงคลิปเหล่านั้นมาแสดงบนหน้าร้าน โดยที่ผู้ซื้อมั่นใจได้ว่าคลิปเป็นของร้านนั้นจริง

## 2. ข้อตัดสินเชิงผลิตภัณฑ์

| รหัส | ข้อตัดสิน | เหตุผล |
|---|---|---|
| V1 | ร้าน**เลือกจากคลิปในบัญชีที่เชื่อมไว้** ไม่ใช่วาง URL เอง | วาง URL เปิดให้เอาคลิปคนอื่นมาอ้างเป็นของตัวเองได้ ซึ่งทำลายเหตุผลทั้งหมดของการเอาคลิปมาโชว์บนหน้าที่ใช้ตัดสินใจโอนเงิน |
| V2 | ฝังคลิปให้เล่นในหน้า ไม่ใช่ลิงก์ออกไป | เจ้าของผลิตภัณฑ์เลือกเอง หลังพิจารณาข้อแลกเปลี่ยนเรื่องน้ำหนักหน้าและการติดตามของแพลตฟอร์ม |
| V3 | โหลด iframe เมื่อผู้ชมกดเท่านั้น แสดงรูปปกก่อน | ฝังพร้อมกันหลายอันดึงสคริปต์ของแพลตฟอร์มหลายเมกะไบต์ตั้งแต่เปิดหน้า และแพลตฟอร์มเห็นทันทีว่าใครเปิดหน้าร้านทั้งที่ผู้ชมยังไม่ได้เลือกดู |
| V4 | คลิปเป็นแท็บ "ปักหมุด" ที่มาก่อนแท็บอื่นเสมอ | คลิปคือสิ่งที่ร้านตั้งใจให้เห็นก่อน |
| V5 | จำกัด 6 คลิป | กันหน้าร้านยาวจนเนื้อหาสำคัญตกจอ และกันโหลดเกินจำเป็น |
| V6 | แสดงยอดวิว/ไลก์เท่าที่แพลตฟอร์มให้ ไม่มีก็ซ่อน | กติกาเดียวกับตัวเลขอื่นในหน้าร้าน — ไม่แสดงศูนย์ ไม่แต่งตัวเลข |

## 3. ขอบเขตต่อแพลตฟอร์ม

| แพลตฟอร์ม | สถานะ | ยอดวิว | ยอดไลก์ | หมายเหตุ |
|---|---|---|---|---|
| Facebook Page | ใช้งานได้ | ได้ | ได้ | ใช้ token เดิมจากการเชื่อมช่องทางแชท ไม่ต้องขอสิทธิ์เพิ่ม |
| Instagram | ใช้งานได้ | ต้องเชื่อมใหม่ | ได้ | ยอดวิวต้องการสิทธิ์ `instagram_manage_insights` ที่เพิ่งเพิ่ม ร้านที่เชื่อมไว้ก่อนหน้าต้องกดเชื่อมใหม่ |
| TikTok | ยังไม่ทำ | — | — | รอ TikTok อนุมัติแอป โครงข้อมูลรองรับไว้แล้ว |
| YouTube | ยังไม่ทำ | — | — | ตัวแยกวิเคราะห์ลิงก์รองรับแล้ว แต่ยังไม่มีการเชื่อมบัญชี |

## 4. สิ่งที่ไม่อยู่ในขอบเขต

- อัปโหลดคลิปเข้าระบบเราเอง — พึ่งแพลตฟอร์มที่ร้านใช้อยู่แล้ว
- แก้ไข/ตัดต่อคลิป
- ยอดที่อัปเดตสด — เป็นค่า ณ เวลาที่ร้านกดบันทึก
- คลิปจากบัญชีส่วนตัวที่ไม่ได้เชื่อมกับร้าน

## 5. ความเสี่ยงที่รับไว้

| ความเสี่ยง | การจัดการ |
|---|---|
| ยอดที่แสดงล้าสมัย | เป็น snapshot โดยตั้งใจ — ยิง API ทุกครั้งที่มีคนเปิดหน้าร้านจะช้าและชนลิมิต ค่าอัปเดตเมื่อร้านกดบันทึกใหม่ |
| ร้านลบคลิปบนแพลตฟอร์มหลังปักหมุด | ตอนเปิดหน้าตั้งค่าจะตัดออกจากรายการที่เลือกไว้พร้อมแจ้งเหตุผล |
| แพลตฟอร์มเปลี่ยนรูปแบบข้อมูล | ทุกจุดที่ดึงข้อมูลทนต่อความล้มเหลวได้ กรณีแย่สุดคือไม่มีตัวเลข ไม่ใช่หน้าพัง |
| ฝัง iframe จากภายนอกบนหน้าที่ผู้ซื้อกำลังตัดสินใจ | จำกัดสิทธิ์ iframe แน่นที่สุดเท่าที่ยังเล่นได้ และ URL ฝังประกอบขึ้นเองจากรหัสที่ตรวจแล้ว |
