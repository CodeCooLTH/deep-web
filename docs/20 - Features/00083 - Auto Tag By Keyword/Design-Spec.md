### Section breakdown (prose)

**1. หัวหน้า (`PageBreadcrumb` + subtitle)**
- breadcrumb: หน้าแรก › ตั้งค่า › จัดการแท็ก
- subtitle บรรทัดเดียว (`text-default-700 text-sm mb-base`) ตามหน้าพี่น้อง `auto-notify/page.tsx`
- ไม่มี stat card:
  - ตัวเลขทั้งหมดอยู่ในแถวแล้ว
  - hero-metric template ถูกห้าม
  - หน้า auto-reply ใช้ `ProductStats` แต่ที่นั่นมี 3 สถานะที่ต้องนับ ส่วนที่นี่ไม่มีอะไรให้นับซ้ำ

**2. การ์ด "แท็กของร้าน" (พระเอกของหน้า)**
- `card-header` ซ้าย = ช่องค้นหา (โผล่เมื่อมีมากกว่า 10 แถว เพราะแท็กที่ยังไม่ตั้งค่าไม่มีเพดาน) ขวา = ปุ่ม `เพิ่มแท็ก` ปุ่มเดียวของหน้า ตาม seller-action-placement "List toolbar"
- ตัวนับ "{n} จาก 50 แท็ก" แสดงเฉพาะเมื่อ n ≥ 40 ถ้าแสดงตลอดจะเป็นข้อมูลคงที่ที่ไม่ช่วยตัดสินใจ
- ครบ 50: ปุ่มเพิ่ม `disabled` พร้อมบรรทัดอธิบายใต้ header (ห้ามพึ่ง tooltip บนมือถือ)
- เนื้อหา:
  - `<lg` = การ์ดรายการผ่าน `DataTable mobileCard`
  - `lg+` = ตารางผ่าน `DataTable`
  - ไม่มีตัวเลือกจำนวนต่อหน้า (fix 20) และ pagination โผล่เมื่อมากกว่า 20 แถว (`card-footer` + `TablePagination`)
  - เรียงตามชื่อ ใช้ locale ไทย แท็กที่ยังไม่ตั้งค่าอยู่ท้ายสุด header "แท็ก" กับ "ใช้ในห้อง" กดเรียงได้ (ใช้หาแท็กที่ไม่มีห้อง)

**3. แถวแท็ก (ตาราง/การ์ด ใช้ข้อมูลชุดเดียวกัน หน้าตาเดียวกัน)**
- ชื่อแท็ก = `badge` พื้น `bg-primary/15` ตัวหนังสือ `text-primary-ink`:
  - ต้องเป็นรูปทรงเดียวกับป้ายแท็กในแชท (`badge`) แอดมินจะจำได้ว่า "นี่คืออันเดียวกับที่เห็นในห้อง"
  - ชื่อยาว 30 ตัว: `truncate` + `min-w-0` + `max-w-full` (ดู convention flex-header-truncation)
- ป้าย "ยังไม่ได้ตั้งค่า" = outline เป็นกลาง (`border-default-300 bg-card text-default-700 border` ตามรอยป้าย "ไม่ใช้งาน" ของ auto-reply):
  - เจตนาไม่ใช้ warning เหลือง เพราะร้านเก่าอาจมีแท็กพิมพ์เองหลายสิบอัน จะกลายเป็นกำแพงสีเหลือง
  - ป้ายนี้ไม่ใช่ข้อผิดพลาด
- "ใช้ในห้อง": `{n} ห้อง` ใช้ `tabular-nums` เมื่อเป็น 0 เขียน "ไม่มีห้อง" (สีจาง) ตัวเลขหลักพันใส่ comma
- คำอัตโนมัติ:
  - ชิปเป็นกลาง `border border-default-300 bg-card text-default-800` ครอบด้วย “ ” โชว์ 3 คำ (แท็บเล็ต 4 คำ) แล้ว `+n`
  - ไม่มีคำ = ข้อความ "ติดด้วยมือเท่านั้น" (`text-default-700`)
  - ตั้งใจให้ต่างจากชิปคำตรวจจับ `bg-primary/10` ของ auto-reply (ดูหัวข้อ Impeccable compliance)
- เมื่อสร้างคำสั่งซื้อ: ข้อความ "ถอดเอง" (`text-primary-ink font-medium`) หรือ "ไม่ถอด" (`text-default-700`) แสดงอย่างเดียว ไม่ใช่สวิตช์ ตามบทเรียนของ `AutoReplyListing.tsx` (สวิตช์ในตารางเคยถูกถอดออก เปลี่ยนที่ตัวแก้ที่เดียว)
- ปุ่ม `แก้ไข` มีที่เดียวต่อแถว เป็นปุ่ม outline (`btn border-default-300 text-default-800 border`):
  - เดสก์ท็อป: ไอคอน `pencil` + ข้อความ
  - มือถือ: ไอคอนอย่างเดียวขนาด `size-11` พร้อม `aria-label="แก้ไขแท็ก {ชื่อ}"`
  - ลบไม่อยู่ในแถว อยู่ในตัวแก้ ดูข้อ 4
- แถวที่กำลังแก้: `bg-primary/5` และปุ่ม `aria-expanded="true"`

**4. ตัวแก้ (EditorCard) — ฟอร์ม RHF + Yup**
- เป็น `card` ใบเดียวใช้ทั้งเพิ่ม แก้ และตั้งค่าแท็กที่ยังไม่ตั้ง ไม่ใช้ modal เพราะเป็นฟอร์มที่มีหลายช่อง (HR8 ของ agent: blocking dialog ต้อง Swal เท่านั้น Swal ใส่ฟอร์มชิปไม่เหมาะ จึงใช้ inline)
- ตำแหน่ง:
  - `<xl` = เหนือรายการ
  - `xl+` = คอลัมน์ขวา แถวบน และอยู่ใน `xl:sticky` (ตรวจว่าไม่มี ancestor `overflow` มาตัด; ถ้าตัดให้ถอด sticky แล้วแจ้ง Controller)
  - คอมโพเนนต์เดียว วางด้วย grid (`xl:col-start-3`) ไม่ render สองชุด
- เปิดจากแถวบน `<xl`: เลื่อนหน้าไปที่ตัวแก้และโฟกัสช่องชื่อ (`scrollIntoView` เคารพ `prefers-reduced-motion`) ปิดแล้วคืนโฟกัสและตำแหน่งเลื่อนไปที่ปุ่ม `แก้ไข` ของแถวนั้น (รอยเดียวกับ `closeEditor` ใน `AutoNotifyClient`)
- ฟิลด์:
  1. **ชื่อแท็ก** (`form-input`, `maxLength=30`, label ผูก `htmlFor`) ตัวนับ "n/30" โผล่เมื่อ ≥ 24
  2. **ติดแท็กเมื่อร้านพิมพ์คำว่า (ไม่บังคับ)**:
     - ช่องพิมพ์ + ปุ่ม `เพิ่มคำ` ในแถวเดียว (`input-group`)
     - กด Enter เพิ่มคำ และต้องไม่ทำงานระหว่างพิมพ์ไทยที่ยังไม่ยืนยัน (`isComposing` / keyCode 229) เพราะ Enter ของคีย์บอร์ดไทยมือถือใช้ยืนยันคำ
     - ปุ่ม `เพิ่มคำ` ต้องเห็นตลอดเพื่อไม่พึ่ง Enter
     - ถ้าผู้ใช้พิมพ์ค้างแล้วกดบันทึก ระบบรวมคำนั้นให้ (ถ้าผ่านกติกา) ไม่ทิ้งเงียบ ๆ
     - ถ้าคำค้างใช้ไม่ได้ (เช่นสั้นเกิน) ให้บล็อกและขึ้น error ที่ช่อง
  3. **รายการคำ**: เป็นแถว (`ul` ที่มี `divide-y` + `border rounded`) ไม่ใช่ชิป:
     - แต่ละแถวสูง ≥ 44px ข้อความตัดบรรทัดได้ ปุ่ม `✕` ขนาด `size-11 lg:size-9`
     - เหตุผล: คำยาวได้ถึง 50 ตัว ชิปลบด้วยพื้นที่นิ้วเล็กหรือชนกันง่าย
     - คำสั้น (≤ 3 ตัว) ติดป้าย `badge bg-warning/15 text-warning-ink` "คำสั้น"
     - ถ้ามีคำสั้น: แสดงบรรทัดเตือน 1 บรรทัด `role="status"` ใต้รายการ ไม่ใช่ error
  4. **สวิตช์ "ถอดแท็กเมื่อสร้างคำสั่งซื้อ"** (`form-switch` + `<label htmlFor>` + ข้อความ "ถอดเอง/ไม่ถอด" ข้างสวิตช์ ตามแบบ `AutoNotifyRow.tsx`) ค่าเริ่มต้นปิด
- Footer: ซ้าย = `ลบแท็ก` (เฉพาะโหมดแก้ไข เป็นปุ่มข้อความ `text-danger-ink` ห่างจากปุ่มหลัก) ขวา = `ยกเลิก` → `บันทึก` (primary ขวาสุด):
  - ที่ <sm: ปุ่มหลักสองปุ่มแต่ละปุ่ม `flex-1` ในแถวเดียว ส่วน `ลบแท็ก` ขึ้นแถวล่างแยกด้วยเส้นประ (`border-t border-dashed`)
  - destructive ไม่ติด primary และไม่อยู่บนแถวรายการ ตามเจตนาของ seller-action-placement §3 (ข้อเบี่ยงเบนจากตัวอักษร ดูข้อ Impeccable compliance)
- `บันทึก` disabled เมื่อ: กำลังส่ง, หรือโหมดแก้ไขที่ยังไม่มีการเปลี่ยนแปลง (`isDirty=false`) โหมดเพิ่มไม่ disable ปล่อยให้ validation อธิบาย
- แท็กที่ยังไม่ตั้งค่า: เหนือฟิลด์ มีกล่องข้อมูล (`bg-default-100 rounded-lg p-3 text-sm`) อธิบายสถานะ ดูในหัวข้อ Content outline

### User flow

1. เปิดเมนู "จัดการแท็ก" เห็นรายการ กด `เพิ่มแท็ก` ตัวแก้เปิดขึ้น โฟกัสที่ช่องชื่อ
2. พิมพ์ชื่อ เพิ่มคำ (Enter หรือปุ่ม `เพิ่มคำ`) เปิดสวิตช์ถอด กด `บันทึก`:
   - ปุ่มเปลี่ยนเป็นสถานะกำลังบันทึก (spinner)
   - สำเร็จ: ตัวแก้ปิด แถวใหม่โผล่ในรายการ toast `เพิ่มแท็ก “รอคีย์ออเดอร์” แล้ว` โฟกัสคืนไปปุ่ม `เพิ่มแท็ก`
3. กด `แก้ไข` ที่แถว: ตัวแก้เปิดพร้อมค่าเดิม ถ้าตัวแก้อื่นค้างการแก้ไข ขึ้น Swal "ทิ้งการแก้ไขที่ยังไม่บันทึก?" ก่อน
4. เปลี่ยนชื่อที่มีห้องใช้อยู่ แล้วกดบันทึก: ขึ้น Swal เตือนจำนวนห้อง ยืนยันแล้วเปลี่ยนทุกห้อง ถ้าไม่มีห้องใช้ บันทึกเลยไม่ถาม
5. กด `ลบแท็ก` ในตัวแก้: ขึ้น Swal แดง บอกจำนวนห้อง ยืนยัน → ตัวแก้ปิด แถวหาย toast บอกผล
6. แท็กที่ยังไม่ตั้งค่า: กด `แก้ไข` เห็นกล่องอธิบาย ตั้งคำ/สวิตช์/เปลี่ยนชื่อ แล้วบันทึก ป้ายหายไปจากแถว
7. หน้าโดนลบ/แก้จากอีกเครื่อง: ดู error 409/404 ด้านล่าง

### Content outline (ภาษาไทย)

> คำเรียก: ในสเปกนี้ใช้ "แท็ก" ให้ตรงกับ UI เดิม (`t.inbox.tagsLabel = 'แท็ก'`, "เพิ่มแท็ก" ใน `TagInput`) ตามกฎ HR16 / PRD §4.1 ที่ให้ใช้คำเดียวทั้งระบบ แต่ PRD/คำสั่ง user เขียน "tag" ดูข้อ Open questions #1 (สลับได้ด้วยการแทนที่คำเดียวทั้งไฟล์ i18n)

ทุกข้อความต้องอยู่ใน `th.ts` และ `en.ts` ภายใต้ namespace ใหม่ `tagManager` (หน้านี้ใช้ `getT()` / `useT()` ตามหน้า auto-notify ของ 00047)

**หัว/เมนู**
- เมนู + title + breadcrumb: `จัดการแท็ก` (trail: `ตั้งค่า`)
- subtitle: `ตั้งชื่อแท็กของร้าน แล้วให้ระบบติดและถอดแท็กให้เองตามที่ร้านพิมพ์ในแชท`

**การ์ดรายการ**
- ชื่อการ์ด: `แท็กของร้าน`
- ตัวนับ (≥ 40): `{n} จาก 50 แท็ก`
- ปุ่ม: `เพิ่มแท็ก`
- ปุ่มเพิ่ม disabled (ครบ 50) + บรรทัดใต้ header: `ร้านมีแท็กครบ 50 แล้ว ลบแท็กที่ไม่ใช้ก่อน จึงเพิ่มแท็กใหม่ได้`
- ค้นหา: placeholder/aria `ค้นหาแท็ก`
- ค้นหาแล้วไม่พบ: `ไม่พบแท็กที่ตรงกับ “{q}”`
- หัวคอลัมน์: `แท็ก` · `ใช้ในห้อง` · `ติดอัตโนมัติเมื่อร้านพิมพ์` · `เมื่อสร้างคำสั่งซื้อ` · (sr-only) `การจัดการ`
- ห้อง: `{n} ห้อง` / `ไม่มีห้อง`
- คำ: `“{คำ}”` + `+{n}` / `ติดด้วยมือเท่านั้น`
- สถานะถอด: `ถอดเอง` / `ไม่ถอด`; การ์ดมือถือเขียน `เมื่อสร้างคำสั่งซื้อ: ถอดเอง`
- ป้าย: `ยังไม่ได้ตั้งค่า`
- ปุ่มแถว: `แก้ไข` (aria: `แก้ไขแท็ก {ชื่อ}`)

**ตัวแก้**
- title: `เพิ่มแท็กใหม่` / `แก้แท็ก` / `ตั้งค่าแท็ก` (แท็กที่ยังไม่ตั้งค่า) · บรรทัดรอง: `ใช้อยู่ใน {n} ห้อง`
- กล่องแท็กที่ยังไม่ตั้งค่า: `แท็กนี้มีอยู่ในแชทแล้ว แต่ร้านยังไม่ได้ตั้งค่า ตั้งคำหรือการถอดเองที่นี่ แล้วกดบันทึกเพื่อเก็บเข้ารายการ`
- ชื่อ: label `ชื่อแท็ก` · placeholder `เช่น รอคีย์ออเดอร์` · helper `1–30 ตัวอักษร ชื่อซ้ำกันในร้านไม่ได้` · ตัวนับ `{n}/30`
- คำ: label `ติดแท็กเมื่อร้านพิมพ์คำว่า` + `(ไม่บังคับ)` · placeholder `เช่น สรุปออเดอร์` · ปุ่ม `เพิ่มคำ` · helper `ร้านพิมพ์ข้อความที่มีคำใดคำหนึ่ง ห้องนั้นจะติดแท็กนี้ ไม่ใส่คำเลย = ติดด้วยมือเท่านั้น` · ตัวนับ `{n} จาก 10 คำ`
- รายการคำว่าง: `ยังไม่มีคำ แท็กนี้จะติดด้วยมือเท่านั้น`
- ลบคำ: aria `ลบคำ {คำ}`
- ป้ายคำสั้น: `คำสั้น` · บรรทัดเตือน (warning ไม่ใช่ error): `คำสั้นอาจทำให้ห้องติดแท็กบ่อยกว่าที่ต้องการ ลองใช้วลีที่ร้านพิมพ์เฉพาะตอนสรุปงาน เช่น “สรุปออเดอร์”`
- สวิตช์: label `ถอดแท็กเมื่อสร้างคำสั่งซื้อ` · สถานะ `ถอดเอง` / `ไม่ถอด` · helper `เมื่อมีคำสั่งซื้อใหม่ผูกกับห้องนั้น แท็กจะถูกถอดเอง ไม่ว่าใครเป็นคนติด คำสั่งซื้อที่จับคู่ด้วยเบอร์โทรอย่างเดียวไม่ถอด`
- ปุ่ม: `บันทึก` (โหมดเพิ่ม: `เพิ่มแท็ก`) · `ยกเลิก` · `ลบแท็ก`
- ระหว่างบันทึก: ปุ่มแสดง spinner และ `กำลังบันทึก…` (`aria-busy` บนฟอร์ม)

- ชื่อว่าง: `ใส่ชื่อแท็ก`
- ชื่อยาวเกิน: `ชื่อแท็กยาวได้ไม่เกิน 30 ตัวอักษร`
- ชื่อซ้ำในร้าน: `ร้านมีแท็ก “{ชื่อ}” อยู่แล้ว ใช้ชื่ออื่น หรือแก้แท็กเดิมแทน`
- คำสั้น (1 ตัว): `คำต้องยาวอย่างน้อย 2 ตัวอักษร`
- คำยาว: `คำยาวได้ไม่เกิน 50 ตัวอักษร`
- คำซ้ำ: `แท็กนี้มีคำนี้อยู่แล้ว`
- คำเกิน 10: `ใส่คำได้สูงสุด 10 คำต่อแท็ก`

**Swal**
- ลบ (มีห้อง): title `ลบแท็ก “{ชื่อ}”?` · text `จะถอดแท็กนี้ออกจาก {n} ห้อง และลบคำที่ตั้งไว้ด้วย ย้อนกลับไม่ได้ ตัวกรองกล่องแชทที่บันทึกไว้ด้วยแท็กนี้อาจต้องเลือกใหม่` · ยืนยัน `ลบแท็ก` · ยกเลิก `เก็บไว้`
- ลบ (ไม่มีห้อง): text `ไม่มีห้องที่ใช้แท็กนี้อยู่ ลบแล้วคำที่ตั้งไว้จะหายด้วย ย้อนกลับไม่ได้`
- เปลี่ยนชื่อ: title `เปลี่ยนชื่อแท็กใน {n} ห้อง?` · text `“{เดิม}” จะเปลี่ยนเป็น “{ใหม่}” ในทุกห้องของร้านทันที ตัวกรองกล่องแชทที่บันทึกไว้ด้วยชื่อเดิมอาจต้องเลือกใหม่` · ยืนยัน `เปลี่ยนชื่อ` · ยกเลิก `ยังไม่เปลี่ยน`
- เปลี่ยนชื่อแบบรวมกับชื่อที่มีแต่ในห้อง (Q-6): ต่อท้าย `ชื่อ “{ใหม่}” ใช้อยู่ในอีก {m} ห้องแล้ว ห้องที่มีทั้งสองชื่อจะเหลือแท็กเดียว`
- ทิ้งการแก้ไข: title `ทิ้งการแก้ไขที่ยังไม่บันทึก?` · text `ข้อมูลที่กรอกไว้จะหายไป` · ยืนยัน `ทิ้งการแก้ไข` · ยกเลิก `แก้ต่อ`

**Toast** (`pacesToast`)
- สำเร็จ: `เพิ่มแท็ก “{ชื่อ}” แล้ว` · `บันทึกแท็ก “{ชื่อ}” แล้ว` · `เปลี่ยนชื่อเป็น “{ใหม่}” แล้ว ({n} ห้อง)` · `ลบแท็ก “{ชื่อ}” แล้ว ถอดออกจาก {n} ห้อง` (n=0: `ลบแท็ก “{ชื่อ}” แล้ว`)
- ล้ม: `บันทึกไม่สำเร็จ ข้อมูลที่กรอกยังอยู่ ลองกดบันทึกอีกครั้ง` · `ลบแท็กไม่สำเร็จ ลองอีกครั้ง`
- ชนกับคนอื่น (409/404): warning `มีคนแก้แท็กนี้ไปก่อน โหลดรายการใหม่ให้แล้ว` (+ `router.refresh()`)
- 403: `บัญชีนี้แก้แท็กไม่ได้แล้ว เจ้าของร้านหรือผู้จัดการอาจเปลี่ยนสิทธิ์ไว้` (+ refresh)

**ข้อผิดพลาดระดับฟอร์ม** (กล่อง `bg-danger/15 text-danger-ink` เหนือ footer; ชื่อรหัสให้ตรง SRS เมื่อเขียน)
- แท็กครบ 50: `ร้านมีแท็กครบ 50 แล้ว ลบแท็กที่ไม่ใช้ก่อน แล้วเพิ่มแท็กใหม่ได้`
- ติดอัตโนมัติครบ 20: `ร้านตั้งให้ติดอัตโนมัติได้สูงสุด 20 แท็ก เอาคำออกจากแท็กอื่นก่อน หรือเอาคำของแท็กนี้ออกเพื่อบันทึกเป็นแท็กที่ติดด้วยมือ`

**ข้อควรรู้** (4 ข้อ)
1. `ตรวจเฉพาะข้อความที่คนของร้านพิมพ์ ข้อความของลูกค้า และข้อความที่ระบบส่งเอง (ตอบอัตโนมัติ ผู้ช่วยอัตโนมัติ ส่งอัตโนมัติถึงลูกค้า) ไม่ทำให้ติดแท็ก`
2. [ไอคอน Facebook + Instagram] `Facebook และ Instagram: ติดได้ทั้งตอนพิมพ์ในกล่องแชท Deep และตอนพิมพ์ในแอป Meta`
3. [ไอคอน LINE] `LINE: ติดได้เฉพาะที่พิมพ์ในกล่องแชท Deep ข้อความที่พิมพ์ในแอป LINE OA เอง ระบบมองไม่เห็น`
4. `ถ้าแอดมินถอดแท็กเอง แล้วร้านพิมพ์คำนั้นอีก แท็กจะติดกลับ ถือเป็นรอบใหม่ · มีผลกับข้อความหลังบันทึกเท่านั้น ไม่ย้อนหลัง · ห้องแชทในแอป Deep ยังไม่มีแท็ก`

**สถานะว่าง**
- หัว `ยังไม่มีแท็ก` · เนื้อหา `แท็กคือป้ายที่ติดบนห้องแชท ใช้กรองหาห้องที่ยังมีงานค้าง ตั้งให้ระบบติดและถอดเองได้`
- ตัวอย่าง (ป้าย `ตัวอย่าง`): `ร้านพิมพ์ “สรุปออเดอร์ค่ะ ยอดรวม 590 บาท”` → `ห้องนั้นติดแท็ก [รอคีย์ออเดอร์]` → `สร้างคำสั่งซื้อของห้องนั้น แท็กหายเอง`
- ปุ่ม `เพิ่มแท็ก` (primary) · `ใช้ตัวอย่างนี้` (outline)

**โหลดล้มเหลวระดับหน้า**
- `โหลดแท็กของร้านไม่สำเร็จ ลองโหลดใหม่อีกครั้ง` · ปุ่ม `โหลดใหม่`

### Edge states ที่ต้องออกแบบ

- **Empty (ไม่มีแท็กเลย)**: ดูแบบ D ในหัวข้อ Layout:
  - ซ่อนปุ่ม `เพิ่มแท็ก` ใน header เมื่อไม่มีแถว (ให้มี primary ปุ่มเดียวต่อหน้า) แล้วโชว์ปุ่มหลักในเนื้อหาว่าง
  - `ใช้ตัวอย่างนี้` เติมค่าลงตัวแก้ (ชื่อ `รอคีย์ออเดอร์` · คำ `สรุปออเดอร์` · สวิตช์เปิด) แต่ยังไม่บันทึก ตามมติ P-8 ที่ห้ามสร้างข้อมูลให้ร้านเงียบ ๆ
- **Empty ของการค้นหา**: ข้อความไม่พบ + ปุ่มล้างคำค้น
- **มีแต่แท็กที่ยังไม่ตั้งค่า**: ไม่ใช่ empty แสดงรายการปกติ
- **Loading**: `loading.tsx` โครงเดียวกับ auto-notify แต่ 4 แถว (`role="status" aria-busy`); ระหว่าง mutation ปุ่มเป็น spinner และตัวแก้ `aria-busy`; ห้ามทับทั้งหน้าด้วย overlay
- **Error โหลด**: การ์ดข้อความ + ปุ่ม `โหลดใหม่` (`router.refresh()`)
- **Error บันทึก**: ข้อมูลในฟอร์มคงอยู่เสมอ; error เฉพาะฟิลด์ใต้ฟิลด์; ระดับฟอร์มในกล่องเหนือ footer; ที่เหลือ toast
- **No-permission**: `NoPermissionCard capability="H3"`; API คืน 403; ไม่มีโหมดอ่านอย่างเดียว
- **ชื่อ/คำยาวผิดปกติ**: ชื่อ 30 ตัวตัดด้วย truncate; คำ 50 ตัวตัดบรรทัดในแถวคำ (`break-words`) และตัดด้วย `truncate` ในชิปของรายการ
- **ตัวเลข**: 0 ห้อง = "ไม่มีห้อง"; หลักพัน/หมื่นใส่ comma และ `tabular-nums`; 50/50 แท็ก = ปุ่มปิด + เหตุผล
- **ซ้ำ/พิมพ์ค้าง/IME**: คำซ้ำหลัง trim/ยุบช่องว่าง/ตัวอังกฤษพิมพ์เล็ก = error ใต้ช่อง ไม่เพิ่ม; Enter ระหว่างพิมพ์ไทยไม่เพิ่มคำ
- **ปิดแท็บขณะค้าง**: `beforeunload`
- **ผู้ใช้หลายคนแก้พร้อมกัน**: 409/404 → warning + refresh (ไม่ทับข้อมูลที่เพิ่งแก้)

### Impeccable compliance

- **Mode: Operate** (register product override ตาม `PRODUCT.md` เมื่อทำ seller console) เกณฑ์ตัดสินคือ scanability ความสม่ำเสมอกับหน้าพี่น้อง และ native expectation แบรนด์อยู่ในรายละเอียด (ศัพท์ ป้ายช่องทางจริง ตัวอย่างเฉพาะ Deep) ไม่ใช่การตกแต่ง
- **The One Voice Rule**: accent น้ำเงิน Paces (`bg-primary` token ไม่ใช่ม่วง) ใช้เฉพาะ
  1. ปุ่ม `เพิ่มแท็ก`/`บันทึก`
  2. ป้ายชื่อแท็ก (ตรงกับป้ายในแชท)
  3. ข้อความ `ถอดเอง` และสวิตช์ตอนเปิด
  4. แถวที่กำลังแก้ (`bg-primary/5`)
  - ชิปคำ ตัวเลขห้อง ข้อความ "ไม่ถอด" เป็นกลาง; รวมแล้วต่ำกว่า 10% ของจอ
- **พระเอกของหน้า**: คอลัมน์ "แท็ก" ในรายการ (ป้ายสีเดียวที่เด่นสุด ต่อด้วยปุ่มหลัก) และในตัวแก้คือคู่ "คำที่ทำให้ติด + สวิตช์ถอด" ซึ่งเป็นแก่นของฟีเจอร์ การ์ดข้อควรรู้ถอยเป็นเอกสารอ้างอิงน้ำหนักเบา
- **Verified-Means-Green**: ไม่ใช้เขียวกับสถานะใดในหน้า (ถอดเอง/ตั้งค่าแล้วไม่ใช่การ "ยืนยัน") เขียวมีเฉพาะ toast สำเร็จของ `pacesToast.success` ซึ่งตรงความหมาย "สำเร็จ"; "ยังไม่ได้ตั้งค่า" เป็นกลาง ไม่ใช่เหลือง/แดง
- **Sentence case / ไทย**: ไม่มี ALL CAPS; ปุ่มเป็นกริยา+กรรม (`เพิ่มแท็ก` `ลบแท็ก` `เปลี่ยนชื่อ` `ทิ้งการแก้ไข`) ไม่มี "ตกลง/OK"
- **Ink-tinted shadow**: ใช้เงาของ `.card` ตามธีม ไม่เพิ่มเงาเอง
- **น้ำเสียง**: ปุ่มบอกผล error บอกทางออก ไม่ใช้ "ไม่สามารถ…ได้/คุณไม่มีสิทธิ์" ตัวอย่าง: 403 เขียนเป็น "บัญชีนี้แก้แท็กไม่ได้แล้ว…" พูดถึงบุคคลที่สามเป็นกลาง ("เจ้าของร้านหรือผู้จัดการอาจเปลี่ยนสิทธิ์") ไม่มีคำไฮป์
- **จุดที่ theme/ตัวอย่างพี่น้องขัดกับ Impeccable หรือกับกันเอง และการตัดสิน** (ระบุให้ Controller เพ่งตอนรัน critique):
  1. **ชิปคำ**: auto-reply ใช้ `bg-primary/10 text-primary` สำหรับคำตรวจจับ แต่ที่นี่ใช้ชิปเป็นกลาง เพราะป้ายแท็กในแชทเป็น `bg-primary/15` อยู่แล้ว ถ้าคำเป็นสีเดียวกันจะแยก "สิ่งที่ติด" ออกจาก "สิ่งที่ทำให้ติด" ไม่ได้ และ accent จะเกินสัดส่วน → ยอมเสียความเหมือนกับ auto-reply
  2. **ป้ายแท็กในแชทใช้ `text-primary`** (ไม่ใช่ `-ink`) คอนทราสต์ต่ำกว่าที่ควร แต่หน้านี้ใช้ `text-primary-ink` ตามกฎ soft badge ผลคือเฉดต่างเล็กน้อยจากป้ายในห้อง (เฉดเดียวกัน ความเข้มต่าง) แนะนำให้ตามแก้ป้ายในแชทเป็นงานแยก ไม่ใช่ในฟีเจอร์นี้
  3. **ลบอยู่ในตัวแก้ ไม่ใช่ ⋯ ที่แถว** seller-action-placement §3 เขียนว่า destructive อยู่ใน ⋯ แต่เมนู ⋯ ที่มีรายการเดียวในตารางที่ `overflow` ตัด popover ได้ (convention scroll-container-clips-popovers) จึงเสี่ยงกว่าประโยชน์ ตัดสินวางไว้ในตัวแก้ ห่างจาก primary และต้องผ่าน Swal เจตนาของกฎ (กันกดพลาด) ยังอยู่
  4. **ลบใช้ `text-danger-ink`** ไม่ใช่ `text-danger` เพราะ `#f7577e` บนขาวไม่ผ่าน 4.5:1
  5. **ตัวแก้ inline แทน modal**: เหตุผลข้างต้น; แต่บน `<xl` ตัวแก้อยู่บนสุดแล้วเลื่อนหน้าไป ต้องดูตอน critique ว่าไม่หลงทิศ
  6. **ไม่มี stat card/eyebrow/gradient/การ์ดซ้อนการ์ด**: กล่องตัวอย่างในสถานะว่างเป็นกรอบเส้นประใต้การ์ดเดียว (precedent `NewKeywordForm.tsx`)
- **ค่าที่ Paces ไม่มี token**: ไม่มี ไม่ใช้ arbitrary Tailwind เลย ทุกอย่างใช้ `size-11`, `min-h-11 lg:min-h-0`, `text-primary-ink`, `bg-warning/15`, `gap-base` ที่มีจริง ถ้าจะใช้ `xl:sticky xl:top-20` ให้ตรวจว่าคำสั่ง `top-20` มี และไม่ชน header (ไม่ได้ใช้ค่าดิบ)

### Design decisions + rationale

1. **รายการ + ตัวแก้ inline บนหน้าเดียว ไม่แยกเป็นหน้า `/new` และ `/[id]`**: แท็กมีแค่ 3 ฟิลด์ เปิดทั้งหน้าเป็นภาระ และแท็กที่ยังไม่ตั้งค่าไม่มี id ให้ทำเป็น route นอกจากนี้ลดจำนวน route ที่ต้องประกาศ capability
2. **ตัวแก้ติดคอลัมน์ขวาบน `xl`**: ใช้พื้นที่ 30% ให้มีเนื้อหาจริง (ตัวแก้ + ข้อควรรู้) ไม่ใช่ที่ว่าง; ที่ 1440 รายการ 2/3 กว้างพอสำหรับ 5 คอลัมน์
3. **สถานะถอดเป็นข้อความอย่างเดียวในรายการ**: หน้าพี่น้อง auto-reply ผ่านบทเรียน "สวิตช์ในตารางทำให้เกิดการเปลี่ยนสถานะโดยไม่เห็นบริบท" มาแล้ว
4. **ไม่มี stat cards, pagination ตั้งแต่ต้น, ตัวเลือกจำนวนต่อหน้า**: pagination และค้นหาโผล่ตามจำนวนแถวจริง (แท็กที่ยังไม่ตั้งค่าไม่มีเพดาน)
5. **แถวคำแทนชิปในตัวแก้**: คำยาวถึง 50 ตัว และพื้นที่นิ้ว 44px ทำง่ายกว่าในแถว
6. **สถานะว่างสอนด้วยตัวอย่างของจริงของ Deep** ("สรุปออเดอร์" → "รอคีย์ออเดอร์") ติดป้าย "ตัวอย่าง" ตาม PRODUCT.md
7. **ตัวเลขที่ไม่ช่วยตัดสินใจถูกตัด** (เช่น ตัวนับ 50 แสดงเมื่อใกล้เพดานเท่านั้น)

### Anti-slop self-check

1. **เฉพาะ Deep ไหม**: ใช่ เพราะใช้ชื่อแท็กและคำจริงของโดเมน ("รอคีย์ออเดอร์", "สรุปออเดอร์"), ไอคอนช่องทางจริง (Facebook/Instagram/LINE) จาก `getChannelDisplay`, ข้อจำกัดของ LINE echo, และกฎ "ติดกลับเมื่อพิมพ์คำซ้ำ" ที่เป็นพฤติกรรมเฉพาะของระบบนี้ ถ้านำสเปกไปใช้กับสินค้าอื่นต้องเปลี่ยนเกือบทุกข้อความ
2. **เด่นที่สุด 1 อย่างต่อจอ**: ป้ายชื่อแท็กในรายการ (accent เดียวที่เห็นซ้ำ) คู่กับปุ่ม `เพิ่มแท็ก`; ในตัวแก้คือชุดคำ+สวิตช์; การ์ดข้อควรรู้ถอยลง ไม่ใช่ทุกการ์ดน้ำหนักเท่ากัน
3. **ตัดของซ้ำ/คงที่**: ตัด stat cards, ตัวเลือกจำนวนต่อหน้า, ปุ่มลบรายแถว, ปุ่ม X หัวตัวแก้ (ซ้ำกับ `ยกเลิก`), ตัวนับ 50 ที่แสดงตลอด, สวิตช์ในตาราง; เก็บข้อควรรู้ 4 ข้อที่แต่ละข้อมีข้อเท็จจริงไม่ซ้ำ
4. **ครบทุก state**: empty (ไม่มีแท็ก / ค้นหาไม่พบ) · loading (`loading.tsx` + spinner ปุ่ม) · error (หน้า, ฟิลด์, ฟอร์ม, toast) · no-permission · ชื่อ/คำยาว · 0 ห้อง · หลักพันห้อง · ครบ 50 · พิมพ์ไทยค้าง/ซ้ำ · แก้พร้อมกัน — ดูหัวข้อ Edge states
5. **copy บอกสิ่งที่ทำได้จริง**: ปุ่ม `เพิ่มคำ` `ลบแท็ก` `เปลี่ยนชื่อ` บอกผล ไม่ใช่ท่าทาง; error บอกทางออก ("ลบแท็กที่ไม่ใช้ก่อน", "เอาคำออกจากแท็กอื่นก่อน"); ห้ามแนะนำสิ่งที่ปุ่มไม่มี — กรณีครบ 50 ปุ่ม `เพิ่มแท็ก` ปิด และคำแนะนำ "ลบแท็กที่ไม่ใช้" มีทางทำได้จริง (ปุ่ม `แก้ไข` → `ลบแท็ก`)
6. **คำเดียวกัน = ของเดียวกัน**: "แท็ก" ทั้งหน้า (ตรงกับ `tagsLabel` เดิม), "ห้อง" = ห้องแชท, "คำ" = คำที่ทำให้ติด, "ถอดเอง" ใช้ทั้งรายการ ตัวแก้ ศัพท์เดียว (ข้อสังเกต: PRD ใช้ "tag" — เปิดเป็นคำถามให้ Controller)
7. **สีสื่อความถูก**: เขียวไม่มีเลยนอกจาก toast สำเร็จ; แดงเฉพาะลบ/error จริง; "ยังไม่ได้ตั้งค่า" และ "ไม่ถอด" เป็นกลาง; สถานะเดียวกันสีเดียวกันทั้งรายการและการ์ดมือถือ (ใช้ `StatusCell` แบบเดียวกับที่ auto-reply ใช้ซ้ำ ให้ข้อมูลเดียวกันหน้าตาเดียว)
