## ข้อมูลที่เพิ่ม

- `Trend.unconfirmed: number[]` (จาก `getSalesSeries.unconfirmedValues`) · `Trend.expense?: number[]` — เติมเฉพาะ `needExpense` · ค่าใช้จ่ายรายวัน = `getPnlReport` ทีละวัน (memo ร่วมกับช่วงรายงาน) — นิยามเดียวกับแถวค่าใช้จ่าย · `sumTrend` รวม expense เฉพาะเมื่อทุกร้าน OK มีค่า
- ไม่แตะ schema/migration

## ข้อจำกัดที่รู้

- Flex วาดเส้นเฉียงไม่ได้ → เส้นเป็นจุดวาง `position: absolute` ไล่ 4 ช่วงต่อวัน (ตำแหน่ง `offsetStart/offsetBottom` เป็น %) — ยังไม่เคยดูบน LINE มือถือจริง
- ค่าใช้จ่ายรายวัน = P&L 7 ครั้ง/ร้าน/รอบ (เฉพาะเทมเพลตที่มีกราฟ + บล็อกค่าใช้จ่าย) — ช้าเมื่อไหร่ทำ query รายวันก้อนเดียว
- พรีวิวในหน้าตั้งค่ามีร้านล้มในตัวอย่าง (≥3 ร้าน) → แถวรวมค่าใช้จ่าย/แท่งแดงไม่ขึ้นในพรีวิว (กฎ "มีร้านล้ม = รวมไม่ได้" เดิม)

## รอบ 3 — รูปสินค้าใน Top 3 (user: `[รูป] ชื่อสินค้า  จำนวน`)

- แถว Top 3: รูปสี่เหลี่ยม 40px มุมมน · ชื่อ · จำนวน — มีรูปอย่างน้อยหนึ่งแถว ⇒ ทุกแถวมีช่องรูป (ไม่มีรูป = กล่องเทา) · ไม่มีรูปเลย = แถวแบบเดิม (golden ไม่เปลี่ยน)
- รูป = `Product.images[0]` ของสินค้าในร้านนั้น (`findMany where { id in top3, shopId }`) · สินค้าพิมพ์เอง/URL ภายนอก = ไม่มีรูป
- LINE รับแค่ JPEG/PNG แต่รูปในระบบมี webp/gif → `GET /api/line-report/product-image?k=<คีย์>&s=<HMAC>` แปลงเป็น JPEG 160×160 (sharp) cache 1 ปี
  - 🛑 route อ่านไฟล์จาก storage ตรง ไม่ผ่านด่านสิทธิ์ของ `/api/files` → **ต้องมีลายเซ็น** (HMAC-SHA256 ด้วย `NEXTAUTH_SECRET`, ผูกกับคีย์) ออกให้เฉพาะคีย์รูปสินค้าที่ service ดึงจาก Product · URL คงที่ต่อคีย์ (retry ส่ง payload เดิม)
