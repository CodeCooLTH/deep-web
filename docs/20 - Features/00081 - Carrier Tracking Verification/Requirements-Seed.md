# 00081 — เช็คสถานะพัสดุส่งเองจาก API ขนส่ง (เมล็ดความต้องการ ยังไม่ใช่ PRD)

> แยกออกจาก 00080 ตามมติ user 2026-10-18 ("ตามแนะนำ") · 00080 ปุ่ม "ส่งสำเร็จ" = ทางสำรองที่ใช้ได้ทุกขนส่ง
> ต้องเขียน PRD + BRD ให้ user อนุมัติก่อนโค้ด (HR11) · ต้องทำ spike ด้านล่างให้จบก่อนเขียน PRD

## ความต้องการจาก user

1. "มีท่าอื่นไหมว่าของส่งถึงจริง ๆ เช่นระบบเช็คผ่าน API" (2026-10-18) — ส่งลิงก์ Flash Express Open API มาให้
2. รับข้อเสนอ: ทำ 00080 ก่อน แล้วแยกการเช็คผ่าน API เป็นฟีเจอร์ต่อยอดทีละขนส่ง

## แนวคิดที่เสนอ

- เลขพัสดุส่งเองที่เช็คได้ → ระบบเลื่อน "รอจัดส่ง → กำลังจัดส่ง" เมื่อขนส่งรับของ และ "กำลังจัดส่ง → สำเร็จ" เมื่อส่งถึง เหมือนที่ iShip ทำ
- ใช้ขั้นเดียวกับ 00080 (BR-MS-22) ไม่สร้างสถานะใหม่
- ใบที่ปิดจากข้อมูลขนส่ง ติดป้าย/ชนิดเหตุการณ์ต่างจากใบที่ร้านกดเอง → ลดความเสี่ยงร้านปั่น Trust Score (PRD 00080 §6.1)
- เลขที่เช็คไม่ได้ = ใช้ปุ่มของ 00080 ตามเดิม

## ข้อเท็จจริงที่รู้แล้ว (2026-10-18 — อ่านเอกสาร ยังไม่ได้ยิงจริง)

**Flash Express** (https://open-docs.flashexpress.com/#open-api-reference)
- `POST /open/v1/orders/{pno}/routes` · `routesBatch` (pnos คั่น comma) · `deliveredInfo` (ผู้เซ็นรับ · รูป · POD)
- webhook สถานะ/เส้นทาง ตั้งผ่าน `/open/v1/setting/web_hook_service` · ส่งซ้ำย้อนหลังไม่ได้ → ต้องมีการดึงเองเป็นรอบเสริม
- ต้องเซ็นทุกคำขอด้วย `mchId` + secret key (SHA256) · ขอคีย์ต้องติดต่อซัพพอร์ต Flash
- error 1019 "pno and mchId not match" → น่าจะดูได้เฉพาะพัสดุใต้ `mchId` ของร้านเอง · สถานะว่างจนกว่าขนส่งรับของ

**ไปรษณีย์ไทย**
- มี Track & Trace API แบบ token · เจอแต่ไลบรารีบุคคลที่สาม (PyPI `thailandpost-track`, npm `thailand-post`) ที่บอกว่าต้องขอสิทธิ์จากไปรษณีย์
- น่าจะดูได้ทุกเลข (เว็บสาธารณะค้นได้) — ยังไม่ยืนยัน

**ตัวรวมหลายขนส่ง** (TrackingMore · ClickPost ฯลฯ)
- API เดียวหลายขนส่งไทย + webhook · มีค่าใช้จ่ายต่อเลข · ข้อมูลผ่านบุคคลที่สาม

**iShip (มีอยู่แล้ว)**
- `getTraces(token, trackNo)` → `POST /api/traces` (`src/lib/iship/client.ts:384`) · พัสดุที่ยังไม่ถูกสแกนตอบ 500 body ว่าง = "ยังไม่มีข้อมูล"
- ⚠ ผลว่างแยกไม่ออกระหว่าง "เลขนี้ไม่ใช่ของ iShip" กับ "ยังไม่สแกน" → spike ต้องใช้เลขที่ขนส่งสแกนแล้วแน่ ๆ

## Spike ที่ต้องทำก่อนเขียน PRD

1. ยิง iShip `/api/traces` ด้วยเลขพัสดุส่งเองที่ขนส่งสแกนแล้ว (ไม่ได้เปิดผ่าน iShip) ด้วย token ร้านที่เชื่อม iShip — ได้เส้นทางไหม
2. ถามซัพพอร์ต Flash: ดูเลขที่ไม่ได้เปิดผ่าน Open API ได้ไหม (เช่น ส่ง walk-in ที่สาขา) · ร้านขอ `mchId` เองหรือ Deep ขอแบบ platform
3. ไปรษณีย์ไทย: ช่องทางขอ token ทางการ + เงื่อนไขใช้งานเชิงพาณิชย์
4. ตัวรวม: ราคาต่อเลขที่ปริมาณของเรา เทียบกับต่อเองทีละขนส่ง
