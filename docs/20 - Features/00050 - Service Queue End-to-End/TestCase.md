# Test Case: ร้านบริการครบวงจร

---

## 1. Overview

### 1.1 สิ่งที่เอกสารนี้เป็นและไม่เป็น

ตารางในหมวด §2 **สร้างจากรายชื่อเทสจริงที่รันผ่าน** ไม่ได้พิมพ์ขึ้นเอง — เอกสารเทสที่ลอกด้วยมือ
จะเพี้ยนจากโค้ดวันแรกที่มีคนเพิ่ม/ลบเคส แล้วกลายเป็นเอกสารที่อ่านแล้วเชื่อไม่ได้

### 1.2 มาตรฐานที่ใช้ตัดสินว่า "เทสนี้ใช้ได้"

🛑 **เขียวไม่พอ ต้องพิสูจน์ด้วย mutation** — คืนตรรกะที่ผิดกลับเข้าไปแล้วเทสต้องแดง
ถ้าไม่แดง แปลว่าเทสยืนยันแค่ว่า "โค้ดทำตามที่คนเขียนเทสคิด" ไม่ใช่ว่า "คนเขียนคิดถูก"

ระหว่างรอบนี้ mutation จับเทส/ด่านที่ตัวเองเพิ่งเขียนได้ **4 ครั้ง**:

| # | อาการ | บทเรียน |
|---|---|---|
| 1 | ด่าน "ทุก query ต้อง scope shopId" ใช้วิธี **นับหัว** แล้วบังเอิญ 6 ชน 6 พอดี | ด่านต้องผูก *คำสั่งกับ where ของคำสั่งนั้น* ไม่ใช่ยอดรวมทั้งไฟล์ |
| 2 | regex ดึงเนื้อฟังก์ชันด้วย `[\s\S]*?\n}` หยุดที่วงเล็บปิดของ **ชนิด args** | ด่านแดงค้างทั้งที่โค้ดถูก — คลาสเดียวกับ `^\s+` ที่กิน `\n` |
| 3 | ด่าน "ต้อง render ชีต" ใช้ `toContain('<StartWalkInSheet')` | ผ่านกับ `<StartWalkInSheetX` ด้วย — ต้องใช้ regex ที่มี `\b` |
| 4 | เทส "walk-in ยังกดเข้ารับบริการได้" **ยืนยันพฤติกรรมที่เป็นบั๊ก** | ปลายทาง 404 เมื่อใบนั้นไม่มีนัด — เทสเขียวมาตลอด |

### 1.3 ผลรัน ณ วันที่จัดทำ

`npx tsc --noEmit` → 0 · `npx vitest run src/` → **2984 passed / 253 files**
เคสของฟีเจอร์นี้ **92 เคส** ใน 7 ไฟล์ · mutation ที่พิสูจน์แล้วว่าแดงจริง **32 แบบ**
