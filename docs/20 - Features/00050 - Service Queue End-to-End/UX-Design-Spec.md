## สิ่งที่พบและแก้

### F-1 · จอหลังล็อกอินไม่ได้รับการแก้ที่จอ guest ได้ไปเมื่อ 6 วันก่อน (สำคัญที่สุด)

`/o/[token]` มี 2 จอที่แสดงออเดอร์ **ใบเดียวกัน** ต่างกันแค่ล็อกอินหรือยัง
2026-08-11 `GuestOrderView` ถูกแก้ 2 อย่าง แต่ `OrderDetailMobile` ไม่ได้ตามไป:

| | ก่อน | หลัง |
|---|---|---|
| หัวข้อ section (7 จุด) | `variant='overline' color='text.disabled'` = **2.30:1 ตก AA** | `<SectionTitle>` = `<h2>` จริง 15px/500 บนหมึกหลัก |
| screen reader | ทั้งหน้าไม่มี heading ให้กระโดดตาม | มี `<h2>` 7 ตัว |

🛑 จอที่ยังตกคอนทราสต์คือจอที่ผู้ซื้อใช้ **ยืนยันรับของและเขียนรีวิวจริง** และ PRODUCT.md
ผูกกลุ่มผู้ใช้ไว้กับผู้สูงวัย/digital-literacy ต่ำ

**แก้เชิงโครงสร้าง ไม่ใช่แก้รายจุด:** ยก `SectionTitle` ออกเป็น `SectionTitle.tsx` ไฟล์ร่วม
ทั้งสองจอ import ตัวเดียวกัน ⇒ แยกจากกันอีกไม่ได้ (HR16)

### F-2 · น้ำหนักตัวอักษรและขนาดหลุด ramp

| จุด | ก่อน | หลัง | กฎ |
|---|---|---|---|
| ชื่อร้าน | 800 | **700** | DESIGN.md §Strong step ยกเคสนี้เป็นตัวอย่างเอง |
| ยอดรวม | `1.0625rem` (17px) + 800 | **18px + 700** | 17px ไม่อยู่บน ramp · *"ยอดเงินที่มีคำกำกับเป็นข้อความ ใช้ Strong"* |
| หัวข้อชวนรีวิว | 800 | **700** | *"ห้ามใช้ 800 กับข้อความ อีกต่อไป"* |

ตัวอักษรแทนโลโก้ร้าน (2 จุด) **คง 800** — เป็น *ภาพ* ไม่ใช่ข้อความ คลาสเดียวกับ Metric
เดิมจอ guest เขียนเหตุผลไว้ จอหลังล็อกอินไม่มี จึงอ่านเหมือนหลุดกฎ — เติมคอมเมนต์ให้ตรงกันแล้ว

### F-3 · `fontFamily: 'monospace'` บนเลขพัสดุ

คอมเมนต์ในโค้ดอ้างว่าเป็น "Hard Rule 5 exception" — **แต่ carve-out ของ HR5 คือ code block เท่านั้น**
เลขพัสดุไม่ใช่ code block และ DESIGN.md §The No-Mono-On-Thai Rule สั่งทางแก้ไว้ตรงตัว:
*"ถ้าอยากได้ตัวเลขเรียงคอลัมน์ให้ใช้ `tabular-nums` ไม่ใช่เปลี่ยน family"*

→ `fontVariantNumeric: 'tabular-nums'` + `letterSpacing: .04em` (ได้การเรียงโดยไม่ฆ่า Anuphan)

### F-4 · คำว่า "สินค้า" บนจอที่ร้านบริการก็เห็น (3 จุด)

- หัวข้อชวนรีวิว `"สินค้าถึงมือคุณแล้ว"` → ผันเป็น `"รับบริการเรียบร้อยแล้ว"`
- ปุ่มแจ้งปัญหา `"ยังไม่ได้รับสินค้า?"` → `"มีปัญหากับรายการนี้?"` (ประโยคเดียวกับจอ guest)
- **หัวไดอะล็อกยืนยัน** `"ยืนยันว่าได้รับสินค้าแล้ว?"` ทั้งที่ปุ่มที่เพิ่งกดเขียน `"ยืนยันว่ารับบริการแล้ว"`
  ⇒ **คนละคำในการกดครั้งเดียว** — ผันตามประเภทร้านแล้ว

### F-5 · arbitrary value ที่ไม่มีคอมเมนต์กำกับ (3 จุด)

`pb-[max(1rem,env(safe-area-inset-bottom))]` — DESIGN.md อนุญาต carve-out นี้ (Paces ไม่มี token
ของ safe-area) **แต่บังคับให้เขียนคอมเมนต์กำกับ** · `AppointmentSummarySheet` มีอยู่แล้ว อีก 3 ไฟล์ขาด
→ เติมครบ

🛑 `theme-guard` **ไม่จับ** `pb-[...]` — ผ่าน hook ไม่ได้แปลว่าผ่าน DESIGN.md
