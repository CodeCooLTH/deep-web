# PRD: คุณภาพแชทและแพลตฟอร์มของโฆษณา

---

## Executive Summary

00091 ทำให้ร้านเห็นว่า **แอดไหนทำยอดขาย** และเฟส 2 (FR-010) ดึง **ค่าโฆษณา** จาก Meta มาคำนวณ ROAS แล้ว แต่ร้านยังตอบ 4 คำถามนี้ไม่ได้โดยไม่เปิด Ads Manager:

1. **Meta บอกว่าได้แชท 702 ห้อง ทำไม Deep เห็น 651?** — แชทหายไปไหน หรือนับคนละแบบ
2. **แชทจากแอดนี้ "คุยจริง" แค่ไหน** — ทักแล้วเงียบ / คุยต่อ / บล็อกเพจ
3. **แอดไปโผล่ที่ไหนแล้วได้แชทถูกที่สุด** — Facebook ฟีด, Reels, Instagram Stories …
4. **แอดเข้าถึงคนอายุ/เพศไหน**

ฟีเจอร์นี้เพิ่ม **รายงาน "คุณภาพโฆษณา"** หน้าใหม่ `/reports/ad-quality` ดึงตัวเลขจาก Meta Marketing API Insights ผ่านการเชื่อมบัญชีโฆษณาเดิม (00092) แบบเดียวกับ FR-010 (ดึงสด + แคช 15 นาที · ไม่มีตารางใหม่) แล้ววาง **ตัวเลขของ Meta ข้างตัวเลขของ Deep** โดยติดป้ายชัดว่าตัวไหนมาจากไหน และตัวไหนเป็นค่าประมาณ

ข้อเท็จจริงที่กำหนดขอบเขต: **Deep รู้ว่าแชทมาจากแอดไหน แต่ไม่รู้ว่าแอดถูกแสดงที่ตำแหน่งไหน และไม่รู้อายุ/เพศลูกค้า** — ยอดขายจึงแยกตามตำแหน่ง/อายุ/เพศไม่ได้ และหน้าจอจะไม่แสร้งว่าแยกได้

| เป้าหมาย | รายละเอียด |
|----------|-----------|

## 4. Business Requirements (ภาพรวม — FR เต็มดู [[BRD]])

### 4.1 ที่วาง: รายงานแยก `/reports/ad-quality` (มติ user 2026-11-14)

หน้า `/reports/ads` มี 9 การ์ดแล้ว (00091 FR-009/010) และทุกการ์ดใหม่ใช้ข้อมูลจาก Meta ทั้งหมด (ช้ากว่า · ขึ้นกับการเชื่อม · มีค่าประมาณ) — user เลือกทำเป็น **รายงานแยก** เมนู "คุณภาพโฆษณา" ในกลุ่ม ANALYTICS ต่อจาก "ยอดขายตามโฆษณา"

- ใช้ตัวเลือกช่วงวันที่และเพจแบบเดียวกับรายงานยอดขายตามโฆษณา · ลิงก์ข้ามสองรายงานพกช่วง/เพจไปด้วย
- มีตัวเลือก "แอด" เพิ่ม (ทุกแอด / แอดเดียว) สำหรับการ์ดตำแหน่งและอายุ/เพศ
- UI tone ตามหน้า Paces `dashboard/analytics` (ภาพที่ user ส่ง) — แทนม่วงด้วยสีอื่น (HR7)

### 4.2 เนื้อหารายงานคุณภาพโฆษณา

| การ์ด | ตอบคำถาม | แหล่งข้อมูล |
|---|---|---|
| แถบตัวเลขรวม | ค่าโฆษณา · การแสดงผล · เข้าถึง · ความถี่ · CTR · CPC · แชท Meta vs Deep | Meta (+ Deep สำหรับแชท) |
| แชทที่ Meta นับ vs แชทที่ Deep เห็น | US-1, US-2 | Meta `messaging_conversation_started_7d` · Deep `ConversationAdReferral` |
| คุณภาพแชทรายแอด (ตาราง) | US-3, US-6 | Meta actions + Deep คำสั่งซื้อ |
| แพลตฟอร์มและตำแหน่ง | US-4 | Meta breakdowns `publisher_platform, platform_position` |
| อายุและเพศ | US-5 | Meta breakdowns `age, gender` |

### 4.3 ยอดขายแยกตามตำแหน่ง/อายุ/เพศ — ไม่แสดง

webhook referral ของ Messenger บอกแค่ "แอดไหน" ไม่บอกตำแหน่ง และ Deep ไม่มีอายุ/เพศของลูกค้า การ "เกลี่ยยอดขายตามสัดส่วนแชท" จะต้องสมมติว่าทุกตำแหน่งปิดการขายได้เท่ากัน — ซึ่งคือสิ่งที่ร้านอยากรู้พอดี ตัวเลขเกลี่ยจะดูเหมือนคำตอบทั้งที่เป็นแค่สมมติฐาน (ขัด `partial-data-must-be-labeled-or-filled`) **จึงไม่แสดงยอดขาย/ROAS ต่อตำแหน่งเลย** แสดงแค่ตัวชี้วัดฝั่ง Meta + ต้นทุนต่อแชท และเขียนบอกบนการ์ดว่าทำไม

## 5. Business Rules & Constraints

| กฎ | คำอธิบาย |
|----|----------|
| **ตัวเลข Meta กับ Deep ไม่ปนกัน** | ทุกคอลัมน์ระบุแหล่ง (ป้าย "Meta" / "Deep") · ไม่เอาตัวเลข Meta ไปหาร/คูณกับตัวเลข Deep ยกเว้นสูตรที่ BRD กำหนด (ส่วนต่างแชท · ต้นทุน) |
| **ยอดขายมาจาก Deep เท่านั้น** | สืบจาก 00091 FR-010 — ห้ามใช้ purchase/conversion value ของ Meta |
| **ค่าประมาณต้องมีป้าย** | เข้าถึง · ความถี่ · ทุกตัวเลขที่แยกตามตำแหน่ง/อายุ/เพศ = "ประมาณการ" ตามที่ Meta ประกาศ |
| **ไม่มีข้อมูล ≠ 0** | Meta ไม่ส่งข้อมูลส่วนไหน แสดงสถานะ "ไม่มีข้อมูลจาก Meta" ไม่ใช่ 0 |
| **เจ้าของร้านเท่านั้น** | สิทธิ์ `F1` เดียวกับรายงานยอดขายตามโฆษณา |
| **ไม่มีตารางใหม่** | ดึงสด + แคช 15 นาที แบบเดียวกับ FR-010 |
| **ดึงเมื่อเปิดรายงานนี้เท่านั้น** | รายงานยอดขายตามโฆษณาไม่เรียก Meta เพิ่มจากที่ FR-010 เรียกอยู่ |

| ข้อจำกัด | รายละเอียด |
|---------|-----------|
| **สิทธิ์ `ads_management` ระดับ Standard** | การเชื่อม 00092 ใช้ได้เฉพาะบัญชีที่มี role บนแอป Deep → รายงานนี้ใช้ได้จริงเฉพาะร้านนำร่องจนกว่าจะผ่าน App Review (Advanced) |
| **ข้อมูลแยกย่อยของ Meta เป็นค่าประมาณ** | "Insights breakdown values are estimated" (เอกสาร Meta) · ผลรวมแต่ละกลุ่มอาจไม่เท่ายอดรวม |
| **Meta จำกัด breakdown บางตัว** | ประกาศ 2025-10 / มีผล 2026-01-12: บาง breakdown จำกัดประวัติ หรือต้องใช้งานแบบ async · บางบัญชีอาจไม่ได้ข้อมูลบางส่วน (ประกาศ 2026-08-06 สำหรับ `frequency_value`) |
| **attribution ต่างกัน** | Meta นับแชทตามการตั้งค่า attribution ของบัญชี (คลิก/ดูภายในหน้าต่างเวลา) · Deep นับเฉพาะห้องที่ webhook referral บอกว่ามาจากแอด ณ ตอนคลิก |
| **Rate limit ของ Insights** | Standard access มีโควตาเรียก Insights ต่ำกว่า Advanced — ต้องแคชและดึงเฉพาะเมื่อเปิดรายงาน |
| **บัญชีโฆษณาเดียวต่อร้าน** | สืบจาก 00092 |

## 6. Out of Scope

| หัวข้อ | เหตุผล |
|--------|--------|
| ยอดขาย/ROAS แยกตามตำแหน่ง อายุ เพศ (รวมแบบประมาณ) | Deep ไม่มีข้อมูลรองรับ — ดู 4.3 |
| ภูมิภาค (`region`) | user ให้เป็นทางเลือก · ตัด v1 เพื่อลดจำนวนคำขอ (วิดีโอ p25–p100 ไม่รองรับ breakdown นี้ด้วย) — เพิ่มได้ภายหลังด้วยรูปแบบเดียวกับอายุ/เพศ |
| งาน async report (`POST /insights` → `report_run_id`) | v1 ใช้คำขอปกติ · breakdown ที่ Meta บังคับ async แสดงสถานะ "ไม่มีข้อมูล" · ทำเมื่อเจอจริงบน prod |
| กราฟรายวันของตัวชี้วัดคุณภาพ | v1 เป็นยอดรวมทั้งช่วง (ไม่ใช้ `time_increment=1`) ลดขนาดคำตอบ |
| นับความลึกของแชทจากข้อความใน Deep เอง | เป็นทางเลือกที่แม่นกว่าสำหรับแชทที่ถึง Deep — คำถามเปิด Q3 |
| แก้แอด/งบ/กลุ่มเป้าหมายจาก Deep | อ่านอย่างเดียว |
| แชท Native ในแอปผู้ขาย | ไม่แตะแชท (HR18 ไม่เกี่ยว) — แอปเปิดหน้ารายงานผ่าน WebView ตามเดิม |
| เก็บประวัติ Insights ลงฐาน | ไม่มีตารางใหม่ (มติเดียวกับ FR-010) |

## 7. Risks & Mitigation

| ความเสี่ยง | แนวทางแก้ไข |
|-----------|-------------|
| ร้านเห็นส่วนต่างแชทแล้วคิดว่า Deep "ทำแชทหาย" | การ์ดอธิบายสาเหตุ 4 แบบ (BRD BR-AIQ-04) · ส่วนต่างติดลบ (Deep มากกว่า) อธิบายด้วย · ไม่ใช้สีแดง/danger |
| ชื่อ action ของ Meta เปลี่ยน/ไม่ส่งมา → ตัวเลขหายเงียบเป็น 0 | ไม่มี action ในคำตอบ = "—" ไม่ใช่ 0 (BR-AIQ-07) · เก็บตัวอย่าง payload จริงของร้านนำร่องก่อนเขียน parser (`external-payload-schema`) |
| Rate limit (โค้ด 17/80004) ทำรายงานพัง | แคช 15 นาทีต่อชุดคำขอ · ดึงเฉพาะเมื่อเปิดรายงาน · การ์ดที่ล้มแสดงสถานะของตัวเอง การ์ดอื่นยังแสดง |
| ค่าประมาณถูกอ่านเป็นตัวเลขจริง | ป้าย "ประมาณการ" ที่หัวการ์ด + หมายเหตุใต้การ์ด · ไม่บังคับผลรวมย่อยให้เท่ายอดรวม |
| เปิดใช้ทุกร้านไม่ได้ (Standard access) | ระบุในหน้าเชื่อมบัญชีและแบนเนอร์ว่าเป็นช่วงทดลอง · ยื่น App Review `ads_management`/`ads_read` Advanced แยก |
| Meta เปลี่ยนนโยบาย breakdown (เช่น ต้อง opt-in ใน Ads Manager) | การ์ดมีสถานะ "Meta ไม่ส่งข้อมูลส่วนนี้" พร้อมคำแนะนำ · ไม่ทำให้การ์ดอื่นล้ม |
| หน้าช้าเพราะเรียก Meta 4 คำขอ | ยิงขนานกัน · timeout รวม 8 วินาที · การ์ดโหลดแยก (streaming) |

## 8. Glossary

| คำ | ความหมาย |

| **แชทจากแอด (Deep)** | จำนวนห้องแชทที่ Deep ได้รับ referral source = ADS ของแอดนั้นในช่วงวันที่ (นิยามเดียวกับ 00091 FR-008) |
