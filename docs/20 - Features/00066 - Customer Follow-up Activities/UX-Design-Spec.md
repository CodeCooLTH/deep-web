## 0. แนวคิดร่วม (ทุกพื้นผิวใช้ชุดเดียวกัน)

### 0.1 พระเอกของแต่ละพื้นผิว

| พื้นผิว | สิ่งที่ต้องเด่นที่สุด | ที่เหลือถอย |
|---|---|---|
| a แผงในห้อง | รายการ **เลยกำหนด** (แผงกางเองเมื่อมี) | รายการปกติ / ที่ทำแล้ว |
| b bubble | ว่า "มีงานเลยกำหนดไหม" (ไอคอน+ข้อความเปลี่ยน ไม่ใช่แค่สี) | ตอนไม่มีงานเลยกำหนดเป็นปุ่มเงียบ (ขาวขอบเทา) |
| c หน้ารวม | คอลัมน์ **เลยกำหนด** + **วันนี้** (แท็บตั้งต้นบนมือถือ = คอลัมน์แรกที่ไม่ว่าง) | ภายหลัง / ทำแล้ว |

### 0.2 แผนที่สถานะ → สีเดียวทุกที่ (ห้ามหลุด)

ใช้คู่ token ที่มีอยู่แล้ว `bg-{x}/15 text-{x}-ink`. ค่า `-ink` มี override โหมดมืดใน `_root.css:207-211` ⇒ AA ทั้งสว่าง/มืด.

| สถานะ | ป้าย | สี | ไอคอน (ห้ามพึ่งสีอย่างเดียว) |
|---|---|---|---|
| เลยกำหนด | "เลยกำหนด" | `bg-danger/15 text-danger-ink` | `clock-exclamation` |
| ครบวันนี้ (ยังไม่เลย) | "ครบวันนี้" | `bg-warning/15 text-warning-ink` | `clock` |
| ยังไม่ถึง (ปกติ) | ไม่มีป้าย (เวลาเป็นข้อความ) | — | — |
| เลื่อนมา ≥2 ครั้ง | "เลื่อนมา N ครั้ง" | `bg-warning/15 text-warning-ink` | `refresh` |
| ทำแล้ว | ผลลัพธ์เป็นข้อความ | `bg-default-100 text-default-800` | `check` |

- **ไม่ใช้เขียวเลยทั้งฟีเจอร์.** "ทำแล้ว" คือพนักงานกดเอง ไม่ใช่ verified. `InboxList` ใช้ `circle-check` เขียวแทน "เธรดปิดงานแล้ว" อยู่ ถ้าฟีเจอร์นี้ใช้เขียวด้วย ผู้ขายจะอ่านว่า "ห้องปิดแล้ว" กับ "รายการติดตามเสร็จ" เป็นของเดียวกัน.
- **แดงใช้กับเลยกำหนดอย่างเดียว.** เป็นความล้มเหลวจริง (พลาดกำหนด). "งานค้าง" ปกติเป็นเทา.
- ผลลัพธ์ทั้ง 4 ค่า **เป็นกลางหมด** ("ไม่สนใจแล้ว" ไม่แดง, "ติดต่อได้·สนใจต่อ" ไม่เขียว) — เป็นข้อมูลอ้างอิง ไม่ใช่ตัดสินร้าน (BRD A7).

### 0.3 การ์ดกลางชุดเดียว `FollowUpCard` (variant: `panel` · `board` · `profile` · `bubble`)

ตามข้อกำหนด "ปุ่มชุดเดียวทุกพื้นผิว". `bubble` ตัดเหลือ ✓ อย่างเดียว (BRD FR-07).

```
 ┌───────────────────────────────────────────────────────────┐
 │ (ic) หัวข้อรายการ (semibold text-sm, line-clamp-2)     [⋮]│
 │ พรุ่งนี้ 10:00 · [เลยกำหนด] [เลื่อนมา 2 ครั้ง]              │  ← text-xs; ป้ายตาม §0.2
 │ (รูป20) สมชาย ใจดี                                        │  ← ผู้รับผิดชอบ แถวของตัวเอง
 │ โน้ต 2 บรรทัด… เพิ่มเติม                                  │  ← เฉพาะเมื่อมีโน้ต
 │ [✓ ทำแล้ว]  [⏱ เลื่อน]                                    │  ← แถวปุ่ม
 └───────────────────────────────────────────────────────────┘
   done:  ผล "ไม่รับสาย" · ปิดโดย คุณเอ 14:20      [เปิดกลับ]  [⋮]
```

- **ลำดับปุ่ม:** `ทำแล้ว` = ปุ่มหลักเดียวของการ์ด. ตัวนี้ `bg-primary text-white` **เฉพาะการ์ดเลยกำหนด**; การ์ดอื่น `bg-primary/15 text-primary-ink` (ไม่ให้ทุกการ์ดกวาดสีน้ำเงิน). `เลื่อน` = outline `border-default-300`. `แก้ไข` / `ลบ` อยู่ใน `⋮` (ลบ = `pacesConfirm.danger` ตาม `seller-action-placement.md`).
- **ไม่ใช้ dropdown / popover สำหรับ ทำแล้ว-เลื่อน — ใช้ "เปิดแถวต่อท้ายในการ์ด" (inline reveal):** (ก) แผงอยู่ในกล่อง `overflow-y-auto` popover `absolute` จะโดนตัด (`scroll-container-clips-popovers.md`) (ข) ผลลัพธ์ 4 ค่ากับปุ่มลัด 3 ค่า เป็นชิปกดเดียวเห็นครบ ไม่ต้องเปิดเมนูอีกชั้น.

```
 กด [ทำแล้ว] → การ์ดขยายแถวล่าง:
 │ ผลเป็นอย่างไร (ไม่บังคับ)                                  │
 │ [ติดต่อได้ · สนใจต่อ] [ไม่รับสาย] [ขอให้ติดต่อใหม่]        │
 │ [ไม่สนใจแล้ว]  [ข้าม]                          [ยกเลิก]    │
 กด [เลื่อน] → 
 │ เลื่อนไป                                                   │
 │ [พรุ่งนี้ 09:00] [อีก 3 วัน · พฤ. 2 ต.ค.] [สัปดาห์หน้า · ...]│
 │ [เลือกเอง ▾] → วันที่ / เวลา / ☐ทั้งวัน / [เลื่อน]          │
```
  ชิป = `<button>` `badge`-style, พื้นที่กด `min-h-11 lg:min-h-0` (ตามแบบ `EditButton` / ชิปสถานะขายใน `CustomerCrmSection`). ปุ่มลัดใช้ `quickSnooze(now)` จาก `src/lib` (เวลาไทยตายตัว — BR-ACT-12) ทั้ง client (แสดงวันที่ในชิป) และ server (ค่าจริง).
  ปิดแถวด้วย Esc / กดปุ่มเดิมซ้ำ / `ยกเลิก`, โฟกัสกลับปุ่มที่เปิด. เปิดพร้อมกันได้ทีละแถวต่อรายการ.
- **การ์ดกว้างแคบไม่เท่ากัน** (แผงขวา 384px บนจอ 1440 ≠ การ์ดกระดาน 288px ≠ การ์ดโปรไฟล์ 70%) → **ห้ามใช้ breakpoint ของ viewport ใน `FollowUpCard`** ใช้ container query (`@container` + `@lg:`) ตามแบบ `PriceCompareSheet`. ไม่งั้น `sm:` ยิงในแผง 384px บนจอกว้างผิด.
- **แถว/การ์ดในแผงและโปรไฟล์ = แถวแบ่งด้วย `border-b border-default-200`** ไม่ใช่ `.card` ซ้อนใน `.card` (ห้ามการ์ดซ้อนการ์ด). เฉพาะกระดาน (คอลัมน์ไม่ใช่การ์ด) ที่ใช้ `.card` ตาม `TaskItem`.
- **โน้ต:** `line-clamp-2` + ปุ่มข้อความ "เพิ่มเติม" แสดงเมื่อ `note.length > 80` (นับตัวอักษร ไม่วัด DOM — กันวงจร `measurement-must-not-decide-what-it-measures`). หัวข้อ 200 ตัว: `line-clamp-2` + `title=` เต็ม.
- ผู้รับผิดชอบถูกถอด/บัญชีลบ: `user-off` + "ทีมงานที่ถูกถอดออกแล้ว". ผู้รับผิดชอบ = ฉัน แสดงชื่อตามปกติ (ไม่ต้องพิเศษ).
- ตัวเลขนับ (`n`) ทุกที่ผ่าน `formatCount(n)` → ≥100 = "99+" (LIST_MAX = 200).
- ข้อมูลวัน-เวลาทั้งหมดผ่าน `formatDate*` / `formatTimeHM` ห้าม `toLocaleString`. ป้ายเวลา: วันนี้/พรุ่งนี้/เมื่อวาน + เวลา; นอกนั้น `formatDateTH`. งานทั้งวัน **ไม่แสดงเวลาที่ใดเลย** (BR-ACT-03).

### Section breakdown
- **แถวหัว:** ปุ่มสลับ (`aria-expanded`, `aria-controls`) ซ้าย + ปุ่มเพิ่มขวา. n = รายการ *เปิด* ในขอบเขตลูกค้าเดียวกัน (`panelModel().openCount`); ป้ายเลยกำหนดใช้ `lateCount` — **symbol เดียวกับป้ายแถวห้อง/กระดาน** (AC-ACT-22).
- **กางเอง** เมื่อ `lateCount>0` ตอนโหลดครั้งแรกของห้องนั้น (`panelModel().expanded`); หลังจากนั้นผู้ใช้คุมเอง (ไม่พับกลับเมื่อ late→0 — กันจอกระโดดใต้นิ้ว). เปลี่ยนห้อง = คำนวณใหม่.
- **ควบคุมด้วย React state ไม่ใช้ Preline `hs-accordion`** (parent re-render บ่อย — เหตุผลเดียวกับที่ `CustomerPanelBody` ใช้ tab ด้วย state).
- รายการจากห้องอื่นของลูกค้าเดียวกัน: ป้ายเล็ก "จากห้อง {ชื่อห้อง}" (text-xs, เทา) และการ์ดนั้นเปิดห้องนั้นได้ (ลิงก์ชื่อ).
- ตัวเลือกผู้รับผิดชอบ: ซ่อนทั้งช่องในร้าน PERSONAL (AC-ACT-07).

### ฟอร์มสร้าง/แก้ — sheet (มือถือ) / modal กลาง (≥lg)
Base โครง: `CustomerPanelSheet.tsx` (`fixed inset-0 z-80`, `role="dialog" aria-modal`, `useLockBodyScroll`, ESC ปิด). **ไม่ใช้ inline edit ในแผง** เพราะแถวปักหมุดจะแย่งความสูงจากแท็บ.

โน้ต (ไม่บังคับ)                  0/1000
[                                    ]

- **ค่าตั้งต้น = พรุ่งนี้ 09:00 (เวลาไทย, คำนวณจาก `quickSnooze`)** ⇒ ทุกช่องบังคับมีค่าอยู่แล้ว จดได้ = พิมพ์หัวข้อ + กด "บันทึก" (PRD: "จดได้ใน 3 ขั้น"). ผู้ขายแก้ได้.
- ติ๊ก "ทั้งวัน" → ช่องเวลา `disabled` + ค่าเวลาไม่ถูกส่ง.
- ส่ง `{date, time|null, allDay}` เวลาไทย ไม่ส่ง timestamp (TD-FU-6).
- **แก้รายการที่ปิดแล้ว:** ช่อง ชนิด/วันที่/เวลา/ผู้รับผิดชอบ `disabled` + ข้อความใต้ฟอร์ม "รายการที่ปิดแล้วแก้ได้เฉพาะหัวข้อและโน้ต — เปิดกลับก่อนถ้าต้องการเปลี่ยนวัน" (บอกทางออกที่มีปุ่มจริง).
- **Error inline ใต้ช่อง** (`is-invalid` + `aria-describedby`) ไม่ใช่ toast อย่างเดียว; error ที่ set ต้องมีที่ render จริง.
- ชนิด 3 ค่า `form-select`; ผู้รับผิดชอบ `form-select` (คือ field ที่ผูก react-hook-form/Yup → **ไม่ใช้ hs-dropdown**).

### Edge states (a)
| สถานะ | พฤติกรรม |
|---|---|

### ตัวกรอง — เพิ่มหัวข้อใน `InboxFilterPanel`
วางต่อจากหัวข้อ "แท็ก" ก่อน "พัสดุ" (`:307-326`). ใช้ `Section` + `Chip` เดิม ไม่สร้างตัวใหม่.

```

│ ติดตามลูกค้า                                     │
│ [เกินกำหนด (4)] [กำลังจะมาถึง (7)] [เสร็จสิ้น (12)]│  ← ชิปกดสลับ ติ๊กหลายอันได้ (OR)
│ พัสดุ …                                          │
```
- **การนับตัวกรอง:** `countActiveFilters()` เพิ่ม `if (f.followUp.length > 0) n++` (นับเป็น 1 ไม่ว่าเลือกกี่ค่า ตามแบบ `tags`, `:40-47`). ปุ่มตัวกรองและวงกลมจำนวนไม่ต้องเปลี่ยนรูปแบบ.
- `ChatFilterState` เพิ่ม `followUp: ('late'|'upcoming'|'done')[]`, `DEFAULT_CHAT_FILTER.followUp = []` (แก้ที่ `chat-list-query.ts` ให้ tsc บังคับครบ). ข้ามหมวด = AND.
- **ซ่อนหัวข้อทั้งก้อนเมื่อทั้ง 3 ค่านับ = 0 และไม่มีค่าที่เลือกค้าง** (ร้านที่ไม่เคยใช้ฟีเจอร์ไม่ต้องเห็นตัวกรองที่ว่างสามอัน). ผู้ขายค้นพบฟีเจอร์ผ่านแผง/bubble/เมนูซ้ายอยู่แล้ว.
- ต้องมีตัวเลขต่อค่า — ต้องมีที่มาของตัวเลข (Q-6).
- คำอธิบายใต้ชิปบรรทัดเดียว (`hint` ของ Section): "แสดงห้องที่มีรายการติดตาม" — ไม่ใช่นิยามยาว.

### ป้ายบนแถว `InboxList`
วางเป็นชิปแรกในบรรทัดป้าย (`mt-1 flex flex-wrap items-center gap-1`, `InboxList.tsx:1869`) ก่อน `behaviorBadges`.

```
 สมชาย ใจดี                           14:05
 คุณ: ได้ค่ะ จะโทรกลับพรุ่งนี้...
 [⏰ เลยกำหนด 2] [vip]          ← แดงอ่อน + ไอคอน
 สมชาย ใจดี
 [☰ งานค้าง 3]                   ← เทา + ไอคอน list-check
```
- เลยกำหนด ≥1 → `badge text-2xs bg-danger/15 text-danger-ink` + `clock-exclamation` + "เลยกำหนด {n}". ไม่มีเลยกำหนดแต่มีเปิด → `badge text-2xs bg-default-100 text-default-700` + `list-check` + "งานค้าง {n}". **ป้ายเดียวต่อแถว** (เลยกำหนดชนะ). `text-2xs` ตามชิปพี่น้องในบรรทัดเดียวกัน (sibling parity) — ข้อความสั้นและมีไอคอนช่วย.
- 🛑 **ต้องแก้เงื่อนไขห่อ `(salesStatus !== 'UNSPECIFIED' || contactTags.length>0 || … )` ที่ `:1864-1868` เพิ่ม `|| followUpBadge`** — ไม่งั้นแถวที่ไม่มีแท็ก/สถานะอื่นจะไม่ render ป้ายนี้เลย และไม่มี gate ไหนจับ (บทเรียนคลาส `ui-boolean-needs-a-testable-home`). ข้อมูลมาจาก `enrichWithFollowUpCounts` ก้อนเดียวต่อหน้า (ไม่ยิงทีละแถว); สร้างป้ายด้วยฟังก์ชันบริสุทธิ์ `rowBadge(counts)`.
- `aria-label` เต็ม: "เลยกำหนด 2 รายการ จากงานติดตาม 3 รายการ"; `title` เดียวกัน (มือถือไม่มี hover — อย่าพึ่ง `title`).
- ขอบเขตของ n = ขอบเขตเดียวกับแผงในห้อง (BR-ACT-10). ห้อง DEEP: เฉพาะห้อง.

## User flow

1. **จดจากห้อง:** เปิดห้อง → (แผงกางเองถ้ามีเลยกำหนด) → กด "เพิ่ม" → sheet/modal ค่าตั้งต้นพรุ่งนี้ 09:00 → พิมพ์หัวข้อ → "บันทึก" → toast "เพิ่มรายการติดตามแล้ว" → แผงกาง + โฟกัสรายการใหม่.
2. **ถึงกำหนด:** push (แอป) → กด → `/inbox/{id}` (ถ้าร้านอื่น: `ChatShopAutoSwitch`) → แผงกางเอง → "ทำแล้ว" → เลือกผลหรือ "ข้าม" → การ์ดย้ายไป "ทำแล้วล่าสุด".
3. **เลื่อน:** การ์ด → "เลื่อน" → ชิปลัด (หรือ "เลือกเอง") → toast "เลื่อนเป็น พรุ่งนี้ 09:00 แล้ว" → ป้าย "เลื่อนมา N ครั้ง" (≥2 ขึ้นเตือน).
4. **ผู้จัดการตามงานทีม:** เมนูซ้าย "ติดตามลูกค้า" → กระดาน (แท็บ/คอลัมน์เลยกำหนดก่อน) → กรอง "ยังไม่มีคนรับ" → กดการ์ดเข้าห้อง.
5. **เห็นจากกล่องแชท:** ตัวกรอง "เกินกำหนด" หรือป้ายแดงบนแถว → เปิดห้อง → แผงกางอยู่แล้ว.
6. **bubble:** เปิดหน้าแชท → ปุ่มแดงอ่อน "เลยกำหนด 2" → กาง → ✓ (ปิดทันที) หรือกดแถวเข้าห้อง.

## Edge states รวม (นอกเหนือจากรายพื้นผิว)
- **ตัวเลข 0 และหลักร้อย:** panel `(0)`; bubble ไม่มีปุ่มเมื่อ 0; ป้าย/แท็บ/วงกลมนับ ≥100 = `99+`.
- **สิทธิ์:** ทุกคนในร้านทำได้ทุกอย่างกับทุกรายการ (BR-ACT-05) → UI ไม่ซ่อน/ปิดปุ่มตามผู้สร้าง. รายการของร้านอื่น = ไม่พบ (ไม่ใช่ 403). แพ็กเกจถูกล็อก (`activeLocked`) ใช้ได้ปกติ (S-1).
- **ขนาดจอ:** ทุกพื้นผิวทดสอบที่ 320 / 768 / 1024 / 1440. `FollowUpCard` ใช้ container query; ส่วนอื่นใช้ breakpoint Paces (`lg`=1024 เส้นเดียวของ seller shell).
- **โหมดมืด:** ทุกสีมาจาก token (`-ink` มี dark override); ห้ามเทา hardcode.
- **เคลื่อนไหว:** กาง/พับ/แถวเปิดต่อท้าย ≤200ms, `motion-reduce:transition-none`; ไม่มี choreography ตอนโหลด.
- **โฟกัส:** แถวเปิดต่อท้าย → โฟกัสชิปแรก, ปิดแล้วคืนโฟกัสปุ่มต้นทาง; ฟอร์ม → โฟกัสช่องหัวข้อ (เดสก์ท็อปเท่านั้น — มือถือไม่ auto-focus กันคีย์บอร์ดดันชีต); tablist ใช้ลูกศรตามแบบ `onTabKeyDown` ใน `CustomerPanel`.
- **การแข่งขัน (E9/E18):** ปิด/ลบซ้ำ = ผลสำเร็จเงียบ ไม่ error; การ์ดที่ถูกอีกคนเปลี่ยนสถานะ → optimistic rollback + `errNotFound`/รีเฟรช.

### Impeccable compliance

- **Mode: Operate.** พื้นผิวทั้ง 5 อยู่ใน `(paces)/seller/**` ผู้ใช้กำลังทำงาน (ตอบแชท ตามงาน) → scanability, consistency, ของคุ้นเคย (kanban / ปฏิทินเดือน / ชิปตัวกรอง) มาก่อนการแสดงออก. แบรนด์อยู่ที่รายละเอียดแม่น (เวลาไทยตายตัว, ป้ายมีไอคอน+คำ, ข้อความบอกทางออก). ไม่ใช้ Persuade/brand register.
- **One Voice:** น้ำเงิน primary ปรากฏเฉพาะ (1) ปุ่ม "ทำแล้ว" ของการ์ด*เลยกำหนด* เท่านั้น (ตัวเต็ม) (2) "บันทึก" ในฟอร์ม (3) ชิป/แท็บ/segmented ที่ selected (4) "เพิ่ม" แบบ soft `bg-primary/15`. การ์ดอื่น ปุ่มทำแล้วเป็น soft. ปุ่ม bubble ไม่ใช่น้ำเงิน.
- **Verified-Means-Green:** ไม่ใช้เขียวเลยทั้งฟีเจอร์ (ดู §0.2) — "ทำแล้ว" ไม่ใช่การยืนยันโดยบุคคลที่สาม; "ไม่มีงานเลยกำหนด" เป็นข้อความกลาง. ป้องกันการอ่านสับสนกับ `circle-check` เขียวของ "เธรดปิดงาน" ในแถวแชท.
- **สีแดง:** เฉพาะ "เลยกำหนด" (ล้มเหลวจริง = พลาดกำหนด). "ครบวันนี้"/"เลื่อนมา ≥2" เป็น warning; "งานค้าง" เป็นกลาง.
- **AA ทั้งสองโหมด:** ทุกป้ายใช้ `bg-{x}/15 text-{x}-ink` (ค่า light 6.2–8.5:1 · dark override `_root.css:207-211`). **ไม่ใช้ `text-white` บน `bg-danger`** (~3.3:1 ตก AA; โหมดมืด `danger-ink` เป็นชมพูอ่อน ขาวบนนั้นตกหนักกว่า). ไม่ใช้ opacity ลดความเข้มข้อความ "ทำแล้ว". จุดในปฏิทินมือถือไม่ใช่ตัวแบก (non-text 3:1 ที่ขนาดเล็กตก) ตัวแบก = ตัวหนา+ขีดใต้เลขวัน + `aria-label` + คำอธิบายข้อความ.
- **ไม่พึ่งสีอย่างเดียว:** ป้ายเลยกำหนด = ไอคอน `clock-exclamation` + คำ; bubble เปลี่ยนไอคอนและข้อความ ไม่ใช่แค่พื้น; ทำแล้ว = `check` + ผลลัพธ์เป็นข้อความ; จุดปฏิทินทำแล้ว = จุดกลวง.
- **Sentence-case / Ink shadow:** ไทย ไม่มีตัวพิมพ์ใหญ่บังคับ; bubble/กล่องกาง ใช้ `shadow-lg` ของ Paces (`rgba(76,76,92,.2)` ผสมหมึก ไม่ดำ).
- **anti-slop:** ไม่มี gradient, ไม่มี hero-metric, ไม่มี eyebrow caps, ไม่มีการ์ดซ้อนการ์ด (แผง/โปรไฟล์ใช้แถวแบ่งเส้น; การ์ดเฉพาะกระดาน), ไม่มี `border-s-3` แถบสี (แม้ Paces อนุญาต — ไม่จำเป็น).
- **น้ำเสียง:** ทุก error บอกทางออก (`errTitleMax` = "ตัดให้สั้นลง", `errNotFound` = บอกว่ารีเฟรชแล้ว, `profileNoRoom` = บอกว่าจะเพิ่มได้เมื่อไหร่); ไม่มี "ไม่สามารถ…ได้"; toast ไม่ไฮป์.
- **จุดที่ theme ขัดกับ Impeccable / แนวทางที่ตัดสิน:**
  1. **ค่าแตกต่างนอก token (HR7 carve-out ที่ต้องเขียน comment บรรทัดนั้น):** (ก) `bottom-[calc(1rem+env(safe-area-inset-bottom))]` ของ bubble บนมือถือ (ข) `max-h-[70dvh]` ของกล่อง bubble (ค) ไม่มีอื่น. *Controller ดู 2 จุดนี้ตอน critique.*
  2. **`text-2xs` (11px) บนป้ายแถวกล่องแชท** — ขัด PRODUCT.md ("ตัวอักษรใหญ่กว่ามาตรฐาน") แต่เป็น sibling parity กับชิปในบรรทัดเดียวกัน; แก้ทั้งบรรทัดเป็นงานแยกไม่ใช่ที่นี่. ที่อื่นในฟีเจอร์นี้ใช้ `text-xs` ขึ้นไป.
  3. **BRD เขียน "popover" ในปฏิทิน / bubble** — เบี่ยงเป็นชีตวัน/กล่องที่หลุดกล่อง เพราะ popover ในกล่อง `overflow` โดนตัด (`scroll-container-clips-popovers.md`) และเป็นการ์ดเต็ม + แถวเปิดต่อท้าย.
  4. **theme ไม่มี floating pill** (bubble) — ประกอบจาก primitive, ขอ Controller ตัดสิน.
  5. **theme ไม่มีแถวเปิดต่อท้าย (inline reveal)** — เป็นแพตเทิร์นใหม่จากธรรมชาติของ `.badge` กดได้ + `.btn`; ไม่ใช่ component ใหม่ แต่เป็นการประกอบ. อยู่ใน critique watch-list.
- **เฝ้าระวังตอน `/impeccable critique` (สำหรับ Controller):** ลำดับชั้นการ์ดเลยกำหนดเทียบปกติในแผง (ปุ่มทึบเฉพาะ overdue จริงไหม) · bubble ชน composer/dock/แผงขวาที่ 1440×900 + 390×844 · ป้ายเลยกำหนดในแถวแชทกับชิปอื่นชิงพื้นที่ที่ rail 320px · แถบแท็บมือถือ 5 แท็บ scroll ที่ 320 · คอนทราสต์โหมดมืด.

### Design decisions + rationale
1. **แถวพับปักหมุด แทนแท็บที่ 5** — งบแท็บเต็มแล้ว + ห้าม slide + ซ่อนใต้แท็บ = ฟีเจอร์ที่หาไม่เจอ.
2. **inline reveal แทน dropdown สำหรับ ทำแล้ว/เลื่อน** — กันโดนตัดใน scroll, เห็นตัวเลือกครบในการกดเดียว.
3. **ค่าตั้งต้นฟอร์ม = พรุ่งนี้ 09:00** — จด = พิมพ์หัวข้อ + บันทึก. (ค่าตั้งต้นของ UI ไม่ใช่กฎธุรกิจ; ถ้า product ไม่เห็นด้วยให้เปลี่ยนที่ค่าเดียว.)
4. **ไม่เขียว** — ดู Compliance.
5. **แผงตัวกรองหน้ารวม = แผงเดียวกับกล่องแชท** — ผู้ขายเรียนรู้ครั้งเดียว; ไม่มีรูปแบบตัวกรองที่สอง.
6. **ค่าตั้งต้น "ทั้งร้าน"** — หน้ามีไว้ดูทีม; "ของฉัน" อยู่ที่ bubble. เข้าจาก push รวมได้ "ของฉัน".
7. **ปฏิทินเดสก์ท็อป = FullCalendar / มือถือ = จุดสี** ตามที่ `/queues` ทำแล้ว — ไม่คิดใหม่ (sibling parity, HR1 มี Base ธีมครบ).
8. **ซ่อนหัวข้อตัวกรองเมื่อนับ 0 ทั้งสามค่า** — ไม่มีตัวกรองว่างสำหรับร้านที่ไม่เคยใช้.
9. **bubble `placement` อยู่ใน `bubbleModel` (ฟังก์ชันบริสุทธิ์)** — ตำแหน่งที่เดาผิดคือคลาสบั๊กที่ไม่มี gate จับ.

### Anti-slop self-check

1. **เฉพาะกับ Deep ไหม:** ใช่ — เวลาไทยตายตัว/พ.ศ., ขอบเขต "ลูกค้าเดียวกันข้ามห้อง" + ป้าย "จากห้อง", ร้าน PERSONAL ไม่มีตัวเลือกคน, โหมดรวมหลายร้าน, สลับร้านจาก push, ห้อง DEEP ไม่มีแท็ก, ผู้รับผิดชอบที่ถูกถอด. นำไปใช้กับสินค้าอื่นทันทีไม่ได้.
2. **มีพระเอก 1 อย่างต่อหน้าจอไหม:** ใช่ — ตาราง §0.1. ปุ่มหลักทึบเฉพาะ overdue; หัวคอลัมน์ overdue เป็นตัวเดียวที่มีป้ายสี.
3. **ของซ้ำ/คงที่ที่ตัด:** ตัดแท็บที่ 5; ตัดตัวเลขบนเมนูซ้าย (BRD); ตัดป้ายชนิดบนรายการทุกใบแบบสีสด (ชนิดเป็นไอคอนเล็กนำหน้า); ตัดไอคอนบนปุ่มสลับกระดาน/ปฏิทิน; ไม่มีการ์ด "สรุปตัวเลข" บนหน้ารวม (ตัวเลขอยู่ในแท็บ/หัวคอลัมน์อยู่แล้ว); หัวข้อตัวกรองที่ 0 ซ่อน.
4. **สถานะครบไหม:** ครบทุกพื้นผิว — empty / loading (skeleton) / error (พร้อมทางออก) / ข้อความยาว (clamp/truncate) / 0 และ 99+ / ร้านอื่น / session ไม่มี id / สลับร้านล้ม / ปฏิทิน >1,000 / แจ้งเตือนเครื่องปิด.
5. **copy บอกสิ่งที่ระบบทำได้จริง:** ปุ่มบอกผล ("เพิ่ม/ทำแล้ว/เลื่อน/เปิดกลับ/ลบรายการ"); `profileNoRoom` ไม่แนะนำปุ่มที่ไม่มี (ไม่มีปุ่มเพิ่มในสถานะนั้น, บอกว่าเพิ่มได้ที่ห้องแชท); toast ปิดรายการชี้ทาง "เปิดกลับจากแผงในห้องแชท" ซึ่งมีจริง (ไม่สัญญา undo).
6. **คำเดียวกัน = ของเดียวกัน:** "ติดตามลูกค้า" (ฟีเจอร์) · "รายการติดตาม" (ชิ้น) · "เลยกำหนด/งานค้าง/ครบวันนี้" คงตลอด; ไม่มี "กิจกรรม/งาน/นัดหมาย" ปนใน UI. ตัวเลข symbol เดียว (AC-ACT-22).
7. **สีสื่อความถูกไหม:** ตาม §0.2 — ไม่มีเขียว, แดง = เลยกำหนด, warning = ครบวันนี้/เลื่อนซ้ำ; สถานะเดียวกันสีเดียวทุกพื้นผิว (การ์ด/ป้ายแถว/ปฏิทิน/bubble).
8. **แตะมือถือได้จริง:** ชิปกด `min-h-11`, ปุ่ม `.btn` ได้ 44px จาก `safepay-overrides.css`, ✓ ใน bubble 44×44, ปุ่มเพิ่มไอคอน 44×44; bubble เมื่อกางอยู่โซนนิ้วโป้ง (ขวาล่าง) และซ่อนในห้องบนมือถือ (ไม่บังช่องพิมพ์).
9. **ที่ 1440px:** กระดานเห็น 4 คอลัมน์เต็ม + ครึ่งของ 5 (ไม่มีคอลัมน์ว่าง); โปรไฟล์ 70% มีของ (รายการ+ออเดอร์) และคอลัมน์ 30% เป็นหัวโปรไฟล์เดิม; แผงห้องเป็นคอลัมน์ขวา 384px เดิม.

### Open questions (ให้ Controller / user / developer)

- **Q-1 ไอคอน (HR12 — ห้ามเดา):** ทุกชื่ออยู่ในโปรเจกต์/ธีมจริง แต่ *การจับคู่ความหมาย* ขอให้ user เลือก: ชนิด ตามเรื่อง=`message-circle` · นัดคุยกับลูกค้า=`phone-call` · อื่น ๆ=`list-check`; และ "เลื่อน"=`refresh` ซึ่งซ้ำความหมาย "โหลดใหม่" — มีทางเลือกอื่นในชุดไหม (`clock-play`, `calendar-plus` มีจริงในโปรเจกต์)?
- **Q-2** `chevron-right` (ปฏิทินเดือนถัดไป) ยังไม่พบใช้ในโปรเจกต์ — ยืนยันชื่อกับตารางไอคอน tabler ก่อน (ถ้าไม่มี ใช้ `arrow-right` ที่อยู่ในตารางธีม).
- **Q-3 bubble ไม่มี theme match** — ยอมรับ "ประกอบจาก `btn` pill + `.card` shadow-lg" ไหม.
- **Q-4** (a) มติ "แผงพับปักหมุดเหนือแท็บ" แทนแท็บที่ 5 และ (c) "ชีตวันแทน popover" — เบี่ยงจากถ้อยคำ BRD/PRD; ขอ user เห็นชอบ.
