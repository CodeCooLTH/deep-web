# ส่วนขยาย 2026-10-04: ชื่อลูกค้าบนออเดอร์ฝั่งร้าน

## 1. ปัญหาที่ร้านแจ้ง

ร้านบริการกรอกชื่อลูกค้าเป็น `4กฐ9100 คุณบุญคอง` โดยใส่ทะเบียนรถไว้ใช้ค้นหา พอลูกค้าล็อกอินยืนยันออเดอร์ ระบบเอา **ชื่อบัญชีของลูกค้า** (ชื่อ Facebook/LINE) ไปแสดงแทนชื่อที่ร้านกรอก ผลคือ:
- ทะเบียนหายจากจอ
- ค้นด้วยทะเบียนไม่เจอ เพราะช่องค้นหาค้นจากชื่อที่โชว์อยู่
- หน้ารายละเอียดแสดง `@fb1234567890` ซึ่งเป็นรหัสที่ระบบตั้งให้ ร้านอ่านแล้วไม่รู้ว่าเป็นใคร

ต้นเหตุมีสองจุด:
- `orders/page.tsx`: `buyerName: o.buyer?.displayName ?? o.buyerName`
- `resolveBuyerNames()`: `displayName || username || buyerName`

ทั้งสองจุดให้ชื่อบัญชีชนะชื่อที่ร้านกรอก เป็นแบบนี้กับทุกประเภทร้าน

## 2. มติ user (เลือกจาก design canvas)

| # | มติ |
|---|---|
| D-BN-1 | **ชื่อหลัก = ชื่อที่ร้านกรอกเสมอ** ถ้าร้านไม่ได้กรอก (ใบเก่า) ค่อยใช้ชื่อบัญชี |
| D-BN-2 | **หน้ารายการ (แบบ C)** แสดงเป็นบรรทัดดังนี้ ทั้งการ์ดมือถือและตารางเดสก์ท็อป:<br>1. ติ๊กน้ำเงิน (คงไว้) + ชื่อที่ร้านกรอก<br>2. ไอคอนคน (`tabler:user`) + ชื่อบัญชี<br>3. ข้อมูลเดิม (เพจ · วิธีชำระ · เบอร์) |
| D-BN-3 | **การ์ดผู้ซื้อในหน้ารายละเอียด (แบบ B)** แสดงชื่อที่ร้านกรอก ตามด้วย `บัญชี: <ชื่อบัญชี>` และเลิกโชว์ `@username` |
| D-BN-4 | **ซ่อนบรรทัดชื่อบัญชี** เมื่อชื่อบัญชีซ้ำกับชื่อหลัก (ไม่สนช่องว่าง/ตัวพิมพ์) หรือเป็นชื่อที่ระบบตั้งให้ ได้แก่ `User` (OAuth ที่ไม่ส่งชื่อ) และ `User_1234` (สมัครด้วยเบอร์) |
| D-BN-5 | ค้นหาได้ด้วย ชื่อที่ร้านกรอก · ชื่อบัญชี · username · เบอร์ (และฟิลด์เดิมทั้งหมด) |
| D-BN-6 | **หน้า "ลูกค้า" (`/customers`) ยังไม่แก้รอบนี้** ยังโชว์ชื่อบัญชีแทนชื่อที่ร้านกรอก เพราะหน้านี้รวมหลายออเดอร์ ต้องตัดสินก่อนว่าจะใช้ชื่อจากใบไหน |

## 3. สิ่งที่เปลี่ยน

**กติกาเดียว (SSOT):** `src/lib/buyer-name.ts` → `resolveOrderBuyerName({ typedName, accountName })` คืน `{ name, accountName }` และ `isPlaceholderAccountName()`

| จุด | ก่อน | หลัง |
|---|---|---|
| หน้ารายการ `orders/page.tsx` | `displayName ?? buyerName` | `buyerName` = ชื่อหลัก · `buyerAccountLabel` = บรรทัดรอง · `buyerAccountName` = ชื่อบัญชีดิบ (ไว้ค้นหา) |
| การ์ดมือถือ `OrderCard.tsx` | ชื่อเดียว | + บรรทัดชื่อบัญชี (ไอคอนคน) |
| ตารางเดสก์ท็อป `OrdersTable.tsx` | ชื่อเดียว | + บรรทัดชื่อบัญชี (ไอคอนคน) |
| การ์ดผู้ซื้อ `CustomerDetails.tsx` | ชื่อบัญชี / `@username` | ชื่อที่ร้านกรอก / `บัญชี: …` |
| กล่องยืนยัน "ให้บริการตามนัดแล้ว" (`AppointmentCard`) | ชื่อบัญชีก่อน | ชื่อที่ร้านกรอกก่อน |
| ค้นหา `order-search.ts` + `order-search-sql.ts` | ไม่มีชื่อบัญชี | เพิ่มชื่อบัญชีดิบ ทั้ง TS และ SQL (parity) |
| `resolveBuyerDisplayName()` ใน `order-display.ts` | ไม่มีผู้เรียก และใช้กติกาผิด | **ลบ** (HR16 ห้ามมีนิยามที่ขัดกันค้างอยู่) |

**ไม่แตะ:**
- ใบเสร็จและปฏิทินคิว: ใช้ชื่อที่ร้านกรอกอยู่แล้ว
- การ์ดรีวิว: ชื่อคนรีวิวคือเจ้าของบัญชี ถูกแล้ว
- หน้าแอดมิน
- แชท: ชื่อผู้ติดต่อในแชทเป็นอีกเรื่อง

**ไม่มี migration ไม่มีการแก้ข้อมูล** ชื่อที่ร้านกรอกอยู่ในฐานครบมาตลอด แค่ไม่ถูกเอามาแสดง
