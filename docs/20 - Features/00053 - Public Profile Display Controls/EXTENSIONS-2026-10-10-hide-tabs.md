# CR — ร้านเลือกซ่อนแท็บบนหน้าร้านสาธารณะเองได้

> CR ต่อยอด 00053 (ตัวควบคุมการแสดงผล) ไม่ใช่ feature ใหม่ — 00053 เป็นเจ้าของ "สวิตช์ที่ร้านใช้คุมสิ่งที่คนนอกเห็น"
> อยู่แล้ว (`showPrices`) · 🛑 HR11: เอกสารนี้ต้องผ่าน user ก่อนแตะโค้ดบรรทัดแรก

## 1. ที่มา

user (2026-10-10) ส่งรูปแถบแท็บหน้าร้าน (ปักหมุด · **บริการ 2** · สินค้า 47 · รีวิว · เกี่ยวกับร้าน) แล้วสั่ง
*"หน้า profile เอา บริการออกหน่อย"* → เมื่อถามขอบเขต ตอบ *"ทำให้แต่ละร้านเลือกตั้งค่าได้เองครับ"*

สถานะปัจจุบัน: แท็บโผล่อัตโนมัติตามข้อมูล (`computeVisibleTabKeys` ใน `src/lib/profile-tab-keys.ts`) —
แท็บบริการขึ้นเมื่อร้านเป็น `SERVICE_QUEUE` และมีบริการ ≥1 ตัว · ตัวจัดหน้าร้าน (00035) **จัดลำดับได้อย่างเดียว**
และ `applyTabOrder` ถูกเขียนให้ "ไม่มีทางตัดแท็บทิ้ง" โดยตั้งใจ (guardrail ของ 00035 D-9)

## 2. ขัดกับมติเดิมไหม — 00035 D-9

D-9 (non-negotiable) ห้ามซ่อน **สัญญาณความน่าเชื่อถือ**: หัวโปรไฟล์ · รีวิว · trust score/ป้ายยืนยัน · สถิติออเดอร์
เหตุผล: ถ้าร้านซ่อนเฉพาะตัวที่แย่ได้ ตัวเลขที่เหลือหมดความหมาย

แท็บ **บริการ / สินค้า / ปักหมุด / ห้องพัก / ปฏิทิน** เป็น *เนื้อหาที่ร้านเสนอขาย* ไม่ใช่สัญญาณความน่าเชื่อถือ
→ ซ่อนได้โดยไม่ละเมิด D-9 · แท็บ **รีวิว** ยังซ่อนไม่ได้ตาม D-9 · **เกี่ยวกับร้าน** ซ่อนไม่ได้ (เป็นแท็บเดียวที่รับประกันว่าแถบแท็บไม่ว่าง)

## 3. ข้อเสนอที่รอเคาะ

| # | คำถาม | ข้อเสนอ |
|---|---|---|
| D-1 | ซ่อนแท็บไหนได้บ้าง | `pinned` `services` `items` `rooms` `calendar` · **ห้าม** `reviews` (D-9) และ `about` |
| D-2 | สวิตช์อยู่ที่ไหน | หน้า `/public-profile` การ์ดเดียวกับสวิตช์ซ่อนราคา (ใช้บนมือถือได้ — ตัวจัดหน้าร้านเป็น desktop-only) · แสดงเฉพาะแท็บที่ร้านนั้นมีข้อมูลจริง |
| D-3 | ซ่อนแล้วกระทบอะไร | กระทบ**เฉพาะแถบแท็บบนหน้าร้านสาธารณะ** (`/u/*`, `/b/*`) — ข้อมูลบริการ/สินค้าไม่ถูกลบ · ระบบจองคิว · การสร้างออเดอร์ · ลิงก์ตรงที่ร้านส่งให้ลูกค้า ทำงานเหมือนเดิม |
| D-4 | ค่าตั้งต้น | ไม่ซ่อนอะไรเลย (ร้านเดิมทุกร้านเห็นเหมือนเดิม — zero regression) |

## 4. ผลกับระบบ (ถ้าอนุมัติ)

- **DB**: `ShopPageLayout.hiddenTabs String[] @default([])` — additive · ร้านที่ไม่มีแถว อ่านเป็น `[]` ที่ service
  (หลักเดียวกับ fallback ของ `isPublished`/`showPrices`) · ⚠ HR15: push `main` = migrate prod ในตัว · local ต้อง apply เอง · migrate ล้ม = deploy ไม่ขึ้น
- **กฎบังคับที่ server ไม่ใช่แค่ UI**: validation กรองให้เหลือเฉพาะคีย์ใน D-1 · `reviews`/`about` ที่ส่งมาถูกทิ้ง — และ
  `computeVisibleTabKeys` ตัดแท็บที่ซ่อนออก ณ จุดเดียว (หน้าร้านจริง + canvas ตัวจัดหน้าร้านใช้ชุดเดียวกัน)
- **API**: `PATCH /api/shops/current/page-builder/tabs` แบบเดียวกับ `.../prices` (owner/ทีม ตามสิทธิ์เดิมของ `.../prices`)
- **ตัวจัดหน้าร้าน (00035)**: แท็บที่ซ่อนไม่โผล่ใน canvas/รายการจัดลำดับ · การซ่อนไม่แตะ `tabOrder` → เปิดกลับมาแล้วอยู่ที่เดิม **ยกเว้น**ร้านกด "บันทึก" ตัวจัดหน้าร้านระหว่างที่ซ่อนอยู่ (draft ไม่มีคีย์นั้น) แท็บจะไปต่อท้ายแทน — ยอมรับ ณ รอบนี้
- **D-2 ปรับตอนลงมือ**: สวิตช์โชว์ตาม *ประเภทร้าน* (`vertical`) ไม่ใช่ตามว่ามีข้อมูลจริง — เลี่ยง query ข้อมูลทุกแท็บซ้ำในหน้าตั้งค่า · แท็บที่ไม่มีข้อมูลจะไม่โผล่บนหน้าร้านอยู่แล้ว สวิตช์นั้นจึงไม่มีผลเสีย
- **เทส**: `profile-tab-keys` — ซ่อน `services` แล้วหาย · ส่ง `reviews`/`about` มาซ่อน → ยังอยู่ (เทสต้องแดงถ้าเอาด่าน D-1 ออก)
- **SRS**: sync `docs/SRS.md` (field ใหม่ + endpoint) ตาม HR11
