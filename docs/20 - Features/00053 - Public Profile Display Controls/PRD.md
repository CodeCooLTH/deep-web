# PRD: ตัวควบคุมการแสดงผลหน้าร้านสาธารณะ (Public Profile Display Controls)

---

## Executive Summary

หน้าร้านสาธารณะของ Deep (`/u/[username]` และ `/b/[slug]` — ไฟล์เดียวกัน คนละทางเข้า) ทุกวันนี้ **แสดงทุกอย่างที่ร้านมี โดยที่ร้านเลือกไม่ได้**: สินค้าที่ `isActive` ทุกชิ้นขึ้นกริด ห้องพักที่เปิดใช้งานทุกห้องขึ้นแท็บห้องพัก บริการทุกรายการขึ้นแท็บบริการ และราคาของทุกอย่างถูกพิมพ์ลงการ์ดเสมอ ตัวเลือกเดียวที่ร้านมีคือสวิตช์ระดับ "ทั้งหน้า" (`ShopPageLayout.isPublished` จาก feature 00035) ซึ่งเป็นทางเลือกแบบมีหรือไม่มี — ปิดแล้วคนนอกเห็นแค่ข้อความว่าหน้านี้ปิดอยู่

ช่องว่างนี้ชนกับวิธีขายจริงของร้านจำนวนมากบนแพลตฟอร์ม: ร้านบริการและร้านที่ขายของราคาผันแปร (งานสั่งทำ · ราคาตามสเปก · ราคาที่ต่อรองในแชท) ต้องการให้หน้าร้านทำหน้าที่เป็น "แฟ้มผลงาน + หลักฐานความน่าเชื่อถือ" แล้วให้การคุยเรื่องราคาไปเกิดในแชท การพิมพ์ตัวเลขไว้บนการ์ดจึงทำร้ายร้านกลุ่มนี้สองทาง — ผู้ซื้อคัดออกจากตัวเลขก่อนได้คุย และร้านต้องคอยแก้ราคาในระบบทุกครั้งที่นโยบายราคาเปลี่ยน เช่นเดียวกับที่ร้านหลายแห่งมีสินค้าในระบบไว้ใช้กับ POS/แชท (ของแถม · รายการภายใน · สินค้าที่เลิกโปรโมทแล้วแต่ยังมีสต็อก) ซึ่งไม่ควรไปนั่งอยู่หน้าร้านให้ลูกค้าใหม่เห็นเป็นอย่างแรก

ฟีเจอร์นี้เพิ่มตัวควบคุม 3 ชั้นให้ร้าน ทั้งหมดตั้งค่าที่เมนู **โปรไฟล์สาธารณะ** (`/public-profile`) ที่เดียว:

1. **สวิตช์ราคา (ระดับร้าน)** — เปิด/ปิดการแสดงราคาบนหน้าร้านสาธารณะทั้งหน้า **ค่าตั้งต้นคือปิด** (มติผู้ใช้ 2026-08-23) ปิดแล้วไม่มีข้อความอะไรมาแทนที่ตัวเลข แต่ **บรรทัดยอดสะสมยังอยู่ครบ** ("ขายแล้ว 12 ชิ้น" / "ใช้บริการแล้ว 3 ครั้ง" / "เข้าพักแล้ว 8 ครั้ง") เพราะนั่นคือหลักฐานที่ทำให้การ์ดยังพูดแทนร้านได้เมื่อไม่มีราคา
2. **สวิตช์รายตัว** — เลือกได้ว่าสินค้า/บริการ/ห้องพัก **ชิ้นไหน** จะขึ้นหน้าร้าน ค่าตั้งต้นคือแสดงทุกชิ้น (ร้านเดิมไม่มีอะไรเปลี่ยน) การซ่อนไม่กระทบการขายผ่านแชท/POS/ออเดอร์เลย
3. **ชิปเรียงลำดับบนแท็บสินค้า** — "ขายดี" และ "ยอดนิยม" ให้ผู้ซื้อจัดกริดเองได้ แทนที่จะเห็นเฉพาะของที่เพิ่งเพิ่มล่าสุดเสมอ

คุณค่าหลักไม่ใช่ฟีเจอร์ใหม่ที่ขายได้ แต่คือการคืน**สิทธิ์ตัดสินใจว่าหน้าร้านของตัวเองจะพูดอะไร**ให้เจ้าของร้าน ซึ่งเป็นเงื่อนไขที่ทำให้ร้านกลุ่มบริการ/งานสั่งทำกล้าส่งลิงก์หน้าร้านให้ลูกค้าจริง — ทุกวันนี้ร้านกลุ่มนี้เลือกที่จะไม่ส่งเลย

🛑 **ผลกระทบที่ต้องรู้ก่อนอนุมัติ:** ค่าตั้งต้นของสวิตช์ราคาเป็น "ปิด" แปลว่า **หน้าร้านทุกร้านบน prod หยุดแสดงราคาทันทีที่ deploy** จนกว่าเจ้าของจะเข้ามาเปิดเอง — นี่คือการตัดสินใจของผู้ใช้ (2026-08-23) ไม่ใช่ผลข้างเคียง และเป็นเหตุผลที่ต้องมีแถบแจ้งในหน้า `/public-profile` บอกร้านว่าราคาถูกซ่อนอยู่และเปิดกลับได้ตรงไหน

## 2. User Personas (กลุ่มผู้ใช้งาน)

### 2.1 เจ้าของร้านบริการ / งานสั่งทำ (SERVICE_QUEUE)

- **บริบท:** ราคาขึ้นกับหน้างาน ต้องถามรายละเอียดก่อนเสมอ ลูกค้าที่ทักมาพร้อมความคาดหวังราคาผิดคือลูกค้าที่คุยยากที่สุด
- **สิ่งที่ต้องการ:** หน้าร้านที่โชว์ผลงาน + รีวิว + จำนวนครั้งที่ให้บริการ โดยไม่มีตัวเลขราคา
- **ความสำเร็จ:** ส่งลิงก์หน้าร้านให้ลูกค้าใหม่ได้โดยไม่ต้องอธิบายเรื่องราคาก่อน

### 2.2 เจ้าของร้านค้าออนไลน์ (ONLINE_SALES)

- **บริบท:** มีสินค้าในระบบมากกว่าที่อยากโชว์ — ของแถม, สินค้าที่ทำไว้ให้ POS กดเร็ว, สินค้าใกล้เลิกขาย
- **สิ่งที่ต้องการ:** เลือกได้ว่าอะไรขึ้นหน้าร้าน โดยไม่ต้องปิดการขาย (`isActive = false`) ซึ่งจะทำให้กดขายในแชท/POS ไม่ได้ไปด้วย
- **ความสำเร็จ:** หน้าร้านเหลือแต่ของที่ตั้งใจขายให้คนใหม่ และของขายดีขึ้นก่อน

### 2.3 ผู้ซื้อที่กำลังตัดสินใจ

- **บริบท:** เปิดลิงก์หน้าร้านจากแชท/โฆษณา ยังไม่รู้จักร้าน
- **สิ่งที่ต้องการ:** รู้ว่าร้านนี้ของขายดีคืออะไร คนอื่นซื้ออะไรกัน — และถ้าไม่มีราคา ต้องรู้ว่าจะไปถามที่ไหน
- **ความสำเร็จ:** ยังเห็นหลักฐาน (ยอดขาย/ยอดถูกใจ/รีวิว) แม้ไม่มีราคา และมีปุ่มแชทให้กดถามอยู่แล้วบนหน้าเดิม

## 4. Business Rules & Constraints

### 4.1 กฎทางธุรกิจหลัก

- **BR-PPD-01** — "ไม่มีแถว `ShopPageLayout`" ต้องอ่านเป็น `showPrices = false` (ซ่อนราคา) ซึ่ง **กลับทิศกับ `isPublished` ที่ fallback เป็น `true`** ในตารางเดียวกัน ทั้งสองค่าอยู่บรรทัดติดกันในฟังก์ชันเดียวกัน ต้องมีคอมเมนต์กำกับว่าทำไมไม่เหมือนกัน
- **BR-PPD-02** — การซ่อนราคาเป็นเรื่องของ *หน้าร้านสาธารณะ* เท่านั้น ห้ามลามไปแชท ออเดอร์ การ์ดสินค้าที่ส่งเข้าแชท หรือหน้าใด ๆ หลังร้าน
- **BR-PPD-03** — การซ่อนรายตัวไม่แตะ `pinnedAt`/`isActive` เด็ดขาด (สามคอลัมน์ตอบคนละคำถาม: "ปักหมุดไหม" / "ขายอยู่ไหม" / "โชว์หน้าร้านไหม")
- **BR-PPD-04** — สิทธิ์แก้ทุกสวิตช์ = OWNER หรือ ADMIN ของร้านที่ active เท่านั้น บังคับที่ server ไม่ใช่ซ่อนปุ่ม
- **BR-PPD-05** — รายการที่ซ่อนต้องถูกกรองตั้งแต่ query ไม่ใช่ดึงมาแล้วกรองตอน render (ข้อมูลจะไหลเข้า RSC payload ไปแล้ว)
- **BR-PPD-06** — ตัวนับบนแท็บและกติกา "แท็บที่ไม่มีข้อมูลจะไม่ถูก render" ต้องนับ **หลัง** กรองเสมอ ไม่งั้นจะได้แท็บที่กดเข้าไปแล้วว่างเปล่า

### 4.2 ข้อจำกัดทางธุรกิจ

- สวิตช์ราคาเป็น **ค่าเดียวทั้งร้าน** ไม่มีการตั้งราคาโชว์/ไม่โชว์รายชิ้น (ถ้าต้องการซ่อนราคาเฉพาะบางชิ้น ให้ซ่อนทั้งรายการนั้นแทน — ดู §5)
- แท็บบริการยังไม่มีข้อมูลยอดนิยม/ยอดใช้บริการต่อรายการ จึงยังไม่มีชิปเรียงลำดับและไม่มีบรรทัดยอดสะสมบนการ์ดบริการ (ดู §5)

### 9.2 สมมติฐาน (Assumptions)

- ร้านส่วนใหญ่มีสินค้าที่แสดงบนหน้าร้าน **ไม่เกิน 48 ชิ้น** — เพดานการดึงข้อมูลของแท็บสินค้าตั้งไว้ที่ 48 ถ้ามีมากกว่านั้น ส่วนที่เกินจะไม่เข้ามาอยู่ในชุดที่เรียง (ต้องมีป้ายบอก ไม่ใช่เงียบ — ดู `partial-data-must-be-labeled-or-filled.md`)
- ไม่มี analytics ฝั่งหน้าร้านสาธารณะ ณ วันที่เขียน — KPI ข้อที่วัดการกดชิปจึงประเมินจาก feedback ไม่ใช่ตัวเลข
- ผู้ซื้อที่เห็นการ์ดไม่มีราคาจะใช้ปุ่มแชทที่มีอยู่แล้วบนหน้าเดิมในการถาม (ไม่ต้องเพิ่ม CTA ใหม่)

## 10. Appendix

### 10.1 ตัวอย่าง User Journey

**ร้านบริการ (BT Premium — SERVICE_QUEUE) ปิดราคา**

1. เจ้าของเปิด `/public-profile` เห็นการ์ด "ราคาบนหน้าร้าน" มีแถบเตือนว่า *ราคาถูกซ่อนอยู่*
2. ตัดสินใจว่าถูกแล้ว ไม่แตะสวิตช์
3. เลื่อนลงมาการ์ด "รายการที่แสดงบนหน้าร้าน" เห็น "แสดงอยู่ 12 จาก 15" — ปิดสวิตช์สินค้าภายใน 3 ชิ้นที่ไม่อยากให้ลูกค้าเห็น
4. กด "ดูหน้าร้านของฉัน" → การ์ดไม่มีราคา แต่ยังมี "ใช้บริการแล้ว 3 ครั้ง" ใต้ชื่อ
5. ส่งลิงก์ให้ลูกค้าใหม่ทางแชท

**ร้านค้าออนไลน์เปิดราคากลับ**

1. เจ้าของเห็นแถบเตือนในหน้า `/public-profile` ว่าราคาถูกซ่อน
2. เปิดสวิตช์ → toast ยืนยัน → เปิดหน้าร้านเห็นราคาเหมือนเดิมทุกใบ
3. ผู้ซื้อกดชิป "ขายดี" บนแท็บสินค้า → กริดเรียงใหม่ตามยอดขายจริง

### 10.2 สิ่งที่หน้าร้านยังบอกอยู่เมื่อไม่มีราคา

เพื่อไม่ให้การ์ดกลายเป็นรูปเปล่า ๆ สิ่งเหล่านี้ยังอยู่ครบเมื่อสวิตช์ราคาปิด: ชื่อรายการ · คำอธิบายสั้น · รูป · ยอดถูกใจ · **ยอดสะสม ("ขายแล้ว/ใช้บริการแล้ว/เข้าพักแล้ว")** · ป้ายปักหมุด · คะแนนรีวิวของร้าน · คะแนนความน่าเชื่อถือ · ปุ่มแชทกับร้าน
