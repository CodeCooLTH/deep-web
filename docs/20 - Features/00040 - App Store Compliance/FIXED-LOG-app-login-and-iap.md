⇒ ตอบกลับถาม Apple ว่าเปิดให้สมัครในแอปได้ไหม (ใช้แบบฟอร์มเดียวกับ

## กติกาที่ได้จากรอบนี้ (กันพลาดซ้ำ)

1. **คุกกี้ที่ตั้งแล้วเด้งออกนอกเว็บทันที เชื่อไม่ได้ใน WebView** — เกิดแล้ว 2 ครั้งคนละคุกกี้
   (csrf 09-16 · callback-url 09-17) ⇒ อะไรที่ต้องพร้อมก่อนออกไป OAuth ให้เตรียมตั้งแต่เปิดหน้า
2. **ปลายทางหลังล็อกอินห้ามเป็นหน้ายืนยันตัวตน** — แต่ `/auth/callback/*` ของ LINE/IG
   เป็นปลายทางที่ถูกต้อง **ห้ามเหมารวม** ไม่งั้นสองเจ้านั้นล็อกอินไม่ได้ทันที
3. **หน้าที่ไม่เคยเช็ค session + `proxy.ts` ยกเว้น `/auth` ทุกด่าน** = คนล็อกอินแล้วมาโผล่ได้
   โดยไม่มีใครกัน ⇒ ต้องมีด่านที่ตัวหน้าเอง
4. **ปุ่มที่ถูกซ่อนตามกฎ ต้องเปลี่ยนคำรอบ ๆ ให้ตรงด้วย** — ซ่อนปุ่มแต่ปล่อยคำโปรยที่ชวนให้
   กดปุ่มนั้นไว้ = ผู้ใช้หาไม่เจอแล้วสรุปว่าแอปพัง · ตรวจทุกครั้งที่ `isSignUpRestricted`
   หรือ `isPaymentRestricted` ซ่อนอะไรสักอย่าง ว่ามีคำที่พูดถึงของชิ้นนั้นค้างอยู่ไหม

5. **แก้ 2 รอบไม่หาย = หยุดเดา ไปจำลองให้เห็นกับตาก่อน** — #67 กับ #68 เดาต้นเหตุจาก
   "อาการคล้ายบั๊กเก่า" (คุกกี้มาช้าใน WebView) แล้วแก้ผิดจุดทั้งสองรอบ · สิ่งที่พาไปเจอต้นเหตุจริงคือ
   (ก) ถามอาการที่แยกสาเหตุได้ ("ช่องยังมีข้อความไหม" ⇒ หน้าไม่ได้โหลดใหม่เลย) และ
   (ข) จำลองด้วย Playwright WebKit **ให้เงื่อนไขตรง prod** — จำลองรอบแรกผ่านเพราะ
   `NEXTAUTH_URL` ใน local เป็นคนละโดเมนกับหน้า ⇒ วิ่งคนละกิ่ง · ต้องเช็กว่า prod ตั้งค่ายังไง
   (`/api/auth/providers` บอก baseUrl ได้โดยไม่ต้องล็อกอิน) แล้วตั้ง local ให้ตรง
   · `callbacks.redirect` **ต้องคืน URL เต็มเสมอ** — ค่าเดียวกันถูกใช้ทั้งเป็น `Location` (รับ path ได้)
   และเป็น `data.url` ให้ `signIn` ฝั่งหน้าเว็บ (รับ path ไม่ได้) เทส Apple ผ่านจึงไม่ได้แปลว่าทางอื่นผ่าน
6. **ของแบบนี้ห้ามแก้ทีละหน้า** — พอไล่จริงเจอ **8 จุด**ที่ล็อกอินแล้วเปลี่ยนหน้า (ผู้ขาย 4 ·
   แอดมิน 2 · ผู้ซื้อ 2) ⇒ ทำเป็นตัวกลาง `goAfterLogin()` + เทสที่ **กวาดทั้ง `src/`
   หาทุก `signIn(redirect:false)`** ไม่ใช่รายชื่อไฟล์ที่ฮาร์ดโค้ดไว้ ของใหม่จะได้ถูกจับเอง
7. **ลบแพ็กเกจทดสอบในฐานข้อมูลอย่างเดียวไม่พอ** — การสมัครยังอยู่ที่ Apple ID ในเครื่อง ⇒ กด
   "กู้คืนการซื้อ" = สิทธิ์กลับมาทันที (ระบบทำถูก ลูกค้าจริงต้องได้แบบนี้) · ยกเลิกแล้วก็ยังใช้ได้
   จนจบรอบ · TestFlight นับ 1 เดือน = 1 วัน · ซื้อผ่าน TestFlight ด้วย Apple ID จริง
   **ล้างประวัติไม่ได้** ("Clear Purchase History" ใช้ได้เฉพาะบัญชี Sandbox ที่สร้างใน App Store Connect)
   ⇒ ก่อน Submit: ยกเลิกในแผ่นจัดการการสมัคร + ลบแถวในฐานข้อมูล + **ห้ามกดกู้คืนบนเครื่องนั้นจนหมดรอบ**
   · คนตรวจของ Apple ใช้ Apple ID ของเขาเอง ไม่ได้รับผลจากการสมัครค้างของเรา
