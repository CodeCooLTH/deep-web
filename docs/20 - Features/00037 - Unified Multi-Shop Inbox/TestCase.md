# TestCase: กล่องแชทรวมหลายร้าน

## 1. อัตโนมัติ — รันแล้วผ่าน

`src/lib/__tests__/chat-scope.test.ts` (13 เคส) + `src/app/api/chat/conversations/[id]/route.test.ts` (14 เคส รวมของเดิม)

| ID | เคส | คาดหวัง | สถานะ |
|----|-----|---------|-------|
| U-01 | `SINGLE` | `shopIds = [activeShopId]` และ **ไม่เรียก** `listAccessibleShopIds` | ผ่าน |
| U-02 | `UNIFIED` (เจ้าของ + สมาชิก ซ้ำกัน) | ครบทุกร้าน dedupe แล้ว, `activeShopId` ไม่ขยับ | ผ่าน |
| U-03 | `UNIFIED` แต่เข้าถึงร้านเดียว | `mode='SINGLE'`, `storedMode='UNIFIED'` | ผ่าน |
| U-04 | ร้าน active ถูก soft-delete | คืน `null` (ไม่ fallback ไป PERSONAL) | ผ่าน |
| U-05 | ไม่มี session / `id` เป็น null | คืน `null` | ผ่าน |
| U-06 | คอลัมน์มีค่าประหลาด (`"ALL_SHOPS_PLEASE"`) | ตกเป็น `SINGLE` (fail-closed) | ผ่าน |
| U-07 | แถว `User` หายไป (race กับการลบบัญชี) | ยังตอบได้แบบ `SINGLE` ไม่ throw | ผ่าน |
| U-08 | ร้าน active ถูก package lock | `activeLocked=true` + `lockReason` ส่งต่อ (โหมดรวมไม่ปลดล็อกให้ใคร) | ผ่าน |
| U-09 | `intersectScopedShopIds` ไม่ส่งตัวกรอง | คืนทั้งขอบเขต | ผ่าน |
| U-10 | 🛑 ยิง `shopId` ที่ไม่มีสิทธิ์ | คืน `[]` — **ไม่ใช่ขอบเขตทั้งก้อน ไม่ใช่ 403** (BR-UNI-02) | ผ่าน |
| U-11 | ส่งปนทั้งในและนอกขอบเขต | เหลือเฉพาะที่อยู่ในขอบเขต | ผ่าน |
| U-12 | `normalizeChatScopeMode` case-sensitive | `"unified"` → `SINGLE` | ผ่าน |
| R-01 | PATCH เธรดนอกขอบเขต | 404 และ **ไม่เรียก service เลย** | ผ่าน |
| R-02 | โหมดรวม: PATCH เธรดของอีกร้านในขอบเขต | เรียก `updateConversationState` ด้วย **shopId ของเธรด** ไม่ใช่ร้าน active | ผ่าน |

**Regression baseline:** เทียบกับ `7b117278` (ก่อนฟีเจอร์) แล้ว — fail เท่ากันเป๊ะ 98 ข้อ (หนี้ที่มีอยู่ก่อน: `activity.service`, `auto-reply.service`, `channel-chat-ingest`, `chat-service-filters` 3 ข้อ, `conversations/route.test.ts` collection error จาก `server-only`) และ pass เพิ่ม 15 ข้อ → **ไม่มี regression**

## 3. หนี้ที่ยังไม่ปิด

1. **browser QA ทั้ง 31 เคสยังไม่เคยกด** — user รับไปตรวจเองบน prod ตามข้อตกลงเดิม

3. E2E Playwright ยังไม่มีสำหรับฟีเจอร์นี้
