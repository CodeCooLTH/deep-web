# BRD: บัญชีส่วนตัวและการเชื่อมต่อบัญชี (Business Requirements Document)

---

## 1. บทนำ

### 1.1 วัตถุประสงค์ของเอกสาร

เอกสารนี้มีวัตถุประสงค์เพื่อ:
1. อธิบายความต้องการเชิงหน้าที่ของการเปิดทางให้ผู้ถูกเชิญเข้าร้านธุรกิจสร้างร้านส่วนตัวของตัวเองได้จริง (ส่วน A) และหน้าตั้งค่าบัญชีส่วนตัวที่แยกจากร้าน (ส่วน B) ในรูปแบบที่ทดสอบได้ — **implement รอบนี้**
2. บันทึกความสามารถ "เชื่อมต่อบัญชี" (ส่วน C) ที่ **มีอยู่แล้วบน production** (feature 00001 FR-LO-16 + FR-LO-04, commit `e69513c4`) ให้ถูกต้อง แทนที่การเข้าใจผิดในฉบับ v1.0 ว่าต้องสร้างใหม่ พร้อมยกธงประเด็นที่ยังต้องให้ user ตัดสิน
3. รวบรวมกฎทางธุรกิจทั้งหมดพร้อมรหัสอ้างอิง `BR-PAC-*` เพื่อให้ทีมพัฒนาและทีมทดสอบใช้ร่วมกัน — ครอบคลุมทั้งกฎ 1-ร้าน-ต่อ-คน, กฎเบอร์ immutable, สิทธิ์ OWNER/ADMIN, และผลกระทบต่อ Trust Score/Tier
4. สร้างความเข้าใจร่วมว่าอะไรคือของใหม่ (A, B) และอะไรคือการใช้ซ้ำ/อ้างอิงของที่มีอยู่แล้ว (C, และ backend ของ A) จาก feature 00012 / 00008 / 00001 / 00015 ที่อยู่บน production แล้ว

### 1.2 ขอบเขตของระบบ

**บัญชีส่วนตัวและการเชื่อมต่อบัญชี** คือส่วนขยายของระบบบัญชีผู้ใช้เดิม ที่ (1) เปิดทางเข้าจริงให้สร้างร้านส่วนตัวจาก account switcher, (2) แยกหน้าตั้งค่าที่เป็นของ "คน" ออกจากหน้าตั้งค่าที่เป็นของ "ร้าน" และ (3) บันทึก + ยกธงปัญหา discoverability ของความสามารถ "เชื่อมต่อบัญชี" ที่มีอยู่แล้ว

**เข้าสู่ระบบ (Input):**
- สถานะการมี/ไม่มีร้านส่วนตัวของ user (จาก `GET /api/business/context`)
- สถานะ `hasBusinessMembership` และ `activeShopRole` ของ session ปัจจุบัน (จาก `lib/auth.ts`)
- ข้อมูลโปรไฟล์ที่ user แก้ไข (ชื่อที่แสดง, username, รูป, อีเมล)

**ออกจากระบบ (Output):**
- ร้านส่วนตัวที่ถูกสร้างขึ้น พร้อม active shop ที่สลับไปแล้ว
- ข้อมูลโปรไฟล์ user ที่อัปเดตแล้ว สะท้อนบน topbar/switcher ทันที

**ระบบที่เกี่ยวข้อง:**
- feature 00012 — Shop Staff Invite Links (`POST /api/shops/open-personal`, `ensurePersonalShop()`)
- feature 00008 — Business Account & Packages (`Shop.kind`, `ShopMember`, `Shop.trustScore`)
- feature 00001 — Login & Onboarding (`/onboarding` wizard, `resolveOnboardingGate()` ใน `lib/onboarding-gate.ts`, **และเจ้าของความสามารถทั้งหมดของส่วน C**: FR-LO-16 account linking, FR-LO-04 reset password)
- feature 00015 — Order Claim & Forced Login (`account-merge-ticket.ts`, `link-account` — พฤติกรรมบัญชีซ้ำแบบ "ย้าย" ที่ถูกพบระหว่างตรวจ D2)
- ระบบคำนวณ Trust Score เดิม (`trust-score.service.ts`) — อ้างอิงเท่านั้น ไม่แก้ไข
- ระบบอัปโหลดไฟล์เดิม (`POST /api/upload`)

### 1.3 กลุ่มผู้ใช้งาน

| กลุ่มผู้ใช้ | บทบาท | สิทธิ์การใช้งาน |
|-----------|--------|----------------|
| **ผู้ถูกเชิญเข้าร้านธุรกิจ — role OWNER** | สร้างร้านส่วนตัวของตัวเอง | สร้างได้ 1 ร้าน ต่อเมื่อยังไม่มีร้านส่วนตัวมาก่อน — สิทธิ์เท่ากับ role ADMIN ทุกประการ (ดู §8.5) |
| **ผู้ถูกเชิญเข้าร้านธุรกิจ — role ADMIN** | สร้างร้านส่วนตัวของตัวเอง | สร้างได้ 1 ร้าน ต่อเมื่อยังไม่มีร้านส่วนตัวมาก่อน — สิทธิ์เท่ากับ role OWNER ทุกประการ (ดู §8.5) |
| **user ทุกคนที่ login แล้ว** | แก้ไขข้อมูลส่วนตัวของตัวเอง | แก้ได้เฉพาะบัญชีของตัวเองเท่านั้น (avatar/displayName/username/email) |
| **ผู้ดูแลแพลตฟอร์ม Deep** | ดูภาพรวมความปลอดภัยของ API บัญชีผู้ใช้ | อ่านอย่างเดียว ไม่แก้ไขบัญชีของ user อื่นผ่านหน้านี้ |

## 2. ความต้องการหลัก (Functional Requirements)

### 2.1 ส่วน A — สร้างร้านส่วนตัวจาก account switcher (implement รอบนี้)

#### FR-PAC-01: แถวสร้างร้านส่วนตัวในบัญชีสวิตเชอร์

**User Story:**
> ในฐานะผู้ถูกเชิญเข้าร้านธุรกิจที่ยังไม่มีร้านส่วนตัว ฉันต้องการเห็นทางเลือก "สร้างร้านส่วนตัวของฉัน" อยู่ในที่ที่ฉันกำลังใช้งานอยู่แล้ว เพื่อให้ขายของในนามตัวเองได้โดยไม่ต้องรู้ว่าต้องไปหาหน้าไหน

**Acceptance Criteria:**
- [ ] user ที่มี business membership อย่างน้อย 1 ร้าน (role ใดก็ได้ — OWNER หรือ ADMIN) และไม่มีร้านที่ `kind = PERSONAL` เลย ต้องเห็นแถว "สร้างร้านส่วนตัวของฉัน" ทั้งใน account switcher บน desktop และบนมือถือ
- [ ] user ที่มีร้านส่วนตัวอยู่แล้ว (ไม่ว่าจะตั้ง slug เสร็จหรือยัง) ต้อง **ไม่เห็น** แถวนี้เลย — เห็นเป็นแถวร้านส่วนตัวปกติที่สลับได้แทน
- [ ] user ที่ไม่มี business membership เลย (ไม่เคยถูกเชิญ) ต้อง **ไม่เห็น** แถวนี้ในบริบทของฟีเจอร์นี้ (account switcher sheet มือถือไม่ mount เลยตาม `AccountSwitcherLauncher.tsx` ที่มีอยู่ก่อนแล้ว — ไม่แก้ไข)
- [ ] กดแถวนี้แล้วต้องมีการยืนยันก่อนสร้างจริง (ไม่สร้างทันทีที่กดครั้งแรกโดยไม่มีการยืนยัน)
- [ ] ยืนยันแล้ว ระบบต้องสร้างร้านส่วนตัวสำเร็จและสลับ active shop ไปร้านนั้นทันที
- [ ] กดปุ่มนี้ซ้ำหลายครั้งติดกัน (เช่น กดสองครั้งเร็ว ๆ) ต้องไม่สร้างร้านส่วนตัวซ้ำ 2 ร้าน — บังคับด้วย partial unique index ระดับฐานข้อมูล ไม่ใช่แค่ debounce ฝั่ง UI
- [ ] หลังสร้างสำเร็จ แถว "สร้างร้านส่วนตัว" ต้องหายไปจาก switcher ทันที (ไม่ต้อง refresh หน้า)
- [ ] `User.trustScore` ก่อนและหลังสร้างร้านส่วนตัวต้องเท่ากันเป๊ะ (ดู §8.6)

**Business Flow:**
1. ผู้ถูกเชิญเปิด account switcher เห็นแถว "สร้างร้านส่วนตัวของฉัน"
2. กดแถวนี้ → เห็นข้อความยืนยันอธิบายว่าจะพาไปตั้งค่าร้านต่อ
3. กดยืนยัน → ระบบสร้างร้านส่วนตัว (หรือคืนร้านเดิมถ้ามีอยู่แล้ว) → สลับ active shop
4. พาไปหน้า onboarding ของร้านที่สร้างใหม่
