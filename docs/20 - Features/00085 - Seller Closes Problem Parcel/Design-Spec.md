**กล่องเตือน**
- ปัจจุบันเป็น `<p>` ที่ `ShipmentStatusView.tsx:773-786` เปลี่ยนเป็น `<div className="rounded-lg px-3 py-2.5 text-xs ${NOTICE_BOX[tone]}">`
- ข้างในเรียง: แถว icon + ข้อความเดิม → ปุ่ม → บรรทัด "ปิดแล้วเลิกปิดได้ภายหลัง"

**ปุ่ม**

- icon `tabler:archive`
- ไม่ใช้ `btn-primary` / `btn-soft-*` (ไม่มีในธีม)

**เงื่อนไขแสดงปุ่ม**

- ห้ามเขียน `carrierStatus==='issue'` ใน JSX

## 2. Modal (helper ใหม่ `pacesCloseParcelProblem` ใน `paces-swal.ts`)

ประกอบจาก pattern ที่มีอยู่ในไฟล์เดียวกัน
- `pacesConfirmTerms`: `didOpen` + ปิดปุ่มยืนยันไว้จนกรอกครบ
- `pacesEditTextFields`: html + `preConfirm` อ่าน DOM
- `pacesConfirmAsync`: `showLoaderOnConfirm` และ throw = ไม่ปิดโมดัล

ตั้งค่าเพิ่ม
- `buttonsStyling:false`, `allowOutsideClick:false`
- **ไม่ใส่ `icon`** (กินพื้นที่มือถือ)
- ปุ่มยืนยัน `CONFIRM_BTN.primary` (ถอนคืนได้ จึงไม่ใช่ danger)

│ [ เลือกเหตุผล                  ▾ ]   │  form-select h-11

│ ┌──────────────────────────────────┐ │  rounded-lg bg-default-100 p-4
│ │ ▣ ส่งไม่สำเร็จ                   │ │  text-base font-semibold
│ │ ไม่พบประวัติว่าพัสดุถึงผู้รับ      │ │

- ทุกจอกว้าง 32em
- มือถือ: container ของ Swal เลื่อนเอง ไม่ต้องตั้ง max-height
- เหตุผลเป็น `<select class="form-select h-11">`
  - ตัวเลือก: `FIRE` ไฟไหม้ · `LOST` ของหาย · `DAMAGED` สินค้าเสียหาย · `OTHER` อื่น ๆ
  - textarea ซ่อนอยู่จนเลือก `OTHER`: `border-default-300 text-default-900 min-h-24 w-full rounded-lg border px-3 py-2 text-sm`, `maxlength=200`, นับความยาวหลัง trim, escape ด้วย `esc()`
- กล่องผล A และ B ใช้พื้น neutral ทั้งคู่ **ห้ามเขียว ห้ามแดง**
  - icon ผล A `tabler:package-off`
  - icon ผล B `tabler:arrow-back-up`
- คำถามคืนเงินเป็น radio **ไม่ default** ค่าใดเลย
- ระหว่างโหลด preview: skeleton 3 แถว `h-4 w-2/3 animate-pulse rounded bg-default-100` และปุ่มยืนยันปิดอยู่

### Copy
**หัวโมดัล**
- Title `ปิดพัสดุที่มีปัญหา`
- Label `เหตุผลที่ปิด` · placeholder `เลือกเหตุผล`

**ช่อง "อื่น ๆ"**
- label `ระบุเหตุผล` · placeholder `เช่น ขนส่งแจ้งว่าพัสดุตกน้ำ`
- error `พิมพ์อย่างน้อย 5 ตัวอักษร`

**ผล A `ส่งไม่สำเร็จ`**
- `ไม่พบประวัติว่าพัสดุถึงผู้รับ จึงบันทึกเป็น ส่งไม่สำเร็จ`
- แถว `ยอดขาย` → `ไม่นับเป็นยอดขาย`
- แถว `ค่าส่งขาไป` → `฿{x} นับเป็นต้นทุนของร้าน`
  - ถ้าเป็น COD ต่อท้าย `(ไม่รวมค่าธรรมเนียมเก็บเงินปลายทาง)`
  - ไม่รู้ยอด → ตัดตัวเลขออก

**ผล B `ส่งสำเร็จ · คืนไม่สำเร็จ`**
- `พบว่าพัสดุถึงผู้รับเมื่อ {วันเวลา} แล้วหายระหว่างส่งคืน`
- ที่มา: `จากประวัติขนส่ง` / `ผู้ซื้อกดยืนยันรับของแล้ว`
- B + COD: `ไม่นับเป็นยอดขาย เพราะยังไม่ได้รับเงินปลายทาง`

**คำถามคืนเงิน**
- หัว `ลูกค้าได้รับเงินคืนหรือไม่`
- ตัวเลือก 1: `คืนเงินลูกค้าแล้วหรือจะคืน` (hint `ยอดขายออเดอร์นี้จะถูกหักออก ค่าส่งขาไปนับเป็นต้นทุน`)
- ตัวเลือก 2: `ไม่คืนเงิน` (hint `ยอดขายออเดอร์นี้นับตามเดิม`)
- ท้ายกลุ่ม: `ระบบไม่ได้โอนเงินคืนให้ แค่บันทึกว่าร้านตัดสินใจอย่างไร`

**หมายเหตุประวัติไม่ครบ**
- `ประวัติขนส่งของพัสดุใบนี้ไม่ครบ ผลที่ระบบตัดสินอาจคลาดเคลื่อน ถ้าพัสดุถึงผู้รับแล้ว ให้ตรวจกับขนส่งก่อน หรือปิดไปก่อนแล้วเลิกปิดได้ภายหลัง`

**ปุ่มและ toast**
- ปุ่ม `ยืนยันปิดพัสดุ` / `ยังไม่ปิด`
- toast `ปิดพัสดุแล้ว บันทึกเป็น {ชื่อผล}`

### Edge states
| สถานะ | สิ่งที่แสดง |
|---|---|
| preview ล้มเหลว | กล่อง `NOTICE_BOX.danger` ข้อความ `โหลดผลที่ระบบตัดสินไม่สำเร็จ` + `ลองใหม่` · ปุ่มยืนยันปิดเสมอ |
| เน็ตหลุด / 500 | throw ⇒ โมดัลไม่ปิด · `ปิดพัสดุไม่สำเร็จ ลองกดยืนยันอีกครั้ง ถ้ายังไม่ได้ให้รีเฟรชหน้านี้` |
| 409 | ปิดโมดัล ⇒ `pacesAlert` info `สถานะพัสดุนี้เปลี่ยนไปแล้ว` / `มีคนปิดหรือขนส่งอัปเดตไปก่อนหน้านี้ แผงจะโหลดสถานะล่าสุดให้` ⇒ รีเฟรชแผง |
| 403 | `บัญชีนี้ปิดพัสดุไม่ได้` / `ให้ผู้ดูแลร้านที่จัดการพัสดุได้เป็นคนปิดแทน` |
| ผลเปลี่ยนระหว่างเปิดโมดัล | client ส่ง `expectedOutcome` ⇒ server ตอบ `OUTCOME_CHANGED` พร้อมผลใหม่ ⇒ โมดัลไม่ปิด กล่องผลอัปเดต + รีเซ็ตคำตอบคืนเงิน · `ผลที่ระบบตัดสินเปลี่ยนไประหว่างที่เปิดหน้าต่าง ตรวจผลด้านบนแล้วกดยืนยันอีกครั้ง` |
| ชื่อผู้ปิดถูกลบ | แสดง `ผู้ดูแลร้าน` |

## 3. หลังปิด (แทนกล่องแดงตรงตำแหน่งเดิม)

```
 [พัสดุ TH0123…]  [ส่งไม่สำเร็จ]   badge bg-default-100 text-default-800
 ●──●──●──○    จุดปัจจุบันเทา (TONE_DOT_SOLID.secondary ตรง ๆ ห้ามผ่าน CURRENT_DOT.secondary ที่เป็นเขียว)
 ┌─ warning (เฉพาะเมื่อขนส่งส่งสถานะขัดกับผลที่ปิด) + ปุ่ม เลิกปิด ─┐
 ┌─ กล่องสรุป bg-default-100 rounded-lg px-3 py-2.5 ─────────────────┐
 │ ▣ ปิดพัสดุแล้ว · ส่งไม่สำเร็จ          text-sm font-semibold     │
 │ เหตุผล  สินค้าเสียหาย                  break-words                │
 │ ปิดโดย  {ชื่อ} · {formatDateTime}                                 │
 │ ไม่นับเป็นยอดขาย · ค่าส่งขาไปนับเป็นต้นทุน                         │
 │ ↩ เลิกปิด  (btn text-primary hover:underline min-h-11 px-0 ·      │
 │             ซ่อนเมื่อมีกล่อง warning ที่มีปุ่มอยู่แล้ว)             │
 └──────────────────────────────────────────────────────────────────┘
```

- **badge:** ห้ามใช้ `TONE_BADGE.secondary` เพราะเป็นสีม่วง · ข้อความอ่านจาก `STAGE_BADGE_OVERRIDE` (HR16)
- **บรรทัดเงินของผล B (โอน + ไม่คืน):** `นับเป็นยอดขายตามเดิม · เลือกไม่คืนเงิน`
- **ยืนยันเลิกปิด:** ใช้ `pacesConfirmAsync` ด้วย `icon:'question'` และ `confirmSemantic:'primary'`
  - หัวข้อ `เลิกปิดพัสดุนี้?`
  - ข้อความ `พัสดุจะกลับไปตามสถานะล่าสุดจากขนส่ง ถ้ายังมีปัญหาจะกลับไปอยู่ในกอง "พัสดุมีปัญหา" และยอดขายของออเดอร์นี้จะคำนวณใหม่ตามปกติ`
  - ปุ่ม `เลิกปิด` / `ยังปิดไว้`
  - toast `เลิกปิดแล้ว`
- **กล่อง warning เมื่อขนส่งส่งสถานะที่ขัดกับผลที่ปิด** (`NOTICE_BOX.warning`)
  - ผล A แล้วขนส่งส่ง delivered / payment_success: `ขนส่งแจ้งว่าพัสดุถึงผู้รับแล้ว ({เวลา}) หลังที่ปิดเป็น ส่งไม่สำเร็จ ระบบยังไม่เปลี่ยนยอดให้ ถ้าพัสดุถึงจริงให้เลิกปิด`
  - ผล A แล้วขนส่งส่ง return*: `ขนส่งแจ้งว่าพัสดุกำลังตีกลับหรือกลับถึงร้านแล้ว ({เวลา}) หลังที่ปิดเป็น ส่งไม่สำเร็จ ระบบยังไม่เปลี่ยนยอดให้ ตรวจกับขนส่ง ถ้าไม่ตรงให้เลิกปิด`
  - ผล B แล้วขนส่งส่ง issue: `ขนส่งแจ้งปัญหาใหม่ ({ข้อความ}) หลังปิดแล้ว ระบบยังไม่เปลี่ยนผลที่ปิดไว้ ตรวจกับขนส่ง ถ้าไม่ตรงให้เลิกปิด`
- **ไม่มีสิทธิ์:** ไม่แสดงปุ่มหรือลิงก์ใด ๆ แต่ยังเห็นกล่องสรุป

## 4. ป้ายในแถวแชท การ์ด และ /orders

- เพิ่ม key ใหม่ใน `ORDER_STAGE_META` และ `STAGE_BADGE_OVERRIDE` · ไม่ต้องสร้าง markup ใหม่
- ป้าย `ส่งไม่สำเร็จ` ใช้ icon `package-off`
- ป้าย `ส่งสำเร็จ · คืนไม่สำเร็จ` ใช้ icon `arrow-back-up`
- ทั้งสองป้ายพื้นเทา · ขึ้น 3 วันแล้วหาย
- ทุกที่ที่วาดแถบพัสดุต้องรับค่า `closed` เป็น field บังคับ (ไม่ใส่แล้ว tsc ฟ้อง)
  - ผู้เรียก `ShipmentRail`: MiniShipmentTimeline, ShipmentHoverCard, ShipmentStepper, OrderProgressBar, ShippingCard, ParcelTimeline

## 5. หน้าผู้ซื้อ `/o/[token]`

- ใช้ tone warning (เหลือง) · เปลี่ยนแค่ข้อความใน code path เดิมของ `ParcelTimeline` และ `NOTICE_OF`
- ผล A: `ส่งไม่สำเร็จ — ร้านบันทึกว่าพัสดุนี้ไม่ถึงมือคุณ ติดต่อร้านเพื่อสอบถามขั้นตอนต่อไป`
- ผล B: `พัสดุถึงปลายทางแล้ว แต่การส่งคืนร้านไม่สำเร็จ ติดต่อร้านหากต้องการสอบถามเพิ่มเติม`
- 🛑 ผู้ซื้อได้รับแค่ผลที่ปิด (outcome) ห้ามส่งเหตุผล ชื่อผู้ปิด ตัวเลขเงิน หรือคำตอบเรื่องคืนเงิน
