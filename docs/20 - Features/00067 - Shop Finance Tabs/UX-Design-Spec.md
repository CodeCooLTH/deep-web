# UX Design Spec: แท็บการเงินร้าน

---

## 1. บริบทและปัญหาที่ออกแบบเพื่อแก้

| ปัญหาที่เห็นจริง | ผลที่ตามมา |
|-----------------|-----------|
| หน้าเรื่องเงินมี 2 หน้าคนละกลุ่มเมนู | ผู้ขายไม่เคยเจอหน้าค่าใช้จ่าย |
| หน้า `/sales` ตอบได้แค่ "เก็บเงินครบยัง" | ไม่ตอบ "เดือนนี้เหลือเท่าไหร่" |
| ร้านบริการไม่มีข้อมูลต้นทุน | ถ้าเขียนคำว่า "กำไร" ตัวเลขจะเท่ากับยอดขายเป๊ะ = โกหก |

**คำถามเดียวที่หน้านี้ต้องตอบ:** *เดือนนี้ร้านเหลือเงินเท่าไหร่ และเงินหายไปไหน*

## 2. โครงหน้า (Information Architecture)

```
การเงินร้าน  (/seller/sales)
├── แท็บ 1  กำไรขาดทุน   ?tab=pnl      ← ค่าเริ่มต้น
│   ├── [เมื่อข้อมูลไม่ครบ] ป้ายเตือน + CTA เติมข้อมูล
│   ├── ตัวเลขใหญ่ + badge %เปลี่ยนแปลง
│   ├── แถบองค์ประกอบ  รายได้ / ค่าใช้จ่าย
│   ├── กราฟแท่งคู่  รายได้ เทียบ ค่าใช้จ่าย  (+ ตัวเลือกช่วง)
│   └── ตารางแยกรายวัน + หมายเหตุสูตร
├── แท็บ 2  ยอดเก็บเงิน  ?tab=collect
│   ├── ตัวเลขใหญ่ ยอดขายรวม
│   ├── แถบสมการ  รับจริง + ค้างรับ = ยอดขาย
│   ├── กราฟแท่งซ้อน เก็บแล้ว / ค้างรับ
│   └── รายการต้องตามเก็บ (กดเข้าแชทได้)
└── แท็บ 3  ค่าใช้จ่าย   ?tab=expense
    ├── ตัวเลขใหญ่ จ่ายออกทั้งหมด
    ├── แถบองค์ประกอบ ต้นทุนอะไหล่ / ค่าใช้จ่ายร้าน
    ├── แยกตามหมวด
    └── รายการ + ปุ่มบันทึกเพิ่ม  (= ExpenseWorkspace เดิม)
```

**ลำดับของแท็บมีเหตุผล:** แท็บแรกคือคำตอบ แท็บสองคือ "เงินเข้าครบยัง" แท็บสามคือ "เงินออกไปไหน" — อ่านจากซ้ายไปขวาได้เป็นประโยค

## 4. Component spec

### 4.1 แถบแท็บ

**Base:** `theme/paces/Admin/TS/src/app/(admin)/ui/tabs/page.tsx` ผ่าน precedent ในรีโป `src/app/(paces)/seller/(chat)/inbox/[conversationId]/components/CustomerPanel.tsx:912`

```
<nav class="nav-tabs border-default-200 border-b px-4" role="tablist" aria-label="...">
  <button role="tab" aria-selected=... class="nav-link -mb-px inline-flex items-center gap-1.5 px-2 py-3 text-sm
       [active]  border-b-2 border-primary text-primary
       [inactive] border-b-2 border-transparent">
```

| ข้อกำหนด | ค่า |
|----------|-----|
| ความสูงที่แตะได้ | ≥ 44px (`py-3` + line-height ให้ถึง) |
| จำนวนแท็บ | 3 — ที่ 390px ใช้ `flex-nowrap` ไม่ให้ตกบรรทัด |
| ห้าม | `overflow-x-auto` (แท็บแค่ 3 ต้อง fit พอดี) |
| คีย์บอร์ด | roving `tabIndex` + `onKeyDown` ลูกศรซ้าย/ขวา |
| ไม่มีไอคอนในแท็บ | คำ 3 คำสั้นพอ ไอคอนจะเบียดที่ 390px |

### 4.2 การ์ดตัวเลขใหญ่

**Base:** `src/app/(paces)/seller/(dashboard)/_shared/PacesStatCard.tsx` (โครง 3 แถวของธีม)

| แถว | เนื้อหา |
|-----|--------|
| 1 | หัวข้อ `card-title text-sm` + ไอคอน `info-circle` ที่มี `title` อธิบายสูตร |
| 2 | วงกลม `size-9 rounded-full` สีตามความหมาย + ตัวเลข + badge %เปลี่ยนแปลง ชิดขวา (`ms-auto`) |
| 3 | จุดสี + ชื่อตัวชี้วัด … ค่าชิดขวา |

**ข้อยกเว้นที่อนุญาต:** ตัวเลขใหญ่บนมือถือใช้ `text-3xl font-bold tabular-nums` ตาม precedent ที่มีอยู่แล้วใน `SalesChartSheet.tsx:637` — ไม่ใช่ `text-xl` ของการ์ดสถิติ เพราะบทบาทต่างกัน (ตัวเลขนี้คือคำตอบของทั้งหน้า)

**🛑 `tabular-nums` บังคับ** — ตัวเลขที่เปลี่ยนตามการสลับแท็บต้องไม่ขยับความกว้าง

### 4.3 ป้ายข้อมูลไม่ครบ (หัวใจของงานนี้)

| องค์ประกอบ | สเปก |
|-----------|------|
| ป้าย | `badge bg-warning/15 text-warning-ink` + ไอคอน `alert-triangle` · ข้อความ **"ตัวเลขนี้ยังไม่ใช่กำไรจริง"** |
| หัวข้อ | **"กำไรได้มากที่สุด"** ไม่ใช่ "กำไรสุทธิ" |
| ตัวเลข | นำหน้าด้วย `≤` · สี `text-default-400` (กลาง) |
| วงกลมไอคอน | `bg-default-200` ไม่ใช่สีความหมาย |
| คำอธิบาย | บอกตรง ๆ ว่า *"ยังไม่ได้หักอะไรเลย กำไรที่แสดงจึงเท่ากับยอดขายเป๊ะ ๆ ซึ่งไม่ใช่ความจริง"* |
| CTA | 2 แถวแบบ list item มีไอคอน + ข้อความรอง + chevron · แถวแรก "ตั้งราคาทุนของบริการ · ยังไม่ได้ตั้ง n จาก m" · แถวสอง "บันทึกค่าใช้จ่ายของร้าน" |
| รายการสรุป | ยอดขายที่ยืนยันแล้ว = ตัวเลข · ต้นทุนอะไหล่ = **"ยังไม่ได้ตั้ง"** (สี warning-ink) · ค่าใช้จ่ายร้าน = **"ยังไม่มีรายการ"** |

**เหตุผลที่ห้ามใช้สีเขียว:** Impeccable กฎ *Verified-Means-Green* — เขียวสงวนให้ "สำเร็จ/ยืนยันแล้ว" ตัวเลขที่ยังพิสูจน์ไม่ได้ใช้เขียวไม่ได้

### 4.4 กราฟ

**Base:** `theme/paces/Admin/TS/src/app/(admin)/widgets/charts/components/` (Hard Rule 10) ผ่าน `@/components/wrappers/ApexChart`

| แท็บ | ชนิด | ซีรีส์ | สี |
|------|------|-------|-----|
| กำไรขาดทุน | bar คู่ | รายได้ · ค่าใช้จ่าย | `getColor('chart-primary')` · `getColor('chart-danger')` |
| ยอดเก็บเงิน | bar ซ้อน | เก็บเงินแล้ว · ค้างรับ | `getColor('chart-primary')` · `getColor('chart-default')` |
| ค่าใช้จ่าย | bar เดี่ยว | จ่ายออก | `getColor('chart-danger')` |

**ข้อควรระวังจาก v9:** `yaxis.seriesName` ที่ชี้ชื่อซีรีส์ที่ไม่มีอยู่ ทำให้ ApexCharts ให้ซีรีส์นั้นใช้แกนของตัวเองแล้วสเกลเพี้ยนทั้งกราฟ **โดยไม่มี error** — ต้องมีเทสยืนยัน (TC-009)

**สีคู่ น้ำเงิน/ชมพู แทน เขียว/แดง:** เพื่อให้แยกออกด้วยความสว่าง ไม่ใช่ด้วยเฉดอย่างเดียว (คนตาบอดสีแดง-เขียวอ่านได้) — และตรงกับภาพอ้างอิงที่หัวหน้าส่งมาพอดี

### 4.5 ตัวเลือกช่วงเวลา

**Base:** `src/app/(paces)/seller/(dashboard)/dashboard/components/DashboardRangeControl.tsx`

กล่อง:  flex items-center gap-0.5 rounded-lg bg-default-100 p-0.5
pill:   min-h-11 rounded-md px-3 text-xs font-medium

ตัวเลือก: `เดือนนี้` · `6 เดือน` · `ปีนี้` — **ไม่มี custom date picker ในมือถือ** (กินพื้นที่เกินคุณค่า) เดสก์ท็อปยังมีตัวเลือกช่วงแบบเดิม

### 4.6 รายการต้องตามเก็บ

**Base:** `src/app/(paces)/seller/_follow-up/FollowUpCard.tsx` (โครงรายการที่มีปุ่มเข้าแชท)

| ส่วน | เนื้อหา |
|------|--------|
| ซ้าย | วงกลม `size-9` + ป้ายสั้น (`ค้าง` / `ครบ`) |
| กลาง | ชื่อลูกค้า (เน้น) · ชื่อบริการ + วันที่ (รอง) |
| ขวา | ยอดค้าง (เน้น สี warning-ink) · "ค้าง n วัน" (รอง) |

## 6. Copy (ข้อความบนจอ)

ทุกข้อความต้องอยู่ใน dictionary ทั้ง `th` และ `en` (feature 00047) — ห้าม hardcode

| คีย์ | ไทย | หมายเหตุ |
|------|-----|---------|
| หัวหน้า | การเงินร้าน | |
| แท็บ 1 | กำไรขาดทุน | |
| แท็บ 2 | ยอดเก็บเงิน | |
| แท็บ 3 | ค่าใช้จ่าย | |
| หัวข้อตัวเลข (ครบ) | กำไรสุทธิ · เดือนนี้ | จาก `order-profit-presentation` |
| หัวข้อตัวเลข (ไม่ครบ) | กำไรได้มากที่สุด · เดือนนี้ | จาก `order-profit-presentation` โหมด `capped` |
| ป้ายเตือน | ตัวเลขนี้ยังไม่ใช่กำไรจริง | |
| สูตร | กำไรสุทธิ = ยอดขายที่ยืนยันแล้ว − ต้นทุนอะไหล่ − ค่าใช้จ่าย | คำว่าต้นทุนผันตาม `ORDER_VOCAB.costNoun` |
| สมการเก็บเงิน | รับจริง + ค้างรับ = ยอดขาย | |
| หมายเหตุค้างรับ | ค้างรับ คือยอดที่ยังไม่ได้บันทึกการรับเงิน ไม่ได้แปลว่าลูกค้าไม่จ่าย | บังคับมี |
| หมายเหตุค่าใช้จ่าย | ค่าใช้จ่ายร้านลงตามวันที่ที่บันทึก ไม่ได้เฉลี่ยรายวัน | บังคับมี |
| CTA ต้นทุน | ตั้งราคาทุนของบริการ | + "ยังไม่ได้ตั้ง n จาก m" |
| CTA ค่าใช้จ่าย | บันทึกค่าใช้จ่ายของร้าน | |

**น้ำเสียง:** sentence case · ไม่ใช้ ALL CAPS ไทย · **ห้าม emoji** (Hard Rule 12) ใช้ Iconify เท่านั้น

## 7. Accessibility

| ข้อ | เกณฑ์ |
|-----|-------|
| แท็บ | `role="tablist"` + `role="tab"` + `aria-selected` + roving `tabIndex` + ลูกศรซ้าย/ขวา |
| เป้าแตะ | ≥ 44×44px ทุกปุ่ม/แท็บ/แถวรายการ |
| contrast | ตัวอักษร ≥ 4.5:1 — ใช้คู่ `-ink` เสมอเมื่อสีความหมายเป็นตัวหนังสือบนพื้นขาว (`#02bc9c` บนขาว = 2.21:1 **ตก**) |
| สีไม่ใช่ช่องทางเดียว | กำไร/ขาดทุนต้องอ่านออกจากเครื่องหมาย (`+`/`−`/`≤`) และคำ ไม่ใช่จากสีเท่านั้น |
| ประกาศการเปลี่ยนแท็บ | `aria-live="polite"` บอกว่าข้อมูลทั้งหน้าเปลี่ยนแล้ว (precedent `DashboardRangeControl`) |
| ตัวเลข | `tabular-nums` เพื่อให้เทียบแนวตั้งได้ |

### Impeccable compliance

**Mode:** operate (`(paces)/**` — งาน seller)

| กฎ Impeccable | ทำตามอย่างไรในสเปกนี้ |
|---------------|---------------------|
| **One Voice** | `#236dc9` (Counter Blue) ใช้กับ action และแท็บที่เลือกเท่านั้น — ไม่ทาเป็นพื้นหลังก้อนใหญ่ |
| **Verified-Means-Green** | เขียวใช้เฉพาะกำไรที่ข้อมูลครบและรับเงินจริง — สถานะ `capped` ใช้สีกลาง §4.3 |
| **Ink ไม่ใช่ดำ** | ตัวอักษรใช้ `#4c4c5c` / `#313a46` / `#627189` ไม่ใช่ `#000` |
| **เงาผสมโทน** | `0px 1px 4px rgba(130,143,163,.15)` — เทาอมน้ำเงินตาม token ไม่ใช่เงาดำ |
| **ลำดับชั้นมาจากลำดับการอ่าน ไม่ใช่ขนาดกล่อง** | การ์ดทุกใบสูงเท่ากัน "พระเอก" คือใบแรก (บทเรียน `PnlReportCard` v3 ที่เคยทำการ์ดใหญ่กว่าใบอื่นแล้วเหลือพื้นที่ว่างครึ่งใบ) |
| **สีต้องสื่อความหมาย ไม่ไล่ตามลำดับธีม** | เขียว = เงินเข้า · ชมพู = เงินออก · เทา = เป็นกลาง · ฟ้า = ค่าที่คำนวณมา |
| **ห้าม emoji** | ใช้ Iconify ทุกจุด |
| **ข้อมูลบางส่วนต้องติดป้าย** | §4.3 ทั้งหัวข้อ |

## 10. สิ่งที่ตั้งใจไม่ทำ

| ไม่ทำ | เหตุผล |
|-------|--------|
| ไม่เพิ่มแท็บ "บัญชี" ในแถบล่างของแอป | แถบล่างเป็นของเว็บ มี 5 ช่องเต็มแล้ว (บทเรียน: tab ซ้อน = 2 แถบ) |
| ไม่ทำ donut chart ของหมวดค่าใช้จ่าย | ที่ 390px อ่านสัดส่วนจากแท่งง่ายกว่าวงกลม |
| ไม่ทำ custom date picker บนมือถือ | กินพื้นที่เกินคุณค่า |
| ไม่ใส่ไอคอนในปุ่มแท็บ | เบียดที่ 390px |
| ไม่ทำโหมดมืด | ทั้งระบบยังไม่มี |
