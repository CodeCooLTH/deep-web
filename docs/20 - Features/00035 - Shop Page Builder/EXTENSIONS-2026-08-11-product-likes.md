# CR — ถูกใจสินค้าบนหน้าร้านสาธารณะ

> ทำเป็น **CR ต่อยอดหน้าโปรไฟล์สาธารณะ** ไม่ใช่ feature ใหม่ทั้งชุด (user ตัดสิน 2026-08-11:
> "ไม่ต้องทำ PRD ก็ได้มั้ง ทำเป็น CR/NR เข้า Public Profile เดิม") — วางไว้ที่ 00035 เพราะเป็น
> feature เดียวที่ tag `public-profile` และเป็นเจ้าของผังหน้าร้านสาธารณะ
>
> 🛑 **ยังยึด Hard Rule 11 ตรงที่ "เขียนข้อกำหนดก่อนเขียนโค้ด"** — สิ่งที่ย่อคือ *ปริมาณเอกสาร*
> (CR 1 ไฟล์ แทน 7 ไฟล์) ไม่ใช่ *ลำดับ* เอกสารนี้เขียนเสร็จก่อนแตะโค้ดบรรทัดแรก

## 1. ที่มา

user (2026-08-11): *"เพิ่ม like love ให้หน่อย (ให้คนมาเห็นแล้วกดได้)"*

หน้าร้านสาธารณะเป็นจุดสัมผัสแรกของผู้ซื้อ (ส่วนใหญ่มาจากลิงก์ที่ร้านส่งให้ และ **ยังไม่มีบัญชี**)
ตอนนี้ผู้ชมทำอะไรกับสินค้าไม่ได้เลยนอกจากดู — ปุ่มถูกใจให้ช่องทางแสดงความสนใจแบบไม่มีต้นทุน

## 2. การตัดสินใจที่ล็อกแล้ว (user ตอบเอง 4 ข้อ)

| # | คำถาม | คำตอบ |
|---|---|---|
| D-1 | guest กดได้ไหม | **กดได้** — เป็น gimmick เล็ก ๆ ไม่บังคับล็อกอิน |
| D-2 | กดที่อะไร | **รายสินค้า** (ไม่ใช่ระดับร้าน) |
| D-3 | โชว์ยอดไหม | **โชว์** และ **ต้อง cache** |
| D-4 | นับเข้า Trust Score ไหม | **ไม่นับ** |

### สิ่งที่ D-4 ปกป้องไว้ และห้ามมีใครเปลี่ยนทีหลังโดยไม่คุย

Trust Score ทั้งระบบตั้งอยู่บนหลักว่า **หลักฐานต้องเป็นสิ่งที่ร้านสร้างเองไม่ได้** (PRODUCT.md
§Positioning) — ยอดถูกใจจาก guest คือตัวเลขที่ปั่นได้ด้วยการเปิดหน้าเว็บซ้ำ ๆ จากอุปกรณ์ต่างกัน
ถ้าวันหนึ่งมีคนเสนอให้เอาไปคิดคะแนน คำตอบคือ **ไม่** และเหตุผลอยู่บรรทัดนี้

## 3. ขอบเขต

**อยู่ในขอบเขต**
- ปุ่มถูกใจ + ยอดบนการ์ดสินค้าในหน้า `/b/[slug]` และ `/u/[username]`
- กดซ้ำ = ยกเลิก (toggle)
- guest กดได้โดยไม่ต้องล็อกอิน

**นอกขอบเขต (ตั้งใจ)**
- ถูกใจระดับร้าน · ถูกใจห้องพัก/บริการ/คลิป
- รายการ "สินค้าที่ถูกใจ" ของผู้ใช้
- แจ้งเตือนผู้ขายเมื่อมีคนกด
- เอาไปคิด Trust Score / จัดอันดับสินค้า (D-4)

## 4. Business Rules

- **BR-LIKE-01** — 1 อุปกรณ์ ถูกใจสินค้าหนึ่งได้ **1 ครั้ง** บังคับด้วย `@@unique([productId, deviceKey])`
  ที่ระดับฐานข้อมูล ไม่ใช่ที่แอป (ตรวจแล้วเขียนยังชนกันได้ตอนกดรัว)
- **BR-LIKE-02** — กดซ้ำ = **ยกเลิก** ยอดลดลง 1 · ยอดต่ำสุดคือ 0 ห้ามติดลบไม่ว่ากรณีใด
- **BR-LIKE-03** — **ยอดอ่านจากคอลัมน์ที่ denormalize ไว้** (`Product.likeCount`) ไม่ใช่ `count()`
  ทุกครั้งที่เปิดหน้า — นี่คือ "cache" ตาม D-3 · การ์ดสินค้ามีได้ถึง 12+ ใบต่อหน้า การนับสดคือ
  12 aggregate query ต่อการเปิดหนึ่งครั้งบนหน้าที่เป็นจุดสัมผัสแรกของผู้ซื้อ
- **BR-LIKE-04** — ตัวนับกับตารางรายการ **ต้องเขียนในทรานแซกชันเดียวกัน** ไม่งั้นยอดกับจำนวนแถวจริง
  จะเพี้ยนถาวรโดยไม่มีอะไรฟ้อง
- **BR-LIKE-05** — สินค้าที่ปิดขาย/ถูกลบ ไม่รับการกดใหม่ (แต่ยอดเดิมไม่ถูกล้าง)
- **BR-LIKE-06** — ยอด **0 ไม่ต้องแสดงตัวเลข** แสดงแค่ปุ่ม — "ถูกใจ 0" บนสินค้าที่เพิ่งลง
  อ่านแย่กว่าไม่บอกอะไร (หลักเดียวกับ `soldCount > 0` ที่การ์ดใบเดียวกันใช้อยู่แล้ว)

## 5. ตัวตนของผู้กด (guest)

ไม่มีบัญชี → ต้องมีคีย์ที่ผูกกับ "อุปกรณ์" เพื่อให้ toggle ได้และกันกดซ้ำ

- คุกกี้ `deep_did` — uuid สุ่ม, `httpOnly`, `sameSite=lax`, อายุ 1 ปี, ตั้งจากฝั่งเซิร์ฟเวอร์
- **ไม่ผูกกับ `userId` แม้ล็อกอินอยู่** — ทำให้ตรรกะมีทางเดียว และ D-1 บอกว่าเป็น gimmick
  การผูกบัญชีจะพาไปสู่คำถาม "ย้ายของเก่ามาไหม" ที่ไม่คุ้มกับสิ่งที่ได้

🛑 **กันได้แค่การกดซ้ำโดยบังเอิญ ไม่ได้กันการปั่น** — ล้างคุกกี้/เปิด incognito ก็กดใหม่ได้
ยอมรับได้เพราะ D-4 ตัดผลต่อ Trust Score ออกไปแล้ว **ถ้าวันไหนตัวเลขนี้เริ่มมีผลต่ออะไรก็ตาม
ต้องกลับมาอ่านย่อหน้านี้ก่อน**

## 6. Data model

```prisma
model ProductLike {
  id        String   @id @default(uuid())
  productId String
  deviceKey String   // ค่าในคุกกี้ deep_did — ไม่ใช่ userId (ดู §5)
  createdAt DateTime @default(now())

  product Product @relation(fields: [productId], references: [id], onDelete: Cascade)

  @@unique([productId, deviceKey])   // BR-LIKE-01
  @@index([productId])
}
```

เพิ่มใน `Product`: `likeCount Int @default(0)` (BR-LIKE-03) + relation `likes ProductLike[]`

## 7. API

`POST /api/products/[id]/like` → `{ liked: boolean, likeCount: number }`

- ไม่ต้องล็อกอิน · ตั้งคุกกี้ให้ถ้ายังไม่มี
- toggle ในทรานแซกชันเดียว (BR-LIKE-04)
- 404 ถ้าสินค้าไม่มี/ปิดขาย (BR-LIKE-05)
- อยู่ใต้ rate-limit ของ `guardApi` ที่มีอยู่แล้ว

## 8. UI

หัวใจโปร่งมุมบนซ้ายของรูปสินค้า (ฝั่งตรงข้ามกับ badge แพลตฟอร์มที่อยู่มุมขวา)
กดแล้วทึบทันทีแบบ optimistic แล้วค่อย sync กับ response · ยอดอยู่ข้างหัวใจเมื่อ > 0

🛑 หัวใจอยู่ **บนรูป** ไม่ใช่ใต้ชื่อสินค้า เพราะการ์ดทั้งใบเป็นลิงก์ไปหน้าสินค้าอยู่แล้ว
ปุ่มที่ซ้อนบนลิงก์ต้อง `stopPropagation` และต้องมีพื้นที่แตะของตัวเองที่ไม่ทับกับ hit area ของการ์ด

## 9. สิ่งที่จะไม่ถูกแตะ

- Trust Score · แถบตัวเลขหลักฐาน · "ขายแล้ว N" — ไม่มีอะไรในนี้เกี่ยวกับยอดถูกใจ
- ลำดับสินค้าในกริด (ยังเรียงตามปักหมุด/วันที่เหมือนเดิม)
