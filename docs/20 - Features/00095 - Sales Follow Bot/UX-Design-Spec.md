- BRD (§0, FR-FB-40/41/42, BR-FB-70..75, §6.5), SRS TFR-FB-04/18/19/20, SDS S-7/S-8, API §4.0-4.12, REFERENCE-gochat-v3 §6, mockup gochat

## 0. กติกากลางของงานนี้

### 0.1 Mode, ชื่อ, ที่ตั้ง

| เรื่อง | ตัดสิน |
|---|---|
| Mode | **Operate** ทุกจอ (คอนโซลผู้ขาย) ไม่ใช่ brand |
| ชื่อบนจอ | "บอทติดตามยอดขาย" ตาม BR-FB-70 · ชื่อ "บอทขุด" ใช้ในทีมเท่านั้น ห้ามขึ้น UI · ใช้ "บอทติดตาม" ตัวเดียวทั้งสเปก ไม่ปนกับ "ผู้ช่วยอัตโนมัติ" (บอทตอบ) และ "ติดตามลูกค้า" (00066 เตือนพนักงาน) |
| เมนู | `/settings/sales-follow-bot` ต่อจากแถว `ส่งอัตโนมัติถึงลูกค้า` (`src/lib/seller-menu.ts:187`) ในกลุ่มเดียวกัน |
| ไอคอนของบอทนี้ | **ยังไม่เคาะ ต้องถาม (HR12)** → ดู Q1. ใช้ `robot` ไม่ได้เพราะเป็นของ DeepBot/ผู้ช่วยอัตโนมัติ ใช้ `send` ไม่ได้เพราะเป็นของ 00078. ในสเปกเขียนว่า `ICON_FOLLOWBOT` |
| สิทธิ์ | ทุกคนที่ตอบแชทได้ทำได้ทุกอย่าง (BRD §0 Q-11 ข) → **ไม่มีหน้าแบบอ่านอย่างเดียว** (SRS TFR-FB-19 ยืนยัน). บทบาทที่ไม่มีสิทธิ์ใช้ `NoPermissionCard` ตามพี่น้อง ห้ามเขียนคำว่า "เฉพาะเจ้าของ" |
| Select | ทุก dropdown/select = **Select2 (react-select)** ผ่าน `@/components/wrappers/Select` ห้าม native `<select>` |
| Dialog | ที่ต้องคลิกตอบ = `pacesConfirm`/`pacesAlert` (Swal) · ที่เด้งแล้วหาย = `pacesToast` |

### 0.2 ความหมายของสี (ใช้เหมือนกันทุกจอ)

| สถานะ | class | เหตุผล |
|---|---|---|
| บอท: ปิด | `badge bg-default-200 text-default-800` | เงียบ ไม่ใช่ความล้มเหลว |
| บอท: ทดสอบ | `badge bg-info/15 text-info-ink` + ไอคอน `flask` | มีไอคอน ไม่สื่อด้วยสีอย่างเดียว |
| บอท: เปิดใช้ | `badge bg-primary/15 text-primary-ink` | **ไม่ใช้เขียน** เพราะ "กำลังทำงาน" ไม่ใช่ "ยืนยันแล้ว" (ตามพี่น้อง `AutoNotifyRow`: เปิด = primary-ink) |
| ผลขั้น: ส่งแล้ว | `bg-success/15 text-success-ink` | **เขียวใช้ที่นี่ที่เดียว** เพราะเป็น "สำเร็จ" จริง ต้องเป็นสถานะที่ตั้งหลังตัวส่งรับสำเร็จ ไม่ใช่ตอนจองคิว (เงื่อนไขนี้ดู Q10) |
| ผลขั้น: ข้าม / พัก / รอคุณตอบ / ไม่แน่ใจว่าส่งถึง | `bg-warning/15 text-warning-ink` | ไม่ได้ออกแต่ไม่ใช่ความผิดพลาด |
| ผลขั้น: ส่งไม่สำเร็จ | `bg-danger/15 text-danger-ink` | แดงเฉพาะล้มจริง |
| ผลขั้น: กำลังส่ง / รอส่ง | `bg-default-200 text-default-800` / ข้อความเทา | ยังไม่มีผล |
| แท็กของร้าน (ชิปเงื่อนไข) | `badge bg-primary/15 text-primary-ink` | เหมือน `TagBadge` ใน `settings/tags` |
| สถานะการขาย (ชิปเงื่อนไข) | `badge border border-default-300 bg-card text-default-800` | ขอบเทา ไม่ใช้สีเลย กันแย่งกับแท็ก |

### 0.3 จุดที่ใช้ accent สีธีม (primary น้ำเงิน ไม่ใช้ม่วง)
- ปุ่มหลักหน้าละ 1 ปุ่ม: `สร้างบอทติดตาม` / `บันทึก`
- ป้ายสถานะ "เปิดใช้"
- ชิปแท็ก
- ขั้น "ถัดไป" ในแผงห้อง (จุดและตัวหนา)
- ลิงก์ในประโยค

สีเทา ขอบ และข้อความรองคุมที่เหลือ

## 1. จอ 1 — `/settings/sales-follow-bot` (แท็บ "บอท" + "ประวัติการส่ง")

- เจ้าของ/แอดมินเห็นในแวบเดียวว่า บอทไหนทำอะไร เงื่อนไข เปิดอยู่หรือไม่ ตามอยู่กี่ห้อง (AC-FB-80)

### 1.3 Section breakdown
- **หัวหน้า**: `PageBreadcrumb` + บรรทัดอธิบายเดียวตามพี่น้อง (`auto-notify/page.tsx`) ไม่มีการ์ดอธิบายยาว
- **แท็บ** เป็นลิงก์ `?tab=log` (แชร์ลิงก์ได้) หน้าตา segmented แบบ `ChatbotTabs` ปุ่มสร้างอยู่แถวเดียวกัน ขวาสุด
- **แถวบอท (ตาราง)**
  - คอลัมน์ 1 (ตัวเด่นที่สุดของแถว): ชื่อบอท `font-medium text-default-900 truncate`. ใต้ชื่อคือตัวอย่างข้อความขั้นแรกบรรทัดเดียว `text-xs text-default-700 truncate` โดยแทน `{ชื่อ}` ด้วยชื่อตัวอย่าง "สมชาย" (ใช้ตัวสร้างข้อความเดียวกับพี่น้อง `rowPreviewLine`)
  - ใต้ตัวอย่างคือเตือน "แท็กหาย" (เฉพาะเมื่อมี `warnings`): `text-warning-ink text-xs` + ไอคอน `alert-triangle`. บอกผลด้วยเพราะ ALL = ไม่ตามห้องใหม่ (fail-closed, SRS TFR-FB-07) ส่วน ANY บอทยังตามด้วยแท็กที่เหลือ
  - คอลัมน์ 2: บรรทัดสถานะการขาย (ชิปขอบเทา สูงสุด 2 + `+N` · ว่าง = ข้อความ "ทุกสถานะ") → บรรทัดแท็ก (ชิป primary สูงสุด 3 + `+N`, ตามด้วยข้อความ "มีแท็กใดแท็กหนึ่ง"/"มีครบทุกแท็ก" เมื่อมี ≥2 แท็ก) → โลโก้ช่องทาง `ChannelMark` สูงสุด 3 + `+N`
  - คอลัมน์ 3: `{N} ขั้น` + `ภายใน {ระยะรวม}`; ถ้ามีขั้น `adOnly` เพิ่มบรรทัด `text-xs`: "ขั้น {n} ส่งเฉพาะลูกค้าจากโฆษณา" (มีเฉพาะเมื่อจริง)
  - คอลัมน์ 4: badge สถานะ; ใต้ badge คือ "ตามอยู่ {n} ห้อง" (จาก `activeRunCount` เฉพาะ n>0 · ทดสอบ = "แชททดสอบ {k} ห้อง"). **ไม่แสดง "ตามอยู่ 0 ห้อง"** เพราะเป็นค่าคงที่ที่ไม่ให้ข้อมูล
  - ทั้งแถวเป็นลิงก์ไปหน้าแก้ (`DataTable onRowClick` + ปุ่มไอคอน `pencil` 37px มองเห็นอยู่เสมอ ตามที่ `DataTable` กำหนดไว้)
- **ประวัติ**: เรียงใหม่→เก่า keyset 50 รายการ · ไม่มีตัวกรอง (BR-FB-71) · "บอทที่ถูกลบแล้ว" เป็นตัวเทาเอียงไม่ใช่ลิงก์

- **ประวัติ ว่าง**: "ยังไม่มีการส่ง" / "เมื่อบอทส่งข้อความแรก จะเห็นรายการที่นี่"
- **ประวัติ ล้ม**: "โหลดประวัติไม่สำเร็จ" + `ลองใหม่`
- **ประวัติ กำลังโหลดเพิ่ม**: ปุ่ม "โหลดเพิ่ม" disabled + ไอคอน `loader-2` หมุน (`motion-reduce:animate-none`)

## 2. จอ 2 — ฟอร์มสร้าง/แก้บอท `/settings/sales-follow-bot/new` · `/settings/sales-follow-bot/[id]`

### 2.1 Layout

**Desktop ≥1024px (2/3 + 1/3 ตามพี่น้อง `grid gap-base lg:grid-cols-3`)**

### 2.2 Section breakdown และกติกา

1. **ชื่อและสถานะ**
   - ชื่อ: `form-input` มีตัวนับ `n/60`
   - สถานะ: segmented radio `ปิด / ทดสอบ / เปิดใช้` (สไตล์ `bg-light rounded-lg p-1` ของ `ChatbotTabs`) พร้อมบรรทัดอธิบายของค่าที่เลือก 1 บรรทัด
     - ปิด: "บอทไม่ทักใคร"
     - ทดสอบ: "ทักเฉพาะแชทที่เลือกไว้ทดสอบ"
     - เปิดใช้: "ทักลูกค้าจริงที่ตรงเงื่อนไข ลองกับแชททดสอบก่อนจะปลอดภัยกว่า" (นี่คือ "แนะนำในฟอร์ม" ของ BR-FB-80)
   - **หน้าสร้าง**: segmented ถูกล็อกที่ "ปิด" + บรรทัด "บอทใหม่เริ่มที่สถานะปิด บันทึกก่อนแล้วจึงเลือกทดสอบหรือเปิดใช้" (AC-FB-04)
   - **เมื่อฟอร์มมีการแก้ไขค้าง**: segmented ถูกล็อก + บรรทัดเหตุผล "กดบันทึกก่อน แล้วค่อยเปลี่ยนสถานะ" (API เปลี่ยนสถานะแยก endpoint และใช้ `expectedUpdatedAt` ร่วมกัน). เมื่อกด `บันทึก` ระบบ PATCH แล้ว PUT status ตามลำดับ
   - **เลือก "ทดสอบ"**: โชว์ช่อง "แชทสำหรับทดสอบ (เลือกได้ 1–20 แชท)" เป็น Select2 หลายค่า ค้นผ่าน `test-rooms?channelIds=..&q=` (react-select ฐานไม่มี async: ใช้ `onInputChange` + `filterOption={null}` โหลดตัวเลือกเอง) ค่าตัวเลือก = ชื่อผู้ติดต่อ + โลโก้ช่องทาง. ไม่ได้เลือกช่องทางก่อน = disabled + เหตุผล "เลือกช่องทางก่อน แล้วจึงเลือกแชททดสอบ"
   - **ปุ่ม "ลบบอท"** (เฉพาะหน้าแก้): มุมขวาหัวการ์ด `btn text-danger-ink` ไอคอน `trash` → ดูข้อ 2.4
2. **เงื่อนไข**
   - สถานะการขาย: Select2 หลายค่า 7 ตัวเลือกจาก `options.stages` placeholder "ทุกสถานะ"
   - แท็ก: Select2 หลายค่า จาก `options.tags` (≤20) + ลิงก์ `จัดการแท็ก` → `/settings/tags`
   - ตัวสลับ มีแท็กใดแท็กหนึ่ง/มีครบทุกแท็ก: segmented เล็ก โผล่เมื่อเลือก ≥2 แท็กเท่านั้น (1 แท็ก = ตัวสลับไม่มีความหมาย)
   - แท็กที่ถูกลบ (`missing:true`): ค้างในช่องเป็นชิป warning "vip (ถูกลบแล้ว)" + บรรทัดผลกระทบเหมือนในตาราง จนกว่าผู้ใช้เอาออก
   - **ประโยคสรุปเงื่อนไขสดใต้ช่อง** (คำนวณจากค่าที่เลือก): "ทักลูกค้าที่ยังไม่ซื้อ และติดแท็ก ถามราคา หรือ VIP" / ไม่เลือกทั้งสอง = ข้อความ error ของ `NO_CONDITION` (AC-FB-02). ประโยคนี้ทำให้ผู้ขายอ่านกฎของตัวเองเป็นภาษาคนก่อนกดบันทึก
3. **ช่องทาง** เป็นรายการ checkbox (ไม่ใช้ select เพราะมี ≤ไม่กี่ช่อง เห็นสถานะล็อกได้โดยไม่ต้องเปิด dropdown)
   - แถว: `form-checkbox` + `ChannelMark` + ชื่อช่อง
   - ช่องที่ชน (`findChannelConflicts` ตัวเดียวกับ server คำนวณสดตามสถานะการขายที่เลือก): checkbox disabled + ไอคอน `lock` + บรรทัด `text-xs` "บอท “{ชื่อบอท}” แล้ว" (ลิงก์ไปบอทนั้น) → AC-FB-20
   - ถ้าช่องที่ติ๊กไว้กลับกลายเป็นชน (ผู้ใช้เปลี่ยนสถานะภายหลัง): แถวขึ้นข้อความแดง "ชนกับบอท “{ชื่อ}” เอาช่องนี้ออก หรือเลือกสถานะการขายที่ไม่ซ้อนกัน"
   - ช่องที่ `status≠ACTIVE`: badge warning "การเชื่อมต่อหลุด" (เลือกได้ บอทจะพักส่งจนกลับมา)
   - เลือกช่อง LINE อย่างน้อย 1 ช่อง: บรรทัด info ใต้รายการ "ขั้นที่ส่งทาง LINE ใช้โควตาข้อความของร้าน ถ้าโควตาเต็มจะข้ามขั้นนั้น" (Q-8 ก)
4. **ข้อความที่จะส่ง** คือพระเอกของจอ (การ์ดใหญ่สุด เนื้อหาเยอะสุด)
   - ขั้นเรียงบน **รางเส้นประแนวตั้ง** (ท่า timeline ของ theme: วงกลมเลขขั้น + เส้นประเชื่อม) ขั้นไม่ใช่การ์ดซ้อนการ์ด แต่เป็นแถวคั่นด้วยรางเดียว
   - แถวเวลา: ขั้นแรก "รอ [ตัวเลข] [หน่วย] หลังร้านตอบลูกค้าครั้งล่าสุด" · ขั้นถัดไป "ถ้าลูกค้ายังไม่ตอบ รอต่ออีก [ตัวเลข] [หน่วย]" (AC-FB-18). ตัวเลขเป็น `.input-group` ที่กำหนดความกว้างที่ wrapper (`w-24`) เพราะ `.form-input` เป็น `width:100%` และไม่ได้ห่อ `@layer` (`paces-component-reference` §4). หน่วยเป็น Select2 ไม่ค้นหา (นาที/ชั่วโมง/วัน)
   - ข้างแถวเวลามีเวลาสะสม `text-xs text-default-700`: "นับรวมแล้ว ส่งหลังร้านตอบประมาณ 3 ชม. 30 นาที"
   - **ขั้นที่เวลาสะสม >23 ชม.** ขึ้น badge warning `ส่งได้เฉพาะลูกค้าที่ทักมาจากโฆษณา (Messenger/IG)` + บรรทัด "เกิน 24 ชม. แล้ว Messenger/IG ให้ส่งต่อได้เฉพาะลูกค้าที่มาจากโฆษณา คนอื่นจะไม่ได้รับข้อความนี้" (AC-FB-16) ธง `adOnly` คำนวณฝั่ง server แต่ฟอร์มคำนวณสดด้วยค่าเดียวกัน (`limits.adOnlyAfterMin=1380`)
   - ชนิดขั้น: segmented `ข้อความ` / `ข้อความ + รูป`
   - ตัวแก้ข้อความ: **ยก `TemplateEditor` ออกมาเป็นตัวแก้แบบชิปตัวแปร** เฉพาะส่วนเนื้อ (contenteditable + `paint`/`domToText`/`makeChip`/เมนู `{`/อีโมจิ/ตัวนับ) ตัดส่วนตัวอย่างข้อความตั้งต้น, ปุ่มคืนค่าตั้งต้น, การเรียก API ของ auto-notify ออก. ตัวแปรเดียวคือ `ชื่อ`. ตัวนับ `n/1000`
   - ขั้น "ข้อความ + รูป": พื้นที่รูปใต้ตัวแก้ ภาพย่อ + `เลือกรูป` / `เปลี่ยนรูป` / `เอารูปออก`. ลำดับที่ส่งจริง = ข้อความก่อน แล้วรูป (AC-FB-12). **แหล่งเลือกรูปไม่มี theme match ที่ตรง** → ดู Q7
   - ปุ่มเลื่อนขึ้น/ลง/ลบ: ปุ่มที่ใช้ไม่ได้ต้องมีเหตุผล (ขั้นแรกเลื่อนขึ้นไม่ได้ ขั้นสุดท้ายเลื่อนลงไม่ได้ ขั้นเดียวลบไม่ได้) → `disabled` + `title` และ `aria-describedby` ชี้บรรทัดเหตุผลที่ซ่อนจากตาแต่อ่านได้ด้วย screen reader. บนมือถือ (ไม่มี hover) ให้เหตุผลปรากฏเป็นบรรทัดเล็กใต้หัวขั้น เมื่อกดปุ่ม disabled
   - ปุ่ม `เพิ่มขั้น`: ล็อกเมื่อครบ 10 ขั้นหรือเวลาสะสมเต็ม พร้อมบรรทัดเหตุผลใต้ปุ่มเสมอ (AC-FB-17): "ครบ 10 ขั้นแล้ว" / "เวลาสะสมถึง 6 วัน 23 ชม. แล้ว ลดเวลารอของขั้นก่อนหน้าเพื่อเพิ่มขั้นใหม่"
   - บรรทัดสรุปท้ายการ์ด: "รวม {N} ขั้น · ภายใน {ระยะรวม}" และ `card-footer` 1 บรรทัด "บอทจะหยุดทักเองเมื่อลูกค้าตอบ สถานะการขายเปลี่ยน (เช่น เปิดบิลแล้ว) แท็กถูกเอาออก หรือเกินเวลาที่ส่งได้" (แทน (i) tooltip ของ gochat ที่เปิดไม่ได้บนมือถือ)
5. **ตัวอย่างในแชท** (การ์ดขวา sticky `lg:sticky lg:top-20`; มือถือ/แท็บเล็ต = การ์ดท้ายสุด)
   - **ไม่ใส่ข้อความลูกค้าสมมติ** แสดงเฉพาะสิ่งที่ระบบส่งจริง: ตัวคั่นเวลา ("รอ 30 นาทีหลังร้านตอบ" / "ถ้าลูกค้ายังไม่ตอบ รอต่ออีก 3 ชม.") → บับเบิลฝั่งร้านคลาสเดียวกับของจริง (`rounded px-6 py-3 bg-primary text-white` จาก `ThreadMessageList.tsx:827`) + ป้ายเกยขอบ "บอทติดตาม" แบบเดียวกับในแชทจริง (ดู §4)
   - `{ชื่อ}` แสดงเป็น "สมชาย" ตัวอย่าง · "ข้อความ + รูป" = บับเบิลข้อความ ตามด้วยบับเบิลรูป (AC-FB-12/14)
   - ขั้น `adOnly` มีป้ายเล็กใต้ตัวคั่น "เฉพาะลูกค้าจากโฆษณา"
   - ขั้นที่ยังไม่มีข้อความ: บับเบิลเทาจาง "ข้อความขั้นที่ {n} จะแสดงที่นี่" (ตัวอย่างไม่ว่างเปล่าตั้งแต่เปิดฟอร์ม เพราะแสดงโครงเวลาของทุกขั้นอยู่แล้ว)

### 2.3 Savebar และการตรวจ
- savebar: ซ้าย ข้อความ `มีการแก้ไขที่ยังไม่บันทึก` (โผล่เมื่อ dirty) · ขวา `ยกเลิก` (ขอบเทา) + `บันทึก` (primary ปุ่มเดียวของหน้า) ขณะบันทึก "กำลังบันทึก…" disabled
- `beforeunload` เมื่อ dirty (ท่า `AutoNotifyClient`). `ยกเลิก` ตอน dirty = `pacesConfirm.warning` (ท่าเดิม `discardConfirm*`)
- error ของ server (`issues[]`) ผูกกับช่องที่เกี่ยวข้องและขั้นนั้น ๆ (`stepIndex`) + เลื่อนไปช่องแรกที่ผิด + `pacesToast.error` "บันทึกไม่ได้ ตรวจช่องที่ขึ้นสีแดง". ข้อความต้องมี `role="alert"`

## 6. User flow
1. เมนู `ตั้งค่า > บอทติดตามยอดขาย` → เห็นตาราง (หรือ empty) → `สร้างบอทติดตาม`
2. กรอกชื่อ → เลือกสถานะการขาย/แท็ก → ติ๊กช่องทาง (ช่องล็อกบอกเหตุ) → เพิ่มขั้น พิมพ์ข้อความ + แทรกชิป `ชื่อ` → ดูตัวอย่างข้างขวา → `บันทึก` (สถานะ "ปิด")
3. กลับเข้าบอทเดิม → เลือก "ทดสอบ" + แชททดสอบ → `บันทึก` → ตรวจในแชทของแชททดสอบ (แผง + ชิป)
4. เลือก "เปิดใช้" → Swal ยืนยัน → `บันทึก` → ตารางแสดง "เปิดใช้" + "ตามอยู่ N ห้อง"
5. ในห้องแชท: ชิป "บอทกำลังตาม" → แผงแสดงขั้น → ลูกค้าตอบ = แถว/ชิปหายทันที แล้วบรรทัดระบบ "…หยุด: ลูกค้าตอบแล้ว" ขึ้นกลางห้อง
6. กด `หยุดบอท` → Swal → แถวหาย → toast
7. แท็บ `ประวัติการส่ง` ดูผลและเหตุผลของทุกขั้น

## 9. ### Impeccable compliance

- **Mode: Operate** — คอนโซลผู้ขายที่ผู้ใช้อยู่ระหว่างงาน เกณฑ์คือ scanability, ความสม่ำเสมอกับพี่น้อง และ native expectation ไม่ใช่การแสดงออก. register ของโปรเจกต์เป็น brand แต่ตาม `PRODUCT.md` ถูก override เป็น product สำหรับ `(paces)`
- **North star "Trusted Counter"**: เน้นให้ผู้ขายเห็นและควบคุมสิ่งที่ระบบพูดแทนร้าน (ตัวอย่างในแชท, ประโยคสรุปเงื่อนไข, เหตุผลทุกครั้งที่ข้าม/หยุด) น้ำเสียงอบอุ่นเป็นกันเอง ไม่ใช้ราชการ ไม่ไฮป์
- **One Voice**: primary น้ำเงินโผล่เฉพาะปุ่มหลักหน้าละ 1 ปุ่ม, ป้าย "เปิดใช้", ชิปแท็ก, ขั้นถัดไปในแผง, ลิงก์ในประโยค — ไม่มีม่วง `#7367F0` ไม่มี hex/rgba
- **Verified-Means-Green**: เขียว (`success-ink`) ใช้เพียง "ส่งแล้ว" ซึ่งเป็นผลสำเร็จจริง · "เปิดใช้" "ทดสอบ" "ตามอยู่" "รอส่ง" "รอคุณตอบ" ไม่ใช้เขียน ใช้ primary/info/warning ตามตาราง §0.2
- **Sentence case/ไทย**: ไม่มี uppercase · ปุ่มเป็น กริยา+กรรม ("สร้างบอทติดตาม" "หยุดบอท" "ลบบอท")
- **เงา**: ใช้ `shadow` ของ `.card`/Paces เท่านั้น ไม่มีดำสนิท
- **Anti-slop**: ไม่มี gradient/hero metric/eyebrow/การ์ดซ้อนการ์ด (ขั้นเป็นแถวบนรางเดียว) · ขอบ 1px เท่านั้น · `border-s-3` ไม่ได้ใช้
- **น้ำเสียงข้อความ**: ทุก error มีทางออก (ตาราง Validation) · ไม่มี "ไม่สามารถ…ได้"/"คุณไม่มีสิทธิ์" · พูดถึงลูกค้าเป็นกลาง ("ลูกค้าบล็อกหรือเลิกติดตามช่องทางนี้") ไม่กล่าวหา
- **อะไรคือพระเอกของหน้า**: จอรายการ = ชื่อบอท + ป้ายสถานะ · ฟอร์ม = การ์ด "ข้อความที่จะส่ง" + ตัวอย่างข้างขวา · แผงห้อง = ขั้นถัดไป / กล่อง "รอคุณตอบลูกค้า"

## 12. Open questions (ให้ผู้ใช้/Controller ตัดสิน)

- **Q1 ไอคอนบอทติดตาม (HR12 ห้ามเดา)** ใช้ทั้งเมนู, ชิป, ป้ายบับเบิล, ตัวคั่นตัวอย่าง, บรรทัดระบบ, หน้าเร็ว ๆ นี้. `robot` ถูก DeepBot/ผู้ช่วยอัตโนมัติใช้แล้ว, `send`=00078, `clock-play`=00066. ข้อเสนอ: `message-forward` (ส่งข้อความตามไป) ตัวสำรอง `hourglass-high`, `target-arrow` ผมยังไม่ได้ยืนยันว่าชื่อเหล่านี้มีใน tabler ของโปรเจกต์ (ใช้ผ่าน `@iconify/react` ตอน build ให้ตรวจก่อน) — ขอผู้ใช้เลือก
- **Q2 ยืนยันก่อน "หยุดบอท"** ผมเสนอให้มี Swal เพราะย้อนกลับไม่ได้ในรอบเดิม AC-FB-88 เขียนแค่ "กดแล้วหายทันที" ไม่ขัดถ้าให้ยืนยันก่อน ถ้าอยากให้ไวแบบ gochat ตัด Swal ออกได้โดยไม่กระทบส่วนอื่น
- **Q3 แผงตอนไม่มี run** เสนอ "ไม่แสดงอะไร" (ตาม AC-FB-74/85) ทางเลือก: แสดงบรรทัดจาง "ห้องนี้ไม่มีบอทติดตาม" เมื่อมีบอทที่ครอบห้องนี้ได้ — ยังไม่เสนอเพราะต้องมี endpoint เพิ่ม
- **Q4 ชิป "รอคุณตอบก่อน" (warning)** เป็นส่วนเสริมนอก AC-FB-90 ใช้ข้อมูล `awaitingShop` ที่ API มีอยู่แล้ว ไม่เพิ่ม endpoint ถ้าไม่เอา ใช้ชิป info ตลอด
- **Q5 ตำแหน่งแผง** แท็บ "ข้อมูลลูกค้า" ต่อจาก CRM (เสนอ) หรือแท็บ "ติดตาม" ของ 00066 (ชนความหมายกับ "ติดตามลูกค้า") — ขอยืนยัน
- **Q6 ความขัดในเอกสาร**
  - BRD §1.3 ยังเขียนว่า CHAT "ไม่สร้าง/แก้/ลบบอท" แต่ §0 Q-11 (ข) และ AC-FB-93 ให้ทุกคนที่ตอบแชทแก้ได้
  - AC-FB-82 (หน้าอ่านอย่างเดียว) และ AC-FB-89 (ห้องล็อกให้คนอื่น) ไม่มีแนวคิดรองรับในโค้ด (SRS TFR-FB-19/20 ยอมรับ และฉันค้น schema ไม่พบ lock ของห้อง) → ผมออกแบบให้ `หยุดบอท` ถูกล็อกเฉพาะ `canStop=false` กับขณะรอผล
  - ขอให้ product แก้ BRD ให้ตรง (HR11)
- **Q7 ตัวเลือกรูปของขั้น "ข้อความ + รูป"** ไม่พบ theme match ที่เหมาะ (ไม่มี image-picker แบบคลัง). closest = `form/fileuploads/Dropzone.tsx` + ท่าอัปโหลดใน `QuickMessageManager.tsx` (ต้อง Explore ว่าเก็บ `imageFileId` แบบเดียวกันไหม) และ `@/lib/upload-client` (ห้ามส่งไฟล์ผ่าน body) — ขอ Controller ตัดสินก่อนเริ่มสร้าง
- **Q8 หน้า "เร็ว ๆ นี้"** ยืนยันใช้ card + empty state (ไม่ใช้ theme coming-soon)
- **Q9 ข้อความเหตุผลทั้งชุด** (§4.3, §7) เป็นข้อเสนอจาก ux ต้องให้ product ยืนยันก่อนเข้าตารางเหตุผลฝั่ง server (SSOT) โดยเฉพาะ "รอผลนานเกินไป ระบบจึงไม่ส่งซ้ำ กันลูกค้าได้ข้อความสองรอบ" และ "ร้านกดหยุดในห้องนี้" (ไม่ระบุตัวบุคคล)

- **Q11 `ICON` กับ `SENDING` ค้าง >10 นาที** (AC-FB-62 "ไม่แน่ใจว่าส่งถึง") ผมแสดงเป็น warning ไม่ใช่ danger เพราะยังไม่ยืนยันว่าล้ม — ขอ product ยืนยันนิยาม

## 19. รอบละหลายชิ้น + quick message (ผู้ใช้ 2026-11-16)

- ศัพท์: หน่วยที่บอทส่งตามเวลา = **"รอบ"** (รอบที่ 1, 2, 3 · ตาราง "3 รอบ · ภายใน …" · ชิปกล่องแชท "บอทตาม 1/3" = รอบ) · ภายในรอบมี "ข้อความ" และ "รูป" หลายชิ้น
- การ์ดรอบ: รายการชิ้นเรียงตั้ง ลากหรือเลื่อนขึ้น/ลงได้ · ท้ายรายการมีปุ่ม 3 ตัว `+ ข้อความ` `+ รูป` `+ quick message` · ครบ 5 ชิ้นปุ่มล็อกพร้อมเหตุผล
- ชิ้นรูป = แถวรูปย่อ 1–5 รูป + ปุ่มเพิ่มรูป · ชิ้น quick message = การ์ดอ่านอย่างเดียวแสดงชื่อ + ข้อความย่อ + รูปย่อ + ปุ่ม "เปลี่ยน" (เปิดตัวเลือก quick message ของร้านแบบเดียวกับในช่องพิมพ์แชท) · quick message ถูกลบ = การ์ดเตือน "quick message นี้ถูกลบแล้ว รอบนี้จะข้ามชิ้นนี้"
- ตัวอย่างในแชทแสดงทุกฟองของรอบตามลำดับ ป้าย "บอทติดตาม n/N" ที่ฟองแรกของรอบ
