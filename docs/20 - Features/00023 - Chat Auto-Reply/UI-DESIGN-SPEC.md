# UI Design Spec — ตอบแชทอัตโนมัติ

## 0. หมายเหตุกระบวนการ (ต้องอ่านก่อน)

🛑 **เอกสารนี้ Controller เขียนเอง ไม่ได้ผ่าน `safepay-ux` ตามที่ Hard Rule 8 กำหนด**

เหตุผล: การ spawn subagent ใน session นี้พังตั้งแต่ S-05 (`tmux: terminal_handle_stale`) ลองซ้ำหลายรอบไม่สำเร็จ — user รับทราบข้อจำกัดและสั่งให้เดินต่อ (2026-07-29)

สิ่งที่ทำเพื่อรักษา *เจตนา* ของกฎไว้แม้ทำตามตัวอักษรไม่ได้:
- ยังคงขั้นตอน "ออกแบบก่อนเขียนโค้ด" ไว้ครบ (เอกสารนี้เกิดก่อนโค้ดทุกบรรทัด)
- ยึด `UI-REFERENCE.md` ที่ user freeze คำตัดสินไว้แล้ว 3 ข้อ
- ยึด Paces primitive + Base-file mapping จริง (ไม่ประดิษฐ์ layout เอง)

**หนี้ที่ต้องเก็บ:** ให้ `safepay-ux` review เอกสารนี้ย้อนหลังเมื่อ subagent ใช้งานได้ แล้วบันทึกส่วนต่างใน Gate 2

## 3. หน้า 1 — รายการกลุ่มคำ (`/settings/auto-reply`)

```
┌──────────────────────────────────────────────────────────────┐
│ ตั้งค่า > ตอบแชทอัตโนมัติ                    (breadcrumb)    │
├──────────────────────────────────────────────────────────────┤
│ ⚠ แถบเตือนโหมดทดสอบ (แสดงเฉพาะเมื่อเปิดอยู่ — AC-021-07)     │
│   "อยู่ในโหมดทดสอบ ตอบเฉพาะ 2 เธรดที่เลือก                   │
│    ลูกค้าคนอื่นจะไม่ได้รับคำตอบ"   [ปิดโหมดทดสอบ]           │
├──────────────────────────────────────────────────────────────┤
│ card                                                          │
│  card-header: [ไอคอน] ตอบแชทอัตโนมัติ        [○ เปิดใช้งาน]  │
│  card-body:                                                   │
│   คำอธิบายสั้น 1 บรรทัด                                       │
│   ┌────────────────────────────────────────────────────────┐ │
│   │ [ค้นหา...]        [ทั้งหมด ▾]         [+ สร้างกลุ่มคำ] │ │
│   ├────────────────────────────────────────────────────────┤ │
│   │ ☐ ชื่อกลุ่ม      คำ   กฎ   รูปแบบ   สถานะ   แก้ล่าสุด  │ │
│   │ ☐ สนใจสินค้า      7    3   มีคำใน..  ● เปิด  1 ชม.  ⋮ │ │
│   │ ☐ ถามราคา         4    1   ตรงทั้ง..  ● เปิด  2 วัน  ⋮ │ │
│   │ ☐ เก็บปลายทาง     3    2   มีคำใน..  ○ ปิด   5 วัน  ⋮ │ │
│   └────────────────────────────────────────────────────────┘ │
│   [เลือก 2 รายการ]  [เปิดใช้งาน] [ปิด]      (แถบ bulk)      │
└──────────────────────────────────────────────────────────────┘
```

**mobile (<768):** ตารางกลายเป็น card list ต่อกลุ่มคำ — ชื่อเป็นหัว, คำ/กฎเป็น meta บรรทัดล่าง, สถานะเป็น badge, action เป็น `⋮`

**พฤติกรรม**
- สวิตช์ระดับร้าน = `PATCH /config` — ปิดแล้วแถวยังแก้ได้ (ตั้งค่าล่วงหน้าได้) แต่มี hint ว่า "ปิดอยู่ จะยังไม่ตอบลูกค้า"
- `⋮` → แก้ไข / ทำสำเนา / ลบ (ลบต้องยืนยันด้วย Sweet Alert)
- **empty state:** ยังไม่มีกลุ่มคำ → อธิบายว่าระบบจะยังไม่ตอบอะไรเลย + ปุ่มสร้างกลุ่มแรก **ห้ามใช้ emoji** ใช้ไอคอน `tabler-message-2-search`
- STAFF: ทุกปุ่มเขียนหาย เหลืออ่านอย่างเดียว (`canEdit` จาก API)

## 4. หน้า 2 — แก้กลุ่มคำ (`/settings/auto-reply/[id]`)

```
┌─────────────────────────────────┬────────────────────────────┐
│ ซ้าย (แก้ไข)                    │ ขวา (ทดสอบ — sticky)       │
│ ┌─────────────────────────────┐ │ ┌────────────────────────┐ │
│ │ ทั่วไป                      │ │ │ ทดสอบกฎ                │ │
│ │  ชื่อกลุ่ม [_____________]  │ │ │ [ข้อความลูกค้า______]  │ │
│ │  รูปแบบ  [มีคำในประโยค ▾]  │ │ │ เพจ    [ทั้งหมด ▾]     │ │
│ │  ลำดับ   [100]  [○ เปิด]   │ │ │ โฆษณา  [ไม่ระบุ ▾]     │ │
│ ├─────────────────────────────┤ │ │ สินค้า [ไม่ระบุ ▾]     │ │
│ │ คำตรวจจับ (7)               │ │ │          [ทดสอบ]       │ │
│ │  [สนใจ ×][สนใจครับ ×]...    │ │ ├────────────────────────┤ │
│ │  [+ เพิ่มคำ_______]         │ │ │ ผลลัพธ์:               │ │
│ ├─────────────────────────────┤ │ │  ┌──────────────────┐  │ │
│ │ คำตอบกลาง                   │ │ │  │ บับเบิลข้อความ   │  │ │
│ │  [textarea______] 115/1000  │ │ │  │ ที่ลูกค้าจะได้รับ │  │ │
│ ├─────────────────────────────┤ │ │  └──────────────────┘  │ │
│ │ แยกตามเพจ (2)          [+]  │ │ │ ─────────────────────  │ │
│ ├─────────────────────────────┤ │ │ จับได้: "สนใจ"         │ │
│ │ แยกตามโฆษณา (3)        [+]  │ │ │ ใช้กฎ: Keyword+เพจ+โฆษณา│ │
│ ├─────────────────────────────┤ │ │ กฎอื่นที่ไม่ถูกเลือก:  │ │
│ │ แยกตามสินค้า (0)       [+]  │ │ │  · ถามราคา (ลำดับต่ำกว่า)│ │
│ └─────────────────────────────┘ │ └────────────────────────┘ │
└─────────────────────────────────┴────────────────────────────┘
```

**mobile:** แผงทดสอบย้ายลงล่างสุด (ไม่ sticky) — ยังต้องเข้าถึงได้ ไม่ตัดทิ้ง

**พฤติกรรมสำคัญ**
- แผงทดสอบเรียก `POST /simulate` — **ไม่เขียนอะไร ไม่ส่งข้อความ** ต้องมีข้อความกำกับให้ผู้ใช้มั่นใจ
- ส่วน "กฎอื่นที่ไม่ถูกเลือก" มาจาก `matchTrace` + `fallbackFrom` — **นี่คือส่วนที่ AC-020-04 บังคับ** และเป็นสิ่งที่ reference ของ Facebook ไม่มี
- ถ้า `willHandoff = true` ต้องบอกชัดว่า "ระบบจะไม่ตอบและส่งต่อพนักงาน" ไม่ใช่แสดงบับเบิลว่าง
- ตัวนับอักษรในช่องคำตอบ (AC-005-04)
- เลือกโฆษณาจาก `GET /ads` (โฆษณาที่เคยมีคนทักจริง) — ไม่ต้องให้ร้านคัดลอกรหัสเอง (AC-007-05)

## 5. S-14 — UI ในหน้าแชทเดิม

| จุด | รายละเอียด |
|---|---|
| **ป้ายบนบับเบิล** | ข้อความที่ `autoReplyKind = 'AUTO'` → chip เล็ก "ระบบตอบ"; `'AUTO_TEST'` → chip "ทดสอบ" สีต่างกัน (AC-012-02, AC-021-05) ใช้ badge ของ Paces ไม่ใช่ emoji |
| **แถบสถานะเมื่อถูกหยุด** | เหนือช่องพิมพ์: "หยุดตอบอัตโนมัติจนถึง 14:30" + ปุ่ม "เปิดกลับ" → `PATCH /conversations/{id}/auto-reply` `{clearPause:true}` (AC-016-03/04) |
| **สวิตช์รายเธรด** | ในแผงข้อมูลลูกค้าด้านขวา — `autoReplyEnabled` (null=ตามร้าน / true / false) |

## 6. Impeccable compliance

- **Verified-Means-Green:** สถานะ "เปิดใช้งาน" ใช้เขียว `#28C76F` ไม่ใช่น้ำเงิน — สอดคล้องกับที่ระบบใช้เขียวแทน "ยืนยันแล้ว/ทำงานอยู่" ทั้งแพลตฟอร์ม
- **One Voice:** สีหลักของหน้าคือ Paces น้ำเงิน; ม่วง Vuexy ห้ามโผล่เด็ดขาด
- **น้ำเสียง:** ข้อความอธิบายต้องบอก *ผลที่จะเกิดกับลูกค้า* ไม่ใช่ศัพท์ระบบ — เช่น "ลูกค้าจะได้รับข้อความนี้ทันทีที่ทักมา" ไม่ใช่ "trigger reply on inbound"
- **แถบโหมดทดสอบ** เป็น warning ไม่ใช่ error (ระบบไม่ได้พัง แค่จำกัดขอบเขต) — และต้องค้างตลอดไม่ใช่ toast ที่หายไป
- **ลำดับชั้น:** สวิตช์ระดับร้านอยู่บนสุดเสมอ เพราะเป็นสิ่งที่ตอบคำถามแรกของผู้ใช้ ("ตอนนี้ระบบทำงานอยู่ไหม")
