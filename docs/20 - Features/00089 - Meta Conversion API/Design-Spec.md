### Section breakdown
- **หัวหน้า:** `PageBreadcrumb` + บรรทัดอธิบายหนึ่งย่อหน้า (`text-default-700 text-sm`) ตามท่า sibling ใน `tags/page.tsx` ประโยคที่สองเป็นข้อเท็จจริงเรื่องความเป็นส่วนตัว (ส่งแค่รหัสเพจ+PSID) ซึ่งตรงกับ PRODUCT.md ที่ว่า trust ต้องแสดงด้วยข้อเท็จจริง
- **การ์ดตาราง:** เฉพาะ `ShopChannel` ที่ provider=`MESSENGER` และ status≠`DISCONNECTED` (IG/LINE ไม่ขึ้น)
  - **ชื่อเพจ:** avatar (`BuyerAvatar`) + ชื่อ `truncate` + `title=` (เพจร้านเดียวกันต่างกันที่ท้ายชื่อ ตามบทเรียนใน `ChannelsClient`) + บรรทัดรอง "Messenger" `text-xs text-default-700`
  - **สถานะ:** badge soft 3 แบบ + ข้อความรองใต้ badge เฉพาะกรณีพิเศษ (ดู Content outline)
  - **ส่งสำเร็จ 7 วัน:** ตัวเลขชิดขวา `tabular-nums` · ไม่เคยส่งหรือเพจปิดและไม่มีข้อมูล = "–" (ไม่ใช่ 0) · 0 จริง = "0"
  - **Purchase ส่งเมื่อ:** ข้อความล้วน (สร้างคำสั่งซื้อ / ยืนยัน / ชำระครบ) ถ้าไม่มี dataset ไหนเปิด Purchase = "ไม่ได้เปิด"
  - **สวิตช์:** `form-switch` ผูก PUT ของเพจ · เพจที่ยังไม่มี dataset → สวิตช์ `disabled` + `title` อธิบาย และปุ่มทางเข้าเด่นขึ้นแทน
  - **แถวกดได้ทั้งแถว** (`onRowClick` ของ `DataTable`) ไปหน้า detail · สวิตช์และปุ่มในแถว `stopPropagation`
- **แถวที่ token เสีย:** ปุ่ม `btn-sm bg-primary/15 text-primary` "เชื่อมเพจใหม่" เป็น `<a href="/api/channels/facebook/connect">` (endpoint นี้ตอบ 302 ต้องเป็น anchor ธรรมดา ตามบทเรียนใน `ChannelsClient`)
- **ตัวเด่นของหน้า:** คอลัมน์สถานะ+สวิตช์ ไม่มีการ์ดตัวเลขใหญ่ แถวที่หยุดมีแค่ badge แดงกับปุ่มแก้ ซึ่งเป็นสองสิ่งเดียวที่สีแรงในหน้า

### User flow
1. เข้า `/settings/conversions-api` → เห็นเพจพร้อมสถานะ
2. กดสวิตช์ของเพจที่เคยเปิดมาแล้ว → optimistic + toast "ปิดการส่งของเพจ {ชื่อ} แล้ว"
3. กดสวิตช์เปิดครั้งแรก → Swal ถามก่อน → ยืนยันแล้ว PUT → toast
4. กดแถว → `/settings/conversions-api/[channelId]`
5. เพจ token เสีย → กด "เชื่อมเพจใหม่" → OAuth → กลับมาที่ `/settings/channels?status=connected`

- Empty (ไม่มีเพจ Messenger): icon `brand-messenger` · `ยังไม่มีเพจ Messenger ที่เชื่อมไว้` · `เชื่อมเพจ Facebook ก่อน แล้วกลับมาเปิดการส่งยอดที่นี่` · ปุ่ม `เชื่อมเพจ Facebook` → `/settings/channels`

### Edge states
- **Empty:** ข้างบน · **Loading:** skeleton ตาม `tags/loading.tsx` · **Error:** `SellerErrorState` (`ลองใหม่`)
- **No-permission:** `NoPermissionCard` · **ฟีเจอร์ปิด/นอกรายชื่อทดลอง:** `notFound()` (ไม่ใช่การ์ดไม่มีสิทธิ์ เพราะร้านต้องไม่รู้ว่าฟีเจอร์มีอยู่ — FR-001)
- **ชื่อเพจยาว/ซ้ำท้าย:** `truncate` + `title` · **ตัวเลขล้าน:** `1,248,305` ไม่ตัดบรรทัด `whitespace-nowrap`
- **เพจ `TOKEN_INVALID` ที่ระดับ ShopChannel** (ไม่ใช่เฉพาะ dataset) → แสดง "หยุดเพราะ token เสีย" เหมือนกัน
- **สวิตช์ PUT ล้ม:** revert + toast error (ไม่ทิ้งสวิตช์ไว้ผิดตำแหน่ง)

### Section breakdown

**A. Header strip** — การ์ดใบเดียว (ไม่ซ้อนการ์ด)
- ซ้าย: avatar + ชื่อเพจ (`text-base font-semibold`) + บรรทัดรอง "Messenger · {badge สถานะ}"
- ขวา: ป้าย `ส่งเหตุการณ์ของเพจนี้` + `form-switch` (สวิตช์หลัก) · **นี่คือพระเอกของหน้า** ใหญ่กว่าสวิตช์อื่นเพราะอยู่ในแถวของตัวเอง ไม่ปะปนรายการ
- สวิตช์หลักปิดอยู่ → แสดงบรรทัดข้อมูลใต้ header (neutral `bg-default-100`): `เพจนี้ปิดการส่งอยู่ ตั้งค่าไว้ล่วงหน้าได้ แต่จะยังไม่ส่งอะไรจนกว่าจะเปิด`
- สวิตช์ยังอยู่ตำแหน่ง "เปิด" เมื่อ token เสีย (ร้านเปิดไว้) แต่ badge บอกว่า "หยุดเพราะ token เสีย" ผู้ใช้จึงไม่เข้าใจผิดว่ากำลังส่ง

**B. Banner token เสีย** — แสดงเมื่อมี dataset ≥1 ตัวหยุดเท่านั้น
- ใช้ markup ของ banner ใน `AutoNotifyClient` (`rounded-lg p-3 text-sm`, icon `alert-triangle`) แต่สี `bg-danger/15 text-danger-ink` (ไม่ใช้ `text-danger` เปล่า — ตกคอนทราสต์)
- บอก 3 อย่าง: อะไรเกิด · อะไรจะเกิดกับของที่ค้าง · ต้องทำอะไร
- ปุ่ม `เชื่อมเพจใหม่` (anchor เหมือนหน้า 1) เฉพาะกรณีมี dataset แบบ "อัตโนมัติจากเพจ" หยุด ถ้าเป็นแบบ "กรอกเอง" ข้อความชี้ไปที่ปุ่ม `เปลี่ยน token` ในแถว dataset นั้น (ไม่มีปุ่มซ้ำ)
- ตัวนับเหตุการณ์ค้างไม่แสดงในนี้ (อยู่ในการ์ดผลการส่งแล้ว กันข้อมูลซ้ำ)

**C. ชุดข้อมูล (Dataset)** — `ul divide-y` ไม่ใช่การ์ดซ้อน (ปฏิบัติตาม DESIGN.md "ห้ามซ้อนการ์ดในการ์ด")
- แถว dataset: ชื่อเรียก (`text-sm font-medium`) + badge แหล่งที่มา (neutral: `อัตโนมัติจากเพจ` / `กรอกเอง`) + ปุ่มลบ (`btn-icon` icon `trash`, `aria-label="ลบชุดข้อมูล {ชื่อ}"`, 44px บนมือถือ)
- บรรทัด ID: `Dataset ID {id}` (`tabular-nums`, **ไม่ใช้ `font-mono`** เพราะกฎ No-Mono-On-Thai) · ต่อด้วยสถานะ token แบบข้อเท็จจริง: อัตโนมัติ = `ใช้ token ของเพจ` · กรอกเอง = `token ตั้งไว้แล้ว` + ปุ่ม text `เปลี่ยน token` (ไม่แสดงค่า token เลยทุกกรณี) ไอคอน `lock` ขนาดเล็กหน้า token — ใช้สี neutral ไม่ใช้เขียว เพราะ "ตั้งไว้แล้ว" ไม่ใช่ "Meta ยืนยันแล้ว"
- Dataset ที่หยุด: badge `bg-danger/15 text-danger-ink` "หยุดส่ง" ต่อท้ายชื่อ + ปุ่มแก้ในแถว
- **Test Event Code + ทดสอบ:** `input-group` (theme `InputGroup.tsx`) `form-input` + ปุ่ม `btn border-default-300` "ทดสอบ" · ข้อความช่วยใต้ช่องเปลี่ยนตามค่า (ว่าง = ตรวจ token อย่างเดียว · มีรหัส = ส่ง Purchase ฿1)
- **ผลทดสอบ:** กล่องผลแบบ inline ใต้แถว `role="status" aria-live="polite"` ไม่ใช้ modal ไม่ใช้ toast (ต้องอยู่ให้อ่านจนกว่าผู้ใช้จะลองใหม่)
- **เพิ่มชุดข้อมูล:** ปุ่ม `btn bg-primary` ที่หัวการ์ด เปิดแผง inline (กล่องใน `rounded-lg bg-default-100 p-3` ตามท่า callout 12/10px ใน DESIGN.md) มี radio 2 ตัวเลือก (`form-radio` fieldset ท่าเดียวกับ `trackingTiming` ใน `AutoNotifyRow`)
  - **ใช้ชุดข้อมูลของเพจ:** ไม่มีช่องกรอก ปุ่ม `ใช้ชุดข้อมูลของเพจ` กดแล้วมี spinner บนปุ่ม
  - **กรอกชุดข้อมูลของฉันเอง:** ช่อง `ชื่อเรียก` (ไม่บังคับ) · `Dataset ID` (`inputmode="numeric"`) · `Access token` (`type="password"` `autocomplete="off"`) · ปุ่ม `ตรวจและบันทึก` + `ยกเลิก`
  - ครบ 3 ชุด: ปุ่มเพิ่ม `disabled` + ข้อความ `ครบ 3 ชุดแล้ว ลบชุดเดิมก่อนถึงจะเพิ่มได้` (ไม่ซ่อนปุ่ม เพราะผู้ใช้ต้องรู้ว่าทำไมกดไม่ได้)
- **ลบ:** `pacesConfirm.danger` (Swal) ชื่อ dataset ในหัวข้อ · ชุดอื่นไม่เปลี่ยนอะไร (BR คีย์กันซ้ำคงเดิม) บอกในข้อความ

**D. เหตุการณ์ที่ส่ง** — 12 แถว แบ่งกลุ่มตามลำดับของการขาย (กลุ่มเป็นหัวข้อประโยคปกติ ไม่ใช่ eyebrow ตัวพิมพ์ใหญ่)
- ถ้ามี dataset >1 → `nav-tabs` ในหัวการ์ดเลือก dataset (state ใน React ไม่ใช้ Preline `hs-tab` เพราะ state หายเมื่อ re-render เช่นเดียวกับ `hs-dropdown`) · มี 1 ชุด → ไม่มีแท็บ แสดงชื่อชุดเป็นข้อความรองในหัว
- **กลุ่ม + ลำดับ:**
  1. *ก่อนซื้อ:* ดูสินค้า (ViewContent) · สนใจ (LeadSubmitted) · สนใจจริง (QualifiedLead) · ทิ้งตะกร้า (CartAbandoned)
  2. *ซื้อและชำระ:* **ซื้อ (Purchase)** · สร้างคำสั่งซื้อ (OrderCreated) · ส่งลิงก์คำสั่งซื้อ (InitiateCheckout) · แนบสลิป (AddPaymentInfo)
  3. *หลังซื้อ:* จัดส่งแล้ว (OrderShipped) · ส่งถึงลูกค้า (OrderDelivered) · ยกเลิกคำสั่งซื้อ (OrderCanceled) · รับของคืน (OrderReturned)
  - **Purchase เด่นที่สุดในรายการ:** ชื่อ `font-semibold` (ตัวอื่น `font-medium`) + แถวบอกจังหวะปัจจุบันเป็นข้อความ `ส่งเมื่อชำระครบ` + ลิงก์ `เปลี่ยน` เลื่อนไปการ์ดจังหวะ Purchase — เป็นการอ่านค่า ไม่ใช่ตัวควบคุมซ้ำ ไม่ใช้สีเพิ่ม
- **โครงแถว (ใช้ `AutoNotifyRow` เป็นต้นแบบ):** ซ้าย = ชื่อไทย + ชื่อ Meta ในวงเล็บ `text-xs text-default-700` + บรรทัดคำอธิบายว่าส่งเมื่อไร (`text-xs text-default-700`) · ขวา = สวิตช์ · ใต้ชื่อมี summary ยอด (`ยอดสุทธิ · แนบสินค้า`) + ปุ่ม `btn-sm` "ตั้งยอด" เฉพาะเหตุการณ์ที่มียอด
- **ตัวตั้งค่ายอด (inline ขยายใต้แถว, ทีละแถว):** radio `ยอดสุทธิ` (default) / `ไม่รวม VAT` + สวิตช์ `แนบรายการสินค้า` · บันทึกอัตโนมัติทุกครั้งที่เปลี่ยน (optimistic + toast) · ปุ่ม `เสร็จ` ปิดแผงและคืนโฟกัสให้ปุ่ม `ตั้งยอด` (ท่า `closeEditor` ของ `AutoNotifyClient`) · เมื่อมี dataset >1 แสดงบรรทัด `ตั้งค่านี้ใช้กับทุกชุดข้อมูลของเพจ` (ถ้ามีชุดเดียวไม่แสดง เพราะไม่ให้ข้อมูล)
  - **ไม่มีตัวเลือก "ไม่รวมค่าส่ง"** (PRD Q5)
  - InitiateCheckout = ไม่มียอด ไม่มีปุ่มตั้งยอด · Lead/QualifiedLead = ยอดมาจากกฎแท็ก (แถวเขียน `ยอดตามกฎแท็กด้านล่าง ({n} กฎ)`) · ViewContent = `ส่งราคาสินค้าตามการ์ด` ไม่มี option (Open Q4)
  - Lead/QualifiedLead เปิดอยู่แต่ไม่มีกฎ → แถวขึ้นบรรทัดเตือน `bg-warning/15 text-warning-ink`: `เปิดอยู่ แต่ยังไม่มีกฎแท็ก จึงยังไม่ส่งอะไร`
- ไม่มี dataset → การ์ดนี้แสดง empty state `เพิ่มชุดข้อมูลก่อน แล้วเลือกเหตุการณ์ที่จะส่ง` (ไม่แสดง 12 แถวที่กดไม่ได้)
- เปิด dataset ใหม่แล้วทุกเหตุการณ์ยังปิด → บรรทัดข้อมูล `ยังไม่ได้เปิดเหตุการณ์ใด จึงยังไม่ส่งอะไรเข้าชุดข้อมูลนี้`

**E. จังหวะส่ง Purchase** (ระดับเพจ — คอลัมน์ขวา sticky บน xl)
- `form-select` native (Hard Rule 6 ก — ผูกค่า) ตัวเลือก: `สร้างคำสั่งซื้อ` · `ยืนยัน` · `ชำระครบ` ใต้ช่องมีคำอธิบายของตัวเลือกที่เลือกอยู่ 1 บรรทัด (เปลี่ยนตามค่า): สร้าง = `ส่งทันทีที่สร้างคำสั่งซื้อในห้องแชท` · ยืนยัน = `ส่งเมื่อลูกค้ายืนยันรับ หรือชำระครบ แล้วแต่อันไหนมาก่อน` · ชำระครบ = `ส่งเมื่อรับเงินครบยอด มัดจำบางส่วนยังไม่นับ`
- `form-switch` `นับออเดอร์ร่างที่ยืนยันแล้ว` + คำอธิบาย `ออเดอร์ที่ระบบตรวจจากแชทแล้วคุณกดยืนยัน จะนับเป็น "สร้างคำสั่งซื้อ" · มีผลกับ Purchase (ถ้าเลือกสร้าง) และ สร้างคำสั่งซื้อ (OrderCreated)`
- เปลี่ยนจังหวะหลังจากส่ง Purchase ของออเดอร์ไปแล้ว → ไม่ส่งซ้ำ (FR-006) บอกใน helper หนึ่งบรรทัดใต้ select: `เปลี่ยนแล้วมีผลกับออเดอร์ถัดไป ที่ส่งไปแล้วไม่ส่งซ้ำ`
- บันทึกอัตโนมัติ (select onChange / switch) + toast

### User flow
1. **ตั้งครั้งแรก:** เข้าหน้า → ยังไม่มี dataset → empty ในการ์ดเหตุการณ์ → กด `เพิ่ม` → เลือก `ใช้ชุดข้อมูลของเพจ` → ได้แถว dataset → ใส่ Test Event Code → `ทดสอบ` → เห็นผลสำเร็จ inline → เลือกเหตุการณ์ที่จะส่ง → ตั้งจังหวะ Purchase → สลับสวิตช์หลักเป็นเปิด (Swal ยืนยันครั้งแรก)
2. **ตั้งยอด:** กด `ตั้งยอด` ที่แถวเหตุการณ์ → แผงขยาย → เปลี่ยน radio/สวิตช์ → บันทึกเอง → `เสร็จ`
3. **ตั้งกฎ Lead:** แท็บสนใจจริง → `เพิ่มกฎ` → เลือกแท็ก ใส่ยอด → `บันทึกกฎ` → toast
4. **ลบ dataset:** กด trash → Swal → ยืนยัน → แถวหาย ชุดอื่นคงเดิม
5. **token เสีย:** banner แดง → `เชื่อมเพจใหม่` → OAuth → กลับ `/settings/channels` (callback เดิม) → ร้านกลับมาหน้านี้ผ่านเมนู

### Section breakdown
- การ์ดเดียว: หัวการ์ดมีชื่อ + หมายเหตุอายุข้อมูล + ตัวกรอง 2 ตัว (`card-header flex-wrap gap-2`)
- **ตัวกรอง:** `FilterDropdown` 2 ตัว (สถานะ · เหตุการณ์) ตามท่า `OrdersTable.tsx` ไม่ส่ง `icon` (ไม่ต้องเดาชื่อ icon) ค่าที่เลือกอยู่ปุ่มเป็น soft primary (พฤติกรรมเดิมของ `FilterDropdown`) · ค่า filter อยู่ใน query string (`?status=&event=&page=`) แล้ว `router.replace` เพื่อแชร์/รีเฟรชได้ · เปลี่ยนตัวกรองรีเซ็ตเป็นหน้า 1
- **ตาราง** (`DataTable` + `mobileCard`): ชิดขวาเฉพาะคอลัมน์มูลค่า `tabular-nums` · เวลาใช้ `formatDateTime` ตัวเดียว (conventions/date-format)
- **Badge สถานะ:** `รอ` = `bg-warning/15 text-warning-ink` · `สำเร็จ` = `bg-success/15 text-success-ink` · `ล้มเหลว` = `bg-danger/15 text-danger-ink` · `ข้าม` = `bg-default-100 text-default-800` (ข้ามเป็นพฤติกรรมปกติ ไม่ใช่ความล้มเหลว)
- **คอลัมน์เหตุผล:** ข้อความไทยที่แปลจากเหตุผลภายในแล้วเท่านั้น (ตารางแปลข้างล่าง) ไม่แสดงรหัสข้อผิดพลาดดิบของ Meta เป็นข้อความหลัก
- **ตัวเด่นของหน้า:** แถวที่ `ล้มเหลว` และ `รอ` — เป็นสองสถานะที่มีสีแรงในหน้า ที่เหลือเป็นเทา/ข้อความปกติ

### Impeccable compliance

- **Mode: Operate** — เป็นคอนโซลผู้ขายที่ผู้ใช้อยู่ในงาน ตั้งค่าแล้วไปต่อ (PRODUCT.md ให้ override register เป็น `product` กับ `(paces)`) เกณฑ์ตัดสินจึงเป็นความอ่านง่าย ความคงเส้นคงวากับหน้าพี่น้อง และความคุ้นเคยตามมาตรฐานของเครื่องมือ ไม่ใช่การแสดงออก
- **One Voice / accent:** สีหลัก `bg-primary` (น้ำเงิน Paces ไม่ใช่ม่วง) อยู่เฉพาะ (1) สวิตช์ที่เปิดอยู่ (2) ปุ่มหลักต่อแผง: `เพิ่มชุดข้อมูล` · `ตรวจและบันทึก` · `บันทึกกฎ` (3) แท็บที่เลือก (4) ข้อความสถานะ `ส่งอยู่` เป็น `primary-ink` · ปุ่มรองทั้งหมดเป็น outline เทา · ผู้ใช้เห็น primary แต่ละช่วงจอไม่เกิน 1 ปุ่มทึบ
- **พระเอกของแต่ละหน้า:** หน้า 1 = สถานะ+สวิตช์ในแต่ละแถว · หน้า 2 = สวิตช์หลักของเพจในหัว และรองลงมาคือแถว Purchase (น้ำหนักตัวอักษรหนักกว่าเพื่อนบ้านหนึ่งขั้น + มีข้อความจังหวะกำกับ) · หน้า 3 = แถว `ล้มเหลว`/`รอ`
- **Verified-Means-Green:** เขียวใช้ 2 ที่เท่านั้น คือ badge `สำเร็จ` ใน log กับผลทดสอบผ่าน — ทั้งคู่คือ "Meta ตอบรับแล้ว" จริง · `ส่งอยู่` **ไม่ใช่เขียน** เพราะเปิดสวิตช์ ≠ Meta รับ · `รอ` = warning · `ข้าม` = เทา · `token ตั้งไว้แล้ว` = เทา (ตั้งค่าแล้ว ไม่ใช่ยืนยันแล้ว) · สถานะเดียวกันสีเดียวกันทั้ง 3 หน้า (ผลสำเร็จใน log กับผลทดสอบใช้ token เดียวกัน)
- **Sentence-Case:** ไม่มี `uppercase` ที่ไหนเลย (หัวการ์ด `channels/page.tsx` ใช้ `uppercase` กับข้อความไทยอยู่ — ไม่ลอกมา) · ชื่อ Meta (Purchase ฯลฯ) คงรูปภาษาอังกฤษตามต้นทาง
- **Ink-tinted shadow:** ใช้เงา `.card` ของธีมตามเดิม ไม่ประกาศเงาใหม่
- **น้ำเสียงข้อความ:** error ทุกข้อมี "ทำอะไรต่อ" · ไม่มี "ไม่สามารถ…ได้" · ปุ่มบอกผลลัพธ์ (`ใช้ชุดข้อมูลของเพจ` · `ลบชุดข้อมูล` · `บันทึกกฎ`) · ไม่ไฮป์ · ไม่กล่าวหา (token "Meta ไม่รับ" ไม่ใช่ "คุณใส่ผิด")
- **ที่ theme ขัดกับ Impeccable / กฎอื่น และการตัดสิน:**
  1. **`text-success`/`text-danger` บนพื้นจาง** ใน `ChannelsClient` (L301, 307, 254) ตกคอนทราสต์ → ไม่ลอก ใช้ `-ink` ตาม DESIGN.md
  2. **Hard Rule 6 ข ชี้ `ui/dropdowns/page.tsx` (Preline `hs-dropdown`)** แต่ตัวกรองหน้า log อยู่ในตารางที่ re-render ทุกครั้งที่กรอง → `hs-dropdown` พัง (opacity ค้าง 0 ตาม paces-component-reference §3) จึงใช้ `FilterDropdown` ที่ repo adapt จาก theme ตัวนั้นไว้แล้ว — **ขอ Controller รับทราบ** เพราะ Base: ใน commit ต้องอ้าง `dropdowns/page.tsx` + FilterDropdown คู่กัน
  3. **placeholder** — theme `default-400` (#9ba6b7) ต่ำกว่า 4.5:1 ตาม PRODUCT.md → dev ตรวจ `_forms.css` ว่าหน้าอื่นแก้ไว้แล้วหรือยัง และถ้ายังต้องยกความเข้ม (ห้ามเปลี่ยนเฉด) · placeholder ในสเปกนี้ (`เช่น TEST12345` · `ไม่ระบุ`) เป็นตัวอย่างค่า ไม่ใช่ label
  4. **ไม่มี `btn-primary`/`btn-soft-*` ใน Paces** → ใช้ `btn bg-primary text-white hover:bg-primary-hover` และ soft `bg-primary/15 text-primary`
  5. **Meta/Messenger brand hex** ใน `ChannelsClient` = ข้อยกเว้น HR6 ของ ChannelsClient เอง ไม่เกี่ยวกับสเปกนี้ → ใช้ `getChannelDisplay` แทน ไม่เพิ่มค่าดิบ
  6. **ที่ spec ไม่มี arbitrary value** — ใช้เฉพาะ `size-*`, `gap-base`, `rounded-lg`, `text-xs/sm/md`, `min-h-11 lg:min-h-0` · ไม่มีค่าที่ Paces ไม่มี ไม่ต้องมี comment ยกเว้น
- **จุดเสี่ยงให้ Controller เพ่งตอน critique:** (ก) badge `สำเร็จ`/`ส่งอยู่` สีต่างกันจริงบนหน้าจอเดียวกันไหม (ข) หน้า 2 บน 1440: คอลัมน์ขวา sticky ค้างจริงไหม ไม่ทับ header (ค) แถวเหตุการณ์ 12 แถว + แผงตั้งยอดบนมือถือ 390 ไม่ล้น (ง) ลำดับ DOM vs ลำดับภาพบน xl (grid วางต่างจาก DOM) กระทบ tab order

### Design decisions + rationale
1. **ตารางหน้าแรกไม่มีการ์ดตัวเลขสรุป** — ข้อมูลที่สรุปได้ (จำนวนเพจ) อยู่ในหัวการ์ดแล้ว การ์ดสถิติจะเป็น hero-metric template และซ้ำกับคอลัมน์
2. **ผลการส่งบนหน้า 2 เป็นการ์ดเตี้ยแบบรายการ ไม่ใช่การ์ดตัวเลข** — มีไว้เป็นทางเข้า log และให้เห็นว่าล้มเหลว/รอเท่าไรโดยไม่ต้องเปิดอีกหน้า · ตัวเลขเท่าข้อความ ไม่ขยาย
3. **จังหวะ Purchase อยู่การ์ดแยก ไม่แทรกในแถว Purchase** — เพราะสวิตช์ "นับออเดอร์ร่าง" มีผลกับ OrderCreated ด้วย และค่านี้เป็นระดับเพจ ถ้าวางในแถวเหตุการณ์ผู้ใช้จะเข้าใจว่าเป็นค่าต่อ dataset
4. **ตัวตั้งยอดขยายใต้แถว ไม่เปิด modal** — แก้ทีละแถว เห็นผลบนรายการทันที และเป็นท่าที่ `AutoNotifyClient` ใช้อยู่แล้ว (ผู้ใช้คุ้น)
5. **แท็บเลือก dataset ในการ์ดเหตุการณ์** แทนการวาง 3×12 แถวต่อกัน — หน้ายาวเกิน 3 หน้าจอและสแกนไม่ได้
6. **ไม่จัดกลุ่มเหตุการณ์เป็น "การ์ดละกลุ่ม"** — ใช้หัวข้อกลุ่มในรายการเดียว เลี่ยงการ์ดซ้อน/การ์ดน้ำหนักเท่ากัน
7. **หน้า log ไม่มีปุ่มส่งซ้ำ** — เสี่ยง Purchase ซ้ำ ซึ่งเป็นความเสี่ยงสูงสุดของ PRD
8. **Dataset ID ไม่ใช้ `font-mono`** — กฎ No-Mono-On-Thai + ตัวเลขเรียงด้วย `tabular-nums`

### Anti-slop self-check
1. **เฉพาะ Deep หรือใช้กับสินค้าอื่นได้?** — เฉพาะ Deep: กติกา "Purchase ไม่ย้อนหลัง/ครั้งเดียวต่อออเดอร์" ทำให้มี Swal ยืนยันเปิดครั้งแรก · ตัวเลือก "นับออเดอร์ร่างที่ยืนยันแล้ว" (ออเดอร์ร่างจากแชท 00061) · กฎแท็ก (00083) ดึงแท็กจริงของร้าน · ศัพท์ "ชุดข้อมูล/จังหวะส่ง/ออเดอร์ร่าง/ห้องแชท" ตรงกับโปรเจกต์ · ไม่มีส่วนไหนใช้ได้กับ Settings ของ SaaS ทั่วไปโดยไม่แก้
2. **เด่นที่สุด 1 อย่าง/จอ?** — หน้า 1 สถานะ+สวิตช์ · หน้า 2 สวิตช์หลักของเพจ (แถวของตัวเองในหัว) รอง Purchase · หน้า 3 แถวล้มเหลว/รอ · ไม่มีการ์ดใดน้ำหนักเท่ากันทั้งหน้า (ผลการส่งเตี้ย จังหวะ Purchase เตี้ย ชุดข้อมูล/เหตุการณ์สูง)
3. **element ซ้ำ/คงที่ที่ตัดทิ้ง** — ตัดแล้ว: การ์ดสถิติหน้า 1 · การ์ด "ข้อควรรู้" แบบ sibling (ย้ายสาระ privacy ไปใส่ subtitle บรรทัดเดียว) · ไอคอนต่อแถวเหตุการณ์ (decorative) · ปุ่ม `เชื่อมเพจใหม่` ซ้ำใน banner กับแถว (banner มีเฉพาะกรณีอัตโนมัติ) · บรรทัด `ตั้งค่านี้ใช้กับทุกชุดข้อมูล` แสดงเมื่อมี >1 ชุดเท่านั้น
4. **ทุก state** — หน้า 1: empty/loading/error/no-permission/ฟีเจอร์ปิด/เพจ TOKEN_INVALID/ไม่มี dataset · หน้า 2: ไม่มี dataset · ไม่มีแท็ก · เหตุการณ์ปิดหมด · เพจปิด · ครบ 3 ชุด · ครบ 20 กฎ · ผลทดสอบ 5 แบบ · dirty · หน้า 3: empty ×2 / error / หน้าเกิน · ตัวเลข 0/ล้าน/`–` ทุกที่ที่มีตัวเลข
5. **copy ตรงกับที่ระบบทำได้จริง** — ปุ่ม `ทดสอบ` มี helper บอกว่าจะเกิดอะไรตามค่ารหัส · ไม่แนะนำให้ "ส่งซ้ำ" (ไม่มีปุ่มนั้น) · ผลของ banner บอก "จะส่งต่อให้เอง" ตรงกับ FR-012 (แถวค้างเป็นรอ) · ไม่แนะนำให้ผู้ใช้ทำสิ่งที่ปุ่มไม่มี: กรณีกรอกเองชี้ไป `เปลี่ยน token` ที่มีจริงในแถว
6. **คำเดียวกัน = ของเดียวกัน** — "ชุดข้อมูล (Dataset)" ตลอด (ใส่ "(Dataset)" แค่หัวการ์ดแรก) · "เพจ" = Messenger page ตลอด · "เหตุการณ์" = event · "จังหวะส่ง Purchase" = เงื่อนไขเวลา · "คำสั่งซื้อ" ตามนิยามในระบบ (ร้านบริการอาจใช้ "งาน" ผ่าน `resolveOrderVocab` — Open Q7)
7. **สีสื่อความถูก** — ดูหัวข้อ Verified-Means-Green · แดงเฉพาะ token เสีย + ล้มเหลวจริง · สถานะเดียวกันสีเดียวกันทั้งสามหน้า
8. **แตะได้บนมือถือ** — สวิตช์/ปุ่ม/ลิงก์ ≥44px (overrides ของ `safepay-overrides.css` ครอบ `.btn`, `form-switch`, `form-radio`) · ของที่ประกอบเอง (ปุ่มลบกฎ · แถวผลการส่ง · แท็บ) ใส่ `min-h-11 lg:min-h-0` / `size-11 lg:size-9.25` · action หลัก (`บันทึกกฎ` · `ทดสอบ`) เป็น `w-full` ท้ายการ์ดในโซนนิ้วโป้ง ไม่ลอย
9. **1440 มีคอลัมน์ว่างไหม** — หน้า 2: ซ้าย 2/3 (เนื้อหาจริงยาว) · ขวา 1/3 มีของจริง 2 การ์ด และ sticky ตามหน้าจอ ไม่มีช่องว่างยาว · หน้า 1/3: ตารางเต็มกว้าง คอลัมน์ "เหตุผล" (หน้า log) ยืดรับข้อความ ไม่ปล่อยว่าง

**Behavior สำคัญของหน้า 2**
- **สวิตช์หลัก:** พระเอกของหน้า · เปิดครั้งแรก = Swal `pacesConfirm.question` · ปิดอยู่ → แถบข้อมูลเทา "เพจนี้ปิดการส่งอยู่ ตั้งค่าไว้ล่วงหน้าได้…" · token เสีย: สวิตช์ค้าง "เปิด" แต่ badge บอกหยุด
- **Dataset:** ID ใช้ `tabular-nums` ไม่ใช้ `font-mono` · token ไม่แสดงค่าเลย · "token ตั้งไว้แล้ว" สี neutral (ตั้งค่าแล้ว ≠ Meta ยืนยัน) · ลบ = `pacesConfirm.danger`
- **ทดสอบ:** ช่อง Test code อยู่ใน state ไม่บันทึก (D6 รับแล้ว) · ผลเป็นกล่อง inline `role="status"`: โหลด / token ใช้ได้ / ส่ง Purchase ฿1 สำเร็จ (success) / token ถูกปฏิเสธ (danger-ink) / ไม่มีห้องแชท (warning-ink)
- **เหตุการณ์:** 12 แถวแบ่ง 3 กลุ่ม · แท็บเลือก dataset เมื่อมี >1 ชุด (`nav-tabs` ขับด้วย React state ไม่ใช้ `hs-tab`) · ปุ่ม `ตั้งยอด` เฉพาะเหตุการณ์ที่มียอด · แผงขยายทีละแถว บันทึกอัตโนมัติ + toast · คืนโฟกัสปุ่มเมื่อกด `เสร็จ` · ไม่มีตัวเลือก "ไม่รวมค่าส่ง" · InitiateCheckout ไม่มียอด · Lead/Qualified ยอดมาจากกฎ · ViewContent ส่งราคาสินค้า (Open Q4)
- **กฎแท็ก:** 2 แท็บ ≤20 กฎ/แท็บ · tag picker = native `form-select` · ยอด `input-group ฿` ว่างได้ · ปุ่มบันทึกเปิดเมื่อ dirty · `beforeunload` + Swal discard
- **Edge:** ไม่มี dataset → การ์ดเหตุการณ์เป็น empty ไม่แสดง 12 แถว · ไม่มีแท็ก → empty + ลิงก์ `/settings/tags` · เปิดเหตุการณ์ Lead ไม่มีกฎ → เตือน warning-ink · ชื่อ/แท็กยาว `truncate`+`title` · Dataset ID ไม่ตัด · PUT ล้ม → revert + toast

6. **ศัพท์คงที่:** ชุดข้อมูล · เพจ · เหตุการณ์ · จังหวะส่ง Purchase · คำสั่งซื้อ

8. **มือถือ:** ทุกปุ่ม/สวิตช์/แท็บ ≥44px · `บันทึกกฎ` · `ทดสอบ` เป็น `w-full` ท้ายการ์ด
9. **1440:** ขวา sticky มีของจริง 2 การ์ด · log ให้คอลัมน์เหตุผลยืด
