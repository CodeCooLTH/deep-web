## กลไกที่พลาดแล้วพังเงียบ

- **"ที่นั่ง"/`serviceSeat` ห้ามโผล่ใน UI และ API response** — ผู้ใช้เห็นแค่ "จองแล้ว 6 จาก 8 คิว"
- ห้าม `count()` เทียบ capacity — ต้องวน seat 1..capacity ครอบ SAVEPOINT (EXCLUDE poison ทั้ง transaction 25P02)
- GiST EXCLUDE สร้าง **predicate lock** → ชนกับ transaction ที่ยังไม่ commit จะ **block ไม่ใช่ error**
  ทำให้ seat loop ค้างจนหมดเวลา แก้ด้วย `pg_advisory_xact_lock(24, hashtext(resourceId))` ที่หัว `allocateSeat()`
  (spike เดิมจับไม่ได้เพราะยิงทีละตัวชนกับแถวที่ commit แล้ว — [[feedback_spike_must_match_production_path]])
- error = **P2010 + `meta.code='23P01'` ไม่ใช่ P2002** → `isExclusionViolation` ที่ `src/lib/prisma-errors.ts`
- `computeAppointmentDeposit()` เช็ค override ด้วย `!== undefined && !== null` **ห้าม falsy** (`"0"` = ไม่เก็บมัดจำ)
- ห้าม `prisma db pull` / `migrate dev` — ลบ EXCLUDE constraint ของ 00008/00017/00024 ทิ้ง
