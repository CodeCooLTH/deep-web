## 1. ยืนยันจากโค้ดจริง

**1.1 `expandClusters`** (`follow-up-scope.ts:19`)
- signature: `expandClusters(anchorIds: string[], shopId: string): Promise<Map<anchorId, roomId[]>>`
- ผลรวมตัว anchor เองด้วย
- ห้องที่ไม่ใช่ของร้านจะไม่มี key ใน Map ใช้เป็นตัวเช็ก ownership ได้ (`map.get(id) === undefined` → 404)
- ห้อง DEEP และห้องไม่มี customer ได้คีย์ `v:<id>` ได้ `[ตัวเอง]`
- วิธีใช้: `ids = (await expandClusters([conversationId], shopId)).get(conversationId)` แล้ว `chatMemory.findFirst({ where: { shopId, conversationId: { in: ids } }, orderBy: { updatedAt: 'desc' } })`

**1.2 ตัวแยกค่า attributes**
- **ไม่มีฟังก์ชัน export อยู่** มีสำเนาในไฟล์ 2 ที่
  - `ProductAttributesCardV2.tsx:61-65` ชื่อ `splitValues`
  - `ProductPreviewPanel.tsx:233-236` แบบ inline
  - สองที่ทำเหมือนกัน: `split(',')` → `trim` → ตัดค่าว่าง
- `serializeProduct` (`product.service.ts:145-148`) คืน `attributes` เป็น `{}` เมื่อไม่ใช่ object หรือเป็น array

### 2.1 `W/src/lib/ai-suggest-auto-types.ts` (เพิ่มแบบ additive)

```ts
export const MEMORY_UPDATE_TRIGGER = 'MEMORY_UPDATE' as const
export const MEMORY_UPDATE_OUTCOMES = [
  'OK','SUPERSEDED','REJECTED_PII','REJECTED_FORMAT','REJECTED_SHRINK',
  'SKIPPED_BASE_HAS_PII','SKIPPED_COOLDOWN','SKIPPED_FEW_MESSAGES',
  'RATE_LIMITED','TIMEOUT','ERROR',
] as const
export type MemoryUpdateOutcome = (typeof MEMORY_UPDATE_OUTCOMES)[number]
```

- **ห้ามแตะ** `AUTO_SUGGEST_TRIGGERS`, `AUTO_SUGGEST_OUTCOMES`, `AutoSuggestReason`
- `AutoSuggestReason` derive จาก outcomes และถูกส่งถึง client
- เหตุผลที่ไม่ใส่ `MEMORY_UPDATE` ใน `AUTO_SUGGEST_TRIGGERS`: เป็นชุดที่ client ส่งได้ และถ้าใส่ type ของ `trigger` ใน `RequestAutoSuggestParams` จะกว้างตาม
- การขยาย `claimRun`: พารามิเตอร์ `trigger: AutoSuggestTrigger | typeof MEMORY_UPDATE_TRIGGER` ตัวเดียว
- สถานะแถวความจำ: OK → `status 'READY'`, อื่น ๆ → `'NONE'`, `suggestion` เป็น null เสมอ (ห้ามเก็บข้อความความจำใน `AiSuggestRun`)

**Data flow (เขียน)**
- แอดมิน: PUT → normalize → resolve แถวจริง → CAS `updateMany {id, shopId, version}` → `source='ADMIN'`, `version+1`, `previousText`
- AI: POST `/ai-suggest/auto` READY → `after()` → `maybeUpdateMemory`:
  1. provider typhoon + สวิตช์ `includeCustomerContext`
  2. `shouldAttemptMemoryUpdate` (ไม่เขียนแถว)
  3. `claimRun('mem:<latestId>')`
  4. `baseHasPii` → `SKIPPED_BASE_HAS_PII`
  5. sanitize ฐาน+ข้อความใหม่ (≤ 40)
  6. `reserveSlot(lowPriority, 2 วิ)`
  7. `generateTyphoonMemoryText` (ห้าม `restorePii` ลงความจำ)
  8. `validateAiMemory`
  9. `applyAiUpdate` (CAS)
  10. `finish` ด้วย outcome

- `getServerSession` → `sessionUserId()` ไม่ cast (null→401)
- `resolveConversationShopId` ได้ `shopId` จากเธรดเท่านั้น (แบบ `crm/route.ts:21-31`) ห้ามใช้ร้านที่ active

- สิทธิ์เท่า CRM route (OQ-M10, OOS-17)
- `ai.updating` อ่านแถว `MEMORY_UPDATE` ของห้องตัวเองเท่านั้น

- 2 ตาราง additive: migration เป็น CREATE TABLE/INDEX/FK ล้วน (`rg "ALTER TABLE\|DROP"` ต้องไม่เจอตารางเดิมถูกแก้)
