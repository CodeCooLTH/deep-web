## 1. ข้อมูล (migration เพิ่มอย่างเดียว · 1 ไฟล์)

- `Order.serviceClosedAt Timestamptz(3)?` + `@@index([shopId, serviceClosedAt])`
- `OrderEvent.type` + `SERVICE_CLOSED` (+ `SERVICE_REOPENED` ถ้า D2 = ใช่) — ตามแพตเทิร์น CHECK additive (`docs/conventions/migration-check-constraint-additive.md`)
- **ปิดย้อนหลัง** (UPDATE scope เฉพาะร้าน `vertical='SERVICE_QUEUE'`, `serviceClosedAt IS NULL`, ไม่ใช่ CANCELLED/DRAFTED):
  1. มีนัด + `appointmentStatus IN (COMPLETED, NO_SHOW)` → `serviceEnd` (เวลาจบนัด — ใกล้ความจริงกว่า updatedAt ที่ขยับทุกครั้งที่รับเงิน)
  2. `status=CONFIRMED` ที่ยังไม่ปิด → `occurredAt` ของ event BUYER_CONFIRMED/SYSTEM_CONFIRMED (ไม่มี → `updatedAt`)
  3. `status=SHIPPED` (ข้อมูลเก่า) → event TRACKING_ADDED (ไม่มี → `updatedAt`)
  - รันซ้ำได้ (เงื่อนไข `IS NULL`) · เทสบนฐาน local 5434 ก่อน · prod รันเองตอน deploy (Hard Rule 15)

## 3. การปิดงาน + ด่าน (service + API)

## 10. มติ user (2026-10-11 — "ตามแนะนำ")
- **D1 มัดจำตอนไม่มาตามนัด** — หน้าปิดงานแบบไม่มาตามนัดมี 2 ทางให้เลือก: **เก็บมัดจำ (ค่าตั้งต้น)** = มัดจำเป็นยอดขาย ณ วันปิดงาน · **คืนมัดจำ** = void รายการมัดจำพร้อมเหตุผล "คืนมัดจำ — ลูกค้าไม่มาตามนัด" (ต้อง O6) ยอด ฿0 · ทั้งสองทางบันทึกใน event `SERVICE_CLOSED.meta.deposit = KEPT | REFUNDED`
- **D2 ปิดงานผิด** — ปุ่ม "เปิดงานอีกครั้ง" (O6) ได้เฉพาะก่อนลูกค้ายืนยัน · ล้างวันปิดงาน · event `SERVICE_REOPENED` · ถ้าเคยคืนมัดจำ ไม่ย้อน void อัตโนมัติ (ร้านบันทึกรับใหม่เอง)
- **D3 แก้ไขหลังปิดงาน** — ล็อกเหมือนงานที่ลูกค้ายืนยันแล้ว · ต้องเปิดงานอีกครั้งก่อน

## 12. โปรไฟล์ที่แท้จริง (หลักของระบบ)
- **โปรไฟล์ร้าน (สาธารณะ):** งานสำเร็จ · Trust Score · รีวิว นับเฉพาะ **ลูกค้ายืนยันเอง** — ร้านกดปิดงานเองไม่ทำให้ตัวเลขสาธารณะขึ้น ปั่นไม่ได้
- **โปรไฟล์ลูกค้า (คะแนนลูกค้า):** ไม่มาตามนัดนับจากงานที่ร้านปิดแบบไม่มาตามนัด (แทนการยกเลิกเดิม) — ไม่หาย ไม่ซ้ำ
- **ร่องรอยครบ:** ปิดงาน / เปิดอีกครั้ง / เก็บหรือคืนมัดจำ บันทึก event พร้อมผู้กดและเวลา · เงินไม่ลบ ใช้ void พร้อมเหตุผล
- **ปิดช่องโหว่ที่ทำให้โปรไฟล์ไม่จริง:** ลูกค้ายืนยันงานที่ตัวเองไม่มาไม่ได้ · ยกเลิกงานที่ปิดแล้วไม่ได้ (กันลบประวัติ)
