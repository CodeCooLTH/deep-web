# Mockup — แถบสถานะคำสั่งซื้อ (seller order detail)

> คู่กับ `2026-08-05-order-progress-mockup.html` — เปิดไฟล์ HTML ดูของจริง เอกสารนี้เก็บเหตุผล
> สถานะ: **รอ user เลือกแบบ** ยังไม่แตะโค้ด

## ทำไมต้องออกแบบใหม่รอบที่ 3

| รอบ | ทำอะไร | user ว่ายังไง |
|---|---|---|
| 1 | กล่องขอบประ 4 ช่องเรียงเป็นกริด (Base: Paces checkout stepper) | "timeline คือไม่สวยเลยยยย" |
| 2 | จุดวงกลม + เส้นประเชื่อม เน้น 2 ชั้น (Base: Paces Timeline) | "ก็ยังไม่สวย ช่วยออกแบบเป็น mockup ให้ก่อน" |

อาการที่วัดได้จากทั้ง 2 รอบ — เป็นปัญหาเดียวกันที่ไม่ได้แก้ตรงจุด:

1. **มันเป็นการ์ดใบใหม่เต็มความกว้างที่มีของอยู่นิดเดียว** ทั้ง 2 รอบเปลี่ยนแค่ "ของข้างใน" แต่ไม่เคยตั้งคำถามว่า
   ควรมีการ์ดใบนี้ไหม → พื้นที่ว่างในการ์ดยังเยอะเท่าเดิม
2. ทุกขั้นน้ำหนักใกล้เคียงกัน ตาไม่รู้จะเกาะตรงไหน (รอบ 2 แก้ไปบ้างแต่จุด 32px ยังเล็กเกินกว่าจะเป็นจุดสนใจ)
3. ไม่มีที่ให้ข้อมูลที่ร้านอยากรู้จริง (เวลาแต่ละขั้น / เลขพัสดุ / ยอดเงิน) — มีแต่ชื่อขั้น

## 4 ทางเลือกในไฟล์ HTML

| แบบ | แนวคิด | จุดขาย | จุดที่ต้องยอมแลก |
|---|---|---|---|
| **A** แถบความคืบหน้าแบบขนส่ง | แถบยาวเติมสี + จุดบนแถบ | คุ้นเคยที่สุด (เหมือนแอปขนส่ง) · เห็นทั้งเส้นทางในบรรทัดเดียว | ไม่มีที่เขียนเวลา · มือถือต้องซ่อนป้าย |
| **B** "ตอนนี้" เป็นพระเอก | ตัวใหญ่บรรทัดเดียวบอกว่ารออะไร + แถบขีดบอกตำแหน่ง | ตอบคำถามหลักเร็วที่สุด · หน้าตาเดียวทุกจอ | เห็นภาพรวมเส้นทางน้อยกว่า |
| **C** รวมเข้ากับการ์ดหัว | ไม่มีการ์ดใหม่ เป็นแถบบางใต้เส้นประของการ์ดเดิม | **แก้ต้นเหตุข้อ 1 ตรง ๆ** · หน้าสั้นลง | ไม่เด่น (ตั้งใจ) |
| **D** ไทม์ไลน์แนวตั้ง | จุด + เส้นทึบ แนวตั้งทุกจอ | **มีที่เขียนเวลา/เลขพัสดุครบทุกขั้น** · ยัดกลับคอลัมน์ขวา 25% ได้ · Base มีในธีมตรง ๆ | สูงที่สุด ต้องเลื่อนผ่านทุกครั้ง |

## ข้อมูลที่ทุกแบบต้องรองรับ (ไม่ต่อรอง)

- 4 เส้นทาง: COD มีจัดส่ง (4 ขั้น) · COD ไม่มีจัดส่ง (3) · โอน/พร้อมเพย์ (4) · ยกเลิก (2)
- ข้อความยาวสุด **"ขนส่งเก็บเงินให้แล้ว · รอโอนเข้าร้านตามรอบของขนส่ง"** ต้องมีที่อยู่จริง
  ห้ามตัดทิ้ง — เป็นข้อความที่กันไม่ให้ร้านเข้าใจผิดว่าเงินเข้าบัญชีแล้ว (ฐานข้อมูลไม่มี `paidAt`)
- เขียวสงวนให้ "เสร็จแล้วจริง" เท่านั้น (Verified-Means-Green) — ลดได้แค่ *พื้นที่* ที่เขียวกิน ไม่ใช่ความหมาย
- ลำดับขั้นมาจาก `src/lib/order-progress.ts` (SSOT) — **ไม่แก้ไฟล์นั้น** ไม่ว่าจะเลือกแบบไหน

## ที่ต้องเช็คหลังเลือก (ก่อนเขียนโค้ด)

- **Hard Rule 1/3** — A กับ B ยังไม่มี `Base:` ในธีมที่ชี้ได้ ต้องไปหา progress-bar/segment ใน
  `theme/paces/` ก่อน หรือยอมรับว่าเป็นการประกอบจาก primitive (แบบเดียวกับที่ทำในรอบ 2)
  · **D ไม่มีปัญหานี้** — Paces Timeline ใช้ได้ตรง ๆ
- **Hard Rule 12** — ไอคอนใน mockup (`tabler:coin`/`credit-card`/`truck`/`circle-check`/`x`) ใช้ของเดิมที่มีในโค้ดแล้ว
  ยกเว้น `tabler:circle` (จุดว่างของขั้นที่ยังไม่ถึงในแบบ C) — ต้องยืนยันก่อนใช้
- mockup ใช้ `color-mix()` เพื่อจำลอง `/10` `/15` ของ Tailwind — ตอน implement ใช้ token ปกติ
