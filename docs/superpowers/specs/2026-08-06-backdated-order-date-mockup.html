วันที่สั่งซื้อย้อนหลัง — Mockup

  • สี primary = #236dc9 (น้ำเงิน Paces) — ไม่ใช่ม่วง #7367F0 ซึ่งเป็นของ buyer/Vuexy
  • ไอคอนทุกตัวเป็น SVG แทน tabler icon จริง (@iconify/react) — ไม่มี emoji ที่ไหนเลย
  • วันที่ทุกจุดเป็น พ.ศ. ตาม formatDateTimeTH · ข้อมูลตัวอย่างเป็นทรงเดียวกับของจริง

1. ช่อง “วันที่สั่งซื้อ” — 3 สถานะ

ค่าตั้งต้นยุบไว้เป็นแถวอ่านอย่างเดียว (D-7) เพราะ ~95% ของการคีย์คือ “ตอนนี้” — ช่องกรอกที่โผล่ตลอดเวลาเพิ่มภาระสายตาให้ทุกคนเพื่อคนส่วนน้อย

2. เดสก์ท็อป POS — OrderCreateForm.tsx

แถววันที่วางอยู่ในการ์ดสรุปฝั่งขวา ต่อจากช่องทางขาย/การชำระเงิน — กลุ่มเดียวกันเชิงความหมาย (“ออเดอร์นี้มาจากไหน จ่ายยังไง เมื่อไหร่”) ไม่ปนกับรายการสินค้า

3. มือถือ & แท็บเล็ต — QuickForm.tsx

layout เดียวกัน คนละความกว้าง — บนแท็บเล็ตแถววันที่มีที่พอให้ค่ากับปุ่มอยู่บรรทัดเดียวกันเสมอ ส่วนมือถือปุ่ม “เปลี่ยน” ยังคง tap target ≥ 44px

4. สร้างจากข้อความในแชท — auto-fill

ผู้ขายกดค้างบนข้อความที่ลูกค้าสรุปออเดอร์ไว้เมื่อคืน → draft เปิดขึ้นพร้อมเวลาของข้อความนั้น m.createdAt มีอยู่ในมือแล้วทั้งสองทางเข้า (ChatThread.tsx:982 มือถือ / :1788 เดสก์ท็อป) แค่ปัจจุบันถูกทิ้งตอนเรียก openDraft

5. หลังบันทึก — toast ที่บอกว่าออเดอร์ไปอยู่ไหน

รายการออเดอร์ keyset ด้วย createdAt DESC ออเดอร์ที่ลงวันที่ย้อนหลังจึงไม่โผล่หัวรายการ ถ้าไม่บอก คนคีย์จะหาไม่เจอแล้วคีย์ซ้ำ · toast นี้ขึ้นเฉพาะเมื่อวันที่ที่เลือก ≠ วันนี้ตามเวลาไทย

บันทึกแล้ว · ลงวันที่ 5 ส.ค. 2569 21:14 น.
อยู่ในรายการย้อนหลัง ไม่ใช่หัวรายการ

6. ประวัติคำสั่งซื้อ (feature 00031) — ความจริงไม่หาย

ORDER_CREATED.occurredAt = วันที่ที่เลือก เพื่อให้ไทม์ไลน์อ่านแล้วสมเหตุสมผล แต่เก็บ meta.keyedInAt = เวลาจริงที่คีย์ไว้ด้วยเสมอ · การเลื่อนวันที่ย้ายยอดข้ามงวด จึงเป็นเหตุการณ์แยกชนิด ORDER_DATE_CHANGED ไม่ยุบรวมกับ ORDER_EDITED
