## 1. โมเดลข้อมูล — ล็อกแล้ว ห้ามเสนอเปลี่ยน

- **สถานะเดียว 3 ค่า** — `OFFLINE` ไม่ใช้งาน (ไม่ตอบใครเลย) / `TEST` ทดสอบ (ตอบเฉพาะแชทที่ระบุของกลุ่มนั้น ต้องมี ≥1 แชท) / `LIVE` ตอบลูกค้าจริง (ตอบทุกแชท) — **มีผลทันทีไม่ต้องกดบันทึก**; ขาไป `LIVE` ถามยืนยันเสมอ
- **ไม่มีสวิตช์ระดับร้าน** (ลบทั้ง UI + gate เมื่อ 2026-07-30) — ห้ามออกแบบให้กลับมา
- **คำตรวจจับ** — หลายคำต่อกลุ่ม เป็นชิป ลบรายคำได้ พิมพ์เพิ่มแล้ว Enter (มีผลทันที)
- **ลำดับความสำคัญ** — int 0–1000 ใช้ตอนข้อความเดียวเข้าหลายกลุ่ม มากกว่าชนะ
- **ข้อความตอบกลับพื้นฐาน** — คำตอบเมื่อไม่เข้าเงื่อนไขเฉพาะข้อใด (สิ่งเดียวที่ลูกค้าเห็นจริง)
- **เงื่อนไขเฉพาะ** — คำตอบที่ต่างตาม เพจ/โฆษณา/สินค้า เรียงเจาะจงมาก→น้อย (`orderBy specificity desc` — `auto-reply-rule.service.ts:118`) ระบบเลือกอันบนสุดที่เข้าเงื่อนไข ไม่เข้าข้อไหนถอยไปคำตอบพื้นฐาน
- **แชทสำหรับทดสอบ** — ตารางแชทจริงที่ผูกกับกลุ่มนี้ มีผลเฉพาะตอนสถานะ = `TEST`
- **แผงพรีวิว** — พิมพ์เหมือนเป็นลูกค้าแล้วดูว่าเพจตอบอะไร (ไม่ส่งจริง ไม่บันทึก)

## 2. ปัญหาที่ต้องแก้ — จาก critique 25/40

| ข้อ | คะแนน | กลไกที่วัดได้ | แก้ด้วย |
|---|---|---|---|
| Aesthetic | 2/4 | การ์ด 4 ใบน้ำหนักเท่ากันหมด (`text-default-800 text-base font-semibold` ทุกใบ) · คอลัมน์ขวา 30% ว่าง | ยุบ 4→3 ใบ + type scale 3 ระดับ + treatment ไอคอน 2 ระดับ + เติมของลงคอลัมน์ขวา |
| Help | 2/4 | ไม่มีที่ไหนอธิบายว่าเงื่อนไขเฉพาะชนะคำตอบพื้นฐานยังไง | **บันไดคำตอบ** — โครงเรียงตามลำดับที่ resolver ไล่จริง แถวสุดท้าย = คำตอบพื้นฐาน |
| User Control | 2/4 | เงื่อนไขเฉพาะแก้รายข้อไม่ได้ ต้องลบแล้วสร้างใหม่ · ปุ่มลบยิงลบทันทีไม่ถาม | ปุ่ม `[แก้ไข]` → sheet prefilled + `pacesConfirm.danger` ก่อนลบ |
| Recognition | 2/4 | “ลำดับความสำคัญ” เป็นเลขดิบ 0–1000 ต้องจำเองว่ามาก/น้อยแปลว่าอะไร | บล็อก **“คำที่ซ้ำกับกลุ่มอื่น”** + ปุ่มเลื่อนขึ้น/ลง (เลขซ่อนหลัง “ตั้งตัวเลขเอง”) |
| “ทุกอย่างจางไปหมด” | — | `text-default-500` 27 จุด + `text-default-400` 17 จุด = เทา **44** ต่อ `text-primary` **12** | เพดานเทา (§7) + ชิปคำเป็น `bg-primary/10` ให้ตรงหน้ารายการ |

**แก้ไปแล้วก่อนสเปกนี้ — ห้ามเสนอซ้ำ:** ไอคอน `text-primary` นำหัวข้อ · ไอคอนเตือนเป็นแผ่นสีทึบ · การ์ดคำตอบพื้นฐานมี `border-s-3 border-s-primary` · พรีวิวโชว์คำตอบเป็นบับเบิลจางทันที · ปุ่มสถานะสอดคล้องกับหน้ารายการ

## 4. Section breakdown

### [A] การ์ดตั้งค่ากลุ่ม — น้ำหนักเบาสุดในสามใบ

ยุบ “หัวกลุ่มคำ + คำตรวจจับ + ลำดับความสำคัญ” เป็นก้อนเดียว = **ของที่ตั้งครั้งเดียวแล้วแทบไม่แตะอีก** หัวเรื่อง `text-md` (15)

- **ชื่อกลุ่ม** — `form-input font-semibold` (เดิม) มี `<label class="form-label">` กำกับ (เดิมไม่มี)
- **ปุ่มสถานะ 3 ค่า** — **เก็บของเดิมทั้งดุ้น** (`KeywordEditorClient.tsx:311-326`) `bg-light inline-flex rounded-lg p-0.5` + `STATUS_META[key].active`
- **บรรทัดความพร้อม (ใหม่)** ใต้ปุ่มสถานะ — บอกล่วงหน้าว่าทำไมกดเปิดแล้วจะไม่ผ่าน
  - ขาด → ไอคอน `tabler-alert-triangle` `text-warning` + ข้อความ **`text-default-800`**
  - ครบ → ไอคอน `tabler-check` + ข้อความ `text-default-600` **ห้ามเป็นสีเขียว** (§7 Verified-Means-Green)
- **ชิปคำตรวจจับ** — `bg-default-100 text-default-700` → **`bg-primary/10 text-primary rounded px-2 py-0.5 text-xs font-medium`** ให้ตรงกับ `PhraseChips` ที่ `AutoReplyListing.tsx:96` (SSOT) · ตัดประโยค “ตรงเมื่อมีคำว่า X หรือ Y” ทิ้ง (พูดซ้ำกับชิปที่อยู่ใต้มันเอง) แทนด้วย label `ตอบเมื่อลูกค้าพิมพ์` · ปุ่มลบมี `aria-label="ลบคำ {คำ}"`
- **บล็อก “คำที่ซ้ำกับกลุ่มอื่น” (ใหม่ — แทนช่องตัวเลข)** คั่นด้วย `border-t border-dashed border-default-300`
  - แสดง**เฉพาะเมื่อมีคำซ้ำกับกลุ่มอื่นจริง** — รายการเรียงตาม `priority desc` + badge สถานะของแต่ละกลุ่ม + แถวของตัวเองไฮไลต์ `bg-primary/5` ป้าย “กลุ่มนี้”
  - ปุ่ม `เลื่อนขึ้น` / `เลื่อนลง` (disabled ที่ปลายทั้งสอง) + ลิงก์ `ตั้งตัวเลขเอง` เผยช่อง 0–1000 เดิม
  - ไม่ซ้ำ → เหลือแถวเดียว `ยังไม่มีกลุ่มอื่นใช้คำซ้ำกับกลุ่มนี้` + ลิงก์ `ตั้งลำดับเอง`

### [B] คำตอบที่ลูกค้าจะได้รับ — พระเอก

ยุบการ์ด “ข้อความตอบกลับพื้นฐาน” + “เงื่อนไขเฉพาะ” เป็น **บันไดคำตอบใบเดียว** อ่านบนลงล่างตรงกับลำดับที่ resolver ไล่จริง แถวสุดท้าย “ทุกกรณีที่เหลือ” คือ textarea ของคำตอบพื้นฐานตัวจริง — **โครงนี้เองคือคำอธิบาย ไม่ต้องมีย่อหน้าสอน**

- แถวเงื่อนไขเฉพาะ: เลขลำดับ (`bg-primary/10 text-primary text-2xs font-semibold size-5.5 rounded`) + label `เมื่อมาจาก` + ชิปเงื่อนไข + ข้อความ `line-clamp-3` + ปุ่ม `[แก้ไข][ลบ]`
- **ปุ่มแก้ไข (ใหม่)** เปิด sheet เดิมแบบ prefilled → `PATCH /api/shops/auto-reply/rules/{id}` — route + `AutoReplyRuleUpdateSchema` รองรับครบแล้ว **ไม่ต้องแตะ backend**
- **ปุ่มลบต้องถามก่อน (ใหม่)** — `deleteException()` ตอนนี้ยิงลบทันที กู้คืนไม่ได้

## 7. Impeccable compliance

**Mode: Operate** — authenticated task surface (ตั้งค่า/ฟอร์ม/ตาราง) ที่ผู้ใช้ “อยู่ในงาน”: scanability + consistency + earned familiarity ชนะการแสดงออก แบรนด์อยู่ในความแม่นยำของรายละเอียด ไม่ใช่ในลูกเล่น · `PRODUCT.md` บรรทัด 11 override register เป็น `product` สำหรับ seller console ชัดเจน (ไม่ใช่ brand register แบบ `(marketing)/**`)

### พระเอกของหน้า = การ์ด [B] “คำตอบที่ลูกค้าจะได้รับ”

เพราะเป็นสิ่งเดียวในหน้าที่ **ลูกค้าจริงจะได้เห็น** — เด่นด้วย **3 ทาง ไม่ใช่ทางเดียว**

| | พระเอก [B] | การ์ดรอง [A] [C] [D] |
|---|---|---|
| หัวเรื่อง | `text-lg` (18) `font-semibold` `text-default-900` — **ใบเดียวในหน้า** | `text-md` (15) `font-semibold` `text-default-800` |
| ไอคอน | แผ่น `bg-primary/15 text-primary size-8 rounded-lg` — **ใบเดียวในหน้า** | เปล่า `text-primary size-4` |
| เนื้อหา | สูงที่สุด + `border-s-3 border-s-primary` ชี้แถวที่ใช้เสมอ | — |

> ทางง่ายคือทำใบเดียวมีสีแล้วที่เหลือเทา — แต่นั่นจะพาหน้ากลับไปจางอีก จึงใช้ **treatment** เป็นตัวแยกขั้น ไม่ใช่ **สี**

### จุดที่ใช้ accent สีธีม (น้ำเงิน `#236dc9` ผ่าน token — ครบทุกจุด)

1. **ชิปคำตรวจจับ** `bg-primary/10 text-primary` — นี่คือจุดที่ “จางไปหมด” ถูกแก้ตรงกลไก: **ของชิ้นเดียวกันในสองหน้าต้องสีเดียวกัน**
2. ไอคอนแผ่น `bg-primary/15 text-primary` ที่หัว [B] **เท่านั้น**
3. ไอคอนเปล่า `text-primary` นำหัวข้อ [A] [C] (คงของที่แก้ไปแล้ว แต่ไม่มีแผ่น เพื่อให้มี**ขั้น**)
4. `border-s-3 border-s-primary` ที่แถว “ทุกกรณีที่เหลือ” — accepted exception ตาม DESIGN.md §6 (ย้ายจากขอบการ์ดมาที่แถว เพื่อชี้ของจริงและไม่ให้ accent ซ้อนสองชั้น)
5. ชิปเงื่อนไข `bg-primary/10 text-primary`
6. ปุ่ม action หลัก — `บันทึกการเปลี่ยนแปลง` · `เพิ่มเงื่อนไขเฉพาะ` · `ส่ง` ในพรีวิว
7. บับเบิลฝั่งเพจในพรีวิว `bg-primary text-white` (= “เสียงของร้าน” ใช้สีเข้มได้เต็มที่)
8. เลขลำดับในบันได `bg-primary/10 text-primary text-2xs font-semibold`
9. แถวของตัวเองในบล็อกคำซ้ำ `bg-primary/5`

รวมพื้นที่สีน้ำเงินทึบ/โปร่ง ≈ **6–8% ของ viewport** บนเดสก์ท็อป → **ผ่าน One Voice ≤10%** และไม่ปรากฏบนของที่ไม่ใช่ action หรือไม่ใช่ “คำ/คำตอบ” เลย

### เพดานเทา — กลไกที่ทำให้ critique เดิมได้ 2/4

เดิม `text-default-500` 27 + `text-default-400` 17 ต่อ `text-primary` 12

**กฎในสเปกนี้**
- `text-default-400` ใช้ได้เฉพาะ **ตัวนับตัวอักษร / วันเวลา / ไอคอน decorative**
- placeholder ใช้ **`text-default-500`** (d400 บนขาว 2.9:1 ตก AA)
- helper text ที่พูดซ้ำกับ control ที่อยู่ข้าง ๆ → **ตัดทิ้ง ไม่ใช่ทำให้จางลง**

ตัดไปแล้ว: คำนำ 4→1 บรรทัด · ประโยค “ตรงเมื่อมีคำว่า…” · กล่องเส้นประ empty state · ช่องลำดับความสำคัญเมื่อไม่มีคำซ้ำ

**สัดส่วนเป้าหมายหลังแก้ ≈ เทา 22 : ธีม 20** (เดิม 44 : 12)

## 8. Content — ข้อความทั้งหมด (ภาษาไทย)

### หัวหน้า
- คำนำ (ย่อจาก 4 บรรทัดเหลือ 1): `ตั้งว่าลูกค้าพิมพ์อะไรแล้วเพจจะตอบอะไรกลับให้อัตโนมัติ`
- ลิงก์ย้อนกลับ (`md:hidden`): `ตอบแชทอัตโนมัติ`

### [A]
- หัวการ์ด: `ตั้งค่ากลุ่มคำ` · label: `ชื่อกลุ่มคำ`
- `aria-label` กลุ่มปุ่ม: `สถานะของกลุ่มคำนี้` · ปุ่ม: `ไม่ใช้งาน` / `ทดสอบ` / `ตอบลูกค้าจริง` (มือถือย่อเป็น `ตอบจริง`)
- **บรรทัดความพร้อม**
  - ขาดคำ: `ยังเปิดใช้ไม่ได้ — กลุ่มนี้ยังไม่มีคำตรวจจับ เพิ่มอย่างน้อย 1 คำก่อน`
  - ขาดคำตอบ: `ยังเปิดใช้ไม่ได้ — ยังไม่มีข้อความตอบกลับ ใส่คำตอบใน "ทุกกรณีที่เหลือ" ก่อน`
  - ครบแต่ยัง OFFLINE: `ตั้งค่าครบแล้ว เลือก "ทดสอบ" หรือ "ตอบลูกค้าจริง" เมื่อพร้อม`
  - TEST แต่ยังไม่มีแชท: `โหมดทดสอบต้องเลือกแชทก่อนอย่างน้อย 1 แชท` + ลิงก์ `เลือกแชท`
- label ชิป: `ตอบเมื่อลูกค้าพิมพ์` · placeholder: `เพิ่มคำ… แล้วกด Enter` · `aria-label` ปุ่มลบชิป: `ลบคำ {คำ}`
- **บล็อกคำซ้ำ**
  - หัว: `คำที่ซ้ำกับกลุ่มอื่น`
  - อธิบาย: `"สนใจ" ใช้อยู่ในกลุ่ม "ทักถามสินค้า" ด้วย — ถ้าลูกค้าพิมพ์คำนี้ ระบบจะเลือกกลุ่มที่อยู่บนสุด`
  - แถวของตัวเอง: `กลุ่มนี้` · ปุ่ม: `เลื่อนขึ้น` / `เลื่อนลง` · ลิงก์: `ตั้งตัวเลขเอง`
  - ไม่มีคำซ้ำ: `ยังไม่มีกลุ่มอื่นใช้คำซ้ำกับกลุ่มนี้` + `ตั้งลำดับเอง`
  - ช่องตัวเลข (เมื่อกางออก) label: `ตัวเลขลำดับ (0–1000)` helper: `ตัวเลขมากกว่าถูกเลือกก่อน`

### [B]
- หัวการ์ด: `คำตอบที่ลูกค้าจะได้รับ`
- คำอธิบายกลไก (Help fix): `ระบบไล่จากบนลงล่าง เจอข้อแรกที่ตรงก็ตอบข้อนั้นแล้วหยุด`
- ปุ่ม: `เพิ่มเงื่อนไขเฉพาะ`
- แถวเงื่อนไข: `เมื่อมาจาก` + ชิป `เพจ {ชื่อ}` / `โฆษณา {ชื่อ}` / `สินค้า {ชื่อ}` · ปุ่ม `แก้ไข` `ลบ`
- แถวสุดท้าย: `ทุกกรณีที่เหลือ` + badge `ใช้เมื่อไม่เข้าข้อไหนเลย`
  > เดิมชื่อ “ข้อความตอบกลับพื้นฐาน” — ชื่อใหม่บอกตำแหน่งในบันไดด้วยตัวมันเอง
- placeholder textarea: `เช่น สนใจสินค้ารายการไหนคะ ส่งรูปหรือชื่อสินค้าเข้ามาได้เลยค่ะ` (เดิม)
- ชวนเพิ่มตอนไม่มีเงื่อนไข: `อยากตอบต่างกันตามเพจ โฆษณา หรือสินค้า? เพิ่มเงื่อนไขเฉพาะ`
- sheet โหมดแก้: หัว `แก้เงื่อนไขเฉพาะ` · ปุ่ม `บันทึกเงื่อนไข`
- กล่องอธิบายใน sheet: `เงื่อนไขนี้เจาะจง 2 อย่าง จะถูกตรวจก่อนข้อที่ระบุแค่เพจอย่างเดียว`

### [C]
- ย่อ: `แชทสำหรับทดสอบ (2)` / `มีผลเฉพาะตอนสถานะเป็น "ทดสอบ"` · ปุ่ม `ดูรายการ`
- เต็ม: หัว `แชทสำหรับทดสอบ (2)` · คำอธิบาย `ตอนนี้กลุ่มคำนี้จะตอบเฉพาะแชทในรายการนี้เท่านั้น` · ปุ่ม `เพิ่มแชท`
- หัวตาราง: `คู่สนทนา` `ข้อความล่าสุด` `เพิ่มเมื่อ` `จัดการ`
- ว่าง (เดิม): `ยังไม่ได้เลือกแชทสำหรับทดสอบ` / `เลือกแชทของตัวเองหรือของทีมงาน แล้วทักเข้ามาด้วยคำที่ตั้งไว้เพื่อดูว่าระบบตอบอะไร`

### [D]
- เดิมทั้งหมด + **แถบผลจริง**
  - เคยตอบ: `ตอบไปแล้ว {n} ครั้ง ใน 7 วัน · ล่าสุด {วันที่เวลา}` (ผ่าน `formatDateTime` — `docs/conventions/date-format.md`)
  - ไม่เคยตอบ + LIVE: `ยังไม่มีลูกค้าพิมพ์ตรงกับคำในกลุ่มนี้ใน 7 วันที่ผ่านมา`
  - ไม่เคยตอบ + TEST: `ยังไม่มีแชทในรายการทดสอบทักเข้ามาด้วยคำในกลุ่มนี้`
  - OFFLINE: `กลุ่มนี้ยังไม่ใช้งาน จึงยังไม่เคยตอบใคร`

### [E]
- เดิม + `pacesConfirm.danger` ล้าง: หัว `ล้างสิ่งที่แก้ไว้?` เนื้อ `ค่าที่แก้ในหน้านี้จะกลับไปเป็นค่าที่บันทึกไว้ล่าสุด` ปุ่ม `ล้างที่แก้ไว้`

### confirm / toast
- ไป LIVE (**เก็บของเดิมทุกคำ**): `pacesConfirm.warning`
- ลบเงื่อนไข: หัว `ลบเงื่อนไขเฉพาะข้อนี้?` เนื้อ `ข้อความตอบของข้อนี้จะหายไป และกู้คืนไม่ได้ — กรณีที่เคยเข้าข้อนี้จะไปใช้คำตอบใน "ทุกกรณีที่เหลือ" แทน` ปุ่ม `ลบเงื่อนไข` (`pacesConfirm.danger`)
- เลื่อนลำดับสำเร็จ: `กลุ่มนี้จะถูกเลือกก่อน "{ชื่อกลุ่มอื่น}" แล้ว`
- แก้เงื่อนไขแล้วลำดับขยับ: `บันทึกแล้ว — ข้อนี้ย้ายไปอยู่ลำดับที่ {n}`

## 9. User flow

1. **เปิดหน้า** → เห็นชื่อกลุ่ม + สถานะที่มุมขวาบนของการ์ดแรก · ตรงกลางคือบันไดคำตอบที่มีข้อความจริงอยู่ในนั้น · ขวาคือห้องแชทที่โชว์บับเบิลคำตอบจาง ๆ ทันที → **ภายใน 3 วินาทีรู้ว่า “ลูกค้าจะได้ข้อความนี้”**
2. **พิมพ์คำเพิ่ม** → Enter → ชิปสีน้ำเงินโผล่ต่อท้าย (มีผลทันที) → ถ้าซ้ำกับกลุ่มอื่น `pacesToast.warning` + บล็อก “คำที่ซ้ำกับกลุ่มอื่น” ปรากฏใน [A] ทันที
3. **แก้ข้อความตอบกลับ** → แถบล่างขึ้น `แก้ไข 1 อย่าง: คำตอบพื้นฐาน` → กดบันทึก → toast
4. **กด [แก้ไข] ที่เงื่อนไขข้อ 1** → sheet เปิดพร้อมค่าเดิม → แก้ → `บันทึกเงื่อนไข` → ถ้าลำดับขยับ toast บอกตรง ๆ
5. **กด [ลบ] ที่เงื่อนไข** → `pacesConfirm.danger` → ลบ → toast
6. **กด “ทดสอบ”**
   - ยังไม่มีแชททดสอบ → `pacesToast.error` ที่บอกทางออก + [C] กางอัตโนมัติ + เปิด picker ให้เลย
   - มีแชทแล้ว → เปลี่ยนทันที + แถบเตือนสีเหลืองขึ้นบนสุด + [C] กางเต็ม
7. **กด “ตอบลูกค้าจริง”** → `pacesConfirm.warning` (เดิม) → ยืนยัน → toast + ปุ่มเป็นสีเขียว
8. **กด “เลื่อนขึ้น”** → `PATCH priority` → รายการสลับที่ทันที + toast
9. **กด “ล้างที่แก้ไว้”** → `pacesConfirm.danger` → คืนค่าเดิม
10. **มือถือกด “← ตอบแชทอัตโนมัติ”** → กลับหน้ารายการ (ตอนนี้ต่ำกว่า 768px ไม่มีทางกลับเลยเพราะ breadcrumb `hidden md:flex`)

| สถานะ TEST แต่ 0 แชท | แถบเตือนบนสุด (ข้อความเดิม) + [C] กางเต็มพร้อม empty state + บรรทัดความพร้อม |

## 12. Design decisions + rationale

1. **บันไดคำตอบใบเดียว = signature ของหน้า** — โครงเดียวที่ทำให้กลไก resolver มองเห็นได้ด้วยตาแทนการอธิบาย และเป็นคำตอบที่ dashboard ทั่วไปไม่ทำ (ปกติแยก “Default reply” กับ “Rules table”) ลำดับในบันได = ลำดับที่ระบบไล่จริง — **structure is information ไม่ใช่ decoration**
2. **ไม่ทำให้ทุกไอคอนเลิกเป็นสีธีมเพื่อสร้างลำดับชั้น** — ทางง่ายคือทำใบเดียวเป็นสีแล้วที่เหลือเทา แต่นั่นจะพาหน้ากลับไปจางอีก จึงใช้ **treatment** เป็นตัวแยกขั้น (แผ่นทึบ vs ไอคอนเปล่า) ไม่ใช่ **สี**
3. **ลำดับความสำคัญแสดงเฉพาะเมื่อมีความหมาย** — ค่านี้มีผลก็ต่อเมื่อข้อความเดียวเข้าหลายกลุ่ม ซึ่งเกิดได้เมื่อ**คำซ้ำ**เท่านั้น ร้านที่ไม่มีคำซ้ำจึงไม่ควรเห็นช่องตัวเลขที่ตอบไม่ได้ว่าใส่เท่าไหร่ดี — และเมื่อมีคำซ้ำ ให้เห็น “ใครชนะใคร” เป็นรายการ ไม่ใช่เลขลอย · **โมเดลข้อมูลไม่เปลี่ยน** (ยังเป็น int 0–1000 ผ่าน `PATCH keywords/{id}`)
4. **แถบผลจริงเป็นประโยค ไม่ใช่การ์ดตัวเลข** — DESIGN.md ห้าม hero-metric template ตรง ๆ และ PRODUCT.md บอกว่า trust มาจากหลักฐานจริง ประโยคเดียวที่มีตัวเลขจริงทำงานได้เท่ากันโดยไม่กินพื้นที่และไม่เข้าข่าย slop
5. **ไม่แตะปุ่มสถานะเลย** — เพิ่งทำให้สองหน้าตรงกัน การเปลี่ยนตอนนี้จะย้อนศรตัวเอง (critique P2 บอกชัดว่า “ยังไม่แก้รอบนี้”)
6. **ไม่มี undo หลังเปลี่ยนสถานะ และไม่เสนอให้ทำ** — `pacesToast` ไม่รองรับปุ่มใน toast (ดู `PacesToastOptions`) และตัวควบคุมสถานะอยู่บนจอตลอดเวลาอยู่แล้ว = ย้อนได้ด้วยการกดหนึ่งครั้ง ดีกว่าประดิษฐ์ toast แบบใหม่นอกระบบ
7. **rail แตกที่ `xl` ไม่ใช่ `lg`** — ที่ 1024px sidebar Paces กิน 245px คอลัมน์ขวา 30% จะเหลือ ~234px ห้องแชทอ่านไม่ได้
8. **ซ้าย = “ตั้งค่า” / ขวา = “ทดลอง”** — วัดจาก mockup จริง ไม่ใช่จากการเดา (§3.1 หมายเหตุ)

## 13. ข้อสมมติที่ตัดสินแล้ว — ถ้าไม่เห็นด้วยแจ้งก่อน implement

| # | เรื่อง | ตัดสินเป็น | เหตุผล |
|---|---|---|---|
| A1 | query หา “คำที่ซ้ำกับกลุ่มอื่น” วางที่ไหน | **service function** `getPhraseOverlaps(shopId, keywordId)` ใน `auto-reply-rule.service.ts` แล้ว `[id]/page.tsx` เรียก | query แบบเดียวกันมีอยู่แล้วใน `addPhrases()` — บล็อก `crossGroup` (`auto-reply-rule.service.ts:412-424`, คอมเมนต์ `คำเตือนข้ามกลุ่ม (AC-002-04)`) แค่ยก where ออกมาเป็นฟังก์ชันของตัวเอง · ตาม convention ที่แยก service layer ออกจาก API/page layer · unit-test ได้ |
| A2 | shape ที่ส่งลง client | `overlaps: { id, name, priority, status, sharedPhrases: string[] }[]` เรียง `priority desc` | client แค่ render ไม่ต้องคำนวณ · `sharedPhrases` ใช้เขียนประโยค “{คำ} ใช้อยู่ในกลุ่ม {ชื่อ} ด้วย” |
| A2b | บล็อกคำซ้ำนับกลุ่ม `OFFLINE` ด้วยไหม | **ไม่นับ** — คง `status: { not: 'OFFLINE' }` ตามที่ `crossGroup` เดิมใช้ | กลุ่ม OFFLINE ไม่แข่งกับใครเลยตอนนี้ · การโชว์มันจะทำให้ผู้ใช้กังวลกับสิ่งที่ยังไม่มีผล และทำให้บล็อกนี้โผล่บ่อยเกินจำเป็น · ถ้าโชว์ต้องแยกป้าย “ยังไม่ใช้งาน” เพิ่ม = ซับซ้อนขึ้นโดยไม่ได้อะไร |
| A2c | แถบผลจริงเรียก filter อะไร | `searchLogs(shopId, { keywordId, from: <7 วันก่อน>, decision: 'REPLIED' })` | `SearchLogFilter` มี `keywordId` / `from` / `decision` ครบแล้ว (`auto-reply-log.service.ts:107-124`) · `'REPLIED'` = ค่าที่แปลว่าตอบไปจริง (`AUTO_REPLY_LOG_DECISIONS` ใน `auto-reply-constants.ts:39`) — `SKIPPED`/`HANDOFF`/`FAILED` ไม่นับ |
| A3 | sheet โหมด edit รองรับกี่เงื่อนไข | **single-select** (1 เพจ / 1 โฆษณา / 1 สินค้าต่อข้อ) | 1 แถวในบันได = 1 rule · การเลือกหลายเพจตอน “เพิ่ม” สร้างหลาย rule จึงแก้รวมกันไม่ได้ |
| A4 | `duplicateKeyword` (มีใน service ไม่มี UI) | **ไม่ใส่ในหน้านี้** | จะเพิ่ม action ที่แข่งความสนใจกับพระเอก — ควรไปอยู่หน้ารายการพร้อม bulk action |
| A5 | `uppercase` ที่ `settings/ai/page.tsx:84` | **นอก scope งานนี้** | เป็นละเมิดกฎเดียวกันแต่คนละหน้า — เก็บเป็น carry |

### ⚠️ ข้อที่ยังต้องให้ user / `safepay-product` เคาะ (เป็นกฎธุรกิจ ไม่ใช่ดีไซน์)

**สูตรของปุ่ม “เลื่อนขึ้น / เลื่อนลง”**

ข้อเสนอ: `เลื่อนขึ้น` → `priority = min(1000, max(priority ของกลุ่มที่ซ้ำทั้งหมด) + 1)` · `เลื่อนลง` → `priority = max(0, min(...) − 1)`

**คำถามที่ยังไม่มีคำตอบ:** ถ้าชนเพดาน (มีกลุ่มอื่นอยู่ที่ 1000 แล้ว) หรือชนพื้น (มีกลุ่มอื่นอยู่ที่ 0 แล้ว) จะทำอย่างไร — disable ปุ่มเงียบ ๆ, ยิง error, หรือ renumber ทั้งชุดใหม่? สเปกนี้วาด UI แบบ **disable ปุ่มที่ปลายทั้งสอง** ไว้ก่อน แต่ถ้าเลือก renumber จะกลายเป็น migration/กฎใหม่ ต้องเคาะก่อนเขียนโค้ด
