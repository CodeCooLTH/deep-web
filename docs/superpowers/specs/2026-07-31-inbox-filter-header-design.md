# ส่วนหัวตัวกรองรายการแชท — ทางเลือกการจัดวาง

- **วันที่:** 2026-07-31
- **ขอบเขต:** เฉพาะส่วนหัวของรายการแชท seller `/inbox` (`InboxList.tsx` card-header) — ไม่แตะแถวรายการหรือหน้าเธรด
- **Mockup:** [`2026-07-31-inbox-filter-header-mockup.html`](./2026-07-31-inbox-filter-header-mockup.html) (Mobile 375 / Tablet 768 / Desktop rail 320)
- **สถานะ:** รอ user เลือกทาง — **ยังไม่ implement**

## 1. ปัญหา

บนคอลัมน์แคบ (ซึ่งเป็นความกว้างปกติของรายการแชท) ส่วนหัวกินไป **3 แถว** ก่อนถึงรายการแชทจริง:

```
[ค้นหา]
[ทั้งหมด][Deep][FB][IG]  [ตัวกรอง ▾]
[ทุกเพจ ▾]                     ← ตกลงมาแถวของตัวเองเกือบตลอด
[ทั้งหมด][ร้านอะไหล่][ทดสอบ][+]
```

ผลคือเห็นเธรดต่อหนึ่งจอน้อยลง ซึ่งเป็นสิ่งที่ผู้ใช้มาที่หน้านี้เพื่อดู

---

## 2. ข้อจำกัดที่เรียนรู้มาแล้ว (สำคัญกว่าตัวเลขจำนวนแถว)

รอบวันที่ 2026-07-31 เคยลอง **ยุบช่องทาง+เพจ+สถานะเข้าปุ่ม "ตัวกรอง" ปุ่มเดียว** แล้ว user ปฏิเสธ
และสั่งถอยกลับทั้งหมด (`07eb6aaa`, `db7352c8`) บทเรียนที่ต้องไม่ทำซ้ำ:

| สิ่งที่พลาด | ผลที่เกิด |
|---|---|
| ยุบ pill ช่องทางเข้าดรอปดาวน์ | สลับ FB/IG จาก **1 คลิก → 3 คลิก** ทั้งที่เป็น action ที่ใช้บ่อยที่สุดในหน้านี้ |
| ปุ่มรวมทุกอย่างวางไว้ท้ายแถว | เป็น **single point of access** แล้วถูกดันหลุดขอบเมื่อกลุ่มเยอะ → เข้าไม่ถึงตัวกรองเลย |
| popover ยาวขึ้น 2 หัวข้อ | ทะลุจอและ**เลื่อนข้างในไม่ได้** (ไม่มี `max-height`) |

> **กฎที่ได้:** การลดจำนวนแถวไม่คุ้ม ถ้าต้องแลกด้วยจำนวนคลิกของสิ่งที่ใช้บ่อยที่สุดในหน้านั้น

## 3. ทางเลือก

### ทาง A — ซ่อนสิ่งที่ไม่จำเป็นโดยอัตโนมัติ

ไม่ย้ายอะไรสักอย่าง แค่ไม่แสดงตัวเลือกที่กดไปก็ไม่เกิดผล:

- pill ช่องทาง แสดงเฉพาะช่องทางที่ร้าน**มีจริง** (ดูจาก `channels` ที่ SSR ส่งมาอยู่แล้ว + มีเธรด DEEP ไหม)
- ดรอปดาวน์ "เพจ" โผล่เฉพาะร้านที่มี **มากกว่า 1 เพจ**

| | |
|---|---|
| แถว | **2 แถว** สำหรับร้านส่วนใหญ่ (3 แถวถ้าใช้ครบทุกช่องทาง + หลายเพจ) |
| คลิกที่เสียไป | **ไม่มีเลย** |
| ความเสี่ยง | ต่ำสุด — ไม่มีอะไรย้ายที่ |
| ข้อควรระวัง | ต้องนิยาม "ร้านมีช่องทางนี้จริง" ให้ถูก ไม่งั้นปุ่มหายทั้งที่ควรมี |

### ทาง B — ยุบเฉพาะ "เพจ" เข้าปุ่มตัวกรอง

pill ช่องทางอยู่ที่เดิมครบ ยุบเฉพาะดรอปดาวน์เพจเข้าไปเป็นหัวข้อในปุ่มตัวกรอง (พร้อม badge นับ)

| | |
|---|---|
| แถว | **2 แถว เสมอ** |
| คลิกที่เสียไป | เลือกเพจ 1 → 3 คลิก (กระทบเฉพาะร้านหลายเพจ) |
| ความเสี่ยง | ปานกลาง — ต้องใส่ `max-h` + scroll ใน popover ตั้งแต่แรก |

### ทาง C — จัดแถวใหม่ ไม่ซ่อนอะไรเลย

สลับว่าอะไรอยู่แถวไหน ตามความหมาย:

```
[ค้นหา]
[ช่องทาง...][ทุกเพจ ▾]        ← "ดูจากที่ไหน"
[ตัวกรอง ▾][กลุ่ม...เลื่อนได้]  ← "กรองยังไง"
```

| | |
|---|---|
| แถว | **2 แถว เสมอ** |
| คลิกที่เสียไป | **ไม่มีเลย** |
| ความเสี่ยง | ปานกลาง — ย้ายตำแหน่งของที่ผู้ใช้คุ้นมือ; ปุ่มตัวกรอง**ต้องปักซ้าย** ให้กลุ่มเลื่อนแทน (บทเรียนข้อ 2) |

## 4. หมายเหตุ

- **A รวมกับ B หรือ C ได้** — A เป็นกฎการ "ซ่อนเมื่อไม่มีผล" ไม่ใช่การจัดวาง จึงไม่ขัดกัน
- ทุกทางเลือกใช้ Paces token เท่านั้น (`--color-primary: #236dc9`) — **ห้ามม่วง Vuexy `#7367F0`** ในหน้า `(paces)/**` ตาม DESIGN.md §104 และ Hard Rule 7
- ไม่มี emoji ใน mockup — ไอคอนเป็น SVG ทั้งหมด (Hard Rule 12)
- ทุกทางเลือกต้องเพิ่ม `max-h` + `overflow-y-auto` ให้ popover ตัวกรอง (บั๊กที่เจอจริง: เนื้อหายาวทะลุจอแล้วเลื่อนไม่ได้)
