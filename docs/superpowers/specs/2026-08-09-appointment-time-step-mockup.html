Mockup — ขั้น “เลือกเวลา” ของคิวงาน (SERVICE_QUEUE)

จอที่ user รายงาน 2026-08-09 ว่า “ตั้งค่าเวลายาก” = ขั้นที่ 2 ของ AppointmentDateSheet.tsx (step === 'time'). ไฟล์นี้เสนอ 3 ทางเลือก พร้อมของเดิมไว้เทียบ. สีทุกค่าคัดจาก src/assets/css/config/_root.css ของสกิน Paces ตรง ๆ — ไม่มีสีที่เดาเอง และไม่มี emoji (HR12 — ไอคอนทุกตัวเป็น SVG ทรง tabler ซึ่งของจริงจะเป็น <Icon icon="…">)

ไฟล์ที่จะถูกแก้: src/app/(paces)/seller/(dashboard)/orders/new/components/AppointmentDateSheet.tsx (ใช้ร่วมกับ RescheduleAppointmentSheet และหน้าต่างร่างออเดอร์ในแชท) · ข้อมูลตัวอย่างเป็นทรงเดียวกับที่ GET /api/shops/current/appointments คืนจริง · breakpoint ทุกตัวเป็น container query (@3xl=768 / @5xl=1024) ไม่ใช่ viewport

สิ่งที่พังอยู่ตอนนี้ (จากภาพที่ส่งมา + อ่านโค้ดยืนยันแล้ว)

  • บั๊กจริง — เวลาสิ้นสุดค้างที่ 12:25 ทั้งที่เพิ่งกดชิป 13:00: endTouched.current ถูกตั้งเป็น true ตอนเปิดชีตถ้าฟอร์มเคยมี endTime (บรรทัด 226) แล้ว applyStart() จะ ไม่ auto-fill เวลาสิ้นสุดอีกเลยตลอดชีวิตของชีตนั้น (บรรทัด 475). กดช่วงเวลาใหม่กี่ครั้งก็ได้ช่วงที่ผิดกฎทุกครั้ง
  • คิวงานนี้ durationMinutes = null — ป้ายชิปจึงเป็น 08:00 ไม่ใช่ 08:00–09:00 และชิปเซ็ตให้แค่เวลาเริ่ม. ทางลัดที่โฆษณาว่า “กดครั้งเดียวได้ทั้งเริ่มและจบ” (คอมเมนต์บรรทัด 1075) ทำงานเฉพาะร้านที่ตั้งระยะเวลาไว้เท่านั้น ซึ่ง schema เปิดให้เป็น null ได้
  • กล่อง “ว่างทั้งวัน” กิน ~45% ของจอ เพื่อบอกว่า ไม่มีอะไรอยู่ตรงนี้ — มันคือ flex-1 justify-center py-8 (บรรทัด 978) ที่ไม่ถูกยุบตอนอยู่ขั้นเลือกเวลา ทั้งที่ทั้งขั้นนี้มีงานเดียวคือเลือกเวลา
  • ปุ่ม CTA กลายเป็นข้อความ error (“เวลาสิ้นสุดต้องมาหลังเวลาเริ่ม”) ซ้ำกับบรรทัดแดงเหนือมันแบบคำต่อคำ แล้วเสียป้ายที่บอกว่ากดแล้วได้อะไร — ปุ่มที่ disabled ยังหลุด tab order ด้วย
  • ผู้ขายคิดเป็น “13:00 ใช้เวลา 1 ชม.” แต่จอบังคับให้กรอก เวลาสิ้นสุด ซึ่งเป็นค่าเดียวในจอที่กรอกผิดแล้วพังได้ และต้องปั่น native picker

  • คำว่าระยะเวลาเปลี่ยนจาก “1.5 ชม.” เป็น “1 ชม. 30 นาที” — “1.5 ชม.” อ่านง่ายเฉพาะ 90 พอเป็นคิวงาน 45 นาที (135) จะกลายเป็น “2.25 ชม.” ซึ่งไม่มีใครพูด. mockup ในหน้านี้แก้ตามแล้ว และ ResourceList / PublicServiceList ที่เคยเขียน ${นาที} นาที ดิบ ๆ ถูกดึงมาใช้ตัวเดียวกัน (HR16)

ทำไมถึงแนะนำแบบนี้

  • ช่วงเวลาที่ผิดกฎสร้างไม่ได้เลย — เมื่อไม่มีช่อง “เวลาสิ้นสุด” ให้กรอก เงื่อนไข pendingEnd <= pendingStart ก็เกิดขึ้นไม่ได้ตั้งแต่ต้นทาง. บั๊ก endTouched หายไปพร้อมกับกลไกที่มันอยู่ ไม่ใช่ถูกแพตช์
  • จบใน 2 แตะ (เวลาเริ่ม → ระยะเวลา) และแตะที่สองมักไม่ต้องแตะเลยเมื่อคิวงานตั้ง durationMinutes ไว้ (ชิปนั้นถูกเลือกให้ล่วงหน้า)
  • รองรับ durationMinutes = null ได้จริง — ค่าตั้งต้นตกไปที่ 1 ชม. แล้วผู้ขายกดเปลี่ยนได้ ต่างจากตอนนี้ที่ชิปเซ็ตให้แค่เวลาเริ่มแล้วปล่อยค้าง
  • “กำหนดเอง” ยังพาไปหาช่องกรอกเวลาแบบเดิม — ร้านที่ต้องการ 13:00–16:45 ยังทำได้ ไม่มีอะไรหายไปจากระบบ
  • ขอบเขตงาน: ไฟล์เดียว ไม่แตะ API/DB — onConfirm ยังส่ง {startTime, endTime} เหมือนเดิม แค่ endTime ถูกคำนวณจากระยะเวลาแทนการรับจาก input

  • ได้: คำถาม “ว่างช่วงไหน” ตอบได้ด้วยการกวาดตาครั้งเดียว ไม่ต้องอ่านรายการแล้วแปลงเป็นช่องว่างในหัว. คิวที่ทับกันจริง ๆ เห็นเป็นความสูงที่ทับกัน ไม่ใช่จุดสีเล็ก ๆ บนชิป
  • ได้: ยืดเวลาด้วยการลากขอบล่าง = ตั้งเวลาสิ้นสุดโดยไม่มีช่องให้กรอกผิด (เหตุผลเดียวกับแบบ A แค่คนละท่า)
  • เสีย: บนกล่องแคบ 384px ของหน้าต่างร่างออเดอร์ในแชท ไทม์ไลน์ 12 ชั่วโมง = ~550px ต้องเลื่อนเสมอ และการลากนิ้วในกล่องที่ scroll อยู่แล้วชนกันเอง (ต้องกัน gesture — คลาสเดียวกับปัญหาที่ overlay-scroll-lock.md เล่าไว้)
  • เสีย: งานหนักที่สุดใน 3 แบบ (drag/resize + คำนวณตำแหน่งบล็อกที่ทับกัน + a11y ของการลากต้องมีทางเลือกด้วยคีย์บอร์ดตาม WCAG 2.1.1)
  • ข้อสังเกต: ถ้าเลือกแบบนี้ ควรทำ หลัง แบบ A ไม่ใช่แทน — โครงข้อมูลเหมือนกันทุกอย่าง เปลี่ยนแค่วิธีวาด

เปลี่ยนอะไรบ้าง (ทั้งหมดเป็นการซ่อม ไม่ใช่การออกแบบใหม่)

  • ปิดบั๊ก endTouched — กดชิปช่วงเวลา = ตั้งเวลาสิ้นสุดให้เสมอ (duration ?? 60 นาที) ไม่ว่าผู้ใช้เคยแตะช่องสิ้นสุดมาก่อนหรือไม่. เจตนาเดิมของ endTouched คือกัน auto-fill ทับตอนพิมพ์เวลาเริ่มเอง ไม่ใช่ตอนกดชิปที่โฆษณาว่าเป็นช่วงเวลา
  • ป้ายชิปเป็นช่วงเสมอ — 13:00–14:00 ไม่ใช่ 13:00 แม้คิวงานจะไม่ได้ตั้ง durationMinutes (ตกไปที่ 1 ชม.)
  • ยุบกล่อง “ว่างทั้งวัน” เป็นบรรทัดเดียว ในขั้นเลือกเวลา — คืนพื้นที่ ~300px ให้ตัวเลือกเวลา
  • ปุ่ม CTA เลิกกลายเป็น error — ป้ายคงเป็น “ยืนยัน …” เสมอ (disabled เมื่อยังไม่พร้อม) ส่วนข้อความผิดพลาดอยู่ใต้ช่องที่ผิดจริงที่เดียว ไม่พูดซ้ำสองที่
  • ยังต้องคิดเป็นเวลาสิ้นสุดอยู่ดี — นี่คือข้อจำกัดที่เหลืออยู่ของแบบนี้ ถ้ายอมรับได้ก็เป็นทางที่เร็วที่สุด

สิ่งที่เหมือนกันทั้ง 3 แบบ (ทำแน่นอนไม่ว่าเลือกอันไหน)

  • ปิดบั๊ก endTouched ที่ทำให้กดช่วงเวลาใหม่แล้วเวลาสิ้นสุดค้างค่าเดิม
  • ยุบกล่อง “ว่างทั้งวัน” เป็นแถบบรรทัดเดียวในขั้นเลือกเวลา (กางดูรายการได้เมื่อวันนั้นมีคิว)
  • ปุ่ม CTA ไม่กลายร่างเป็นข้อความ error — ข้อความผิดพลาดอยู่ใต้ช่องที่ผิดจริงที่เดียว ตาม aria-describedby ที่ผูกไว้อยู่แล้ว
  • ทุก tap target ≥ 44px ตาม PRODUCT.md · ไม่มี emoji (HR12) · ไม่มี arbitrary Tailwind value (HR7) · สีทุกค่าเป็น token ของ Paces

ยังไม่ได้ตัดสิน (ต้องถามก่อนลงมือ)

  • หน้าต่าง 08:00–20:00 ที่ hardcode ไว้ — ปุ่ม “เวลาอื่น” ในแบบ A เป็นทางออกชั่วคราว. ทางที่ถูกคือมี “เวลาทำการ” ต่อคิวงาน ซึ่ง user เคาะไว้เมื่อ 2026-08-09 ว่า “ยังไม่ต้องมี” — ถ้าจะทำต้องเป็นงานแยก (แตะ schema)
  • ชุดชิประยะเวลา ที่วาดไว้คือ 30 นาที / 1 / 1.5 / 2 (+3 บนจอกว้าง) — ควรผูกกับ durationMinutes ของคิวงานแค่ไหน (เช่น ร้านตั้ง 45 นาที ควรได้ 45/90/135 แทนไหม)
  • ความละเอียดของเวลาเริ่ม — ตอนนี้ทีละ 1 ชม. ร้านที่นัดทีละครึ่งชั่วโมงต้องใช้ “กำหนดเอง” ทุกครั้ง
