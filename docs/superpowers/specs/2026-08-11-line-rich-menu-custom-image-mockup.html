คำอธิบายปุ่ม (ไม่ปรากฏบนภาพ)

เส้นกริดมาจาก layoutBounds() ตัวเดียวกับที่ส่งพิกัดให้ LINE ไม่ใช่กริดที่วาดแยกด้วยสูตรอื่น — ถ้าวาดคนละสูตร ร้านจะเห็นตรงแต่ลูกค้ากดผิดช่อง

ภาพนี้เป็นแนวตั้งหรือเกือบจัตุรัสเกินไป — เมนูลัดต้องเป็นภาพแนวนอนมาก (กว้างอย่างน้อย 1.45 เท่าของสูง คล้ายแบนเนอร์) ลองครอปภาพให้กว้างขึ้นหรือเลือกภาพใหม่
ไฟล์นี้ยังใหญ่เกิน 1 MB แม้บีบอัดแล้ว — ภาพที่มีรายละเอียดเยอะบีบอัดได้ยาก ลองใช้ภาพกราฟิกที่เรียบกว่า หรือถ่ายภาพใหม่ที่ความละเอียดต่ำลง

ไฮไลต์ใช้ onFocus/onBlur ไม่ใช่ hover — มือถือไม่มี hover และเป็นอุปกรณ์หลักของผู้ขาย · ข้อความ error ทุกอันบอกทางแก้ที่ทำได้จริง ไม่ใช่ “ไฟล์ผิดพลาด”

⑤ เดสก์ท็อป ≥1024px — 2 คอลัมน์เดิม ปุ่มอยู่บนหัว

สิ่งที่ยึดจากของจริง
• เส้นกริด/เลขช่องคำนวณจาก layoutBounds() ตัวเดียวกับที่ส่งพิกัดพื้นที่กดให้ LINE — ถ้าคนละสูตร ร้านเห็นตรงแต่ลูกค้ากดผิดช่อง
• รองรับ 2 / 3 / 4 / 6 ช่อง เท่านั้น · 3 ช่อง = T-split (บนเต็มแถว) · 6 ช่อง = แบบเดียวกับ ref ที่ส่งมา
• เกณฑ์ภาพ JPG/PNG ≤1MB · กว้าง 800–2500 · สูง ≥250 · อัตราส่วน ≥1.45 — ตรวจซ้ำที่ server ด้วย validateRichMenuImage ที่คืนเหตุผลทุกข้อพร้อมกัน
• เส้นกริดเป็นเส้นคู่ (ขาวทึบนอก + primary ประใน) เพราะเส้นสีเดียวจะจมหายถ้าภาพร้านมีสีตรงกับเส้น — Paces ไม่มี primitive สำหรับกรณีนี้ ต้อง compose เอง
• label ของช่อง LINE กำหนดเป็น optional และไม่มีเพดานตัวอักษรระบุไว้ (ยืนยันจากซอร์สทางการ) — ที่ฟอร์มเราบังคับกรอกและจำกัด 60 ตัว เป็นการตัดสินใจของเราเอง ไม่ใช่ข้อบังคับของ LINE
