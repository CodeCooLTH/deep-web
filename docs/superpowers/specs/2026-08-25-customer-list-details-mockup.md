# หน้าลูกค้ารอบแก้ — ยึด component ของธีม (Hard Rule 1)

> 🛑 **ยังไม่แตะโค้ดจริงสักบรรทัด** — เอกสารนี้ + ไฟล์ HTML คู่กัน มีไว้ให้ user ดูก่อนตัดสินใจ

## 1. ที่มา

งาน 00057 ขึ้น prod ไปแล้ว (2026-08-24) แต่ user แจ้งว่า **"เป็นที่ UI แน่ ๆ"** และสั่ง 3 ข้อ:

1. ใช้ UI จาก component ของธีมตาม Hard Rule
2. **หน้า List** → ทำตามหน้า `apps/ecommerce/orders` ของธีม
3. **หน้า Details** → **ออกแบบใหม่**

ผ่าน `safepay-ux` แล้ว (HR8) — แต่ **spec ที่ ux ส่งกลับมาไม่ได้ออกแบบหน้า Details ใหม่** (สรุปว่า "คงเดิมทั้งหมด" แล้วแก้ 3 จุดเล็ก: ขนาดตัวเลข/ระยะห่าง/ลำดับบนมือถือ) ⇒ Controller ไม่รับข้อนั้น และออกแบบ Details ใหม่บนโครง `order-details` ของธีมแทน เพราะถ้าส่ง mockup ตาม ux ไป user จะได้ดูหน้าเดิมที่เพิ่งบอกว่าไม่พอใจ

## 2. หน้า List — ตามหน้า `orders` ของธีม

### โครงที่ยกมา

```
theme/paces/Admin/TS/src/app/(admin)/apps/ecommerce/(orders)/orders/
├── page.tsx                      → grid การ์ดสถิติ + การ์ดตาราง
├── components/OrdersStatCard.tsx → การ์ดสถิติ 1 ใบ
└── components/OrdersList.tsx     → การ์ดตาราง (header/filter/table/footer)
```

**สิ่งที่เพิ่มจริง = แถวการ์ดสถิติ 5 ใบด้านบน** — นี่คือความต่างภาพใหญ่ที่สุดที่ทำให้หน้าเดิม "ไม่รู้สึกเหมือนธีม" เพราะหน้า `orders` ของธีมมีแถวนี้ก่อนตารางเสมอ ส่วนการ์ดตารางด้านล่าง (ค้นหา + ตัวกรอง + `DataTable` + `TablePagination`) ของเดิมตรงกับธีมอยู่แล้ว

### class ที่ต้องใช้ (ยกจากธีมตรงตัว)

```tsx
{/* grid — จาก page.tsx ของธีม */}
<div className="mb-1.25 grid grid-cols-1 gap-1.25 md:grid-cols-2 lg:grid-cols-5">

{/* การ์ด 1 ใบ — Base: OrdersStatCard.tsx */}
<div className="card">
  <div className="card-body">
    <div className="mb-5 flex w-full items-center justify-between gap-3">
      <h3 className="text-lg font-bold tabular-nums">{value}</h3>
      <div className={cn('size-9 flex items-center justify-center rounded-full!', tone)}>
        <Icon icon={icon} className="size-5.5 text-white" />
      </div>
    </div>
    <div className="flex flex-col gap-0.5">
      <span className="text-xs font-bold">{title}</span>
      {caption && <span className="text-2xs text-default-400">{caption}</span>}
    </div>
  </div>
</div>
```

### 5 เมตริก (ทุกตัวมีข้อมูลจริงรองรับ)

| # | หัวข้อ | สีวงไอคอน | caption | ที่มาของตัวเลข |
|---|---|---|---|---|
| 1 | ลูกค้าทั้งหมด | `bg-primary` | — | `entries.length` |
| 2 | ยอดซื้อสะสมรวม | `bg-info` | `เฉลี่ย ฿{n}/คน` | Σ `totalSpent` |
| 3 | ลูกค้าซื้อซ้ำ | `bg-dark` | `{n}% ของลูกค้าทั้งหมด` | `totalOrders >= 2` (เกณฑ์เดียวกับตัวกรอง BR-CUSTP-13) |
| 4 | เป็นสมาชิกแล้ว | `bg-success` | `{n}% ของลูกค้าทั้งหมด` | `isRegistered` |
| 5 | มีสัญญาณเตือน | `bg-warning` | `{n}% ของลูกค้าทั้งหมด` | `hasBehaviorWarning(customerBadges(...))` — ฟังก์ชันเดียวกับตัวกรอง |

**คำนวณจาก `entries` ก้อนเดียวที่ `page.tsx` มีอยู่แล้ว — ห้าม query ซ้ำ** และ **ไม่ผูกกับตัวกรอง/คำค้นหา** (เป็น KPI ของร้าน ไม่ใช่ของผลลัพธ์ที่กรองอยู่ — ตรงกับพฤติกรรม stat card ของธีม)

### 3 อย่างของธีมที่จงใจไม่เอามา

| ของธีม | ทำไมไม่เอา |
|---|---|
| **badge % เปลี่ยนแปลง** (เขียว/แดง) | เราไม่มีข้อมูลย้อนหลังมาเทียบ — ธีมมีเพราะเป็น demo data ใส่แล้วเป็นเลขปลอม |
| **`<CountUp>` เลขวิ่งตอนโหลด** | หน้าเครื่องมือทำงานต้องอ่านได้ทันที ไม่ต้องรอวิ่ง (`Mode: Operate`) |
| **checkbox เลือกแถว + ปุ่มลบ + คอลัมน์ Actions (`👁 ✏ 🗑`)** | ลูกค้าลบไม่ได้/เพิ่มเองไม่ได้ (ไม่มี use case) และทั้งระบบเปลี่ยนมาใช้ "กดทั้งแถว" (`DataTable.onRowClick`) แทนปุ่มไอคอนท้ายแถวไปแล้วตั้งแต่ critique 2026-08-09 |

**ตัวกรองยังใช้ `FilterDropdown` ไม่ใช่ `<select>` ของธีม** — `paces-component-reference.md` บังคับไว้สำหรับ list ที่ re-render (native select ค้าง state) นี่คือ fix ที่ `/orders` ใช้อยู่แล้ว ไม่ใช่การไม่ตามธีม

### Empty state

ร้านที่ยังไม่มีลูกค้าเลย → **ไม่ render แถวสถิติ** (การ์ด 5 ใบที่อ่านว่า 0 ทั้งหมดคือข้อมูลซ้ำกับข้อความว่างข้างล่าง) ไปที่การ์ดข้อความว่างใบเดียว ไม่มีปุ่ม (ไม่มี action ให้ทำจากหน้านี้)

## 3. หน้า Details — ออกแบบใหม่บนโครง `order-details` ของธีม

### โครงที่ยกมา

```tsx
{/* theme/.../ecommerce/(orders)/order-details/page.tsx */}
<div className="grid grid-cols-1 lg:grid-cols-4 gap-base">
  <div className="space-y-base lg:col-span-3"> …เนื้อหาหลัก… </div>
  <div className="space-y-base">              …การ์ดข้อมูล… </div>
</div>
```

| ตำแหน่ง | ธีม (ออเดอร์) | ของเรา (ลูกค้า) |
|---|---|---|
| ซ้าย `col-span-3` | `OrderSummary` (ตารางสินค้า) | **ตารางคำสั่งซื้อทั้งหมด** ของลูกค้าคนนี้ |
| ซ้าย `col-span-3` | `ShippingActivity` (ไทม์ไลน์) | **ไทม์ไลน์กิจกรรมลูกค้า** ← ของใหม่ |
| ขวา | `CustomerDetails` | **ข้อมูลลูกค้า** (avatar + รายการติดต่อมีไอคอนกลม + ปุ่มลัด) |
| ขวา | `ShippingAddress` | **ที่อยู่ล่าสุด** |
| ขวา | `BillingDetails` | **ยอดซื้อสะสม + สรุปตัวเลข** และ **การ์ดสัญญาณที่ควรระวัง** |

### ของใหม่ 4 อย่างที่ยังไม่มีในเวอร์ชันที่ขึ้น prod

1. **ตารางออเดอร์เต็มรูป** (หัวคอลัมน์ + คอลัมน์สถานะพัสดุ) แทนรายการบรรทัดบาง ๆ
2. **ไทม์ไลน์กิจกรรม** — ยกจาก `ShippingActivity.tsx` ของธีม (เส้นประ `after:border-dashed` + จุดสี `size-3.5 rounded-full`) เล่าเรื่องลูกค้าคนนี้ตามเวลา
3. **การ์ด "ข้อมูลลูกค้า"** เป็น `ul` มีไอคอนกลม (ยกจาก `CustomerDetails.tsx` ของธีม) แทนบล็อกข้อความลอย ๆ
4. ป้าย **"สมาชิก"** ที่หัวการ์ด + การ์ดสัญญาณเตือนแยกหัวข้อ **"กับร้านนี้" / "ทั้งระบบ"** ชัดเจน

### ที่คงไว้จากของเดิม (มีเหตุผล ไม่ใช่ความมักง่าย)

- ยอดเฉลี่ยต่อบิลแสดง `—` ไม่ใช่ `฿0` เมื่อไม่มีใบที่นับเป็นยอดขาย
- จำนวนยกเลิกเป็นตัวเลขของตัวเอง (ห้ามให้ผู้ใช้ลบเลขเอง)
- ไม่มีเธรด/ไม่มีเบอร์ → **ไม่ render ปุ่ม** ไม่ใช่ disabled เทา
- การ์ดสัญญาณใช้ `border-s-3 border-warning` (ข้อยกเว้นที่ขึ้นทะเบียนใน `DESIGN.md`) และ **สีเหลืองเท่านั้น ห้ามแดง ห้ามเขียว**
- ที่อยู่ล่าสุด = ใบล่าสุด **ที่มีที่อยู่** ไม่ใช่ใบล่าสุดเฉย ๆ

### ลำดับบนมือถือ

`grid-cols-1` ⇒ DOM order = visual order ⇒ **ข้อมูลลูกค้า/ความน่าเชื่อถือต้องมาก่อน ตารางออเดอร์ตามหลัง** (ของเดิมสลับกัน เพราะ `col-span-7` อยู่ก่อนใน source)

## 4. ข้อจำกัดของข้อมูลที่บังคับการออกแบบ

ธีมมีช่องพวกนี้ แต่เราไม่มีข้อมูล — **ใส่ไปจะเป็นช่องว่างเปล่าหรือข้อมูลปลอม**

| ธีมมี | เราไม่มีเพราะ |
|---|---|
| รูปโปรไฟล์ลูกค้า | Meta บล็อกรูป Messenger จนกว่าจะได้ Advanced Access → ใช้ตัวย่อในวงกลม |
| อีเมลใต้ชื่อ | `Customer.email` เป็น **null ทุกแถวบน prod** (0/477) |
| วิธีชำระเงิน (โลโก้บัตร) | ไม่ได้เก็บวิธีชำระเงินประจำต่อลูกค้า |
| ธงชาติ / "Since 2020" | ไม่มีแนวคิดประเทศของผู้ซื้อ · "ลูกค้าตั้งแต่" ใช้ `firstOrderISO` แทนได้จริง |

## 5. ต้องให้ user เคาะก่อน implement

| # | คำถาม | ค่าตั้งต้นที่เสนอ |
|---|---|---|
| 1 | การ์ดสถิติ 5 ใบ เอาชุดนี้ไหม | ลูกค้าทั้งหมด · ยอดซื้อสะสมรวม · ลูกค้าซื้อซ้ำ · เป็นสมาชิกแล้ว · มีสัญญาณเตือน |
| 2 | **ไทม์ไลน์กิจกรรม** เอาไหม (ของใหม่) | เอา — เล่า สั่งซื้อ/ยกเลิก/ตีกลับ/ลูกค้าใหม่ |
| 3 | ระยะห่างการ์ดสถิติ | ธีมใช้ `gap-1.25` (5px) ซึ่งชิดมาก vs `gap-base` (20px) เท่าจังหวะปกติของระบบ |
| 4 | กดการ์ดสถิติแล้วกรองตารางเลยไหม | ยังไม่ใส่ (ธีมเป็นป้ายนิ่ง) — เพิ่มทีหลังง่าย แค่ห่อด้วย `<Link href="?warn=1">` |
