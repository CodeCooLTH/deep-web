00038 — ตอบกลับคอมเมนต์ (Comment Auto-Reply & Private Reply)

ตั้งค่าต่อเพจให้ระบบตอบใต้คอมเมนต์และทักแชทให้อัตโนมัติ + ทำให้ปุ่ม “ทักแชท” ในแท็บความคิดเห็นกดได้จริง (ปิดหนี้ที่ค้างจาก 00029). ทุกค่าสีและขนาดในหน้านี้คัดจาก token จริงของ Paces ไม่ได้กะเอา — .card radius 8px, .btn 34px, --color-primary #236dc9, badge ใช้ bg-{semantic}/15 ตาม Hard Rule 7

คู่กับ 2026-08-08-00038-comment-auto-reply-design.md · ขอบเขตรอบนี้ = Facebook เท่านั้น (IG เฟส 2 แต่วาดไว้ให้เห็นว่าโครงรองรับ)

ข้อจำกัดของ Meta ที่ทุกจอในหน้านี้ต้องเคารพ

  • ทักแชทได้ครั้งเดียวต่อคอมเมนต์ — กดพลาดย้อนไม่ได้ ปุ่มจึงต้องเปิดกล่องพิมพ์ก่อน ไม่ส่งทันที
  • ภายใน 7 วันนับจากเวลาคอมเมนต์ — เกินแล้วปุ่มต้องปิดพร้อมบอกเหตุผล
  • ทักแล้วยังคุยต่อไม่ได้ จนกว่าลูกค้าจะตอบ — ห้ามออกแบบให้มีข้อความตามหลัง

1 · หน้าตั้งค่า /settings/comment-reply

การ์ดหนึ่งใบต่อเพจที่เชื่อมไว้ (ยกโครงจาก /settings/auto-reply ตาม Hard Rule 1) — 2 สวิตช์แยกกัน แต่ละตัวมีข้อความของตัวเอง ค่าตั้งต้นทั้งคู่ = ปิด

จุดที่ต้องระวังตอน implement

  • ShopChannel มี accessTokenEnc อยู่แถวเดียวกับค่าตั้งค่าเหล่านี้ — ทุก query ที่ส่งออกไปหา client ต้อง select ระบุคอลัมน์ ห้ามคืนทั้งแถว
  • เพจที่ status = 'TOKEN_INVALID' ต้องขึ้นแถบเตือนให้เชื่อมใหม่ และปิดสวิตช์ทั้งใบ — ไม่ใช่ปล่อยให้ตั้งค่าได้แล้วยิงไม่ออกเงียบ ๆ
  • ปิดสวิตช์ B ไม่ปิดปุ่มแมนนวลในแท็บความคิดเห็น (มติ D-6)

2 · ปุ่ม “ทักแชท” ในแท็บความคิดเห็น — 4 สถานะ

วันนี้ตรงนี้เป็น ป้ายนับถอยหลังเฉย ๆ (CommentsClient.tsx:1572 เขียนยอมรับไว้เองว่า “ยังไม่ใช่ปุ่มกดได้”) — รอบนี้ทำให้กดได้จริง ตัวนับ 7 วันคำนวณถูกอยู่แล้วทั้ง service และ UI ไม่ต้องแตะ

กล่องพิมพ์ก่อนส่ง — ทำไมไม่ส่งทันทีที่กด

  • Meta ให้สิทธิ์ทักแค่ครั้งเดียวต่อคอมเมนต์ กดพลาดคือเสียสิทธิ์ถาวร จึงต้องมีจังหวะให้อ่านทวน
  • กล่องเติมข้อความจาก commentPrivateReplyText ของเพจไว้ให้แล้ว (ถ้าตั้งไว้) — แก้ก่อนส่งได้
  • ในกล่องต้องมีคำเตือนเดิมที่หน้านี้มีอยู่แล้ว: คอมเมนต์นี้เป็นสาธารณะ ไม่ใช้กับช่องนี้ — ช่องนี้เป็นข้อความส่วนตัว ต้องเขียนคำเตือนคนละแบบ ไม่ยกมาใช้ซ้ำ
  • ปุ่มแมนนวลจำกัดที่ “1 ครั้งต่อคอมเมนต์” ไม่ใช่ “1 ครั้งต่อคน/โพสต์” — กฎคน/โพสต์เป็นกฎกันสแปมของบอท ถ้าเอามาครอบปุ่มด้วย คนที่คอมเมนต์ 2 ครั้งบนโพสต์เดียวจะถูกทักด้วยมือได้แค่ครั้งเดียวทั้งที่ Meta อนุญาต (ดู §5.3 ของไฟล์ .md)

3 · สถานะ 3 ชั้น + ชิปกรอง

ถ้าไม่ทำข้อนี้ ตัวนับ ยังไม่ตอบ จะกลายเป็น 0 เกือบตลอดทันทีที่เปิดบอท เพราะ Meta ส่งคำตอบของบอทกลับเข้ามาเป็นคอมเมนต์ของเพจ แล้วเกณฑ์เดิม (มีคอมเมนต์ลูกที่ isFromPage = true) จะนับว่า “ตอบแล้ว” ทันที — คำถามที่ต้องการคนจริงจะจมหายไปกับคำตอบอัตโนมัติ

สถานะเกณฑ์นับใน badge แท็บไหม
ยังไม่ตอบไม่มีคอมเมนต์ลูกของเพจเลยนับ
บอทตอบแล้วลูกของเพจ ทุกอัน isAutoReply = trueไม่นับ
คนตอบแล้วมีลูกของเพจอย่างน้อยหนึ่งอันที่ isAutoReply = falseไม่นับ

ตัวเลขทั้ง 4 ต้องมาจาก symbol เดียว

  • จอนี้เคยโชว์ “ยังไม่ตอบ 7 กับ 8” พร้อมกันมาแล้ว (docs/conventions/sibling-surface-parity.md) — ตัวนับบนชิป ตัวนับบน badge แท็บ และตัวกรองที่ใช้จริง ต้องคำนวณจากฟังก์ชันเดียว
  • หน่วยของ badge แท็บยังเป็น จำนวนโพสต์ ไม่ใช่จำนวนคอมเมนต์ — countUnansweredForShop อธิบายเหตุผลไว้แล้ว (ต้องเป็นหน่วยเดียวกับ badge แท็บ “ข้อความ” ที่นับจำนวนเธรด)

4 · เมนูใหม่ในกลุ่ม CHAT

เพิ่มรายการที่ 4 ต่อจาก “ตอบกลับอัตโนมัติ” — กลุ่ม CHAT ตั้งใจรวม “ทุกอย่างที่เกี่ยวกับการคุยกับลูกค้า ทั้งที่คนตอบเองและที่ระบบตอบแทน” อยู่แล้ว (คอมเมนต์ใน seller-menu.ts:93)

รอ user ยืนยัน 1 จุด

  • ไอคอนเมนู — ในภาพใช้ tabler-message-reply (ลูกศรย้อนกลับ) เพื่อนบ้านคือ message-circle / message-bolt / robot. ตาม docs/conventions/no-emoji-use-icons.md ห้ามเดาไอคอนเอง จึงยกมาให้เลือก ไม่ได้ตัดสินแทน
  • เมนูนี้ต้องใส่ใน VERTICAL_VISIBLE_SLUGS ของทุก vertical ที่เห็นเมนู “ข้อความ” อยู่แล้ว — seller-menu.ts เป็น allow-list + fail-closed (00028) ลืมใส่ = เมนูหายเงียบ ไม่มี error
