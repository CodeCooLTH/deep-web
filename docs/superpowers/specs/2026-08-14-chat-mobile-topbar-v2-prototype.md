## 1. ขอบเขต

**แถวหัว (`card-header`)** + **แถวชิปใต้หัว (`ThreadChipStrip`)** — แถวชิปถูกเพิ่มเข้าขอบเขตทีหลัง (user สั่งรอบ 2026-08-15 ดู §5.8)

~~แถวหัวแถวเดียวเท่านั้น~~ — user ยืนยันเอง: *"ผมแค่อยากออกแบบ บน หัวใหม่"* / *"แต่อันอื่นยังอยากให้เหมือนเดิม"*

คงเดิมทุกประการ ไม่แตะ: `ThreadChipStrip` (แถว "จากโฆษณา") · บรรทัดระบบของ Meta · บล็อก "ตอนนี้ Meta AI กำลังตอบลูกค้าในแชทนี้อยู่ + ปุ่มตอบเอง" · ตัวนับ 24 ชม. · แถบ token เสีย · สตรีมข้อความ

> **บันทึกความผิดพลาด:** ฉบับแรกของสเปกนี้ตั้งสมมติฐานเองว่า "เมนูบน = ทั้งก้อน" แล้วเสนอ 3 แบบที่ยุบ/ย้าย/ถอดแถวชิป — ผิดขอบเขตทั้งสามแบบ ทิ้งไปแล้ว จับได้เพราะ user ถามว่า *"แล้วพวก panel noti อื่น ๆ จะไปไว้ไหน"* ซึ่งเป็นคำถามที่ไม่ควรต้องมีคำตอบตั้งแต่แรก

## 2. โจทย์

จัดของ 4 อย่างในแถวเดียว (~61px × 320–390px): ปุ่มย้อนกลับ · ตัวตนลูกค้า (รูป + ตราเพจ + ชื่อ) · คลังไฟล์ + ตัวนับ · `⋯` (ข้อมูลลูกค้า · คำสั่งซื้อ · สวิตช์เสียง 2 ตัว)

ปัญหาจากภาพจริง:

1. ปุ่ม 3 ตัวมี 3 หน้าตา — ย้อนกลับมีกรอบ · โฟลเดอร์มีกรอบ · `⋮` **ไม่มีกรอบ**
2. ไอคอนเปล่าทั้งแถว ไม่มีคำสักตัว — มือถือไม่มี hover
3. กระดิ่งปิดเสียงล้นออกนอกปุ่ม `⋮`
4. ชื่อลูกค้าได้แค่ **85px** ที่ 320px และไม่มีที่ไหนบอกชื่อเพจเป็นตัวหนังสือ

## 4. สี่แบบ

### A — ซ่อมตามธีม (ไอคอน 2 ตัวเหมือนเดิม)

ซ่อม 5 ข้อ ไม่เพิ่มไม่ลด · บรรทัด 2 ใส่ชื่อเพจ · ปุ่มขวาห่อกลุ่ม `gap-1.5` มีกรอบเท่ากันทั้งคู่

```
┌──────────────────────────────────────────────┐
│ [←] (รูป) มูหำหมัด มณีหยา       [ไฟล์3] [⋯ปิดเสียง] │
│           ชาเขียวเหนี่ยวทรัพย์                │
└──────────────────────────────────────────────┘
40 + 30 + 12 + 36 + 12 + [ชื่อ] + 12 + 37 + 6 + 37 = 222  → ชื่อ 98px
```

- **ได้:** แรงน้อยสุด ทุกบรรทัดชี้ต้นทางในธีมได้ · ชื่อเพจอ่านได้บนมือถือครั้งแรก · ปุ่มหน้าตาเดียวกันทั้งแถว · ตัวบอกปิดเสียงไม่ล้น
- **ยังไม่แก้:** **ปุ่มยังเป็นไอคอนเปล่า** — ปัญหาข้อ 2 ยังอยู่ครบ

### B — ปุ่มไฟล์มีคำ

เหมือน A + เปลี่ยนปุ่มคลังไฟล์เป็น `btn btn-sm border-default-300` มีคำว่า **"ไฟล์"** และตัวนับเป็น `badge` ในปุ่ม

```
┌──────────────────────────────────────────────┐
│ [←] (รูป) มูหำหมัด…        [ไอคอน ไฟล์ 3] [⋯ปิดเสียง] │
│           ชาเขียวเหนี่ยวทรัพย์                │
└──────────────────────────────────────────────┘
40 + 30 + 12 + 36 + 12 + [ชื่อ] + 12 + 76 + 6 + 37 = 261  → ชื่อ 59px
```

- **ได้:** แก้ข้อ 2 ตรง ๆ — คำว่า "ไฟล์" อยู่บนจอ ตอบ report ต้นเรื่องที่ทำให้ปุ่มนี้เกิด · ตัวนับอยู่ในปุ่มเป็น `badge` ตาม pattern ธีม แทน badge ลอยมุมที่ชนขอบ
- **เสีย:** ชื่อเหลือ **59px** ที่ 320px — **แคบกว่าปัจจุบัน** ⇒ ต้องยอมให้ปุ่มยุบเป็นไอคอนที่ `<375px` หรือยอมให้ชื่อถูกตัด · ปุ่มเดียวมีคำอีกปุ่มไม่มี (ยอมรับได้เพราะ `⋯` เป็นสัญลักษณ์สากล)

### C — ตัวตนกดได้ (`⋯` ตัวเดียว)

เหมือน A + ทั้งกลุ่ม รูป+ชื่อ+ชื่อเพจ เป็นปุ่มเดียวเปิดแผงลูกค้า (เป้าแตะ ~180×40) · ปุ่มขวาเหลือ `⋯` ตัวเดียว **คลังไฟล์ย้ายเป็นรายการแรกในเมนู พร้อมคำและตัวนับ**

```
┌──────────────────────────────────────────────┐
│ [←] (รูป) มูหำหมัด มณีหยา ›            [⋯ปิดเสียง] │
│           ชาเขียวเหนี่ยวทรัพย์                │
└──────────────────────────────────────────────┘
40 + 30 + 12 + 36 + 12 + [ชื่อ + chevron 18] + 12 + 37 = 179  → ชื่อ 141px
```

- **ได้:** ชื่อได้ **141px** กว้างสุด · เป้าแตะใหญ่สุดและตรงกับที่คนแตะโดยสัญชาตญาณ · แถวหัวสะอาดสุด
- **เสีย:** 🛑 **คลังไฟล์ลึกลง 1 ชั้น (1 แตะ → 2 แตะ)** สวนทางกับ report ที่ทำให้ปุ่มนี้ถูกยกขึ้นมาเมื่อเช้าวันเดียวกัน · "แตะชื่อ = เปิดแผง" ไม่มีสัญญาณในตัว ต้องมี `chevron-right` จาง ๆ กำกับ · ตัวนับไฟล์ไม่เห็นจากนอกเมนู และถ้าจะทำจุดบน `⋯` จะชนกับตัวบอกปิดเสียงที่อยู่มุมเดียวกัน


### D — A + คำเฉพาะจอที่มีที่พอ  **(ที่แนะนำ)**

ฐานคือ A แล้วปุ่มคลังไฟล์ **ผันตามความกว้างจอ**: `<375px` เป็นไอคอนเปล่า · `≥375px` กางเป็นปุ่มมีคำ "ไฟล์"

```
320px  [←] (รูป) มูหำหมัด มณีหยา       [ไฟล์3] [⋯ปิดเสียง]     ชื่อ 98px
390px  [←] (รูป) มูหำหมัด มณีหยา  [ไอคอน ไฟล์ 3] [⋯ปิดเสียง]     ชื่อ 129px
```

- **ได้:** ได้คำกำกับบนจอที่ผู้ใช้จริงเกือบทั้งหมดใช้ (iPhone SE รุ่นเล็กสุดที่ยังขาย = 375px) · ที่ 320px ไม่ทำให้ชื่อพัง ยังได้ 98px เท่า A · ไม่มีอะไรหายหรือลึกลง
- **ต้องยอม:** ต้องใช้ `min-[375px]` ซึ่งเป็น **arbitrary breakpoint — ธีมไม่มี `xs`** ⇒ ต้องเขียนคอมเมนต์กำกับตาม HR7 (ทางเลือกคือใช้ `sm:` = 640px ซึ่งกว้างเกินไปมาก จะไม่มีคำบนมือถือเลย) · ปุ่มเปลี่ยนรูปร่างตามจอ (ในทางปฏิบัติแทบไม่มีผล เครื่องหนึ่งความกว้างคงที่)

## 5.5 คำตัดสินจาก `safepay-ux` (Mode: Operate)

**เลือก D** (ux เรียกว่า "A+") — เหตุผลเดียวกับที่ผมเสนอ แต่ ux เติมฐานให้แน่นขึ้น:

- **A ไม่ใช่ "ทางเลือกออกแบบ" แต่คือการกลับไปทำตามธีมที่ควรเป็นอยู่แล้ว** ⇒ เป็นฐานบังคับของทุกแบบ ไม่มี trade-off ให้ชั่ง
- **ตัด C:** ย้อนงานที่เพิ่งเสร็จเมื่อเช้าวันเดียวกัน (คลังไฟล์เพิ่งลด 4 ชั้น → 1 แตะ) — "แก้ปัญหาหนึ่งแล้วปลุกปัญหาที่เพิ่งปิดกลับมา"
- **ตัด B เดี่ยว:** ตาม `PRODUCT.md` กลุ่มผู้ใช้มี digital-literacy ต่ำ/ผู้สูงวัย ⇒ **"รู้ว่ากำลังคุยกับใคร" สำคัญกว่า "รู้ความหมายไอคอน folder"** ซึ่งเป็นสัญลักษณ์สากลที่เดาได้ ต่างจากชื่อคนที่เดาไม่ได้เลยถ้าถูกตัดเหลือ 4 ตัวอักษร
- **ไม่มีแบบที่ 4** — พิจารณา 2 แนวแล้วปฏิเสธ: (ก) ทำปุ่มไฟล์เด่นด้วย `bg-primary/15` → ขัด One Voice + ธีมตั้งใจให้ปุ่มใน toolbar หน้าตาเดียวกันหมด (ข) C ผสม A → เพิ่มความซับซ้อนโดยไม่ได้แก้อะไรที่ D ยังไม่ได้แก้

## 5.6 🛑 วัดจากม็อกอัพจริงแล้ว — คำแนะนำเปลี่ยนจาก D เป็น **A**

ทั้งผมและ ux ตัดสินจาก **งบพื้นที่** อย่างเดียว โดยไม่เคยเทียบกับ **ความกว้างจริงของชื่อ** เปิดม็อกอัพในเบราว์เซอร์แล้ววัดด้วย `measureText` + `getBoundingClientRect` (Anuphan 600 16px) ได้ผลนี้:

ชื่อในภาพที่ user ส่งมา — "มูหำหมัด มณีหยา" — **ต้องการ 113.1px**

| | 320px | 390px (iPhone 14/15) | 768px |
|---|---|---|---|
| ปัจจุบัน | 85 → ตัด | **113.0 → พอดีเป๊ะ เหลือ 0px** | 113 → เต็ม |
| **A** | 98 → ตัด | **122.8 → เต็ม เหลือ 10px** | 122.8 → เต็ม |
| **D** | 98 → ตัด | **103 → ตัด ขาด 10px** | 122.8 → เต็ม |

**D ทำให้ชื่อถูกตัดบน iPhone รุ่นมาตรฐาน ทั้งที่ปัจจุบันยังไม่ตัด** — จอต่ำสุดที่ปุ่มมีคำใส่ได้โดยชื่อไม่ถูกตัดคือ **401px** ⇒ `min-[375px]` ที่ทั้งผมและ ux เลือกไว้ **ผิดตัวเลข** ต้องเป็น `min-[401px]` ซึ่งครอบแค่ Pro Max (430px) = ผู้ใช้ส่วนน้อย ⇒ **ปุ่มมีคำแทบไม่มีประโยชน์บนมือถือจริง**

> บทเรียนซ้ำจาก `docs/retro/2026-08-12-queues-day-sheet-retrospective.md`: *"ม็อกอัพไม่มีวันเจอเพราะ fixture ใช้ชื่อสั้นกว่าครึ่ง"* — รอบนี้ใช้ชื่อจริงจากภาพที่ user ส่งมา จึงเจอ **แต่เจอตอนเปิดม็อกอัพดู ไม่ใช่ตอนคำนวณ** — ตัวเลขงบพื้นที่ที่กางไว้อย่างละเอียดทั้ง 4 แบบ ไม่มีอันไหนบอกได้ว่าชื่อจะถูกตัดหรือไม่ เพราะไม่เคยมีใครวัดว่า "ชื่อยาวเท่าไร"

### เรื่องปุ่มย้อนกลับ 30 vs 37px — ตอบได้แล้วด้วยเลขเดียวกัน

| | 320px | 390px |
|---|---|---|
| A + ย้อนกลับ **30px** (ตามธีม) | 98 → ตัด | 122.8 → **เต็ม เหลือ 10px** |
| A + ย้อนกลับ **37px** (คงเดิม) | 91 → ตัด | 115.8 → **เต็ม เหลือ 2.7px** |

**ทั้งสองทางชื่อเต็มที่ 390px** ⇒ 7px นั้นไม่ได้เป็นตัวตัดสินว่าชื่อจะถูกตัดหรือไม่ ⇒ **คง 37px ได้ ไม่ต้องแลกเป้าแตะ** — แต่ 30px ให้ buffer มากกว่า 4 เท่า (10px vs 2.7px) สำหรับชื่อที่ยาวกว่านี้เล็กน้อย

**ชื่อที่ยาวจริง ๆ ถูกตัดทุกแบบอยู่ดี** — "ณัฐวรรณ ศรีสุวรรณวงศ์" ต้องการ 166px ซึ่งไม่มีแบบไหนที่ `<768px` ให้ได้

**F — เติมป้ายลูกค้าเข้าแถวชิปเดิม** (`?variant=F`)
คงโครง `ThreadChipStrip` ทุกอย่าง เพิ่มรายการเข้า array ในลำดับที่ 3: คำเตือน → ออเดอร์ → **ป้ายลูกค้า** → ที่มา

**G — แยก 2 ระดับ** (`?variant=G`)
แถวชิปพื้นขาวเหลือ**เฉพาะสิ่งที่ต้องลงมือ** (คำเตือน + สถานะออเดอร์) · ข้อมูลนิ่งลงไป**แถบจางบรรทัดเดียว** พื้นเทา ตัวเล็ก ไม่มีกรอบชิป: ป้ายลูกค้า · ยอดซื้อ · ที่มา

- ได้: **ที่ 390px อ่านได้ 3 รายการรวด** ("ลูกค้าเก่า · 4 ออเดอร์ · ตีกลับ 2 · จากโฆษณา") เพราะไม่มีกรอบชิปกินที่ · อ่านออกใน 1 วินาทีว่ามีอะไรต้องทำไหม (ไม่มีชิปสี = ไม่มีอะไรค้าง) · ไม่มีคำเตือน → แถวชิปหายทั้งแถว เหลือ **26px** (จาก 44)
- เสีย: เพิ่มรูปแบบใหม่ (แถบจาง) ที่**ยังไม่มี precedent ตรง ๆ ในธีม** ต้องหา pattern รองรับก่อน · ที่มาของแชทเคยกดกางดูรูปโฆษณา/คอมเมนต์ต้นทางได้ พอเป็นแถบจางต้องตัดสินว่ายังกดได้ไหม · เมื่อมีคำเตือน 2 แถบซ้อน = **70px** สูงกว่าเดิม 26px

**ความเห็น: G** — F ล้มด้วยตัวเองในม็อกอัพ (ของที่เพิ่มเข้าไปมองไม่เห็นบนจอจริง จึงเท่ากับไม่ได้เพิ่ม) ส่วน G แลกความสูงตอนมีคำเตือน (ซึ่งเป็นส่วนน้อย) กับการเห็นข้อมูลมากขึ้นตอนปกติ

หยิบของที่ดีที่สุดของแต่ละแบบ:

- **คำเตือนแบบ H** — แถบสีเต็มความกว้าง มีปุ่มในตัว **โผล่เฉพาะเมื่อมี** (จุดที่ชิปเดิมทำได้แย่ที่สุด: ต้องเลื่อนหา)

```
┌──────────────────────────────────────────────┐
│ [←] (รูป) มูหำหมัด มณีหยา    [🛒4][📁3][⋯]  │  66px
│           ชาเขียวเหนี่ยวทรัพย์                │
```

### ของที่ซ้ำกันเอง (บอกเรื่องเดียวกัน >1 ที่บนจอเดียว)

1. **สถานะ AI โผล่ได้ 3 ที่พร้อมกัน** — บรรทัดในสตรีม + บล็อกแทนช่องพิมพ์ + แถบ manual-override **อ่านจาก `readMetaAiControlMarker` แหล่งเดียวกันเป๊ะ**
2. 🛑 **token ตายขึ้น 2 ที่พร้อมกันแน่นอนบน LINE** (ยืนยันเอง): ชิป `CT:1921` = `isExternal && tokenInvalid` · บล็อกแทน composer `CT:1564` = เงื่อนไขเดิม + `channel==='LINE'` ⇒ **สับเซต ⇒ ขึ้นทั้งคู่เสมอ** และทั้งคู่มีลิงก์ไป `/settings/channels`
3. **โควตา LINE เรื่องเดียว 3 จุด** — ชิป + ตัวเลขบนปุ่มส่ง + placeholder
4. **ที่มาแบบคอมเมนต์ 2 ที่** — ชิป `ctx:comment` + บรรทัดอังกฤษของ Meta ที่ยังลอยในสตรีม ไม่ถูกซ่อน

### ข้อมูลที่มาถึงหน้านี้แล้วแต่ไม่มีที่แสดง (ตรวจเองยืนยันแล้ว)

- 🛑 **`commentOrigin.createdTime`** — grep เจอ **ครั้งเดียวคือบรรทัดประกาศ type** (`CT:747`) ⇒ เวลาที่ลูกค้าคอมเมนต์ ส่งมาแล้วทิ้งทั้งดุ้น
- 🛑 **`commentOrigin.attachmentUrl`** (`CT:745`) — ถูกใช้เป็น**เงื่อนไขเลือกคำ**เท่านั้น (`CT:2218`) ⇒ **รูปที่ลูกค้าแนบมากับคอมเมนต์ไม่เคยถูก render** ต้องกดออกไป Facebook
- **`channelName`** — เหลือที่เดียวคือ `title=` ⇒ มือถือไม่ขึ้น เดสก์ท็อปบัง UI (ตรงกับภาพที่ user ส่ง)
- `adReferral.adTitle` — ถ้ามี `adBody` จะไม่มีวันถูกแสดง (เหลือแต่ใน tooltip)

### อาการเสียที่เห็นจากภาพจริงที่ user ส่งมา (ม็อกอัพไม่มีทางเจอ)

1. **ที่มาโผล่พร้อมกัน 2 อัน** (`จากคอมเมนต์` + `จากโฆษณา`) — ทุกม็อกอัพก่อนหน้าสมมติว่ามีทีละอัน
2. 🛑 **ชิปถูก `max-w-52` + `truncate` ตัดจนไร้ความหมาย** — `เกิน 24 ชั่วโมงแล้ว — ตอบ...` / `ห้องนี้กำลังใช้ทดสอบ Dee...` ⇒ **แย่กว่าไม่มีชิป** และทำให้ทางแก้แบบ F (เติมชิปเข้าไปอีก) ผิดทางยิ่งกว่าที่สรุปไว้
3. **นับถอยหลังกินหัวเธรดมหาศาลและวินาทีเดินตลอด** — `ใกล้หมดเวลาตอบ — เหลือ 3 ชั่วโมง 53 นาที 33 วินาที` อยู่ในสายตา 4 ชม. ติด
4. **`title=` tooltip บังชื่อลูกค้า** บนเดสก์ท็อป
5. **การ์ดโฆษณาที่กางมี 2 ปุ่มปิด** — `✕` กับ `⌃ ย่อ`
