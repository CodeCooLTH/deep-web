Mockup — ปรับปรุงหน้า /expenses (feature 00016)

โครงใหม่: หน้าเป็น “หน้ารายการ” เต็มตัว — ฟอร์มที่เคยแปะค้างกลางหน้าถูกย้ายเข้า modal ที่เปิดจากปุ่ม “เพิ่มค่าใช้จ่าย” (pattern เดียวกับโมดัลในหน้า orders) และเพิ่มการ์ดสรุปสองใบระหว่าง P&L กับรายการ ทุกอย่างประกอบจาก Paces primitive + token จาก _root.css ตัวจริง (primary #236dc9 ไม่ใช่ม่วง)

สิ่งที่เปลี่ยนจากของเดิม

  • ฟอร์ม → modal — ExpenseForm ไม่แปะกลางหน้าแล้ว ทั้ง “เพิ่ม” และ “แก้ไข” ใช้ modal ตัวเดียวกัน (จบเรื่อง scroll กระโดดขึ้นไปที่ฟอร์มตอนกดแก้ไข)
  • P&L card — จาก 5 ช่องเท่ากันหมด → hero “กำไรสุทธิ” ตัวใหญ่ + 4 ตัวเลขสนับสนุน (ลำดับชั้นชัดขึ้น)
  • การ์ดใหม่ 2 ใบ — “ค่าใช้จ่ายแยกหมวด” (แถบสัดส่วน + legend) และ “สรุปเร็ว” — คำนวณจากรายการในช่วงที่เลือก ไม่ต้องแตะ schema
  • รายการ — จากตารางแบน → จัดกลุ่มตามวันพร้อมยอดรวมรายวัน + แถวมี icon หมวด; มือถือได้แถวการ์ดแทนตารางที่ล้นจอ
  • filter chip ตามหมวด + ค้นหา — ของเดิมตั้งใจไม่ทำเพราะ “list เล็ก” แต่พอสะสมข้ามเดือนแล้วหาไม่เจอ (ข้อนี้รอคุณเคาะว่าเอาไหม)

ยังไม่ตัดสินใจ — รอคุณเคาะ

  • หมวดหมู่ใน modal: ตอนนี้วาดเป็น ปุ่มชิป 7 อัน (icon + ชื่อ) เพราะกดบนมือถือเร็วกว่า — ถ้าอยากยึด <select class="form-select"> เดิมก็เปลี่ยนได้ (radio group ยัง bind RHF ได้ปกติ ไม่ใช่ hs-dropdown ที่ห้ามใช้)
  • มือถือ: ปุ่มเพิ่มเป็น แถบล่างเต็มความกว้าง (ที่วาดไว้) หรือ FAB กลม
  • “แยกหมวด + สรุปเร็ว” เอาทั้ง 2 ใบ หรือเอาแค่ใบเดียว

ผลกระทบของข้อ 4 (รายจ่าย → หน้ายอดขาย)

  • /sales ตอนนี้ query แค่ getOrdersByShop() — ต้องเพิ่ม query ค่าใช้จ่ายรายวันในช่วงเดียวกัน แล้วเติมลง DailyRow (เพิ่มฟิลด์ expense + netProfit) และ SummaryData
  • กราฟ SalesChart / SalesChartSheet ต้องเพิ่ม series ค่าใช้จ่าย — วางเป็นแท่งแยกข้างกัน ไม่ใช่ stack ทับยอดขาย (คนละหน่วยความหมาย stack แล้วอ่านผิดทันที) และต้องผ่าน ApexChart wrapper + getColor() ตาม Hard Rule 10
  • ค่าใช้จ่ายผูกกับ expenseDate (วันที่ผู้ใช้เลือกเอง) ส่วนยอดขายผูกกับ order.createdAt — ย้อนหลังบันทึกค่าใช้จ่ายของเมื่อวานได้ ตัวเลขวันเก่าจะขยับ ต้องไม่ cache ค้าง
  • สิทธิ์: /expenses มี gate แพ็กเกจ/สิทธิ์พนักงาน (resolveExpenseAccess) แต่ /sales ไม่มี — ร้านที่ยังไม่ปลดล็อกฟีเจอร์ต้องไม่เห็นคอลัมน์ค่าใช้จ่าย/กำไรสุทธิ (ไม่ใช่เห็นเป็น ฿0 ซึ่งโกหก)

  • empty state → seller/(dashboard)/_shared/SellerEmptyState.tsx
  • ยืนยันลบ → src/lib/paces-swal.ts (pacesConfirm.danger) · toast → pacesToast (Hard Rule 9)

ข้อควรระวังที่เห็นตั้งแต่ตอนวาด

  • “+12.4% จากช่วงก่อนหน้า” ในการ์ด P&L เป็นข้อมูลใหม่ — getPnlReport ตอนนี้ไม่คืนค่าเปรียบเทียบ ต้องเพิ่ม query ช่วงก่อนหน้า (ถ้าไม่เอา ตัดทิ้งได้ ไม่กระทบอย่างอื่น)
  • “แยกหมวด/สรุปเร็ว” คำนวณจาก list ที่โหลดมาแล้วได้ ถ้า list ที่ดึงมาถูกจำกัดด้วยช่วงเวลาเดียวกับ P&L — ตอนนี้ listExpenses(shopId) ดึงทั้งหมดไม่ผูกช่วง ต้องแก้จุดนี้ให้ตรงกันก่อน ไม่งั้นตัวเลขสองการ์ดจะขัดกันเอง
  • ปุ่มล่างจอมือถือทับ safe-area — ต้องมี env(safe-area-inset-bottom) พร้อม comment กำกับ (carve-out Hard Rule 7)
