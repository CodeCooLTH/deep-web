CSS ในไฟล์นี้คือของจริง — คอมไพล์ app.css ของโปรเจกต์ออกมาเป็น paces-theme.css (1.1MB) แล้วลิงก์ตรง ๆ · <html> ตั้ง attribute ชุดเดียวกับ src/app/(paces)/layout.tsx ทุกตัว รวม data-skin="default"

คลาสที่ใช้เป็นสำนวนเดียวกับโค้ดจริง — card · btn bg-primary text-white hover:bg-primary-hover · badge bg-success/15 text-success · form-switch (ดึงมาจากการนับความถี่ในไฟล์ seller จริง ไม่ได้คิดเอง)

คอลัมน์กลางเรนเดอร์เนื้อหาจริง ไม่ใช่รายการชื่อบล็อก — ผู้ขายเห็นหน้าร้านที่กำลังจัดตรง ๆ มีเครื่องมือลอยทับเมื่อชี้

วิธีเพิ่มบล็อกคือปุ่มบวก ไม่ใช่ลากข้ามคอลัมน์ เคาะแล้ว 2026-08-07 — คลังอยู่นอก iframe (Paces) canvas อยู่ใน iframe (Vuexy) และ pointer event ไม่ข้ามขอบ document · แตะปุ่มบวกแล้วบล็อกไปโผล่ท้าย canvas จากนั้น ลากจัดลำดับได้เต็มที่ภายใน canvas ซึ่งคือคุณค่าหลักของเครื่องมือ

คงโครงแท็บของหน้าร้านไว้ เคาะแล้ว 2026-08-07 — สิ่งที่จัดลำดับได้มี 2 อย่างเท่านั้น: บล็อกเหนือแถบแท็บ (เหรียญตราเด่น · โพสต์จากเพจ) และ ลำดับแท็บ · ห้องพัก/รีวิว/คลิป ยังเป็นแท็บเหมือนเดิม ปิดหรือเอาออกไม่ได้ · หัวโปรไฟล์ตรึงบนสุดตายตัว

เฟสนี้ desktop-only เคาะแล้ว 2026-08-07 — มือถือไม่มีตัวจัดเรียง แต่ต้องไม่เป็นทางตัน ดูหัวข้อ 2

ทำไมถึงปล่อยไม่ได้: กลุ่มนี้มีทั้งด้านดีและด้านแย่ ถ้าซ่อนได้ทีละใบ ร้านที่มีปัญหาจะซ่อนเฉพาะตัวที่แย่ แล้วตัวเลขที่เหลือหมดความหมายทั้งชุด · ซ่อนได้ทางเดียวคือปิดทั้งหน้า

5 · เรื่องที่ต้องเคาะก่อนลงมือ

1. canvas ต้องเป็น iframe ของหน้าจริง เคาะแล้ว 2026-08-07
หน้าร้านสาธารณะเป็น Vuexy (MUI + --mui-palette-*) แต่ builder เป็น Paces — เอา component หน้าร้านมา render ตรง ๆ ในหน้า Paces ไม่ได้ สีจะหายเงียบ ๆ โดย build ผ่านหมด
เคยพิจารณาย้ายหน้าร้านไปใช้ Paces เพื่อตัดปมนี้ (ต้นทุนต่ำกว่าที่คิด — MUI เหลือแค่ 9 import และ sx= 5 จุด จาก className= 101 จุด) แต่ ตัดสินว่าไม่ย้าย: PRODUCT.md:19 ระบุ /u/[username] เป็น brand register (Vuexy) เป็นชื่อ path ตรงตัว และยืนยันซ้ำ 2026-08-03 · Product Principle 4 (PRODUCT.md:129) แยกบทบาทไว้ชัด: surface สาธารณะแบกตัวตนแบรนด์ / surface ใช้งานจริงต้อง "หายไปในงาน" · และสี tier สูงสุด ("Deep Star") ใน src/lib/trust-tier.ts ผูกกับ Vuexy primary โดยตรง ย้ายแล้วชนกฎ Paces ทันที
ทางที่ใช้: canvas embed iframe ของ route จริงในโหมดพรีวิว แล้วคุยกันด้วย postMessage (เลือกบล็อก → ไฮไลต์ใน iframe · ลากสลับ → ส่ง draft state ใหม่) — เป็น pattern มาตรฐานของ visual editor ทุกเจ้า และ ตรงกับของจริงมากกว่าการวาดบล็อกเองด้วย token Paces เพราะไม่มีทาง drift · หมายเหตุ: บล็อกใน canvas ของ mockup นี้จึงเป็นภาพแทน ไม่ใช่สิ่งที่จะ implement ตรง ๆ
2. ลำดับที่ลากไปโผล่ที่ไหน — หน้าร้านตอนนี้เป็น แท็บ ไม่ใช่หน้าเลื่อนยาว ต้องเพิ่มคอลัมน์เก็บลำดับ (เช่น Shop.profileLayout) และแก้ ShopProfile.tsx ให้เรียงตามคอลัมน์นั้น
3. รูปโพสต์ Facebook หมดอายุได้ — FacebookPost.thumbnailUrl เก็บ URL ของ Meta ตรง ๆ ไม่ได้ mirror ลง storage เรา ถ้าเอาไปแปะหน้าร้านถาวรอาจกลายเป็นรูปแตก ต้องตัดสินว่าจะ mirror ตอนกดเพิ่มลงหน้าร้านหรือยอมรับความเสี่ยง
