# รายการที่แสดงบนหน้าร้าน — ทำไมของเดิมใช้ยาก และจะแก้อย่างไร

ม็อกอัพ: `2026-08-23-item-visibility-redesign.html` (390 / 768 / 1440)

## ของเดิมมีปัญหาอะไร (จากหน้าจริงที่ user ส่ง — ร้านที่มีสินค้า 32 ชิ้น)

| # | อาการ | ทำไมมันแย่ |
|---|-------|-----------|
| P1 | สวิตช์อยู่ขอบขวาสุด ห่างจากชื่อสินค้า ~1,800px บนจอ 1440 | ตาต้องวิ่งข้ามจอทั้งใบต่อการกดหนึ่งครั้ง และเสี่ยงกดผิดแถวเพราะไม่มีอะไรลากสายตาไปถึง |
| P2 | 32 แถว × 79px = เลื่อนยาว ~2,500px อยู่กลางหน้าตั้งค่า | ของที่อยู่ใต้การ์ดนี้ (คลิปที่แสดงบนหน้าร้าน ฯลฯ) ถูกดันหายไปจนไม่มีใครรู้ว่ามี |
| P3 | ไม่มีปุ่มทำทีเดียวทั้งชุด | ร้านที่อยากซ่อนเกือบทั้งหมดแล้วเปิดเฉพาะบางชิ้น ต้องกดทีละ 30 ครั้ง |
| P4 | มองไม่ออกว่าอันไหนถูกซ่อนอยู่ ถ้าไม่ไล่ดูสวิตช์ทีละอัน | ตัวนับบอกแค่ "แสดงอยู่ 32 จาก 32" แต่หา 3 ตัวที่ซ่อนไม่เจอ |
| P5 | แถวสูง 79px แต่บรรจุแค่ชื่อ | เห็นสินค้าต่อจอน้อยมาก (~8 ชิ้น) ทั้งที่ข้อมูลต่อแถวมีบรรทัดเดียว |
| P6 | รูปว่างเป็นไอคอนเทาเหมือนกันหมด | ไม่ใช่บั๊ก — สินค้าที่เพิ่มล่าสุดของร้านนี้ยังไม่ได้ใส่รูปจริง ๆ แต่พอเรียงใหม่สุดขึ้นก่อน ทั้งจอเลยกลายเป็นไอคอนซ้ำ ๆ ที่แยกไม่ออก |

## ทางแก้

1. **จัดเป็นกริดหลายคอลัมน์** (1 คอลัมน์ <768px · 2 คอลัมน์ ≥768 · 3 คอลัมน์ ≥1440)
   แถวกว้างสูงสุด ~460px ⇒ สวิตช์อยู่ห่างจากชื่อไม่เกินความกว้างการ์ดหนึ่งใบ (P1) และเห็นสินค้า
   ต่อจอมากขึ้น ~3 เท่า (P5)
2. **แถบเครื่องมือในหัวกลุ่ม**: ชิปกรอง `ทั้งหมด · แสดงอยู่ (n) · ซ่อนอยู่ (n)` + ปุ่ม
   `แสดงทั้งหมด` / `ซ่อนทั้งหมด` (P3, P4)
3. **แถวที่ถูกซ่อนดูต่างจริง** — ชื่อจาง + รูปหม่นลง + ป้าย `ซ่อนอยู่` ⇒ กวาดตาหาเจอโดยไม่ต้อง
   อ่านสวิตช์ (P4) 🛑 ไม่ใช้สีอย่างเดียวเป็นตัวบอก (WCAG 1.4.1) จึงมีป้ายข้อความกำกับด้วย
4. **ตั้งต้นแสดง 12 แถว** แล้วมีปุ่ม `ดูทั้งหมด (32)` ⇒ การ์ดนี้ไม่ยาวเกิน ~1 จอ (P2)
   ค้นหาหรือกดชิปกรองจะแสดงผลลัพธ์ทั้งหมดเสมอ (คนที่ค้นหาแล้วต้องกด "ดูเพิ่ม" อีกทีคือ UI ที่กวน)
5. แถวสูง 56px · รูปย่อ 36px · ชื่อบรรทัดเดียว `truncate`

## สิ่งที่ไม่เปลี่ยน
- สวิตช์ยังบันทึกทันทีแบบ optimistic + เด้งกลับเมื่อล้ม (FR-PPD-07)
- ตัวนับยังคิดจาก override ปัจจุบัน ไม่ใช่ค่าที่ server ส่งมาตอนโหลด (AC-12-1)
- พื้นที่กดของสวิตช์ยังเต็มความสูงแถว
- ยังไม่มีรูป = ไอคอนตามชนิดเหมือนเดิม (ไม่ใช่บั๊ก)

## ประเด็นที่ยังต้องตัดสิน
- ปุ่ม `ซ่อนทั้งหมด` ควรถามยืนยันก่อนไหม (กดพลาดครั้งเดียว = หน้าร้านว่างทั้งแท็บ)
  → ม็อกอัพนี้ใส่ `pacesConfirm.warning` ไว้เฉพาะ "ซ่อนทั้งหมด" ทางเดียว ส่วน "แสดงทั้งหมด" ไม่ถาม

# 2 · แท็บรีวิวบนหน้าร้าน (ผู้ซื้อ)

## ข้อเท็จจริงที่เปลี่ยนการออกแบบทั้งหมด

query ฐาน prod (2026-08-23): **ทั้งแพลตฟอร์มมีรีวิว 23 อัน — มีข้อความแค่ 1 อัน · มีรูป 0 · ร้านตอบกลับ 0**

⇒ แท็บนี้ **ไม่ใช่ฟีดคอมเมนต์ มันคือรายการให้ดาว** แต่ถูกจัดหน้าเหมือนฟีดคอมเมนต์ (บล็อกสูง ~193px
ต่ออัน + อวาตาร์กลม 56px) ผลที่ได้คือจอที่เต็มไปด้วยแถวหน้าตาเหมือนกันเป๊ะ 7 แถว (`U••••••••` ซ้ำทุกอัน
อวาตาร์เทาเหมือนกันหมด) ซึ่ง **อ่านเป็นรีวิวปลอม** — ตรงข้ามกับสิ่งที่แพลตฟอร์มความน่าเชื่อถือต้องการที่สุด

## ปัญหาที่เจอ

| # | อาการ | ทำไมมันแย่ |
|---|-------|-----------|
| R1 | ข้อมูลที่เด่นที่สุดในแต่ละแถวคือ **เลขคำสั่งซื้อ** (`คำสั่งซื้อ DP2569085552519D`) | ผู้ซื้อไม่รู้จักเลขนี้และใช้ทำอะไรไม่ได้ — มันคือ id ภายในที่ถูกวางไว้ในตำแหน่งที่ควรเป็นเหตุผลว่า "ทำไมรีวิวนี้เชื่อได้" |
| R2 | 🛑 **แถบสรุปบอก 21 รีวิว แต่ชิปบอก "ทั้งหมด 10"** | `getReviewsByUsername(username, take = 10)` cap ไว้ 10 โดยไม่มีอะไรบอกผู้อ่าน — ตัวเลขสองค่าของสิ่งเดียวกันบนจอเดียว (คลาสเดียวกับ `partial-data-must-be-labeled-or-filled.md`) |
| R3 | อวาตาร์เทาเหมือนกันทุกแถว + ชื่อถูกปิดบังเหมือนกันทุกแถว | แยกไม่ออกว่าเป็นคนละคน ⇒ อ่านเป็นของปลอม |
| R4 | ~193px ต่อรีวิวที่มีข้อมูลจริงแค่ "กี่ดาว + เมื่อไหร่" | เห็นได้ ~4 อันต่อจอ ทั้งที่แต่ละอันมีข้อมูลบรรทัดเดียว |
| R5 | รีวิวที่ **มี** ข้อความ ถูกจัดหน้าเหมือนรีวิวที่ไม่มี | ของมีค่าที่สุด (ข้อความจริงจากลูกค้า) ไม่ได้ถูกยกขึ้นมาเลย |

## ทางแก้

1. **แยกเป็นสองชนิดแถว**
   - *มีข้อความ* → การ์ดเต็ม ยกข้อความขึ้นเป็นตัวเอก (16px) + รูป (ถ้ามี) + คำตอบของร้าน (ถ้ามี) — ขึ้นก่อนเสมอ
   - *ให้ดาวอย่างเดียว* → แถวกระชับ 52px ใต้หัวข้อ `รีวิวที่ให้ดาวอย่างเดียว` (เห็น 8–10 อันต่อจอ)
   🛑 ไม่ซ่อนรีวิวที่ไม่มีข้อความ — มันคือหลักฐานว่ามีคนซื้อจริง แค่ไม่ต้องกินพื้นที่เท่ารีวิวที่มีเนื้อหา
2. **เลิกโชว์เลขคำสั่งซื้อ** เปลี่ยนเป็นป้าย `✓ ยืนยันรับของแล้ว` (เขียว Verified-Means-Green) ซึ่งตอบคำถาม
   ที่ผู้ซื้อถามจริง ๆ ว่า "รีวิวนี้มาจากคนที่ซื้อจริงไหม"
3. **อวาตาร์เป็นตัวอักษรแรกบนพื้นสีที่ derive จากชื่อ** ⇒ แต่ละแถวต่างกันจริงโดยไม่เปิดเผยตัวตนเพิ่ม
4. **ชิปกรองนับจากยอดเดียวกับแถบสรุป** (21/17/3/1) + ปุ่ม `ดูรีวิวเพิ่ม (อีก N)` ⇒ ตัวเลขบนจอไม่ขัดกันอีก (R2)

## สิ่งที่ไม่เปลี่ยน
- แถบสรุป (4.8 + กราฟแท่ง) — เป็นส่วนที่ทำงานดีอยู่แล้ว
- การปิดบังชื่อผู้รีวิว (PDPA) และ empty state เดิมที่อธิบายว่าใครรีวิวได้
- ไอคอนช่องทาง (Facebook ฯลฯ) บนรีวิวที่มา่จากช่องทางนอก

## ประเด็นที่ยังต้องตัดสิน
- `ดูรีวิวเพิ่ม` โหลดเพิ่มทีละ 10 หรือกางทั้งหมดทีเดียว (ร้านที่มีรีวิวหลักร้อยจะต่างกันมาก)
- ป้าย `✓ ยืนยันรับของแล้ว` ควรอยู่ทุกแถวบนมือถือไหม (พื้นที่แคบ — ม็อกอัพนี้ตัดออกบนมือถือ เหลือเฉพาะเดสก์ท็อป)
