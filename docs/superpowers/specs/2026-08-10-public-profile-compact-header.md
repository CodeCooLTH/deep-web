## 3. สิ่งที่ทำได้เลย (ไม่ขัดมติใด ๆ)

### 3.1 ประโยคอธิบายอัตราสำเร็จ → หลังการแตะ

เดิม inline เสมอ 2 บรรทัด:
> "อัตราสำเร็จจะขึ้นเมื่อมีออเดอร์ที่จบแล้วครบ 5 ใบ — ไม่ได้แปลว่าร้านมีปัญหา"

ใหม่: เซลล์ "อัตราสำเร็จ" เป็น `<button aria-haspopup="dialog">` เปิด `ResponsiveSheet` (instance ที่ 3 ของ component เดิม)

🛑 **ตัวเลข 4 ช่องและป้ายสั้น "ยังสรุปไม่ได้" ยังอยู่ครบเสมอ** — ไม่แตะมติ 2026-07-26 แม้แต่ช่องเดียว
เปลี่ยนแค่ประโยคขยายความยาว ๆ ที่ไม่ต้องอ่านทุกครั้ง (1 ชั้นของ disclosure ไม่ใช่ 2 ตาม NN/g)

**Edge state ที่พลาดง่าย:** ร้านที่ข้อมูลครบ (`completionBelowMinSample` และ `completionExcluded` เป็น falsy ทั้งคู่)
→ **ห้าม render เป็นปุ่มเลย** เซลล์ต้องกลับเป็น static ไม่มี `cursor:pointer` หลอกว่ากดได้แต่ไม่มีอะไรเกิดขึ้น

### 3.2 รัดระยะห่าง

บน spacing scale เดิม ไม่มีค่าใหม่ (`pbe-3`→`pbe-2` ฯลฯ) — รวม ~10px ต่อจอ

### 3.3 ประกอบใหม่ด้วย primitive ของธีม (ปิดหนี้ HR1 ในงานเดียวกัน)

หัวโปรไฟล์วัดจาก HTML จริง: **98 element มีคลาส MUI แค่ 25**

| บล็อกปัจจุบัน | เปลี่ยนเป็น | Theme source |
|---|---|---|
| ชิปคะแนน `<span>` + ชิป tier `<span>` | MUI `Chip` | `theme/vuexy/.../user-profile/connections/index.tsx:48` |
| ป้ายระดับ `absolute inline-end-[-4px]` | MUI `Badge overlap='circular'` | `theme/vuexy/.../apps/chat/AvatarWithBadge.tsx` |
| ปุ่มวงกลมเล็ก (เช็คเขียว / info) `<button>` | `@core/components/mui/IconButton` | มีในโปรเจกต์แล้ว (ไฟล์นี้ใช้อยู่แล้วกับปุ่มปิดโมดัล — 2 pattern ปนกันในไฟล์เดียว) |
| แถบตัวเลข value+label | **ไม่เปลี่ยน** | `connections/index.tsx:52-60` ใช้ `Typography` ซ้อนกันแบบเดียวกัน = theme-consistent อยู่แล้ว |
| ปก + fallback onError | **ไม่เปลี่ยน** | `CardMedia` ไม่รองรับ onError-fallback ที่ `ProfileImg` ทำอยู่ — เบี่ยงโดยมีเหตุผล |
| ปุ่มเหรียญ (ไอคอนกลม + ป้ายใต้ภาพ ไม่มีขอบ) | **ไม่เปลี่ยน** | ไม่พบ MUI primitive ที่ตรง — raw `<button>` สมเหตุสมผล |

### ข · แถวเพจที่เชื่อมต่อ

| ตัวเลือก | ได้ | เสีย |

### ค · ปุ่ม "แชทกับร้าน" บนมือถือ + แท็บเล็ต

| ตัวเลือก | ได้ | เสีย |
|---|---|---|

| **ค-2 คงเป็นปุ่มในโฟลว์** | ไม่ต้องแตะอะไร | ปุ่มกิน 82px กลางหน้า และผู้ใช้ต้องเลื่อนถึงจะเจอ action หลัก |

**หมายเหตุ:** ค-1 **ไม่ใช่การย้อนมติ** — คอมเมนต์ที่อธิบายปุ่มลอยฝั่งเดสก์ท็อป (`ProfileHero.tsx:737-738`) พูดถึงแค่
"บนจอกว้างปุ่มเต็มความกว้างกินพื้นที่เกินความสำคัญ" ไม่มีที่ไหนอธิบายว่าทำไม**มือถือ**ถึงควรเป็น inline
= ช่องว่างในการตัดสินใจ ไม่ใช่ข้อที่เคยถูกปฏิเสธ

⚠️ **ก่อน implement ค-1 ต้องเช็ค** `(marketing)/layout.tsx` มี `viewport-fit=cover` ไหม ก่อนใส่ `env(safe-area-inset-bottom)`
ไม่มี = ได้ 0 เงียบ ๆ (`docs/conventions/ios-safe-area.md`) → ใช้ padding คงที่ 16px ไปก่อน ไม่ต้องแก้ viewport meta ในรอบนี้

## 5. ห้ามยุบเด็ดขาด

หน้านี้คือหน้าที่ผู้ซื้อใช้ตัดสินใจโอนเงิน — ตัดอันไหนแล้วหน้าเสียหน้าที่ตัวเอง:

1. **ตราแบรนด์ Deep** — ตัดแล้วผู้ชมแยกไม่ออกว่านี่คือหน้าที่บุคคลที่สามรับรอง
2. **คะแนน `/100` + tier** — สรุปหลักฐานทั้งหมดเป็นตัวเลขเดียว
3. **เช็คเขียวยืนยันตัวตน** — 35% ของคะแนน ปลอมไม่ได้
4. **ตัวเลข 4 ช่องครบเสมอ** — หลักฐานเดียวที่ร้านเขียนเองไม่ได้ · **ยุบรูปแบบได้ ยุบจำนวนช่องไม่ได้**
5. **เช็คเขียว OAuth บนโลโก้เพจ** — สิ่งเดียวที่ทำให้แถวนั้นเป็นหลักฐาน ไม่ใช่ลิงก์ที่พิมพ์เอง
6. **ไอคอนเหรียญ** — หลักฐานที่ระบบมอบเอง ร้านขอเอง/ซื้อไม่ได้
7. **ปุ่มแชท** (เมื่อ `canChat`) — ย้ายตำแหน่งได้ ถอดไม่ได้

## 6. Edge states ที่เกิดจากการยุบรอบนี้

- **ร้านข้อมูลครบ** → ปุ่มบนเซลล์อัตราสำเร็จต้องไม่ render (ดู §3.1)
- **ไม่มี `canChat`/`shopId`** → fixed bar ไม่ render เลย ไม่เว้นที่ว่างค้างที่ก้นจอ
- **จอเตี้ย (landscape / iPhone SE)** → fixed bar ทับเนื้อหาท้ายแท็บถาวร ต้องเผื่อ padding-bottom ที่ container ของ **แท็บ** ไม่ใช่แค่ hero
- **ชื่อเหรียญสั้นมาก** หลังตัด 1 บรรทัด → `truncate` ไม่มีผล ไม่ต้อง handle พิเศษ
- **ชื่อร้านยาว 2 บรรทัด** → พฤติกรรมเดิม ไม่เปลี่ยน

## 7. Impeccable compliance

- **Mode: Read** (เอียง Persuade ที่ปุ่มแชท) — ผู้ซื้อกำลังสแกนหาหลักฐานก่อนตัดสินใจ เกณฑ์คือ scanability/hierarchy ของหลักฐานชนะการประดับ
- **One Voice** — ไม่เพิ่มม่วงใหม่เลย ปุ่มแชทยังเป็นจุดเดียวที่ใช้ม่วงเข้ม (fixed bar สูง ~64–70px ≈ ≤5% ของจอ)
- **Verified-Means-Green** — ไม่แตะ เขียวยังอยู่ที่เดิมทั้งเช็ค OAuth และระดับยืนยันตัวตน
- **Sentence-case** — ข้อความใหม่ทั้งหมดเป็นประโยคปกติ ไม่มี ALL CAPS
- **Ink-Tinted Shadow** — ถ้า fixed bar ต้องมีเงาแยกจากเนื้อหา ใช้ shadow token ฝั่ง buyer ไม่ใช่ดำสนิท
- **hero-metric template** — craft-floor เตือนเรื่อง "เลขใหญ่ ป้ายเล็ก" แต่ pattern นี้ **earned back แล้ว** ทั้งจาก DESIGN.md (สร้าง typography role "Metric" ไว้เฉพาะ) และจาก theme เอง (`connections/index.tsx` ใช้ pattern เดียวกันในหน้า user-profile) → **ไม่ใช่การละเมิดที่ต้องแก้** และนี่คือเหตุผลที่ **ปฏิเสธ**ข้อเสนอ "ยุบแถบตัวเลขเป็นบรรทัดเดียวคั่น `·` แบบ GitHub" — จะเป็นการลดชั้นจาก "ภาพ" เป็น "ข้อความ" ซึ่งขัด role ที่ระบบออกแบบไว้
