# รายการออเดอร์ — ปุ่ม "ตัวกรอง" + โมดัล + ตัวกรองโฆษณา (UX spec)

ม็อกอัพ: `docs/superpowers/specs/2026-11-15-orders-filter-modal-mockup.html` (1280 / 768 / 390)
สถานะ: user ตัดสินใจครบแล้ว 2026-11-15 (ดู "มติผู้ใช้" ท้ายไฟล์) — ลงโค้ดแล้ว

## 1. สภาพปัจจุบัน (อ่านจากโค้ด 2026-11-15)

| จอ | ตัวกรอง | ที่เก็บค่า |
|---|---|---|
| เดสก์ท็อป `OrdersTable.tsx` | ดรอปดาวน์ 6–7 ตัวเรียงแถว: สถานะ · พัสดุ · วิธีส่งมอบ · สถานะนัด · ขนส่ง · ช่วงเวลา · แถวละ N | สถานะ/ขนส่ง/ช่วงเวลา = column filter ของ TanStack (หายเมื่อรีเฟรช) · พัสดุ/วิธีส่งมอบ/สถานะนัด = URL `?stage` `?fulfillment` `?appt` |
| มือถือ `OrdersList.tsx` (`lg:hidden`) | แถวชิปแกนหลัก + **มีโมดัล "ตัวกรอง" เต็มจออยู่แล้ว** (สถานะการขาย · วิธีส่งมอบ · ประเภท · ช่วงเวลา) — กดแล้วมีผลทันที ปุ่ม "ดูผลลัพธ์" แค่ปิด | local state + URL ปนกัน |

ช่องว่างระหว่างจอ: มือถือไม่มี "ขนส่ง" · เดสก์ท็อปไม่มี "ประเภท" — สองจอกรองไม่เท่ากัน

ออเดอร์ทั้งร้านโหลดมาฝั่ง client ครบอยู่แล้ว (`orders/page.tsx` ไม่มี `take`) และทุกแถวมี `ad: OrderAdView | null` แล้ว (`page.tsx:509` → `toOrderAdView`) ⇒ **ตัวกรองโฆษณาไม่ต้องเพิ่ม query/API/migration**

## 2. Layout

**แถบเครื่องมือ (ทุกจอ)**
- ช่องค้นหา (เดิม) · ปุ่ม `ตัวกรอง` (icon `adjustments-horizontal`) + badge จำนวนแกนที่เปิดอยู่ · ส่งออก · สร้างออเดอร์
- ปุ่มเมื่อมีตัวกรองเปิดอยู่: ขอบ/พื้น primary อ่อน · ไม่มีตัวกรอง: ปุ่มขอบเทา ไม่มี badge
- มือถือ: ปุ่มไอคอนอย่างเดียว 44×44 badge มุมขวาบน · `aria-label="ตัวกรอง (3)"`

**แถวชิปตัวกรองที่ใช้อยู่** (ใต้แถบ แสดงเมื่อมี ≥1 แกน)
- 1 แกน = 1 ชิป `ชื่อแกน: ค่า` + ปุ่ม × (`<button aria-label="ล้างตัวกรอง{แกน}">`)
- โฆษณา: เลือก 1 ตัว = รูปย่อ + ชื่อ · หลายตัว = `โฆษณา: N ตัว` (เดสก์ท็อปแสดงชื่อตัวแรก `+N`)
- ท้ายแถว: `ล้างทั้งหมด` · เดสก์ท็อปชิดขวา `42 จาก 1,286 ใบ`
- pill `?work=` / `?apptDay=` ที่มาจากไทล์หน้าแรก ย้ายมาอยู่แถวนี้ด้วย (หน้าตาเดียวกับชิปอื่น)
- มือถือ: แถวชิปแกนหลักเดิมคงไว้ด้านบน · แถวชิปตัวกรองอยู่ใต้ เลื่อนแนวนอน · แกนที่อยู่บนแถวบนแล้วไม่ซ้ำ

**โมดัล**
- เดสก์ท็อป ≥1024: กลางจอ `max-w-4xl` 2 คอลัมน์ — ซ้าย = แกนค่าเดียว · ขวา (340px) = โฆษณา (รายการเลื่อนในตัว)
- แท็บเล็ต 640–1023: กลางจอ `max-w-lg` คอลัมน์เดียว เนื้อหาเลื่อน หัว/ท้ายตรึง
- มือถือ <640: bottom sheet สูงเกือบเต็มจอ หัว/ท้ายตรึง · ปุ่ม `min-h-11`
- ลำดับ section: ช่วงเวลา · สถานะ · พัสดุ (หรือ สถานะนัด ในร้านบริการ) · วิธีส่งมอบ + ขนส่ง (คู่กันเมื่อจอกว้างพอ) · โฆษณา
- แกนค่าเดียว = ปุ่มเม็ดยา (`aria-pressed`) มีตัวเลขจำนวนต่อท้าย · "ทั้งหมด" ตัวแรกเสมอ
- ช่วงเวลา: เม็ดยา preset + `เลือกวันที่` (กดแล้วขยาย `<input type="date">` ในที่เดิม — ตาม `OrderDateFilterDropdown` เดิม ไม่ใช้ Flatpickr)
- section ซ่อนตามกติกาเดิมทุกข้อ (`hasShippingAxis`, `courierOptions.length > 1`, `appointmentFilter` ฯลฯ) — ห้ามแสดงปุ่มที่กดแล้วไม่เกิดอะไร
- footer: `ล้าง` (ซ้าย) · `ใช้ตัวกรอง · N ใบ` (ขวา, primary)
- ไม่มีประโยคอธิบายใด ๆ ในโมดัล — ป้ายอย่างเดียว

## 3. "แถวละ N" อยู่นอกโมดัล

ย้ายไป footer ของตารางข้างปุ่มเลขหน้า (เดสก์ท็อปเท่านั้น — มือถือเป็น lazy-load ไม่มีเลขหน้า)
เหตุผล: ไม่ได้เปลี่ยนว่าออเดอร์ไหนเข้าเกณฑ์ ไม่ควรนับใน badge และไม่ควรถูกปุ่ม "ล้าง" ล้าง · ผู้ใช้ปรับมันตอนดูเลขหน้า ไม่ได้ปรับตอนคิดเรื่องเกณฑ์

## 4. พฤติกรรม

- **กดใช้ (ไม่ live)**: ในโมดัลเลือกเป็นร่าง → `ใช้ตัวกรอง` ค่อยมีผล · ปิดด้วย ×/Esc/แตะฉากหลัง = ทิ้งร่าง
  - เหตุผล: มีหลายแกน + รายการโฆษณาแบบเลือกหลายตัว ถ้า live ตารางข้างหลังจะกระตุกทุกคลิก
  - ตัวเลขบนปุ่มคำนวณสดจากร่าง (ทำได้ทันทีเพราะข้อมูลอยู่ฝั่ง client) — ร่างได้ 0 ใบ ปุ่มยังกดได้ แสดง `ใช้ตัวกรอง · 0 ใบ`
  - 🛑 เปลี่ยนพฤติกรรมโมดัลมือถือเดิม (เดิม live) — ดูคำถาม Q1
- **`ล้าง`** ในโมดัล = ล้างร่างทุกแกน (ยังไม่มีผลจนกด `ใช้ตัวกรอง`) · `ล้างทั้งหมด` บนแถวชิป = มีผลทันที
- **× บนชิป** = ล้างแกนนั้นทันที ไม่เปิดโมดัล · แตะตัวชิป = เปิดโมดัล
- **badge** = จำนวนแกนที่ไม่ใช่ "ทั้งหมด" (โฆษณาที่เลือก 3 ตัว นับ 1) · ไม่นับคำค้นและแถวละ N
- **ตัวเลขในตัวเลือก** = นับจากออเดอร์ทั้งหมด (แบบ `courierOptions` เดิม) ไม่ใช่ faceted ตามแกนอื่น — ตัวเลขที่ "ตรงกับผล" มีที่ปุ่ม `ใช้ตัวกรอง` แล้ว
- เปลี่ยนตัวกรองแล้วกลับหน้า 1 (เหมือนเดิม)
- **URL**: ทุกแกนเก็บใน URL เพื่อรีเฟรช/ส่งลิงก์ได้ — เพิ่ม `?status=` `?courier=` `?date=` `?ad=` (คั่นด้วย `,`) ข้าง `?stage` `?fulfillment` `?appt` `?q` เดิม · ใช้ `pushQuery` ตัวเดียวกับที่มีอยู่ ครั้งเดียวตอนกด `ใช้ตัวกรอง`

## 5. ตัวกรองโฆษณา

- แหล่งข้อมูล: `row.ad` (`OrderAdView`) ของออเดอร์ที่โหลดมาแล้ว — `Order.adId/adTitle/adPhotoFileId` เขียนครั้งเดียวโดย `stampOrderAdAttribution`/backfill (00091)
- ตัวเลือก = โฆษณาที่ "มีออเดอร์ของร้านอย่างน้อย 1 ใบ" เท่านั้น จัดกลุ่มด้วย `adId` เรียงจำนวนมาก→น้อย (แบบ `courierOptions`) — ไม่ดึงรายชื่อแอดจาก Meta
- แต่ละแถว: checkbox · `AdThumb` (`/api/files/{id}?variant=thumb` · ไม่มีรูป = ไอคอน speakerphone) · ชื่อจาก `adDisplayName()` · จำนวนใบ
- ชื่อแอดในแต่ละใบเป็นภาพนิ่ง ถ้าชื่อต่างกันใน adId เดียว ใช้ชื่อจากใบล่าสุด
- แถวพิเศษบนสุด `ไม่ได้มาจากโฆษณา` = `ad === null` (คำเดียวกับ `/reports/ads` — HR16) รวมถึง: ออเดอร์ที่ไม่ได้สร้างจากแชท · แชทที่ไม่มี referral จากแอด · referral ที่ไม่มี adId (`pickAdAttribution` ทิ้ง)
- **ไม่มีหมวด "ไม่ระบุ" แยก**: แอดที่มี adId แต่ไม่มีชื่อ เป็นแอดตัวหนึ่ง แสดง `รหัสโฆษณา {adId}` ตาม `adDisplayName` อยู่แล้ว
- ลิงก์ `ทุกโฆษณา` หัว section = ติ๊กทุกแอด (ไม่รวม "ไม่ได้มาจากโฆษณา") — ค่า URL `?ad=any` ไม่ใช่รายชื่อยาว
- ช่องค้นหา = กรองชื่อในรายการฝั่ง client · แสดงเมื่อมีแอด > 5 ตัว
- หลายตัว = OR · ระหว่างแกน = AND
- แกนนี้ซ่อนทั้ง section เมื่อร้านไม่มีออเดอร์จากแอดเลย

## 7. คำถามถึง user

1. **กดใช้ vs live**: ยอมเปลี่ยนโมดัลมือถือเดิม (ตอนนี้กดแล้วมีผลทันที) เป็น "เลือกแล้วกด `ใช้ตัวกรอง`" ไหม?
2. **ประเภทออเดอร์** (สินค้า/ดิจิทัล/บริการ) มีแต่มือถือ — ใส่ในโมดัลทุกจอ หรือเอาออก?
3. **URL** ของสถานะ/ขนส่ง/ช่วงเวลา: ตอนนี้รีเฟรชแล้วหาย — ย้ายเข้า URL ทั้งหมดตามข้อ 4 ไหม?
4. **ลิงก์จาก `/reports/ads`**: เพิ่มปุ่ม "ดูออเดอร์" ในแถวแอด → `/orders?ad={adId}` ไหม? (ทำได้ทันทีเมื่อข้อ 3 ผ่าน)
5. **"แถวละ N"** ย้ายลง footer ตาราง ได้ไหม หรือให้คงอยู่บนแถบเครื่องมือ (ขวาสุด)?

## 8. มติผู้ใช้ 2026-11-15 (ทุกข้อ "ตามที่แนะนำ" — ตอบคำถามข้อ 7 ครบ)

1. **โมดัลตัวเดียวทุกจอ แบบ "เลือกแล้วกด `ใช้ตัวกรอง`"** — มือถือเลิกมีผลทันทีตอนแตะ · เดสก์ท็อป 2 คอลัมน์กลางจอ · แท็บเล็ต 1 คอลัมน์ · มือถือ bottom sheet หัว/ท้ายตรึง · ปุ่มท้ายแสดงจำนวนผลลัพธ์สด `ใช้ตัวกรอง · N {ออเดอร์/คำเรียกของร้าน}` + ปุ่ม `ล้าง`
2. **"ประเภท" มีทุกขนาดจอ** ไม่ใช่เฉพาะมือถือ
3. **ทุกตัวกรองอยู่ใน URL** (รีเฟรชไม่หาย): `status` `stage` `appt` `fulfillment` `courier` `date` `type` `ad` (`ad` ซ้ำได้หลายค่า · token `none` = ไม่ได้มาจากโฆษณา · ตรวจ id ด้วย `/^\d{1,30}$/`) — ค่าที่ไม่รู้จักถูกทิ้ง ไม่ crash · ลิงก์ `ทุกโฆษณา` (`?ad=any`) ในหัวข้อ 5 **ไม่ทำ**
4. **`/reports/ads` มีลิงก์ "ดูออเดอร์" ต่อแอด** → `/orders?ad={adId}` (แถวตาราง + แถวมือถือของ `AdTableCard`) · หน้าออเดอร์รับ `?ad=` ตั้งแต่โหลดแรก (state อ่านจาก URL ล้วน)
5. **"แถวละ N" ย้ายไป footer ตารางข้างเลขหน้า** — ไม่ใช่ตัวกรอง: ไม่นับ badge · `ล้าง` ไม่รีเซ็ต
