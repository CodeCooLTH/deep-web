# 00057 — re-design หน้าลูกค้า · prototype 3 ทางเลือก

> 🛑 **ของทิ้ง ไม่ใช่สเปก** — ไฟล์นี้กับ `.html` คู่กันมีไว้ตอบคำถามเดียว แล้วโยนทิ้ง
> ตัวที่ชนะต้องถูก **เขียนใหม่** ตอนเอาเข้าโค้ดจริง (ผ่าน `safepay-ux` ตาม HR8) ไม่ใช่ก็อปไปแปะ

## คำถามที่ต้องตอบ

หน้ารายชื่อลูกค้าควรจัดข้อมูลแบบไหน ในเมื่อต้องทำสองอย่างพร้อมกัน:
1. **เน้นสถิติความน่าเชื่อถือ** (อัตราปฏิเสธรับของ / อัตราคืนของ) — user สั่ง 2026-08-25
2. **ยอดซื้อสะสมรายคนก็ยังจำเป็น** — user ย้ำในรอบเดียวกัน ห้ามลดชั้น

ของที่ใช้อยู่บน prod ตอนนี้ทำข้อ 1 ได้บนมือถือ แต่ **บนเดสก์ท็อปยังกลับลำดับชั้น** (impeccable critique
2026-08-25 §5.2) และคอลัมน์ "ยอดซื้อสะสม" เสี่ยงหลุดขอบขวาที่ 1024px

## วิธีเปิด

เปิดไฟล์ `2026-08-26-customer-redesign-prototype.html` ด้วยเบราว์เซอร์ **ดับเบิลคลิกได้เลย**
— ไม่ต้องรัน dev server ไม่ต้องต่อฐานข้อมูล

สลับทางเลือกด้วย **แถบดำล่างจอ** หรือปุ่ม **← →** บนคีย์บอร์ด (URL เปลี่ยนตาม แชร์ลิงก์ได้)
แต่ละทางเลือกแสดง 3 ขนาดพร้อมกัน: มือถือ 390 · แท็บเล็ต 768 · เดสก์ท็อป 1280

## 3 ทางเลือก — ต่างกันเชิงโครงสร้าง ไม่ใช่ต่างกันแค่สี

| | โครง | affordance หลัก | ตอบ "ความน่าเชื่อถือ" ยังไง | ตอบ "ยอดซื้อสะสม" ยังไง |
|---|---|---|---|---|
| **A** คิวงานตามความเสี่ยง | จัดกลุ่มตามระดับความเสี่ยง มีหัวกลุ่ม **ไม่มีตาราง ไม่มีหน้าแบ่ง** | *"เคลียร์กลุ่มบนสุดให้หมด"* | ความเสี่ยงเป็นตัว**จัดลำดับทั้งหน้า** ไม่ใช่คอลัมน์หนึ่ง | ตัวเลขหนาชิดขวาทุกแถว น้ำหนักเท่าชื่อ |
| **B** แยกซ้าย-ขวา | รายชื่อผอมซ้าย + แผงรายละเอียดขวา | *"ไล่ดูหลายคนเร็ว ๆ โดยไม่เสียตำแหน่ง"* | แผงขวาให้เต็มรูป (แถบ + อัตรา + แยกขอบเขต) | ตัวเลขใหญ่ในแผงเดียวกัน **เห็นพร้อมกันในจอเดียว** |
| **C** บัญชีแน่น | ตารางล้วน ไม่มีการ์ดต่อแถว ไม่มีแถบ | *"เทียบหลายคนพร้อมกัน แล้วเรียงตามคอลัมน์"* | อัตราตีกลับเป็น**คอลัมน์ที่เรียงได้** | เป็นคอลัมน์ที่เรียงได้เหมือนกัน ⇒ สองแกนเท่าเทียม |

## สิ่งที่เห็นจากการ "เปิดดูจริง" (ไม่ใช่จากภาพในหัว)

เปิดด้วย browser-harness แล้ววัดจริงทั้ง 3 ขนาด:

- **C พังบนมือถือ** — ที่ 390px เหลือ 4 คอลัมน์แรก **ยอดซื้อสะสม/ออเดอร์/ตีกลับ/วันที่ ถูกตัดหมด**
  และเบอร์โทรตกบรรทัด 3 แถว ⇒ ถ้าเลือก C ต้องมีทางแยกสำหรับมือถือ ไม่ใช่ตารางเลื่อนข้าง
- **B บนมือถือกลายเป็นรายชื่อล้วน** — แผงรายละเอียดตกไปอยู่ใต้รายชื่อทั้งชุด ต้องเลื่อนผ่านทุกคนก่อนถึงมัน
  ⇒ B ต้องคู่กับชีตเต็มจอบนมือถือ (แบบที่ `/queues` ทำเมื่อ 2026-08-12) ไม่ใช่ปล่อยให้ stack เอง
- **A ทำงานได้ทั้ง 3 ขนาดโดยไม่ต้องมีทางแยก** แต่ที่ 1280 มันเป็นคอลัมน์เดียวกลางจอ = เปลืองพื้นที่แนวนอน

## 🛑 กับดักที่เจอระหว่างทาง — สำคัญกว่าตัวม็อกอัพ

ม็อกอัพเดิมของโปรเจกต์เขียน token เองใหม่ทั้งชุด (`:root{--primary:#236dc9;...}` + `.card` ของตัวเอง)
ซึ่งคือกับดัก "สำเนาเก่าโดยไม่มีอะไรเตือน" ที่คอมมิต `e3e2ced5` เพิ่งถอด CSS 1MB ออกเพื่อเลี่ยง

ไฟล์นี้จึง **ดึง CSS สดจาก prod** (`seller.deepthailand.app/_next/static/chunks/*.css`) แทน
— ได้ token จริงของวันนี้ ไม่ต้องรัน dev server และไม่มีสำเนาให้เก่า

**แต่มีเงื่อนไขที่ต้องรู้:** Tailwind v4 คอมไพล์เฉพาะ utility ที่ **แอปใช้จริง**
⇒ คลาสที่แอปไม่เคยใช้จะ **ไม่มีในไฟล์ และเงียบสนิท ไม่มี error ไม่มีอะไรเตือน**

เกิดขึ้นจริงกับไฟล์นี้: รอบแรกเขียน `lg:grid-cols-12` / `lg:col-span-4` / `lg:col-span-8`
ซึ่งไม่มีในชุด ⇒ **Variant B เรนเดอร์เป็นคอลัมน์เดียวทั้งที่ออกแบบเป็นสองคอลัมน์ — และดูเหมือนตั้งใจ**
ถ้าไม่ได้เปิดวัด `getComputedStyle` จะส่งม็อกอัพที่โกหกไปให้หัวหน้าตัดสินใจ

**วิธีกัน** — ก่อนใช้คลาสไหน ตรวจก่อน:
```bash
curl -sL https://seller.deepthailand.app/dashboard | grep -oE '/_next/static/[^"]+\.css'
curl -sL https://seller.deepthailand.app/_next/static/chunks/<hash>.css | grep -o 'lg\\:col-span-2'
```
ที่ยืนยันแล้วว่ามี: `grid-cols-1..6` · `lg:grid-cols-2..6` · `lg:col-span-1..3` ·
`xl:grid-cols-10/12` · `xl:col-span-3/5/7` · `md:col-span-2..12` · `ps-3/4/5` · `pe-2/3` · `border-s-3`
ที่ยืนยันแล้วว่า **ไม่มี**: `btn-primary` · `btn-ghost` · `btn-warning` · `lg:grid-cols-12` ·
`lg:col-span-4/8` · `pe-4` · `sm:border-s` · `sm:ps-4`

## ถ้าเลือกได้แล้ว

คำตอบที่มีประโยชน์ที่สุดมักไม่ใช่ "เอา A" แต่เป็น **"เอาหัวกลุ่มของ A + แผงขวาของ B"**
เขียนคำตอบ (ทางเลือกไหน เพราะอะไร) ลงไฟล์นี้ แล้ว:

1. ผ่าน `safepay-ux` ออก Design Spec ของตัวที่ชนะ (HR8) — **ห้ามก็อป markup จากม็อกอัพเข้าโค้ดจริง**
   โค้ดในนี้เขียนใต้เงื่อนไข prototype: ไม่มีเทส ไม่มี error handling ไม่มี a11y ครบ
2. รัน `/impeccable critique` หลัง build เสร็จ (HR8 gate)
3. ทั้ง `.html` + `.md` อยู่บน branch `proto/customer-redesign-2026-08-26` **ไม่เอาเข้า main**
   — repo นี้ push main = deploy prod ทันที
