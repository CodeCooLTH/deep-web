กราฟยอดขาย — ร้านประเภท “สินค้าและบริการ” (SERVICE_QUEUE)

ตัวอย่างข้อมูล: BT Premium เดือน ส.ค. 2569 · วันนี้ = 7 · แท่งทึบ = เงินเข้ามือร้านแล้ว (นับในเลขฮีโร่) · แท่งลายทาง = เงินที่ยังไม่เข้า (ไม่นับ)

แบบที่เคาะแล้ว — แท่งโปร่งลายทาง + นัดค้างเป็นสีแดง

นิยามที่กราฟนี้ใช้ (SERVICE_QUEUE เท่านั้น — vertical อื่นไม่แตะ)

ชั้นยอดลงตะกร้าวันไหน
มัดจำ Σ depositAmount เฉพาะใบที่ depositReceivedAt != null วันของ depositReceivedAt — วันที่เงินเข้าจริง
เสร็จสิ้น Σ (totalAmount − มัดจำที่รับแล้ว) มีนัด → วัน serviceStart เมื่อ appointmentStatus = COMPLETED
ไม่มีนัด → วัน createdAt
วันเข้ารับบริการ Σ (totalAmount − มัดจำที่รับแล้ว) ของนัดที่ยังไม่ COMPLETED / NO_SHOW วัน serviceStart · ≥ วันนี้
เลยวันนัด สูตรเดียวกัน วัน serviceStart · < วันนี้ = ค้างต้องตามเก็บ
  • เลขฮีโร่ 8,300 = มัดจำ 3,100 + เสร็จสิ้น 5,200 — เงินเข้ามือจริงเท่านั้น ไม่รวม 18,900 ที่รออยู่
  • ไม่มีการนับซ้ำ — เงินก้อนเดียวลงได้ตะกร้าเดียว: มัดจำลงวันรับมัดจำ ส่วนที่เหลือลงวันปิดงาน
  • NO_SHOW หายจากกราฟเอง ไม่ต้องเขียนกฎเพิ่ม — มัดจำที่ริบไว้ยังนับอยู่ (เข้าไปแล้วตั้งแต่วันรับ) ส่วนที่เหลือไม่เคยถูกนับ แท่งลายทางหายไป
  • วันที่มีทั้งเงินเข้าและนัดค้างในวันเดียวกัน แท่งจะซ้อนกัน — ความสูงทั้งแท่ง = มูลค่างานของวันนั้น ส่วนที่ลายทางคือส่วนที่ยังไม่ได้รับ
  • เส้น “จำนวนการเข้ารับบริการ” (นับใบ) ของเดิมถูกแทนที่ — ตัวนับใบยังอยู่ในชีตเต็มจอ

งานที่พ่วงมาด้วย (ไม่ใช่แค่แก้กราฟ)

  • คอลัมน์ใหม่ Order.depositReceivedAt — ตอนสร้างงานมี checkbox “รับเงินมัดจำแล้ว” ติ๊กมาจากโรงงาน (กรณีปกติคือรับมัดจำหน้าร้านตอนจอง) · ปลดติ๊กได้ แล้วค่อยกด “รับมัดจำแล้ว” ทีหลังในหน้างาน
  • ปุ่ม “เสร็จสิ้น / ไม่มาตามนัด” — service + API มีครบตั้งแต่ feature 00024 แต่ไม่มีหน้าจอไหนเรียกเลย (grep ทั้ง repo = 0) ถ้าไม่ทำ แท่งเขียวจะเป็น 0 ตลอดกาล · ตำแหน่งปุ่มต้องผ่าน safepay-ux ตาม Hard Rule 8
  • หน้า /sales เปลี่ยนนิยามตามด้วย · กำไรขาดทุน /expenses ไม่แตะรอบนี้
