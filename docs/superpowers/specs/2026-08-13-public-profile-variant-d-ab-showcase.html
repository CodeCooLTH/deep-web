Variant D · A+B Showcase — rev9 ใช้ข้อมูลจริงจาก /b/tanapathardware

แก้ 2 อย่างตามที่ทักมา: (1) แผงหลักฐานเหลือ 3 บรรทัด (เดิมไทล์ 2×2 = 12 บรรทัด) (2) ช่องทางโซเชียลกลายเป็นบล็อก "ช่องทางทางการ" ที่พูดออกมาตรง ๆ ว่ายืนยันความเป็นเจ้าของแล้ว

ทำไมแผงหลักฐานเดิมถึงอ่านยาก — ไม่ใช่แค่ข้อความเยอะ แต่มัน "ซ้ำ"
3 ใน 4 ไทล์พูดเรื่องเดียวกับแถวตัวเลขที่อยู่เหนือมันไม่ถึง 40px (ออเดอร์ · ลูกค้า · ซื้อซ้ำ · คะแนนรีวิว) ผู้ชมต้องอ่านของเดิมสองรอบในสองรูปแบบ แล้วสงสัยว่าเลขสองชุดต่างกันตรงไหน
แผงนี้จึงเหลือเฉพาะสิ่งที่แถวตัวเลขบอกไม่ได้: การยืนยันตัวตน · อัตราสำเร็จ · ความเร็วตอบแชท — 3 บรรทัด · กรอบ "คำถาม → คำตอบ" ยังอยู่ครบใน ?variant=b ซึ่งมีพื้นที่แบบแถวเต็มให้มันจริง ๆ
เพจทางการ — รอบสามกลับไปยึดผังที่ prod ใช้อยู่แล้ว
รอบก่อนผมทำเป็นการ์ดเต็มใบ ~200px และโตเป็นเชิงเส้นตามจำนวนเพจ (4 เพจ ≈ 300px+) ⇒ ร้านที่ควรได้ประโยชน์จากบล็อกนี้มากที่สุด กลับโดนมันดันเนื้อหาตกจอมากที่สุด
ผังของ prod (ChannelStrip) กะทัดรัดอยู่แล้ว — เพจเรียงแนวนอน มีรูป+เช็ค / ชื่อ / แพลตฟอร์ม + ยอดติดตาม ครบใน ~44px · ที่ผมเกือบทำรอบสอง (รูปซ้อน + ชื่อเดียว) แย่กว่า prod เพราะสูงเท่ากันแต่เสียชื่อเพจใบที่สอง เสียแพลตฟอร์ม เสียยอดติดตาม
แก้แค่ 2 จุดที่ขาดจริง: (1) เพิ่มบรรทัดกำกับ ~18px ที่มีคำว่า "ทางการ" — ของเดิมความหมายอยู่ในเช็ค 9px + tooltip ที่มือถือเข้าไม่ถึง (2) VISIBLE=2 แล้ว "อีก N" ของ prod กางต่อในหน้า ⇒ เปลี่ยนเป็นเปิดหน้าเต็ม ⇒ ความสูงคงที่ไม่ว่าจะกี่เพจ (ดูเฟรม "กรณี 4 เพจ" ล่างสุด)
ข้อความกันเพจปลอมย้ายไปหน้าเต็ม — ยอมรับข้อแลกเปลี่ยนนี้โดยตั้งใจ: คนที่สงสัยคือคนที่จะกดเข้าไปอ่าน ส่วนที่ยังทำงานโดยไม่ต้องอ่านคือเช็คเขียว + คำว่า "ช่องทางทางการ" + ชื่อเพจ
ช่องทางทางการ — ของเดิมมีหลักฐานอยู่แล้ว แต่มองไม่เห็น
ChannelStrip ที่หน้าจริงใช้อยู่ มีเช็คเขียวอยู่แล้ว ขนาด 9px และความหมายทั้งหมดฝากไว้กับ title= + tooltip ที่ต้องแตะค้าง ⇒ บนมือถือผู้ชมไม่มีทางรู้เลย ว่าเพจนี้ต่างจากลิงก์ที่ใครก็พิมพ์ใส่ได้
กลไกที่ทำให้เชื่อได้คือ OAuth — ร้านเข้าสู่ระบบกับแพลตฟอร์มเองแล้วกดอนุญาต ชื่อและรูปจึงถูกดึงจากแพลตฟอร์มโดยตรง ไม่ใช่ข้อความที่ร้านพิมพ์
สองอย่างที่ห้ามเขียนเด็ดขาด: ห้ามเขียนว่า "Deep ตรวจสอบแล้วว่าเป็นเพจของร้าน" (เราไม่ได้ตรวจ เรารับผลจาก OAuth) · ห้ามเขียนว่าเพจที่ไม่อยู่ในรายการเป็นเพจปลอม (ร้านอาจมีเพจจริงที่ยังไม่ได้เชื่อม) — ประโยคที่พูดได้จริงคือ "ยังไม่ได้ยืนยันกับ Deep" ซึ่งพอสำหรับการตัดสินใจอยู่แล้ว
เหรียญ — เด่นด้วย "ตำแหน่ง + ปลายทาง" ไม่ใช่ด้วยพื้นที่
"ให้เด่นขึ้น" กับ "ลดพื้นที่" ไปด้วยกันไม่ได้ถ้าคิดแค่เรื่องขนาด — แถวสรุปแบบ IG สูงราว 40px (กริดชื่อใต้ไอคอนเดิมสูง ~96px) แต่ย้ายขึ้นมาอยู่ในแผงหลักฐานเดียวกัน ใต้บรรทัดยืนยันตัวตน แล้วมี "+ อีก N" ที่กดไปหน้าเต็มได้จริง
ปลายทางนี้คือของที่ระบบยังไม่เคยมี — ProfileHero.tsx เขียนกำกับไว้เองว่า "ไม่มีลิงก์ ดูทั้งหมด เพราะยังไม่มีปลายทางให้ไป" แถวสรุปบนมือถือของหน้าจริงจึงกดไม่ได้มาตลอด ทั้งที่ criteriaLabel + earnedAtIso ถูกส่งมาถึงหน้าจอครบแล้ว ⇒ ผู้ใช้มือถือไม่เคยรู้เลยว่าเหรียญแต่ละใบได้มายังไง
เหรียญอยู่ในแผงหลักฐานไม่ใช่บล็อกแยก เพราะมันคือหลักฐานชนิดหนึ่ง (ระบบมอบให้เองจากพฤติกรรมจริง ร้านขอเองหรือซื้อไม่ได้) — แยกออกไปเมื่อไหร่มันจะอ่านเป็นของประดับ ซึ่ง DESIGN.md ห้ามไว้ตรงตัว
คำอธิบายร้าน — ย่อ 2 บรรทัด กดที่ตัวข้อความเพื่อกาง
ของจริงใน ProfileHero ทำแบบนี้อยู่แล้ว แต่ variant D รอบก่อนผมลืมยกมา ปล่อยเป็นข้อความเต็ม 4 บรรทัด
🛑 หัวใจของแพตเทิร์นนี้คือ ปุ่มโผล่จากการวัดว่าล้นจริง ไม่ใช่นับจำนวนตัวอักษร — ภาษาไทยไม่มีช่องว่างระหว่างคำ จำนวนอักขระบอกไม่ได้ว่าจะตก 2 บรรทัดไหม (เคยพลาดจนปุ่มโผล่ตลอดแม้ข้อความสั้น — ที่มาของ lib/clamp-overflow.ts) · คำว่า "เพิ่มเติม" ซ้อนท้ายบรรทัดสุดท้ายบนพื้นทึบ ไม่กินบรรทัดใหม่
แท็บกลับมาแล้ว — ผมถอดออกเองโดยไม่ได้บอก
ผมเอาแท็บออกตั้งแต่ variant A (เหตุผลตอนนั้น: หลักฐานถูกซ่อนหลังแท็บที่คนส่วนใหญ่ไม่กด) แล้ว D สืบทอดมา
🛑 แต่ "ถอดแท็บ" กับ "ชูของให้เด่น" ขัดกันเองบนมือถือ: ไม่มีแท็บ = คลิป + สินค้า + รีวิว + เกี่ยวกับร้าน ต่อกันเป็นหน้าเดียวยาวมาก ยิ่งของเยอะยิ่งยาว ⇒ ของที่อยู่ล่างสุดไม่มีใครเห็นอยู่ดี การซ่อนไว้หลังแท็บที่กดได้ ดีกว่าการวางไว้ล่างสุดที่ไม่มีใครเลื่อนถึง
ทางออก: เอาแท็บกลับ (ผังเดียวกับ prod) แล้วยก แถวโชว์ไว้เหนือแท็บ — ของที่ร้านอยากให้เห็นจึงเห็นทันทีโดยไม่ต้องกดแท็บ
ต่างจาก prod จุดเดียว: แท็บรีวิวแสดงเสมอแม้ยังไม่มีรีวิว — prod ตัดทั้งแท็บทิ้งเมื่อ 0 รีวิว ซึ่งอ่านว่า "หน้านี้ไม่มีเรื่องรีวิว" ไม่ใช่ "ร้านนี้ยังไม่มีใครรีวิว" (ร้านจริงที่ดู: 179 ออเดอร์ / 0 รีวิว)
rev9 — แก้ม็อกอัพที่ขัดกันเอง + ตามที่ user เคาะ
rev8 ใส่ "95% ตัวใหญ่" ไม่ครบทุกเฟรม (มือถือได้ทั้งตัวใหญ่และบรรทัดในลิสต์ = เลขซ้ำสองที่ · เดสก์ท็อปไม่ได้เลย) ⇒ เทียบกับเฟรมไหนก็เห็นคนละแบบ
user เคาะให้เป็น 3 บรรทัดเท่ากัน — ถอดตัวเลขนำออกทุกเฟรม อัตราสำเร็จกลับเป็นบรรทัดเดียวเท่าบรรทัดอื่น · ข้อแลกเปลี่ยนที่รับไว้: 95% จะเล็กกว่า "ซื้อซ้ำ 8" ในแถวตัวเลขด้านบน ทั้งที่เป็นหลักฐานที่แข็งกว่า (critique P1 เคยชี้จุดนี้)
คำว่า "Official Page" ในภาษาไทย → ใช้ "เพจทางการ"
เทียบตัวเลือก: "เพจทางการ" = คำที่คนไทยใช้เรียกของสิ่งนี้จริง อ่านออกทันที · "ช่องทางทางการ" (ที่ผมใช้รอบก่อน) = ตรงกับศัพท์ภายในระบบ (ShopChannel, หน้าตั้งค่าฝั่งผู้ขาย) แต่ "ทางการ" ซ้อน "ช่องทาง" อ่านแข็งแบบราชการ ซึ่งขัด Brand Personality ("credibility ที่อบอุ่น ไม่ใช่ข่มขู่") · "บัญชีทางการ" = คำที่ LINE ใช้เอง แต่คนไม่ใช้กับ Facebook
ข้อแลกเปลี่ยนที่รับไว้: แถว Instagram / LINE OA ไม่ใช่ "เพจ" ตามนิยามเคร่งครัด — แต่ป้ายแพลตฟอร์มรายแถวบอกชนิดไว้แล้ว และบนบรรทัดที่มีไว้กันเพจปลอม คำที่คนอ่านออกทันทีสำคัญกว่าความถูกต้องทางเทคนิค
🛑 ถ้าเลือกคำนี้ ต้องเปลี่ยนทุกที่ที่ผู้ซื้อเห็นพร้อมกัน (แท็บ "เกี่ยวกับร้าน" ของหน้าจริงยังเขียน "ช่องทางที่เชื่อมต่อ") — สองคำสำหรับของสิ่งเดียวกันบนหน้าเดียวคือสิ่งที่ HR16 ห้าม
rev8 — แก้ตามผล critique รอบ 2 (คะแนน 19/40)
P0: ชิป 41/100 กดได้แล้ว เปิดแผงอธิบาย (เฟรมล่างสุด) ที่ยกจาก ProfileHero ทั้งชุดไม่แก้ถ้อยคำ — รวมประโยค "ร้านไม่สามารถซื้อหรือปลอมคะแนนได้" ซึ่ง PRODUCT.md สร้างจุดยืนทั้งหมดไว้บนมัน และหน้านี้เคยลบที่เดียวที่พูดมันออกไป
P1: ยก 95% อัตราสำเร็จ ขึ้นเป็นตัวเลขนำของแผงหลักฐาน 22px สี Verified Ink #18804A — รอบก่อนผมลดตัวเลขโซเชียลลง 18px แต่ไม่เคยยกตัวที่ดีขึ้น ทำให้ 2 ซื้อซ้ำ ยังดังกว่า 95% ทั้งที่ 95% จาก 168 ใบคือหลักฐานแข็งที่สุดที่ร้านนี้มี
+ แก้ regression 2 ตัวที่ผมสร้างเองรอบก่อน (ไม่เห็นในม็อกอัพ เพราะเป็น a11y): ถอด aria-label ที่บังราคาจาก screen reader · ย้าย <h2> ออกนอก <button> ที่ทำให้ heading ถูกถอดจาก a11y tree
ข้อมูลจริงจาก prod ล้มสิ่งที่ผมสมมติไว้รอบก่อน 4 ข้อ — ร้านนี้ ไม่มีรีวิวเลยสักใบ (ไม่มีแท็บรีวิวบนหน้าจริง) ทั้งที่มี 179 ออเดอร์ · ยืนยันแค่ระดับ 1 (เบอร์โทร) จึงไม่ใช่สีเขียวตามกฎ Verified-Means-Green · คะแนน 41/100 = Deep Classic ไม่ใช่ Gold แบบที่ผมสมมติ ปกจึงเป็นโทนอำพันเข้ม · เปิดร้านเดือนที่แล้ว (ก.ค. 2569) แต่ทำได้ 179 ออเดอร์
