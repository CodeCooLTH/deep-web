## 1. Flow 4 ขั้น (user เคาะ 2026-10-10)

| ขั้น | ใครกด | ทำอะไร | ค่าในระบบ |
|---|---|---|---|
| 1 | ร้าน | สร้างงาน / จองนัด → ส่งลิงก์ | `status PENDING` · `appointmentStatus SCHEDULED` (walk-in = null) |
| 2 | ลูกค้า (ไม่บังคับ) | ยืนยันนัด · ขอเลื่อนได้ | `CONFIRMED_BY_BUYER` / `RESCHEDULE_REQUESTED` |
| 3 | ร้าน | **ปิดงาน — กดครั้งเดียว**: เลือกผล (ให้บริการแล้ว / ไม่มาตามนัด) + รับเงินที่เหลือ | `COMPLETED`/`NO_SHOW` + `OrderPayment` + **`serviceClosedAt` (ใหม่)** |
| 4 | ลูกค้า | ยืนยันรับบริการ = จบ · รีวิวได้ทันที | `status CONFIRMED` |

- ลูกค้า login OTP แล้วกดขั้น 4 ได้เลย ข้ามขั้น 2–3
- **เงินภายในร้านทั้งหมดนับที่ขั้น 3** (ยอดขาย · กำไรขาดทุน · ยอดสะสมลูกค้า · แดชบอร์ด · ชีตการเงิน · รายงาน LINE · รายงานแอดมิน · Portfolio) — วันที่ของยอด = **วันปิดงาน**
- **หน้าร้านสาธารณะนับที่ขั้น 4** (งานสำเร็จ · Trust Score · รีวิว) — คงเดิม (`order-stats.ts`, `trust-score.service.ts`, `review.service.ts`)

### มติเพิ่ม (2026-10-10)
1. มัดจำที่รับตอนจอง → นับเข้ายอดขาย **ทั้งก้อนตอนปิดงาน** (ไม่ใช่วันที่รับแบบ 00034) · ก่อนปิดแสดงเป็น "มัดจำรับล่วงหน้า"
2. ไม่มาตามนัด + ร้านเก็บมัดจำ → **นับมัดจำเป็นยอดขาย** (คืนมัดจำ = ไม่มียอด)
3. ลูกค้าขอเลื่อน → เก็บไว้ในขั้น 2 · ร้านเลือกเวลาใหม่แล้วกลับเป็น "จองแล้ว"
4. walk-in → ข้ามจากขั้น 1 ไปปิดงานได้ทันที
5. งานเก่าที่ลูกค้ายืนยันแล้วแต่ร้านไม่เคยปิด → **ปิดย้อนหลังอัตโนมัติ** (วันปิด = วันลูกค้ายืนยัน) ครั้งเดียวตอน deploy

## 3. ตั้งค่ารายงานการเงิน (หน้าใหม่ `/settings/report`)

- สวิตช์: ยอดขาย (เปิดเสมอ) · รับเงินแล้ว/ค้างรับ · มัดจำรับล่วงหน้า · จำนวนงาน · ต้นทุนอะไหล่ · ค่าใช้จ่ายร้าน · กำไรขาดทุน
- รูปแบบกราฟ: แท่งซ้อน (ค่าเริ่มต้น) · แท่งคู่ · เส้น · พื้นที่ · ตัวเลขหลักบนการ์ด · ช่วงเวลาเริ่มต้น

- กราฟ 3 แท็บ (อิงตัวอย่างที่ user ส่ง): ยอดขาย (แท่งเดียว รับแล้ว+ค้างรับ · กดแท่งดูยอด · ยอดรวม+แถบสัดส่วน) · ค่าใช้จ่าย (ค่าใช้จ่ายร้าน+ต้นทุน) · สรุปภาพรวม (แท่งคู่ + ส่วนต่าง)

## 6. มติเพิ่ม (user เคาะ 2026-10-11 — "ตามแนะนำ")
1. **ตัดขั้น "เริ่มให้บริการแล้ว" (SHIPPED) ออกจากร้านบริการ** — ไม่มีให้กด ไม่มีการ์ด/ตัวกรอง/เช็กลิสต์ในหน้างานบริการ · ข้อมูลจริงร้านบริการในเครื่อง = 0 งานอยู่สถานะนี้ · ถ้าบน prod มีค้าง → ย้ายเป็น "ปิดงานแล้ว" (วันปิด = `updatedAt` ตอนเปลี่ยนเป็น SHIPPED / event ที่บันทึก) ใน migration ปิดย้อนหลัง
2. **เลิกใช้ "ยกเลิก + เหตุผลลูกค้าไม่มา (BUYER_NO_SHOW)" ในร้านบริการ** — ไม่มาตามนัดทำผ่าน "ปิดงาน → ไม่มาตามนัด" ทางเดียว (เลือกเก็บ/คืนมัดจำ) · ตัวเลือกเหตุผลนี้ซ่อนในหน้ายกเลิกของร้านบริการ · งานเก่าที่ยกเลิกด้วยเหตุผลนี้คงเป็น "ยกเลิก" (ไม่แก้ย้อนหลัง)
3. **ปิดการยืนยันอัตโนมัติ 3 ทางสำหรับร้านบริการ** (`order-auto-confirm` ส่งถึง+7 วัน · `order-pickup-auto-confirm` รับที่ร้าน+48 ชม. · `settleCodFromCarrier` COD) — "สำเร็จ" ของร้านบริการมาจากลูกค้ากดเองเท่านั้น · ร้านประเภทอื่นทำงานเหมือนเดิมทุกอย่าง
4. **ยังไม่ทำ "ค้างจ่าย" ของค่าใช้จ่าย** — แท็บค่าใช้จ่ายในกราฟแบ่งเป็น ค่าใช้จ่ายร้าน + ต้นทุนอะไหล่ · ถ้าจะทำภายหลัง = งานแยก (`Expense.paidAt` + วันครบกำหนด + ช่องในฟอร์ม)

## 6.1 การันตีว่าไม่กระทบร้านประเภทอื่น
- ทุกพฤติกรรมใหม่ผ่านฟังก์ชันตัดสินตัวเดียวใน `src/lib` (ต่อยอด `usesServiceFinanceRules`) — ห้ามเขียน `vertical === 'SERVICE_QUEUE'` สด

- migration เพิ่มอย่างเดียว · การปิดย้อนหลังแตะเฉพาะงานของร้าน SERVICE_QUEUE
