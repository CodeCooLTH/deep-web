## 1. ปัญหา

แถบพัสดุมี **4 จุดตายตัว** (`SHIPMENT_STAGES` ใน `src/lib/iship/status.ts:247`) และ "ขาตีกลับ" ถูกยัดลงไปโดย
override แค่ *คำ* (`lastLabel`) กับ *ไอคอน* (`lastIcon`) ของจุดที่ 4:

| รหัสขนส่ง | ปักจุดที่ | ผลบนจอ |
|---|---|---|
| `return` (กำลังตีกลับ) | 2 | **ตำแหน่งเดียวกับ "กำลังจัดส่ง" เป๊ะ** |
| `return_success` (ถึงร้าน) | 3 | **ยึดช่องของ "จัดส่งสำเร็จ"** |

⇒ พัสดุที่ตีกลับมากองที่ร้านอ่านว่า **"เดินหน้าครบ 4 ขั้น จบสวย"** และครึ่งหลังของเรื่อง
(ตีกลับเมื่อไร ทำไม ถึงร้านหรือยัง) ไม่มีที่ยืนบนจอเลย

| ออเดอร์ที่มีพัสดุ active >1 | 0 |

### 🛑 บั๊กที่เจอระหว่างทาง — 00056 เปิดพัสดุขากลับไม่ได้เลยสักใบ

```sql
CREATE UNIQUE INDEX "OrderShipment_active_order_key"
    ON "OrderShipment"("orderId") WHERE "status" <> 'CANCELLED';
```

**ไม่มีคอลัมน์ `direction` ใน index และไม่เคยถูกแก้** (ยืนยันกับ `pg_indexes` บน prod แล้ว)

1. `canCreateReturn()` บังคับว่าเปิดใบคืนได้ต่อเมื่อของถึงมือลูกค้า ⇒ ออเดอร์นั้น**มีพัสดุขาไป `CREATED` แน่นอน**
2. `createReturnShipment()` (`iship.service.ts:1027`) `create({ status:'PENDING', direction:'RETURN' })` บน `orderId` เดิม
3. index เห็น `PENDING ≠ CANCELLED` ⇒ **P2002**
4. ฟังก์ชันนั้น **ไม่มี try/catch P2002** ⇒ ร้านได้ 500 ดิบ

`RETURN = 0 แถว` บน prod คือหลักฐานยืนยัน — ยังไม่มีร้านไหนเจอเพราะยังไม่มีใครกด

## 6. 🛑 หนี้ที่ต้องบันทึก — และคำที่เคยเขียนไว้ต่ำกว่าความจริง

### 6.1 เคส "คืนของ" (00056) **เข้าไม่ถึงทั้ง 6 จอ** ไม่ใช่แค่ตาราง

ข้อความเดิมในไฟล์นี้เขียนว่า *"ตาราง `/orders` ยังมองไม่เห็นเคสคืนของ"* ซึ่ง **ต่ำกว่าความจริง**

ตรวจซ้ำ 2026-08-25 (impeccable critique): `rg "orderReturn" src/ --glob '*.tsx'` คืน **1 บรรทัด
และเป็นคอมเมนต์** ⇒ **ไม่มีจอไหนส่ง `orderReturn` เข้า `describeReturnLeg()` เลยสักจอ**
กิ่ง `RETURN` ทั้งกิ่ง (คำ `ลูกค้าแจ้งคืน`/`คุณแจ้งคืน`/`ร้านได้รับแล้ว` · จำนวนจุด 4/3/2 ตาม
`trackingSource`) **ยังไม่เคยขึ้นจอจริงสักครั้ง**

**ทำไมถึงเป็นแบบนั้น:** หน้ารายละเอียดออเดอร์ก็ไม่ได้โหลดข้อมูลใบคืนฝั่ง server เหมือนกัน —
`OrderDetailClient.tsx:528` ส่ง `initialCount={0}` ให้ `ReturnPanel` แล้วให้มันยิง API เอาเอง
ตอนเปิด พร้อมคอมเมนต์ว่า *"ออเดอร์ส่วนใหญ่ไม่มีการคืนของ การนับทุกครั้งที่เปิดหน้าคือคิวรีที่
แทบไม่มีใครได้ใช้"* ⇒ ไม่ใช่แค่ตารางที่เลี่ยง join ทั้งหน้ารายละเอียดก็เลี่ยงเหมือนกัน

🛑 **นี่คือ "ฟีเจอร์ที่ยังไม่เสร็จ" ตามเกณฑ์ของ `known-limitation-vs-unfinished.md`
ไม่ใช่ "หนี้ที่รู้ตัว"** — Q1 ที่ user เคาะคือ **ก+ข** (ตีกลับ + คืนของ) และครึ่งหนึ่งของ
ขอบเขตนั้นเข้าไม่ถึงเลย · Q26(C) ที่ user อนุมัติถูกอธิบายว่า "ตารางมองไม่เห็น" ซึ่งเป็น
คนละขนาดกับความจริง **ต้องให้ user ตัดสินใหม่บนข้อมูลที่ถูก ไม่ใช่ปล่อยผ่านด้วยมติเดิม**

**ทางเลือกเมื่อจะทำต่อ:** หน้ารายละเอียด (`ShippingCard`) เป็นที่ที่คุ้มที่สุด — ร้านจัดการ
ใบคืนที่นั่นอยู่แล้ว และเป็นการเปิดหน้าทีละใบ ไม่ใช่เส้นทางร้อนแบบตาราง

### 6.2 ป้ายใต้จุดล้นในคอลัมน์ 1/4 ของหน้ารายละเอียด (**ของเดิม ไม่ใช่ของรอบนี้**)

`ShippingCard` ถูกวางใน `grid lg:grid-cols-4` ที่ฝั่งซ้ายกิน `col-span-3` ⇒ เนื้อที่แถบ

### 6.3 คอนทราสต์ไอคอนในจุด — ตก WCAG 1.4.11 (**ของเดิมทั้ง family**)
