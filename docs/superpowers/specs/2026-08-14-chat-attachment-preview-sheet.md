# ชีตพรีวิวไฟล์แนบเต็มจอ (มือถือ) — กล่องแชทผู้ขาย

> # 🛑 สถานะ: **ขึ้น prod แล้วถอดออกในวันเดียวกัน (2026-08-14)** — อย่าทำซ้ำตามเอกสารนี้
>
> ขึ้น prod `e3a3c167` แล้ว revert `d2e5b8a5` ภายในไม่กี่สิบนาที เอกสารทั้งฉบับด้านล่างเก็บไว้เป็น
> **หลักฐานว่าอะไรถูกทดลองแล้วไม่ได้ผล** ไม่ใช่สเปกของของที่มีอยู่จริง
>
> ## สองข้อที่พังและเป็นบทเรียนจริง
>
> **1. `accept="image/*"` ไม่ได้ข้ามเมนูของ iOS — ข้อนี้ผิดล้วน ๆ**
> D-3 อ้างว่าปุ่มที่ระบุ `accept="image/*"` จะพาเข้าคลังรูปตรง ๆ ลดการแตะไป 1 ชั้น. ของจริงคือ
> iOS ขึ้นเมนู "Photo Library / Take Photo / Choose Files" เหมือนเดิมทุกประการ — **เว็บไม่มีวิธี
> สั่งปลายทางของ picker ได้เลย** แอตทริบิวต์เดียวที่บังคับได้คือ `capture` ซึ่งแปลว่า "เปิดกล้อง"
> (ตรงข้ามกับที่ต้องการ) ไม่มีค่าที่แปลว่า "คลังรูป"
> 🛑 ข้อนี้ถูกเขียนไว้ในสเปกฉบับนี้เองว่า "ยังไม่ verify ด้วยมือจริง" แล้วยังถูกยกไปเขียนเป็น
> **ข้อเท็จจริง** ในคอมมิตและในคำอธิบายให้ user — user เป็นคนจับได้ในนาทีแรกที่กด
> (คลาสเดียวกับ `docs/conventions/value-fate-decided-at-write-site.md`)
>
> **2. ชีตไม่ได้ลดขั้นตอน มันเพิ่มจอ**
> จำนวนแตะก่อน/หลังเท่ากันเป๊ะ (6 ครั้ง) แต่มีจอเต็มมาคั่นระหว่าง "เลือกรูปเสร็จ" กับ "กดส่ง"
> ซึ่งซ้ำกับที่ picker ของ iOS โชว์รูปที่เลือกให้ดูอยู่แล้ว. user: *"step งงกว่าเดิม … กว่าจะได้กดส่ง"*
> **เหตุผลเชิงโครงสร้าง:** ใน Messenger หน้าเลือกรูปกับปุ่มส่งคือจอเดียวกัน ของเราแยกเป็น 2 จอเสมอ
> เพราะจอแรกเป็นของ OS ที่เราแตะไม่ได้ ⇒ ชีตของเราไม่มีทางเป็น "ทางลัด" ได้ เป็นได้แค่จอยืนยันเพิ่ม
> — ประเมินข้อนี้ได้ตั้งแต่ก่อนลงมือ แต่ไม่ได้นับจำนวนแตะจริงมาเทียบ
>
> ## ทางที่เหลืออยู่จริงมีทางเดียว: native
> ให้ฝั่ง native ของแอปผู้ขายดักการกดปุ่ม แล้วเปิด image picker ของเครื่องเอง (ข้ามเมนู 3 ตัวเลือก)
> แล้วส่งไฟล์กลับเข้าเว็บผ่าน bridge ที่มีอยู่แล้ว (`src/lib/native-bridge.ts`) ⇒ ได้ flow ที่ user
> ขอตรงตัว: *กดไอคอน → คลังรูปเปิดทันที → เลือก → กดส่ง*
> ใช้ได้เฉพาะคนที่เปิดผ่านแอป · ต้องแก้รีโปแอป + build + ส่ง store
>
> **สิ่งที่เก็บไว้จากรอบนี้ (ไม่เกี่ยวกับชีต):** คีย์ i18n `attachUploading`/`attachRemove`
> (เดิมเป็นสตริงดิบใน `ChatThread.tsx`) · ปุ่มลบบนคิวไฟล์ `bg-black/50` → `bg-dark/60`
> · คอมเมนต์เตือนเรื่อง `accept` ที่ `ChatThread.tsx` เหนือปุ่มแนบไฟล์

## 1. ข้อจำกัดที่ตัดสินขอบเขตทั้งหมด

🛑 **เว็บอ่านคลังรูปในเครื่องมาวาดกริดเองไม่ได้ — ไม่ว่าในเบราว์เซอร์หรือใน WebView ของแอปเรา** ไม่มี API ให้ JavaScript แตะ Photos framework; สิ่งเดียวที่เรียกได้คือ `<input type="file">` ซึ่ง **ยกหน้าจอเลือกไฟล์ทั้งหมดให้ OS** เราแต่งอะไรข้างในไม่ได้เลย (ไม่มี "Recents ▾" ไม่มีปุ่ม HD)

⇒ ครึ่งบนของภาพอ้างอิงเป็น native code ของ Messenger เอง **ทำได้ทางเดียวคือเขียน native module + bridge เข้า WebView ซึ่งต้อง build + ส่ง store ใหม่ และใช้ไม่ได้กับผู้ขายที่เปิดผ่าน Safari/Chrome ตรง ๆ**

⇒ **มติ (user เคาะ 2026-08-14): ทำเวอร์ชันเว็บล้วน** — ขั้นตอนเลือกไฟล์ยังเป็น picker ของ OS (ซึ่ง iOS 14+/Android 13+ หน้าตาใกล้เคียงของ Messenger อยู่แล้ว: เต็มจอ, กริด, badge ตัวเลข, ปุ่มยืนยันล่างจอ) แล้ว **ชีตของเราขึ้นมารับช่วงต่อหลังเลือกไฟล์เสร็จ** ซึ่งเป็นครึ่งที่ระบบเราแย่กว่าเขาจริง ๆ (ตอนนี้ได้แค่แถบ thumbnail แคบ ๆ `ChatThread.tsx:3907-3949`)

## 4. Acceptance criteria

- **AC-01** viewport <768 → แนบ 3 รูป → ชีตเต็มจอ กริด 3 รูป + ปุ่ม "ส่ง 3 รายการ"
- **AC-02** ลบ 1 รูป → กริดเหลือ 2 → ปุ่มเปลี่ยนเป็น "ส่ง 2 รายการ" ทันที
- **AC-03** ลบจนเหลือ 0 → ชีตปิดเอง กลับ composer เดิม
- **AC-04** กดส่ง → ชีตปิด → บับเบิลรูป N ใบขึ้นในเธรดตามลำดับที่เลือก
- **AC-05** แนบ `.pdf` ในเธรด LINE (ไม่รับไฟล์เอกสาร) → toast error, ไฟล์ไม่โผล่ในกริด
- **AC-06** viewport ≥768 → แนบไฟล์ → แถบ thumbnail เดิมทุกประการ ไม่มีชีต
- **AC-07** ชีตเปิด → ลากนิ้วบนพื้นหลัง → เธรดไม่เลื่อน (scroll lock)
- **AC-08** ชีตเปิด → กด back (Android) → ชีตปิด ไม่ออกจากหน้าเธรด
- **AC-09** พิมพ์ข้อความ → แนบรูป → เห็นบรรทัด "จะส่งข้อความนี้ไปด้วย: …" เหนือปุ่มส่ง
- **AC-10** ปิดชีตโดยไม่ส่ง → ไฟล์ยังอยู่ครบในแถบ thumbnail เดิม พิมพ์ต่อแล้วกดส่งจาก composer ได้

## 6. Edge cases

| กรณี | พฤติกรรม |
|---|---|
| ไฟล์บางใบล้ม (oversize/ชนิดไม่รองรับ) | ไม่เข้า `pendingImages` (ของเดิม) · toast `z-1080` ลอย **เหนือ** ชีต `z-80` ⇒ ยังเห็น ไม่หายเงียบ · ไฟล์ที่สำเร็จเข้ากริดปกติ |
| ไฟล์เอกสาร/เสียง (พรีวิวไม่ได้) | ชิปไอคอน + ชื่อ + ขนาด ไม่ใช่กรอบเทาว่าง |
| `composerDisabled=true` | ปุ่มแนบทั้งคู่ disabled ตั้งแต่ต้น · ถ้ามีไฟล์ค้างจากก่อนหน้า ชีตเปิดได้แต่ปุ่มส่ง+"เพิ่มไฟล์" disabled พร้อมเหตุผลเหนือปุ่ม |
| กด "เพิ่มไฟล์" แล้วยกเลิก picker | ไม่มี `onChange` ยิง → ชีตอยู่ครบ (ผ่านโดยธรรมชาติ ไม่ต้อง handle) |
| หมุนจอข้าม 768px ตอนชีตเปิด | `matchMedia('change')` → ชีต unmount, แถบ thumbnail เดิม render แทนในเฟรมเดียวกัน ไม่มีช่วงว่าง |
| ปิดชีตแล้วไฟล์ที่เหลือในคิวอัปโหลดเสร็จ | 🛑 **ห้ามเด้งชีตกลับมาเอง** — `dismissed` รีเซ็ตที่ event "ผู้ใช้เลือกไฟล์ใหม่" (`onChange`/paste/drop) ไม่ใช่ที่ "`pendingImages` ยาวขึ้น" ไม่งั้นชีตที่เพิ่งปิดจะเด้งกลับทุกครั้งที่ไฟล์ถัดไปอัปโหลดเสร็จ |

## 7. งบพื้นที่ 320px (กางก่อนเสนอ ตาม `flex-header-truncation.md`)

หลัง `px-4` เหลือ **288px** · `.btn.btn-icon` = 37px · `gap-1` = 4px

- base case ปัจจุบัน 6 ปุ่ม + ปุ่มสร้างออเดอร์ = 7 ปุ่ม = 7×37 + 6×4 = **283px** → **เหลือ 5px ยังบรรทัดเดียว** ✅
- worst case (ร้านคิวงาน + ช่องทางที่ส่งสติกเกอร์ได้ = 9 ปุ่ม) = 9×37 + 8×4 = **365px** → wrap ปุ่มสร้างออเดอร์ (`ms-auto`) ลงบรรทัดสอง — **เป็นพฤติกรรมเดิมที่ออกแบบไว้แล้ว** (คอมเมนต์ `ChatThread.tsx:3601-3608`, แถวจริงที่ `3609`) ไม่ใช่ regression ใหม่ แค่ threshold ขยับ

**ชื่อไฟล์ยาวในกริด:** ต้องครบชุด `min-w-0` (กล่อง) + `max-w-full` + `truncate` (ลูก) + `overflow-x-hidden` (กล่อง scroll) — ไม่ครบชุดแล้วชื่อไฟล์จะดันกล่องกว้างเกินจอ ไม่ใช่ถูกตัด (เกิดบน prod มาแล้ว 2026-08-12)

## 9. Impeccable compliance

**Mode: Operate** — เครื่องมือทำงานของผู้ขาย เกณฑ์ = scanability/consistency ไม่ใช่ความโดดเด่นทางภาพ

- **One Voice:** accent เดียวในชีตคือปุ่ม "ส่ง N รายการ" (`bg-primary`) ที่เหลือเป็นกลาง/semantic ล้วน
- **Verified-Means-Green:** ไม่ใช้เขียวเลย — ยังไม่มีอะไรถูกยืนยัน (รูปยังไม่ถูกส่ง)
- **Ink-tinted overlay:** `bg-dark/60` ไม่ใช่ `bg-black/50` ดิบ (ตรงกับ `PhotoAlbum`/`CustomerFileTile` ในโฟลเดอร์เดียวกัน)
- **Tap target:** ปุ่มปิด 44×44 ✅ · ปุ่มส่งเต็มความกว้าง `min-h-11` ✅ · **ปุ่ม × มุมรูป 36px — ต่ำกว่าเกณฑ์ 44px** ยอมรับตาม precedent ทั้งแอป (secondary + ย้อนกลับได้ + cell ใหญ่ ~100px) **ระบุตรง ๆ ไม่ปิดบัง**
- **Anti-slop:** ไม่มี gradient/eyebrow/hero-metric/การ์ดซ้อนการ์ด · ชีตเลื่อนขึ้นด้วย transition มาตรฐานท่าเดียวกับชีตอื่นในแอป ไม่ใช่ของประดับใหม่
- **คำ:** ทุก error message reuse ของเดิมที่ผ่าน clarify มาแล้ว · `aria-label` ปุ่มปิด = "ปิด กลับไปพิมพ์ข้อความ" (บอกทางออก ไม่ใช่ "ปิด" เปล่า ๆ)
