## 2. ปัญหาที่เห็นได้จากภาพหน้าจอที่ user ส่งมา

ข้อมูลจริง: เสาร์ 15 ส.ค. 2569 · 9 นัด (ทั้งวัน 1 · 09:00–10:00 ห้าใบ · 10:00–11:00 สามใบ) · เปิดจอ 17:43

1. **เวลาถูกพิมพ์ซ้ำ 5 รอบ** — `09:00 / –10:00` โผล่ติดกัน 5 ใบ ทั้งที่เป็นค่าเดียวกัน ส่วนตัวที่ต่างกันจริง
   (ชื่อคน) ตัวเล็กกว่าและอยู่คอลัมน์ที่ถูกบีบ
2. **เลขออเดอร์กินบรรทัดที่ 2 ของทุกใบ** — `#DP25690815BD0309` ยาว 18 ตัว ไม่ใช่สิ่งที่คนยืนหน้าร้าน
   ใช้เลือกลูกค้า แต่ได้พื้นที่เท่าชื่อ
3. **ป้าย "นัดแล้ว" 9 ใบเหมือนกันหมด** — ป้ายที่ทุกแถวเหมือนกันไม่ได้แยกอะไร แต่กินขวามือ ~92px
   ทุกแถว (คอมเมนต์ในโค้ดยอมรับเองว่าที่ 320px คอลัมน์ชื่อเหลือ ~40px จึงต้องใส่ `flex-wrap`)
4. **ไม่มีอะไรบอกว่าตอนนี้ถึงไหนของวัน** — เปิด 17:43 นัดทั้ง 9 ใบผ่านเวลาไปหมดแล้ว แต่จอหน้าตา
   เหมือนตอน 8 โมงเช้าเป๊ะ
5. **ทำอะไรจากจอนี้ไม่ได้เลย** — ปิดผลต้องเข้าออเดอร์ทีละใบ วันละ 9 รอบเข้า-ออก
   ทั้งที่ปุ่มมีอยู่แล้วใน `AppointmentCard.tsx` และ endpoint `POST /api/orders/[token]/appointment/outcome`
   มีมาตั้งแต่ 00024
6. **"ทั้งวัน" ปนกับนัดมีเวลา** ในลิสต์เดียวโดยไม่มีเส้นแบ่ง
7. **ไม่บอกว่าเป็นบริการอะไร** — ต้องแตะ API (§6)

## 4. สามแบบที่เสนอ

### แบบ A — จัดกลุ่มตามช่วงเวลา (เปลี่ยนน้อยสุด)

```
เสาร์ 15 ส.ค. 2569                        9 นัด
─────────────────────────────────────────────
 ☀ ทั้งวัน                               1 คิว
 ┌───────────────────────────────────────────┐
 │ Thanawit Atikitchinnawut               ›  │
 │ [นัดแล้ว]  #DP25690815BD0309              │
 └───────────────────────────────────────────┘
 09:00 – 10:00                            5 คิว
 ┌───────────────────────────────────────────┐
 │ เกียรติศักดิ์ นอขุนทด                    ›  │
 │ [นัดแล้ว]  #DP256908786F6C3F              │
 └───────────────────────────────────────────┘
 … อีก 4 ใบ
 10:00 – 11:00                            3 คิว
```

- เวลาพูดครั้งเดียวต่อกลุ่ม · ชื่อขึ้นเป็น 15px semibold ได้เต็มบรรทัด · ป้าย+เลขออเดอร์ลงไปแถวรอง
- **ผลที่วัดได้:** เห็นครบ 9 ใบในจอเดียว (ของเดิมเห็น 6 ใบก่อนต้องเลื่อน)
- **เสีย:** ยังทำอะไรไม่ได้ · ยังไม่รู้ว่าถึงไหน · เลื่อนไปกลางลิสต์แล้วหัวกลุ่มหลุดจอ = ไม่รู้ว่าดูช่วงไหนอยู่
  (แก้ด้วย sticky หัวกลุ่ม — เพิ่มความซับซ้อนและต้องระวังชนกับ `SellerMobileHeader`)

### แบบ B — รางเวลา + โหนดสถานะ

ยกทรงจาก `theme/paces/.../apps/crm/activities/page.tsx` ตรง ๆ (คอลัมน์เวลา + เส้นประ + วงกลมไอคอน)

- **ได้:** ลำดับเวลาอ่านออกทันที · โหนดบอกสถานะด้วย *รูปร่าง* ไม่ใช่แค่สี
- **เสีย (ตัวตัดสิน):** กิน **78px ถาวรทุกแถว** (เวลา 52 + โหนด 26) — ที่ 320px เหลือชื่อ ~150px
  ≈ 10 ตัวอักษรไทย ทั้งที่ปัญหาข้อ 1 คือชื่อถูกบีบอยู่แล้ว · และ **เวลายังซ้ำทุกแถวเหมือนเดิม แค่ย้ายที่**
- ⇒ ทรงนี้เหมาะกับจอที่กว้างกว่านี้ ซึ่งเป็นจอที่หน้านี้ไม่มี (≥1024 = FullCalendar)

### แบบ C — A + ลงมือได้จากลิสต์ ← **ผมเสนออันนี้**

เพิ่มจาก A:

| ส่วนที่เพิ่ม | ทำไม |
|---|---|
| หัววันบอก `9 นัด · ปิดผลแล้ว 3` + แถบความคืบหน้า | ตอบคำถามเดียวที่ผู้ขายถามตอนบ่าย: "เหลืออีกกี่ใบ" · derive จาก items ที่มีอยู่แล้ว (COMPLETED + NO_SHOW) ไม่ต้องขอ API |
| เส้น **ตอนนี้ HH:mm** | เฉพาะตอนดูวันนี้ · หายไปเมื่อจิ้มวันอื่น (ไม่งั้นอ่านเป็น "ตอนนี้ของวันนั้น" ซึ่งไม่มีความหมาย) |
| ปุ่ม **ให้บริการแล้ว** ในการ์ด | โผล่เฉพาะใบที่ `now ≥ start` และยังไม่ terminal · ยิง endpoint เดิม · confirm ด้วย `pacesConfirm` ที่ระบุชื่อ+เวลา เหมือนหน้าออเดอร์เป๊ะ |
| `⋯` = ไม่มาตามนัด / เลื่อนนัด / เปิดออเดอร์ | destructive ต้องอยู่ในเมนู |
| กลุ่มที่ปิดผลครบ **ยุบเหลือบรรทัดเดียว** | 5 การ์ดที่ไม่มีอะไรให้ทำ → 1 บรรทัด กดกางได้ · **ยุบเฉพาะตอนทั้งกลุ่ม terminal** เหลือค้างใบเดียวก็กางทั้งกลุ่ม |

**เสีย:** การ์ดสูงขึ้น ~44px เฉพาะใบที่ถึงเวลา · มีปุ่มที่ย้อนไม่ได้อยู่ในลิสต์ · ต้องจัดการ loading/error รายใบ

## 5. สถานะที่การ์ดต้องรองรับ (ครบทุกค่าใน `APPOINTMENT_STAGE_META`)

| สถานะ | ป้าย | การ์ดทำอะไร |
|---|---|---|
| `SCHEDULED` ยังไม่ถึงเวลา | นัดแล้ว (warning) | ไม่มีปุ่ม |
| `SCHEDULED` / `CONFIRMED_BY_BUYER` ถึงเวลาแล้ว | ตาม SSOT | ปุ่ม "ให้บริการแล้ว" + `⋯` |
| `RESCHEDULE_REQUESTED` | ลูกค้าขอเลื่อน (info) | แถบซ้าย `border-info border-s-3` (ท่าเดียวกับ `AppointmentCard.tsx`) + ปุ่ม "เลือกเวลาใหม่" |
| `COMPLETED` | ให้บริการแล้ว (success) | ไม่มีปุ่ม · ชื่อเบาลงเป็น `font-medium text-default-700` |
| `NO_SHOW` | ไม่มาตามนัด (danger) | เหมือนบน |

🛑 **ห้ามใช้ `opacity` กับการ์ดที่ปิดผลแล้วทั้งใบ** — ป้ายสถานะจะตกคอนทราสต์ ให้ลดน้ำหนักที่ชื่ออย่างเดียว

สถานะ **ว่างทั้งวัน / skeleton / โหลดล้ม** = ยกของเดิมมาทั้งหมด ไม่ออกแบบใหม่
(มีเหตุผลเขียนกำกับครบใน `AppointmentMonthBoard.tsx` แล้ว — โดยเฉพาะข้อที่ว่า "โหลดล้ม" ห้ามพูดว่า "ว่าง")

## 7. ต้องให้ user ตัดสิน 3 ข้อ

1. ~~**เลือกแบบไหน** — A / B / C~~ → **ปิดแล้ว 2026-08-11: user เอาการจัดกลุ่ม (A/C) · B ตกไป**
   ยังค้างเฉพาะ "เอาปุ่มปิดผลในการ์ดด้วยไหม" (ส่วนที่ C มีเกิน A) — ดู §9.5
2. **ป้าย "นัดแล้ว" ที่ซ้ำ 9 ใบ — ตัดทิ้งไหม**
   ตัดแล้วจอเงียบลงมาก แต่ "นัดแล้ว" จะถูกสื่อด้วย *ความว่างเปล่า* ซึ่งอ่านไม่ออกว่าเป็นสถานะหนึ่ง
   หรือระบบยังไม่รู้ — และถ้าทำที่การ์ดจะเกิด **นิยามที่สองของสีสถานะ** ชนกับ `APPOINTMENT_STAGE_META`
   ที่ประกาศตัวเองเป็น SSOT (**HR16**) · ถ้าเอาจริง ผมจะทำที่ตัว SSOT ไม่ใช่ที่การ์ด
3. **`AppointmentDayRows` ใช้ 3 จอ — เปลี่ยนหมดหรือแยกโหมด**
   ชีตของ `/orders/new` **ห้ามมีปุ่มปิดผล** (ผู้ใช้กำลังกรอกร่างค้างอยู่ กดออกไปแล้วสิ่งที่พิมพ์หาย —
   เหตุผลนี้เขียนไว้ในไฟล์แล้วที่ prop `onRowClick`) ⇒ อย่างน้อยต้องมี prop คุมว่าจอไหนได้ปุ่ม

### 9.3 งานฝั่งข้อมูล — **แยกเป็น 2 คำขอ ไม่ยัดลงคำขอเดิม**

ตอนนี้ `AppointmentMonthBoard` ยิง `GET /api/shops/current/appointments?from=&to=` **ครั้งเดียวครอบทั้งเดือน**
แล้วกรองวันในเครื่อง ⇒ ถ้าเติมเบอร์ลงคำขอเดิม จะได้ **เบอร์ลูกค้าทั้งเดือน (100–200 เบอร์) นอนใน flight payload เพื่อแสดงวันเดียว**

| คำขอ | คืนอะไร | ทำไม |
|---|---|---|
| **เดือน** (ของเดิม ไม่แตะ) | นับนัดต่อวัน — ไม่มีเบอร์ ไม่มีรูป | ปฏิทินต้องการแค่ตัวเลข |
| **รายวัน** (ใหม่) | เฉพาะวันที่จิ้ม: `buyerContact` · `avatarUrl` · ช่องทาง + ชื่อเพจ · `conversationId` | เบอร์อยู่ใน payload ครั้งละ 1 วัน · รูป/ช่องทางเป็น join ที่แพงเกินจะดึงทั้งเดือน |

- **เส้นทางของรูป:** `Order.customerId` → `Customer.externalContacts[]` → `avatarUrl` scope ด้วย `Order.shopChannelId`
  (PSID เป็น page-scoped ห้าม dedup ข้ามเพจ ตาม `@@unique([shopChannelId, externalUserId])`) — **ยังไม่มี helper ตัวไหนทำเส้นทางนี้**
- **ปุ่ม "ทักแชท"** ต้องได้ `conversationId` มาด้วย ไม่งั้นกดแล้วไปไม่ถูกห้อง — ไม่ทำรอบนี้ก็ตัดปุ่มออก
  อย่าปล่อยให้ลิงก์ไปหน้ารวม

### 9.4 🛑 TFR-010 ต้องแก้ไปพร้อมกัน — ไม่ใช่แอบเติม field

`TFR-010` (`docs/20 - Features/00024 …/SRS.md:201`) มี 3 บรรทัด:

user สั่งให้เบอร์เด่น ⇒ ข้อ 3 เป็นเท็จทันทีที่ merge **ต้องแก้ SRS + `API.md` §4.5 + คอมเมนต์ใน

ยังคงไว้: **ไม่ส่งอีเมล** (ไม่มีจอไหนขอ) · ตัดที่ server ตามข้อ 2

### 10.2 การเดินวัน — **3 ทางเข้า ต้องเรียกฟังก์ชันเดียวกัน**

ปัด · กด `‹ ›` · จิ้มวันบนแถบสัปดาห์ — ห้ามต่างคนต่างเขียน

- ปัด**ซ้าย** = วันถัดไป (เนื้อหาเลื่อนตามนิ้ว) · ปัด**ขวา** = วันก่อนหน้า
- **ปัดในเดือนเดียวกัน = ไม่ยิง API** (ข้อมูลทั้งเดือนอยู่ในเครื่องแล้ว) · ข้ามขอบเดือน = ยิงใหม่
  **และปฏิทินข้างหลังต้องเปลี่ยนเดือนตามด้วย** ไม่งั้นปิดชีตแล้วเจอเดือนเก่า
- ระหว่างโหลดเดือนใหม่ → skeleton **ห้ามขึ้น "ว่างทั้งวัน"** (กฎที่ `AppointmentMonthBoard` เขียนไว้เองแล้ว)
- **ห้ามให้ลูกศรกระโดดข้ามวันว่าง** — ลูกศรที่เดินไม่เท่ากันทุกครั้ง ผู้ใช้จะเลิกเชื่อว่ามันคือ "วันถัดไป"
- ไม่มีขอบเขต → `‹ ›` ไม่มีสถานะ disabled
- หัวชีต `aria-live="polite"` — ปัดแล้วเนื้อหาเปลี่ยนยกแผง ผู้ใช้ screen reader ต้องได้ยินว่าวันไหน/กี่นัด

### 10.3 🛑 4 อย่างที่ต้องแก้ให้ได้ ไม่งั้นแย่กว่าของเดิม

1. **iOS/WebView ยึด "ปัดขวาจากขอบซ้าย" เป็นปุ่มย้อนกลับ** — คนที่เริ่มนิ้วตรงขอบจะ *ออกจากหน้า*
   แทนที่จะได้วันก่อนหน้า ⇒ **ลูกศรไม่ใช่ของแถม** และเป็นทางเดียวที่ผู้ใช้คีย์บอร์ด/AT มี
   (ยังไม่ได้เช็คว่าแอป `deep-mobile-seller` เปิด swipe-back ไว้ไหม — **ต้องถามฝั่งแอป**)
2. **ปุ่ม back ของเครื่องต้องปิดชีต ไม่ใช่ออกจากหน้า** — `history.pushState` ตอนเปิด + ฟัง `popstate`
   ถ้าไม่ทำ ผู้ขายที่ใช้ผ่านแอปกด back หวังปิดชีต แล้วหลุดออกจากหน้าคิวงานทั้งหน้า
   **ข้อนี้ลืมบ่อยที่สุดและไม่มี gate ไหนจับได้**
3. **ชีตประกอบเองด้วย React state ⇒ ต้องเรียก `useLockBodyScroll`** + ทุก `overflow-y-auto` ข้างในต้องมี
   `overscroll-contain` (`overlay-scroll-lock.md` — พลาดมาแล้ว 11 ใบในรอบเก็บตก 2026-08-07)
4. **แกนชนกันเอง** — ในชีตต้องเลื่อนขึ้นลงอ่าน และปัดซ้ายขวาเปลี่ยนวัน ⇒ axis lock + `touch-action: pan-y`
   + **ดัก `touchcancel` คู่กับ `touchend` เสมอ** (เบราว์เซอร์ยิง cancel เมื่อมันยึด gesture ไปทำ scroll เอง)
   — ยกทั้งชุดจาก `SwipeableRow.tsx` ซึ่งแก้ปัญหาชุดนี้มาแล้ว

**Impeccable compliance**

- *One Voice* — น้ำเงินบนจอนี้ถูกใช้ 2 ที่เท่านั้น: ช่องวันที่เลือกในปฏิทิน และปุ่ม "งานใหม่" ท้ายจอ
  การ์ดไม่ใช้ `bg-primary`/`text-primary` เลย ยกเว้นเส้น "ตอนนี้" (1px + จุด 8px — ต่ำกว่า 10% ชัดเจน)
- *Verified-Means-Green* — เขียวโผล่ที่ `COMPLETED` เท่านั้น (ข้อเท็จจริงที่ผู้ขายยืนยันเองแล้ว)
  `CONFIRMED_BY_BUYER` ยังเป็น primary ตามที่ `appointment-stage.ts` ตัดสินไว้ · แถบความคืบหน้า
  ใช้เขียวเพราะนับเฉพาะใบที่ปิดผลแล้วจริง
- *tap target ≥44px* — ปุ่มในการ์ดและ `⋯` ใช้ `min-h-11` ทั้งคู่ (`.btn` ของธีม = 36px ต่ำกว่าเกณฑ์)
- *WCAG 1.4.1* — ไม่มีความหมายไหนถูกเข้ารหัสด้วยสีล้วน: ป้ายมีคำเสมอ · แถบความคืบหน้ามีตัวเลข `3 / 9` กำกับ
- *Ink Plum* — ตัวหนังสือใช้ `text-default-900/800/700/500` ไม่มี `#000`
