## แต่ละการ์ดนับอะไร

แหล่งข้อมูล: แถว `MetaCapiEvent` ของเพจนี้ (`shopId` + `dataset.shopChannelId`) · `status` = PENDING / SENT / FAILED / SKIPPED · ช่วง = N วันล่าสุด (7 หรือ 30) · delta = เทียบกับช่วงยาวเท่ากันที่อยู่ติดกันก่อนหน้า

| การ์ด | ตัวเลขใหญ่ | บรรทัดรอง | sparkline |
|---|---|---|---|
| **รอส่ง** | `status = PENDING` **ตอนนี้** (ไม่ผูกช่วง) | ล้มเหลว = `status = FAILED` และ `createdAt` อยู่ในช่วง (แถวล้มเหลวไม่มี `sentAt`) · ส่งล่าสุด = `max(sentAt)` ของ SENT · มีรอส่งเมื่อไรขึ้น "เก่าสุดรอมา …" จาก `min(createdAt)` ของ PENDING | **ไม่มี** |
| **ส่งสำเร็จ** | `status = SENT` และ `sentAt` อยู่ในช่วง (ทุก eventKey) | delta % | นับรายวันตาม `sentAt` |
| **ยอดขายที่ส่งให้ Meta** | ผลรวม `payload.value` ของ `eventKey = PURCHASE`, `status = SENT`, `sentAt` อยู่ในช่วง | จำนวนออเดอร์ = นับ `payload.orderId` ไม่ซ้ำ · delta % · "นับจากตอนส่ง Purchase" | ผลรวม ฿ รายวันตาม `sentAt` |
| **ลีด (สนใจจริง)** | นับ `eventKey = QUALIFIED_LEAD`, `status = SENT`, `sentAt` อยู่ในช่วง | delta % | นับรายวันตาม `sentAt` |

ทำไมรอส่งไม่มี sparkline: PENDING เป็นสถานะ ณ ตอนนี้ แถวจะเปลี่ยนเป็น SENT/FAILED ภายหลัง จึงย้อนดูไม่ได้ว่าเมื่อวานค้างอยู่กี่ตัว ถ้านับรายวันตาม `createdAt` จะได้ปริมาณที่เข้าคิว ไม่ใช่จำนวนที่ค้าง แล้วกราฟจะดูเหมือนบอกว่ามีงานค้าง ซึ่งไม่จริง เลยแทนด้วยสิ่งที่ใช้ตัดสินใจได้จริง คือ "เก่าสุดรอมา X ชม." (เกิน 7 วันแล้ว Meta ไม่รับ แถวกลายเป็น SKIPPED) กับลิงก์ "ดูที่ล้มเหลว" ไปหน้าบันทึกที่กรองไว้แล้ว

### ต้องตัดสินก่อนลงโค้ด (HR16 · ยืนยันกับโค้ดแล้ว)

1. **ยอดอาจนับซ้ำเมื่อเพจมีหลายชุดข้อมูล** — `@@unique([datasetRowId, dedupeKey])` แปลว่าออเดอร์เดียวมีแถว Purchase 1 แถวต่อชุดข้อมูล ถ้าเพจมี 2 ชุด ยอดจะออกมา 2 เท่า ⇒ ยอดขาย/จำนวนออเดอร์ต้องนับ `payload.orderId` ไม่ซ้ำข้ามชุดข้อมูล (หรือนับตามชุดที่เลือกในแท็บ) · ส่งสำเร็จ/ลีดก็มีปัญหาเดียวกัน ต้องเลือกว่าจะนับตามแถว (= จำนวนครั้งที่ส่ง) หรือตามเหตุการณ์จริง · ม็อกอัพเขียนหน่วยว่า "เหตุการณ์"
2. **ช่วงนับไม่ตรงกับตัวเดิม** — `src/lib/meta-capi/stats.ts` (`getCapiWeekStats`) ตอนนี้นับทุกสถานะตาม `createdAt` 7 วัน แต่ข้อเสนอนี้นับ SENT ตาม `sentAt` และนับรอส่งตอนนี้ ตัวเลขจะต่างจากเดิมเล็กน้อย และต้องเพิ่ม index `(shopId, status, sentAt)` หรือรับว่า query ใช้ `@@index([shopId, createdAt])` ไม่ได้
3. **"ยอดขาย" ไม่ใช่ยอดขายของร้าน** — `payload.value` คือยอดที่ส่งให้ Meta ตามโหมดที่ตั้ง (ยอดสุทธิ หรือไม่รวม VAT · ส่งตอนสร้าง/ยืนยัน/ชำระครบ) ไม่ใช่นิยามยอดขายของ `getSalesSeries` จึงตั้งชื่อการ์ดว่า "ยอดขายที่ส่งให้ Meta" และมีบรรทัด "นับจากตอนส่ง Purchase" ห้ามย่อเหลือ "ยอดขาย"
4. delta: ช่วงก่อนเป็น 0 แต่ช่วงนี้มี ⇒ ป้าย "ใหม่" (ไม่หารด้วย 0) · เป็น 0 ทั้งคู่ ⇒ ไม่แสดง delta แสดง "ยังไม่มีข้อมูลช่วงนี้" + เส้นประแบน

## การ์ด "เหตุการณ์ที่ส่ง" (แท็บ 4)

- แทนสวิตช์ 12 แถว: แสดงเฉพาะเหตุการณ์ที่ชุดข้อมูลในแท็บส่งอยู่ (ตัวอย่าง 3 ตัว: ซื้อ · สนใจจริง · จัดส่งแล้ว) · ตัวเลขบนแท็บ = จำนวนที่เปิด
- แถว: ชื่อไทย + ชื่อ Meta · คำอธิบาย · ปุ่มตัวเลือกเดิม ("ตั้งยอด" / "แก้กฎ") · ปุ่ม x "เอาออก" (aria-label มีชื่อเหตุการณ์ · มือถือ 44px)
- เอาออก = ลบ key ออกจาก `MetaCapiDataset.events` (String[]) · ค่าตั้งยอด/กฎแท็กเก็บแยกอยู่แล้วจึงยังอยู่ · ไม่ถาม Swal ใช้ pacesToast + "เลิกทำ" แทน
- "+ เพิ่มเหตุการณ์" เปิด modal: ช่องค้นหา (ชื่อไทย/ชื่อ Meta) · เฉพาะที่ยังไม่ได้เพิ่ม จัด 3 กลุ่ม กลุ่มที่เพิ่มครบแล้วไม่แสดง · checkbox หลายตัว ทั้งแถวแตะได้ · ท้าย "ยกเลิก" / "เพิ่ม {n} เหตุการณ์" (n=0 ปุ่มกดไม่ได้ ข้อความ "เลือกเหตุการณ์ก่อน")
- ว่าง: ไอคอน + แนะนำให้เริ่มจาก Purchase + ปุ่มทึบ "เพิ่มเหตุการณ์" ปุ่มเดียว
- Desktop/Tablet ปุ่มเพิ่มอยู่หัวการ์ดถัดจากแท็บ · Mobile ปุ่มเต็มกว้างใต้รายการ · modal มือถือเต็มจอ
- ไม่ต้องแก้ data model: `MetaCapiDataset.events` เป็นรายการ key ที่เปิดต่อชุดข้อมูลอยู่แล้ว · เพิ่มจาก modal = ต่อท้ายอาร์เรย์ · เปลี่ยนแค่ UI
