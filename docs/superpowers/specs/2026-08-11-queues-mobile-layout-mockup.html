ปัญหาที่วัดได้ (ไม่ใช่ความรู้สึก)

  • ปุ่มหลักถูก FAB ทับเสมอ ไม่ว่าจะเลื่อนสุดแค่ไหน — FAB เขียน absolute top-[-30px] (SellerBottomNav.tsx:305) คือยื่นขึ้นเหนือแถบ nav 30px แต่ระยะเว้นท้ายหน้าเผื่อไว้ 5.5rem = nav 72px + หายใจ 16px (safepay-overrides.css:146) ⇒ เหลือ แถบ 14px ที่เนื้อหาจะอยู่ใต้ FAB ถาวร (แถบลายทางแดงในภาพ) และปุ่มเต็มความกว้างที่วางไว้ท้ายสุดจะจบพอดีในแถบนั้น
  • ปุ่มอยู่นอกจอตั้งแต่เปิดหน้า — ปฏิทิน 392px + หัวข้อวัน + นัด 3 ใบ ดันปุ่มไปที่ y≈732 ต้องเลื่อนก่อนถึงจะเจอ
  • ซ้ำกับ FAB เชิงความหมาย — ทั้งคู่ไป /orders/new ต่างกันแค่ปุ่มบนบอร์ดพก ?appointmentDate= ไปด้วย ตอนนี้จึงชนกันทั้งความหมายและพิกัด

ผลรวมของสองการเปลี่ยน

  • เดือน 5 แถว (ราว 5 ใน 12 เดือน) ปฏิทินเหลือ 344px จาก 392px
  • ในเดือนแบบนี้ ปุ่มและนัดใบแรกอยู่ในจอตั้งแต่เปิดหน้า โดยไม่ต้องแตะนิ้วเลย
  • ผลข้างเคียงที่ต้องยอมรับ: การ์ดจะสูงไม่เท่ากันระหว่างเดือน (ต่างกัน 48px) เวลากด ‹ › เปลี่ยนเดือนจะเห็นความสูงขยับ — เป็นพฤติกรรมเดียวกับปฏิทินของ Google/Apple บนมือถือ
  • ถ้าไม่อยากให้ความสูงขยับ ตัดข้อนี้ออกได้ เหลือแค่ย้ายปุ่ม ซึ่งยังแก้เรื่อง FAB ทับได้ครบ
C · Mobile 320px (iPhone SE) จุดที่แคบที่สุดที่ต้องรอด

ทำไมปุ่มไม่ไปอยู่ในแถวเดียวกับหัวข้อวันที่

  • ที่ 320px แถว “ศ. 14 ส.ค. 2569 + 3 นัด” กินเกือบเต็มความกว้างอยู่แล้ว ถ้ายัดปุ่มเข้าไปด้วยจะต้องย่อเป็นไอคอนหรือตัดคำ ซึ่งทำให้ผู้ใช้ไม่รู้ว่ามันพก “วันที่” ไปให้
  • ปุ่มเต็มความกว้างเป็นบล็อกของตัวเอง = ไม่ต้องแก้ markup ของปุ่มเลยแม้แต่คลาสเดียว ย้ายตำแหน่งอย่างเดียว (diff เล็กที่สุดเท่าที่จะเป็นไปได้)
  • ทุกปุ่มยังสูง 44px ครบตามเกณฑ์การแตะ
D · Tablet & Desktop ไม่เปลี่ยน — และนี่คือคำตอบ ไม่ใช่การละเว้น

ทำไมไม่มีภาพแท็บเล็ต/เดสก์ท็อปให้ดู

หน้า /queues สลับ component ตามความกว้างจริง ๆ ไม่ใช่แค่สลับคลาส: QueuesCalendarSwitch.tsx ส่งมือถือไป AppointmentMonthBoard ส่วนแท็บเล็ต/เดสก์ท็อปไป AppointmentCalendar ซึ่งเป็นตารางเดือนแบบเต็มที่มีชื่อผู้จองอยู่ในช่องวันเลย

การเปลี่ยนทั้งสองข้อในรอบนี้ (fixedWeekCount และตำแหน่งปุ่ม) อยู่ในไฟล์ของมือถือล้วน จึงไม่มีทางกระทบจอใหญ่ — และปัญหาที่แก้ (FAB ทับ / ปุ่มนอกจอ) ก็ไม่มีอยู่บนจอใหญ่ตั้งแต่แรก เพราะที่นั่นไม่มี bottom nav และไม่มี FAB

ถ้าอยากให้จอใหญ่เปลี่ยนตามด้วย ต้องเป็นงานแยกที่เริ่มจากการดู AppointmentCalendar ก่อน — บอกได้ครับ จะทำม็อกอัพให้อีกใบ

สิ่งที่จงใจไม่แตะในรอบนี้

  • legend 2 บรรทัด — เก็บไว้ เพราะคนตาบอดสีต้องแยกสถานะด้วยรูปร่าง ไม่ใช่สีอย่างเดียว (ประหยัดได้แค่ 26px ไม่คุ้มกับที่เสีย)
  • ป้าย “นัดแล้ว” ที่ซ้ำทุกใบ — มันซ้ำเพราะวันนั้นสถานะเหมือนกันจริง ๆ วันที่มีใบ “ขอเลื่อนนัด” ปนเข้ามาป้ายจะทำงานทันที
  • แถบ 14px ที่ FAB ทับ — รอบนี้แก้ด้วยการย้ายปุ่มออกจากแถบ แต่ ต้นเหตุยังอยู่ (padding-bottom ไม่ได้นับส่วนที่ FAB ยื่นขึ้นมา) และกระทบ ทุกหน้า seller บนมือถือที่วางปุ่มเต็มความกว้างไว้ท้ายสุด — ควรเป็นงานแยกที่ต้อง QA กว้างกว่านี้

สิ่งที่จะแก้จริงถ้าอนุมัติ — 2 จุด ในไฟล์เดียว

  • AppointmentMonthBoard.tsx · prop ของ <FullCalendar> → เพิ่ม fixedWeekCount={false}
  • AppointmentMonthBoard.tsx · ย้ายบล็อก JSX ของปุ่ม จากท้ายสุดของส่วนล่าง ขึ้นมาไว้ระหว่าง “หัวข้อวันที่” กับ “รายการนัด” — ไม่แก้ class / aria-label / onClick ของปุ่มเลย
  • ไม่มี migration · ไม่แตะ API · ไม่แตะสถานะ (ว่าง/โหลด/error/เต็ม) · ไม่แตะ token สีใด ๆ
