### User stories ที่ครอบ
- ในฐานะเจ้าของร้าน ฉันอยากรู้ว่ายอดจากแอด **ได้เงินจริงเท่าไร** ไม่ใช่แค่ยอดสั่ง (FR-011, 013)
- ฉันอยากเห็นว่าแคมเปญ/ชุดโฆษณา/แอดไหนคุ้ม และกดลงถึงออเดอร์ได้ (FR-012)
- ฉันอยากรู้ว่าแอดพาลูกค้าใหม่หรือเก่า ขายสินค้าอะไร ช่วงเวลาไหน (FR-014, 015, 017)
- ฉันอยากได้คำแนะนำสั้น ๆ ว่าแอดไหนควรตรวจ/ควรลงต่อ (FR-018)
- ฉันอยากรู้ว่าตัวเลขเหล่านี้ครอบคลุมออเดอร์ทั้งร้านกี่ % (FR-019)

### Section breakdown (prose)

**หัวหน้า (ใช้ร่วมทุกแท็บ)**
- ช่วงวันที่ + เพจ จาก URL เดียวกับ `/reports/ads` (`from/to/shopChannelId`) · ช่วงสูงสุดตาม `MAX_RANGE_DAYS` มีแถบ `clamped` เดิม
- บรรทัดช่วงวันที่เหลือบรรทัดเดียว (ตามมติ commit 5e9aea2fc) · ไม่มีบรรทัดบัญชี/เวลาอัปเดต
- ปุ่มขวา: `ดูยอดขายตามโฆษณา` (→ `/reports/ads` พกช่วง/เพจ) · `ส่งออก CSV` เฉพาะแท็บแคมเปญ
- เปลี่ยนช่วง/เพจ = **คงแท็บ ทิ้งพารามิเตอร์ drill** (`campaign`, `adset`) เหมือนที่ ad-quality ทิ้ง `?ad`

**แท็บ (ผูก URL `?tab=`)**
- ค่า: `summary` (default · ไม่ใส่ใน URL), `campaigns`, `quality`, `products`, `customers`, `time`, `coverage` · ค่าผิด → `summary`
- `page.tsx` อ่าน `tab` แล้วเรียก service ของแท็บนั้นเท่านั้น · สลับแท็บ = `router.push(..., { scroll:false })` ใน `useTransition` เหมือน `FinanceTabs` (ปุ่มย้อนกลับพากลับแท็บเดิม)
- สลับแท็บทิ้ง `campaign/adset/q/sort`
- ≥md: `nav-tabs` `flex-nowrap` **ห้าม `overflow-x-auto`** (มติเดิมของ FinanceTabs) · `role=tablist/tab`, roving tabindex ←/→/Home/End · active = `border-b-2 border-primary text-primary`
- <md: native `<select class="form-select">` bind `?tab=` (label "มุมมอง") — เป็น form-select ตามกฎ 6 ไม่ใช่ hs-dropdown (OS picker, ไม่ re-render พัง)

**แท็บ 1 สรุป**
- การ์ดหลัก: "รับเงินแล้ว" เป็นตัวเลขเด่นเดียวของหน้า (`text-xl font-bold tabular-nums`) + `DeltaText` + `{x}% ของยอดขายจากแอด` (`text-lg font-semibold`)
- แท่งแบ่ง 2 ส่วน `h-3` (`role="img"` + aria-label): รับเงินแล้ว = `bg-success`, ยังไม่รับเงิน = `bg-warning` · รับแล้ว + ยังไม่รับ = ยอดขายจากแอด (ตามเทสใน FR-011)
- ตาราง 3 คอลัมน์ (ตัวชี้วัด · ช่วงนี้ · เทียบช่วงก่อน) แบบเดียวกับการ์ด ② ของ `/reports/ads`: ยอดขายจากแอด · {noun} · เฉลี่ยต่อใบ · ยกเลิก/ตีกลับ (n ใบ · %) · กำไรส่วนเกิน · แถวท้าย `คลิกแอดถึงสั่งซื้อ (มัธยฐาน) N วัน`
- เทียบช่วงก่อนฐาน 0 → ช่อง delta `—` ไม่แสดง %
- ยกเลิก/ตีกลับ: **เพิ่มขึ้น = `text-warning-ink` ลดลง = `text-success-ink`** (กลับขั้วจาก DeltaText ปกติ → เพิ่มพร็อพ `tone="inverse"`)
- กำไรส่วนเกิน: ป้าย `ต้นทุนไม่ครบ {n} ใบ` = `badge bg-warning/15 text-warning-ink` (ติดค่า ไม่ต้องมีประโยค) · ติดลบ = `text-danger-ink` + เครื่องหมาย − · บวก = หมึกปกติ (ไม่ใช้เขียว เพราะยังไม่ใช่ตัวเลขยืนยัน)
- ตัวบรรทัดอธิบายเดียว `text-xs` ใต้ตาราง: `กำไรส่วนเกิน = ยอดสุทธิ − ต้นทุน − ค่าส่ง − ค่าโฆษณา ไม่หักค่าใช้จ่ายร้าน` (FR-016 บังคับให้มี 1 บรรทัด)
- ค่าโฆษณา/ROAS ไม่ OK → แถวกำไรส่วนเกินซ่อน (ไม่แสดง "—" ตาม FR-010) + `AdSpendNotice` เดิมบนแท็บ
- การ์ด "ควรดูต่อ" (FR-018): **การ์ดใบเดียว แถวเป็นรายการ `divide-y`** (ไม่ใช่การ์ดซ้อนการ์ด/ไม่ใช่กริดการ์ดเท่ากัน)
  - แถว: `AdThumb size-8` · ชื่อแอด (truncate+title) · หัวข้อกฎ + ตัวเลขที่ใช้ตัดสิน + ช่วงที่เทียบ (บรรทัดเดียว `text-sm`) · "ลองทำ" 1 บรรทัด `text-default-700 text-sm` · ป้ายระดับ
  - ป้าย `ควรตรวจสอบ` = `bg-warning/15 text-warning-ink` (icon `alert-triangle`) · `โอกาส` = `bg-primary/15 text-primary-ink` (icon `trending-up`) — **ห้ามเขียว/แดง**
  - แถวเป็น `<button>` `min-h-11` เปิด `AdOrdersSheet` ของแอดนั้น
  - เรียงควรตรวจสอบก่อนโอกาส · ไม่มีแอดผ่านเกณฑ์ ≥10 ออเดอร์ → **ไม่วาดการ์ด** · ห้ามขึ้นข้อความ "ไม่มีคำแนะนำ"

**แท็บ 2 แคมเปญ**
- ระดับ: แคมเปญ → ชุดโฆษณา → แอด · URL `?tab=campaigns&campaign={id}&adset={id}` (ไม่มี `campaign` = ระดับแคมเปญ)
- crumb บนการ์ด: `ทุกแคมเปญ › {ชื่อ} › {ชื่อ}` · ระดับปัจจุบัน `font-semibold` ระดับบน `text-primary` เป็นลิงก์ `min-h-11` · mobile เหลือปุ่มย้อนบรรทัดเดียว
- จัดกลุ่มด้วยรหัส ชื่อล่าสุดจาก Meta (FR-012)
- คอลัมน์: ชื่อ(+รหัสบรรทัดรอง) · ค่าโฆษณา · ออเดอร์ · ยอดขาย · รับเงินแล้ว · ROAS · กำไรส่วนเกิน — ที่ `xl+` เพิ่ม เฉลี่ย/ใบ · %ยกเลิก · เรียงได้ทุกตัวเลข · เรียงเริ่มต้น ยอดขายมาก→น้อย
- ไม่ทราบแคมเปญ: แถวพิเศษ ท้ายตารางเสมอไม่ว่าเรียงแบบไหน · icon `help-circle` · กดแล้วไปรายการแอดตรง ๆ (ไม่มีชั้นชุดโฆษณา)
- แถวรวม `รวมทุกแคมเปญ ({n}) ` = ผลรวมแคมเปญ + ไม่ทราบ = ยอดจากแอดทั้งหมด (เทสใน FR-012)
- ระดับแอด: กดแถว → `AdOrdersSheet` (ออเดอร์ ≤50 ใบล่าสุดตามเดิม)
- Meta ไม่ OK (ยังไม่เชื่อม/สิทธิ์หมด): ข้ามชั้นแคมเปญ/ชุดโฆษณา แสดงตัวแอดตรง ๆ หัวการ์ด `ทุกแอด` + `AdSpendNotice` — **ห้ามแสดงตารางที่มีแถวเดียว "ไม่ทราบแคมเปญ"** · คอลัมน์ ค่าโฆษณา/ROAS/กำไรซ่อน
- ส่งออก CSV = ระดับที่เห็นบนจอ (สิ่งที่เห็น = สิ่งที่ได้ เหมือน xlsx ของ `/reports/ads`)

**แท็บ 3 คุณภาพออเดอร์**
- Waterfall: ยอดสั่งทั้งหมด → หักยกเลิก → หักตีกลับ/คืน → ยังไม่รับเงิน → รับเงินแล้ว · แต่ละแท่งมาจากชุดใบที่ไม่ซ้อนกัน · ค่าบนแท่งเป็น `formatBahtCompact`
- แท่ง 100% ต่อแอด top 10 (ตามจำนวนออเดอร์) 5 สถานะ: รอดำเนินการ · จัดส่งแล้ว · สำเร็จ · ยกเลิก · ตีกลับ — ค่า `Order.status` จริง
- ตารางรายแอดทั้งหมด (ค้นหา/เรียง/แบ่งหน้า/footerRow) เป็นที่เดียวที่มี **อัตราตัวเลข** (รับเงินจริง · ยกเลิก · ตีกลับ) — กราฟไม่ซ้ำตัวเลขเหล่านี้
- อัตรารับเงินจริง = รับเงินแล้ว ÷ ยอดสั่งรวม (นับยกเลิกด้วย) ตาม FR-013 · ค่าสูง/ต่ำใช้หมึกปกติ ไม่ลงสีเขียว/แดงกับตัวเลข

**แท็บ 4 สินค้า**
- ตาราง: รูป · ชื่อ · ใบ · ชิ้น · ยอด · ราคาเฉลี่ย · %ยกเลิก · ป้าย `ก่อนหักส่วนลดท้ายบิล` (`badge bg-info/15 text-info-ink`) อยู่ที่ card-header — ป้ายเดียวต่อการ์ด ไม่ซ้ำทุกแถว
- รายการพิมพ์เอง (ไม่มี productId) จัดกลุ่มตามชื่อ ไม่มีรูป → ไทล์ `package`
- Heatmap แอด × สินค้า: แถว = แอด คอลัมน์ = สินค้า (top 10 × top 10 ตามยอด) · ชื่อบนแกนตัดที่ ~14 ตัวอักษร tooltip ขึ้นชื่อเต็ม + ฿ + ใบ · ช่องไม่มียอดเป็น `chart-gray` · เพียงสีเดียว `chart-primary` ไล่ 4 ระดับความเข้ม (ไม่ใช้แดง-เขียวไล่)
- Heatmap ไม่มี interaction นอก tooltip · หมายเหตุ 1 บรรทัดใต้กราฟ: `แสดง 10 แอด × 10 สินค้าที่ยอดสูงสุด`
- <768: ซ่อน heatmap แทนด้วยรายการ แอด → สินค้า 3 อันดับ (ชื่อ · ฿)

**แท็บ 5 ลูกค้า**
- การ์ดบน: แท่ง 100% เดียว (ตามยอด) ใหม่ / เดิม / ไม่ทราบ + 3 คอลัมน์ (คน · ฿ · %) · สี ใหม่ = `chart-primary` · เดิม = `chart-delta` · ไม่ทราบ = `default-300`
- ตารางรายแอด: ต้นทุนได้ลูกค้าใหม่ = ค่าโฆษณา ÷ ลูกค้าใหม่ — คอลัมน์ **ซ่อนทั้งคอลัมน์** เมื่อ Meta ไม่ OK · แอดที่ไม่มีค่าโฆษณาในช่วงนั้น = `—`
- บรรทัดนิยาม 1 บรรทัด `text-xs`: `ลูกค้าใหม่ = ออเดอร์แรกของลูกค้าในร้าน · นับเฉพาะออเดอร์ที่บันทึกแอดนั้น`

**แท็บ 6 ช่วงเวลาขาย**
- ตัวสลับ ยอดขาย | จำนวน = tablist เล็ก 2 ตัว (ท่าเดียวกับ DailyOverviewCard) เปลี่ยน series ไม่ remount
- บรรทัดพระเอก `ขายดีสุดวัน{…} {HH}:00–{HH+1}:00 · {฿} ({n} ใบ)` อยู่เหนือ heatmap — เป็นข้อความที่อ่านจบก่อนต้องมองสี
- Heatmap ไม่มี data label ในช่อง (หนาแน่นเกิน) · ช่องว่าง = `chart-gray` · ความเข้มตามค่า 4 ระดับของ `chart-primary` · legend ของ apex `ไม่มี / น้อย / … / มาก` · tooltip `{วัน} {HH}:00 · ฿… · n ใบ`
- ใต้กราฟบรรทัดเดียว: `เวลาไทย · เวลาที่ขายได้ ≠ เวลาที่ควรยิงแอด`

**แท็บ 7 ความครอบคลุม**
- แท่ง 100% 2 แท่ง (ตามจำนวน · ตามยอด) × 3 กลุ่ม: จากแอด (ยืนยันแล้ว) = `chart-primary` · จากแชทแต่ระบุแอดไม่ได้ = `default-400` · ไม่ได้มาจากแชท = `default-200`
- ตาราง 3 แถว + แถวรวม (= ยอดขายทั้งร้านตาม `salesOrderWhere`) — ตัวเลขชิดแท่ง กันต้องเดา
- บรรทัดเดียวใต้ตาราง: `ออเดอร์ที่ระบุแอดไม่ได้ จะไม่ถูกนับให้แอดใด` (FR-019 บังคับ)
- "สถานะข้อมูล Meta": แถวเดียวในการ์ดแยก — ป้ายสถานะ + ชื่อบัญชี + `แอด {n} ตัวไม่มีชื่อแคมเปญ` (กดไปแท็บแคมเปญ → กลุ่มไม่ทราบแคมเปญ)
  - เชื่อมแล้ว = `badge bg-success/15 text-success-ink` · สิทธิ์หมด/โหลดไม่สำเร็จ = `bg-warning/15 text-warning-ink` + ปุ่ม (ไปเชื่อมใหม่ / ลองใหม่) · ยังไม่เชื่อม = `bg-default-100 text-default-800` + ปุ่ม `เชื่อมบัญชีโฆษณา` → `/settings/capis`

### User flow
1. เข้า `/reports/ad-revenue` → แท็บ สรุป เห็น "รับเงินแล้ว" ก่อนเสมอ
2. เปลี่ยนช่วง/เพจ → grid จาง + `กำลังคำนวณใหม่…` → เนื้อหาแท็บปัจจุบันโหลดใหม่ (แท็บอื่นไม่ยิง)
3. กดแถวคำแนะนำ → ชีตออเดอร์ของแอด → ปุ่มย้อนกลับของเครื่องปิดชีต
4. กดแท็บ แคมเปญ → ตารางแคมเปญ → กดแถว → ชุดโฆษณา → กดแถว → แอด → กดแถว → ชีตออเดอร์ · crumb/ปุ่มย้อน กลับทีละชั้น · ปุ่มย้อนของเบราว์เซอร์กลับทีละชั้น (push)
5. ส่งออก CSV (แท็บแคมเปญ) → ไฟล์ของระดับที่เห็น → `pacesToast.success/error`
6. แท็บ ความครอบคลุม → กดชื่อ "แอด N ตัวไม่มีชื่อแคมเปญ" → แท็บแคมเปญที่กลุ่มไม่ทราบ

### Edge states ที่ต้องออกแบบ
- **ไม่ใช่เจ้าของร้าน:** `NoPermissionCard` capability `F1` (เหมือนพี่น้อง)
- **ไม่มีร้าน active:** `SellerEmptyState` `building-store` เดิม
- **ร้านไม่เคยมีข้อมูลโฆษณาเลย:** หน้าว่างเดิม ไม่วาดแท็บ/กรอง
- **ฐานล่ม:** `SellerErrorState` ทั้งหน้า (ห้ามหน้าตาเหมือนว่าง)
- **ช่วงนี้ไม่มีออเดอร์จากแอด:** หัว+กรอง+แท็บอยู่ครบ · เนื้อหาแท็บ = `SellerEmptyState compact` + ปุ่ม `ดู 30 วันล่าสุด` (ทางออก)
- **Loading ครั้งแรก:** `loading.tsx` = หัว + แถบแท็บ + skeleton 2–3 การ์ด (ไม่วาง spinner กลางจอ) · **สลับแท็บ:** Suspense `key=tab|from|to|page|…` + skeleton ของแท็บนั้น · ระหว่างรอ แถบแท็บใหม่ `aria-selected` ตามที่กด (optimistic) และเนื้อหาเดิมจาง `opacity-60`
- **Meta ไม่เชื่อม/สิทธิ์หมด/สกุลเงิน/ล้ม:** `AdSpendNotice` เดิมบนแท็บ สรุป · แคมเปญ · ลูกค้า (ใช้ค่าโฆษณา) · ซ่อนคอลัมน์ ค่าโฆษณา/ROAS/กำไร/ต้นทุนได้ลูกค้าใหม่ (ไม่ใช่ "—") · แท็บ คุณภาพ/สินค้า/ช่วงเวลา **ไม่ต้องมีแบนเนอร์** เพราะไม่ใช้ Meta · โทน warning ไม่ใช่ danger
- **Insights ล้มชั่วคราว:** ปุ่ม `ลองใหม่` = `router.refresh()` (ท่า `CardState`)
- **เทียบช่วงก่อนฐาน 0:** delta `—`
- **ตัวเลข 0 / หลักล้าน:** ฿0 แสดงตามจริงในการ์ดหลัก · ≥฿1,000,000 ในคอลัมน์แคบใช้ `formatBahtCompact` + `title` เต็ม
- **ชื่อแคมเปญ/ชุด/แอด/สินค้ายาว:** `truncate` + `title` (ตาราง) · `line-clamp-2 break-words` (รายการมือถือ) · รหัส `break-all` · `min-w-0` ทุกชั้น
- **ไม่มีรูปแอด/สินค้า:** `AdThumb`/ไทล์ `package`
- **แอดเดียว/แคมเปญเดียว:** แท่ง 100% มีแถวเดียวได้ · heatmap 1×N ได้ · ไม่ซ่อนการ์ด
- **`truncated`/`clamped`:** แถบเตือนเดิม
- **drill id ไม่ตรงกับช่วงใหม่/ไม่มีอยู่:** ตกกลับระดับบนสุด ไม่ขึ้น 404

### Impeccable compliance
- **Mode: Operate** — หน้ารายงานเจ้าของร้านใน `(paces)` ที่ผู้ใช้อยู่ในงานตัดสินใจงบโฆษณา · เกณฑ์ = scanability, consistency กับ `/reports/ads` + `/reports/ad-quality`, ความหนาแน่นพอดี, ตัวเลขเปรียบเทียบได้ · register override เป็น `product` ตาม PRODUCT.md
- **พระเอกของหน้า:** "รับเงินแล้ว" ในแท็บสรุป (ตัวเลขเดียว `text-xl font-bold`, ที่อื่นถอยเป็นตารางเล็ก) · ในแต่ละแท็บมีของเด่นเดียว: waterfall (คุณภาพ) · บรรทัด "ขายดีสุด…" (ช่วงเวลา) · การ์ดแท่ง 100% (ความครอบคลุม/ลูกค้า) · ตารางแคมเปญ (แคมเปญ)
- **One Voice:** accent น้ำเงิน `primary` ใช้ที่: แท็บ active (เส้นล่าง+ตัวอักษร) · ลิงก์ crumb · ป้ายโอกาส · ชุดข้อมูล "จากโฆษณา" ในกราฟ (`chart-primary`) · ปุ่มหลักไม่มีบนหน้านี้ (ไม่มี primary action) → <10% ของพื้นที่
- **Verified-Means-Green:** เขียวใช้เฉพาะ "รับเงินแล้ว/สำเร็จ" (ยืนยันแล้ว: ได้รับเงินจริง) และป้าย "เชื่อมแล้ว" ของ Meta · "ยังไม่รับเงิน/รอดำเนินการ" = เหลือง (warning) · ลูกค้าใหม่/จากแอด = น้ำเงิน (ไม่ใช้เขียว เพราะไม่ใช่การยืนยัน) · คำแนะนำ "โอกาส" = น้ำเงิน ไม่ใช่เขียว (ยังเป็นการคาดการณ์) · กำไรส่วนเกินบวกไม่ลงเขียว (ตัวเลขไม่ครบ ยังไม่ยืนยัน)
- **แดง:** ใช้เฉพาะ ตีกลับ (ความล้มเหลวจริง) และกำไรติดลบ · "ยกเลิก" ใช้ beta จางลง (.55) แยกจาก ตีกลับ ไม่ให้ทั้งกราฟแดง
- **Sentence-Case:** ไทยไม่ใช้ uppercase · ป้ายเป็นประโยคสั้น
- **เงาผสมหมึก:** ไม่มีเงาใหม่ — ใช้ `.card` ของธีม
- **Anti-slop:** ไม่มี gradient ตกแต่ง (gradient `.35→0` ของ area ไม่มีในหน้านี้) · ไม่มี hero-metric ซ้ำ 6 ไทล์ — ตัวเลขรองเป็นตาราง ไม่ใช่การ์ดตัวเลข · ไม่มี eyebrow · ไม่มีการ์ดซ้อนการ์ด (คำแนะนำเป็นรายการในการ์ดเดียว) · ไม่มี border-left ตกแต่ง
- **ฟอนต์:** Anuphan (ไม่ระบุอื่น) · ตัวเลข `tabular-nums` (ไม่ใช้ `font-mono`)
- **น้ำเสียง:** "ลองทำ…" บอกทางออก · ไม่กล่าวหา ("ยกเลิกสูง" พูดถึงตัวเลขของแอด ไม่ใช่ลูกค้า) · ไม่ไฮป์ ("โอกาส" ไม่ใช่ "สุดยอด") · ไม่ใช้ "ไม่สามารถ…ได้"
- **ที่ theme ขัดกับ Impeccable:**
  1. heatmap ตัวอย่างของธีมใช้ `chart-alpha`/`chart-beta` (เขียว/ชมพู) ตามความสวยงาม → **Impeccable ชนะ** ใช้สีเดียวไล่ระดับ (ตำแหน่งยอดขาย ≠ ผ่าน/ไม่ผ่าน)
  2. ธีมวาด tablist แบบหลายแท็บให้เลื่อนได้ → ขัดมติ "ห้ามแถบเลื่อนแนวนอนมือถือ" → ใช้ native select <md
  3. ธีมไม่มี waterfall → ใช้ rangeBar (ระบุแล้ว ให้ Controller ยืนยัน)
- **จุดเสี่ยงสำหรับ `/impeccable critique` ที่ Controller ต้องเพ่ง:** (ก) แท็บ 7 ตัว ณ 768–1023px ล้นหรือไม่ (ข) heatmap 24 คอลัมน์ที่ 1024–1279 อ่านชื่อแกนได้ไหม (ค) ตาราง 9 คอลัมน์ในแท็บแคมเปญที่ xl (ง) คอนทราสต์ป้ายเหลือง/ฟ้าในโหมดมืด · ไม่มีค่าดิบ/arbitrary ที่ต้องขอข้อยกเว้น

### Anti-slop self-check
1. **เฉพาะ Deep ไหม:** ใช่ — แกนคือ "รับเงินแล้ว vs ยังไม่รับเงิน" ตาม `isOrderUnpaid`, สถานะออเดอร์ จัดส่ง/ตีกลับ/คืน ของ Deep, "ไม่ทราบแคมเปญ" จากข้อจำกัดที่ฐานเก็บแค่รหัสแอด, ค่าใช้จ่าย COD · ถ้าเอาไปใช้กับสินค้าอื่นต้องเขียนใหม่เกือบหมด
2. **พระเอก 1 อย่าง:** มีต่อแท็บ (ระบุข้างบน) · แท็บสรุปเลือก "รับเงินแล้ว" เป็นตัวเดียว ส่วนยอดขาย/ออเดอร์/เฉลี่ยถอยเป็นแถวตาราง
3. **ข้อมูลซ้ำ/คงที่:** ตัดแล้ว — ไม่ทำการ์ด 6 ใบสำหรับ 6 ตัวเลข (รวมในตารางเดียว) · แท่ง 100% ไม่ซ้ำอัตราตัวเลข (ตารางเป็นเจ้าของ) · ไม่แสดงการ์ดว่าง "ไม่มีคำแนะนำ" · ไม่แสดงตาราง "ไม่ทราบแคมเปญ" แถวเดียวเมื่อ Meta ไม่ OK · ป้าย `ก่อนหักส่วนลด` ติดที่หัวการ์ดครั้งเดียว
4. **ครบ state:** ครบใน Edge states (ว่างทั้งร้าน/ว่างช่วง/ผิดพลาด/โหลดแท็บ/Meta 5 สถานะ/ฐาน 0/ชื่อยาว/ไม่มีรูป/แอดเดียว/0 และหลักล้าน)
5. **copy:** ปุ่มบอกผลลัพธ์ (`ส่งออก CSV` · `ดู 30 วันล่าสุด` · `เชื่อมบัญชีโฆษณา` · `ลองใหม่`) · ไม่แนะนำให้ทำสิ่งที่ปุ่มไม่มี — "ลองทำ" ของคำแนะนำเป็นการกระทำนอกหน้า (ไม่อ้างปุ่มปิดแอด) · ผู้ใช้สั่งตัดข้อความยาว: ทุกบรรทัดอธิบายสั้นเหลือเท่าที่ FR บังคับ (3 บรรทัด: นิยามกำไร / ไม่นับแอดที่ระบุไม่ได้ / เวลาที่ขายได้ ≠ ควรยิงแอด)
6. **คำเดียวกัน = ของเดียวกัน:** "รับเงินแล้ว" = ไม่เข้า `isOrderUnpaid` ทุกแท็บ · "จากแอด" = ยืนยันแล้ว (ไม่มี "อนุมาน") · "ตีกลับ/คืน" ใช้คู่ · `{noun}` ผันตามประเภทร้าน · "กำไรส่วนเกิน" ≠ "กำไร" (ไม่ใช้คำหลังเฉย ๆ) · ต่างจาก `adQuality` ที่ใช้ "แชท (Meta)/แชท (Deep)" — หน้านี้ไม่แตะคำนั้น
7. **สี:** ตารางสีด้านบนตรึงสถานะ→สีเดียวทั้งหน้า · เขียวเฉพาะยืนยัน · แดงเฉพาะตีกลับ/ขาดทุน · ม่วง `chart-secondary` ห้าม
8. **มือถือ:** ปุ่มกรอง/ปุ่มแถว/select แท็บ `min-h-11` · แท็บเปลี่ยนเป็น select (ไม่มีเป้าเล็ก) · action หลัก (เปลี่ยนมุมมอง) อยู่ใต้หัวหน้า ไม่ลอยนอกโซนนิ้ว · heatmap แอด×สินค้า ถูกแทนด้วยรายการ (ช่องเล็กกว่า 44px แต่เป็นการอ่าน ไม่ใช่การกด) · heatmap เวลา transpose เป็นแถวยาว เลื่อนทั้งหน้า ไม่ใช่เลื่อนในกรอบ
9. **1440 กว้าง:** แท็บสรุปใช้ 2 คอลัมน์ในการ์ดเดียว (ตัวเลขหลักซ้าย/ตารางขวา) จึงไม่มีฝั่งว่าง · แท็บคุณภาพ 5/7 ทั้งสองฝั่งมีกราฟ · แท็บอื่นเป็นการ์ดเต็มกว้างที่ตารางยืดตาม · **ความเสี่ยงที่เหลือ:** heatmap เวลา 7×24 ที่ 1440 กว้างแต่เตี้ย (7 แถว) — ตั้ง `height` ≈ 280 และให้บรรทัด "ขายดีสุด…" อยู่บนเพื่อไม่ให้การ์ดดูโล่ง

### Design decisions + rationale
- **ตัวกรอง: ไม่ใช้ `AdReportFilters` ซ้ำตรง ๆ** — ผูก xlsx export/บรรทัดบัญชี/tz/`ads` prop ที่ผู้ใช้เพิ่งสั่งตัดจาก ad-quality · ก๊อป `AdQualityFilters` เป็นสำเนาที่ 3 ลดความเสี่ยงต่อ 2 หน้าที่ขึ้น prod แล้ว · ข้อแลก: ซ้ำโค้ด 3 ที่ (Open Q4)
- **แท็บบน server ต่อแท็บ** ผ่าน `?tab=` (ตามที่ขอ) + Suspense key — ไม่ยิง Insights/คำนวณแท็บที่ไม่ดู
- **สลับแท็บ=`push`** เหมือน FinanceTabs เพื่อปุ่มย้อนกลับพากลับแท็บเดิม
- **7 แท็บ → select บนมือถือ** แทนแถบเลื่อน (มติ 2026-10-01 + บทเรียน FinanceTabs ที่แท็บที่ 3 ถูกซ่อนครึ่งใบ)
- **Drill ผ่าน URL** `campaign/adset` — ลิงก์ได้ ย้อนทีละชั้น · ระดับแอดเปิดชีตเดิมแทนหน้าที่ 4
- **คืนค่าที่ FR บอก "ทุกตัวเลขกดลงถึงออเดอร์"** อย่างจำกัด: กดได้เมื่อมีแอดตัวเดียวเป็นเป้า (แถวแอด/แถวคำแนะนำ) — ตัวรวมกดไม่ได้ (Open Q1)
- **Waterfall ด้วย rangeBar** — ธีมไม่มี waterfall ตรง ๆ
- **Heatmap สีเดียว** แทนเขียว-ชมพูของธีม — ความเข้ม = จำนวนเงิน ไม่ใช่ดี/ร้าย
- **การ์ดคำแนะนำ = รายการในการ์ดเดียว** ไม่ใช่กริดการ์ด 3 ใบเท่ากัน (กฎ no identical cards / no nested cards)
- **ซ่อน (ไม่ใช่ "—") ตอน Meta ไม่ OK** ตามที่ FR-010 ตกลงไว้ — คงความสอดคล้อง

### Open questions (ให้ Controller / developer)
1. **ออเดอร์ที่กดได้จากแถวรวม:** FR-011..016 บอก "ทุกตัวเลขกดลงถึงรายการออเดอร์ได้" แต่ `/api/reports/ads/orders` กรองด้วย `adId` เดียว และ `AdOrdersSheet` รับ `AdViewRow` · ผมออกแบบให้กดได้เฉพาะแถวระดับแอด + แถวคำแนะนำ · แถวแคมเปญ/ชุดโฆษณา/การ์ดสรุป กดไม่ได้ (กดลงชั้นถัดไปแทน) — ยอมรับได้ไหม หรือต้องขยาย API รับ `adIds[]`/`campaignId` ? ถ้าขยายต้องเพิ่มใน spec backend (เทส tenant)

3. **ความกว้างแท็บที่ 768 และ 1024:** ประเมินคร่าว ๆ รวม ~650px ใน nav-tabs `px-3 text-sm` ที่เนื้อหา ~736px — ต้องวัดจริง (Anuphan ไทยกว้างกว่าประมาณการ) · ถ้าเกิน ให้เปลี่ยนจุดสลับเป็น select ที่ `<lg`
4. **ซ้ำโค้ดตัวกรอง 3 ที่:** แนะนำให้ extract `AdRangeFilters` กลาง (slot ปุ่มขวา) เป็นงานแยกหลังเฟส 3 ไม่ใส่ใน PR นี้ — ตัดสินใจ?
5. **เกณฑ์แสดงบรรทัด "ขายดีสุด…" ในแท็บช่วงเวลา:** ออเดอร์น้อย (เช่น 3 ใบ) บรรทัดนี้จะชี้ช่วงที่ไม่มีความหมาย · เสนอซ่อนเมื่อออเดอร์ในช่วง <10 (เกณฑ์เดียวกับ FR-018) — ต้องการให้ product ยืนยัน ไม่ใช่ผมตั้งกฎใหม่
6. **ทางเข้าหน้านี้:** เมนู รายงาน → ต้องเพิ่มเมนู · และจะใส่ลิงก์จาก `/reports/ads` ด้วยไหม (ตอนนี้มี "ดูคุณภาพโฆษณา" + ส่งออก · เพิ่มอีกปุ่มทำให้แถวขวาแออัดบนมือถือ) — แนะนำ: เพิ่มเฉพาะเมนู ไม่เพิ่มปุ่ม
7. **`DeltaText` เพิ่ม `tone="inverse"`** (ขึ้น = warning, ลง = success) สำหรับ ยกเลิก/ตีกลับ — เป็นการแก้ component ร่วม backward-compatible
8. **ไม่ได้ใส่บล็อก `=== DEEP-HANDOFF ===`** เพราะไม่ได้อ่าน `command-center-agent-protocol.md` และคำสั่งมาจาก Controller โดยตรง ไม่ใช่สายพาน · ถ้าต้องการให้ผมต่อท้ายตามโครง บอกได้ · `ป้ายถัดไป: stage:build`
9. **ไม่มี `frontend-design/SKILL.md` ในรีโป** — ถ้ามีที่อื่นให้ชี้ path เพื่อให้ผมอ่านก่อนรอบถัดไป
