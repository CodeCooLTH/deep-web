### Impeccable compliance

**Mode: Operate** — ทั้ง 2 หน้าเป็น task surface ของ seller ที่ล็อกอินแล้ว (ตาราง/ฟิลเตอร์/bulk action/ฟอร์ม) ไม่ใช่ brand surface — ตาม `PRODUCT.md` §Register ("override เป็น `product` per-task เมื่อทำงานบน seller console") + `operate.md` ("earned familiarity — เครื่องมือต้องหายไปในงาน"). เกณฑ์ตัดสินคือ scanability/consistency-กับหน้าอื่นในโปรดักต์เดียวกัน ไม่ใช่ความแปลกใหม่

- **One Voice (primary น้ำเงิน `#236dc9` ≤10%)** — น้ำเงินโผล่เฉพาะ: ปุ่ม `+ เพิ่มคำถาม`/`บันทึก`/`ย้าย`, chip กรองที่ถูกเลือกอยู่ (`ทั้งหมด` active), checkbox/switch ที่ `checked`, ลิงก์ `แก้คำตอบ`/`แก้`. **ที่เหลือทั้งหมด (badge สถานะ, แถวตาราง, ตัวเลขสถิติ, ปุ่ม "ข้าม"/"ยกเลิก") เป็น neutral (`text-default-*`) หรือ semantic** (success/warning/danger) — จุดเสี่ยงที่สุดที่มักพลาด (บทเรียน `feedback_impeccable_detector_vs_design`) คือสถิติหัวการ์ด (`142 ข้อ · ใช้งานอยู่ 128 · ...`) **ต้องเป็น `text-default-500` ล้วน ไม่ทาน้ำเงิน** เพราะเป็นข้อมูลอ่านอย่างเดียว ไม่ใช่ action
- **Verified-Means-Green** — badge `ใช้งานอยู่` (คำถามที่ toggle เปิด, พร้อมตอบลูกค้าจริง) = `bg-success/15 text-success` (ยืนยันแล้วว่าใช้งานจริง ตรงความหมาย "ผ่าน"). badge `รอกรอก N ข้อ` = **`bg-warning/15 text-warning`** (ยังไม่ทำอะไร ไม่ใช่ผิด ไม่ใช่สำเร็จ — ห้ามเขียวตามกฎข้อนี้ตรง ๆ). badge `ปิดไว้`/`ไม่เคยถูกใช้` = neutral outline (`border-default-300 text-default-700`) ไม่ใช่ danger (ปิดเองไม่ใช่ error). สถานะ "ล้มเหลว" ใน CSV preview เท่านั้นที่ได้ `danger`
- **Sentence case** — ป้าย/ปุ่มทั้งหมดเป็นประโยคไทยปกติ ("เพิ่มเข้าคลังคำถาม" ไม่ใช่ "เพิ่มเข้าคลังคำถาม!!") ไม่มี ALL CAPS จุดไหนเลย (mockup เดิมก็ไม่มี)
- **Ink-tinted shadow** — การ์ด/โมดัล/ชีททั้งหมดใช้ `.card` shadow token ของ Paces (`0 1px 4px rgba(130,143,163,.15)`) เดิม ไม่เพิ่ม custom shadow ใด ๆ — ไม่มีจุดขัดกัน
- **Anti-slop** — ไม่มี hero-metric template (สถิติหัวการ์ดเป็นบรรทัดข้อความ ไม่ใช่ตัวเลขใหญ่แยกการ์ด), ไม่มี eyebrow ตัวพิมพ์เล็กจิ๋ว, ไม่มีเลข section 01/02 ในหน้าจริง (เลข "05"/"07" ใน mockup เป็นเลขเอกสารอ้างอิงเท่านั้น ไม่ใช่ UI), แถวตารางไม่ใช่การ์ดซ้อนการ์ด (`divide-y` ธรรมดา ตาม `DataTable.tsx` mobile mode)
- **น้ำเสียง** — "ข้าม" ไม่ใช้คำแรง, empty state ทั้งสองจุดบอกวิธีเริ่ม/ความหมายของความว่าง ไม่ใช่ "ไม่มีข้อมูล" เฉย ๆ, error banner บอกวิธีแก้ (ลองใหม่/ตรวจไฟล์) ไม่ใช้รูปประโยคราชการ

**จุดที่ mockup (ภาพประกอบ) ขัดกับของจริงในระบบ — ตัดสินไว้แล้ว ระบุให้ Controller ตรวจซ้ำ:**

| จุด | mockup บอกอะไร | ตัดสิน | เหตุผล |
|---|---|---|---|
| แถบ bulk action | inline row ในการ์ด (bg primary-wash) | **คงเป็น inline row ตามตำแหน่งใน mockup** แต่ปรับ token เป็น Paces (`bg-primary/10`) แทน hex ของ mockup — ไม่ย้ายไปเป็น floating pill แบบ `BulkActionBar.tsx` (ออเดอร์) | mockup ผ่านรีวิว 4 รอบ = SSOT ของ **ตำแหน่ง/ลำดับชั้นของหน้านี้โดยเฉพาะ** (สอดคล้อง `reference-vs-theme-source.md`: asset/layout ตาม ref ที่ approve แล้ว, component/token ตาม theme) — inline บอก "โหมดเลือกอยู่" ชัดกว่า floating pill ที่ลอยทับ list ยาว |
| เวลา "ล่าสุดวันนี้ 16:41" / "เมื่อวาน" | relative-day copy | **ใช้ `formatDateTime()` แบบเต็ม** ("31 ก.ค. 2569 16:41") แทน relative label | โปรเจกต์มีเฉพาะ `formatDate`/`formatDateTime` (Hard Rule วันที่) ไม่มี helper "วันนี้/เมื่อวาน" อยู่แล้ว — เพิ่ม logic relative-day ใหม่นอกขอบเขต S-id นี้ (ไม่ใช่ business rule แต่เป็น util ใหม่ที่ควรมี S-id ของตัวเอง) → ทำเครื่องหมายเป็น "เพิ่มได้ทีหลังไม่ block" ใน Open Questions |
| "สินค้าที่เกี่ยวข้อง" ใน sheet §05 มือถือ | มีช่อง product picker | **ตัดออกตามคำสั่ง Controller** (AI Enhance ยังไม่ทำ) | ตรงกับ scope ชัดเจนอยู่แล้ว ไม่ใช่จุดขัดกัน แค่ยืนยันซ้ำ |
| `.tool` แถบเครื่องมือมีพื้นหลังสีเทาอ่อนคาด (`--line-soft`) | toolbar แยกโซนด้วยสี | **ไม่ใส่พื้นหลังแยกโซน** ใช้ toolbar โปร่งเหมือน `AutoReplyListing.tsx`/`ProductsListing.tsx` (การ์ด-header ธรรมดา) | ของเดียวกันในโปรดักต์ต้องหน้าตาเดียว (craft-floor "Consistent affordances") — หน้ารายการอื่นทั้งหมดในหลังบ้านไม่มี toolbar สีคาด การใส่เฉพาะหน้านี้จะดูเป็น "ประกอบขึ้นมาคนละที" |

## ต้องถาม user ก่อน implement

1. **"ข้าม" มี undo ไหม / เห็นซ้ำได้ไหม** — สเปกนี้ออกแบบเป็น dismiss ทางเดียว (ไม่มี undo, ไม่มีตัวกรอง "แสดงที่ข้ามแล้ว") เพราะ non-goal ไม่ได้พูดถึง แต่ถ้าร้านกด "ข้าม" พลาดจะกู้คืนไม่ได้เลย — Controller/product ต้องยืนยันว่ารับความเสี่ยงนี้ หรือให้เพิ่ม toast แบบมีปุ่ม "เลิกทำ" ใน S-id เดียวกัน
2. **เวลา "ล่าสุด"** — ใช้ `formatDateTime` เต็ม (ตาม Hard Rule วันที่) แทน relative "วันนี้/เมื่อวาน" ของ mockup — ยืนยันว่าโอเค หรือต้องการ relative-day util ใหม่ (นอกขอบเขต S-id ปัจจุบัน ต้องเปิด S-id เพิ่ม)
3. **Icon สำหรับ "ย้ายไปกลุ่มอื่น"** เลือก `tabler:arrow-right` ไปก่อน (ปลอดภัย/มีจริงแน่นอน) — ถ้าต้องการไอคอนที่สื่อ "ย้ายเข้ากลุ่ม" ชัดกว่านี้ (เช่น folder-transfer) ต้องให้ user เลือกจาก gallery `theme/paces/Admin/TS/src/app/(admin)/icons/tabler/page.tsx` เอง เพราะไม่ใช่ไอคอนที่มี precedent ใช้แล้วในโค้ด
4. **modal "เพิ่ม/แก้ไขคำถาม" ในหน้า A** ไม่มีอยู่ใน mockup เลย (mockup มีแต่ sheet ฝั่งคิว) — ผมออกแบบเทียบจาก field เดียวกัน (คำถาม/คำตอบ/toggle) แต่รูปแบบ modal/sheet นี้ยังไม่ผ่านสายตา user โดยตรง — ควร screenshot ให้ user เห็นก่อน implement จริงหรือถือว่าอนุมัติผ่าน pattern ที่ established แล้ว (CustomerPanelSheet precedent)?

### Anti-slop self-check

1. **เฉพาะกับ Deep จริงไหม** — hint "ตัวกรอง 'ไม่เคยถูกใช้' คือตัวที่จะได้ใช้บ่อยสุด" และ hint กรอง PII เป็นข้อความที่อธิบายพฤติกรรมจริงของระบบนี้ (D5/A4) ไม่ใช่ copy generic "no results found" — เอาไปแปะสินค้าอื่นไม่ได้ทันทีเพราะอ้างอิงกลไกจับคู่ตรงตัว/PII filter ของ Deep เอง
2. **1 อย่างเด่นที่สุดต่อหน้า** — หน้า A: ปุ่ม `+ เพิ่มคำถาม` (primary น้ำเงินทึบ) เด่นสุด ที่เหลือ (สถิติ, ตาราง) เป็น neutral. หน้า B: ปุ่ม `กรอกคำตอบ` ต่อแถว (primary) เด่นกว่า `ข้าม` (ghost/neutral) เสมอ — ไม่มีจุดไหนที่สองปุ่มน้ำหนักเท่ากัน
3. **ตัดอะไรทิ้ง** — ตัด "สินค้าที่เกี่ยวข้อง" ออกจาก sheet ตามคำสั่ง (ค่าคงที่ในขอบเขตนี้ที่ยังไม่มี backend รองรับ); ไม่ใส่คอลัมน์ "แก้ไขล่าสุด" ในตารางคลัง (มีอยู่แล้วในหน้ารายการกลุ่มคำ กม.ซ้ำไม่ได้ให้ข้อมูลใหม่ต่อแถวคำถาม)
4. **State ครบ** — ระบุ empty/loading/error/bulk/เลขศูนย์/เลขหลักพัน/ข้อความยาวผิดปกติ ครบทั้ง 2 หน้า (ดูตาราง State list)
5. **copy ตรงกับสิ่งที่ทำได้จริง** — แก้ hint ของ mockup ที่โกหก user ("ระบบจะจับคำถามที่ความหมายใกล้เคียงกันด้วย") เป็นข้อความบอกตรง ๆ ว่า v1 จับคู่ตรงตัว 100% เท่านั้น (ตาม A1) — ป้องกัน "ตั้งไว้แล้วไม่ทำงาน" ซ้ำรอยบั๊กที่ user เพิ่งเจอ
6. **คำเดียวกันหมายถึงของเดียวกัน** — "ใช้งานอยู่" หมายถึง toggle เปิดของคำถามนั้นทั้ง 2 หน้าที่มีคำนี้ปรากฏ (chip กรอง + badge สถานะ), "กลุ่มคำ"/"คลัง" ใช้แยกกันตลอด (กลุ่มคำ = keyword group, คลัง = qna library ของกลุ่มนั้น) ไม่สลับกัน
7. **สีสื่อความหมายถูก** — เขียวสงวนให้ "ใช้งานอยู่" เท่านั้น; "รอกรอก" ใช้ warning ไม่ใช่เขียว/แดง; "ล้มเหลว" (CSV) ใช้ danger เท่านั้นตอนที่ import จริงล้มเหลว
8. **แตะได้จริงบนมือถือ** — ปุ่ม `กรอกคำตอบ`/`ข้าม`/สวิตช์ทุกจุดอ้างอิง `min-h-11`/`size-11` (44px) ตาม precedent ที่มีอยู่แล้วในโค้ด (`AutoReplyListing.tsx` mobile card ปุ่ม `size-11`); ไม่มี checkbox/bulk บนมือถือจึงไม่มีปัญหา tap-target เล็กเกินสำหรับ selection
9. **จอกว้าง 1440** — ทั้ง 2 หน้าเป็น single-column card เต็มความกว้าง content area (ไม่มีคอลัมน์ข้างที่ว่างเปล่า) เพราะเนื้อหาเป็นตาราง/list ที่ควรใช้ความกว้างเต็มสำหรับอ่านคำถาม-คำตอบยาว — ไม่ทำ layout 70/30 ที่ไม่มีอะไรให้ใส่ฝั่ง 30

### Impeccable compliance

**Mode: Operate** (ทั้ง 3 จุดเป็น task surface ของ seller — ตาราง/ฟอร์ม/รายการแชทที่ใช้งานทุกวัน ไม่ใช่ brand surface)

- 🛑 **Verified-Means-Green — จุดขัดที่ต้องแก้จากสิ่งที่ scope baseline เขียนไว้:** scope บอกให้ใช้ `bg-success/15 text-success` ตามภาพอ้างอิง (เขียวมิ้นต์) แต่**ผมไม่เห็นด้วยกับสีนี้ และเสนอเปลี่ยน** — ดูเหตุผลเต็มในหัวข้อ "หน้า C" ด้านล่าง (สรุปสั้น: "DeepBot ตอบให้" ไม่ใช่เหตุการณ์ "ยืนยันแล้ว/สำเร็จ" ตามนิยามกฎนี้ — มันคือข้อมูลว่า "ใครตอบ" เท่านั้น ใช้เขียวจะทำให้สัญญาณเขียวเฟ้อและซ้ำกับ badge `สำเร็จ` ของ order stage ที่อยู่แถวเดียวกันอยู่แล้ว)
- **Sentence case / Ink shadow / anti-slop** — เหมือนเดิมทั้ง A/B; หน้า C ไม่เพิ่ม shadow/gradient ใด ๆ, ไอคอนไม่ใช่ emoji (`tabler:robot` เป็น outline icon)
- **น้ำเสียง** — ป้าย/prefix ในหน้า C บอกข้อเท็จจริง ("DeepBot ตอบข้อความนี้") ไม่ใช่การตลาด ไม่ไฮป์

**จุดที่ theme/ภาพอ้างอิง ขัดกับ Impeccable — ตัดสินไว้แล้ว ให้ Controller ตรวจซ้ำ:**

|---|---|---|---|
| Bulk action row (หน้า A) | inline row ในการ์ด | คงตำแหน่งตาม mockup, token เปลี่ยนเป็น Paces | (เดิม — ดูรอบก่อน) |

### สิ่งที่มีอยู่แล้วในแถวนี้ (ยืนยันจากโค้ดจริง ไม่เดา)

```
[avatar+channel-badge]  ★ ชื่อลูกค้า                      4 ชม.
                         คุณ: ข้อความล่าสุด...
                         [สำเร็จ]green [ad_id.1202…]gray     [📁ทดสอบ]gray ← ชื่อ "กลุ่มแชท" ที่ร้านตั้งเอง
```
- `[สำเร็จ]` = `orderStage.COMPLETED` badge = **`bg-success/15 text-success-ink`** (เขียวจริง อยู่ในแถวจริง — ยืนยันจาก `src/lib/order-stage.ts:46`)
- `[📁ทดสอบ]` = **`groupChip`** = ชื่อกลุ่มแชทที่ร้านสร้างเอง (chat organization group, `ChatGroupTab.name`) — **บังเอิญชื่อ "ทดสอบ" ในภาพที่ user ส่งมา ไม่เกี่ยวกับโหมดทดสอบของ auto-reply เลย** ⚠️ ต้องระวังเรื่องคำซ้ำ (ดูหัวข้อ "จุดต้องระวัง" ด้านล่าง)
- แถวนี้แน่นอยู่แล้วจริงบน 360px (มี badge/chip สูงสุด 3 ชิ้นในบรรทัดเดียว + เวลาบนขวา + จุดยังไม่อ่านที่มุม avatar)

### เงื่อนไขที่ป้ายขึ้น (ล็อกตาม scope baseline)

ข้อความ **ล่าสุด** ของเธรดเป็นฝั่งร้าน (`lastSenderRole === 'SHOP'`) **และ** ข้อความนั้นมี `autoReplyKind != null` — ไม่ใช่ `autoReplyCount > 0` (กัน "ป้ายค้างตลอดกาล" ตามที่ scope เตือนไว้แล้ว)

### ทางเลือกการวาง — 2 แบบ พร้อมข้อดี-ข้อเสีย (Controller/user ต้องเลือก)

**ตัวเลือก 1 (แนะนำ) — inline prefix แทนที่ "คุณ: " บนบรรทัด preview เดิม ไม่เพิ่ม pill/badge ใหม่เลย**

```
[avatar+channel-badge]  ★ ชื่อลูกค้า                      4 ชม.
                         🤖 DeepBot: ข้อความล่าสุด...
                         [สำเร็จ]green [ad_id.1202…]gray     [📁ทดสอบ]gray
```
- เปลี่ยนบรรทัดโค้ดที่มีอยู่แล้ว (`InboxList.tsx:1171-1174`): เดิม `{c.lastSenderRole === 'SHOP' && preview && <span>คุณ: </span>}` → เพิ่มเงื่อนไขแยก: ถ้าข้อความนั้น `autoReplyKind != null` → แสดง `<Icon icon="robot" className="text-primary size-3" /> <span className="text-primary font-medium">DeepBot{isTest ? ' · ทดสอบ' : ''}: </span>` แทน "คุณ: " ธรรมดา
- **ข้อดี:** กินพื้นที่ 0px เพิ่ม (ใช้ slot เดิม) → **ไม่มีความเสี่ยงล้นจอ 360px เลย**, ไม่มีสีเขียวมาแย่งความหมายกับ `[สำเร็จ]`, สอดคล้อง `text-primary` เดียวกับ `AutoReplyTag.tsx` ที่ shipped แล้ว, สื่อความ "ใครตอบข้อความนี้" ตรงจุดที่สุด (อยู่ติดกับตัวข้อความ ไม่ใช่ badge แยกลอย)
- **ข้อเสีย:** ไม่ตรงกับรูปที่ user ส่งมาเป๊ะ (ภาพเป็น pill พื้นเขียว ไม่ใช่ text prefix) — เป็นการตีความรูปแบบใหม่ ต้องขอ user ยืนยันก่อน (Hard Rule 6: ต้องถามเมื่อไม่ใช่ asset/content ตรง ๆ)

**ตัวเลือก 2 — ยังเป็น pill ตามฟอร์มของภาพ แต่เปลี่ยนสีเป็นน้ำเงิน + วางที่มุมล่างขวา (โซนเดียวกับ groupChip)**

```
[avatar+channel-badge]  ★ ชื่อลูกค้า                      4 ชม.
                         คุณ: ข้อความล่าสุด...
                         [สำเร็จ]green [ad_id.1202…]gray  [🤖DeepBot]blue [📁ทดสอบ]gray
```
- Badge: `<span className="badge bg-primary/15 text-primary text-2xs inline-flex items-center gap-1"><Icon icon="robot" width={11}/>DeepBot{isTest?' · ทดสอบ':''}</span>`
- วางในโซน `groupChip` เดิม (คอลัมน์ขวา ใต้เวลา) — **บน 360px ถ้ามีทั้ง groupChip และ DeepBot badge พร้อมกันจะซ้อน/ล้น** → ต้องกำหนดลำดับความสำคัญ: **DeepBot badge สำคัญกว่า (ข้อมูล operational เร่งด่วนกว่า) → ซ่อน groupChip เมื่อมี DeepBot badge ในแถวเดียวกัน** (fallback: แสดง DeepBot อย่างเดียว)
- **ข้อดี:** ตรงฟอร์มภาพอ้างอิงมากกว่า (ยังเป็น pill+icon+text)
- **ข้อเสีย:** เพิ่มความหนาแน่นของแถวที่แน่นอยู่แล้ว, ต้องมี fallback logic ซ่อน groupChip (ความซับซ้อนเพิ่ม), ยังต้องแก้สีจากเขียว→น้ำเงินอยู่ดี (ไม่ตรงภาพ 100%)

**คำแนะนำของผม: ตัวเลือก 1** — ปลอดภัยกว่าใน 3 มิติที่ Controller เตือนไว้ (มือถือ, สีชนกัน, ความสม่ำเสมอกับ `AutoReplyTag.tsx`) แต่ **ต้องขอ user ยืนยันก่อน implement** เพราะเบี่ยงจากฟอร์ม pill ที่ส่งภาพมาให้จริง ๆ (ดู "ต้องถาม user" ด้านล่าง)

### ไอคอน

ยืนยันตามที่ Controller อ่านจากภาพ: **`tabler:robot`** — ไม่ต้องเดา เพราะ **มีอยู่แล้วจริงในโค้ด prod** (`AutoReplyTag.tsx:130` ใช้ `<Icon icon="robot" className="text-xs" />`) ยืนยันว่ามีอยู่จริงในชุด tabler ที่โปรเจกต์ใช้อยู่แล้ว — ไม่ใช่ชื่อที่เดาใหม่

### สี — สรุปคำแนะนำ

`text-primary` (ตัวเลือก 1) หรือ `bg-primary/15 text-primary` (ตัวเลือก 2) — **ไม่ใช่ `bg-success/15 text-success`** ตามเหตุผลในหัวข้อ Impeccable compliance ด้านบน

### Dark mode

ทั้งสองตัวเลือกใช้ token เดิมที่มีอยู่แล้วในระบบ (`text-primary` / `bg-primary/15`) ซึ่ง Paces resolve เป็นสี dark-mode ของตัวเองอัตโนมัติผ่าน `--color-primary` (เหมือนที่ `AutoReplyTag.tsx` ทำงานถูกต้องใน dark mode อยู่แล้วใน prod) — ไม่ต้องเพิ่ม logic แยก

### จุดต้องระวัง (นอกเหนือจากที่ Controller ถาม)

**คำ "ทดสอบ" ชนกัน 2 ความหมายในแถวเดียว** — ถ้าร้านมีกลุ่มแชทชื่อ "ทดสอบ" (organizational group, ชื่อที่ร้านตั้งเอง) จริง ๆ ตามภาพที่ส่งมา และเธรดนั้นบังเอิญก็ถูก DeepBot ตอบด้วยโหมด AUTO_TEST → แถวเดียวจะมีทั้ง `[📁ทดสอบ]` (ชื่อกลุ่ม) และ `DeepBot · ทดสอบ` (โหมดทดสอบของบอท) พร้อมกัน ซึ่งเป็นคำเดียวกันแต่ความหมายคนละเรื่องเลย — เสี่ยงงงมาก แนะนำเปลี่ยนคำในป้ายบอทเป็น `DeepBot (ทดสอบ)` วงเล็บแทนจุด เพื่อลดโอกาสอ่านเป็นชื่อเดียวกับชิปกลุ่ม แต่คำนี้ผูกกับ `AutoReplyTag.tsx` ที่ prod ใช้อยู่แล้ว (`'DeepBot · ทดสอบ'`) — เปลี่ยนแค่จุดเดียวจะทำให้ 2 ที่ไม่ตรงกันอีก **จึงไม่ใช่จุดที่ผมควรตัดสินเอง ใส่ไว้ใน "ต้องถาม user"**
