ความทนของการเชื่อมต่อ LINE — 5 surface

ส่วนขยาย 00025 (2026-08-12) · Design Spec: 2026-08-12-line-connection-health-design-spec.md · Requirement: EXTENSIONS-2026-08-12-connection-health.md

Mobile 390 · Tablet 768 · Desktop 1280 — token คัดจาก _root.css ตรง ๆ

สิ่งที่ม็อกอัพนี้แก้

  • การ์ดเดิมมี 2 สถานะ (เชื่อมแล้ว / เชื่อมต่อใหม่) และขึ้น เขียว "เชื่อมแล้ว" ได้ทั้งที่ webhook ไม่เคยถูกตั้ง — ละเมิด Verified-Means-Green มาตลอด
  • สายขาดได้ 4 ทาง แต่ 3 ทางระบบไม่รู้และร้านไม่รู้ (secret ไม่ตรง · webhook ปิด/ไม่ตั้ง · destination ไม่เจอ) — ทั้งสามมีหน้าตาเดียวกันคือ "วันนี้ลูกค้าเงียบจัง"
  • POST /v2/bot/channel/webhook/test ตอบ success:true ได้ทั้งที่เราประมวลผล event ไม่ได้เลย ⇒ ปุ่มทดสอบต้องอ่านตัวนับของเราเองเป็นจังหวะที่สอง

S1 — การ์ด LINE ใน /settings/channels 6 สถานะ แสดงตัวร้ายแรงสุดตัวเดียว (AC-CH-23/24)

ลำดับความสำคัญ (AC-CH-23) — เรียงตาม "ร้านเสียหายเร็วแค่ไหนถ้าไม่แก้"

  • SECRET_MISMATCH danger · shield-lock > TOKEN_INVALID danger · alert-circle > WEBHOOK_* warning · link-off > TOKEN_EXPIRING warning · clock-exclamation > HEALTHY success · shield-check
  • 🛑 เขียว = HEALTHY เท่านั้น — status='ACTIVE' ไม่พอ ต้องผ่านทุกด่าน
  • ทุกสถานะที่ไม่ HEALTHY มี ปุ่มทางออก 1 ปุ่ม ไม่ใช่แค่ป้ายบอกอาการ

S2 — ปุ่ม "ทดสอบการเชื่อมต่อ" 2 จังหวะ AC-CH-16/17/18

🛑 ทำไมต้องมีระดับ "ผ่านแต่มีข้อสังเกต"

  • การตรวจ inbound เป็น absence-of-failure (ตัวนับความล้มเหลวไม่ขยับ) ไม่ใช่ presence-of-success ⇒ มีความไม่แน่นอนโดยธรรมชาติ ห้ามรายงานเป็นเขียวเต็ม
  • แถวที่ 3 คือแถวเดียวที่ตอบคำถามจริงว่า "event ที่ LINE ส่งมา เราประมวลผลได้ไหม" — สองแถวบนตอบแค่ว่าตั้งค่าถูก

S3 — แถบแทนที่ช่องพิมพ์เมื่อ TOKEN_INVALID เฉพาะ LINE (OQ-1) · AC-CH-21/22

สิ่งที่เปลี่ยนและไม่เปลี่ยน

  • เปลี่ยน: จาก dim ทั้งแถบ (opacity-50 pointer-events-none) เป็น บล็อกแทนที่ — Base: ChatThread.tsx:3121-3153 (showAiTakeoverComposer) เปลี่ยน tone bg-info/15→bg-danger/15, icon robot→alert-circle
  • ไม่เปลี่ยน: entry ใน ThreadStatusBar เหนือเธรดยังอยู่เหมือนเดิม (เห็นได้แม้เลื่อนอ่านข้อความเก่าขึ้นไปไกล)
  • 🛑 บล็อกได้เฉพาะ status='TOKEN_INVALID' = LINE ปฏิเสธเราจริงมาแล้ว — ห้ามบล็อกจากการอนุมาน (บทเรียน viaStandby 2026-08-09)
  • 🛑 tokenInvalid ชนะโควตาเสมอเมื่อเกิดพร้อมกัน (ตรงกับคอมเมนต์เดิม ChatThread.tsx:1412)

S4 — "คุณปิดแจ้งเตือนของร้านนี้อยู่" AC-CH-31/33 · จุดแทรกเดียว InboxList.tsx

ทำไมไม่มีปุ่มปิด (OQ-2)

  • บล็อกหายเมื่อ กด "เปิดแจ้งเตือน" สำเร็จเท่านั้น — เงื่อนไขตรงกับความจริง ไม่ใช่การซ่อน
  • ปิดถาวรได้ = ร้านลืมว่าปิดแจ้งเตือนอยู่ แล้วพลาดข้อความสำคัญโดยไม่รู้ตัว
  • PATCH ล้ม → toast error บล็อกยังอยู่ ไม่ optimistic-hide (ซ่อนผิดแล้วเสียหายกว่าปุ่มค้าง)
  • 🛑 ไม่มีแถว = เปิด · มีแถวค่า true = เปิด → ทั้งสองกรณีไม่แสดงบล็อก (AC-CH-33)

S5 — ป้าย "ปิดแจ้งเตือน" ในรายชื่อสมาชิก AC-CH-32 · ทำทีหลัง

ทำไม S5 เป็นสีเทา ไม่ใช่เหลือง

  • S4 = เรื่องของตัวเอง → info + ปุ่มแก้ทันที
  • S5 = เรื่องของคนอื่น → neutral + ไม่มีปุ่ม เพราะเจ้าของ toggle แทนพนักงานไม่ได้อยู่ดี (NotificationPrefsCard ผูกกับ session.user.id ของเจ้าของค่าเอง)

หมายเหตุสำหรับ developer

  • ไอคอนในม็อกอัพนี้เป็น ตัวแทนชั่วคราว — ของจริงใช้ @iconify/react tabler ตามที่ระบุใน Design Spec (shield-lock · alert-circle · link-off · clock-exclamation · shield-check · bell-off · help-circle) — ห้าม emoji ในโค้ดจริง (HR12)
  • คลาสที่ ไม่มีอยู่จริงในธีม ห้ามใช้: btn-ghost · btn-warning · btn-soft-*
  • ปุ่มทุกตัวบนมือถือต้อง min-h-11 (.btn-sm สูงจริง ~30px ต่ำกว่าเกณฑ์ 44px)
  • ลำดับสถานะต้องอยู่ใน resolveLineChannelHealth() ที่ src/lib/line/channel-health.ts — ห้ามเทอร์นารีใน JSX (AC-CH-25)
