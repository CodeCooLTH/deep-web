### ตารางรายแอด (การ์ด 9)
- คอลัมน์ 7 ช่อง (ให้พอดี 1280 − sidebar 260): **โฆษณา** (รูป + ชื่อ + รหัสแอด) · แชทจากโฆษณา · คำสั่งซื้อ / *อัตราปิดการขาย* · ยอดขาย / *ยอดเฉลี่ยต่อใบ* · ค่าโฆษณา / *ต้นทุนต่อออเดอร์* · ROAS · ยกเลิก/คืน — ตัวเอียง = บรรทัดรองใต้ค่าหลัก
- ตัวเลขทุกช่อง **จัดกลาง** (user ขอ) · ชื่อแอดชิดซ้าย ตัดด้วย … + title ชื่อเต็ม
- ไม่มีชื่อ → "รหัสโฆษณา {adId}" · ไม่มีรูป → ไทล์ไอคอน · แชท 0 → อัตราปิด "—"
- แถวรวมท้ายตาราง: ผลรวมต้องเท่าการ์ด 1/2 (HR16)
- Mobile: การ์ดรายการ — ยอดขาย · คำสั่งซื้อ (ปิด %) · ROAS (ค่าแอด) + บรรทัดล่าง แชท/เฉลี่ย/ต้นทุน/ยกเลิก

## 3. ข้อมูลในม็อกอัพ

- **จริง (ร้านธนภัทร์ 30 วัน):** 8 แอดแรกในตาราง (แชท/ออเดอร์/อัตรา/ยอด/เฉลี่ย/ยกเลิก) · ยอดจากโฆษณา ฿187,210 · สัดส่วน 95.95%/4.05% · แชท 1,380 · คำสั่งซื้อ 384 · อัตราปิด 27.8%
- **สมมติเพื่อให้รวมกันลง:** 4 แอดท้าย (รวม ฿11,520 / 29 ใบ / 16 แชท) · ยอดไม่ได้มาจากโฆษณา ฿7,902 (คำนวณย้อนจาก 4.05%) · ตัวเลขช่วงก่อนหน้า · รูปทรงซีรีส์รายวัน (ผลรวมเท่าการ์ดเป๊ะ)
- **ตัวอย่าง (มีป้าย):** ค่าโฆษณา ฿49,600 · ROAS 3.77 · ต้นทุนต่อออเดอร์ · จังหวัด · ช่องทาง · เพจ
- ⚠️ brief ให้ "379 ใบ / 17 ใบ" ในแถบสัดส่วน แต่ "คำสั่งซื้อ 384" ในตาราง — โค้ด `getAdSalesReport` นับ `adOrders` จากลูปเดียวกับ `rows[].orders` จึง**ต้องเท่ากันเสมอ** ม็อกอัพใช้ 384 ทั้งสองที่ (ถ้า 379 มาจากหน้าจริง แปลว่าเป็นคนละช่วงเวลา — ต้องยืนยัน)

## 4. Edge cases

- **ยังไม่เชื่อมบัญชีโฆษณา:** แบนเนอร์บนสุด + ปุ่ม "เชื่อมบัญชีโฆษณา" ไป `/settings/capis` · ช่องค่าโฆษณา/ROAS/ต้นทุน = "—" · แท็บ KPI 3-4 แสดง "—" กดแล้วเห็นข้อความ + ปุ่มเชื่อม · กล่อง ROAS ในการ์ด 3 กลายเป็นชวนเชื่อม (ดูสลับในม็อกอัพ)
- **เชื่อมแล้วแต่ token หมดอายุ/ไม่มีสิทธิ์ (MetaAudienceConnection.status ≠ ACTIVE):** เหมือนยังไม่เชื่อม + ข้อความ "การเชื่อมบัญชีโฆษณาหมดอายุ"
- **แอดในฐานเราไม่มีใน Insights** (ลบแอด/คนละบัญชีโฆษณา): ค่าโฆษณา "—" ไม่ใช่ ฿0 · **แอดที่มี spend แต่ไม่มีแชท/ออเดอร์**: ต้องแสดงแถวด้วย (ROAS 0.00) — ไม่งั้นแอดที่เผาเงินเปล่าหายจากตาราง
- **ROAS ดีที่สุด:** นับเฉพาะแอด ≥ 10 คำสั่งซื้อ (ไม่งั้นแอด 5 ใบ ROAS 6.71 ชนะ) — มติ user 2026-11-14: 10 ใบ
- **อัตราปิดการขายเกิน 100%** (ลูกค้าคลิกก่อนช่วงแล้วสั่งในช่วง — คอมเมนต์ใน service ยอมรับไว้แล้ว) เห็นในแถว "โปรล้อแม็ก 11.11" 155.56% — ต้องมีคำอธิบายที่หัวคอลัมน์ (มีแล้วใน FR-008)
- **ช่วงก่อนหน้าเป็น 0:** delta ไม่แสดง (ห้ามหาร 0) · "วันนี้" เทียบกับเมื่อวานทั้งวัน (ยังไม่จบวัน — ต้องระบุ)
- **`truncated`** (เกิน 20,000 ใบ): ป้ายเตือนเหมือนเดิม
- ร้านไม่มีข้อมูลแอดเลย (`hasAnyAdData=false`): หน้าว่างแบบ FR-008 เดิม ไม่วาดการ์ดกราฟ
- จังหวัด: ใบรับหน้าร้าน/ร้านบริการไม่มีที่อยู่ → "ไม่ระบุจังหวัด" (ต้องแสดง ห้ามตัดทิ้ง — ตัวเลขไม่ครบต้องบอก)
- ApexCharts: ห้ามมีคีย์ค่า `undefined` (กับดัก 00078) · วันที่ไม่มีขาย = 0 ไม่ใช่ null

## 5. FR-010 — ค่าโฆษณาจาก Meta (ตรวจกับโค้ดแล้ว)

- การเชื่อมมีอยู่แล้วจาก 00092: `MetaAudienceConnection` (1:1 Shop) มี `adAccountId` + `tokenEnc` + `status` · OAuth ขอ `ADS_SCOPES = 'ads_management'` (`src/lib/facebook/constants.ts`) — `ads_management` อ่าน Insights ได้ (ครอบ `ads_read`) แต่ทั้งคู่ยัง **Standard Access** ⇒ ใช้ได้เฉพาะบัญชีที่มี role ในแอป จนกว่าจะผ่าน App Review
- เรียก `GET /act_{adAccountId}/insights?level=ad&fields=ad_id,spend,impressions,inline_link_clicks,ctr,cpc,cpm&time_range={since,until}&time_increment=1` (แพตเทิร์น `graph()` เดียวกับ `meta-audience.service.ts`)
- **ROAS = ยอดขายของ Deep ÷ spend** · **ต้นทุนต่อออเดอร์ = spend ÷ คำสั่งซื้อของ Deep** — ห้ามใช้ purchase/conversion ของ Meta (นับซ้ำ/ช่วงเวลาไม่ตรงกับนิยามยอดขายเรา — HR16)
- เขตเวลา: Insights คืนตามเขตเวลาของบัญชีโฆษณา ต้องตรงกับวันแบบเวลาไทยที่เราใช้ — ถ้าบัญชีโฆษณาไม่ใช่ Asia/Bangkok ต้องแจ้ง
- แคช: ไม่ยิง Graph ทุกครั้งที่เปิดหน้า — เก็บผลรายวันต่อแอด (ตารางใหม่ → **migration · HR15**) หรือแคชช่วงสั้น — รอมติ
- บัญชีโฆษณาเดียวต่อร้าน (`shopId @unique`) — ร้านที่ยิงแอดจากหลายบัญชีจะได้ค่าโฆษณาไม่ครบ ⇒ ต้องติดป้าย "ค่าโฆษณาจากบัญชี {adAccountName} เท่านั้น"

## 6. คำถามที่ยังเปิด

1. ~~เกณฑ์ "ROAS ดีที่สุด"~~ → 10 ใบ (มติ user 2026-11-14) · ทำเป็น 2 เฟส: เฟส 1 = การ์ดที่มีข้อมูลในฐานแล้ว (ไม่มี migration) · เฟส 2 = ค่าโฆษณา/ROAS
2. การ์ดช่องทาง: ใช้ `shopChannelId → provider` (ข้อเท็จจริงว่าทักจากไหน) หรือ `Order.salesChannel` (ร้านเลือก/แก้เองได้ มี TIKTOK/STOREFRONT) — ม็อกอัพใช้แบบแรก
3. การ์ดช่องทางนับยอด**ทั้งร้าน** หรือเฉพาะ**จากโฆษณา** (ม็อกอัพ = ทั้งร้าน เพราะเกือบทุกใบจากแอดเป็น Messenger อยู่แล้ว)
4. เก็บ Insights ลงฐาน (migration) หรือยิงสด + แคช
5. จังหวัด: ทำแผนที่ด้วยไหม (ม็อกอัพ = รายการอย่างเดียว · ธีมใช้ jsvectormap ไม่มีแผนที่ไทยในธีม)
6. ส่งออก: ไฟล์เดิมของ FR-008 + คอลัมน์ค่าโฆษณา/ROAS หรือส่งออกทั้งแดชบอร์ด
7. ยืนยัน 379 vs 384 (ข้อ 3)
