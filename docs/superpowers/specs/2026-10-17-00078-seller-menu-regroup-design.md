# ข้อเสนอจัดกลุ่มเมนู seller ใหม่ (00078 PR)

Read-only: ผมยังไม่ได้แก้ไฟล์ใด และยังไม่ได้ render เมนูจริง ทุกอย่างอิงจากการอ่านโค้ด ผมอ่านเต็มเฉพาะ `seller-menu.ts`, `role-nav.ts`, `seller-menu-server.ts`, ทะเบียน route/capability และเทสที่เกี่ยวข้อง ส่วน `DESIGN.md` อ่านแค่ต้นไฟล์ ยังไม่ได้เปิด `PRODUCT.md`, `design.json` หรือ playbook ของ Impeccable

## 1. โครงเมนูจริงตอนนี้

ลำดับการกรองอยู่ที่ `resolveVisibleSellerMenu` (ทางเดียว) ผ่าน `resolveSellerMenuItems` ใช้กับ `(dashboard)` sidebar และ `(chat)` ChatNavRail เมนูนี้ใช้ร่วมกับ shortcut catalog ด้วย

มีแหล่งเมนูแค่ชุดเดียวคือ `sellerMenuItems` ส่วนมือถือไม่มีเมนูชุดที่สอง แต่ใช้ 3 ทางแยกกัน:
- แถบล่าง 4 แท็บ (`resolveMobileNav`)
- รายการ `QUICK_LINK_URLS` ที่ hardcode ไว้ในหน้า `/shop`
- เมนูลัดบนหน้าแรก ซึ่งดึงจาก catalog ของเมนูเดียวกัน

| กลุ่มเดิม (ป้ายที่เห็น) | รายการ (slug → ป้าย) | เงื่อนไขแสดง |
|---|---|---|
| **ANALYTICS** | dashboard ภาพรวมร้านค้า · sales ภาพรวมกำไร/ขาดทุน (SERVICE = "การเงินร้าน") · reports-agents การตอบแชทของแอดมิน · reports-products ยอดขายรายสินค้า | sales และ reports-products เฉพาะเจ้าของ (F1) · reports-products เฉพาะ ONLINE · reports-agents ตามสิทธิ์ X4 |
| **MANAGE** | orders (ป้ายผันตาม vertical) · auctions · products · inventory · queues ตารางงาน · rooms · calendar · bookings · inspection · housekeepers · customers · follow-ups · expenses | auctions และ inventory เฉพาะ ONLINE · queues เฉพาะ SERVICE · rooms, calendar, bookings, inspection, housekeepers เฉพาะ LODGING · inventory ซ่อนใน iOS/Android ถ้ายังไม่สมัคร และซ่อนทุกกรณีเมื่อ `hidePaidFeatures` · expenses ของ SERVICE ชี้ไป `/sales?tab=expense` และซ่อนได้ตามตั้งค่ารายงาน |
| **CHAT** | inbox · chat-desk · settings-auto-reply · settings-comment-reply · settings-chatbot · settings-order-agent | chat-desk เฉพาะเจ้าของ (X7) · auto-reply, comment-reply, chatbot ต้อง H3 (เจ้าของ+ผู้จัดการ) · order-agent เฉพาะ ONLINE (X3) |
| **SHOPS** | reviews · verification ระดับร้าน · badges · wallet · subscriptions · admins พนักงาน · line-reports | wallet และ subscriptions ซ่อนบน Android (subscriptions ยังเหลือใน iOS ซึ่งมี IAP) · admins เฉพาะร้านธุรกิจ (T2) · line-reports เฉพาะผู้ที่เป็นเจ้าของหลักของร้านใดร้านหนึ่ง |
| **SETTING** | shop ร้านค้า · public-profile ตั้งค่าหน้าร้าน · settings การจัดส่ง · settings-channels ช่องทางการขาย · settings-job-types ประเภทงาน · settings-reports ตั้งค่ารายงาน | settings เฉพาะ ONLINE · job-types และ settings-reports เฉพาะ SERVICE |

รวมปัจจุบัน ONLINE 28 รายการ, SERVICE 26, LODGING 27 และ 00078 เพิ่มอีก 1

ผมพบว่า `seller-menu.ts` ไม่มี slug `seller:settings-auto-notify` ส่วนเมนูลัดค่าเริ่มต้นคือ 8 รายการแรกของ catalog ตามลำดับ sidebar (`computeDefaultSlugs`)

## 2. ทำไมถึงดูสะเปะสะปะ

1. **ป้ายกลุ่มเป็นอังกฤษตัวพิมพ์ใหญ่ในแอปไทย**
   - ป้ายคือ `ANALYTICS / MANAGE / CHAT / SHOPS / SETTING` และ `applyMenuLocale` ไม่แปลป้ายกลุ่ม
   - CSS `.menu-title` สั่ง `uppercase` + `letter-spacing:.1em` + ขนาด 0.7 เท่า
   - ขัดกับกฎ Sentence-Case และคำสั่ง "ภาษาไทยเรียบง่าย ลด jargon" ของ PRODUCT.md
   - "SHOPS" กับ "SETTING" และแท็บมือถือ "ร้านค้า" แยกความหมายกันไม่ออก
2. **หน้าตั้งค่ากระจายอยู่ 3 กลุ่ม**
   - CHAT มีงานจริง 2 รายการ (ข้อความ, โต๊ะแชท) ปนหน้าตั้งค่า 4 หน้า
   - SETTING มีหน้าตั้งค่า 4–5 หน้า
   - ตั้งค่ารายงานอยู่ใน SETTING แต่ "รายงานเข้ากลุ่ม LINE" อยู่ SHOPS
3. **SHOPS เป็นถังรวม**: ชื่อเสียงร้าน (รีวิว, ระดับร้าน, ความสำเร็จ) ปนกับเงิน/แพ็กเกจ (กระเป๋า, แพ็กเกจ), ทีม (พนักงาน) และรายงาน (LINE)
4. **ลำดับไม่ตามความถี่ใช้งาน**
   - รายงาน (ANALYTICS) ขึ้นก่อนงานประจำวัน แต่แถบล่างมือถือวางคำสั่งซื้อและแชทมาก่อน
   - ใน MANAGE "การประมูล" มาก่อน "สินค้า" และ "ค่าใช้จ่าย" ซึ่งเป็นการเงินเจ้าของอย่างเดียวไปอยู่กับงานประจำวัน
5. **4 หน้าตั้งค่าเรื่อง "อัตโนมัติ" อยู่ปนกัน** (ตอบกลับอัตโนมัติ, ผู้ช่วยอัตโนมัติ, สร้างออเดอร์จากแชท และ 00078 จะเพิ่มอีกหน้า) ต้องมีหัวกลุ่มที่บอกบริบท
6. **ต่าง vertical กลุ่มบวมไม่เท่ากัน**: MANAGE ของ LODGING มี 9 รายการ ส่วน SETTING ของ LODGING มีแค่ 3

## 3. โครงใหม่ที่เสนอ (7 กลุ่ม ป้ายภาษาไทย)

หลักที่ใช้: งานประจำวันขึ้นก่อน, หน้าตั้งค่าอยู่ท้ายสุดติดกัน, ทุกกลุ่มไม่เกิน 6 รายการในทุก vertical, **ไม่เปลี่ยน URL และไม่เปลี่ยน slug ของรายการ** (เมนูลัดที่ผู้ใช้ปักไว้ยังอยู่ครบ)

| # | กลุ่ม | รายการตามลำดับ |
|---|---|---|
| 1 | **งานประจำวัน** | ภาพรวมร้านค้า → คำสั่งซื้อ/งานบริการ/บิลเข้าพัก → ตารางงาน → การจอง → ปฏิทินการจอง → สินค้า → จัดการสต็อก → การประมูล → ห้องพัก → แม่บ้าน |
| 2 | **แชทและลูกค้า** | ข้อความ → โต๊ะแชท → ลูกค้า → ติดตามลูกค้า → การตอบแชทของแอดมิน |
| 3 | **รายงานและการเงิน** | ภาพรวมกำไร/ขาดทุน (การเงินร้าน) → ค่าใช้จ่าย → ยอดขายรายสินค้า → รายงานเข้ากลุ่ม LINE |
| 4 | **ความน่าเชื่อถือ** | รีวิว → ระดับร้าน → ความสำเร็จ → แผนการตรวจสอบ |
| 5 | **ตั้งค่าแชท** | ช่องทางการขาย → ตอบกลับอัตโนมัติ → ตอบกลับคอมเมนต์ → **ส่งอัตโนมัติถึงลูกค้า** → สร้างออเดอร์จากแชท → ผู้ช่วยอัตโนมัติ |
| 6 | **ตั้งค่าร้าน** | ร้านค้า → ตั้งค่าหน้าร้าน → การจัดส่ง → ประเภทงาน → ตั้งค่ารายงาน |
| 7 | **ทีมและแพ็กเกจ** | พนักงาน → แพ็กเกจของฉัน → กระเป๋าเงิน |

ในกลุ่ม 5 ผมเรียง "ผู้ช่วยอัตโนมัติ" (ใช้ AI มีค่าใช้จ่าย) ไว้ท้ายสุด ตามเจตนาเดิมในโค้ดที่ให้ของฟรีมาก่อน

**`/settings/auto-notify` อยู่ที่ไหน:** กลุ่ม 5 "ตั้งค่าแชท" ลำดับที่ 4
- slug ใหม่ `seller:settings-auto-notify`
- ไอคอน `send` ตาม spec ของ 00078 (ยังไม่ได้ยืนยันชื่อในชุด tabler)
- ไม่ใส่ในลิสต์ `*_ONLY_SLUGS` เลย เพราะเห็นทุก vertical
- PRD Q-26 เขียนว่า "กลุ่มเมนู CHAT" ต้องแก้ถ้อยคำให้ตรง

### การตัดสินใจที่ควรให้ user เคาะ (ผมย้ายของที่โค้ดเดิมเขียนเหตุผลไว้)

- **ลูกค้า / ติดตามลูกค้า ย้ายจาก MANAGE ไป "แชทและลูกค้า"** คอมเมนต์เดิมตั้งใจให้ "ลูกค้า" อยู่ MANAGE เพราะเป็นทะเบียนที่ใช้ตอนเปิดบิล แต่ตอนนี้เมนูลูกค้ากับติดตามลูกค้าอยู่ติดกับข้อความ และบทบาท CHAT/BILLING เห็นลูกค้าเหมือนกัน ถ้าไม่เห็นด้วยให้คืนไป "งานประจำวัน" แล้วกลุ่มนั้นจะเป็น 6–8 รายการ
- **"การตอบแชทของแอดมิน" ย้ายจาก ANALYTICS ไป "แชทและลูกค้า"** ถ้าคงไว้ใน "รายงานและการเงิน" ผู้จัดการ/แอดมินแชทจะเห็นกลุ่มการเงินที่มีรายการเดียวที่ไม่ใช่เรื่องเงิน การย้ายทำให้กลุ่ม 3 เป็นของเจ้าของล้วน
- **"ช่องทางการขาย" ย้ายจาก SETTING ไป "ตั้งค่าแชท"** เพราะเป็นขั้นแรกที่ต้องเชื่อมก่อนจะตั้งตอบกลับอัตโนมัติได้

### ความเสี่ยงต่อ App Store (hidePayments / hidePaidFeatures)
- การกรองยึด slug ไม่ยึดกลุ่ม ลำดับ `applyInventoryGate → applyPaymentRestriction → applyCapabilityMenu → ...` ไม่เปลี่ยน และมีเทส blocker ยึดอยู่ จึงไม่แตะลำดับนี้
- ไม่มี slug ที่ถูกซ่อนเพราะข้อจำกัดของแอปถูกย้ายไปกลุ่มที่เห็นต่างกัน
- กลุ่ม "ทีมและแพ็กเกจ" บน Android เหลือแค่ "พนักงาน" ถ้าเป็นร้านส่วนตัวกลุ่มจะว่างและต้องหายไปทั้งกลุ่ม ตอนนี้ `applyCapabilityMenu` ถอดกลุ่มว่างได้ก็ต่อเมื่อกลุ่มยังมีรายการก่อนถูกกรอง
- กลุ่ม "รายงานและการเงิน" ไม่มีรายการไหนผูก `hidePayments` (line-reports ยกเว้นโดยตั้งใจ)
- **ข้อเสนอเสริม:** เติมการถอดกลุ่มว่างที่ท้าย `resolveVisibleSellerMenu` พร้อมเทส 1 ข้อ กันหัวกลุ่มลอยเปล่าเมื่อมีใครย้ายรายการในอนาคต ปัจจุบัน `applyPaymentRestriction`, `applyVerticalMenu` และ `applyFinanceMenu` ไม่ถอดกลุ่มว่างเอง

### Anti-slop self-check
1. **เฉพาะ Deep:** มีกลุ่ม "ความน่าเชื่อถือ" (รีวิว, ระดับร้าน, ความสำเร็จ, แผนการตรวจสอบ) ซึ่งเป็นแก่นของ Deep และแยกกลุ่ม "ตั้งค่าแชท" ตามชุดฟีเจอร์แชทที่มีจริง
2. **พระเอกต่อหน้าจอ:** "งานประจำวัน" ขึ้นบนสุด กลุ่มอื่นเป็นรอง
3. **ตัดของซ้ำ:** ไม่เพิ่มรายการหรือกลุ่มที่ไม่ทำงาน; กลุ่มที่สิทธิ์น้อยแล้วว่างจะถูกถอดอัตโนมัติ
4. **State:** กลุ่มว่าง, vertical ที่ไม่รู้จัก (fail-closed ตามเดิม), iOS/Android ถูกครอบคลุมแล้ว ส่วนป้ายยาวผิดปกติในแถบ rail ที่หุบอยู่ ยังไม่ได้ตรวจ
5. **Copy:** ป้ายกลุ่มบอกชนิดงานตรง ๆ ("ตั้งค่าแชท" = หน้าตั้งค่า ไม่ใช่งานที่ทำทุกวัน)
6. **คำเดียวกันหมายถึงของเดียวกัน:** ยังเหลือ "ร้านค้า" ที่เป็นทั้งรายการเมนู (`/shop`) และแท็บล่างมือถือ แต่ไม่ใช่ป้ายกลุ่มอีกต่อไป
7. **สี:** ไม่มีการเปลี่ยนสีใด
8. **แตะบนมือถือ:** ไม่เปลี่ยน เพราะ sidebar ซ่อนอยู่
9. **จอ 1440:** sidebar เต็มแนวตั้งด้วย 29 รายการ + 7 หัวกลุ่ม ไม่มีคอลัมน์ว่างเพิ่ม
