ห้องแชทผู้ขาย — 3 แบบที่แก้ไข

prototype · 2026-08-15 · ของทิ้ง · ทุกแบบผ่าน Design Spec ของ safepay-ux แล้ว
ทั้ง 3 แบบแก้เหมือนกันหมด — ตัดชิป token ที่ซ้ำกับบล็อกล่างบน LINE · แยก "label สั้น" ออกจาก "ประโยคเต็ม" (ต้นเหตุจริงของชิปที่ถูกตัด) · merge ที่มา 2 อันเป็นก้อนเดียว · นับถอยหลังย้ายลงจากหัวและนับเป็นนาที · แสดง attachmentUrl + createdTime ที่เคยถูกทิ้ง · ซ่อนบรรทัดอังกฤษของ Meta เฉพาะชนิด comment-reply · ลบปุ่ม ✕ ปิดโฆษณาถาวร

ต่างกันที่รูปทรง: ของพวกนี้ควรเป็น แถบซ้อนกัน · การ์ดเดียว · หรือ อยู่ในสตรีมตามลำดับเวลา
จอซ้าย = เคสของครบ (AI ถือห้อง + ใกล้หมดเวลา + ที่มา 2 อัน + ลูกค้าใหม่) จอขวา = เคสปกติ

A แถบซ้อนกัน — แต่ละเรื่องมีแถบของตัวเอง

3 ชั้นแยกกันชัด เรียงตามระดับบังคับอ่าน: คำเตือน (พื้นสี มีปุ่ม) → ที่มาของแชท (พื้นขาว มีรูป) → บริบทลูกค้า (จาง บรรทัดเดียว) · ชั้นไหนไม่มีของก็ไม่ render เลย

ได้

  • ลำดับความสำคัญอ่านจากบนลงล่างได้ทันที ไม่ต้องตีความ
  • แต่ละชั้นหายได้อิสระ — เคสปกติเหลือ บรรทัดเดียว 26px
  • ใกล้โครงเดิมที่สุด ทยอยแก้ทีละชั้นได้ ไม่ต้องรื้อพร้อมกัน

เสีย

  • เคสของครบมี เส้นคั่นเต็มจอ 3 เส้นซ้อนกัน — ดูเป็นชั้น ๆ เยอะ
  • ทุกแถบกว้างเท่ากันหมด ไม่มีอะไรบอกว่าอันไหน "ของลูกค้ารายนี้" อันไหน "ของระบบ"
เคสของครบ 184pxเคสปกติ 92px

B การ์ดเดียว — ทุกอย่างอยู่ในกล่องเดียวใต้หัว

ของทั้ง 3 ชนิดยุบเข้า การ์ดใบเดียว ที่ลอยอยู่ใต้หัวเธรด (มีขอบ มีเงา มีระยะห่างรอบ) — สื่อว่า "นี่คือข้อมูลของลูกค้ารายนี้ทั้งก้อน" แยกจากตัวแอปด้วยสายตา

ได้

  • แยก "ของลูกค้ารายนี้" ออกจาก "ของแอป" ได้ในภาพเดียว
  • ไม่มีเส้นคั่นเต็มจอหลายเส้น — สงบกว่าเมื่อมีของเยอะ
  • ย้ายทั้งก้อนได้ทีหลังโดยไม่ต้องแยกชิ้น

เสีย

  • เสียความกว้าง 24px จากระยะห่างซ้าย-ขวา และสูงขึ้นจาก padding การ์ด
  • เคสปกติดูหนักเกินจริง — ข้อมูลบรรทัดเดียวถูกใส่กรอบการ์ดทั้งใบ
  • คำเตือนอยู่ในการ์ดลอย = ดูเบากว่าแถบเต็มจอ ซึ่งขัดกับความเร่งด่วนของมันเอง
เคสของครบ ~200pxเคสปกติ ~52px

C ที่มาอยู่ในสตรีมตามลำดับเวลา — เลื่อนหายได้

แยกตามอายุของข้อมูล: คำเตือน = สถานะปัจจุบัน → ตรึงเป็นแถบใต้หัว · ที่มาของแชท = เหตุการณ์ที่เกิดก่อนข้อความแรก → เป็นการ์ดใบแรกในสตรีม เลื่อนหายไปกับข้อความเก่าเมื่ออ่านต่อ · บริบทลูกค้า = แถบจางใต้หัว

ได้

  • ที่มาเลิกกินพื้นที่ถาวร — อ่านแล้วเลื่อนผ่านไปเหมือนข้อความอื่น
  • ตรงกับลำดับเวลาจริง: ลูกค้าคอมเมนต์ → แล้วจึงเกิดห้องนี้ ⇒ มันควรอยู่ก่อนข้อความแรก
  • การ์ดในสตรีมใส่เนื้อหาได้เต็มที่ (รูปแนบใหญ่ · ข้อความยาว) โดยไม่กินที่หัวจอ

เสีย

  • 🛑 เลื่อนไปแล้วหาไม่เจอ — ต้องเลื่อนกลับบนสุด ห้องที่คุยยาวจะไกลมาก
  • 🛑 ห้องแชทเปิดมาอยู่ล่างสุดเสมอ ⇒ เธรดที่คุยมานาน ผู้ขายจะไม่เห็นการ์ดนี้เลยตั้งแต่แรก
  • ต้องตัดสินว่าการ์ดอยู่ก่อนหรือหลังตัวคั่นวันที่ และจะเป็นยังไงตอนโหลดข้อความเก่าเพิ่ม
เคสของครบ 124px ตรึง + การ์ดในสตรีมเคสปกติ 92px

D ไม่มีพื้นที่กลางเลย — ทุกอย่างผูกกับจุดที่มันเกี่ยวข้อง

🛑 A/B/C ทั้งสามยืนบนสมมติฐานเดียวกันว่า "ต้องมีพื้นที่เหนือสตรีม" — แบบนี้ทิ้งสมมติฐานนั้น:
• คำเตือนที่ขวางการส่ง → บล็อกแทนช่องพิมพ์ (มีอยู่แล้ว)
• คำเตือนที่ไม่ขวาง (ใกล้หมดเวลา · ห้องทดสอบ) → แถบบางเกาะบนขอบช่องพิมพ์ ไม่ใช่บนขอบจอ — เพราะมันเกี่ยวกับการพิมพ์ครั้งถัดไป ไม่ใช่เกี่ยวกับห้อง
• ที่มาของแชท → การ์ดแรกในสตรีม (ตามลำดับเวลา)
• บริบทลูกค้า → บรรทัด 2 ของหัวเธรด สลับที่กับชื่อเพจเมื่อมีของสำคัญกว่า
⇒ เหนือสตรีมเหลือหัวเธรดอย่างเดียว 66px เสมอ ทุกสถานการณ์

ได้

  • ความสูงคงที่ 66px ไม่ว่าจะเกิดอะไรขึ้น — จอไม่กระโดดเวลามีคำเตือนโผล่
  • คำเตือนอยู่ติดนิ้วที่กำลังจะพิมพ์ ไม่ใช่อยู่ไกลบนสุดของจอ
  • ทุกอย่างมีเหตุผลว่าทำไมถึงอยู่ตรงนั้น — ไม่มี "ที่ทิ้งของ" อีกต่อไป

เสีย

  • บรรทัด 2 ต้องแย่งกันระหว่างชื่อเพจกับป้ายลูกค้า — ใส่ได้ทีละอย่าง (วัดแล้วที่ 390px มีที่ ~123px)
  • คำเตือนบนช่องพิมพ์อาจถูกมองข้ามถ้าผู้ขายไม่ได้กำลังจะพิมพ์
  • เปลี่ยนที่อยู่ของของหลายชิ้นพร้อมกัน — ผู้ใช้เดิมต้องเรียนรู้ใหม่
เหนือสตรีม 66px คงที่เท่ากันทุกสถานการณ์

E หัวเธรดพูดได้ — ใช้ที่เดิม เปลี่ยนสิ่งที่มันบอก

ไม่เพิ่มชั้นใหม่เลยแม้แต่ชั้นเดียว — หัวเธรดเปลี่ยนตัวเองตามสถานการณ์:
• ปกติ: บรรทัด 2 = ชื่อเพจ · พื้นขาว
• มีเรื่องต้องรู้: พื้นหัวเปลี่ยนเป็นสีเตือน + บรรทัด 2 กลายเป็นคำเตือน + ปุ่มจัดการ
• ที่มาของแชท + บริบทลูกค้า → อยู่หลังการแตะกลุ่มชื่อ (เปิดแผงลูกค้า)

ได้

  • 66px เสมอ และไม่มีชั้นใหม่ให้เรียนรู้ — ที่เดิมทุกอย่าง แค่เปลี่ยนเนื้อ
  • สีพื้นทั้งแถบเห็นชัดกว่าชิปเล็ก ๆ มาก — มองปราดเดียวรู้ว่าห้องนี้มีเรื่อง
  • แก้ง่ายที่สุดในทุกแบบ — แตะไฟล์เดียว ไม่สร้าง component ใหม่

เสีย

  • 🛑 ได้ทีละเรื่องเดียว — มี 3 คำเตือนพร้อมกันต้องเลือกอันเดียวมาโชว์ ที่เหลือหายไปหลังการแตะ
  • ที่มาของแชทหายจากจอ ⇒ ย้อนสิ่งที่ ux ตัดสินไว้ ("ต้องรู้ก่อนตอบ ไม่ใช่อ้างอิงเมื่อสงสัย")
  • ชื่อเพจหายเมื่อมีคำเตือน — ผู้ขายหลายเพจจะไม่รู้ว่ากำลังตอบในนามเพจไหน
เหนือสตรีม 66px คงที่ไม่มี component ใหม่

F แผงเดียวหลังปุ่ม — ซ่อนทั้งหมด กดดูเมื่อต้องการ

หัวเธรดมีปุ่มสถานะเดียว (จุดสีบอกว่ามีเรื่อง) กดแล้วกางแผงเดียวที่รวมทุกอย่าง: คำเตือนทุกอัน · ที่มาของแชท · บริบทลูกค้า — เรียงตามความสำคัญในแผงเดียว
สิ่งที่ยังขวางจริง (AI ถือห้อง / token ตาย) ยังบล็อกที่ช่องพิมพ์เหมือนเดิม ไม่ซ่อน

ได้

  • 66px เสมอ และจอสะอาดที่สุดในทุกแบบ
  • ของเยอะแค่ไหนก็ใส่ได้หมด — แผงเลื่อนได้ ไม่มีอะไรถูกตัดคำ
  • ผู้ขายที่รู้อยู่แล้วว่าห้องนี้มีอะไร ไม่ต้องเห็นซ้ำทุกครั้งที่เปิด

เสีย

  • 🛑 คำเตือนกลายเป็นจุดสีจุดเดียว — "ใกล้หมดเวลา" กับ "ลูกค้าปิดรับข้อความ" หน้าตาเหมือนกันจนกว่าจะกด
  • ที่มาของแชทต้องกด 1 ครั้งถึงเห็น — ย้อนมติ ux เหมือนแบบ E
  • ของที่ต้องรู้ก่อนตอบ ถูกวางไว้หลังการกระทำ = ผู้ขายที่รีบจะไม่กด
เหนือสตรีม 66px คงที่ทุกอย่างอยู่หลัง 1 แตะ
