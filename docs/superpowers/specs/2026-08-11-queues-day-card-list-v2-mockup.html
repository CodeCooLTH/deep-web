4 · งานฝั่งข้อมูล — 3 อย่างนี้ไม่มีใน payload วันนี้เลยสักตัว

วิธีที่ผมเสนอ: แยกเป็น 2 คำขอ ไม่ใช่ยัดทุกอย่างลงคำขอเดิม

ตอนนี้ AppointmentMonthBoard ยิง GET /api/shops/current/appointments?from=&to= ครั้งเดียวครอบทั้งเดือน แล้วกรองวันที่จิ้มในเครื่อง — ถ้าเติมเบอร์+รูป+ช่องทางลงคำขอเดิม จะได้ เบอร์ลูกค้าทั้งเดือน (อาจ 100–200 เบอร์) นอนอยู่ใน flight payload เพื่อแสดงวันเดียว

คำขอได้อะไรทำไม
เดือน (ของเดิม ไม่แตะ)นับจำนวนนัดต่อวัน ลงจุดในปฏิทิน — ไม่มีเบอร์ ไม่มีรูป เหมือนเดิมทุกประการปฏิทินต้องการแค่ตัวเลข · TFR-010 ข้อ 1–2 ยังบังคับได้เต็ม
รายวัน (ใหม่)เฉพาะวันที่จิ้ม: buyerContact · avatarUrl · ช่องทาง+ชื่อเพจ · conversationIdเบอร์อยู่ใน payload ครั้งละ 1 วัน ไม่ใช่ 1 เดือน · และรูป/ช่องทางเป็น join ที่แพงเกินจะดึงทั้งเดือนอยู่แล้ว
  • ต้องแก้เอกสารพร้อมกัน — TFR-010 บรรทัด “ปฏิทินต้องการแค่ชื่อย่อ + เลขออเดอร์ ไม่ต้องการเบอร์” กลายเป็นเท็จทันทีที่ merge · ถ้าไม่แก้ คนอ่านคนถัดไปจะเจอเอกสารที่ขัดกับโค้ด แล้วไม่รู้ว่าอันไหนถูก
  • ยังไม่ส่งอีเมล — ไม่มีจอไหนขอ · ตัดออกที่ server ตามกฎเดิม
  • เส้นทางของรูป: Order.customerId → Customer.externalContacts[] → avatarUrl โดย scope ด้วย Order.shopChannelId (PSID เป็น page-scoped — ห้าม dedup ข้ามเพจ ตาม @@unique ในสคีมา) · ยังไม่มี helper ตัวไหนทำเส้นทางนี้ ต้องเขียนใหม่
  • ปุ่ม “ทักแชท” ต้องได้ conversationId มาด้วย ไม่งั้นกดแล้วไปไม่ถูกห้อง — ถ้าไม่อยากทำรอบนี้ ให้ตัดปุ่มออก อย่าปล่อยให้ลิงก์ไปหน้ารวม

ยังไม่ได้พิสูจน์

  • ยังไม่ได้กดจริงสักครั้ง — ตัวที่ภาพนิ่งตอบไม่ได้: ปุ่ม “โทร” กับพื้นที่กดทั้งใบทับกันตรงไหน (การ์ดทั้งใบเปิดออเดอร์ แต่ในใบมีปุ่มอีก 3 ปุ่ม = ต้องกัน event ให้ครบ), เมนู ⋯ ของใบล่างสุดเด้งทะลุขอบจอไหม
  • ยังไม่ผ่าน safepay-ux (HR8) — session นี้ห้ามเรียก subagent ผมอ่าน design.json + theme source เอง
  • สัดส่วนรูปจริง/ตัวย่อในเฟรม เดาจากชื่อในภาพหน้าจอ (Latin script = น่าจะมาจาก Messenger) — ยังไม่ได้ query ว่าร้านนี้มีนัดจากช่องทางไหนกี่ใบจริง ๆ
