4 เรื่องที่ท่านี้ต้องแก้ให้ได้ ไม่งั้นมันจะแย่กว่าของเดิม

  1. 🛑 iOS/WebView ยึด “ปัดขวาจากขอบซ้าย” ไว้เป็นปุ่มย้อนกลับอยู่แล้ว — คนที่เริ่มนิ้วตรงขอบจะ ออกจากหน้า แทนที่จะได้วันก่อนหน้า ⇒ ลูกศร ‹ › ไม่ใช่ของแถม มันคือทางที่ทำงานได้เสมอ และเป็นทางเดียวที่ผู้ใช้คีย์บอร์ด/screen reader มี (ปัดไม่มี affordance ให้ AT เลย)
  2. 🛑 ปุ่ม back ของเครื่องจะปิดแอป ไม่ใช่ปิดชีต ถ้าชีตเป็น React state ล้วน — ผู้ขายที่ใช้ผ่านแอป จะกด back หวังปิดชีตแล้วหลุดออกจากหน้าคิวงานทั้งหน้า ⇒ ต้องผูก history.pushState ตอนเปิด แล้วปิดชีตเมื่อ popstate (ข้อนี้คนลืมบ่อยที่สุดและไม่มี gate ไหนจับได้)
  3. 🛑 ชีตประกอบเองด้วย React state = ต้องเรียก useLockBodyScroll + ทุก overflow-y-auto ข้างในต้องมี overscroll-contain — ไม่งั้นลากนิ้วในชีตแล้ว หน้าข้างหลังถูกดึงจนเนื้อหาหลุดกรอบ (เกิดมาแล้ว 11 ใบในรอบเก็บตก 2026-08-07)
  4. 🛑 แกนชนกันเอง — ในชีตต้องเลื่อนขึ้นลงอ่านรายการ และปัดซ้ายขวาเปลี่ยนวัน ⇒ ต้อง axis lock แบบเดียวกับ SwipeableRow (ล็อกแกนหลังนิ้วขยับ 6px แล้วไม่เปลี่ยนแกนอีกจนปล่อย)

3 ทางเข้า ผลเหมือนกันปัด · กด ‹ › · จิ้มวันบนแถบสัปดาห์ (แบบ B) — ทั้งสามต้องเรียกฟังก์ชันเดียวกัน ไม่ใช่ต่างคนต่างเขียน (บทเรียน “ตัวเลขเดียวกันต้องมาจาก symbol เดียว”)
ทิศทางปัดซ้าย = วันถัดไป (เนื้อหาเลื่อนตามนิ้ว) · ปัดขวา = วันก่อนหน้า — ทิศเดียวกับปฏิทินทุกตัวที่ผู้ใช้เคยใช้
ข้ามเดือนปัดในเดือนเดียวกัน = ไม่ยิง API (ข้อมูลทั้งเดือนอยู่ในเครื่องแล้ว) · ปัดข้ามขอบเดือน = ยิงเดือนใหม่ + ปฏิทินข้างหลังต้องเปลี่ยนเดือนตามด้วย ไม่งั้นปิดชีตแล้วเจอเดือนเก่า = จอเดียวขัดกันเอง
ระหว่างโหลดเดือนใหม่ใช้ skeleton ของเดิม ห้ามขึ้น “ว่างทั้งวัน” (กฎที่ AppointmentMonthBoard เขียนไว้เองแล้ว) และห้ามค้างรายการของวันก่อนหน้าไว้เฉย ๆ
วันว่างติดกันปัดผ่านวันว่างได้ตามปกติ — ตัวนับในหัวชีตบอกทันทีว่า “0 นัด” · ห้ามให้ลูกศรกระโดดข้ามวันว่าง (ลูกศรที่เดินไม่เท่ากันทุกครั้ง = ผู้ใช้เลิกเชื่อว่ามันคือ “วันถัดไป”)
ขอบเขตไม่ตัน — เดินไปข้างหน้า/ถอยหลังได้เรื่อย ๆ ข้ามปีก็ได้ · ‹ › จึงไม่มีสถานะ disabled
ประกาศให้ AT รู้หัวชีตต้องเป็น aria-live="polite" — ปัด/กดลูกศรแล้วเนื้อหาเปลี่ยนยกแผง ผู้ใช้ screen reader ต้องได้ยินว่าตอนนี้เป็นวันไหนและกี่นัด (ของเดิมมี live region อยู่แล้ว ยกมาใช้ต่อ)

การเปิด/ปิดชีต

  • ความสูง = เต็มจอ รวมหัวแอป (user เคาะ) — ในโค้ดคือ fixed inset-0 + z-80 (token เดียวกับ OrderQrSheet/AccountSwitcherSheet) และ 🛑 ต้อง padding-top: env(safe-area-inset-top) ไม่งั้นหัวชีตไปนอนใต้รอยบาก/แถบสถานะ (โปรเจกต์เปิด viewport-fit=cover ไปแล้วเมื่อ 2026-08-06 ค่านี้จึงคืนค่าจริง ไม่ใช่ 0)
  • เปิด: จิ้มวันในปฏิทิน — วันเดิมที่จิ้มซ้ำก็เปิด (ไม่ toggle ปิด เพราะผู้ใช้จะงงว่าทำไมกดแล้วไม่ขึ้น)
  • 🛑 ปิด: ปุ่ม ✕ คือทางออกเดียวที่มองเห็น — เมื่อทับหัวแอปแล้ว ปุ่มเมนู/ชื่อหน้าหายไปด้วย ไม่มีฉากมืดให้แตะ และไม่มีขอบปฏิทินโผล่ให้เดา ⇒ ✕ ต้อง ซ้ายสุดในระยะนิ้วโป้ง ขนาด 44px และมีพื้นอ่อนรองให้เห็นว่ากดได้ (ไอคอนลอย ๆ บนพื้นขาวอ่านเป็นของตกแต่ง)
  • ปิดได้อีกทาง: ปุ่ม back ของเครื่อง (ดูข้อถัดไป) · ลากลงจากหัวชีต — ทางเลือก ไม่บังคับ แต่ถ้าทำต้องระวังชนกับการเลื่อนอ่านรายการ (แกนเดียวกัน)
  • 🛑 ปุ่ม back ต้องปิดชีต ไม่ใช่ออกจากหน้า — history.pushState ตอนเปิด + ฟัง popstate · ถ้าไม่ทำ ผู้ขายที่ใช้ผ่านแอปจะกด back หวังปิดชีตแล้วหลุดออกจากหน้าคิวงานทั้งหน้า
  • เปิดหน้ามาครั้งแรก ชีตเปิดอยู่ไหม? — ผมเสนอ เปิดที่ “วันนี้” เลย เพราะคำถามแรกของทุกเช้าคือ “วันนี้มีใครบ้าง” ไม่ใช่ “เดือนนี้หน้าตาเป็นยังไง” · ของเดิมก็ตั้งต้นที่วันนี้อยู่แล้ว (selectedKey = today)
