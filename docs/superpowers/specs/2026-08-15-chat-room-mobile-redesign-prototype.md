## 3. สามแบบ — ต่างกันที่ "ของที่ไม่ใช่ข้อความ ไปอยู่ที่ไหน"

| แบบ | หลักการ | chrome เหนือสตรีม | ที่อยู่ของสถานะ |
|---|---|---|---|
| **A** ยุบเป็นบรรทัดเดียว | จอเป็นของบทสนทนา — ทุกอย่างอื่นยุบเหลือบรรทัดสรุป 1 บรรทัด กดกางเป็นแผงเต็ม | **คงที่ 71px** ทุกสถานการณ์ | แผงกางจากบนสุด |
| **B** ละลายเข้าสตรีม | ห้องแชทมี **พื้นผิวเดียว = สตรีม** ที่มา/บริบทเป็นการ์ดตามลำดับเวลา คำเตือนปักท้าย | **66px** ไม่มีชั้นซ้อน | การ์ดในสตรีม + แถบปักท้าย |
| **C** แยกสองพื้นผิว | แยก **"คุย"** ออกจาก **"งาน"** — จอแชทสะอาดล้วน งานอยู่ในลิ้นชักโผล่หัว 33px | **66px** | ลิ้นชักเหนือช่องพิมพ์ |

แต่ละแบบมี 4 เฟรม: `320px ของครบ` · `390px ของครบ` · `430px ของครบ + สถานะที่สอง` · `390px ปกติ`
(3 ความกว้างตาม `feedback_mockup_3_devices` — มือถือทั้งหมดตามขอบเขต)

### A — ยุบเป็นบรรทัดเดียว

หัวเธรดหด **44px** · ทุกอย่างลงมาอยู่ในบรรทัดสรุป **27px** ที่อ่านซ้าย→ขวา: *ต้องแก้ก่อน → ลูกค้าเป็นใคร → มาจากไหน* · แตะแล้วกางแผงจัดกลุ่ม **ต้องลงมือ / ลูกค้ารายนี้ / ที่มาของแชท** · คำเตือนที่ **ขวางการส่งจริง** ไปเกาะขอบช่องพิมพ์แทน

- **ได้:** เหนือสตรีม **71px คงที่** — คำเตือน 0 หรือ 4 อันสูงเท่ากัน เลย์เอาต์ไม่กระโดด (K = 3 แถบซ้อน ~93px) · สตรีมได้ที่มากที่สุด ~452px · แผงมีที่ให้ **ประโยคเต็ม** จึงแก้ปัญหาชิปถูก `truncate` จนไร้ความหมาย
- **เสีย:** 🛑 **คำเตือนถูกลดชั้นเป็นตัวเลข** — "บอทหยุดตอบ" ไม่มีถ้อยคำบนจอจนกว่าจะกด · +1 แตะสำหรับทุกอย่าง · **ชื่อเพจหายจากหัวเธรด** ซึ่งย้อนมติ §5.5 ที่เพิ่งตัดสินไป

### B — ละลายเข้าสตรีม

ไม่มีชั้น chrome ใต้หัวเลย · **ที่มาของแชท = การ์ดใบแรกในสตรีม** ตามเวลาจริง พร้อม**รูปที่ลูกค้าแนบมากับคอมเมนต์** · ของที่ยังจริงอยู่ (คำเตือน) **ปักท้ายสตรีมเหนือช่องพิมพ์** ซึ่งเป็นที่ที่ตาอยู่เสมอ

- **ได้:** **ไม่ต้องประดิษฐ์ pattern ใหม่นอกธีมเลยสักอัน** · ที่มาได้เต็มกว้าง อ่านได้ว่าลูกค้าคอมเมนต์ว่าอะไร · **ที่มา 2 อันไม่ชนกัน** (การ์ด 2 ใบ ไม่ใช่ชิป 2 อันแย่งแถวเดียว) · ไม่มีอะไรถูกตัดเลย
- **เสีย:** **ที่มาหาไม่เจอเมื่อเลื่อนพ้นไปแล้ว** (เฟรม 430px แสดงเคสนี้) · คำเตือนปักท้ายกิน **พื้นที่สตรีมจริง** ~93px · การ์ดบริบทปนกับข้อความจริง

### C — แยกสองพื้นผิว

จอแชทสะอาดล้วน · ของ 57 ชนิดย้ายไปลิ้นชัก **"งาน"** ที่โผล่หัวมา **33px** แสดงเรื่องเร่งที่สุดเรื่องเดียวพร้อมสีของมัน · กางแล้วเจอคำเตือน + ออเดอร์ + คลังไฟล์ + ข้อมูลลูกค้า + ที่มา เป็น **ทางเข้าเดียว ไม่ใช่ 5 ทาง**

- **ได้:** หัวเธรดกลับไปทำหน้าที่เดียว **ชื่อได้ ~200px @390** (แบบ E ได้ 122.8px) · สิ่งเร่งด่วนอยู่ติดนิ้วที่กำลังจะพิมพ์ · **ออเดอร์เหลือ 1 แตะ + เห็นตัวเลข** — ตอบ feedback ลูกค้าจริง *"ลูกค้าที่ใช้บนมือถือส่วนใหญ่เน้นดู Order lists"* ได้ตรงที่สุด
- **เสีย:** ลิ้นชักกินที่ถาวร 33px แม้ไม่มีอะไรต้องทำ · เรื่องที่ 2-3-4 มองไม่เห็นจนกว่าจะกาง (แย่กว่า A ที่อย่างน้อยบอกจำนวน) · **ลิ้นชักลากได้ยังไม่มีในธีม** และท่าลากชนกับการเลื่อนสตรีม · ที่มาถูกฝังลึกที่สุด

## 3.5 🛑 user เคาะ **B** แล้วสั่งแก้ → **B2** (ค่าตั้งต้นของม็อกอัพแล้ว)

> *"แบบ B ดีปะ แต่ตรงรายการด้านล่าง เวลามันมีปัญหา (พวกสีแดงๆ) ให้ขึ้นว่า สถานะห้องแชท (3) กดแล้ว slide up ดู lists ได้ ไม่ต้องเอาพวก ข้อมูลคำสั่งซื้อหรือรูปอะไรไปรวม แต่ผมอยากให้ลองใส่ chat ที่มี order กำลังจัดส่ง"*

### ออเดอร์กำลังจัดส่ง — แยกเป็นแถบของตัวเอง

🛑 **ไม่ได้ยุบรวมเข้าแผงสถานะ และไม่ใช่แค่เพราะ user สั่ง — โค้ดจริงเห็นด้วย.**
`OrderProgressBar.tsx` เขียนคอมเมนต์ไว้เองว่า *"แถบนี้เป็นทางลัดดูสถานะ **ไม่ใช่ alert** — โทน primary ไม่ใช่ warning/danger"*
⇒ ยุบพัสดุไปกองเดียวกับ "token ตาย" คือพารถบรรทุกไปอยู่กองเดียวกับของพัง ซึ่งโค้ดจริงตั้งใจเลี่ยงมาตั้งแต่ต้น

ท้ายสตรีมจึงมี **2 แถบยุบที่แยกกันด้วยสีและคำ**: พัสดุ (info = ข้อมูล) · สถานะ (danger = ต้องลงมือ)

### ที่ต้องตัดสินต่อใน B2

1. คำเตือนระดับ **danger ที่ขวางการส่งจริง** (token ตาย/โควตาหมด) ควรดันข้อความขึ้นมาบนแถบเลยไหม — ตอนนี้ทำเท่ากันหมด

### ทำไมไฟล์ HTML ทำ "CSS เดียวกันเป๊ะ" ไม่ได้ (พิสูจน์แล้ว ไม่ใช่ข้ออ้าง)

| อุปสรรค | หลักฐาน |
