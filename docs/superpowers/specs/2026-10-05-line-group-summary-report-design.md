# Design Spec: 00068 LINE Group Summary Report (รายงานเข้ากลุ่ม LINE)

> ผู้ออก: `safepay-ux` (2026-10-05) · mockup: [`2026-10-05-line-group-summary-report-mockup.html`](2026-10-05-line-group-summary-report-mockup.html) (3 จอ: 375 / 768 / 1180)
> Surface: Paces seller `(paces)/seller/(dashboard)/business/line-reports/**`
> อ่านแล้ว: PRODUCT.md, DESIGN.md, `.impeccable/design.json`, impeccable shape/operate/craft-floor, `paces-component-reference.md`, หน้าพี่น้อง `/business`, `QuotaUsageCard`, `LockedStateBanner`, `settings/ai` + `AiSettingForm`, `settings/channels/LineChannelCard`, `settings/auto-reply/order-agent/OrderAgentClient`, `FinanceVisibilityToggle`, mockup 00061, `docs/conventions/seller-action-placement.md`

## สรุปการตัดสินใจหลัก

1. **IA = list → หน้า detail แยก route** (ไม่ทำ list+detail หน้าเดียว)
2. **พระเอกแต่ละหน้า:** detail = พรีวิวข้อความที่จะไปโผล่ในกลุ่ม LINE (คอลัมน์ขวา sticky บนเดสก์ท็อป) · bind = โค้ด `ผูก 482913` · list = สถานะ "รายงานจะถึงกลุ่มไหม" ต่อแถว
3. **บันทึกอัตโนมัติทุกตัวควบคุม** แบบ `OrderAgentClient` (PATCH ทันที, revert + `pacesToast.error` เมื่อล้ม) ไม่มีปุ่มบันทึก · ปุ่ม primary เดียวของหน้า detail = "ส่งทดสอบ" ใน action-bar
4. **ไม่ใช้เขียว LINE เป็นพื้นหรือปุ่ม** ใช้แค่โลโก้จริง `/images/logos/line.svg` (แบบ `LineChannelCard`) — เขียวใน Deep = ยืนยันแล้ว (Verified-Means-Green)
5. **ไม่มี wizard stepper component** — รายการ 3 ขั้นแนวตั้งในการ์ดใบเดียว ตามแบบ `LineConnectWizard`

## User stories

- **S1** เจ้าของที่มี Business Package ACTIVE ผูกกลุ่ม LINE ของทีมกับบอท "Deep รายงานยอด" ให้ยอดไปถึงทีมโดยไม่ต้องเปิดแอปดูทีละร้าน
- **S2** เลือกว่ากลุ่มนี้เห็นร้านไหน (สาขาเดียว / รวมหลายร้าน)
- **S3** ตั้งเวลารายวัน (≤4 เวลา) และรายเดือน (วันตัดรอบ) โดยไม่ต้องคำนวณช่วงวันที่ในหัว
- **S4** คุมว่าตัวเลขไหนขึ้นในกลุ่ม โดยเฉพาะ "กำไร"
- **S5** เห็นตัวอย่างข้อความก่อนส่ง + กดส่งทดสอบได้
- **S6** รู้ทันทีเมื่อรายงานส่งไม่ถึง (บอทถูกนำออก / แพ็กเกจหมด / ส่งล้ม) พร้อมทางแก้
- **S7** รู้ว่าพิมพ์ `สรุปวันนี้` / `สรุปเดือนนี้` ในกลุ่มได้
- **S8** ผู้ยังไม่มีแพ็กเกจเข้าใจว่าฟีเจอร์คืออะไรและทำไมใช้ไม่ได้

## IA

```
/business                           (เดิม) เพิ่มแถวลิงก์ "รายงานเข้ากลุ่ม LINE" ใต้ QuotaUsageCard
/business/line-reports              list (+ empty + locked)
/business/line-reports/new          ผูกกลุ่ม ขั้น 1–2 (ยังไม่มี record)
/business/line-reports/[groupId]    PENDING → ขั้น 2–3 (โค้ดวิ่งอยู่)
                                    BOUND / BOT_REMOVED / PAUSED → ตั้งค่า + พรีวิว + ประวัติ
```

เหตุผล:
1. detail มีฟอร์ม 4 ชุด + พรีวิว + ประวัติ ที่ 375 ต้องเป็นหน้าเต็ม — drawer/โมดัลคือของที่ Operate mode เตือน
2. ตรงกับหน้าพี่น้อง `settings/auto-reply` (list → `[id]` → `new`) และ `business/[shopId]/invites`
3. deep link ได้ (แจ้งเตือน "บอทถูกนำออก" ชี้ตรงกลุ่ม)
4. PENDING ใช้ `[groupId]` เดียวกับ BOUND — แถว "รอผูก" คลิกกลับไปดูโค้ดที่วิ่งอยู่ได้ และเปลี่ยนเป็นหน้าตั้งค่าเองเมื่อผูกสำเร็จ
5. ที่ 1180 มี sidebar 245 เหลือ ~895–935px ⇒ 2 คอลัมน์ของ detail ต้องแตกที่ `lg` (1024) ไม่ใช่ `xl` · ใช้ `lg:grid-cols-5` (ฟอร์ม 3 : พรีวิว 2) ไม่ใช่ 7:3 (พรีวิวจะเหลือ ~268px แคบเกิน bubble)

**Access:** เฉพาะ owner ของบัญชี — ADMIN/STAFF → `notFound()` และไม่แสดงแถวลิงก์ในหน้า `/business` (ไม่บอกว่ามีหน้านี้)

## Layout

ต่ำกว่า 1024 = mobile shell (SellerMobileHeader + bottom nav 72px, gutter 16px) ⇒ 768 ยังเป็นคอลัมน์เดียว · 1180 = sidebar + topbar · ภาพจริงดูใน mockup

### A. List (มีกลุ่ม)
- การ์ด "กลุ่มรายงานของฉัน" + `3 จาก 10 กลุ่ม` + ปุ่ม "เพิ่มกลุ่ม" (เต็มกว้างต่ำกว่า `sm`, ชิดขวาใน header ที่ `sm`+)
- แถว (แพตเทิร์นแถวของ `LineChannelCard`): ไอคอนกลุ่ม `size-10 rounded-lg bg-light` + โลโก้ LINE ซ้อนมุม → ชื่อกลุ่ม (`truncate` + `title=`) → "กลุ่มสาขา" / "กลุ่มรวม 5 ร้าน" + chip ร้าน ≤2 ใบ + `+3` → ป้ายสถานะ → ส่งถัดไป → ล่าสุด
- `lg`: grid 12 คอลัมน์ (ชื่อ+ร้าน 5 · สถานะ+ถัดไป 3 · ล่าสุด 3 · chevron 1)
- ทั้งแถวเป็นลิงก์ (min-h 44px); ปุ่ม "ผูกใหม่" ในแถวเป็นปุ่มจริงแยก ไม่ซ้อน anchor
- ลำดับแถว: มีปัญหา → รอผูก → ปกติ (ภายในกลุ่มเรียงตามเวลาส่งถัดไป)

| สถานะ | ป้าย | สี | เหตุผล |
|---|---|---|---|
| ผูกแล้ว | `circle-check` ผูกแล้ว | `bg-success/15 text-success-ink` | ยืนยันแล้วจริง |
| รอผูก | `clock` รอผูก | `bg-warning/15 text-warning-ink` | ยังไม่ยืนยัน ห้ามเขียว |
| บอทถูกนำออก | `link-off` บอทถูกนำออก | `bg-danger/15 text-danger-ink` | ส่งไม่ถึงจริง |
| หยุดส่งเพราะแพ็กเกจ | `lock` หยุดส่งเพราะแพ็กเกจ | `bg-warning/15 text-warning-ink` | แก้ได้ ไม่ใช่ความผิดพลาด |

"ส่งล่าสุด": สำเร็จ = `circle-check` `text-success-ink` + ข้อความ neutral · ล้ม = `circle-x` `text-danger-ink` "ส่งไม่สำเร็จ" · ยังไม่เคย = neutral

### B. Empty
ข้อความ + CTA "เพิ่มกลุ่มแรก" + 3 ขั้น + ตัวอย่าง Flex static · 375 = CTA ก่อน ตัวอย่างท้าย · 768 = 3 ขั้นเป็น `md:grid-cols-3` · 1180 = `lg:grid-cols-2` (ซ้ายข้อความ+CTA+ขั้นแนวตั้ง, ขวาตัวอย่าง)

### C. ผูกกลุ่ม 3 ขั้น (`/new` และ `[groupId]` PENDING)
- การ์ดเดียว `<ol>`: ขั้นปัจจุบัน `bg-primary text-white` · ผ่านแล้ว `bg-primary/15 text-primary` + `check` · ถัดไป `bg-primary/15 text-primary`
- ขั้น 1: "เปิดใน LINE" (`btn bg-light` + โลโก้) + QR (`qrcode.react` แบบ `OrderQrSheet`) — มือถือซ่อนหลังปุ่ม "แสดง QR", ≥768 เปิดเสมอ
- ขั้น 2 ก่อนกด: checkbox รับทราบ "รับทราบว่าทุกคนในกลุ่มจะเห็นตัวเลขที่ส่ง และ Deep ลบข้อความที่ส่งไปแล้วออกจากกลุ่มไม่ได้" → ปุ่ม primary "สร้างโค้ด" disabled จนกว่าจะติ๊ก · หลังกด: กล่อง `bg-light rounded-lg p-4`, `ผูก 482913` `text-2xl font-semibold tabular-nums` (Anuphan **ห้าม font-mono**), `CopyLinkButton` เดิม, badge นับถอยหลัง `bg-warning/15 text-warning-ink` "ใช้ได้อีก 09:41" — ไม่มี progress bar
- หมดเวลา: กล่องเป็น `bg-default-100` + "โค้ดหมดอายุแล้ว" + ปุ่ม "สร้างโค้ดใหม่" (หยุด poll)
- poll ทุก 3 วิ (หยุดเมื่อแท็บไม่ active) · สำเร็จ → แบนเนอร์ `bg-success/15` + ปุ่ม "ตั้งค่ารายงานของกลุ่มนี้" (ไม่ auto-redirect)
- 1180: การ์ด `max-w-3xl` ชิดซ้าย ไม่เติมการ์ดตกแต่งข้าง
- **ขั้น 1.5 "เลือกร้านที่รวม"** (มติ Controller 2026-10-05, SDS §12 #2): checkbox list ร้านที่เจ้าของเป็น `Shop.userId` · preselect เมื่อมีร้านเดียว · ต้องเลือก ≥1 ก่อน "สร้างโค้ด" ได้
- เปิดกลุ่ม `PENDING` ซ้ำ (โหลดหน้าใหม่) แสดงปุ่ม "สร้างโค้ดใหม่" แทนโค้ดเดิม — server เก็บแค่ hash แสดงโค้ดเดิมไม่ได้
- ขั้น 1 ต้องมีบรรทัด: "ถ้ากลุ่มนี้มี LINE OA อื่นอยู่ (เช่น OA ของร้าน) ให้นำออกก่อน — กลุ่มหนึ่งมี OA ได้ตัวเดียว"
- จุดแจ้งเตือนแถบล่างอยู่ที่แท็บ **"ร้านค้า"** (ไม่มีแท็บ "ธุรกิจ" ในแถบล่างจริง — SDS §12 #1)

### D. Detail (BOUND)
- **Action-bar** (`seller-action-placement.md` §2): ซ้าย `‹` + ป้ายสถานะ · ขวา `⋯` → "ส่งทดสอบ" (primary) · ตัวนับ "เหลือ 3 จาก 5 ครั้งวันนี้" ใต้ action-bar ชิดขวา
- **หัวกลุ่ม:** บล็อกข้อความ (ไม่ใช่การ์ด) ชื่อเต็มขึ้นบรรทัดได้ + "ผูกเมื่อ …"
- **ลำดับ:** มือถือ = ร้าน → เวลา → ตัวเลข → **พรีวิว** → คำสั่งในกลุ่ม → ประวัติ · `lg` = ซ้าย (ร้าน, เวลา, ตัวเลข, ประวัติ) 3 : ขวา (พรีวิว sticky, คำสั่งในกลุ่มไม่ sticky) 2
- **ร้านที่รวม:** `form-checkbox` ต่อแถว · ชื่อเต็มไม่ truncate + ชนิดร้าน ("ร้านบริการ" / "ร้านขายของ" / "ร้านส่วนตัว") · ร้านถูกล็อก = disabled + เหตุผล `text-default-700` · ร้านสุดท้ายที่ติ๊กอยู่ disabled + "ต้องเลือกอย่างน้อย 1 ร้าน"
- **เวลาส่ง:** การ์ดเดียว รายวัน/รายเดือนคั่นเส้นประ · หัวแถว `form-switch` · ปิด = เหลือ "ปิดอยู่" · เวลา = chip `bg-primary/10 text-primary` + × · เพิ่มด้วย **`form-select` native** + "เพิ่มเวลา" · ค่า 00:00–23:30 ทีละ 30 นาที + `24:00 — สรุปทั้งวันที่เพิ่งจบ` · ครบ 4 = disabled + helper · วันตัดรอบ `form-select` "วันที่ 1"…"วันที่ 31" + "สิ้นเดือน" + ตัวอย่างช่วงคำนวณสด (`formatDate`)
- **ตัวเลขที่แสดง:** checkbox 4 ตัวเปิด default + เส้นประ + "กำไร" ปิด default · ติ๊กกำไร → `pacesConfirm.warning` ก่อนเสมอ (แบบ `FinanceVisibilityToggle`) · เปิดแล้วมีแถบเตือนถาวร `bg-warning/15`
- **พรีวิว:** `.card` + seg `role=radiogroup` "รายวัน | รายเดือน" (ตัวที่ปิดอยู่ disabled) · กรอบ `bg-light` ครอบ bubble `max-w-xs` · ข้อมูลตัวอย่างคงที่ + คำว่า "ตัวอย่าง" เสมอ
- **ส่งทดสอบ:** ยิงข้อมูลจริงตามค่าที่บันทึกแล้ว · ไม่มี confirm (§3.1) · ผลเป็น `pacesToast`
- **พิมพ์ในกลุ่มได้เลย:** chip คำสั่ง 2 ตัวคัดลอกได้ + คำอธิบายบรรทัดเดียว
- **ประวัติ:** `table table-sm` ที่ ≥768 (แบบ `MovementHistoryTable`), มือถือแถว 2 บรรทัด · คอลัมน์ เวลา · ประเภท (neutral) · ผล (สำเร็จ success / ไม่สำเร็จ danger / ข้าม neutral) · สาเหตุ
- **ยกเลิกการผูก:** ใน `⋯` ท้ายสุด `text-danger-ink` → `pacesConfirm.danger` → DELETE → toast → กลับ list · ไม่มี danger zone ท้ายหน้า
- **แบนเนอร์บนสุด** (เฉพาะมีปัญหา, โครง `LockedStateBanner`): บอทถูกนำออก (danger + "ผูกใหม่") · หยุดเพราะแพ็กเกจ (warning + CTA ตามกฎ payments) · ส่งล่าสุดล้ม = แสดงใน header ประวัติเท่านั้น

**Preview bubble** (แก้ตามมติ PRD/BRD 2026-10-05):
- หัว "รายงานยอดรายวัน" `text-primary-ink` + ป้ายวันที่ `bg-primary/15` + บรรทัด "ข้อมูล ณ 21:02 น. · รวม N ร้าน" · รอบ 24:00 หัวเป็น "สรุปวันที่ 5 ต.ค. 2569 (ครบทั้งวัน)"
- ออเดอร์ · **ยอดขาย (นับแล้ว)** (ตัวเดียวที่หนา) + บรรทัดรอง "ยังไม่นับเป็นยอดขาย ฿xx,xxx (รอยืนยัน/รอขนส่งรับ)" · "ยกเลิก 6 ใบ (ใบที่เปิดในช่วงนี้)" (neutral ไม่แดง)
- กลุ่มต่างประเภท: หมายเหตุใต้ยอดรวม "ยอดแต่ละร้านคิดตามกติกาของประเภทธุรกิจ"
- แยกรายร้าน + **ขายดี 3 อันดับรายร้าน** (ไม่รวมข้ามร้าน) หัวมีหมายเหตุ "นับทุกใบที่ไม่ยกเลิก" · แสดง 2 ร้านแรก ที่เหลือ "…และอีก 2 ร้าน"
- เปิดกำไร: กำไร**รายร้านเท่านั้น** ไม่มียอดรวม + หมายเหตุ "กำไรแต่ละร้านคิดตามกติกาของประเภทธุรกิจ จึงไม่รวมเป็นยอดเดียว" · ร้านที่ต้นทุนไม่ครบ = "กำไรได้มากที่สุด ≤ ฿…"
- ยอดสะสมรอบนี้ (รายวันที่ไม่ใช่ 24:00) → หมายเหตุร้านที่ถูกล็อก → "เปิด dashboard"

### E. Locked
- **E1 ไม่เคยมีแพ็กเกจ:** การ์ดเดียว `icon-sq lock` + หัวข้อ + ย่อหน้า + CTA · ตัวอย่าง Flex static ข้าง ๆ (แสดงสิ่งที่ได้แทนการบรรยาย) · 1180 = 2 คอลัมน์
- **E2 เคยมีกลุ่มแต่แพ็กเกจไม่ active:** list อยู่ครบ ทุกแถว "หยุดส่งเพราะแพ็กเกจ" + แบนเนอร์เหนือการ์ด · detail อ่านได้แก้ไม่ได้ เหลือ "ยกเลิกการผูก" ใน `⋯`

| เงื่อนไข | CTA | ปลายทาง |
|---|---|---|
| ปกติ ไม่เคยสมัคร | "ดูแพ็กเกจธุรกิจ" | `/business` |
| ปกติ `LOCKED_RENEWAL_FAILED` | "ต่ออายุแพ็กเกจ" | `/business` |
| `shouldHidePayments` + `shouldOfferIap` | "ดูแพ็กเกจธุรกิจ" | `/business/subscribe` |
| `shouldHidePayments` ไม่มี IAP (Android) | ไม่มี CTA ไม่มีราคา ไม่มีลิงก์ | อธิบายอย่างเดียว |

## Impeccable compliance

- **Mode: Operate** — เกณฑ์คือ consistency กับหน้าพี่น้อง ไม่ใช่การแสดงออก
- **One Voice:** น้ำเงิน `bg-primary` เฉพาะปุ่ม primary 1 ตัว/หน้า, วงกลมขั้น, chip เวลา, switch/checkbox ที่ติ๊ก, ลิงก์, หัวบับเบิล · ไม่มีพื้นน้ำเงินเต็มบล็อก
- **Verified-Means-Green:** เขียวเฉพาะ "ผูกแล้ว", "ส่งสำเร็จ", แบนเนอร์ผูกสำเร็จ · รอผูก/นับถอยหลัง/หยุดเพราะแพ็กเกจ = warning · ข้าม/ยกเลิกในพรีวิว = neutral · แดงเฉพาะส่งล้มจริง/บอทถูกนำออก · ตัวหนังสือบนพื้นจางใช้ `-ink` ทุกจุด
- **สี LINE:** ไม่ใช้เขียว LINE เป็นพื้น/ปุ่ม/พื้นพรีวิว ใช้โลโก้ asset เท่านั้น
- **Sentence-case:** ไม่มี ALL CAPS, ไม่ลอก `uppercase` ของ `settings/ai`
- **ข้อความรอง** ใช้ `text-default-700` (ไม่ใช่ 400/500) เพื่อผ่าน 4.5:1 — Controller เช็คตอน critique
- **พรีวิวซ้อนกรอบ** ยอมรับ เพราะเป็นภาพแทนวัตถุภายนอก + caption "ตัวอย่าง" — จุดเสี่ยง critique
- **ความเสี่ยง critique:** (ก) พรีวิวซ้อนกรอบ (ข) การ์ด "เวลาส่ง" แน่น — ถ้าแน่นแยก 2 การ์ด (ค) autosave อาจทำให้ไม่มั่นใจ — mockup ใส่ "บันทึกอัตโนมัติ" ใต้ชื่อกลุ่มไว้แล้ว

## Design decisions

1. detail แยก route ไม่ใช้ drawer/โมดัล
2. autosave — ปุ่ม primary คือ "ส่งทดสอบ" ซึ่งทดสอบค่าที่บันทึกแล้ว ตรงกับพรีวิวเสมอ
3. switch = เปิดปิดฟีเจอร์ · checkbox = เลือกรวมรายการ
4. กำไรแถวสุดท้าย + Swal ก่อนเปิด (แบบ `FinanceVisibilityToggle`)
5. นับถอยหลังไม่มี progress ring/bar
6. ตัดการ์ดสรุปสถานะและ danger zone
7. list ให้แถวมีปัญหาขึ้นก่อน
8. พรีวิวใช้ข้อมูลตัวอย่าง ติดป้าย "ตัวอย่าง"
9. มือถือ: พรีวิวอยู่หลัง "ตัวเลขที่แสดง" (ไม่ลอย — ชน bottom nav + safe-area)
10. "ส่งทดสอบ" ไม่มี confirm (§3.1) มีเพดาน 5/วัน + ประวัติ
