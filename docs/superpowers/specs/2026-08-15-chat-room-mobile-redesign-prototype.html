ห้องแชทผู้ขายบนมือถือ — โครงใหม่ทั้งห้อง 3 แบบ

2026-08-15 · prototype (โค้ดทิ้ง) · สลับด้วยลูกศร ← → หรือ ?variant=A|B|C

คำถามที่ม็อกอัพนี้ตอบ: ห้องแชทบนมือถือควรจัดโครง ทั้งห้อง ยังไง เมื่อของที่ต้องแสดงมี 57 ชนิด กระจายใน 10 โซน — รอบก่อน ๆ วันนี้ (A–K และ 3 แบบเมื่อ 13:22) ตอบเฉพาะโซน 1+2 = 19/57 ชนิด ⇒ ข้อสรุปเดิมใช้ได้เฉพาะในขอบเขตที่มันถูกทดสอบ (2026-08-14-chat-mobile-topbar-v2-prototype.md §5.10)
ทุกแบบถูกทดสอบด้วย “เคสของครบ” เป็นค่าตั้งต้น — คำเตือน 4 อันพร้อมกัน · ที่มา 2 อัน (คอมเมนต์ + โฆษณา) · นับถอยหลัง · แถบตอบเองแทน AI · ป้ายลูกค้า · ออเดอร์ค้าง. นี่คือเคสที่ม็อกอัพ A–K ไม่เคยทดสอบเลยสักแบบ และเป็นเคสที่ user ส่งภาพจริงมาให้ดู ⇒ ถ้าแบบไหนพังตรงนี้ ให้ตกไปตั้งแต่ต้น ไม่ต้องดูเคสปกติ

สามแบบต่างกันที่ “ของที่ไม่ใช่ข้อความ ไปอยู่ที่ไหน”

แบบหลักการchrome เหนือสตรีมที่อยู่ของสถานะ
A
ยุบเป็นบรรทัดเดียว		 จอเป็นของบทสนทนา ทุกอย่างอื่นยุบเหลือ บรรทัดสรุป 1 บรรทัด ที่กดกางเป็นแผงเต็มรายการ คงที่ 44 + 27 = 71px ทุกสถานการณ์ แผงกางจากบนสุด (ยังเห็นสตรีมข้างหลัง)
B
ละลายเข้าสตรีม		 ห้องแชทมี พื้นผิวเดียว = สตรีม ที่มา/บริบท/ออเดอร์เป็นการ์ดตามลำดับเวลา คำเตือนปักท้ายสตรีม 66px (หัวเธรดล้วน) ไม่มีชั้นซ้อน การ์ดในสตรีม + แถบปักท้ายเหนือช่องพิมพ์
C
แยกสองพื้นผิว		 แยก “คุย” ออกจาก “งาน” — จอแชทสะอาดล้วน งานทั้งหมดอยู่ในลิ้นชักที่โผล่หัวมา 33px 66px (หัวเธรดล้วน) ลิ้นชักเหนือช่องพิมพ์ (ลาก/แตะขึ้น)

B2 B ที่แก้ตามที่สั่ง + เคสออเดอร์กำลังจัดส่ง

สิ่งที่สั่งมา: เอาแบบ B · แถบด้านล่างเวลามีปัญหา (สีแดง ๆ) ให้ขึ้นว่า “สถานะห้องแชท (3)” กดแล้ว slide up ดู list ได้ · ไม่ต้องเอาข้อมูลคำสั่งซื้อหรือรูปอะไรไปรวม · และลองใส่ chat ที่มี order กำลังจัดส่ง

แก้จาก B ตรงท้ายสตรีม: จากเดิม คำเตือน 3 แถบซ้อนกัน ~93px เหลือ แถบเดียว 33px เขียนว่า “สถานะห้องแชท” + ตัวเลข — แตะแล้วแผง slide up ขึ้นมาแสดงรายการเต็มประโยค แล้วปัดลงปิด. ในแผงมีแต่สถานะล้วน ไม่มีออเดอร์ ไม่มีไฟล์ ไม่มีที่มา ตามที่สั่ง

ออเดอร์กำลังจัดส่ง — แยกเป็นแถบของตัวเอง ไม่ใช่รายการในแผงสถานะ

🛑 นี่ไม่ใช่แค่ทำตามที่สั่ง — โค้ดจริงเห็นด้วย. OrderProgressBar.tsx เขียนคอมเมนต์ไว้เองว่า “แถบนี้เป็นทางลัดดูสถานะ ไม่ใช่ alert — โทน primary ไม่ใช่ warning/danger” ⇒ ถ้ายุบพัสดุไปกองเดียวกับ “token ตาย” เมื่อไหร่ คือพารถบรรทุกไปอยู่กองเดียวกับของพัง ซึ่งเป็นสิ่งที่โค้ดจริงตั้งใจเลี่ยงมาตั้งแต่ต้น

ท้ายสตรีมจึงมี 2 แถบยุบ ที่แยกกันชัดด้วยสีและคำ — พัสดุ (info · ข้อมูล) และสถานะ (danger · ต้องลงมือ): รวม 66px ตอนของครบ ยังน้อยกว่า 93px ของ B เดิม ที่ยังไม่นับแถบพัสดุด้วยซ้ำ

แถบพัสดุกางแล้วได้ กล่องตามภาพที่ส่งมาเป๊ะ — โลโก้ขนส่ง (ไฟล์จริงในรีโป public/images/logos/flash-express.jpeg) + ชื่อขนส่ง + เลขพัสดุตัวหนา + ปุ่มคัดลอก + stepper 4 จุด. ไม่ได้วาดใหม่ — โครงมาจาก ShipmentStepper.tsx ที่มีอยู่แล้ว (grid-cols-4 · ป้ายใต้จุด · ครึ่งเส้นด้านนอกของจุดหัว-ท้ายโปร่ง) และคำทั้ง 4 ขั้นมาจาก SHIPMENT_STAGES (iship/status.ts:189) ไม่ได้พิมพ์เอง

ในสตรีมยังมี การ์ดคำสั่งซื้อ วางไว้ ณ เวลาที่เปิดบิลจริง — นี่คือหลักของ B ทำงานถูกทาง: “ตอนที่ลูกค้าสั่ง” คือเหตุการณ์ (อยู่ในสตรีม) · “ตอนนี้ของถึงไหน” คือสถานะที่ยังเดินอยู่ (ปักท้าย)

ได้

  • ท้ายสตรีมนิ่ง — 66px ของครบ / 33px ปกติ ไม่ว่าคำเตือนจะมี 1 หรือ 7 อัน
  • ไม่ต้องประดิษฐ์ pattern ใหม่เลยสักอัน — ยุบ/กาง + badge +N มีอยู่แล้วใน OrderProgressBar ส่วน stepper มาจาก ShipmentStepper ที่ใช้ร่วมกันทุกจุดอยู่แล้ว
  • เลขพัสดุ + ปุ่มคัดลอกอยู่ในห้องแชท — ไม่ต้องออกไปหน้าออเดอร์เพื่อก็อปเลขให้ลูกค้า
  • แผงสถานะมีที่ให้ ประโยคเต็ม ⇒ ปิดอาการ “ชิปถูกตัดจนไร้ความหมาย” ที่เห็นในภาพจริง
  • พัสดุกับคำเตือนแยกกองกันด้วยสี — อ่านออกใน 1 วินาทีว่า “มีของต้องแก้ไหม” แยกจาก “ของถึงไหน”

เสีย / ต้องตัดสิน

  • คำเตือนไม่มีถ้อยคำบนจอจนกว่าจะกด — เห็นแค่ “สถานะห้องแชท (3)” (ข้อเสียเดียวกับแบบ A แต่แลกมากับความสูงที่นิ่ง)
  • ตอนมีคำเตือน ระดับ danger ที่ขวางการส่งจริง (token ตาย/โควตาหมด) ควรดันข้อความขึ้นมาบนแถบเลยไหม หรือให้เท่ากันหมด — ตอนนี้ทำเป็นเท่ากันหมด
  • ออเดอร์ 2 ใบขึ้นไป แถบโชว์ใบล่าสุด + ตัวเลข 2 — กางแล้วต้องเลือกใบ ยังไม่ได้ออกแบบส่วนนั้น
  • แถบพัสดุกินที่ถาวร 33px แม้ของส่งถึงแล้ว — ต้องยืมกติกาหมดอายุของ order-stage.ts (จัดส่งสำเร็จ → แสดง 3 วันแล้วหาย)

A ยุบเป็นบรรทัดเดียว — “จอเป็นของบทสนทนา”

หัวเธรดหดเหลือ 44px (ปุ่มย้อนกลับ btn-sm btn-icon 30px ตามธีม + รูป + ชื่อ + ปุ่มสถานะ + ⋯) — ชื่อเพจ ป้ายลูกค้า ที่มา ออเดอร์ คำเตือน ทั้งหมด ยุบลงมาอยู่ใน บรรทัดสรุปเดียว 27px ที่อ่านซ้ายไปขวาได้: “ต้องแก้ก่อน” → “ลูกค้าคนนี้เป็นใคร” → “มาจากไหน”. แตะบรรทัดนั้น = กางแผงเต็มรายการจากบนสุด (จัดกลุ่ม ต้องลงมือ / ลูกค้า / ที่มา)

เหนือสตรีมสูงเท่ากัน 71px เสมอ ไม่ว่าจะมีคำเตือน 0 หรือ 4 อัน — เลย์เอาต์ไม่เคยกระโดด ส่วนคำเตือนที่ ขวางการส่งจริง (token ตาย / โควตาหมด) ไปเกาะขอบช่องพิมพ์แทน เพราะนั่นคือจุดที่ผู้ขายจะรู้ตัว

ได้

  • สตรีมได้พื้นที่มากที่สุดในสามแบบ — เหนือสตรีม 71px คงที่ (ของครบและปกติเท่ากัน)
  • คำเตือนหลายอันไม่ทำให้จอบวม — 4 อันยังเป็น 27px บรรทัดเดียว (แบบ K จะเป็น 3 แถบซ้อน ~93px)
  • ที่ 320px บรรทัดสรุปยังอ่านได้ เพราะเม็ดยา “ต้องแก้ 2” มาก่อน ส่วนที่ถูกตัดคือหางของบริบทซึ่งไม่เร่งด่วน
  • แผงกางแก้ปัญหา “ชิปถูก truncate จนไร้ความหมาย” — ในแผงมีที่ให้ประโยคเต็มทุกบรรทัด
  • สถานะ AI ที่เคยโผล่ 3 ที่พร้อมกัน เหลือที่เดียว (แถบเหนือช่องพิมพ์)

เสีย

  • คำเตือนถูกลดชั้นเป็นตัวเลข — “บอทหยุดตอบ” ไม่มีถ้อยคำบนจอจนกว่าจะกดกาง ต้องเชื่อว่าผู้ขายจะกด
  • เพิ่ม 1 แตะสำหรับทุกอย่างที่เคยอ่านได้เลย (ที่มาของแชท · ป้ายลูกค้าเต็ม)
  • ชื่อเพจหายจากหัวเธรด (ไปอยู่ในบรรทัดสรุป/แผง) — ย้อนสิ่งที่เพิ่งตัดสินไปใน §5.5 ว่าบรรทัด 2 ต้องมีชื่อเพจ
  • บรรทัดสรุปเป็น pattern ใหม่ ยังไม่มี precedent ตรง ๆ ในธีม

B ละลายเข้าสตรีม — “ทุกอย่างคือเหตุการณ์”

ไม่มีชั้น chrome ใต้หัวเธรดเลย. ที่มาของแชท (คอมเมนต์/โฆษณา พร้อมรูปที่ลูกค้าแนบมา ซึ่งวันนี้ยังไม่เคย render เลย) กลายเป็น การ์ดใบแรกในสตรีม ตามลำดับเวลาจริง · ป้ายลูกค้า/ออเดอร์ เป็นการ์ดถัดมา · เลื่อนพ้นไปแล้วก็หายไปเลย เพราะมันคือ “เรื่องที่เกิดตอนเริ่มห้อง” ไม่ใช่สถานะถาวร

ของที่ ยังจริงอยู่ตอนนี้ (คำเตือน) ไม่หายไปกับการเลื่อน — มันไป ปักท้ายสตรีมเหนือช่องพิมพ์ ซึ่งเป็นที่ที่ตาอยู่เสมอ เพราะห้องแชทเปิดมาอยู่ล่างสุดทุกครั้ง

ได้

  • เหนือสตรีม 66px คงที่ และไม่มีชั้นซ้อนให้ต้องเรียนรู้ — โครงเดียวกับแอปแชททุกตัวที่ผู้ขายใช้อยู่แล้ว
  • ที่มาของแชทได้พื้นที่เต็มกว้าง อ่านได้ว่าลูกค้าคอมเมนต์ว่าอะไร + เห็นรูปที่แนบมา (commentOrigin.attachmentUrl และ createdTime ที่ส่งมาถึงหน้านี้แล้วแต่ถูกทิ้งทั้งดุ้น)
  • ที่มา 2 อันพร้อมกันไม่ชนกัน — เป็นการ์ด 2 ใบเรียงตามเวลา ไม่ใช่ชิป 2 อันแย่งแถวเดียว
  • ไม่มีอะไรถูก truncate เลย ทุกข้อความได้บรรทัดเต็ม

เสีย

  • ที่มาหาไม่เจอเมื่อเลื่อนพ้นไปแล้ว — เธรดยาว ๆ ต้องเลื่อนขึ้นสุดเพื่อดูว่ามาจากโฆษณาชิ้นไหน
  • คำเตือนหลายอันปักท้าย = กิน พื้นที่สตรีมจริง (ของครบ 3 แถบ ≈ 93px) จอเหลือข้อความน้อยลง
  • การ์ดบริบทปนกับข้อความจริง — ต้องออกแบบให้แยกออกด้วยสายตา ไม่งั้นดูเหมือนลูกค้าส่งการ์ดมา
  • ห้องที่เพิ่งเปิดใหม่จะเห็นการ์ดบริบท 2–3 ใบก่อนข้อความแรก ดูหนักกว่าที่ควร

C แยกสองพื้นผิว — “คุย” กับ “งาน”

พื้นผิวแชทสะอาดล้วน: หัวเธรด 66px + สตรีม + ช่องพิมพ์ ไม่มีสถานะอะไรแทรกเลย. ของ 57 ชนิดที่ไม่ใช่ข้อความ ย้ายไปอยู่ใน ลิ้นชัก “งาน” ที่โผล่หัวมา 33px เหนือช่องพิมพ์ — หัวลิ้นชักแสดง เรื่องที่เร่งที่สุดเรื่องเดียว พร้อมสีของมัน แล้วลาก/แตะขึ้นเพื่อกางเต็ม

ในลิ้นชักคือทางเข้างานทั้งหมดที่วันนี้กระจายอยู่ 3 ที่: คำเตือน · ออเดอร์ของลูกค้า (วันนี้ต้อง 2 แตะ) · คลังไฟล์ · ข้อมูลลูกค้า · ที่มาของแชท — เป็นทางเข้าเดียว ไม่ใช่ 5 ทาง

ได้

  • หัวเธรดกลับไปทำหน้าที่เดียว — ตัวตนลูกค้า + ชื่อเพจ ได้ที่เต็ม ไม่ต้องแย่งกับปุ่ม 3 ตัว (ชื่อได้ ~200px ที่ 390px แทน 122.8px ของแบบ E)
  • สิ่งที่เร่งที่สุด อยู่ติดนิ้วที่กำลังจะพิมพ์ ไม่ใช่อยู่ไกลบนสุดของจอ
  • ทางเข้าออเดอร์เหลือ 1 แตะ และตัวเลขอยู่บนหัวลิ้นชัก (ตอบ feedback ลูกค้าจริงเรื่อง “เน้นดู Order lists”)
  • ของครบกับปกติต่างกันแค่ สีและคำบนหัวลิ้นชัก — ความสูงคงที่ 33px ทุกสถานการณ์ทั้งสองเคส

เสีย

  • ลิ้นชักกินที่ถาวร 33px แม้ไม่มีอะไรต้องทำเลย (แบบ A บรรทัดสรุปก็กิน 27px เหมือนกัน — B ไม่กินเลยตอนไม่มีคำเตือน)
  • เรื่องที่ 2 3 4 มองไม่เห็นจนกว่าจะกาง — แย่กว่า A ตรงที่ A อย่างน้อยบอกจำนวน
  • ลิ้นชักลากได้เป็น pattern ที่ ยังไม่มีในธีม และท่าลากชนกับการเลื่อนสตรีม ต้องกันขอบให้ดี
  • ของที่ควรอ่านโดยไม่ต้องกด (ที่มาของแชท) ถูกฝังลึกที่สุดในสามแบบ
