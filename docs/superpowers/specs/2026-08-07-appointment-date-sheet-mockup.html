3 อย่างที่เปลี่ยนจากของเดิม และเหตุผล

  • ตัดตัวหนังสือ “1 คิว” ออกจากทุกช่อง — ของเดิมเขียนคำเดียวกันซ้ำ 35 ช่องจนไม่เหลือความหมาย แถมกินความสูงจนปฏิทินยาวเต็มจอ ไม่มีที่ให้รายการ. เหลือ 3 สถานะที่แยกกันด้วยรูปร่าง ไม่ใช่ด้วยสีอย่างเดียว: ว่าง = เลขวันเปล่า · มีคิวแล้ว = เลขวัน + จุดเหลือง · เต็ม = กากบาทแทนเลขวัน (user สั่ง 2026-08-07 พร้อมภาพอ้างอิง) — วันที่จองไม่ได้จึงข้ามได้ตั้งแต่กวาดตา ไม่ต้องเพ่งจุดเล็ก ๆ และคนตาบอดสียังแยกออกเพราะรูปร่างต่างกัน. เฉดสีคงของ legend เดิมเป๊ะ ไม่สลับเฉด · ของจริงใช้ <Icon icon="x"> ของ tabler ไม่ใช่ emoji (HR12) และเลขวันยังอยู่ใน DOM (visibility:hidden) ให้ screen reader อ่านวันที่ได้
  • รายการครึ่งล่างใช้ของที่มีอยู่แล้ว ไม่ต้องแตะ backend — GET /api/shops/current/appointments?from&to&resourceId คืน orderNo · buyerName · start · end · appointmentStatus ครบอยู่แล้ว และ select ของมันกันเบอร์/อีเมลไว้ตั้งแต่ใน service (appointment.service.ts:487) ส่วน endpoint ที่ sheet เดิมเรียก (availability) คืนแค่ {capacity, busy:[{start,end}]} ไม่มีชื่อคน — จะโชว์รายการต้องสลับมาใช้ตัวนี้
  • ปุ่มล่างพูดวันที่ออกมาตรง ๆ (“เลือก 11 ส.ค. 2569”) ไม่ใช้คำว่า “วันนี้” — คำนั้นถูกใช้ไปแล้วบนหัวปฏิทินในความหมาย “กระโดดไปวันปัจจุบัน” อยู่จอเดียวกันแล้วอ่านสลับกันได้ทันที. วันเต็มปุ่มจะเทาและเขียนว่า “วันนี้เต็มแล้ว — เลือกวันอื่น” แทนการเด้ง toast ปฏิเสธลอย ๆ
