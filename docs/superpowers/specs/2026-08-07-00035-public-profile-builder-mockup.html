4 · เส้นแบ่งของเหรียญตรา — จุดที่ trust guardrail ไม่ขัดกับ drag & drop

ตรวจ prisma/badge-seed-data.ts จริงแล้วพบว่า Badge.type แยกไว้ให้อยู่แล้ว ไม่ต้องประดิษฐ์กฎใหม่

type: "ACHIEVEMENT" — เลือกและจัดลำดับได้อิสระ
ร้อยออเดอร์จัดส่งสายฟ้าไร้ข้อร้องเรียน ร้านค้าเก่าแก่ขายดีไร้ปัญหาส่งไวระดับเทพ ร้านคะแนนสูง
ทำไมถึงปล่อยได้: เหรียญ achievement ทุกใบเป็นเรื่องดีทั้งหมด — ไม่มี "เหรียญแย่" ให้ซ่อน การเลือกโชว์ 4 ใบจาก 7 ใบจึงเป็นการจัดหน้า ไม่ใช่การปกปิด และคนดูรู้ได้เสมอว่ากดดูทั้งหมดได้
type: "VERIFICATION" + สถิติ — ตรึงตายตัว
ยืนยันครบถ้วนคะแนนความน่าเชื่อถือป้ายระดับการยืนยัน ยอดออเดอร์สำเร็จอัตราสำเร็จรีวิวจากลูกค้า
ทำไมถึงปล่อยไม่ได้: กลุ่มนี้ มีทั้งด้านดีและด้านแย่ — ถ้าซ่อนได้ทีละใบ ร้านที่มีปัญหาจะซ่อนเฉพาะตัวที่แย่ แล้วตัวเลขที่เหลือหมดความหมายทั้งชุด · ซ่อนได้ทางเดียวคือปิดทั้งหน้า (เห็นหมด หรือไม่เห็นเลย)

5 · เรื่องที่ต้องเคาะก่อนลงมือ (มีผลต่อขนาดงานมาก)

1. "ลำดับที่ลาก" ไปโผล่ที่ไหนบนหน้าร้านจริง — หน้าร้านตอนนี้เป็น แท็บ (ปักหมุด/สินค้า/บริการ/ห้องพัก/เกี่ยวกับร้าน/รีวิว) ไม่ใช่หน้าเลื่อนยาวช่องเดียว · ทางที่เสนอ: ลำดับใน canvas = ลำดับแท็บ และ "โพสต์จากเพจ" เป็นบล็อกใหม่ที่แทรกเหนือแท็บได้ · ต้องเพิ่มคอลัมน์เก็บลำดับ (เช่น Shop.profileLayout) และ refactor ShopProfile.tsx ให้เรียงตามคอลัมน์นั้นแทน hardcode

2. พรีวิว realtime เอาระดับไหน — (ก) postMessage เข้า iframe อัปเดตทันทีขณะลาก งานใหญ่ ต้องแตะ route ฝั่ง (marketing) ด้วย · (ข) reload iframe ด้วย query param หลัง debounce งานเล็กกว่ามาก ช้ากว่านิดเดียว — ผมแนะนำ (ข) สำหรับรอบแรก

3. โพสต์จากเพจดึงมาแสดงบนหน้าร้านสาธารณะได้จริงไหม — FacebookPost.thumbnailUrl เก็บ URL ของ Meta ตรง ๆ ไม่ได้ mirror ลง storage เรา (คอมเมนต์ใน schema เขียนไว้ชัด) รูปพวกนี้ มีวันหมดอายุ ถ้าเอาไปแปะหน้าร้านถาวรอาจกลายเป็นรูปแตกทีหลัง — ต้องตัดสินว่าจะ mirror รูปลง bucket ตอนร้านลากมาวาง หรือยอมรับความเสี่ยง

4. เหรียญตราเลือกได้สูงสุดกี่ใบ — mockup ตั้งไว้ 4 ใบตามที่พอดีแถวเดียวบนมือถือ
