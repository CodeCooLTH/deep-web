Public Profile · 3 ทิศทางความงาม

โครงข้อมูล (IA) เหมือนกันทั้ง 3 ทิศทางเป๊ะ — ลำดับ · ถ้อยคำ · ตัวเลข ไม่มีอะไรเปลี่ยน เปลี่ยนแค่ ผิว: พื้นผิว/ความลึก/จังหวะช่องไฟ/การใช้สีประจำระดับ ข้อมูลทั้งหมดเป็นของจริงจาก /b/qa-online (ธนภัทร์ อะไหล่มอเตอร์ไซค์ · 41/100 · Deep Classic)

ทำไมไม่ใช่ ?variant= ตามสูตร prototype: skill นั้นบังคับว่า variant ต้องต่างกัน เชิงโครงสร้าง และเขียนไว้ตรงตัวว่า “ต่างกันแค่สี/ระยะห่าง = วอลเปเปอร์ ไม่ใช่ prototype” แต่โครงหน้านี้ตัดสินไปแล้ว (D ชนะ → ขึ้น prod → ไล่แก้กับข้อมูลจริง ~20 รอบ) คำถามที่เหลือคือ “สวยขึ้นได้ยังไง” ซึ่งเป็นคำถามเรื่องผิว ⇒ เทียบด้วยม็อกอัพเร็วกว่าและไม่ต้องเอาโค้ดชั่วคราวไปใส่ prod
ทั้ง 3 กรอบต่อทิศทางเรนเดอร์จาก template เดียวด้วย JS — รอบก่อน (rev8) ผมแก้ HTML ด้วย regex แล้วมันแมตช์แค่ 1 ใน 3 กรอบ ⇒ มือถือโชว์เลขซ้ำ เดสก์ท็อปไม่โชว์เลย และ user เห็นความไม่ตรงกันนั้น ก่อนผม การเรนเดอร์จากต้นแบบเดียวปิดคลาสบั๊กนั้นทั้งคลาส
สิ่งที่ทั้ง 3 ทิศทางห้ามแตะเหมือนกัน: เขียว #28C76F สงวนให้สิ่งที่ยืนยันแล้วจริง (ระดับ 1 = OTP ห้ามเป็นเขียว) · ม่วง ≤10% ของจอ (One Voice) · % ต้องมาคู่ตัวหารเสมอ (BR-OSM-07) · ไม่มี emoji เป็นไอคอน · ตัวเลขใช้ขั้น Metric 32/22/20 ของ DESIGN.md

A · Card & Depth — เนื้อหาลอยบนการ์ด มีพื้นและความลึก

พื้นเพจเป็นสีหมอก เนื้อหาอยู่บนการ์ดขาวมุมมนมีเงา · ปกมีฉากทับล่างให้ขอบรูปโปรไฟล์ไม่จม · แผงหลักฐานเลิกเป็นแถบเทาเต็มขอบ กลายเป็นการ์ดในตัวที่มีขอบ+มุมมน (ของเดิมกินขอบซ้าย-ขวาจนอ่านเป็น “แถบแจ้งเตือนของระบบ” มากกว่าเนื้อหาที่ร้านภูมิใจ) · บล็อกเพจทางการก็เป็นกล่องมีขอบเช่นกัน
ได้: ลำดับชั้นชัดที่สุด แต่ละกลุ่มแยกจากกันด้วยพื้น ไม่ต้องพึ่งเส้น · คุ้นตาที่สุดกับ Vuexy ที่เหลือทั้งระบบ เสีย: ขอบ+เงาเยอะขึ้น = “แอป” มากกว่า “โปรไฟล์คน” · บนมือถือกินความกว้างไป 2 ชั้น (การ์ดนอก + การ์ดใน)

B · Editorial — ไม่มีกล่องเลย ให้ที่ว่างกับตัวอักษรทำงาน

ขาวล้วนทั้งหน้า ไม่มีพื้นสีสักบล็อก · คั่นด้วยเส้นบางเฉียบ + ช่องไฟที่กว้างขึ้นราว 1.5 เท่า · ชื่อร้านขึ้นเป็น 26–30px · บรรทัดหลักฐานขึ้นเป็น 16px กับ leading 1.5 · หัวข้อ “ทำไมร้านนี้ถึงเชื่อได้” ลดจากหัวข้อหนา 18px เหลือป้ายเบา 15px (มันเป็นป้ายกำกับ ไม่ใช่หัวเรื่องที่ต้องแข่งกับชื่อร้าน)
ได้: สงบ พรีเมียม อ่านสบายที่สุด · เหมาะกับหน้าที่ทั้งหน้าคือ “การอ่านเพื่อตัดสินใจ” เสีย: หน้ายาวขึ้นชัดเจน (จอแรกได้เนื้อหาน้อยลง) · ถ้าร้านไม่มีปก/รูปสวย จะดูโล่งจนเหมือนหน้ายังโหลดไม่เสร็จ

C · Tinted Trust — ใช้สีประจำระดับเป็นบรรยากาศทั้งหน้า

สีของระดับ (Deep Classic = โทนอำพัน) ไล่จากปกลงมา · แผงหลักฐานย้อมอ่อน ๆ ด้วยสีเดียวกันแทนสีเทากลาง · รูปโปรไฟล์มีวงแหวนสีระดับ · ทั้งหน้ากลายเป็นของร้านนี้ ไม่ใช่เทมเพลตที่ใช้ซ้ำได้ทุกร้าน และร้านคนละระดับจะหน้าตาต่างกันทันทีตั้งแต่ยังไม่อ่าน
ได้: จำได้ · สีทำงานสื่อความหมายจริง ไม่ใช่ของประดับ · ต่อยอดกับปกที่ใช้สีระดับอยู่แล้วได้พอดี เสีย: เสี่ยงที่สุด — โทนอำพันของ Classic อยู่ใกล้สี “คำเตือน” มาก ถ้าอัลฟาสูงไปนิดเดียวจะอ่านเป็น “ร้านนี้มีปัญหา” ทันที · และร้าน Deep Gold/Platinum จะได้หน้าที่ฉูดฉาดกว่าโดยไม่ได้ตั้งใจ

B + C · ทิศทางที่เลือก ✔

จังหวะและตัวอักษรของ B + สีประจำระดับของ C — user เลือก 2026-08-13
🛑 สองทิศทางนี้ขัดกันตรง ๆ อยู่จุดเดียว: แผงหลักฐาน — B บอกว่าห้ามมีพื้นสีสักบล็อก ส่วน C บอกว่าให้ย้อมสีระดับ · ตัดสินตาม C เฉพาะบล็อกนี้บล็อกเดียว เพราะเป็นที่เดียวในหน้า ที่สีทำงานสื่อความหมายจริง (ระดับของร้าน) ที่เหลือตาม B คือขาวล้วนไม่มีพื้นสีเลย
ผลข้างเคียงที่ตั้งใจ: พอทั้งหน้าไม่มีสีอื่น บล็อกเดียวที่มีสีจึงกลายเป็นจุดที่ตาไปหยุดเอง โดยไม่ต้องใช้ตัวหนาหรือขนาดมาแย่งความสนใจจากชื่อร้าน — ซึ่งตรงกับหน้าที่ของหน้านี้พอดี

ยังไม่ได้ลงโค้ดจริง — นี่คือม็อกอัพ ถ้าโอเคผมลงให้เลย จุดที่จะแตะจริงมี 4 ไฟล์: ProfileIdentity (ปก/วงแหวน/ตัวอักษร/ช่องไฟ) · EvidencePanel (พื้นย้อม + ขนาดบรรทัด) · OfficialChannelsBlock (ช่องไฟ) · ShopProfile (แท็บ/กริด)
