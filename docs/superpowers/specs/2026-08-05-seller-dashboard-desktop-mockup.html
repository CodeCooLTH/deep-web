Seller Dashboard — เดสก์ท็อป (ดึง widget ที่เคยตัดทิ้งกลับมา)

ครอบเฉพาะบล็อก hidden lg:block ของ src/app/(paces)/seller/(dashboard)/dashboard/page.tsx — มือถือ (Command Center v10) ไม่แตะ ทุกการ์ดในหน้านี้ประกอบจาก component ของ theme/paces/Admin/TS/src/app/(admin)/dashboard/ecommerce/ ตามที่ระบุใต้การ์ด

ตัวเลขทั้งหมดเป็นข้อมูลสมมติ ของร้านตัวอย่าง “บ้านสวนกาแฟ” ไม่ได้ต่อฐานข้อมูลจริง — ใส่ไว้เพื่อดูว่าเลขไทย/ชื่อสินค้าไทยยาว ๆ ลงกล่องแล้วหน้าตาเป็นยังไง

1 สรุปสิ่งที่เปลี่ยน

9 widget ของ theme ecommerce ตอนนี้ใช้จริงแค่ 4 ที่เหลือถูกตัดตั้งแต่ยุค MVP ด้วยเหตุผล “ไม่มี real data source” ซึ่งหมดอายุไปแล้ว — ตารางนี้คือสิ่งที่ตรวจเจอในโค้ดวันนี้

widget ของ theme ตอนนี้ แหล่งข้อมูลจริงที่มีแล้ว ในแบบใหม่
UserCardใช้อยู่shop.name + trust scoreคงเดิม (แถว 1)
StatisticCard ×3ใช้อยู่getOrdersByShop, countsAsRevenueคงเดิม (แถว 1)
SalesReportใช้อยู่getSalesSeries()คงเดิม แต่ย้ายลงแถว 3
RecentOrderใช้อยู่getOrdersByShopคงเดิม (แถว 4)
StorePerformanceOverviewตัดทิ้งOrder.salesChannel = STOREFRONT / FACEBOOK / LINE / TIKTOK / OTHER — และมี SalesChannelBadge.tsx ที่กำหนดสีต่อช่องทางไว้แล้วดึงกลับ → “ช่องทางการขาย”
TopSellingProductsตัดทิ้งgetBestSellerProducts() — ใช้บนมือถืออยู่แล้ว (BestSellerStrip)ดึงกลับ → “สินค้าขายดี”
RecentActivityตัดทิ้งgetRecentActivity() รวม 5 แหล่ง mask PII แล้ว + RecentActivityFeed.tsx เขียนเสร็จนอนอยู่ในโฟลเดอร์ ไม่มีใคร importดึงกลับ → “กิจกรรมล่าสุด”
RevenueByLocationตัดทิ้งOrder.shippingAddress (Json) มีจังหวัด + public/data/thai-address.json 77 จังหวัดดึงกลับ → “ยอดขายตามจังหวัด” (ECharts geo · รายจังหวัด)
WeeklyPerformanceInsightsแทนแล้ว—คง AchievementLevel ไว้ตามเดิม

ตัวตนร้านนำ → งานค้าง → กราฟ → รายการ — ต่างจาก theme ตรงที่ OrderStatusBand (ของเราเอง ไม่มีใน theme) ได้แถวเต็มความกว้างเป็นแถวที่ 2 เพราะเป็นแถวเดียวในหน้าที่ “กดแล้วมีงานให้ทำต่อ” และแผนที่ลงล่างสุดในฐานะข้อมูลประกอบ

สิ่งที่ต้องเขียนกำกับตอน commit — theme วาดการ์ดนี้ด้วย jsvectormap การเปลี่ยนไป ECharts เบี่ยงจาก Base: จึงต้องระบุเหตุผลในคอมมิต และเช็ค Hard Rule 10 ว่าการวาดผ่าน wrapper นับว่าผ่าน gate (grep gate จับ from 'echarts' ตรง ๆ — เรียกผ่าน wrapper จึงไม่ชน)
ขนาดไฟล์ — GeoJSON 77 จังหวัดตัวเต็ม 1.19MB ต้องลดจุดก่อนใช้ (เวอร์ชันในภาพนี้เหลือ ~52KB และยังเห็นขอบจังหวัดครบ) โหลดแบบ dynamic import เฉพาะตอนการ์ดเข้าจอ
ร้านที่ไม่ใช่ประเภทขายออนไลน์ — vertical ≠ ONLINE_SALES ไม่มีการ์ดนี้เลย และออเดอร์ salesChannel = STOREFRONT ไม่ถูกนับเข้าแผนที่ (ไม่ใช่ไปโผล่เป็น “ไม่ระบุจังหวัด”) ยอดบนหัวการ์ดจึงเป็น รายได้จากการจัดส่ง ไม่ใช่รายได้รวมทั้งร้าน
