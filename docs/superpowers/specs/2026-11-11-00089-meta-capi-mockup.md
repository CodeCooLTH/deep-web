# ม็อกอัพ 00089 — ส่งยอดขายให้ Meta

ไฟล์: `2026-11-11-00089-meta-capi-mockup.html` (เปิดตรงในเบราว์เซอร์ได้เลย ไม่ต้อง build) · ปุ่มบนหัวสลับหน้าจอ 1 / 2 / 3 / ทั้งหมด และสลับ light/dark ได้
ทุกหน้าวาด 3 เฟรม: Desktop 1280 · Tablet 768 · Mobile 390 · โครง CSS ลอกจากม็อกอัพ 00078 (สกิน Paces)

## แต่ละหน้าแสดงอะไร

### 1) รายการเพจ `/settings/conversions-api`
- **1** ตารางเพจ Messenger 4 แถว ครบทุกสถานะ: ส่งอยู่ + บรรทัดแดง "ชุดข้อมูล 1 ตัวหยุด" · หยุดเพราะ token เสีย + ปุ่ม "เชื่อมเพจใหม่" · ส่งอยู่ปกติ (ตัวเลข 1,248,305) · ปิด + "ยังไม่มีชุดข้อมูล" (สวิตช์กดไม่ได้)
- Desktop เป็นตาราง มี sidebar กลุ่ม SETTING ต่อจาก "ช่องทางการขาย" (D1) · Tablet 768 กับ Mobile ต่ำกว่า 1024 จึงเป็นเชลล์มือถือ (ไม่มี sidebar มีแถบล่าง) แถวกลายเป็นการ์ดรายการ
- **1b** ว่าง (ยังไม่มีเพจ Messenger) · **1c** Swal ยืนยันตอนเปิดเพจครั้งแรก (D5)

### 2) รายละเอียดเพจ `/settings/conversions-api/[channelId]`
- **2** หน้าหลัก: หัวเพจ + สวิตช์หลัก · banner แดง (ชุด "เว็บไซต์ร้าน" แบบกรอกเองหยุด → ข้อความชี้ไปปุ่ม "เปลี่ยน token" ไม่มีปุ่มซ้ำ) · การ์ดชุดข้อมูล 2/3 (อัตโนมัติจากเพจ + กรอกเอง) · แผงเพิ่มชุดข้อมูลแบบ inline มี 2 ตัวเลือก (เลือกแบบกรอกเองไว้ เห็นฟอร์ม) · Test Event Code + ปุ่ม "ทดสอบ" + ผลสำเร็จ inline · เหตุการณ์ 12 ตัว 3 กลุ่ม มีแท็บเลือกชุดข้อมูล (ชื่อไทย + ชื่อ Meta เช่น "ซื้อ (Purchase)") · แผง "ตั้งยอด" ของ Purchase กางอยู่ (ยอดสุทธิ / ไม่รวม VAT + แนบรายการสินค้า) · จังหวะส่ง Purchase (สร้าง/ยืนยัน/ชำระครบ) + สวิตช์ "นับออเดอร์ร่างที่ยืนยันแล้ว" · กฎแท็ก → Lead ("เมื่อติดแท็ก X ส่งมูลค่า Y บาท") มีแถวใหม่ที่ยังไม่บันทึก · การ์ดผลการส่ง 7 วัน
- Desktop: grid 2/3 + 1/3 (ขวา sticky) · Tablet/Mobile: คอลัมน์เดียวตามลำดับใน spec · มือถือ ผลการส่งยุบเป็นแถวเดียวแตะได้
- **2b** สถานะอื่น: banner แบบอัตโนมัติจากเพจ (มีปุ่มเชื่อมเพจใหม่) · ผลทดสอบ 4 แบบ (กำลังส่ง / token ใช้ได้ / Meta ไม่รับ token / ไม่มีห้องแชท) · สวิตช์หลักปิด · Lead เปิดแต่ไม่มีกฎ · ครบ 3 ชุด · ไม่มีชุดข้อมูล · ร้านไม่มีแท็ก

### 3) บันทึกการส่ง `/settings/conversions-api/[channelId]/log`
- **3** 9 แถว ครบ 4 สถานะ (รอ / สำเร็จ / ล้มเหลว / ข้าม) พร้อมเหตุผลภาษาไทยตามตารางแปลใน spec · ตัวกรองสถานะ + เหตุการณ์ (Desktop วาดตอนเปิดเมนูสถานะ เลือก "ล้มเหลว") · แบ่งหน้า (มือถือ = ก่อนหน้า/ถัดไป)
- **3b** ว่าง 2 แบบ (ยังไม่มีบันทึก / กรองแล้วไม่พบ)

## มติใน spec ที่ม็อกอัพนี้สะท้อน
| มติ | ที่เห็นในม็อกอัพ |
|---|---|
| D1 เมนูอยู่กลุ่ม SETTING ต่อจาก "ช่องทางการขาย" | sidebar desktop ทุกหน้า |
| D3 อยู่ `(dashboard)` มี sidebar/แถบล่าง | ทุกเฟรม |
| D4 สวิตช์บันทึกทันที · กฎแท็กกดบันทึกชัด ๆ | กฎมีปุ่ม "บันทึกกฎ"/"ยกเลิกการแก้" ตอนมีแถวค้าง |
| D5 ไม่ใช้ modal เป็นตัวเลือกแรก | เพิ่มชุดข้อมูล · ตั้งยอด · ผลทดสอบ = inline · Swal เฉพาะเปิดเพจครั้งแรก |
| D6 Test Event Code ไม่บันทึกถาวร | ช่องอยู่คู่ปุ่ม "ทดสอบ" เท่านั้น ไม่มีปุ่มบันทึก · helper บอกผลตามค่าที่ใส่ |
| D7 "ส่งอยู่" ไม่ใช่เขียว | ส่งอยู่ = primary-ink · เขียวมีแค่ badge "สำเร็จ" ใน log กับผลทดสอบผ่าน |
| ไม่มีตัวเลือก "ไม่รวมค่าส่ง" (PRD Q5) | แผงตั้งยอดมีแค่ ยอดสุทธิ / ไม่รวม VAT |
| หน้า log ไม่มีปุ่มส่งซ้ำ | ไม่มี |
| Dataset ID ไม่ใช้ font-mono | ใช้ tabular-nums |

## คำถามที่ต้องให้ user ตัดสิน
1. **ชื่อเมนู:** ใช้ "ส่งยอดขายให้ Meta" (ม็อกอัพใช้ตัวนี้ ลดศัพท์เทคนิค) หรือ "Conversions API" (ร้านที่ยิงแอดอาจค้นด้วยคำนี้) · URL เป็น `conversions-api` ทั้งสองแบบ
2. **เพจที่บางชุดข้อมูลหยุด:** ม็อกอัพแสดง "ส่งอยู่" + บรรทัดแดง "ชุดข้อมูล {n} ตัวหยุด" (หน้า 1 แถวแรก และหัวหน้า 2) — โอเคไหม หรืออยากได้สถานะที่ 4 แยก (เช่น "ส่งบางส่วน")

## ตรวจกับโทเคนใน DESIGN.md — จุดที่ไม่ตรง
ตรงกับ DESIGN.md: primary `#236dc9` (ไม่มีม่วง `#7367F0` ทั้งไฟล์) · คู่ `-ink` ทุกตัว (primary `#1e3a8a` · success `#065f46` · warning `#92400e` · danger `#7f1d1d` · info `#1e40af`) บนพื้น `/15` · semantic `#02bc9c` / `#f9bf59` / `#f7577e` · พื้น `#f6f7fb` · หมึก `#4c4c5c` · การ์ด radius 4px + เงา `0 1px 4px rgba(130,143,163,.15)` · Swal ใช้ `--shadow-lg` `0 4px 16px rgba(76,76,92,.2)` · หัวการ์ดเส้นประ 1px · padding การ์ด 20px · กล่องในการ์ด `rounded-lg` (8px) + p-3 (ท่า callout 12/10) · ฟอนต์ Anuphan ตัวเดียว · ไม่มี emoji · ไม่มี uppercase กับไทย

จุดที่ไม่ตรงหรือ DESIGN.md ไม่ได้ระบุ:
1. **badge กลาง (ปิด / ข้าม / อัตโนมัติจากเพจ / กรอกเอง)** — spec ให้ `bg-default-100` แต่ค่าที่ใช้ในม็อกอัพชุดนี้ (`#f6f7fb`) แทบมองไม่เห็นบนการ์ดขาว จึงใช้ `default-200` (`#eef2f7`) แทน · ต้องเช็คค่าจริงของ `bg-default-100` ใน Paces ตอน build
2. **ปุ่ม soft primary "เชื่อมเพจใหม่"** — spec เขียน `text-primary` ม็อกอัพใช้ `text-primary-ink` ตามกฎ `-ink` (ข้อความบนพื้น `/15`)
3. **สเกลเทา `default-50…900` และค่า dark mode** ลอกจากม็อกอัพ 00078 · DESIGN.md frontmatter มีแค่ `paces-surface` กับ `paces-body-ink` ไม่ได้ระบุสเกลนี้
4. **placeholder** ใช้ `default-500` (`#58626b`) แทนค่า theme `default-400` เพื่อผ่าน 4.5:1 (ตาม Impeccable ข้อ 3 ใน spec)
5. **ค่า arbitrary ในไฟล์ม็อกอัพ** (`w-[245px]` sidebar · `h-[65px]` topbar · `h-[72px]` แถบล่าง · `max-w-[240px]` ชื่อเพจ · `shadow-[var(--shadow-lg)]` เมนูกรอง) ใช้เลียนเชลล์เท่านั้น · ตอน build ต้องใช้ตัวแปร/โทเคนของ Paces (HR7)
6. **ขอบเฟรมอุปกรณ์** (radius 14px · เงา `rgba(0,0,0,.08)`) · พื้นหน้า `#e9ebf0` · ป้ายเหลือง "ร่างเพื่อพิจารณา" = กรอบของม็อกอัพ ไม่ใช่ของหน้าจริง · ฉากหลัง Swal `bg-black/45` เป็นค่าของ Swal เอง
7. **น้ำหนัก 600** ใช้กับ badge/หัวข้อ (ท่าเดียวกับ 00078 และ `.badge` ของ Paces) · ramp ใน DESIGN.md ประกาศ 400/500/700
8. **สิ่งที่ม็อกอัพเพิ่มเองนอก spec** (ขอให้ยืนยัน): แถวกฎที่ยังไม่บันทึกมีพื้น `primary10` + ข้อความ "มีกฎที่ยังไม่บันทึก 1 แถว" ท้ายการ์ด · ปุ่ม "เพิ่มชุดข้อมูล" เปลี่ยนเป็น tonal ตอนแผงเปิด (ให้ "ตรวจและบันทึก" เป็นปุ่มทึบเดียว) · ไอคอนบนปุ่ม (`send` ทดสอบ · `adjustments-horizontal` ตั้งยอด · `device-floppy` บันทึกกฎ · `history` ดูบันทึก)
9. **ไอคอนนอกรายการที่ spec ยืนยัน**: `loader-2` · `check` · `chevron-down` · `filter-off` · `question-mark` · `device-floppy` · `adjustments-horizontal` — ทุกตัวมีใช้ใน `src/` อยู่แล้ว (grep แล้ว) · โลโก้ Messenger บนอวตารใช้ `logos:messenger` แทน ตอน build ใช้ `getChannelDisplay('MESSENGER')`
10. Tablet ใช้ 768 ตามที่ team-lead สั่ง (ม็อกอัพ 00078 ใช้ 834)
