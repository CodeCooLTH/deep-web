## การตัดสินใจ

| ของ | ทำอะไร | เหตุผล |
|---|---|---|
| ชื่อหน้าใน `PageBreadcrumb` | **ซ่อนเฉพาะมือถือ** (prop `compactMobileTitle`, default `false` ⇒ ไม่กระทบ 71 ผู้เรียกอื่น) | หัวแอปพิมพ์คำเดียวกันเป๊ะห่างกัน 40px ไม่ให้ข้อมูลใหม่ และเป็นตัวที่เบียด ‹ › · ≥768px คืนกลับ (ที่นั่นไม่มีหัวแอป) |
| ป้ายเดือน | **กดได้** — `form-select` เลือกเดือนตรง | ดูหัวข้อถัดไป |
| "ข้อมูล ณ …" | **ย้ายไปท้ายหน้า** ไปรวมกับ "นับจากคำสั่งซื้อ N ใบ" | เป็น *ข้อควรรู้ของตัวเลขที่ดูจบแล้ว* ไม่ใช่สิ่งที่ต้องรู้ก่อนดู · **ไม่ตัดทิ้ง** ยังเจอได้ทุกครั้งที่เลื่อนจบ |
| "นับทุกออเดอร์ที่ยังไม่ถูกยกเลิก…" | 🛑 **อยู่ที่เดิม ห้ามย้าย** | หน้านี้ใช้นิยาม "ขายแล้ว" **ต่างจาก `/sales`** ตัวเลขจึงไม่ตรงกันโดยตั้งใจ ย้ายไปท้ายหน้า = ผู้ใช้อ่านตัวเลขจบก่อนรู้นิยาม แล้วสรุปว่าระบบคำนวณผิด (HR16) |
| ช่องติ๊ก 2 ตัว | **ชิปแถวเดียว** | เดิมกิน 92px (44+4+44) · ชิปแบบเดียวกับ `ReportFilters.tsx` และปุ่มหน่วยบนหน้านี้เอง ไม่ใช่ท่าใหม่ · คำสั้นลงได้เพราะพื้นทึบบอกอยู่แล้วว่ากำลังกรอง (คำเต็มอยู่ใน `aria-label`) |
| padding การ์ด | 🛑 **ไม่แตะ** | `.card-header` 20/15px · `.card-body` 20px คือโทเคนที่การ์ดทุกใบในหลังบ้านใช้เหมือนกัน ลดเฉพาะหน้านี้ = การ์ดหน้านี้แปลกกว่าที่อื่น |
| ความสูงกราฟมือถือ | 240 → **200** | ให้กราฟจบในจอแรกพร้อมสินค้า |

### 🛑 "padding เยอะไป" — ตัวการไม่ใช่ padding

ไล่ค่าทุกจุดแล้ว **ไม่มีที่ไหนใช้ค่านอกบันไดของธีมเลย** ตัวที่กินพื้นที่จริงคือ
**จำนวนแถวที่บังคับความสูง 44px ซ้อนกัน** (ช่องติ๊ก 2 แถว = 92px สำหรับตัวกรอง 2 ตัว)
⇒ แก้ที่โครงสร้างเนื้อหา ไม่ใช่ที่ค่า padding

### "วันที่กดยาก" — ตัวจริงคือกระโดดข้ามเดือนไม่ได้

ปุ่ม ‹ › มี `min-h-11 min-w-11` **ผ่านเกณฑ์ 44px อยู่แล้ว** — ตัวที่เป็นปัญหาคือ
**ป้ายเดือนตรงกลางเป็น `<span>` กดไม่ได้** ⇒ จะย้อนไป ก.พ. 2569 ต้องกด ‹ **หกครั้ง**

แก้เป็น `form-select` (HR6: ค่าที่ bind กับ `?month=`) — **32 ตัวเลือก**
(ม.ค. 2567 ถึงเดือนนี้ · เลขมาจาก `MIN_MONTH_ISO = '2024-01'` จริง ไม่ได้เดา)
ปุ่ม ‹ › **คงไว้ไม่แตะ** (เดินทีละเดือนยังเป็นท่าที่ใช้บ่อยสุด)

### 🛑 กับดักที่ต้องเลี่ยงตอน implement

ความสูงกราฟ **ตั้งใน `responsive[]` ไม่ได้** — `ApexChart` wrapper เขียนว่า
`height={height ?? options.chart?.height}` ⇒ **prop ชนะ options เสมอ**
จะวาดที่ความสูงหนึ่งแต่กล่องสูงอีกอย่าง แล้วกราฟถูกตัด (เคยเกิดบน prod จนแท่งค่าน้อยหาย)
⇒ ต้องส่งความสูงจากฝั่ง React ตามจอ
