## 3. แนวทาง A — ปรับบน Paces เดิม (แนะนำ)

### รายการ
- **ไทล์ 4 ตัว** (OrdersStatCard): กำลังตาม · ข้อความที่ส่ง · ลูกค้าตอบกลับ % (บอกตัวตั้ง/ตัวหาร "88 จาก 302") · ส่งไม่สำเร็จ (ลิงก์ไปแท็บประวัติ)
- ตาราง ≥1024 มี 5 คอลัมน์ ชื่อตรงกับเนื้อหา: **บอท** (ชื่อ + ชิปสถานะการขาย/แท็ก + ส่งต่อ) · **ช่องทาง** (รูปเพจ 1 รูป + ไอคอนแพลตฟอร์มซ้อนมุม + ชื่อเพจครั้งเดียว + "Messenger · Instagram") · **รอบ** (จำนวน · เวลารวม + ชิปเวลา + ธงจบ) · **ผล 7 วัน** (3 ตัวเลข + แถบเล็ก) · **สถานะ** (สวิตช์)
- **สวิตช์ในแถว** ปิด↔เปิดใช้ (ยืนยันด้วย Swal `activateTitle` เดิมก่อนเปิด) · บอทโหมด "ทดสอบ" ไม่มีสวิตช์ ขึ้น badge + ลิงก์ "เปิดใช้จริง…" ที่เปิดกล่องยืนยัน เพราะ TESTING ต้องเลือกแชททดสอบ ทำในแถวไม่ได้
- เลิกแสดงข้อความรอบแรกในแถว (ย้ายไปดูในฟอร์ม/ตัวอย่าง)
- <1024: การ์ด 1 คอลัมน์ (มือถือ) / 2 คอลัมน์ (แท็บเล็ต): ชื่อ + สวิตช์ · ชิป + ไอคอนแพลตฟอร์ม · แถบตัวเลข 3 ช่อง · รางรอบ + ปุ่ม `>` — **การ์ดไม่เป็นลิงก์ทั้งใบอีกแล้ว** (มีสวิตช์อยู่ข้างใน ห้ามซ้อน interactive) ชื่อบอทกับปุ่ม `>` เป็นลิงก์

### ฟอร์ม
- 4 การ์ดตามลำดับ: **1 ทักใคร · 2 ส่งทางไหน · 3 ส่งอะไร เมื่อไร · 4 เมื่อจบ** — วงกลมเลขกลายเป็นเครื่องหมายถูก (success) เมื่อส่วนนั้นครบตาม `draftIssues` (ตรงกับ validation ไม่ใช่เดา)
- **ส่วนที่ 4 "เมื่อจบ"** เป็นประโยคเติมคำ 2 แถว: "ลูกค้าตอบกลับ บอทหยุด แล้วส่งต่อให้ [แอดมิน▾]" · "ตามครบแล้วยังไม่ตอบ รอ [1][วัน▾] แล้ว [ปิดงาน▾]" + พับ "บอทหยุดเองเมื่อไร" (4 ข้อเดิม)
- ส่งทางไหน: **รวมตามเพจ** 1 แถวต่อเพจ/OA มีปุ่มแพลตฟอร์มแบบเลือกได้ (Messenger / Instagram) · ช่องที่ชนกับบอทอื่นล็อกพร้อมบอกชื่อบอท
- ส่งอะไร เมื่อไร: **แถบเวลาสะสม** บนสุด (สัดส่วนเวลาของแต่ละรอบเทียบกรอบ 7 วัน) · รอบที่พับ = แถวเดียว (เลข · รูปย่อ · ข้อความต้นแบบตัดบรรทัด) · **กางทีละรอบ** (เดิมกาง ≤3)
- คอลัมน์ขวา sticky ≥1024: การ์ด **"สรุปบอทนี้"** แบบ key-value 5 บรรทัด (แทนประโยคยาวเต็มกว้าง) + การ์ดตัวอย่างแชท (ของเดิม)
- มือถือ: หัวการ์ดของส่วนที่เสร็จแสดงค่าสรุปด้านขวา (เช่น "ยังไม่ซื้อ") · แถบบันทึกล่าง = ดูตัวอย่าง · ยกเลิก · บันทึก (อยู่เหนือ bottom nav ตามเดิม)

## 4. แนวทาง B — ตัวสร้าง automation (ยังอยู่บน token Paces)

### รายการ
- แถบกรวย 4 ช่อง: เข้าเงื่อนไข → ได้รับข้อความ → ตอบกลับ → ปิดงานอัตโนมัติ
- บอทละการ์ด: แถว flow `ทักใคร → รอบ 1…N → จบ` แต่ละโหนดรอบมี "ส่ง n · ตอบ n" และไฮไลต์ **รอบที่ได้ผลที่สุด** · มือถือย่อเป็นกราฟแท่ง "ลูกค้าตอบหลังรอบ" + 2 ตัวเลข
- บอทที่ปิดย่อเหลือหัวการ์ดบรรทัดเดียว

### ฟอร์ม
- ผืนผ้าใบจุด แนวตั้ง: โหนดเริ่ม (ทักใคร + ผ่านช่องทาง) → ป้ายรอ → โหนดรอบ → … → "+ เพิ่มรอบ" → แยก 2 ทาง (ลูกค้าตอบ → ส่งต่อแอดมิน / ไม่ตอบ 1 วัน → ปิดงาน)
- กดโหนด → **แผงขวา (≥1200)** หรือ **แผงล่าง (<1200, offcanvas)** แท็บ "แก้ · ตัวอย่าง"
- ข้อดี: เห็นทั้งบอทในจอเดียว, 2 ทางจบเข้าใจทันที · ข้อเสีย: เปลี่ยนโครงฟอร์มทั้งหมด, เทส form (`form.test.tsx`) ต้องเขียนใหม่มาก, แผงล่างบนมือถือ + คีย์บอร์ดไทย + contenteditable เสี่ยงซ้ำปัญหา iOS (memory: fixed overlay ไม่หดตามคีย์บอร์ด)

## 5. ข้อแนะนำ

**เลือก A** — แก้ปัญหาทุกข้อในตาราง §1 โดยไม่ทิ้งตรรกะที่มีเทสแล้ว (`src/lib/sales-follow-bot/ui.ts` ใช้ต่อได้ทั้งหมด) · แล้ว **ยืมจาก B 1 อย่าง**: ตัวเลข "ตอบหลังรอบไหน" ใส่ในหน้าแก้บอท (หัวการ์ดส่วนที่ 3) เมื่อ query พร้อม — เป็นตัวเลขที่ช่วยร้านตัดสินใจแก้รอบได้จริง

## 8. คำถามที่ต้องให้ user ตัดสิน

1. **A หรือ B?** (แนะนำ A + ตัวเลข "ตอบหลังรอบไหน" จาก B)
2. **สวิตช์ในแถว**: ยอมให้เปิดใช้จากหน้ารายการเลยไหม (มีกล่องยืนยันเดิม) หรือให้เปลี่ยนสถานะได้เฉพาะในฟอร์ม?
3. **นิยาม "ได้ผล"**: ใช้ "ลูกค้าตอบกลับ %" อย่างเดียวพอไหม หรืออยากได้ "ขยับเป็นเปิดบิล/ยืนยันแล้ว" ด้วย — อันหลังไม่มีข้อมูลตรง (`STAGE_CHANGED` ไม่เก็บว่าเปลี่ยนเป็นสถานะอะไร) ต้องเพิ่มคอลัมน์ = migration
4. **ช่วงเวลา**: 7 วันคงที่ หรือมีตัวเลือก 7/30 วัน?
5. **ตัวกรองแท็บประวัติ** (บอท/ผลการส่ง): มติเดิม BR-FB-71 = ไม่มีตัวกรอง — จะเปิดไหม?
6. **แบบตัวอย่างบอท** ในหน้าว่าง (ตามคนถามราคา / เปิดบิลยังไม่โอน / พัสดุมีปัญหา) — ทำหรือไม่ (เป็นของใหม่ ต้องมีเนื้อหาตั้งต้น)
7. รายการช่องทางของบอทที่ใช้ **หลายเพจคนละชื่อ**: แสดงรูปซ้อน ≤2 + "+N" แล้วชื่อเพจแรก (ตาม mockup แถวที่ 2 "+ LINE OA 1") โอเคไหม
