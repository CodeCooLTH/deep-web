5 · สิ่งที่จงใจไม่มีในหน้านี้

รายการนี้สำคัญเท่ากับสิ่งที่มี — เป็นข้อห้ามที่ Reviewer ต้องตรวจก่อน merge

สวิตช์ซ่อนคะแนนความน่าเชื่อถือ สวิตช์ซ่อนรีวิว สวิตช์ซ่อนยอดออเดอร์สำเร็จ สวิตช์ซ่อนป้ายยืนยันตัวตน toggle ซ่อนรายส่วน (สินค้า/บริการ/ห้องพัก/ช่องทาง)
เหตุผล (FR-014 + D-8): ถ้าซ่อนได้เป็นรายตัว มิจฉาชีพจะซ่อนเฉพาะตัวเลขที่แย่ แล้วตัวเลขที่เหลือทั้งหมดหมดความหมายทันที — การซ่อนจึงมีได้แค่สวิตช์เดียวระดับ "ทั้งหน้า" เท่านั้น (เห็นหมด หรือไม่เห็นเลย)

ชื่อร้าน / โลโก้ / ภาพปก / คำอธิบาย / หมวดหมู่ / ที่อยู่ → อยู่ที่ /shop เวลาทำการ · ลิงก์โซเชียล · CTA กำหนดเอง · แก้พิกัด → Phase 2
เหตุผล (D-7 + D-12): ไม่ทำฟอร์มซ้ำกับหน้าที่มีอยู่แล้ว และไม่ออกแบบ UI ให้ field ที่ยังไม่มีใน schema

6 · จุดที่ยังต้องเคาะก่อน implement

1. ชื่อลิงก์ใช้ขีดกลางหรือ underscore — Shop.slug เดิมใช้ a-z0-9- ส่วน User.username เดิมใช้ a-z0-9_ · mockup นี้ยึดขีดกลาง (ตาม D-3 ค่าเดิมที่มี _ ถูก grandfather ใช้ต่อได้)
2. พนักงาน (ADMIN) ปิด/เปิดการมองเห็นได้ไหม — FR-011 ไม่ได้เขียนข้อจำกัดสิทธิ์ไว้ · mockup นี้ตั้งสมมติฐานว่า OWNER เท่านั้น (น้ำหนักผลกระทบเท่ากับการแก้ชื่อลิงก์ซึ่งล็อก OWNER ชัดเจน)
3. ร้าน PERSONAL มีสวิตช์ปิดการมองเห็นด้วยไหม — mockup นี้ให้มีทั้ง 2 ประเภท
4. ชื่อคอลัมน์จริงใน DB — Shop.slug ใช้ต่อ หรือ field ใหม่ · คำเตือน "ไม่มี redirect ย้อนกลับ" ผูกกับพฤติกรรม backend จริง ต้อง sync กับ SDS ก่อนล็อก copy
