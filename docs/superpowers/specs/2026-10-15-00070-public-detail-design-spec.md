# ส่วน A: หน้า `/lr/[token]`

### User stories ที่ครอบ
US-LNK-1 ถึง 4 และ 6 (Must). US-LNK-7 ผ่านป้าย "รายงานทดสอบ". US-LNK-8 ผ่านลิงก์ท้ายหน้า.

### A1. ข้อมูลตัวอย่างที่ใช้ทั้งสเปก (ผลรวมตรง 49,200)

ร้าน BT Premium สุขสวัสดิ์ เป็นร้านบริการ, หัวรายงาน "รายงานยอดรายวัน" (`BASE_TITLE.DAILY`), วันที่ 14 ต.ค. 2569, snapshot 21:01, ผมสมมติให้ปิดงานแล้ว 2 ใบ.

| เวลา | ลูกค้า (สมมติ) | เบอร์ | ชื่องาน | ยอด | ก้อน (`serviceClosedAt`) | แกนการ์ด |
|---|---|---|---|---|---|---|
| 20:31 | คุณปรีชา วงศ์ทอง | •••-•••-318 | ติดตั้งกล้องหน้ารถ | 11,000 | รอปิดงาน | รอยืนยัน |
| 19:36 | คุณนภัส รุ่งเรือง | •••-•••-772 | เปลี่ยนยางหน้า-หลัง | 7,400 | รอปิดงาน | ยืนยันแล้ว |
| 18:55 | คุณสุดา แก้วใส | •••-•••-536 | ตั้งศูนย์ล้อ และอีก 1 รายการ | 7,900 | ปิดงานแล้ว | ยืนยันแล้ว |
| 17:30 | คุณธนากร ศรีสุข | •••-•••-204 | เปลี่ยนโช้คหลัง | 15,000 | ปิดงานแล้ว | ยืนยันแล้ว |
| 11:23 | คุณวิชัย มั่นคง | •••-•••-891 | ติดตั้งไฟหน้า | 7,900 | รอปิดงาน | รอยืนยัน |

- **ผลรวม**
  - ปิดงานแล้ว 22,900 (2 ใบ) + รอปิดงาน 26,300 (3 ใบ) = 49,200.
  - แกนการ์ดคือยืนยันแล้ว 30,300 + รอยืนยัน 18,900 = 49,200. แกนนี้ทำให้ตัวเลขการ์ด `รอยืนยัน 18,900` ไม่เท่า `รอปิดงาน 26,300` บนหน้า (Q-3 ยอมรับแล้ว). แถวรายใบจึงต้องมีทั้งสองแกน (§A6).
- **ค่าใช้จ่าย 6,394**
  - ค่าจ้างพนักงาน 3,500.
  - อื่นๆ 2,000 โน้ต "ค่าน้ำมัน".
  - อื่นๆ 500.
  - ค่าส่ง (จ่ายขนส่ง) 394 ระบบคิดให้.
  - ป้ายหมวดมาจาก `EXPENSE_CATEGORY_LABEL_TH` ซึ่งเป็น "ค่าจ้างพนักงาน" และ "อื่นๆ" (ไม่เว้นวรรค). คำ "เงินเดือน" ใน brief ไม่ตรง SSOT (HR16).
- **ตัวอย่างหลายร้าน**
  - ร้านที่ 2 "ร้านอะไหล่ BT ออนไลน์" (ร้านขายของ) ยอด 12,800 จาก 3 ใบ. ยืนยันแล้ว 9,500 (2 ใบ) + รอยืนยัน 3,300 (1 ใบ). ยกเลิก 1 ใบ. ไม่มีบันทึกค่าใช้จ่าย.
  - ผลรวมกลุ่ม 62,000, "รายการ 8", ยกเลิก 1 ใบ.

### A2. ตำแหน่งหน้า: ยืนยัน `(paces)` สาธารณะ

**เหตุผล**
- ผู้อ่านคือทีมร้านที่เพิ่งกดปุ่มสีน้ำเงิน `#236dc9` จากการ์ด. หน้าต้องเป็นน้ำเงินเดียวกัน. ม่วงคือผู้ซื้อ (HR7).
- `(marketing)` กำลังย้ายไป shadcn (00076) ที่ยังไม่ผ่าน user. หน้าใหม่ใน Vuexy/MUI ต้องรื้อทิ้งทีหลัง.
- RSC กับ Tailwind ไม่มี MUI/Emotion จึงเบากว่าบน in-app browser ของ LINE.
- มีแบบอย่างกลุ่มสาธารณะแล้ว: `seller/auth/layout.tsx`.

**สิ่งที่เอกสารไม่ได้เขียนและต้องจัดการ**
1. `(paces)/layout.tsx` ตั้ง `maximumScale:1, userScalable:false` ให้ทุกหน้า. ทีมร้านที่สายตาไม่ดีจะซูมตัวเลขไม่ได้ (WCAG 1.4.4).
   - ต้อง export `viewport` ใน `(public)/lr/layout.tsx`: `{ width:'device-width', initialScale:1, viewportFit:'cover', maximumScale:5, userScalable:true }`.
   - ต้องเขียน `maximumScale` กับ `userScalable` ให้ครบ เพราะ Next รวม viewport แบบ shallow merge (key ที่ไม่เขียนจะสืบทอดค่า `1`/`false` จาก root).
   - AGENTS.md บอกว่า API ของ Next เวอร์ชันนี้ต่างจากที่รู้ ให้อ่าน `node_modules/next/dist/docs/` ก่อนเขียน.
2. root layout mount `<Analytics/>` และ `<SpeedInsights/>` ทุกหน้า. NFR-LNK-2 กับ AC-05-7 ห้ามสคริปต์วิเคราะห์ในหน้านี้ และ token อยู่ใน path (R-6). ผมตรวจไม่ได้ว่า Vercel เก็บ path จริงหรือเก็บแค่ route pattern `/lr/[token]` → ส่งต่อ T8 (ดู Open questions).
3. `seller/layout.tsx` ใส่ `NavigationLoader`, `AppOAuthBridge`, `PaymentRestrictionProvider` ให้หน้านี้ด้วย. ไม่อ่าน session จึงไม่พัง. Developer ต้องยืนยันว่า `shouldHidePayments()` ไม่ต้องใช้ session.
4. ไม่ใช้ `AuthLogo`. มันห่อ `<Link href="/">` ซึ่งพาคนนอกทีมไปหน้า login และขนาดถูกล็อกใน `_auth.css`. ใช้ `<img>` ของ `src/assets/images/logo-deep-wordmark.png` ตัวเดียวกัน, `alt="Deep"`, `h-6 w-auto`, ไม่เป็นลิงก์.

### A3. รูปแบบเงินและวันที่ (ตัดสินพร้อมเหตุผล)

- **เงิน**
  - ไม่มี ฿ ในแถวและตัวเลขทั้งหน้า. ใช้ `money()` ที่ export จาก `flex-report-blocks.ts` ซึ่งคือ `noBaht(formatBaht(n))`.
  - เหตุผลคือภาษาเดียวกับการ์ดที่ผู้ใช้เพิ่งเห็น และตัวเลขใหญ่จะ render ไบต์เดียวกับการ์ด. Σ ในคอลัมน์ยอดเรียงตรงโดยไม่มีสัญลักษณ์.
  - **ข้อยกเว้นหนึ่งจุด:** ตัวเลขใหญ่ตามด้วยคำว่า "บาท" (ขนาดเล็กกว่า). หน้านี้เปิดแบบไม่มีบริบทของแชท ผู้อ่านสูงวัยต้องรู้หน่วย (PRODUCT.md §Accessibility). แถวและตารางไม่ใส่หน่วยซ้ำ.
- **วันที่**
  - ช่วงวันใช้ `rangeText()` จาก `flex-report-blocks.ts` → "14 ต.ค. 2569" ตรงหัวการ์ด.
  - เวลาใช้ `formatTimeHM()` + " น." สำหรับสเตมป์.
  - รายการข้ามวันใช้ `formatDayMonthTimeTH()` → "13 ต.ค. 11:23".
  - วันหมดอายุใช้ `formatDateTH()`.
  - ไม่ใช้ `formatDate`/`formatDateTime` (รูป dd-mm-yyyy) เพราะ AC-06-4 เขียนไว้ว่าให้ใช้ helper ในไฟล์ `format-date.ts`. ตัวที่เลือกอยู่ในไฟล์เดียวกัน และอ่านเหมือนหัวการ์ด.
- **กับดักวันหมดอายุ**
  - `expiresAt` เก็บเป็น 00:00 ของวันที่ 2 (exclusive).
  - ห้ามแสดง "หมดอายุ 16 ต.ค. 00:00". ให้แสดง "ใช้ได้ถึงสิ้นวันที่ 15 ต.ค. 2569" โดยคำนวณจาก `formatDateTH(new Date(expiresAt - 1))`.

### A5. สีและความหมาย (ภาษาเดียวกับการ์ด)

| ค่าใช้จ่าย | จุดหน้าหัวการ์ดค่าใช้จ่ายเท่านั้น (ตัวเลขเป็นหมึกเทา) | `bg-danger` | `FINANCE_COLORS.outflow` |
| ยกเลิก | ข้อความธรรมดา "ยกเลิก N ใบ" | `text-default-700` | การ์ดก็เป็นข้อความธรรมดา |

- **เขียว** ใช้เฉพาะ "ปิดงานแล้ว" ของร้านบริการ. เป็นความสำเร็จที่ร้านทำเองและยืนยันได้. ไม่มีเขียวบนสถานะที่ยังไม่ยืนยัน.
- **ร้านขายของ "ยืนยันแล้ว" เป็นน้ำเงิน ไม่ใช่เขียน.** ตรงกับแท่งน้ำเงินบนการ์ด ขัดกับ `FINANCE_COLORS.counted` (เขียว) ซึ่งเป็นผลของมติ user 2026-10-08. ให้เพิ่มรายการ `confirmed: { token:'primary', dot:'bg-primary', soft:'bg-primary/15', ink:'text-primary-ink' }` ใน `finance-colors.ts` เป็นบ้านเดียว และให้ `CONFIRMED_BAR` อ้างจากที่นั่น ไม่ใช่พิมพ์ซ้ำ (ดู Open questions).

### A6. รายละเอียดส่วนต่าง ๆ (prose)

**แถวรายการ: ข้อมูลและป้าย**
- ชื่อลูกค้า: `customerName` ถ้าไม่มี → "ลูกค้าไม่ระบุชื่อ" (E-10), ไม่เดาจากเบอร์.
- เบอร์: ใช้ `phoneMasked` ถ้า null ไม่แสดงบรรทัด (E-11) ไม่เขียน "ไม่ระบุ".
- **ร้านบริการมีสองแกน:**
  - ชิปหลัก (เติมสี) = ก้อน "ปิดงานแล้ว"/"รอปิดงาน".
  - marker ย่อย (ไอคอน+ข้อความ ไม่เติมสี) = แกนการ์ด "ยืนยันแล้ว" (`circle-check` น้ำเงิน) / "รอยืนยัน" (`clock` เหลือง-หมึก).
  - ใบ RETURNED ให้แทน marker ด้วย "คืนของแล้ว" (`arrow-back-up`).
- **ร้านขายของ/ที่พัก**: ก้อนกับแกนการ์ดเป็นอันเดียวกัน → ชิปเดียว "ยืนยันแล้ว" (น้ำเงินอ่อน) / "รอยืนยัน" (เหลืองอ่อน). RETURNED ใช้ marker "คืนของแล้ว".
- ถ้า `showSales=false`: ไม่มีคอลัมน์ยอดและไม่มีชิปก้อน. แสดงเฉพาะเวลา/ชื่อ/เบอร์/ชื่องาน.
- เวลาในแถว: วันเดียวแสดง `HH:mm`. ข้ามวัน (รายเดือน) แสดงสองบรรทัด "13 ต.ค." เหนือ "11:23" (`w-14`).
- ชื่องาน/ชื่อลูกค้ายาว: ห่อบรรทัดด้วย `min-w-0 break-words` ไม่ตัดด้วย `truncate` เพราะ 60/80 ตัวอักษรอ่านจบได้ และการตัดซ่อนข้อมูลที่ผู้อ่านต้องการตรวจ.

**ตัวเลขครบ/ไม่ครบ**
- ตัดเพดาน 150 แถว: ท้ายตารางแสดง `.card-footer` + `info-circle`: "แสดง 150 จาก 412 รายการล่าสุด ยอดรวมด้านบนนับครบทุกรายการ ดูรายการที่เหลือใน Deep" (partial-data-must-be-labeled-or-filled).
- `parity: 'MISMATCH'`: callout `role="status" bg-warning/15 text-warning-ink` ใต้หัวการ์ดรายการ: "รายการอาจต่างจากยอดรวมเล็กน้อย เพราะมีการแก้ไขระหว่างสร้างรายงาน".
- ใบยกเลิก: ไม่แสดงเป็นแถว (AC-LINK-04-4). แสดงเป็นจำนวน และเพิ่มท้ายคำอธิบายรายการ: "ไม่รวมใบที่ยกเลิก".

**ค่าใช้จ่าย**
- ส่วนนี้ไม่มีเลย (ไม่ใช่ซ่อน) ถ้า `exposure.expense=false` (E-14).
- `recorded=false` ∧ ยอด 0: หัวการ์ด "ค่าใช้จ่าย" ไม่มีตัวเลข, เนื้อหา "ร้านยังไม่ได้บันทึกค่าใช้จ่ายในช่วงนี้". ห้ามขึ้น 0 (BR-LGS-32).
- `recorded=false` ∧ มีแต่ค่าส่งระบบ: หัว "ค่าใช้จ่ายอย่างน้อย" (จาก `expenseDisplay`).
- บรรทัดระบบ: ใช้ถ้อยคำเดียวกับ `FinancePanels` ที่ใช้อยู่แล้ว: "ค่าส่ง (จ่ายขนส่ง)" กับ "ค่าส่งคืนสินค้า" พร้อมบรรทัดรอง "ระบบคิดให้". ไม่ตั้งคำใหม่ตามเอกสาร ("ค่าส่งขาไป (จากระบบ)") เพื่อไม่ให้คำเดียวกันมีสองชื่อ (HR16). แนะนำให้ย้าย 2 ป้ายนี้ไปไว้ที่ `src/lib/expense.ts` เป็นค่าคงที่.
- ข้ามวัน: แต่ละแถวมีวันกำกับ ("13 ต.ค.") เป็นข้อความรอง.
- ยอดค่าใช้จ่ายรวมระดับกลุ่ม: แสดงเป็นบรรทัดเล็กใต้จำนวนใน GROUP HERO เมื่อ `canSumProfit` ∧ ไม่มีร้าน ERROR เท่านั้น (BR-33). ถ้าไม่ได้ จะไม่มีบรรทัดนี้ ค่าใช้จ่ายอยู่ในร้านใครร้านมัน.
- OOS-6: ห้ามมี "ยอดขายหลังหักค่าใช้จ่าย" ในหน้านี้.

**ท้ายหน้า**
- "ลิงก์นี้ใช้ได้ถึงสิ้นวันที่ 15 ต.ค. 2569 เปิดได้โดยไม่ต้องเข้าสู่ระบบ ควรแชร์เฉพาะคนในทีม" (แนะนำ ไม่ห้าม).

### A10. ช่องว่างของ contract `DetailSnapshotV1` ที่หน้าต้องใช้ (ต้องล็อกก่อนขนาน)

ค่าที่ตัดสินใจ ณ จุดเขียน (value-fate-decided-at-write-site) ต้องอยู่ใน payload ไม่ใช่คำนวณตอน render:

1. **คำเรียกใบ** `orderWord` + `orderWordMixed` (จาก `reportOrderWord()`) และคำคอลัมน์ `itemColLabel` (จาก `resolveProductVocab`) ต่อร้าน. ร้านบริการเดี่ยวจะได้ "บริการ 5 รายการ" ตรงการ์ด. คำ "งาน" ใน brief ไม่ใช่ SSOT (`ORDER_VOCAB.SERVICE_QUEUE.nounShort = 'บริการ'`) ห้ามพิมพ์เอง.
2. **ค่า `status` ของแถว** ต้องเป็นป้ายตามแกนการ์ด (ยืนยันแล้ว/รอยืนยัน/คืนของแล้ว) ไม่ใช่ `OrderStatus` ดิบ. มิฉะนั้นใบ SHIPPED ที่การ์ดนับเป็นยืนยันแล้วจะขึ้นป้าย "กำลังจัดส่ง" ขัดกับหัว.
3. **`excludedReason`** ของร้าน EXCLUDED (LOCKED/DELETED/PURGED). การ์ดพิมพ์เหตุผล หน้านี้ต้องพิมพ์ได้เหมือนกัน.
4. **ธงสำหรับหัวกลุ่ม:** `mixedFinanceRules` + `window.fullDay` ใช้ตัดสินข้อความ "ยอดแต่ละร้านคิดตามกติกา…" และชื่อรายงาน.
5. **`kind`** อยู่ในแถวโครงเปล่าอยู่แล้ว. หน้า 410 ใช้ปรับคำสั่งแนะนำได้ (§A12).

### A11. User flow

1. กดปุ่มบนการ์ด (in-app browser ของ LINE) → โครง skeleton → หน้าสรุป. ไม่มี cookie/login.
2. อ่าน HERO (ยอดขาย + ที่มาของเงิน) → เลื่อนดูรายการ → ค่าใช้จ่าย.
3. หมดอายุ/ไม่พบ/ถูกจำกัด → การ์ดสถานะพร้อมวิธีไปต่อ (ไม่มี payload).
4. เจ้าของร้านกดลิงก์ท้ายหน้าไป Deep.

### B3. พฤติกรรม และ "ป้ายปุ่มต้องไม่โกหก"

ป้ายตั้งต้นของปุ่มคือ `"เปิด Deep"` (`DEFAULT_BUTTON_LABEL`). เมื่อปลายทางเป็นหน้าสรุป ป้ายนี้จะผิดความจริง. การแก้:

1. **ข้อความช่วยใต้ช่องป้าย** (ตอนนี้เขียนว่า "ปุ่มนี้เปิดหน้า Deep ของคุณเสมอ" ซึ่งจะเป็นเท็จ):
   - ปิด → คงเดิม.
   - เปิด → `ปุ่มนี้เปิดหน้าสรุปรายละเอียดของรอบที่ส่ง แก้ได้เฉพาะข้อความบนปุ่ม`
2. **แถบเสนอเปลี่ยนป้าย** เมื่อ `target==='DETAIL'` ∧ `label === DEFAULT_BUTTON_LABEL`: ใต้สวิตช์แสดงข้อความ `ป้ายปุ่มตอนนี้คือ “เปิด Deep” แต่ปุ่มจะเปิดหน้าสรุป` พร้อมปุ่มรอง `ใช้ป้าย “ดูสรุปรายละเอียด”` (`btn btn-sm bg-primary/15 text-primary hover:bg-primary hover:text-white min-h-11 lg:min-h-0`).
   - กดแล้วเปลี่ยนป้ายเป็น `ดูสรุปรายละเอียด` (16 ตัวอักษร ≤ `MAX_BUTTON_LABEL`).
   - **ไม่เปลี่ยนเอง** ป้ายเป็นของเจ้าของ และ `DEFAULT_BUTTON_LABEL` ห้ามเปลี่ยน (กระทบ golden).
3. **หัวแถวและบรรทัดสรุป**
   - เปลี่ยนหัวจาก "ปุ่มเปิด Deep" เป็น `ปุ่มท้ายข้อความ` (ไม่มีเทสผูกกับข้อความนี้ — ตรวจแล้วด้วย grep ใน `src`).
   - สรุปตอนพับ: ปิด `“เปิด Deep” · แสดง` / เปิด `“ดูสรุปรายละเอียด” · แสดง · เปิดหน้าสรุป` / ซ่อน `ซ่อนอยู่`.

# Impeccable compliance

- **Mode:** **Operate** (override register เป็น `product` ตาม `PRODUCT.md` เพราะเป็น `(paces)` ฝั่งผู้ขาย). ส่วนหน้า `/lr` มีน้ำหนัก Read: ผู้อ่านสแกนตัวเลขแล้วลงไปตรวจรายการ. เกณฑ์ตัดสินคือ scanability, ความสม่ำเสมอ, ความคุ้นเคย ไม่ใช่การแสดงออก. แบรนด์อยู่ในรายละเอียดที่แม่น: เลขหลักตรงกับการ์ด, สเตมป์ snapshot, ภาษาตรงไปตรงมา.
- **North star "The Trusted Counter":** หน้านี้คือสลิปสรุปของเคาน์เตอร์. ทุกตัวเลขต้องมีที่มาให้ตรวจ (แถบแบ่ง + รายการ + ค่าใช้จ่าย รวมกันได้ตรง) และบอกชัดว่าเป็นภาพ ณ เวลาไหน. ไม่ประกาศความน่าเชื่อถือ ใช้หลักฐานแทน.
- **One Voice:** accent น้ำเงินอยู่สามจุด (§A5) น้อยกว่า 10% ของจอ. พระเอกของหน้าคือเลข "ยอดขาย" ตัวเดียว `text-3xl` 700.
- **Verified-Means-Green:** เขียวเฉพาะ "ปิดงานแล้ว". "รอ…" ทุกชนิดเป็นเหลือง ไม่ใช่เขียวหรือแดง. แดงใช้กับ "ดึงข้อมูลร้านไม่สำเร็จ" และ error เท่านั้น. TEST ไม่แดง.
- **Sentence-case / ไทย:** ไม่มี `uppercase` (ตัดจาก theme).
- **Ink-tinted shadow:** ใช้ `.card` ของ Paces (เงาอมน้ำเงินเทา). ไม่มีเงาสีดำล้วน.
- **Anti-slop**
  - ไม่มี gradient text (ตัดจาก error page ของ theme).
  - ไม่มี eyebrow.
  - ไม่มีการ์ดซ้อนการ์ด (แถวเป็น `divide-y` ในการ์ด).
  - ไม่มี border ข้าง >1px.
  - ไม่มี placeholder จาง.
  - ไม่มี emoji.
- **น้ำเสียงข้อความ:** บอกทางออกทุก state (410 บอกคำสั่งที่พิมพ์, 429 บอกว่ารอเท่าไหร่, error บอกให้ลองใหม่). ไม่ใช้ "ไม่สามารถ…" หรือ "คุณไม่มีสิทธิ์". อธิบายเหตุโดยไม่กล่าวหา (429: "จากเครือข่ายนี้" ไม่ใช่ "คุณเปิดบ่อย"). พูดถึงลูกค้าเป็นกลาง ("ลูกค้าไม่ระบุชื่อ").

# Design decisions + rationale

- **ตัวเลขใหญ่คือประโยค ไม่ใช่ KPI tile.** จัดชิดซ้ายใต้ป้าย "ยอดขาย" มีคำว่า "บาท" กำกับ (Strong ไม่ใช่ Metric ตาม DESIGN.md) และแถบกับ legend ใต้มันคือหลักฐานของเลข ไม่ใช่การตกแต่ง. เลี่ยง hero-metric template.
- **แถวมือถือแบบ ledger:** เวลานำซ้าย. เหมาะกับการตรวจ "วันนี้ทำอะไรไปบ้าง" ตามลำดับเวลา.
- **ตารางจาก 768 ขึ้นไป** (ไม่รอ lg). 720px พอสำหรับ 5 คอลัมน์ และ iPad portrait ได้ layout ที่คิดแล้ว ไม่ใช่การ์ดมือถือยืดเต็ม.
- **ไม่มีตัวกรอง/ค้นหา/แบ่งหน้า** ตาม §10 (เห็นได้เฉพาะในแอป).
- **คำสั่งในหน้า 410 ระบุตาม `kind`:** รายเดือน → “สรุปเดือนนี้”. ใช้ได้เพราะแถวโครงเปล่าเก็บ `kind` ไว้.

# Open questions (ให้ Controller / developer)

1. **ปุ่ม "ยืนยันแล้ว" ร้านขายของ: น้ำเงิน (ตามการ์ด) หรือเขียว (ตาม `FINANCE_COLORS.counted`)?** ค่าตั้งต้นในสเปก = น้ำเงิน และเสนอเพิ่ม `confirmed` ใน `finance-colors.ts`.
2. **`<details>` แทน `hs-accordion` สำหรับพับร้าน** ไม่พบ theme match ขออนุมัติตาม Rule 1.
3. **Vercel Analytics + SpeedInsights ใน root layout** ส่งผลถึงหน้า `/lr` (NFR-LNK-2, R-6). ผมตรวจไม่ได้ว่าเก็บ path จริงหรือเก็บแค่ route pattern. ต้องให้ `safepay-security` (T8) ตรวจ และอาจต้องแยก layout ของ `(public)` ออกจาก root.
4. **ติด 5 ฟิลด์ใน contract (§A10)** ก่อนล็อกสัญญาข้อมูล.
5. **ตัวเลข "รอยืนยัน 18,900" บนการ์ดของร้านบริการ** ไม่อยู่บนหน้า. ผู้อ่านอาจถามว่าหายไปไหน. ค่าตั้งต้น = ไม่เพิ่ม (ชิปรายใบพอให้ตรวจ). ถ้าต้องการเพิ่ม ต้องเพิ่มฟิลด์ `confirmed/unconfirmed` ใน `DetailShop`.
6. **`focusCancel: true`** บน Swal ของ B ต่างจากพี่น้อง (`confirm-expense`/`confirm-profit`). ผมแนะนำให้ตั้งเพราะเรียกคืนไม่ได้. ถ้า Controller ต้องการให้เหมือนกันทุกตัว ให้ตัดออก.
7. **เปลี่ยนหัวแถว "ปุ่มเปิด Deep" → "ปุ่มท้ายข้อความ"** อยู่นอกถ้อยคำเอกสาร แต่จำเป็นเมื่อปลายทางไม่ใช่ Deep.
8. **คำแนะนำใน 410** ("พิมพ์ สรุปวันนี้…แล้วกดปุ่มบนการ์ด") จริงเฉพาะเมื่อเจ้าของยังเปิดตัวเลือกหน้าสรุปอยู่ ถ้าปิดไปแล้ว การ์ดใหม่จะไม่มีลิงก์. ต้องการให้หน้าเดาไม่ได้ จึงเขียนคำแนะนำเท่าที่จริงเสมอ ("เพื่อรับสรุปใหม่"). ยืนยันถ้อยคำนี้กับ product.
9. **`sticky` ของ HERO** ที่จอใหญ่ ตัดออกเพราะความสูง. ถ้าต้องการ ให้ย้ายค่าใช้จ่ายไปท้ายคอลัมน์ขวา แล้ว HERO อย่างเดียว sticky.
10. **`ORDER_STATUS_META.CONFIRMED.label = 'สำเร็จ'`** ขัดกับ "ยืนยันแล้ว" ของแกนการ์ดสำหรับ A-9 (SSOT ป้ายสถานะ). สเปกนี้ใช้ป้ายแกนการ์ดเป็นหลัก และใช้ `ORDER_STATUS_META.RETURNED` เฉพาะ "คืนของแล้ว". ต้องให้ product ยืนยันว่าถือเป็น SSOT เดียวกัน.
