> ม็อกอัพ: `2026-09-10-inbox-thread-agents-mockup.html` (เปิดในเบราว์เซอร์ · 3 จอ · ชี้เมาส์ที่กองรูปในคอลัมน์เดสก์ท็อปได้จริง)
> คำสั่ง user 2026-09-10: *"ใน chat lists อยากได้ icon (+ hover ชื่อ admin) ที่เข้าไปตอบในแชทได้ด้วย ถ้ามีมากกว่า 1 คน ก็เป็น profile ซ้อน ๆ กัน ไว้ตรงมุมขวาล่าง แต่ถ้ารายการไหนไม่มี admin ตอบเลย (เค้าตอบจากฝั่ง platform มา) ก็ไม่ต้องขึ้นเลย"*

## 1. ใครนับเป็น "แอดมินที่ตอบ"

🛑 **นิยามนี้มีอยู่แล้วตั้งแต่ feature 00059 ห้ามเขียนใหม่** — `src/lib/agent-performance.ts`

```
senderRole='SHOP' AND autoReplyKind IS NULL AND senderUserId IS NOT NULL AND isDeleted=false
```

| กรณี | `senderUserId` | ขึ้นกองรูป |
|---|---|---|
| แอดมินกดตอบใน Deep | มีค่า | ✅ |
| ตอบจาก Business Suite / แอป Messenger (echo) | `null` | ❌ |
| บอท / AI / ตอบอัตโนมัติ | `null` (ทุกตัวส่ง `actorUserId: null`) | ❌ |
| ข้อความที่ถูกลบ | — | ❌ |

ฝาแฝดของกฎนี้ชื่อ `unattributedShopReplySql()` ซึ่งคอมเมนต์เขียนไว้เองว่า *"คนตอบจาก Business Suite (ระบุตัวไม่ได้)"* — ตรงกับเคสที่ user สั่งว่าไม่ต้องขึ้นพอดี

กฎนี้ตอนนี้มี **3 รูปที่ต้องแก้พร้อมกันเสมอ** (วางติดกันตาม HR16): `isHumanAgentReply()` (TS) · `humanAgentReplySql()` (SQL) · `HUMAN_AGENT_REPLY_WHERE` (Prisma — เพิ่มรอบนี้)

## 3. หน้าตา

- **ตำแหน่ง** `absolute right:10px bottom:9px` ของแถว (มุมขวาล่าง ตามที่สั่ง)
- **ขนาด** 20px · ซ้อนเหลื่อม −7px · ขอบขาว 2px (รูปคู่สนทนาหลักคือ 40px จึงไม่แย่งสายตา)
- **ลำดับ** คนที่ตอบล่าสุดอยู่**หน้าสุด** — ใบหน้าสุดเห็นชัดที่สุด ควรเป็นคนที่เกี่ยวกับสถานะปัจจุบันของห้อง ไม่ใช่คนที่บังเอิญตอบเป็นคนแรกเมื่อเดือนก่อน
- **เกิน 3** โชว์ 2 ใบ + ชิป `+N`
- **ชื่อ** `≥1024px` ชี้ที่กองรูป → กล่องดำเหนือกองรูป · `<1024px` ไม่มี (user เลือกเอง)
- **ไม่มีแอดมินตอบ** ไม่วาดอะไรเลย ไม่มีที่ว่างจอง

## 4. ที่ต้องระวัง

✅ **ชุดปุ่มลอย ปักหมุด/ปิดงาน ถูกถอดออกทั้งก้อน** (user เคาะ 2026-09-10 ทาง A: *"ให้เอาออกดีไหม ให้เค้าไป คลิกขวาเอา"*) พร้อมลบ `ConversationRowMenu.tsx` ที่กลายเป็น dead code — `RowAction` ย้ายไปอยู่ `ChatContextMenu.tsx`

ไม่เสียความสามารถอะไรเลย: `ChatContextMenu` (คลิกขวา / กดค้าง) มี `RowAction` **ครบทั้ง 8 ค่าของ type** + สถานะขาย/แท็ก/กลุ่ม/เสียง ⇒ ชุดปุ่มลอยเป็น subset แท้ ๆ · และเมนู `⋯` เป็นเมนูตัวที่สองของแถวเดียวกันที่เนื้อหาไม่เท่ากัน = คำถามเดียวมีสองคำตอบ (HR16)

**ทำไมถึงไม่ใช่การกลับมติไปมา:** ตอนที่ชุดปุ่มถูกสั่งให้ทำ (2026-07-23) คลิกขวาเปิดได้เฉพาะเธรดช่องทางนอก และกดค้างบนมือถือยังไม่มี (มา 2026-08-06) — เหตุผลที่มันมีอยู่หมดอายุไปตั้งแต่ตอนนั้น
ที่เสียจริงมีข้อเดียวคือ **การค้นพบ** · อีก 2 ข้อที่ดูเหมือนจะเสียไม่จริง: เมนูเบราว์เซอร์บนแถวถูก `e.preventDefault()` ปิดตั้งแต่แรกอยู่แล้ว และชุดปุ่มเดิมเป็น `hidden` จนกว่าจะ hover ⇒ แท็บไปไม่ถึงเลย ขณะที่ปุ่ม Menu/Shift+F10 ยิง `contextmenu` ได้จริง

🛑 **ต้อง enrich ทั้ง 2 ทาง** — `enrichWithThreadAgents()` ต้องถูกเรียกทั้งใน `api/chat/conversations/route.ts` และ `inbox/page.tsx` (RSC หน้าแรก) เหมือน enrich ตัวอื่นทุกตัว ทำทางเดียว = กองรูปไม่ขึ้นตอนโหลดหน้าแรกแล้วค่อยโผล่หลัง refetch ซึ่งผู้ใช้อ่านว่าเป็นบั๊ก (บทเรียนเดียวกับ `enrichWithOrderStage`)

🛑 **แอดมินที่ถูกลบบัญชี** — `groupBy` คืน `senderUserId` ที่หา `User` ไม่เจอได้ ⇒ ข้ามไป ไม่วาดรูปเปล่าที่ hover แล้วไม่มีชื่อ

🛑 **a11y** — กองรูปต้องมี `role="img"` + `aria-label` รวมชื่อทุกคน ไม่ใช่ `aria-label` บน `<span>` เปล่า (`docs/conventions/aria-name-requires-supporting-role.md`) และ `title=` ใช้แทน tooltip ไม่ได้เพราะมือถือไม่มี hover
