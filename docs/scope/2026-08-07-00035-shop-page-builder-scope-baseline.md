# Scope Baseline — feature 00035 ตัวจัดหน้าร้าน (Shop Page Builder)

**วันที่ล็อก:** 2026-08-07 · **สถานะ:** DEPLOYED PROD (4 รอบ)
**เอกสาร:** `docs/20 - Features/00035 - Shop Page Builder/` (7/7) · retro `docs/retro/2026-08-07-feature-00035-shop-page-builder-retrospective.md`

## Goal

ผู้ขายเลือกและจัดลำดับสิ่งที่แสดงบนหน้าร้านสาธารณะของตัวเองได้ โดย **สัญญาณความน่าเชื่อถือยังซ่อนหรือแก้ไม่ได้เลย** — ให้ร้านเน้นจุดแข็งของตัวเองได้โดยไม่ทำให้ตัวเลขที่ผู้ซื้อใช้ตัดสินใจโอนเงินหมดความหมาย

## In-Scope

| # | รายการ | สถานะ |
|---|---|---|
| 1 | หน้า `/seller/public-profile/builder` ใน `(fullscreen)` — 2 คอลัมน์ คลัง 30% / canvas 70% | เสร็จ |

| 3 | จัด **บล็อกเหนือแถบแท็บ** (`ShopPageBlock`) — เหรียญตราเด่น 1 บล็อก ≤4 ใบ + โพสต์ Facebook รายโพสต์ | เสร็จ |
| 4 | เพิ่มบล็อกด้วยปุ่ม + **และ** ลากจากคลังมาวางใน canvas | เสร็จ (พิสูจน์ด้วย CDP input จริง) |
| 5 | สวิตช์เผยแพร่/ซ่อนหน้าร้านทั้งหน้า + หน้า "ปิดการแสดงผลชั่วคราว" (HTTP 200 ไม่ใช่ 404) | เสร็จ |

## Out-of-Scope (ตัดสินแล้ว ห้ามแตะโดยไม่เปิดมติใหม่)

| รายการ | เหตุผล |
|---|---|
| **รวม `/u` + `/b` เป็น handle เดียว** | เป็น feature 00034 เดิมที่จองเลขไว้ **แต่เลข 00034 ถูก session อื่นใช้ไปแล้ว** — ถ้าจะทำต้องจองเลขใหม่ |
| **ตัวจัดเรียงบนมือถือ** | desktop-only เฟสนี้ · ทางที่ ux ประเมินไว้แล้วคือแท็บสลับ 3 โหมด + ปุ่มลูกศร |
| **ซ่อน/ลบสัญญาณความน่าเชื่อถือรายส่วน** | ห้ามถาวร ไม่ใช่ "ยังไม่ทำ" — ถ้าซ่อนได้ทีละใบ ร้านที่มีปัญหาจะซ่อนเฉพาะตัวที่แย่ |
| **เพิ่ม/ลบ "บล็อกโครงหน้า" (ห้องพัก/ปฏิทิน/บริการ/สินค้า)** | ยังเป็นแท็บอัตโนมัติ ปรับได้แค่ตำแหน่ง — ไม่มีตัวแทนใน DB |
| **แก้เนื้อหาต้นทางจากในตัวจัดหน้าร้าน** | จัดแค่ "เลือก + ลำดับ" ของที่มีอยู่แล้ว |
| **เทมเพลตหน้าร้าน / ธีมสี** | จัดลำดับ+เนื้อหา ไม่ใช่ปรับ visual design |
| **โพสต์จากแพลตฟอร์มอื่น** | เฉพาะ Facebook (`FacebookPost`) — คลิปครอบ IG/TikTok/YouTube อยู่แล้วในฟีเจอร์เดิม |
| **canvas เป็น iframe ของหน้าจริง** | ลองแล้วตายสนิทบน prod · รื้อเป็น Paces-native · ห้ามกลับไปโดยไม่อ่าน `docs/conventions/cross-context-features.md` |

## Assumptions

1. ร้านที่ยังไม่เคยเปิด builder **ไม่มีแถว `ShopPageLayout`** → service ต้อง fallback `isPublished=true` เอง (zero-regression)
2. `tabOrder` เป็น **ลำดับ ไม่ใช่ allow-list** — คีย์ที่ไม่ได้ระบุไปต่อท้าย ไม่ได้หายไป
3. `badgeIds` ไม่มี FK จริง → ฝั่งอ่านรับผิดชอบกรอง dangling + `Badge.type='ACHIEVEMENT'` ทุกครั้ง
4. canvas เป็น **ภาพแทน** ที่ sync มือกับ `ProfileHero.tsx` — จะเพี้ยนเมื่อหน้าร้านเปลี่ยน จนกว่าจะทำข้อ 4 ใน Deferred

## Deferred → Phase 2

1. **รัน TestCase 136 เคส** — ยังไม่เคยรันสักเคส (integration ติดที่ฐาน local ยังไม่ apply migration)
2. **ยืนยันการลากบนโค้ดชุดล่าสุด** — หลักฐานที่มีมาจาก build ก่อน `97d3267e`
3. **ตัวจัดเรียงบนมือถือ**
4. **ให้ canvas อ่านโครงจาก SSOT เดียวกับ `ProfileHero`** แทน sync มือ
5. **เพดานลิสต์โพสต์** — endpoint รองรับ `?q=&cursor=` อยู่แล้วแต่ยังไม่ต่อ paging (ร้านที่มีโพสต์ 300 อันได้ลิสต์ 300 อัน)
6. **historical-handle redirect** (ถ้าทำ 00034 ต่อ)
