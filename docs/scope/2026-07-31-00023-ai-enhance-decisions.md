# AI Enhance — สิ่งที่ user ตัดสินใจแล้ว (feature 00023 Deep Chat-Bot Assistant)

> บันทึกระหว่างออกแบบ 2026-07-31 · **ยังไม่เริ่มเขียนโค้ดส่วน AI** (user สั่งพัก)
> mockup ที่ผ่านการรีวิว 4 รอบ: `docs/superpowers/specs/2026-07-31-deepbot-ai-enhance-mockup.html`
> ไฟล์นี้คือวัตถุดิบของ Scope Baseline — ห้ามตีความใหม่โดยไม่ถาม user

## ชื่อเรียก (ตกลงแล้ว)

| ชั้น | ชื่อ |
|---|---|
| ฟีเจอร์ / เอกสาร | **Deep Chat-Bot Assistant** |
| เมนู + หน้าจอ | **ผู้ช่วยอัตโนมัติ** |
| บอทในห้องแชท | **DeepBot** |
| ความสามารถที่กำลังจะทำ | **AI Enhance** (เดิม user พิมพ์ "Enchant" — ยืนยันแล้วว่าสะกดผิด) |

`AI Enhance` เป็นคำที่ PRD §5 ของฟีเจอร์นี้ใช้อยู่ก่อนแล้วในหัวข้อ "เลื่อนไปเฟส 2"
คู่กับ "การตั้งค่าบุคลิก/น้ำเสียง AI" — งานรอบนี้คือการดึงของที่วางแผนไว้แล้วเข้ามาทำ

## ตัดสินแล้ว

1. **AI Enhance เป็น toggle รายกลุ่มคำ ไม่มีสวิตช์ระดับร้านเด็ดขาด** (ปฏิเสธ 2 ครั้ง)
   เปิดแล้วตั้งได้ต่อกลุ่ม: น้ำเสียง (4 แบบ) · กฎห้ามตอบ (list) · ขอบเขตข้อมูลสินค้า (ไม่ใช้เลย / เฉพาะที่เลือก / ทั้งหมด)
2. **ปุ่ม "คัดลอกจากกลุ่มอื่น"** แก้ปัญหาพิมพ์ซ้ำ — copy-by-value ไม่ผูกกลับต้นทาง
3. **คลังข้อมูลคำถาม-คำตอบ อยู่ในกลุ่มคำ** เป็นวิธีจับคู่แบบที่สอง
   (คำ = จับตรงตัว · คำถามตัวอย่าง = จับความหมาย) — **คำตรงตัวชนะก่อนเสมอ**
4. **จับคู่ด้วยข้อความล้วนก่อน** → เพิ่ม "ให้ AI เลือกจากรายการ" ทีหลัง → pgvector เมื่อคลังโตเกิน ~200 ข้อ/กลุ่ม
5. **ใช้โมเดล / โควตา / ตัวกรอง PII ร่วมกับ feature 00019** ไม่แยกระบบ
   (ตัวกรองที่ห้ามส่งเบอร์/อีเมล/ที่อยู่เข้า AI ถ้ามีสองชุดแล้วแก้ไม่ครบ = ข้อมูลลูกค้าหลุด)
6. **ชนกฎห้ามตอบ = ไม่ตอบเลย** แล้วส่งต่อคน ไม่ตอบเลี่ยง ๆ — เพราะข้อความที่ส่งไป Messenger แล้ว **ถอนคืนไม่ได้**
7. **AI ล่ม / ช้า / เครดิตหมด → ส่งคำตอบเดิมที่ร้านตั้งไว้ทันที** ลูกค้าต้องได้คำตอบเสมอ
8. **ตารางเวลา = เปิด/ปิดบอท** (ไม่ใช่สลับโหมดตอบ) — ในช่วงบอทช่วยตอบ นอกช่วงคนตอบเอง
   *(ทำเสร็จแล้ว S-04 commit `0749461d`)*
9. **แสดงเครดิตที่ใช้ในห้องแชททุกครั้งที่ AI ช่วยตอบ** + ต้องตรวจว่าเครดิตพอก่อนเรียก AI *(ข้อ 10 ด้านล่าง)*

## 10 · เครดิต — สิ่งที่ user สั่งล่าสุด และความเสี่ยงที่มากับมัน

**สั่งไว้ว่า:** ป้าย DeepBot ในห้องแชทต้องแสดงเครดิตที่ใช้ของการตอบครั้งนั้น
และระบบต้องตรวจก่อนว่าเครดิตพอไหม

**ระบบเครดิตที่มีอยู่แล้ว** (`ai-suggest-quota.service.ts` + `lib/ai-suggest-limit.ts`):
ร้านที่มี Business Package ACTIVE = ไม่จำกัดและไม่นับ · ร้านทั่วไป = ฟรีวันละ 10 ครั้ง
เกินแล้วหัก **฿1 ต่อครั้งจาก `SellerWallet`** (กระเป๋าใบเดียวกับค่า SMS)

**WARNING — ความเสี่ยงที่ไม่มีในฟีเจอร์ 00019 เดิม:**
ของเดิมพนักงานกดส่งเอง = จ่ายเมื่อตั้งใจจ่าย และเห็นยอดตรงหน้า
แต่ DeepBot **ตอบเองตอนไม่มีใครเฝ้า** ร้านที่มีลูกค้าทัก 200 คนในคืนเดียวอาจโดนหัก ฿200
โดยไม่มีใครรู้จนเช้า — ยิ่งตารางเวลาถูกออกแบบมาให้ทำงาน "ตอนแอดมินหลับ" พอดี

**ต้องออกแบบเพิ่ม (ยังไม่ได้ตัดสิน):**
- เพดานค่าใช้จ่ายต่อวัน/ต่อเดือนของ AI Enhance ที่ร้านตั้งเองได้
- แจ้งเตือนเมื่อเครดิตใกล้หมด **ก่อน**หมดจริง
- เครดิตหมดกลางดึก → บอทถอยไปส่งคำตอบดิบ (ข้อ 7) แต่ **ต้องไม่เงียบแบบไร้เหตุผล**
  ป้าย DeepBot ต้องบอกตรง ๆ ว่า "ไม่ได้ใช้ AI — เครดิตไม่พอ"
  มิฉะนั้นจะเป็นอาการ "ตั้งไว้แล้วไม่ทำงาน" ซ้ำรอยบั๊กที่เสียเวลาไล่ทั้งวันนี้
- ตรวจเครดิตต้องเกิด **ก่อน** เรียก AI ไม่ใช่หลัง — เรียกไปแล้วค่อยพบว่าเงินไม่พอ = จ่ายฟรี

## 11 · วิธีจ่ายเงิน (user ตัดสิน 2026-07-31)

**สองทางเลือก ร้านเลือกเอง:**

| ทาง | พฤติกรรม |
|---|---|
| **AI Credit** | หักเครดิตตามการใช้จริง ทุกครั้งที่ AI ช่วยตอบ |
| **Subscription รายเดือน** | ไม่จำกัดจำนวนครั้ง ไม่นับ |

ตรงกับโมเดลของ feature 00019 ที่มีอยู่แล้วทุกประการ (`isOwnerPaidPlan` → ไม่จำกัด;
ไม่มีแพ็กเกจ → โควตาฟรีรายวันแล้วหักจาก `SellerWallet`) — **ไม่ต้องสร้างกลไกใหม่**
ใช้ `ai-suggest-quota.service.ts` ต่อได้ตรง ๆ ตามข้อ 5

**ยังต้องยืนยัน:** "หักตามจริง" = หักต่อครั้งที่ตอบ (แบบ 00019 ฿1/ครั้ง) หรือ
หักตามต้นทุน token จริงที่ใช้ไป — สองอย่างนี้ต่างกันที่ตัวเลขบนป้าย DeepBot
ถ้าเป็นแบบหลังต้องเก็บ token usage ต่อครั้ง ซึ่งของเดิมยังไม่ได้เก็บ

**ยังต้องเคลียร์กับ PRD:** PRD §6 เขียนว่า core ฟรีตลอดไป — ต้องระบุให้ชัดว่า
AI Enhance เป็นส่วนเสริมที่คิดเงิน ไม่ใช่ core (เหมือน SMS ที่คิดเงินอยู่แล้ว)

## 12 · โมเดลที่ใช้ (user ตัดสิน 2026-07-31: "ปรับเป็นตัวเล็ก เน้นให้ตอบไวที่สุด")

**ทั้ง AI ช่วยร่าง (00019) และ DeepBot ใช้ `gemini-2.5-flash-lite` เป็นตัวแรก**
สายสำรอง: `2.5-flash-lite → 2.5-flash → 3.6-flash`

สองอย่างที่ทำแล้วและเป็นตัวชี้ขาดความเร็วจริง:
- **ปิดการ "คิด" ตามรุ่น** — 2.5 ใช้ `thinkingBudget: 0` (ปิดสนิท), 3.x ใช้ `thinkingLevel: "low"`
  (ปิดไม่ได้) · ห้ามส่งปนกัน เอกสารระบุตรง ๆ · ยืนยันผ่าน context7 2026-07-31
- **เรียงสายสำรองตามความเร็ว ไม่ใช่ความใหม่**

**สิ่งที่เหลือแล้วยังกดความเร็วได้อีก (ยังไม่ทำ):**
1. ลดจำนวนคำแนะนำจาก 3 เหลือ 2 หรือ 1 — ตัวที่เหลือที่มีผลจริงกับเวลารอ
2. แผงช่วยร่างยิง 2 รอบเรียงกัน (เช็คโควตา → ขอร่าง) รวมเป็นรอบเดียวไม่ได้เพราะ
   ด่านโควตาต้อง fail-closed ตาม BR-AIQ-12
3. streaming — ลดเวลา "รู้สึกว่ารอ" ไม่ได้ลดเวลาจริง

**ที่ควรแยกเรียกต่างหากตอนทำ AI Enhance:** ด่านตรวจกฎห้ามตอบ ควรเป็น prompt สั้น
ที่ตอบแค่ใช่/ไม่ใช่ (ไม่กี่ร้อย token) แยกจากการเรียบเรียง — ถ้ารวมเป็น prompt เดียว
เวลาบอทตอบผิดจะแยกไม่ออกว่าด่านตรวจพลาดหรือการเรียบเรียงพลาด

## คำถามที่ยังไม่มีคำตอบ (เรียงตามความเสี่ยง)

1. **งบเวลาที่ยอมให้ AI ใช้ก่อนถอยไปคำตอบดิบ** — ต้องเป็นตัวเลขจริง ไม่ใช่หลักการ
   (ทั้งฟีเจอร์ยืนบนสัญญา "ตอบภายในไม่กี่วินาที" ใน PRD)
2. **กฎห้ามตอบตรวจด้วยอะไร** — ข้อความอิสระอย่าง "ห้ามต่อรองราคา" ต้องให้ AI ตัดสิน
   ซึ่งพลาดได้ ยอมรับ false negative แค่ไหน มีชั้นสำรอง (denylist ง่าย ๆ) ไหม
3. ~~AI Enhance ฟรีหรือคิดเงิน~~ **ตอบแล้ว** → ดูข้อ 11 (เครดิตตามใช้จริง หรือ subscription = ไม่จำกัด)
   เหลือแค่ยืนยันว่า "ตามจริง" หมายถึงต่อครั้งหรือต่อ token
4. เพดานจำนวนคำถามในคลังที่โยนเข้า prompt พร้อมกัน (เสนอ 50 ข้อ/กลุ่ม)
5. รูปแบบไฟล์นำเข้า/ส่งออกคลัง (Excel หรือ CSV, คอลัมน์บังคับ)
6. รายการคำ "รับคำ" ที่กรองออกจากคิว — ตายตัวในโค้ด หรือร้านแก้เองได้

## ข้อจำกัดจริงที่ยืนยันจากโค้ดแล้ว

- **Messenger แก้/ถอนข้อความที่ส่งไปแล้วไม่ได้** — เราส่งออกได้ทางเดียวคือ `POST /me/messages`
  ส่วน `is_deleted` เป็นขาเข้าอย่างเดียว (ลูกค้าลบข้อความตัวเอง)
  → "แก้คำตอบ" = สอนไว้ใช้ครั้งหน้า UI ต้องแยก 2 ปุ่ม: **ส่งข้อความแก้ให้ลูกค้า** vs **สอนไว้ใช้ครั้งหน้า**
- **dev DB = prod DB** — migration ต้อง additive เขียนมือ + `migrate deploy` เท่านั้น
- **v3 baseline ยังไม่ปิด และแตะไฟล์เดียวกัน** (`KeywordEditorClient.tsx`) กับที่การ์ด AI Enhance ต้องไปอยู่
  → backend กับหน้าใหม่เดินขนานได้ แต่การ์ดในหน้าแก้ไขกลุ่มคำต้องรอ v3 ปิดก่อน
