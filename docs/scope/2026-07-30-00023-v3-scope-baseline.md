## Goal
ยกหน้า `/settings/auto-reply/[id]` จาก critique 25/40 ให้ผ่านตาม Design Spec V3 — ยุบการ์ด 4 ใบเป็น 3 ใบที่มีลำดับชั้นจริง โดยพระเอกคือ "บันไดคำตอบ" ที่ทำให้กลไก resolver มองเห็นด้วยตา พร้อมปิดช่องแก้/ลบเงื่อนไข, แทนเลข priority ดิบด้วยบล็อกคำซ้ำที่เลื่อนลำดับได้ และแก้ error mapping ที่ทำให้ผู้ใช้เห็น 500 แทนสาเหตุจริง — **โดยไม่แตะโมเดลข้อมูล**

## Non-goals
1. ไม่เปลี่ยนโมเดลข้อมูล — สถานะ 3 ค่า (`OFFLINE`/`TEST`/`LIVE`), `priority` int 0–1000, `matchType`, `specificity` คงเดิมทุกตัว (spec §1 "ล็อกแล้ว ห้ามเสนอเปลี่ยน")
2. ไม่เพิ่ม/แก้ endpoint หรือ Prisma schema — ใช้ route + schema ที่มีอยู่ทั้งหมด (`AutoReplyRuleUpdateSchema` / `AutoReplyKeywordUpdateSchema` — `src/lib/validations.ts:1164,1200`)
3. ไม่แตะปุ่มสถานะ 3 ค่าและสีของมัน (`KeywordEditorClient.tsx:311-326`) — เพิ่งทำให้ตรงกับหน้ารายการ (spec §12 ข้อ 5)
4. ไม่ทำให้สวิตช์ระดับร้านกลับมาในรูปแบบใด (ลบทั้ง UI + gate เมื่อ 2026-07-30)
5. ไม่ redesign หน้ารายการ `/settings/auto-reply` — ใช้เป็น SSOT ของชิป/ปุ่มสถานะเท่านั้น
