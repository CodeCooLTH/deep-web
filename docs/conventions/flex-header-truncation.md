# แถวเดียวที่ของล้น: wrap ตัดสินก่อนหด · งบพื้นที่ต้องคำนวณ · popover ยึด parent

> ที่มา: `docs/retro/2026-08-07-service-shipping-guard-and-chat-ui-retrospective.md`
> (หัวห้องแชทตกบรรทัด + แถบเครื่องมือล้นขอบจอ — user เจอเองบนมือถือ 2 อาการในวันเดียว)

## 1. `min-w-0` + `truncate` ครบ ไม่ได้แปลว่าของจะหด — ดู container ก่อน

**flexbox ตัดสินว่า item จะ wrap ไปบรรทัดใหม่ไหม จากขนาด hypothetical (เนื้อหาเต็ม *ก่อน* หด)**
ไม่ใช่จากขนาดหลัง shrink. ในคอนเทนเนอร์ที่เป็น `flex-wrap` การเติม `truncate`/`min-w-0` จึงไม่มีผล
กับการตัดบรรทัดเลย — มันทำงานหลัง browser ตัดสินใจ wrap ไปแล้ว

```diff
- <div className="card-header">          {/* Paces = flex flex-wrap */}
+ <div className="card-header flex-nowrap">
```

`.card-header` ของ Paces คือ `flex flex-wrap items-center justify-between gap-3` — หัวการ์ดทุกใบ
ในโปรเจกต์นี้จึงตกบรรทัดได้เมื่อเนื้อหาเต็มกว้างเกิน ไม่ว่าจะเขียน truncate ไว้ดีแค่ไหน

**เช็คลิสต์เมื่อ "ใส่ truncate แล้วยังไม่หด":**
1. คอนเทนเนอร์เป็น `flex-wrap` ไหม → ถ้าใช่ ปิด wrap ก่อน
2. มี `min-w-0` ครบทุกชั้นจากคอนเทนเนอร์ลงไปถึงข้อความไหม (flex item ค่าตั้งต้น `min-width:auto`)
3. มี item ไหนถูกล็อกความกว้างตายตัว (`max-w-56`, `w-48`) ที่กว้างกว่าที่ว่างจริงบนจอเล็กไหม —
   เพดานที่ตั้งไว้สำหรับเดสก์ท็อปคือสาเหตุที่มือถือพัง ให้ไล่ตาม breakpoint
   (`max-w-28 sm:max-w-40 md:max-w-48 lg:max-w-56`)
4. ที่ว่างจริงต่างกันตาม breakpoint เพราะปุ่มบางตัวโผล่/หายตามจอ (ปุ่มย้อนกลับ `lg:hidden`,
   ปุ่มข้อมูลลูกค้า `xl:hidden`) — คิดงบพื้นที่ **ที่ breakpoint ที่ปุ่มพวกนั้นยังอยู่**

## 2. แถวเครื่องมือที่มีปุ่มบังคับมีข้อความ: คำนวณงบพื้นที่ก่อนเสนอทางแก้

ก่อนตอบว่า "ย่อคำก็พอ" ให้กางเลขที่ **จอแคบสุดที่ต้องรองรับ (320px)**:

```
288px  = 320 − padding px-4 ทั้งสองข้าง
−242px = ปุ่มไอคอน 6 ตัว (btn btn-icon = 37px) + gap-1 (4px × 5)
------
  46px  เหลือให้ปุ่มที่กติกาบังคับว่าต้องมีข้อความเสมอ  → ไม่พอแม้แต่ไอคอนเปล่า
```

ตัวเลขบอกเองว่าการย่อคำแก้ไม่ได้ ต้อง **ลดจำนวนของที่โชว์** (ยุบเข้าเมนู `⋯`) แล้วค่อยย่อคำเป็น
ของแถม เกณฑ์เลือกว่าอะไรอยู่นอกเมนู = ความถี่การใช้จริง ไม่ใช่ลำดับที่เขียนไว้ในโค้ด

**ทางแก้ที่ไม่เลือกและเหตุผล:** ปล่อยแถวเลื่อนแนวนอน — ของที่อยู่นอกจอไม่มีสัญญาณบอกว่ามีอยู่
ผู้ใช้จะไม่รู้ว่ามีเครื่องมือมากกว่านี้ ต่างจาก `⋯` ที่ทุกคนรู้อยู่แล้วว่า "กดแล้วมีเพิ่ม"

**เก็บของไว้ให้จอใหญ่:** ยุบเฉพาะ `<768px` แล้วให้ `md:inline-flex` คืนปุ่มจริงทั้งหมดบนจอกว้าง —
ไม่ลดสิ่งที่เดสก์ท็อปเคยกดได้ในครั้งเดียว (จอกว้างมักมีปุ่มอื่นที่ `md:hidden` หายไปให้ที่ว่างพอดี)

## 3. popover ที่เป็น `absolute`: ซ่อน "ปุ่ม" ได้ ห้ามซ่อน "กล่องยึด"

แผงที่วางด้วย `absolute bottom-full` ยึดกับ **parent ที่มี `relative`** ไม่ใช่ portal — ถ้าเอา
`hidden md:inline-flex` ไปแปะที่ตัวกล่องยึด แผงจะหายทั้งก้อนที่ breakpoint นั้นทั้งที่ state
เปิดอยู่ (เงียบสนิท ไม่มี error)

```
✅ <div className="relative shrink-0">        ← กล่องยึด: อยู่ทุก breakpoint
     <button className="… hidden md:inline-flex" />   ← ซ่อนเฉพาะปุ่ม
     <button className="… md:hidden" />               ← ปุ่มแทนของจอเล็ก
     {open && <Picker />}                             ← แผงชุดเดียว ไม่ทำ 2 ชุด
   </div>
```

**หนึ่ง state หนึ่งแผง** — อย่าทำ markup 2 ชุดตาม breakpoint แล้วให้แต่ละชุดมีแผงของตัวเอง
(id ชนกัน, DOM ซ้ำ, drift ในอนาคต)

## 4. เมนูที่ประกอบเอง ต้องมีตัวปิดของตัวเอง

ดรอปดาวน์ที่ไม่ได้ขับด้วย Preline ไม่มี "แตะข้างนอกแล้วปิด" ให้ฟรี — ต้องวางฉากโปร่ง
(`fixed inset-0 z-10` ใต้เมนูที่ `z-20`) รับ tap เอง และรายการในเมนูต้องมี `min-h-11` เพื่อให้ได้
tap target 44px (ตัวเมนูเองไม่ใช่โมดัลเต็มจอ จึงไม่เข้าเกณฑ์ `useLockBodyScroll` ตาม
`docs/conventions/overlay-scroll-lock.md`)

## 5. `truncate` ในกล่อง `flex-wrap`: ต้องมี `min-w-0` **ที่กล่อง** และ `max-w-full` **ที่ลูก**

เกิดจริงบน prod 2026-08-12 (`/queues` ชีตคิวงานรายวัน) — ผู้ขายเปิดจอแล้วการ์ดถูกดันหลุดขอบซ้าย
จนอ่านชื่อลูกค้าไม่ได้ทั้งจอ

```tsx
// ❌ ดูเหมือนถูก — มี truncate ครบทุกตัว แต่ไม่หดจริง
<span className="mt-1 flex flex-wrap items-center gap-x-2">
  <span className="badge">นัดแล้ว</span>
  <span className="truncate text-2xs">Messenger · BT Premium Auto Xenon คลอง4 ธัญบุรี</span>
</span>

// ✅
<span className="mt-1 flex min-w-0 flex-wrap items-center gap-x-2">
  <span className="badge">นัดแล้ว</span>
  <span className="max-w-full truncate text-2xs">…</span>
</span>
```

`truncate` = `overflow:hidden` + `text-overflow:ellipsis` + `white-space:nowrap` — สามตัวนี้บอกว่า
"ถ้าล้นให้ตัด" **แต่ไม่ได้บอกว่ากล่องกว้างเท่าไร** flex item มี `min-width:auto` เป็นค่าตั้งต้น
ซึ่งแปลว่า "อย่าหดต่ำกว่าเนื้อหา" ⇒ ตัวหนังสือยาวจะ**ดันกล่องให้กว้างขึ้น**แทนที่จะถูกตัด
(ข้อ 1 ของเอกสารนี้พูดเรื่องการ *ตกบรรทัด* — ข้อนี้คือการ *ล้นออกข้าง* คนละอาการ สาเหตุใกล้กัน)

🛑 **ทำไมมันลามทั้งจอ ไม่ใช่แค่การ์ดใบเดียว:** กล่องแม่ที่เลื่อนได้ใช้ `overflow-y-auto`
และตามสเปก CSS **ถ้าแกนหนึ่งไม่ใช่ `visible` อีกแกนที่เป็น `visible` จะถูกคำนวณเป็น `auto` ให้เอง**
⇒ ลูกล้นแนวนอนแม้พิกเซลเดียว ทั้งกล่องกลายเป็น "เลื่อนข้างได้" แล้วผู้ใช้ปัดทีเดียวเนื้อหาทั้งชีต
เลื่อนหายไปนอกจอ โดยไม่มี error ไม่มี warning

**กันสองชั้นเสมอ** — ปิดต้นเหตุที่ลูก (`min-w-0`/`max-w-full`) **และ** ใส่ `overflow-x-hidden`
ที่กล่องเลื่อน ชั้นหลังไม่ใช่ของซ้ำซ้อน: มันกันลูกตัวที่ยังไม่มีใครเขียนในอนาคตด้วย

ทุกตัวมีอยู่จริงและสะกดถูก สิ่งที่ผิดคือ *ผลลัพธ์เชิงเรขาคณิต* · เห็นได้ทางเดียวคือเปิดจอจริงด้วย
