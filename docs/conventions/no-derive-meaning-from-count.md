# ห้าม derive ค่าที่มีความหมาย จาก "จำนวน"

> ที่มา: feature 00045 (เมนูลัดใน LINE) 2026-08-11 —
> `docs/retro/2026-08-11-line-rich-menu-00045-retrospective.md` P-1

## กฎ

🛑 **ถ้ามีสองค่าที่ *ต่างกันจริง* แต่ให้ตัวเลขเดียวกันได้ ห้ามเดาค่านั้นจากตัวเลข — ต้องเป็นคีย์ที่ถูกเลือก**
แม้วันนี้จะยังมีค่าเดียวก็ตาม

เกณฑ์ตัดสินเป็นคำถามเดียว: *"มีสองความหมายที่นับได้เท่ากันไหม"*

## เคสจริงที่ทำให้เกิดกฎนี้

เลย์เอาต์ของเมนูลัดถูก derive จากจำนวนปุ่ม (`layoutFor(count)`) ซึ่งถูกต้องสมบูรณ์ตราบใดที่
**เราเป็นคนกำหนดปุ่มเองทั้งหมด** พอเปิดให้ร้านอัปโหลดภาพของตัวเอง กลไกนี้พังทันที:

| เลย์เอาต์ | จำนวนช่อง | หน้าตา |
|-----------|-----------|--------|
| `top-1-bottom-2` | 3 | แถวบนเต็มแถว + แถวล่างแบ่งสอง |
| `row-3` | 3 | สามช่องเรียงนอนเท่ากัน |

**สองอันนี้มี 3 ช่องเท่ากัน แต่พิกัดพื้นที่กดคนละเรื่องกันสิ้นเชิง**

ผลถ้าปล่อยไว้: ภาพที่กราฟิกร้านออกแบบมาเป็นสามช่องเรียงนอน จะถูกวางพื้นที่กดเป็น T-split ทับลงไป
⇒ **ลูกค้ากดโดนช่องผิด** โดยที่:

- ร้านเห็นภาพของตัวเองถูกต้องทุกอย่าง
- `tsc` ผ่าน (ชนิดถูกทุกบรรทัด) · เทสเดิมเขียว · build ผ่าน · theme-guard ผ่าน
- ไม่มี error ไม่มี log ไม่มีอะไรผิดปกติให้เห็น
- กว่าจะรู้คือมีลูกค้าบ่นว่า "กดดูสินค้าแล้วมันโทรหาแอดมิน"

## ทำไมกฎนี้ไม่ชัดตั้งแต่แรก

ตอนเขียนรอบแรกมีคอมเมนต์กำกับไว้เองว่า *"ไม่รองรับ 5 ปุ่มเพราะจะมีช่องที่ขนาดไม่เท่าเพื่อน
ซึ่งเพิ่มโอกาสที่ภาพกับพิกัดไม่ตรงกัน"* — คิดถึงความเสี่ยง "ภาพไม่ตรงพิกัด" ไว้แล้วด้วยซ้ำ
แต่ไม่ได้เห็นว่า **ตัวกลไก derive-from-count เองคือช่องทางที่ทำให้ความเสี่ยงนั้นเกิด**

## วิธีที่ถูก

```ts
// ❌ เดาจากจำนวน — พังทันทีที่มีสองความหมายที่จำนวนเท่ากัน
const layout = layoutFor(buttons.length)

// ✅ คีย์ที่ถูกเลือก + allow-list + fail-closed
export const RICH_MENU_LAYOUTS = {
  'top-1-bottom-2': { rows: [1, 2], label: '1 บน + 2 ล่าง — 3 ช่อง' },
  'row-3':          { rows: [3],    label: '1×3 — 3 ช่องเรียงนอน' },
  // …
} as const
const layout = layoutRows(layoutKey)
```

และเมื่อแยกเป็นคีย์แล้ว **ต้องมีด่านตรวจว่าจำนวนตรงกัน** ด้วย — ไม่งั้นจะได้ "ช่องที่ไม่มี action"
(กดแล้วเงียบ) หรือ "ปุ่มที่ไม่มีช่อง" (หายไปเฉย ๆ) ซึ่งทั้งคู่เงียบสนิทเหมือนกัน:

```ts
if (buttons.length !== layoutCellCount(key)) throw new Error('RICH_MENU_BUTTON_COUNT_MISMATCH')
```

## ข้อยกเว้นที่ยังเดาได้

เดาจากจำนวนได้ **เฉพาะเส้นทางที่เราเป็นคนกำหนดข้อมูลเองทั้งหมด** และต้องเขียนกำกับไว้ว่าห้ามใช้
กับเส้นทางที่ข้อมูลมาจากผู้ใช้ — ในเคสนี้คือ `defaultLayoutKeyForCount()` ที่ใช้ได้เฉพาะโหมด
"ระบบสร้างเมนูให้" ซึ่งเราเป็นคนเลือกปุ่มเองทุกปุ่ม

## เทสที่ต้องมี

ต้องมีเทสที่ยืนยันว่า **สองค่าที่นับได้เท่ากัน ให้ผลลัพธ์ต่างกันจริง** — ไม่ใช่แค่เทสว่าแต่ละอันถูก:

```ts
it('[blocker] 1บน+2ล่าง กับ 1×3 มี 3 ช่องเท่ากัน แต่พิกัดต้องต่างกัน', () => {
  expect(layoutCellCount('top-1-bottom-2')).toBe(3)
  expect(layoutCellCount('row-3')).toBe(3)
  expect(layoutBounds(layoutRows('top-1-bottom-2'))).not.toEqual(layoutBounds(layoutRows('row-3')))
})
```
