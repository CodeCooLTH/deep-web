# รูปที่ user ส่งมา ต้องเปิดดูก่อนใช้ ไม่ใช่แค่ก๊อปเข้ารีโป

> เหตุการณ์ต้นเรื่อง: 2026-08-04 — user อัปโหลดโลโก้ขนส่ง 8 ไฟล์ให้แสดงในแถวออเดอร์
> ถ้าเอาไปวางตรง ๆ ด้วย class เดียวกันทั้งชุดจะได้ของแหว่ง 2 แบบพร้อมกัน (`f3ff5768`)

## เช็ค 3 อย่างก่อนเขียน class

```bash
file -b <ไฟล์>                    # ได้ format + ขนาดจริง
ls -la <ไฟล์>                     # ขนาดไฟล์
```
แล้ว **เปิดดูภาพจริง** (Read tool อ่านรูปได้) — metadata บอกไม่ได้ว่าพื้นหลังสีอะไร

| เช็ค | ทำไม | ถ้าไม่ตรงต้องทำอะไร |
|---|---|---|
| **สัดส่วน** จัตุรัสไหม | `object-cover` ในกรอบจัตุรัสจะ **ครอปด้านยาวทิ้ง** — โลโก้ 2:1 จะเหลือแต่กลางคำ อ่านไม่ออก | ใช้ `object-contain` (โลโก้จัตุรัสยังเต็มกรอบเท่าเดิม เพราะ contain = cover เมื่อสัดส่วนตรงกัน) |
| **พื้นหลัง** โปร่งใส / ขาว / สีทึบ | พื้นขาวบนการ์ดขาว = ขอบหายไปเลย ดูเหมือนโลโก้ลอยไม่มีกรอบ | ใส่ `ring-1 ring-default-200` **ให้ทุกใบ** ไม่ใช่เฉพาะใบพื้นขาว (ความสม่ำเสมอสำคัญกว่า) |
| **ขนาดไฟล์** | รูปหลาย MB ในลิสต์ที่มีหลายสิบแถว = โหลดช้าจริง | ขอไฟล์เล็กลง หรือย่อก่อน commit |

## กฎอื่นที่มาคู่กัน

- **ห้ามไปหารูปโลโก้แบรนด์จากอินเทอร์เน็ตมาใส่เอง** — ทั้งเรื่องสิทธิ์ในภาพ และเรื่องที่หน้าจอต้องไม่พึ่ง
  โฮสต์นอกที่เราคุมไม่ได้ (ล่มเมื่อไหร่ UI แหว่งทันที) ถ้าไม่มีไฟล์ → ถาม user
- **ห้ามเดาสีแบรนด์มาทำ badge แทนโลโก้** — ชนกฎห้าม hardcode สีนอก token (Hard Rule 7)
  ใช้ตัวย่อบนพื้นกลาง ๆ (`bg-default-100`) แทนได้ระหว่างรอไฟล์
- **ค้นไฟล์ที่ user เพิ่งอัปโหลด ให้ `ls` ทั้งโฟลเดอร์ก่อนค่อย filter** — คนตั้งชื่อไฟล์เลี่ยงอักขระพิเศษ
  เสมอ (`J&T` → `jandt-express.png`) ตั้ง grep จากชื่อแบรนด์แล้วจะรายงานผิดว่า "ไม่มีไฟล์"
- **แมปที่ระดับแบรนด์ ไม่ใช่รายรหัส** — ผู้ให้บริการมักมีหลายแพ็กเกจต่อแบรนด์ (Flash 6 แบบ,
  KEX 2, ไปรษณีย์ไทย 2, DHL 2) แมปรายรหัสแปลว่าต้องเติมใหม่ทุกครั้งที่เขาออกแพ็กเกจ แล้วของใหม่
  จะตกไปเป็น fallback เงียบ ๆ โดยไม่มีใครรู้ — ดู `src/lib/iship/courier.ts`
