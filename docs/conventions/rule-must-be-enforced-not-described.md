# กฎที่ "เขียนไว้" ยังไม่ใช่กฎที่ "บังคับได้"

> เหตุการณ์จริง 2026-08-11 — feature 00037 เขียน AC-06-6 ไว้ครบใน 3 ที่ แต่ด่านนั้น
> **ไม่เคยถูกสร้างขึ้นมาเลย** ผลคือออเดอร์ที่คีย์จากเธรดของอีกร้านลงร้านผิดเงียบ ๆ บน prod

## เกิดอะไรขึ้น

กฎเดียวกันถูกเขียนไว้ 3 ที่ ทุกที่ถูกต้องทุกตัวอักษร:

| ที่ | ข้อความ |
|---|---|
| `00037/BRD.md` AC-06-6 | "บันทึกรายการที่ร้านของร่างไม่ตรงกับร้านของเธรด → **ปฏิเสธ**" |
| `00037/PRD.md` FR-UNI-06 | "ร่างออเดอร์พก `shopId` ติดตัว และถูกปฏิเสธถ้าไม่ตรงกับเธรด" |
| `DraftOrderProvider.tsx:48` | "`shopId` ที่ส่งไปกับ POST ต้องมาจากค่านี้ค่าเดียว **ห้ามผสมกับ activeShopId เด็ดขาด**" |

ในโค้ดจริง: `OrderCreateForm` รับ prop `shopId` มาแล้ว **โยนทิ้ง** (`shopId: _shopId`) และ
`POST /api/orders` ไม่มีพารามิเตอร์ให้ใส่ด้วยซ้ำ — ไม่มีบรรทัดไหนบังคับกฎนั้นเลย

`TestCase.md` B-24 บันทึกไว้เองว่า *"ถูกปฏิเสธ (ยังไม่มีวิธี repro จากหน้าจอ — ต้องยิง API ตรง)"*

## กติกา

### 1. ก่อน mark AC ว่าเสร็จ ต้องชี้ได้ 2 อย่าง

- **โค้ดบรรทัดไหน** บังคับกฎนี้
- **เทสตัวไหน** ที่แดงถ้าเอาบรรทัดนั้นออก (พิสูจน์ด้วย mutation จริง ไม่ใช่เชื่อว่าเทสครอบ)

ของที่ **ไม่นับ** ว่าเป็นการบังคับกฎ:
- คอมเมนต์ที่อธิบายกฎ (ต่อให้เขียนดีแค่ไหน)
- prop/ตัวแปรที่ส่งมาแล้วไม่ถูกใช้ — โดยเฉพาะที่ตั้งชื่อขึ้นต้นด้วย `_` เพื่อปิดปาก linter
- type/`as` cast ที่ประกาศว่าค่ามีแน่ ๆ (`as { id: string }`) — cast บอกเครื่องมือว่า "ไม่ต้องดูตรงนี้"

### 2. 🛑 "ยังไม่มีวิธี repro" ในเอกสารเทส = ธงแดง ไม่ใช่หมายเหตุ

แปลว่า **"ไม่เคยทดสอบ"** ทางออกมี 2 ทางเท่านั้น: เขียนเทสอัตโนมัติที่ยิงชั้นที่ repro ได้จริง
(route/service) หรือประกาศตรง ๆ ว่า AC ข้อนั้นยังไม่เสร็จ — **ห้ามปล่อยให้อยู่ในสถานะกำกวม**
เพราะ checklist ที่มีข้อกำกวมปนอยู่จะถูกอ่านว่า "ครบแล้ว" ทุกครั้ง

### 3. เทสที่สแกนซอร์สต้องจับ "การเรียก" และ "การถูกนำไปใช้"

```ts
expect(src).toContain('resolveFoo')        // ❌ เขียวได้จากบรรทัด import อย่างเดียว
expect(src).toContain('resolveFoo(')       // ✅ ต้องเป็นการเรียกจริง
expect(src).toMatch(/target\s*[:=]\s*resolveFoo\(/)  // ✅ และผลต้องถูกเอาไปใช้
```

เกิดจริงในวันเดียวกัน: ด่านกัน drift รุ่นแรกเช็คแค่ชื่อ แล้ว **เขียวอยู่ทั้งที่โค้ดถูกเปลี่ยน
เป็นค่าคงที่** จับได้เพราะรัน mutation ไม่ใช่เพราะอ่านทวน

### 4. สแกนจากซอร์สจริง ไม่ใช่รายชื่อไฟล์ที่ hardcode

ด่านที่ไล่ตามรายชื่อจะไม่เห็นไฟล์ที่เขียนขึ้นทีหลัง — ตัวอย่างที่ถูก:
`src/lib/__tests__/session-user.test.ts` grep ทั้ง `src/app/` ห้ามเหลือแพตเทิร์นเดิม

### 5. ห้ามมี carve-out ในด่าน ถ้าเลี่ยงได้

ตอนไล่ปิด 58 จุด มี 4 จุดที่ "เสียหายเบากว่า" (ternary ที่คืน `undefined`) — เลือกแปลงให้หมด
แทนการยกเว้น เพราะ **carve-out คือที่ที่ของกลับมาซ่อน** และทำให้ด่านตอบว่า "0" ไม่ได้อีกต่อไป
