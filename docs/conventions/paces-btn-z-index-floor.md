# `.btn` ของ Paces เป็น `z-index: 10` อยู่แล้ว — `sticky … z-10` จึงแพ้ปุ่ม

**สรุปกฎ:** element ที่เป็น `sticky`/`fixed` ใน `(paces)/**` **ห้ามใช้ `z-10` หรือต่ำกว่า**
ต้อง `z-20` ขึ้นไป · บังคับด้วย `src/lib/__tests__/paces-sticky-z-index.test.ts`

---

## ข้อเท็จจริงที่เป็นต้นเหตุ

ธีม Paces ตั้งไว้ในนิยามของ `.btn` เอง:

```css
@layer components {
  .btn {
    z-index: 10;
    position: relative;
    /* … */
  }
}
```

🛑 **ต้องอ่านจาก CSS ที่คอมไพล์แล้ว ไม่ใช่จากซอร์สธีม** — `grep ".btn {" src/assets/css/` หา
ไม่เจอ เพราะ `.btn` ถูกประกอบผ่าน `@layer` + ไฟล์ config ของสกิน วิธีที่ได้คำตอบจริงคือดึงไฟล์
CSS ที่ dev server เสิร์ฟ แล้วอ่านตรงนั้น:

```bash
curl -s http://seller.deepth.local:3000/auth/sign-in | grep -o 'href="[^"]*\.css[^"]*"'
curl -s "http://seller.deepth.local:3000/_next/static/chunks/<ไฟล์>.css" -o /tmp/app.css
python3 -c "import re;css=open('/tmp/app.css').read();i=css.find('.btn {');print(css[i:i+900])"
```

## ทำไมมันพัง

`position: relative` + `z-index: 10` = **ทุกปุ่มในแอปลอยอยู่ที่ชั้น 10 โดยไม่มีใครเขียนสั่ง**

หัวหน้าจอที่เขียน `sticky top-0 z-10` จึงได้ค่า **เท่ากัน** กับปุ่มทุกตัวในเนื้อหาที่เลื่อนอยู่
ข้างล่าง · เมื่อ `z-index` เสมอกัน CSS ตัดสินด้วย **ลำดับใน DOM** ⇒ ปุ่มที่อยู่ทีหลังชนะ

⇒ เลื่อนหน้าจอลงไป ปุ่ม/ชิปจะลอยขึ้นไปทับชื่อหน้าและปุ่มย้อนกลับ

## เกิดจริง

**2026-08-23 · `/products/new`** — user ส่งภาพจากมือถือมา: ชิปราคาแนะนำ `฿49 ฿99 ฿199 …`
(ซึ่งเป็น `<label class="btn">`) ลอยทับคำว่า "เพิ่มสินค้าใหม่" และปุ่มย้อนกลับ

`FullscreenPageHeader` เขียน `sticky top-0 z-10` มาตั้งแต่วันแรก ⇒ **ทุกหน้าที่ใช้หัวนี้มีอาการ
เหมือนกันหมด** (`/products/new`, `/products/[id]/edit`, `/orders/new`, ตัวจัดหน้าร้าน) แค่ไม่มี
ใครเลื่อนไปเจอตำแหน่งที่มีปุ่มพอดี

## 🛑 ทำไมไม่มี gate ไหนจับได้

`tsc` / `next build` / `eslint` / `theme-guard` ผ่านหมด — `z-10` เป็นคลาสที่ถูกต้องทุกตัวอักษร
สิ่งที่ผิดคือ **ค่ามันบังเอิญเท่ากับของที่ธีมตั้งไว้ให้** ซึ่งมองไม่เห็นจากไฟล์ที่กำลังแก้อยู่
ต้องเปิด CSS ของธีมถึงจะรู้ว่ามีพื้นอยู่ที่ 10

คลาสเดียวกับ `unlayered-css-beats-utilities.md` — กฎของธีมที่ชนะโค้ดเราเงียบ ๆ โดยที่คนเขียน
ไม่มีทางเดาได้จากบรรทัดที่ตัวเองพิมพ์

## ช่วงค่าที่ใช้ได้

| ชั้น | ค่า | ใคร |
|---|---|---|
| พื้นของปุ่ม | `10` | `.btn` (ธีมตั้งเอง) |
| หัว/แถบสติกกี้ในรายการ | `20` | `card-header sticky` ของ inbox/comments · แถบสรุปท้าย auto-reply |
| หัวหน้าจอ fullscreen | `30` | `FullscreenPageHeader` |
| ดรอปดาวน์ Choices | `40` | `safepay-overrides.css` (`!important`) |
| เปลือก fullscreen | `50` | `(fullscreen)/layout.tsx` |

🛑 **ห้ามดันหัวหน้าจอขึ้นไปถึง 40+** — ดรอปดาวน์ของ `<select>` ที่กางขึ้นบนจะถูกหัวทับแทน
= ย้ายบั๊กไปอีกที่ ไม่ใช่แก้ (ด่านเช็คทั้งพื้นและเพดาน)

## 🛑 ตัวที่ "ตอนนี้ยังไม่มีอาการ" ก็ต้องแก้

แถบสรุปท้ายหน้า auto-reply (`KeywordEditorClient`) เป็น `sticky … z-10` เหมือนกัน แต่ไม่เคยมีใคร
รายงาน เพราะมันอยู่ **ท้ายไฟล์** พอดี ⇒ ชนะไทเบรกด้วยลำดับ DOM

นั่นคือรอดด้วย *ตำแหน่งในไฟล์* ไม่ใช่ด้วย *z ที่ถูก* — วันที่มีคนแทรกปุ่มไว้หลังมัน หรือย้ายบล็อก
มันจะพังทันทีโดยไม่มีใครโยงกลับมาถึงเอกสารนี้ได้ ⇒ ด่านครอบทุกตัว **ไม่มี carve-out**
(`rule-must-be-enforced-not-described.md` — carve-out ในด่าน = ที่ที่ของกลับมาซ่อน)

## ตอนเขียนด่าน

ต้อง `stripComments()` ก่อนสแกน — ไฟล์ที่ **ทำถูกตามกฎ** คือไฟล์ที่เขียนคำอธิบายกฎนี้ไว้ด้วย
ซึ่งมีคำว่า `z-10` อยู่ในประโยค ⇒ ด่านที่ไม่ตัดคอมเมนต์จะแดงใส่คนที่ทำถูก แล้วจะถูกปิดทิ้ง
(รอยเดิม: grep gate ของ HR9 แดงค้างจากคำเตือนของตัวเอง 2026-08-02→03 ·
ด่าน `component-declared-in-render` 2026-08-12)

และต้องเทียบ **ทีละ `className`** ไม่ใช่ทั้งไฟล์ — ไฟล์เดียวมีทั้ง `sticky` (z สูง) และ
`absolute` (z-10 ซึ่งถูกต้องในบริบทของมัน) ปนกันได้ตามปกติ
