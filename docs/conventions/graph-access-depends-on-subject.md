# endpoint ของ Meta ที่ล้มเพราะ "ตัวตนของคนที่ถูกถาม" ไม่ใช่ "รูปคำขอ"

> เหตุการณ์ 2026-08-09 — คอมเมนต์ 141 ใบขึ้น "ผู้ใช้ Facebook" และรูปโปรไฟล์ในกล่องแชท
> ไม่เคยขึ้นเลยสักคน โดยมีคำอธิบายในโค้ดและใน `CLAUDE.md` ยืนยันว่า "ยิงไม่ได้" มาตั้งแต่ 00018

## สิ่งที่เกิดขึ้น

`getContactProfile` ฝั่ง Messenger มีคอมเมนต์เขียนไว้ว่า:

> ยิง `GET /{psid}` ตรง ๆ ไม่ได้ — Meta ตอบ 400 "cannot be loaded due to missing permissions"
> **ทุกชุด field**

คอมเมนต์นั้นถูกเขียนหลังทดสอบกับ **ลูกค้า** แล้วได้ 400 จึงสรุปว่าตายทั้งเส้น แล้วเปลี่ยนไปใช้
`/me/conversations?user_id=` ซึ่งให้ชื่อแต่ไม่ให้รูป — และ `avatarUrl` ทั้งระบบเป็น `null` มาตั้งแต่วันนั้น

วัดใหม่ด้วย token ตัวเดียวกัน เพจเดียวกัน:

| subject | ผล |
|---|---|
| ลูกค้า `37558899090391535` | 400 `code=100 subcode=33` |
| ลูกค้าสุ่มอีก 30 คน | 400 ครบ 30 |
| **เจ้าของแอป `28253571950934108`** | **200 พร้อม `profile_pic`** (ซ้ำได้ทั้ง 3 เพจ) |

endpoint ใช้ได้จริง — มันแค่ใช้ได้กับ **คนที่มี role บนแอป** เท่านั้น เพราะฟีเจอร์
`Business Asset User Profile Access` อยู่ที่ **Standard Access** ซึ่งเอกสาร Meta ระบุตรงตัวว่า
*"features with Standard Access are only active for app users who have a role on the app"*

## กฎ

🛑 **ก่อนสรุปว่า endpoint ของ Meta "ใช้ไม่ได้" ต้องทดสอบด้วย subject อย่างน้อย 2 ชนิด:
คนที่มี role บนแอป และคนที่ไม่มี** — ถ้าทดสอบแค่ชนิดเดียวแล้วเขียนคอมเมนต์ว่า "ยิงไม่ได้"
คอมเมนต์นั้นจะกลายเป็นข้อเท็จจริงปลอมที่ปิดทางคนถัดไป (ดู `docs/conventions/domain-term-single-definition.md`
ทิศกลับ: ข้อความในเอกสารที่อ้างพฤติกรรมของโค้ด/ระบบภายนอก ต้องยืนยันก่อนใช้เป็นเหตุผลที่จะ "ไม่ทำ")

🛑 **error ของ Graph ไม่บอกว่าอะไรเป็นตัวแปร** — `code=100 subcode=33` เขียนว่า *"Object with ID
'…' does not exist, cannot be loaded due to missing permissions, or does not support this
operation"* ซึ่งเหมารวม 3 สาเหตุที่ต่างกันสิ้นเชิงไว้ในข้อความเดียว อ่านแล้วเดาไม่ได้เลยว่า
ตัวแปรคือ subject ไม่ใช่ field/permission/endpoint — ต้องแยกตัวแปรด้วยการทดลอง ไม่ใช่ด้วยการอ่าน

🛑 **"โปรเจกต์อื่นทำได้" ไม่ใช่หลักฐานว่าสิทธิ์ต่างกัน** — เคสนี้ทีมข้างเคียง (GoChat V3,
app `27578841345134305`) แสดงรูปโปรไฟล์ได้จริงบนหน้าจอ แต่ตรวจแล้วแอปนั้น
`Business Asset User Profile Access` = `REJECTED / access_level: none` **เหมือนกันเป๊ะ** และขอ
scope น้อยกว่าด้วยซ้ำ. ที่เห็นรูปเพราะคนในจอคือ **นักพัฒนาที่กำลังทดสอบด้วยบัญชีตัวเอง** ซึ่งมี
role บนแอป — เทียบผลลัพธ์บนหน้าจอโดยไม่ดูว่า subject เป็นใคร จะสรุปผิดทั้งกระดาน

🛑 **ออกแบบให้ "วันที่สิทธิ์ผ่าน" ระบบลุกขึ้นเอง** — อย่าผูกเงื่อนไขดึงข้อมูลไว้กับสิ่งที่จะเป็น
จริงตลอดกาล. เงื่อนไขเดิม `ดึงโปรไฟล์เมื่อยังไม่มีชื่อ` แปลว่าวันที่ Advanced Access ผ่าน
จะไม่มีใครได้รูปเลยสักคน เพราะทุก contact "มีชื่อครบแล้ว" — ต้องแยกเงื่อนไขต่อ **ข้อมูลแต่ละชิ้น**
แล้วคุมด้วยรอบเวลา (`ExternalContact.avatarSyncedAt` + `AVATAR_RETRY_INTERVAL_MS`) ไม่ใช่
"ล้มแล้วเลิก" และไม่ใช่ "ไม่มีก็ลองทุกครั้ง" (อย่างหลัง = Graph call ต่อทุกข้อความของ 1,453 คน)

## ญาติกัน: URL ของ Meta หมดอายุเสมอ

`profile_pic` / `full_picture` / URL ไฟล์แนบ ฝังเวลาหมดอายุมาใน `oe=` — รูป IG ที่เก็บเป็น URL ดิบ
เมื่อ 5 ส.ค. กลายเป็น **HTTP 403** ตอน 9 ส.ค. แล้ว `<img onError>` ตกไปตัวอักษรย่อ **โดยไม่มีอะไรฟ้อง**
(ฐานมีค่าอยู่ · หน้าจอ render ถูก · ไม่มี error ที่ไหนเลย) ⇒ ทุกรูปจาก Meta ต้อง `mirrorRemoteImage()`
ลง storage เราแล้วเก็บเป็น **fileId** ไม่ใช่ URL. ค่าที่ขึ้นต้นด้วย `http` ใน `avatarUrl` ให้ถือว่า
"ยังไม่เรียบร้อย" และรอ mirror ใหม่ตามรอบ
