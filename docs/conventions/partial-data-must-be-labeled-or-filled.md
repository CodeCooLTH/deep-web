# ตัวเลขที่ยังมาไม่ครบ — ต้อง "บอก" หรือ "เติมให้เต็ม" ห้ามปล่อยครึ่ง ๆ

**เกิดจริง 2026-08-10** — ผู้ขายทักมาว่า *"ต้นทุนไม่ถูก วันที่ 9 ได้ 31 ออเดอร์ ขั้นต่ำออเดอร์นึงต้อง 34 บาทแล้ว มันน่าจะเกินหรือเปล่า"* ขณะที่หน้าจอขึ้นค่าส่ง ฿328.88

ตรวจแล้ว **ตัวเลขถูกตามข้อมูลที่มีทุกบาท** — มีราคาจริงแค่ 7 ใบจาก 31 ที่เหลือขนส่งยังไม่เข้ารับ iShip จึงยังไม่คิดเงิน

---

## กฎ

🛑 **ตัวเลขบางส่วนที่หน้าตาเหมือนตัวเลขที่ครบแล้ว อันตรายกว่าไม่มีตัวเลขเลย**

ผู้ใช้ไม่มีทางรู้ว่ามันยังไม่จบ ได้แต่สรุปว่า **ระบบคำนวณผิด** แล้วเลิกเชื่อทั้งหน้าจอ — ซึ่งแพงกว่าการเห็นช่องว่างมาก เพราะความเชื่อมั่นที่เสียแล้วลามไปถึงตัวเลขที่ถูกด้วย

เมื่อค่าที่ต้องแสดงมาไม่ครบ มีทางเลือก **2 ทางเท่านั้น**:

### ทาง 1 — บอก
ป้ายกำกับต้องครอบ **ทั้ง 3 สถานะ** ไม่ใช่แค่สองสุดขั้ว:

| สถานะ | ต้องสื่อ |
|---|---|
| ครบแล้ว | แสดงตัวเลขปกติ |
| **มาบางส่วน** | **← ตัวที่มักลืม และเกิดบ่อยที่สุด** |
| ยังไม่มีเลย | ห้ามแสดง `0` — 0 อ่านว่า "ฟรี" ไม่ใช่ "ยังไม่รู้" |

รอบนี้พลาดเพราะเงื่อนไขที่เขียนไว้เป็น `if (value === 0 && pending > 0)` — ครอบเฉพาะ "ยังไม่มีเลย" กรณี "มาบางส่วน" จึงหลุดทุกวัน

### ทาง 2 — เติมให้เต็ม
หาค่าสำรองที่ดีที่สุดที่มี แล้วให้ค่าจริงเขียนทับทีหลัง — ต้องมีลำดับความน่าเชื่อถือที่ชัดเจนและ **ห้ามบวกกัน**:

```
ค่าจริง → ค่าประมาณ → ไม่มี
```

🛑 **เลือกทาง 2 แล้วถึงจะ "ไม่ต้องมีป้าย" ได้** — ถ้ายังเป็นทาง "ปล่อยว่าง" การไม่มีป้ายคือบั๊กเดิมซ้ำ

## กับดักที่เจอระหว่างทาง

**อย่าผูกการเก็บค่าหนึ่งไว้กับเงื่อนไขของอีกค่าหนึ่ง** — `cod_fee` ของ iShip รู้ตั้งแต่วินาทีที่สร้างพัสดุ (คิดจาก % ของยอด COD ไม่ต้องรอชั่ง) แต่โค้ดเดิมเขียนเป็น

```ts
if (carrierPrice != null) {
  save(carrierPrice); save(codFee)   // ← codFee ถูกทิ้งไปด้วยทั้งที่รู้ค่าแล้ว
}
```

ทำให้รายงานต้นทุนต่ำกว่าจริงทั้งวันโดยไม่จำเป็น แต่ละค่าต้องมีเงื่อนไขของตัวเอง

---

## ก่อนเลือกทาง ต้องตอบให้ได้ก่อน

1. **ค่าที่ขาดจะมาเมื่อไหร่** — ถ้าไม่รู้ ต้องเลือกทาง 1 (ทาง 2 ต้องรู้ว่าค่าประมาณจะถูกแทนที่จริง)
2. **ค่าประมาณเบ้ไปทางไหน** — ของ iShip เบ้ต่ำเสมอ (คิดจากน้ำหนักที่ร้านแจ้ง ซึ่ง 92/151 ใบน้อยกว่าที่ชั่งได้จริง) ต้องรู้ทิศทางเพื่อให้อธิบายได้ตอนตัวเลขขยับ
3. **มีค่าอื่นในชุดเดียวกันที่รู้แล้วหรือเปล่า** — ถ้ามี เก็บมันทันที อย่ารอทั้งชุด
