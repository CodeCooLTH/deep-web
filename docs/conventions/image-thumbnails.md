# รูปย่อ — ใช้ตัวกลางเดียว ทั้งเว็บและแอปผู้ขาย

> 2026-10-31 · 00088 (แชท native) ต่อยอด 00054 (รูปย่อตอนอัปโหลด)

## กฎ

1. **ขนาดรูปย่อมีที่เดียว:** `IMAGE_VARIANTS` ใน `src/lib/image-variants.ts` (thumb 480 · lg 1280 · webp) ห้ามตั้งขนาดเองที่อื่น แอปผู้ขายเลือก variant ตามเกณฑ์นี้ (HR18 เฝ้าไฟล์นี้)
2. **ขอรูปย่อมีสองทาง เลือกตามชนิดไฟล์:**
   - รูปสาธารณะ (purpose `IMAGE`: สินค้า/ห้องพัก/โลโก้) → `variantUrlOf()` (`src/lib/file-url.ts`) = ไฟล์ variant ที่สร้างตอนอัปโหลด โหลดเร็วสุด ต้องมี `onError` ถอยไปต้นฉบับ
   - รูปอื่นทั้งหมด (แชท สลิป ไฟล์ที่ไม่รู้ที่มา) → `/api/files/<key>?variant=thumb|lg` = ย่อสด **หลัง** ด่านสิทธิ์ของคีย์ต้นฉบับ ไม่เก็บไฟล์
3. 🛑 **ห้ามสร้างไฟล์ variant (`saveFileAtKey`/`generateImageVariants`) ให้รูปที่ไม่ใช่สาธารณะ** — ด่านสิทธิ์ทั้ง 5 ชั้นของ `/api/files` ตรวจจากคีย์ต้นฉบับ คีย์ variant จึงเป็นสาธารณะเสมอ = สลิป/เอกสารหลุด (เทส `image-variants.guards.test.ts` · `image-variant-on-demand.test.ts`)
4. ห้ามขอ variant ให้ URL ภายนอก (fbcdn/giphy) · gif (ภาพเคลื่อนไหวหาย) · ไฟล์ที่ไม่ใช่รูป — server ก็ตอบต้นฉบับอยู่แล้ว แต่เปลืองคำขอ
5. **แอปผู้ขาย (`deep-seller-app`):** รูปทุกใบในแชท native ผ่าน `src/features/chat/ui/RemoteImage.tsx` (expo-image แคชหน่วยความจำ+ดิสก์ · เลือก variant ตามขนาดที่แสดง · แนบคุกกี้เฉพาะ `isSameOrigin`) และรายการยาวทุกอันผ่าน `ui/ChatList.tsx` (FlashList) — เทส `central-components.test.ts` ในแอปแดงถ้ามีไฟล์ใช้ `Image`/`FlatList` ตรง ๆ

## ทำไม

ก่อนหน้านี้แชท native โหลดรูปเต็มทุกใบ (รูปมือถือ 1–3 MB) ทั้งในฟองข้อความและอวาตาร์ ⇒ เลื่อนกระตุก กินหน่วยความจำ และเปลืองเน็ตลูกค้า · ขณะที่ variant ของ 00054 ใช้กับรูปแชทไม่ได้เพราะจะเปิดรูปส่วนตัวให้เดาคีย์
