# ค่าหนึ่งค่า มีได้หลายทางเข้า และมักเก็บคนละที่

> เหตุการณ์ต้นเรื่อง: 2026-08-04 — ทำบรรทัด "เลขพัสดุ" ในแถวออเดอร์เสร็จและ push ขึ้น prod แล้ว
> ปรากฏว่าออเดอร์ที่ร้าน **ส่งเอง** ไม่ขึ้นเลขพัสดุเลยทั้งที่มีเลขอยู่ในฐาน เพราะโค้ดอ่านจากตาราง
> ของ iShip ทางเดียว (`6b2a2b28` → แก้ที่ `d0f9f949`)

## กฎ

**ก่อนจะอ่าน/แสดง "ค่าที่ผู้ใช้กรอกเข้ามา" ให้ไล่ทางเข้าจากหน้าจอก่อน ไม่ใช่จาก schema ที่กำลังแก้อยู่**

วิธีไล่:
1. หาโมดัล/ฟอร์มที่ผู้ใช้กรอกค่านั้นจริง ๆ
2. นับว่ามี **กี่แท็บ / กี่ปุ่ม submit / กี่ route** ที่จบลงด้วยการเขียนค่านี้
3. ตามแต่ละทางไปจนถึง `prisma.*.create/update` แล้วดูว่าเขียนลง **ตารางไหน**
4. ถ้ามากกว่าหนึ่งตาราง → ฝั่งอ่านต้องอ่านครบทุกทาง และต้องตัดสินว่าทางไหนชนะเมื่อมีพร้อมกัน

grep ที่ใช้ได้จริง:
```bash
# ทางเข้าฝั่ง UI
grep -rn "<ชื่อฟิลด์ไทยบนหน้าจอ>" src/app --include='*.tsx'
# ปลายทางฝั่งเขียน
grep -rn "<ชื่อตาราง>\." src/services --include='*.ts' | grep -E "create|update|upsert"
```

## เคสจริงในโปรเจกต์นี้

### เลขพัสดุ — 2 ทาง 2 ตาราง

| ทางเข้า (โมดัล "แจ้งเลขพัสดุ") | ตาราง | ฟิลด์ที่ได้ |
|---|---|---|
| **ส่งเอง** — ร้านส่งกับขนส่งเองแล้วมากรอกเลข | `ShipmentTracking` | `provider` = **ชื่อขนส่ง** ที่ผู้ขายเลือกจาก dropdown ของเรา (ไม่มีรหัส), `trackingNo` |
| **สร้างพัสดุ iShip** / **เลือกจาก iShip** | `OrderShipment` | `courierCode` + `courierName` + `trackingNo` + `carrierStatus` |

ข้อควรรู้:
- ทั้งสองตารางมีพร้อมกันได้ → **ให้ `OrderShipment` ชนะ** เพราะเป็นใบที่ระบบติดตามสถานะขนส่งให้จริง
- ฝั่งส่งเอง **ไม่มี `courierCode`** มีแต่ชื่อ — โค้ดที่แมปโลโก้/สถานะต้องรับได้ทั้งสองแบบ
  (ดู `src/lib/iship/courier.ts` ที่เทียบกับ `${courierCode} ${courierName}` ไม่ใช่รหัสอย่างเดียว)
- ฝั่งส่งเองไม่ได้เปิดผ่านแพลตฟอร์มไหน → **ห้ามขึ้นไอคอน iShip**
- 🛑 ห้ามให้ฝั่ง iShip เขียน `ShipmentTracking` (`orderId` เป็น unique และ `shipOrder()` สร้างแถวนั้น
  พร้อมเปลี่ยน `Order.status` ในทรานแซกชันเดียว — ชิงเขียนก่อนทำให้ปุ่ม "แจ้งจัดส่ง" ของร้านชน P2002)

## ทำไมถึงพลาดง่าย

ตอนกำลังทำฟีเจอร์ที่ผูกกับตารางหนึ่ง เราสำรวจ schema รอบ ๆ ตารางนั้น ซึ่งเป็นการมองจาก "ที่ที่เรายืนอยู่"
ไม่ใช่จาก "ที่ที่ผู้ใช้ยืนอยู่" — ผู้ใช้เห็นโมดัลเดียวที่มี 3 แท็บ และคิดว่ามันคือเรื่องเดียวกัน

**สัญญาณเตือน:** ถ้าฟีเจอร์ที่ทำอยู่มีคำว่า "หรือ" ในคำอธิบายของผู้ใช้ ("จะส่งเองก็ได้ ผ่าน iShip ก็ได้")
แปลว่ามีมากกว่าหนึ่งทางเข้าเกือบแน่นอน
