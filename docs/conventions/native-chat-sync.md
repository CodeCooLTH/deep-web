# แก้แชทเว็บ ต้องแก้แชท Native ในแอปผู้ขายตาม (HARD RULE 18)

> ที่มา: feature 00088 (2026-10-31) — แอปผู้ขาย `deep-seller-app` มี **แชท Native** ที่ผู้ขายสลับใช้แทนแชทในเว็บได้
> (หน้า "ตั้งค่าแอป" · ค่าเริ่ม = เว็บ) เพื่อความเร็ว · แชท Native เรียก **API ชุดเดียวกับเว็บ** และ **คัดลอกคำ/กติกา**
> ของเว็บไปไว้ในแอป (คนละรีโป ไม่มีโค้ดร่วม) · user สั่ง: "ถ้ามีการแก้แชท ต้องมาแก้ของ native ด้วย เผื่อหัวหน้าแก้ — กลัวแก้ไม่หมด"

## ทำไมต้องมีกฎ

แชทเว็บกับแชท Native คือ **หน้าจอเดียวกันสองชุด** — แก้ฝั่งเว็บแล้วไม่ตามไปแก้แอป ผลคือ:

- ผู้ขายที่ใช้โหมด Native เห็นคำเก่า/ป้ายเก่า/กติกาเก่า (เช่น ส่งใหม่ได้ทั้งที่เว็บเลิกให้ส่ง)
- API เปลี่ยน shape → แอปอ่านไม่ออก แสดงว่างเงียบ ๆ (parser ฝั่งแอปทนข้อมูลหาย = ไม่ crash แต่ก็ไม่ฟ้อง)
- ฟีเจอร์ใหม่ในเว็บ → ไม่มีในแอป และไม่มีใครรู้ว่าต้องทำ

**ไม่มีอะไรฟ้องเลยถ้าไม่มีด่าน** — `tsc`/build/เทสของเว็บผ่านหมด เพราะเว็บไม่รู้ว่ามีแอปอยู่

## ด่านที่บังคับ (ไม่ใช่แค่เอกสาร)

`src/lib/__tests__/native-chat-sync.test.ts` (รันใน **CI ด่าน 2 · vitest src/**) เก็บลายนิ้วมือของ:

| ชนิด | ที่ไหน |
|---|---|
| ทุกไฟล์ในโฟลเดอร์แชท | `src/app/api/chat/**` · `src/app/api/follow-ups/**` · `src/app/api/uploads/**` · `src/app/(paces)/seller/(chat)/**` — **ไฟล์ใหม่/ลบ/แก้ = แดง** |
| ไฟล์/ส่วนที่แอปคัดลอกหรือพึ่ง | รายการใน `src/lib/native-chat-sync/manifest.ts` (`SYNC_ENTRIES`) เช่น `chat-send-failure.ts` · `chat-list-query.ts` · `order-stage.ts` · `service-status.ts` · schema ใน `validations.ts` · ก้อนคำ `inbox`/`followUps` ใน `th.ts` |

เทสแดงจะบอก **ไฟล์ไหนเปลี่ยน · ทำไมแอปพึ่ง · ต้องไปแก้ไฟล์ไหนในแอป**

## ขั้นตอนเมื่อเทสแดง (ทุกคน รวมหัวหน้า)

1. **อ่านว่าเปลี่ยนอะไร** แล้วตัดสิน:
   - กระทบแชท Native → แก้ `deep-seller-app` ตามไฟล์ที่เทสบอก (คำ/ป้าย/กติกา/shape/หน้าจอ) · เปิด PR ของแอป
   - ไม่กระทบ (เช่น แก้คอมเมนต์ · ส่วนที่แชท Native ยังเปิดหน้าเว็บแทน) → จดเหตุผล
2. ปักหมุดใหม่: `npx tsx scripts/native-chat-sync-pin.ts` (เขียน `src/lib/native-chat-sync/pins.json`)
3. ใน PR ของเว็บเขียนบรรทัด **`Native: <ลิงก์ PR ของ deep-seller-app>`** หรือ **`Native: ไม่กระทบเพราะ ...`**
4. ผู้รีวิวดู diff ของ `pins.json` คู่กับบรรทัด `Native:` — มี pins เปลี่ยนแต่ไม่มีบรรทัดนี้ = ตีกลับ

🛑 **ห้าม** รันข้อ 2 เพื่อให้เทสผ่านโดยไม่ทำข้อ 1 · **ห้าม** แก้เทส/ลบรายการใน manifest เพื่อให้ผ่าน

## เมื่อไรต้องเพิ่มรายการใน manifest

- แอปคัดลอกอะไรใหม่จากเว็บ (คำ · ค่าคงที่ · กติกา) → เพิ่ม `SyncEntry` (ระบุ `from` ถ้าเป็นแค่บางส่วนของไฟล์)
- แอปเริ่มเรียก route นอกโฟลเดอร์ที่เฝ้า → เพิ่มรายการ route นั้น
- ฝั่งแอปมีรายการคู่กันที่ `deep-seller-app/src/features/chat/WEB-SYNC.md` — แก้คู่กันเสมอ

## ฝั่งแอป (deep-seller-app)

- ไฟล์ที่เป็นสำเนา มีหัวไฟล์บอกที่มา (`🛑 สำเนาจาก deep-web ...`) + รายการรวมที่ `src/features/chat/WEB-SYNC.md`
- เทส `src/features/chat/__tests__/web-sync.test.ts` เทียบสำเนากับไฟล์เว็บตรง ๆ เมื่อเครื่องมีทั้งสองรีโป (`DEEP_WEB_DIR`)
- แชท Native ยังไม่รองรับอะไร → เปิดหน้าเว็บของห้องนั้นแทน (ไม่มีปุ่มกดแล้วเงียบ) — ฟีเจอร์ใหม่ฝั่งเว็บที่ยังไม่ทำใน native ให้ใช้ทางนี้ระหว่างรอ

## เคสที่ไม่ต้องทำอะไรในแอป (แต่ยังต้องปักหมุด + เขียน `Native:`)

- แก้คอมเมนต์/ชื่อตัวแปรภายใน ที่ไม่เปลี่ยนพฤติกรรม/คำ/shape
- แก้ส่วนที่แชท Native **เปิดหน้าเว็บแทน** อยู่แล้ว (เช่น ฟอร์มสร้างออเดอร์ในแชท) — native ได้ของใหม่อัตโนมัติ
