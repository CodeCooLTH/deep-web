# ปุ่ม "ย้อนกลับ" ห้าม `push` — ไม่งั้นจะวนลูปกับหน้าที่ใช้ `back()`

**สรุปกฎ:** ปุ่มย้อนกลับต้อง **ไม่ทำให้ประวัติยาวขึ้น** เว้นแต่ตอนที่ไม่มีอะไรให้ถอยเลย
ตรรกะอยู่ที่ `src/lib/back-navigation.ts` (ฟังก์ชันบริสุทธิ์) · ด่าน `back-navigation.test.ts`

---

## บั๊กที่เกิดจริง (user เจอบน prod 2026-08-23)

> *"กดย้อนกลับ แก้ไข `/orders/{token}/edit` แล้ว มาหน้า `/orders/{token}` แล้วกดย้อนกลับ
> มันพามาแก้ไขอีกเฉยเลยวนลูป"*

```
[.. , รายละเอียด]                      ← ผู้ใช้อยู่ตรงนี้
  กด "แก้ไข"   → push
[.. , รายละเอียด, แก้ไข]               ← อยู่หน้าแก้ไข
  กดย้อนกลับ   → push(รายละเอียด)       ← 🛑 ตัวปัญหา
[.. , รายละเอียด, แก้ไข, รายละเอียด]   ← อยู่รายละเอียด "ใบใหม่"
  กดย้อนกลับ   → back()
[.. , รายละเอียด, แก้ไข]               ← กลับเข้าหน้าแก้ไข 🔁
```

**ฝั่งหนึ่งดันเข้า อีกฝั่งดึงออก** — หน้าแก้ไข (`FullscreenBackButton` + `backHref`) ใช้ `push`
ส่วนหน้ารายละเอียด (`SellerMobileHeader`) ใช้ `back()` ตามปกติ ⇒ ผลักกันไปมาไม่รู้จบ

### หลักฐานที่ชี้ตัวการได้แน่ ๆ

**หน้าแก้ไขสินค้า `products/[id]/edit` ไม่มีอาการนี้** — โครงหน้าเหมือนกันทุกอย่าง ใช้
`FullscreenPageHeader` ตัวเดียวกัน ต่างกันแค่ **ไม่ส่ง `backHref`** จึงตกไปสาขา `back()`
⇒ ตัวแปรเดียวที่ต่างกันคือ prop นี้

## 🛑 ทำไมไม่มี gate ไหนจับได้

`router.push(href)` เป็นโค้ดที่ถูกต้องทุกตัวอักษร — `tsc`/build/eslint/เทสผ่านหมด
สิ่งที่ผิดคือ **ความหมายของการกระทำเทียบกับชื่อปุ่ม** ซึ่งไม่มีเครื่องมือไหนอ่านออก

และเดิมตรรกะเป็น `if/else` อยู่กลาง component ⇒ **ไม่มีที่ให้เทสจับ**
(`ui-boolean-needs-a-testable-home.md` — จึงยกออกมาเป็นฟังก์ชันบริสุทธิ์)

## กติกา 3 ข้อ

| สถานการณ์ | ทำอะไร | ทำไม |
|---|---|---|
| ปลายทาง **ตายตัว** (`backHref` — `orders/new` → `/orders`) | `router.replace()` | ไปปลายทางที่ตั้งใจ **โดยไม่เพิ่ม entry** · "ตายตัว" ตอบว่า *จะไปไหน* ไม่ใช่ใบอนุญาตให้ push |
| หน้าที่มี **หลายทางเข้า** (`backFallbackHref` — หน้าแก้ไขออเดอร์) | `router.back()` | "ย้อนกลับ" แปลว่า *กลับไปที่ที่เพิ่งมา* ซึ่งไม่คงที่ · เป็นทางเดียวที่ **ลดขนาดประวัติ** จึงไม่มีทางวนลูปตามนิยาม |
| ไม่มีประวัติให้ถอย (`history.length ≤ 1`) | `router.push(fallback)` | เปิดลิงก์ขึ้นมาตรง ๆ · `back()` ตรงนี้จะพาออกจากแอปไปเลย |

## เลือก prop ตัวไหน

ถามว่า **"หน้านี้เข้าได้จากที่เดียวหรือหลายที่"**

- หลายที่ → `backFallbackHref` · หน้าแก้ไขออเดอร์เข้าได้ทั้งจากปุ่มบนหน้ารายละเอียด
  (`OrderDetailClient`) และเมนู ⋮ ในรายการออเดอร์ (`OrderActions` · `OrderCardMenu`)
  ⇒ ถ้าบังคับปลายทางเป็นหน้ารายละเอียด **คนที่มาจากรายการจะถูกพาไปหน้าที่ไม่เคยอยู่**
- ที่เดียว/ตั้งใจให้จบที่เดิมเสมอ → `backHref`

🛑 **ห้ามส่งทั้งสองตัว** — `backHref` ชนะเสมอ แล้วอีกตัวจะกลายเป็นค่าที่ไม่มีผลและโกหกคนอ่าน

## ตอนเขียนด่าน

ด่านที่เช็คว่า "ไฟล์นี้ห้ามมี `backHref=`" ต้องใช้ `\sbackHref=` **มี `\s` นำหน้า** —
เพราะสตริง `backFallbackHref` **มีคำว่า `backHref` อยู่ข้างใน** (`...Fal|lbackHref`)
ร่างแรกของด่านนี้ใช้ `[^k]backHref=` แล้วแดงใส่โค้ดที่ทำถูกทันที
