# แก้คอนทราสต์ห้ามเปลี่ยนเฉดสี

> เขียนหลังเหตุการณ์ 2026-08-03 — ดู `docs/retro/2026-08-03-chat-ios-video-window-unlock-retrospective.md`

## กฎ

**การแก้คอนทราสต์ปรับได้แค่ "ความเข้ม" ของสีเดิม ห้ามสลับไปตระกูลสีอื่น**

ถ้าเฉดที่เข้มพอจนผ่านเกณฑ์ทำให้สีเปลี่ยนความหมาย (เหลือง → น้ำตาล) แปลว่า **ทางแก้ไม่ใช่การเปลี่ยนสีตัวอักษร** — ให้ไปแก้ที่ตัว token เอง หรือเปลี่ยนพื้นหลัง/ขนาด/น้ำหนักตัวอักษรแทน

## ทำไม (เหตุการณ์จริง)

impeccable critique พบว่าสี tone ของธีม Paces ตกเกณฑ์ AA จริง:

| token | ค่า | contrast บนขาว |
|---|---|---|
| `--color-warning` | `#f9bf59` | 1.69:1 |
| `--color-info` | `#5bc3e1` | 2.05:1 |
| `--color-success` | `#02bc9c` | 2.45:1 |
| `--color-danger` | `#f7577e` | 3.12:1 |

จึงไล่เปลี่ยน `text-{tone}` → `text-{tone}-ink` ทั้ง 55 จุดในหน้าแชท ทุก gate ผ่านหมด (tsc/build/emoji/arbitrary) แต่ `-ink` **เปลี่ยนเฉด ไม่ใช่แค่ความเข้ม**:

- `warning` `#f9bf59` เหลือง → `#92400e` น้ำตาล — **ดาวปักหมุดอ่านไม่ออกว่าเป็นดาว**
- `danger` `#f7577e` ชมพูแดง → `#7f1d1d` เลือดหมู

user เห็นแล้วทักทันทีว่าสีเพี้ยน ต้องย้อนทั้งหมด (`33a35890`)

## `-ink` ไม่ได้อยู่ในธีมต้นทาง แต่**เป็น token มาตรฐานของโปรเจกต์แล้ว** (อัปเดต 2026-08-09)

`grep -- "-ink" theme/paces/**/_root.css` = **0** — ข้อนี้ยังจริง มันเป็น token ที่โปรเจกต์เพิ่มเองที่ commit `7b263e02`

🛑 **แต่ห้ามอ่านผลนั้นว่า "แปลว่าอย่าใช้"** — ตั้งแต่ `7b263e02` ตระกูลนี้ถูกยกขึ้นเป็นมาตรฐานใน
`DESIGN.md` §Colors แล้ว: *"ตัวหนังสือสีเขียวบนพื้นขาวต้องใช้ Verified Ink เสมอ … หลักเดียวกันนี้
ถูกขยายเป็นตระกูล token ฝั่ง Paces `--color-{semantic}-ink` สำหรับตัวหนังสือบนพื้น `{semantic}/15`"*
พร้อมค่าคอนทราสต์กำกับครบทั้ง 5 ตัว และ §Components ระบุ status chip = `bg-{semantic}/15` +
`text-{semantic}-ink` ตรงตัว. นิยามจริงอยู่ที่ `src/assets/css/config/_root.css:38-42` (light) และ
`194-198` (dark — ซึ่งเป็นเหตุผลที่ตระกูลนี้มีอยู่: `text-primary` เป็นค่าคงที่ไม่มีคู่ dark)

**สองเอกสารใช้คำว่า "ธีม" คนละความหมาย และนั่นคือกับดักตัวจริง** — หน้านี้หมายถึง *ธีมต้นทางที่
vendor มา* (`theme/paces/`) ส่วน DESIGN.md หมายถึง *design system ของ Deep* (`src/assets/css/`)
คนที่ grep `theme/paces` แล้วได้ 0 จึงสรุปได้ง่าย ๆ ว่า token นี้ไม่เป็นทางการ แล้วเลี่ยงไปใช้
`text-primary`/`text-danger` เปล่า ๆ ซึ่งตกคอนทราสต์บนพื้น `/15` ทุกตัว (เกิดจริงในรอบ 00024
2026-08-09: ชิปที่ถูกเลือกได้ 4.17:1 และบรรทัด error ได้ 2.96:1)

**กติกาที่ถูกต้อง:** ก่อนใช้ token สีใด ๆ ให้ตรวจ **สองที่** — `theme/` (ธีมต้นทาง) และ
`src/assets/css/config/_root.css` (ส่วนขยายที่ขึ้นทะเบียนแล้ว) มีที่ใดที่หนึ่ง = ใช้ได้ตามปกติ
ไม่ต้องขออนุญาตใน commit. ไม่มีทั้งสองที่ = เป็นค่าที่คิดเอง ต้องมีเหตุผลกำกับ

## ข้อยกเว้น: ไอคอนที่ "สี = ตัวตน"

ดาวปักหมุด · โลโก้ช่องทาง · ไอคอนที่ผู้ใช้จำจากสี — **ไม่อยู่ใต้กฎคอนทราสต์ของข้อความ**

WCAG 1.4.11 (non-text 3:1) ไม่บังคับเมื่อข้อมูลมีในรูปแบบอื่นอยู่แล้ว เช่นดาวปักหมุดที่:
- แถวถูกเรียงขึ้นบนสุดอยู่แล้ว
- ปุ่มมี `aria-label`
- เมนู `⋯` เขียนว่า "เลิกปักหมุด"

ต่างจาก**ไอคอนที่อยู่คู่ข้อความเพื่อสื่อสถานะ** (เช่นไอคอนเตือนหน้าข้อความ error) ซึ่งใช้กฎเดียวกับข้อความ

## สิ่งที่ทำได้จริงเมื่อสีธีมตกเกณฑ์

1. **แก้ที่ตัว token** — ปรับ `--color-danger` ให้เข้มขึ้นเท่าที่ยังเป็นชมพูแดง กระทบทั้งแอป ต้องให้ user เห็นตัวอย่างก่อนตัดสิน
2. **เปลี่ยนพื้นหลังแทนตัวอักษร** — `bg-{tone}` ทึบ + `text-white` (ตรวจ contrast ของคู่นั้นด้วย)
3. **เพิ่มน้ำหนัก/ขนาด** — เกณฑ์ large text คือ 3:1 ไม่ใช่ 4.5:1
4. **ใช้ `text-default-700`** สำหรับข้อความรองที่ไม่ต้องสื่อ tone — เป็น token ของธีมแท้ (`#6c757d` = 4.69:1) ไม่เปลี่ยนเฉด ปลอดภัยเสมอ

## รอบขยาย 2026-08-08 — คอนทราสต์เป็นผลของ "คู่สี" ไม่ใช่คุณสมบัติของ class

พบหนี้ 11 จุดตกเกณฑ์ AA ที่อยู่มาหลายเดือน แย่สุด **1.58:1** (`text-warning` บน `bg-warning/10`)
โดยไม่มีชั้นไหนในระบบเห็น — detector ของ impeccable ไม่ตรวจคอนทราสต์ · `theme-guard.sh` ไม่ตรวจ ·
ไม่มีเทสไหนตรวจ (ดู `docs/retro/2026-08-08-product-cost-00016-ext-retrospective.md` §P-4)

🛑 **`text-warning` ถูกต้องตามกฎธีมทุกประการ** มันตกเกณฑ์เฉพาะเมื่อไปอยู่บน `bg-warning/10` —
**ไม่มี grep ไหนเห็นความสัมพันธ์ระหว่าง 2 class นี้** จึงไม่มีทางจับด้วยการสแกนหา class ต้องห้าม

### กฎที่ใช้ได้ทันที

**ข้อความ/ไอคอนบนพื้น tint (`/10` `/15`) ต้องใช้ `-ink` เสมอ ห้ามใช้ semantic ดิบ**

ตัวเลขจริงที่คำนวณไว้ (blend tint บนพื้นการ์ดก่อน แล้วหา ratio — วิธีนี้ cross-check กับค่าที่ทีม
เคยวัดจากจอจริงใน `_root.css:186-190` ตรงกัน ±0.07):

| คู่สี | สว่าง (ดิบ → ink) | มืด (ดิบ → ink) |
|---|---|---|
| warning บน `/10` | **1.58** → 6.75 | 7.95 → 9.17 |
| success บน `/15` | **2.11** → 6.68 | 5.26 → 8.35 |
| danger บน `/15` | **2.68** → 8.47 | 4.27 → 7.16 |
| primary บน `/15` | **4.17** → 8.44 | **2.78** → 7.89 |
| danger บนการ์ดขาว | **3.17** → 10.02 | 5.17 → 8.67 |

`-ink` **ผ่านทั้งสองโหมดทุกคู่** (6.68–9.17) จึงสลับตรง ๆ ได้ ไม่ต้องมี variant แยกธีม —
ตรงกับสถาปัตยกรรมของโปรเจกต์ที่จัดการโหมดมืดด้วยการ redefine token ล้วน (`dark:` variant
ใช้อยู่ **0 ไฟล์** ทั้ง `(paces)` — การใส่เข้ามาคือการเปิดแพตเทิร์นใหม่ ไม่ใช่การตามของเดิม)

### 🛑 token ที่ใช้เป็นทั้งสีพื้นและสีข้อความ แก้คอนทราสต์ด้วยการ redefine ไม่ได้

`--color-primary` ถูกใช้เป็น `bg-primary` ใน **209 ไฟล์** — redefine ให้อ่อนลงเพื่อแก้
`text-primary` บนพื้นเข้มในโหมดมืด จะทำให้ **ปุ่มหลักทั้งแอปกลายเป็นพื้นอ่อนตัวอักษรขาว = แย่กว่าเดิม**

ก่อนแก้ค่า token ใด ๆ:
```bash
rg -c "bg-<token>|text-<token>|border-<token>" src/
```
ถูกใช้เกิน 1 บทบาท → **ห้ามแก้ค่า** ต้องแยก token ("สีข้อความ" ออกจาก "สีพื้น") หรือแก้ที่ระดับ class
